클라우드 전환 사업의 단계별 감리 방법과 검토 항목

문제​

5.클라우드 전환 사업의 단계별 감리 방법과 검토 항목에 대하여 설명하시오.

Ⅰ. 개요​

1. 배경​

행정·공공기관 정보자원 클라우드 전환 정책에 따라 공공 클라우드 전환 사업이 확대되고 있다. 그러나 클라우드 전환은 단순 인프라 이전이 아니라 아키텍처·운영 방식·보안 체계의 전면적 변화를 수반하므로, 기존 구축 사업과 다른 감리 관점이 요구된다.

2. 클라우드 전환 사업의 특수성​

   [기존 정보시스템 구축 감리]        [**클라우드 전환 사업 감리**]
   신규 개발 산출물 검토               **기존 시스템의 이전 적정성** 검토
   기능 요구사항 중심                  **비기능(성능·가용성·보안) 중심**
   물리 인프라 구성 검토               **CSP 서비스 선정·아키텍처 적정성**
   일회성 구축비                       **지속 발생 이용료(TCO)** 검증
   자체 통제                           **책임 공유 모델**(CSP와 책임 분담)
        ▼                                    ▼
   ⇒ **전환 타당성·데이터 이행 정합성·보안·비용**이 핵심 검토 대상

3. 감리의 법적 근거​

  • 「전자정부법」 제57조(감리 의무), 시행령 제71조(감리 대상 기준)
  • 「정보시스템 감리기준」(행정안전부 고시), 감리 점검해설서
  • 클라우드컴퓨팅법, CSAP(클라우드 보안인증), N2SF 등 관련 제도 연계

Ⅱ. 클라우드 전환 사업의 단계와 감리 체계​

1. 전환 사업 단계와 감리 시점​

 ┌─ **① 계획·진단** ─┬─ **② 설계** ─┬─ **③ 구축·전환** ─┬─ **④ 이행·안정화** ─┐
 │  전환 타당성       │ 목표 아키텍처 │ 자원 구축·데이터   │ 전환(Cutover)·      │
 │  대상 선정         │ 보안 설계     │ 이행·시험          │ 운영 이관           │
 │  전환 전략(6R)     │ 이행 계획     │                    │                     │
 └────────┬──────────┴──────┬───────┴─────────┬──────────┴──────────┬──────────┘
      **요구정의 감리**   **설계 단계 감리**   (진행 점검)        **종료 단계 감리**
          ▲                    ▲                                     ▲
          └──────────── **상주감리**(대규모·고위험 사업은 전 기간) ────┘
감리 유형내용
단계별 감리(3단계)요구정의 → 설계 → 종료 시점의 시점 감리(원칙)
상주감리위험도가 크거나 대규모 사업 시 전 기간 상주하며 지속 점검
기술 지원 감리특정 기술 영역(보안·성능)에 대한 전문 감리

2. 감리 방법​

방법내용
문서 검토전환계획서·아키텍처 설계서·이행계획서·시험 결과서 등 산출물 검토
인터뷰발주기관·수행사·운영 담당자 면담을 통한 실태 확인
시스템 점검클라우드 콘솔 직접 확인(자원 구성·보안 그룹·IAM 설정), 로그 분석
시연·실사성능 시험·장애 절체(Failover) 시험 입회 확인
정량 분석성능 측정 데이터, 데이터 정합성 검증 결과(건수·체크섬) 확인
체크리스트감리 점검항목 기반 적합성 판단(적합·부적합·개선권고)

Ⅲ. 단계별 감리 검토 항목​

1. ① 계획·진단 단계 (요구정의 감리)​

핵심 관점: "클라우드로 전환하는 것이 타당한가, 무엇을 어떤 방식으로 전환할 것인가"

   [**전환 전략 — 6R 모델**]
   ┌──────────────┬────────────────────────────────────────┐
   │ **Rehost**    │ 그대로 이전(Lift & Shift) — 신속·저비용   │
   │ **Replatform**│ 일부 최적화(관리형 DB 전환 등)          │
   │ **Refactor**  │ **클라우드 네이티브 재설계**(MSA·컨테이너)│
   │ **Repurchase**│ SaaS로 대체                             │
   │ **Retain**    │ 전환하지 않고 **유지**(레거시·규제 제약)  │
   │ **Retire**    │ **폐기**(사용하지 않는 시스템)           │
   └──────────────┴────────────────────────────────────────┘
   ⇒ 감리는 **시스템별 전략 선정 근거의 타당성**을 검토
검토 영역주요 검토 항목
전환 타당성· 전환 목적·목표의 명확성(비용 절감·확장성·민첩성 중 무엇인가)
· AS-IS 현황 분석의 충실성(자원 사용률·연계 현황·데이터량)
· TCO 분석의 적정성 — 구축비뿐 아니라 3~5년 이용료·전환 비용·인력 비용 포함 여부
· 전환 효과(정량·정성) 산정 근거
대상 선정· 전환 대상·제외 대상의 선정 기준 명확성
· 시스템별 6R 전략 적정성(무조건 Rehost는 클라우드 이점 미확보)
· 우선순위 결정 근거(중요도·난이도·연계 복잡도)
CSP·서비스 선정· CSAP 인증 여부 확인(공공은 필수 요건)
· 서비스 모델(IaaS/PaaS/SaaS) 선정 근거
· 벤더 종속(Lock-in) 대응 방안, 멀티클라우드 검토
· 조달 방식·계약 조건
법·제도 준수· 개인정보 국외 이전 여부, 데이터 저장 위치(국내 리전)
· N2SF 등급 분류와 클라우드 이용 가능 여부
· 개인정보 영향평가(PIA) 대상 여부
위험·조직· 전환 위험 식별·대응계획, 롤백 계획 수립 여부
· 운영 인력 역량·교육 계획, 조직 변화 관리
사업 관리사업 범위·일정·예산의 적정성, 과업 명확성

2. ② 설계 단계 감리​

핵심 관점: "클라우드 특성을 반영한 아키텍처인가, 비기능 요구사항이 충족되는가"

검토 영역주요 검토 항목
아키텍처 설계· 목표 아키텍처의 클라우드 적합성 — 온프레미스 구조를 그대로 옮기지 않았는가
· 자원 규모 산정(Sizing) 근거 — 과다 산정(비용 낭비)·과소 산정(성능 미달) 검토
· 오토스케일링·부하분산 설계
· 네트워크 아키텍처(VPC·서브넷·라우팅), 온프레미스 연계(전용선·VPN)
가용성·재해복구· RTO/RPO 목표 정의와 설계 부합성
· 다중 AZ(가용영역) 구성 여부, 단일 장애점(SPOF) 존재 여부
· 백업·복구 방안(주기·보관기간·복구 시험 계획)
· DR 구성(Active-Standby / Active-Active)
성능· 성능 목표(응답시간·TPS) 정의 및 검증 계획
· 스토리지 유형·IOPS 산정, 캐시·CDN 활용
보안 설계
(핵심)		· 책임 공유 모델에 따른 책임 범위 명확화
· IAM 설계 — 최소 권한, 관리자 계정 분리, MFA 적용
· 네트워크 보안 — 보안 그룹·NACL, 망 분리(N2SF 정합성), 공개 노출 자원 통제
· 암호화 — 저장(EBS·S3)·전송(TLS) 암호화, 키 관리(KMS) 방안
· 보안 로그 수집·보존, 관제 연계
· CSAP 통제항목 반영 여부
데이터 이행 설계· 이행 대상·범위·방식(전체/증분, CDC 활용 여부)
· 정합성 검증 방안(건수·체크섬·샘플 비교) 구체성
· 이행 중단 시간(Downtime) 산정, 대용량 데이터 이행 방안
운영 설계· 모니터링·로깅 체계, 알림 정책
· 자동화(IaC) 적용 계획, 형상관리
· 비용 관리(FinOps) — 태깅 정책·예산 알림
이행 계획전환 순서·일정, 롤백 기준과 절차, 비상 대응 체계

3. ③ 구축·전환 단계 (진행 점검 / 상주감리)​

핵심 관점: "설계대로 구축되었는가, 데이터는 정확히 이행되었는가"

검토 영역주요 검토 항목
자원 구축· 설계 대비 실제 구축 자원의 일치성(콘솔 직접 확인)
· IaC 적용 여부 및 코드-실제 환경 일치
· 불필요·미사용 자원 존재 여부(비용 낭비)
보안 설정· IAM 권한 실제 설정 점검(과도 권한 부여 여부)
· 보안 그룹의 불필요한 전체 개방(0.0.0.0/0) 여부
· 공개 스토리지 버킷 등 설정 오류
· 암호화 적용 실태, 로그 수집 정상 작동
· 취약점 점검 결과 및 조치
데이터 이행
(최대 위험 구간)		· 이행 절차 준수 여부
· 정합성 검증 결과 — 건수 일치, 체크섬, 샘플 데이터 대사
· 문자셋·데이터 타입 변환 오류 여부
· 증분 동기화(CDC) 정상 작동 확인
· 이행 실패 시 재수행·롤백 절차
애플리케이션· 클라우드 환경에서의 정상 동작 확인
· 하드코딩된 IP·경로 등 환경 종속 요소 제거 여부
· 연계 시스템 인터페이스 시험 결과
시험· 성능 시험 결과가 목표치를 충족하는가(부하 시험 실측)
· 장애 절체(Failover) 시험 수행 및 결과
· 백업·복구 시험 결과
· 보안 취약점 진단 결과
진척 관리일정 준수, 이슈·위험 관리 현황, 산출물 완비

4. ④ 이행·안정화 단계 (종료 단계 감리)​

핵심 관점: "안정적으로 전환되었는가, 운영할 준비가 되었는가"

검토 영역주요 검토 항목
전환(Cutover)· 전환 절차 준수, 중단 시간 목표 달성 여부
· 전환 후 서비스 정상 작동 확인(체크리스트)
· 롤백 판단 기준 적용 여부
성능·안정성· 실운영 환경의 성능 지표 충족
· 안정화 기간 중 장애 발생 이력 및 조치
· 자원 사용률 적정성(과다·과소 산정 재검토)
보안 최종 점검· 보안 취약점 조치 완료 여부
· 불필요 계정·권한 회수, 임시 접근 통제 해제
· 보안 관제 연계 정상 작동, CSAP 요건 충족
데이터 최종 검증· 최종 데이터 정합성 확인
· 기존 시스템 데이터의 안전한 처리(보관·파기)
운영 이관· 운영 매뉴얼·장애 대응 절차서 완비
· 운영 인력 교육 이수 및 역량 확보
· 모니터링·알림 체계 정상 작동
· SLA 정의 및 측정 체계 마련
비용· 실제 발생 비용과 계획 대비 분석
· 비용 최적화 조치(예약 인스턴스·미사용 자원 정리)
· 지속 비용 관리 체계(FinOps)
과업 이행· 요구사항 정의서 대비 이행 여부(RTM 기반 추적)
· 산출물 완비성, 검수 조건 충족
기존 자원 처리온프레미스 장비 처리 계획, 라이선스 정리

Ⅳ. 클라우드 전환 감리의 중점 관리 항목​

1. 감리에서 특히 주의할 점​

중점 항목내용
① 형식적 Rehost 경계온프레미스 구조를 그대로 옮기기만 하면 클라우드 이점(탄력성·자동화)을 얻지 못하고 비용만 증가 → 전략 선정의 타당성 검토 필수
② 자원 과다 산정온프레미스 관행대로 피크 기준 고정 산정 → 클라우드 비용 급증
→ 오토스케일링 활용 여부 확인
③ 보안 설정 오류클라우드 사고의 대부분이 침해가 아닌 설정 오류(공개 버킷·과도 권한)
→ 콘솔 직접 점검 필수
④ 데이터 이행 정합성전환 실패의 최대 원인 → 검증 방법의 구체성과 실제 수행 증적 확인
⑤ 책임 공유 모델 이해"클라우드로 옮기면 CSP가 보안을 책임진다"는 오해 → 기관 책임 영역(데이터·계정·설정) 통제 확인
⑥ TCO 검증구축비만 보고 판단하면 안 됨 → 3~5년 총비용(이용료·전송비·라이선스) 검토
⑦ 운영 역량 이관전환은 끝났으나 운영할 사람이 없는 상황 방지 → 교육·매뉴얼 확인

2. 감리 결과 조치​

   [지적 유형]
   **부적합** : 과업 미이행·중대 결함 → **반드시 시정**
   **개선권고** : 품질 향상을 위한 권고 → 검토 후 반영
   **협의필요** : 발주기관·수행사 간 협의 사항
        ▼
   시정조치 요구 → 조치 결과 확인 → **후속 감리 시 이행 여부 재점검**

Ⅴ. 결론​

클라우드 전환 사업 감리는 기존 구축 사업 감리와 달리 "무엇을 새로 만들었는가"가 아니라 "제대로 옮겼는가, 클라우드답게 설계했는가, 안전하고 경제적인가" 를 검토하는 것이 핵심이다.

단계별로는 ① 계획 단계에서 전환 타당성과 6R 전략의 적정성, ② 설계 단계에서 클라우드 적합 아키텍처와 보안 설계, ③ 구축·전환 단계에서 데이터 이행 정합성과 보안 설정 실태, ④ 이행 단계에서 운영 이관 준비와 비용 검증이 각각 중점 검토 대상이 된다.

특히 실무적으로 주의할 세 가지는 ① 형식적 Lift & Shift로 인한 클라우드 이점 미확보, ② 자원 과다 산정에 따른 비용 급증, ③ 침해가 아닌 설정 오류로 인한 보안 사고이다. 이들은 문서 검토만으로는 발견할 수 없으므로, 감리인이 클라우드 콘솔을 직접 확인하고 성능·절체 시험에 입회하는 실증적 접근이 필요하다.

아울러 책임 공유 모델에 대한 정확한 이해가 감리의 전제이다. "클라우드로 옮기면 보안은 CSP 책임"이라는 오해가 가장 흔한 위험 요인이며, 데이터·계정·설정에 대한 기관의 책임이 제대로 이행되는지를 확인하는 것이 클라우드 전환 감리의 고유한 역할이다.
