대규모 AI 서비스를 위한 데이터센터 구축 기술

문제​

4.대규모 AI 서비스를 위한 데이터센터 구축 기술에 대하여 설명하시오.
가.저지연 기술과 스케일링 확보 기술
나.DCI(Data Center Interconnect) 기술

Ⅰ. 개요​

1. AI 데이터센터의 특수성​

생성형 AI 확산으로 데이터센터의 요구사항이 근본적으로 변화하였다. 기존 데이터센터가 다수의 독립적 트랜잭션을 처리했다면, AI 데이터센터는 수천 개 GPU가 하나의 작업을 협력 수행하는 구조이다.

   [기존 데이터센터]                    [**AI 데이터센터**]
   워크로드 : 독립적 트랜잭션            **분산 학습**(수천 GPU 협력)
   트래픽   : **남북(North-South)** 중심  **동서(East-West)** 지배적
   병목     : CPU·스토리지               **네트워크·메모리 대역폭**
   전력밀도 : 랙당 5~10kW                **랙당 40~130kW 이상**
   냉각     : 공랭                       **액침·수랭(Liquid Cooling)**
        ▼                                      ▼
   범용 인프라로 충분                    **전용 아키텍처 필수**

2. 핵심 요구사항​

요구사항내용
초저지연분산 학습에서 GPU 간 통신 지연이 전체 학습 시간을 좌우
초광대역파라미터·그래디언트 동기화에 수백 Gbps~Tbps 필요
선형 확장성GPU 추가 시 성능이 비례 증가해야 함(Scaling Efficiency)
고전력·고발열 대응랙당 전력밀도 급증 → 전력·냉각 인프라 재설계
무손실 전송패킷 손실 시 전체 학습 작업이 지연·재시작

Ⅱ. 가. 저지연 기술과 스케일링 확보 기술​

1. 분산 학습의 병목 구조​

   [분산 학습 1 스텝의 흐름]
   각 GPU : 순전파 → 역전파 → **그래디언트 계산**
                                    │
                          **All-Reduce**(전체 GPU 간 그래디언트 동기화)
                                    │  ← **여기가 병목**
                          파라미터 갱신 → 다음 스텝

   ⇒ 연산 시간보다 **통신 시간이 길어지면 GPU가 놀게 됨(Idle)**
   ⇒ **네트워크 성능 = AI 학습 성능**

2. 저지연 기술​

구분기술내용
네트워크 프로토콜RDMA(Remote Direct Memory Access)CPU·OS 커널을 거치지 않고 원격 메모리에 직접 접근 → 지연 대폭 감소, CPU 부하 제거
RoCEv2(RDMA over Converged Ethernet)이더넷 위에서 RDMA 구현 — 범용성·비용 우위, 무손실 이더넷 필수
InfiniBandAI/HPC 전용 초저지연 네트워크(수 μs), SHARP(스위치 내 집합연산 오프로드) 지원
GPUDirect RDMAGPU 메모리 간 직접 전송(CPU 메모리 경유 없음)
무손실 전송PFC(Priority Flow Control)버퍼 포화 시 상위 스위치에 전송 중지 신호 → 패킷 손실 방지
ECN / DCQCN혼잡 발생 시 패킷 표시로 송신률 조절(혼잡 제어)
딥 버퍼 스위치순간적 트래픽 폭주(Incast) 흡수
토폴로지Fat-Tree / Clos계층적 비차단(Non-blocking) 구조로 임의 노드 간 균등 대역폭
Rail-Optimized 설계GPU별 전용 NIC를 동일 스위치 계층에 배치 → 집합통신 최적화
Dragonfly대규모에서 홉 수 최소화
경로 최적화적응형 라우팅(Adaptive Routing)혼잡 경로를 회피해 동적 경로 선택
패킷 스프레이(Packet Spraying)다중 경로 균등 분산 → ECMP 편중(Hash Polarization) 해소
노드 내 통신NVLink / NVSwitch서버 내 GPU 간 초고속 직접 연결(PCIe 대비 수배 대역폭)
HBMGPU 메모리 병목 해소(고대역폭 메모리)

3. 스케일링 확보 기술​

   [두 가지 확장 축]
   **Scale-Up(수직 확장)**              **Scale-Out(수평 확장)**
   하나의 노드 내 GPU 집적              여러 노드를 네트워크로 연결
   NVLink·NVSwitch로 연결               InfiniBand·RoCE 패브릭
   ▲ 통신 지연 최소                     ▲ 규모 무한 확장
   ▼ 물리적 한계(전력·발열)             ▼ 통신 지연·효율 저하
        └────► **양자 결합**: 노드 내 Scale-Up + 노드 간 Scale-Out
구분기술내용
병렬화 전략데이터 병렬(Data Parallel)데이터를 나누고 모델은 복제 → All-Reduce로 동기화
모델 병렬(Tensor/Pipeline Parallel)모델이 단일 GPU에 안 들어갈 때 계층·텐서 단위로 분할
3D 병렬화데이터+텐서+파이프라인 병렬의 조합(초대규모 LLM 학습의 표준)
ZeRO / FSDP옵티마이저 상태·그래디언트를 분산 저장하여 메모리 절감
집합통신 최적화NCCL / RCCLGPU 집합통신 라이브러리(All-Reduce·All-Gather 최적화)
In-Network Computing스위치가 직접 집합연산 수행(SHARP) → 통신량 감소
통신·연산 중첩그래디언트 계산과 전송을 동시 진행하여 대기 제거
자원 관리쿠버네티스 + GPU 스케줄러GPU 자원 할당·큐잉(Kueue·Volcano), 갱 스케줄링(모든 GPU 동시 확보)
토폴로지 인지 스케줄링통신이 잦은 작업을 물리적으로 인접한 GPU에 배치
MIG·GPU 가상화추론 작업의 GPU 분할 활용
스토리지 확장병렬 파일시스템Lustre·GPFS·WekaFS — 수천 노드 동시 읽기
GPUDirect Storage스토리지 → GPU 직접 전송
데이터 캐싱·프리페치학습 데이터 로딩 병목 제거
인프라 확장전력 인프라랙당 40~130kW 대응, 고전압 직류(HVDC) 배전
액체 냉각직접 칩 냉각(D2C)·액침(Immersion) — 공랭 한계 극복, PUE 개선
모듈형 구축프리팹·컨테이너형으로 신속 증설
신뢰성체크포인팅장애 시 재학습 최소화(수천 GPU 중 1개 장애도 전체 중단)
장애 예측·자동 격리이상 노드 조기 배제

Ⅲ. 나. DCI(Data Center Interconnect) 기술​

1. 개념 및 필요성​

DCI는 지리적으로 분리된 복수의 데이터센터를 고속·저지연 네트워크로 연결하여, 하나의 논리적 자원 풀처럼 운영할 수 있게 하는 기술이다.

   [AI 시대 DCI의 필요성]
   ┌──────────────────────────────────────────────────────┐
   │ ① **단일 DC의 전력 한계** — AI 클러스터가 요구하는     │
   │    수백 MW를 한 곳에서 공급 불가 → **분산 배치 불가피** │
   │ ② **대규모 데이터 이동** — 학습 데이터셋(수 PB) 전송   │
   │ ③ **재해복구·가용성** — 리전 장애 대응(Active-Active) │
   │ ④ **자원 풀링** — 여러 DC의 GPU를 통합 활용            │
   │ ⑤ **엣지 연계** — 추론은 사용자 가까이, 학습은 중앙    │
   └──────────────────────────────────────────────────────┘

   [DCI 구조]
   ┌── DC A ──┐  ◄──── **DCI**(광전송·고속 회선) ────►  ┌── DC B ──┐
   │ GPU 클러스터│      · 대역폭 : 수백 Gbps~수십 Tbps   │ GPU 클러스터│
   │ 스토리지   │      · 지연 : 거리에 비례(광속 한계)   │ 스토리지   │
   └───────────┘      · 암호화·이중화 필수              └───────────┘

2. DCI 계층별 기술​

계층기술내용
광 전송 계층
(Layer 1)		DWDM(고밀도 파장분할다중)하나의 광섬유에 수십~수백 파장을 다중화 → 대역폭 극대화
코히어런트 광전송400G/800G/1.2T 장거리 전송, 고차 변조(QAM)
ZR / ZR+ 광모듈스위치에 직접 장착하는 플러거블 광모듈 — 별도 전송장비 불필요, 비용·전력 절감
OTN광 전송 네트워크 표준, 회선 관리·보호 절체
네트워크 계층
(Layer 2/3)		VXLAN + EVPNDC 간 L2 확장(VM·컨테이너 무중단 이동), 대규모 테넌트 격리
Segment Routing / SRv6트래픽 엔지니어링, 경로 최적화, 프로토콜 단순화
MPLS L2/L3 VPN전통적 사업자 백본 연결
BGPDC 간 경로 광고·제어
제어·운영SDN 컨트롤러DC 간 회선의 중앙 집중 제어·자동 프로비저닝
광 SDN·의도 기반 제어대역폭 온디맨드(Bandwidth on Demand)
보안MACsec / IPsecDC 간 구간 암호화(회선 도청 방지)
양자내성암호(PQC)장기 기밀성 확보(HNDL 대응)
QKD초고보안 구간의 양자키 분배
가용성이중 경로·보호 절체회선 장애 시 50ms 이내 절체, 물리적 경로 분리(Diverse Routing)

3. AI 워크로드 관점의 DCI 설계 고려사항​

   [지연과 워크로드의 관계 — 거리의 물리적 제약]
   광속 기준 : **100km당 약 0.5ms** 왕복 지연 발생
   ┌──────────────┬────────────────┬────────────────────────┐
   │ 거리          │  왕복 지연      │  적합 워크로드           │
   ├──────────────┼────────────────┼────────────────────────┤
   │ 캠퍼스(~10km) │  0.1ms 이하     │ **분산 학습 가능**(제한적)│
   │ 메트로(~100km)│  ~1ms          │ 스토리지 복제, 추론 분산 │
   │ 장거리(1000km)│  ~10ms         │ **DR·데이터 백업**       │
   └──────────────┴────────────────┴────────────────────────┘
   ⇒ **동기식 분산 학습은 DCI를 넘어서기 어려움**
     → 학습은 단일 DC 집중, DCI는 **데이터 이동·DR·추론 분산**에 활용
고려사항내용
워크로드 배치 전략학습(초저지연 필요)은 단일 DC 내, 추론·데이터 파이프라인은 DC 간 분산
대역폭 산정학습 데이터셋 이동량·복제 트래픽 기준 산정, 버스트 대응 여유율 확보
전송 비용회선 임차료·클라우드 Egress 비용이 상당 → 데이터 이동 최소화 설계
전력·입지전력 확보 가능 지역에 분산 배치 → DCI로 논리적 통합(전력 제약 해소 전략)
보안·규제구간 암호화 필수, 데이터 국외 이전 규제 준수
가용성물리적 경로 이중화(서로 다른 관로), 자동 절체

Ⅳ. 종합 아키텍처 및 결론​

1. AI 데이터센터 종합 구조​

   ┌──────────────── **DC A**(학습 클러스터) ────────────────┐
   │  [노드 내] GPU ↔ **NVLink/NVSwitch** ↔ GPU (Scale-Up)   │
   │  [노드 간] **InfiniBand / RoCEv2 + Fat-Tree** (Scale-Out)│
   │           · RDMA·GPUDirect · PFC/ECN 무손실              │
   │  [스토리지] 병렬 파일시스템 + GPUDirect Storage           │
   │  [인프라] 랙당 100kW급 전력 · **액체 냉각**               │
   └──────────────────────┬──────────────────────────────────┘
                **DCI**(DWDM·ZR+ / VXLAN-EVPN / MACsec)
   ┌──────────────────────┴──────────────────────────────────┐
   │  **DC B**(추론·DR)          **DC C**(데이터 레이크)        │
   └─────────────────────────────────────────────────────────┘

2. 결론​

대규모 AI 서비스를 위한 데이터센터의 핵심 전환점은 "연산이 아니라 데이터 이동이 병목" 이라는 인식이다. 수천 개 GPU가 하나의 작업을 수행하는 분산 학습에서는 통신 지연이 곧 학습 시간과 비용이 되므로, RDMA·InfiniBand·무손실 이더넷·Fat-Tree 토폴로지가 필수 요소가 되었다.

스케일링 관점에서는 노드 내 Scale-Up(NVLink)과 노드 간 Scale-Out(InfiniBand)을 결합하고, 3D 병렬화와 토폴로지 인지 스케줄링으로 확장 효율을 확보해야 한다. 아울러 랙당 전력밀도 급증으로 액체 냉각이 선택이 아닌 필수가 되었다는 점도 중요한 변화이다.

DCI는 단일 데이터센터의 전력 한계를 극복하는 분산 전략의 기반이나, 광속에 따른 물리적 지연 제약 때문에 동기식 분산 학습을 DC 간으로 확장하기는 어렵다. 따라서 학습은 단일 DC에 집중하고, DCI는 데이터 이동·추론 분산·재해복구에 활용하는 워크로드 배치 전략이 현실적이다.

궁극적으로 AI 인프라의 경쟁력은 GPU 수량이 아니라 네트워크 효율(MFU)·전력 효율(PUE)·확장 효율을 포함한 데이터센터 총효율에서 결정되며, 국내에서는 전력 확보와 냉각 인프라가 가장 현실적인 제약 요인으로 부각되고 있다.
