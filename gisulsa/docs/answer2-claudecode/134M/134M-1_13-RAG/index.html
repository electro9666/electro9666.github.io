RAG(Retrieval Augmented Generation, 검색 증강 생성)

문제​

13.RAG(Retrieval Augmented Generation)

Ⅰ. 개요​

RAG는 LLM이 답변을 생성하기 전에 외부 지식베이스에서 관련 문서를 검색하여 컨텍스트로 주입함으로써, 환각(Hallucination)을 줄이고 최신·기관 고유 지식에 근거한 답변을 생성하는 아키텍처이다.

   [LLM 단독의 한계]
   · 학습 시점 이후 정보 모름(**지식 컷오프**)
   · 기관 내부 문서 미학습 → 업무 질의 응답 불가
   · **환각** — 모르는 것도 그럴듯하게 생성
   · **근거 제시 불가** → 검증 불가능
        ▼
   [**RAG**] 검색된 근거 문서를 함께 제공 → **출처 있는 답변**

Ⅱ. 동작 원리​

   [**① 사전 인덱싱 단계**(Offline)]
   원본 문서 → **청킹(Chunking)** → **임베딩 모델** → 벡터 → **벡터DB 저장**
                (적정 크기 분할)      (의미를 벡터로)    (HNSW·IVF 인덱스)

   [**② 질의 처리 단계**(Online)]
   사용자 질의
        │ 임베딩
        ▼
   **검색(Retrieval)** ── 벡터 유사도 검색(+키워드 BM25 = **하이브리드**)
        │                  · 권한 필터링 적용
        ▼
   **재순위화(Re-ranking)** ── 상위 후보를 정밀 모델로 재정렬
        │
        ▼
   **증강(Augmentation)** ── 프롬프트에 근거 문서 삽입
        │  "아래 문서만 근거로 답하고, 없으면 모른다고 답하라"
        ▼
   **생성(Generation)** ── LLM이 답변 + **출처(Citation) 제시**

Ⅲ. 구성요소 및 비교​

구성요소역할
문서 처리·청킹문서를 의미 단위로 분할(고정·의미·계층 청킹), 메타데이터 부여
임베딩 모델텍스트를 의미 벡터로 변환(검색 품질의 핵심)
벡터 데이터베이스대규모 벡터의 ANN 검색(HNSW·IVF), 권한·필터 지원
검색기(Retriever)벡터+키워드 하이브리드 검색, 질의 재작성(Query Rewriting)
재순위화(Reranker)Cross-Encoder로 정밀 재정렬 → 정확도 향상
생성기(LLM)근거 기반 답변 생성, 출처 표시
비교 기준RAG파인튜닝
지식 반영외부 검색으로 주입모델 가중치에 학습
최신성문서만 갱신하면 즉시 반영재학습 필요
출처 제시가능(설명책임 확보)불가
환각 억제효과 큼제한적
비용낮음(구축 후 문서 관리)큼(학습 데이터·GPU)
적합사실 기반 지식 질의응답문체·형식·특수 과업

Ⅳ. 고도화 유형 및 고려사항​

유형내용
Naive RAG단순 검색 → 생성(기본형)
Advanced RAG질의 재작성·하이브리드 검색·재순위화·컨텍스트 압축
Modular / Agentic RAG에이전트가 검색 여부·횟수를 판단, 다단계 추론(Self-RAG)
GraphRAG지식그래프를 결합해 개체 간 관계 추론 강화
고려사항내용
검색 품질이 곧 성능"검색이 실패하면 LLM도 실패" → 청킹 전략·임베딩 모델 선택이 핵심
문서 품질 관리중복·구버전 문서 제거, 최신성 유지 체계
보안벡터DB 접근통제(행 수준 보안) — 권한 없는 문서가 검색되면 유출
RAG Poisoning(악성 문서 삽입) 방어
평가 체계검색 정확도(Recall@K), 답변 충실도(Faithfulness), RAGAS 등
비용·지연검색·재순위화로 응답 지연 증가 → 캐싱·경량 모델

Ⅴ. 결론​

RAG는 LLM의 환각·지식 컷오프·근거 부재라는 세 가지 한계를 동시에 완화하는 사실상의 표준 아키텍처이며, 특히 출처를 제시할 수 있어 설명책임이 요구되는 공공·금융·의료 영역에서 파인튜닝보다 우선 채택된다.

다만 RAG의 성능은 LLM이 아니라 검색 품질에 좌우되므로, ① 문서 정제와 청킹 전략, ② 하이브리드 검색과 재순위화, ③ 벡터DB의 권한 기반 접근통제에 투자해야 한다. 즉 RAG 성공의 관건은 모델이 아니라 조직의 문서·데이터 관리 성숙도이다.
