IT 거버넌스(IT Governance)

문제​

3.IT 거버넌스에 대하여 설명하시오.
가.IT 거버넌스의 구성요소
나.IT 거버넌스 효과 측정 지표
다.IT 거버넌스 효과 측정 방법론

Ⅰ. 개요​

1. 개념​

IT 거버넌스는 IT가 조직의 전략과 목표를 지원하고 가치를 창출하도록, 이사회와 경영진이 IT 자원과 위험을 통제·감독하는 리더십·조직구조·프로세스의 체계이다(ITGI 정의).

2. 필요성​

   [IT 투자의 딜레마]
   IT 투자 확대 ─► "**투자 대비 효과가 있는가**"에 대한 설명 불가
        │              "IT는 비용 부서인가 가치 창출 부서인가"
        ▼
   ┌──────────────────────────────────────────────┐
   │ ① **전략 정합성 부재** — IT와 사업 목표의 괴리  │
   │ ② **투자 우선순위 불명확** — 부서별 요구 난립   │
   │ ③ **위험 관리 미흡** — 보안·컴플라이언스 사고   │
   │ ④ **성과 측정 곤란** — IT 가치의 가시화 실패    │
   └──────────────────────────────────────────────┘
        ▼
   **IT 거버넌스** = "IT에 대한 의사결정 권한과 책임의 체계화"

3. 관련 개념 구분​

구분내용
IT 거버넌스"올바른 일을 하는가" — 방향 설정·감독(Evaluate·Direct·Monitor), 이사회·경영진의 책임
IT 관리(Management)"일을 올바르게 하는가" — 계획·구축·운영·모니터링(PBRM), CIO·IT 조직의 책임
관계거버넌스가 방향을 정하고, 관리가 실행함(COBIT 5에서 명확히 분리)

Ⅱ. 가. IT 거버넌스의 구성요소​

1. 5대 핵심 영역 (ITGI Focus Areas)​

   ┌──────────────── **IT 거버넌스 5대 영역** ────────────────┐
   │                                                          │
   │        ① **전략적 정합성**(Strategic Alignment)           │
   │                        ▲                                 │
   │                        │                                 │
   │  ② **가치 전달**  ◄─────┼─────►  ③ **위험 관리**           │
   │  (Value Delivery)      │        (Risk Management)        │
   │                        │                                 │
   │        ④ **자원 관리**(Resource Management)               │
   │                        │                                 │
   │        ⑤ **성과 측정**(Performance Measurement)           │
   │            ▲ 전 영역의 결과를 측정·환류                    │
   └──────────────────────────────────────────────────────────┘
영역내용핵심 질문
① 전략적 정합성IT 전략과 비즈니스 전략의 일치, IT 계획과 사업 계획의 연계, 상호 이해"IT가 사업 목표를 지원하는가"
② 가치 전달IT 투자가 약속한 편익을 실제로 실현, 비용 최적화, 투자 효과 검증"투자한 만큼 가치를 얻는가"
③ 위험 관리IT 위험(보안·가용성·컴플라이언스)의 식별·평가·통제, 위험 수용 수준 설정"위험을 감당 가능한 수준으로 관리하는가"
④ 자원 관리IT 인력·인프라·데이터·애플리케이션의 최적 배분과 활용"자원을 효율적으로 쓰는가"
⑤ 성과 측정전략 이행·서비스 수준·가치 실현의 측정과 모니터링(BSC·KPI)"성과를 어떻게 증명하는가"

2. 실행 구성요소 (구조·프로세스·관계 메커니즘)​

구분구성요소내용
구조
(Structure)		IT 운영위원회(IT Steering Committee)투자 우선순위·예산 심의·승인(경영진 참여)
CIO·CISO·CDOIT·보안·데이터에 대한 책임 임원
아키텍처 위원회, CCB기술 표준·변경 통제
조직 구조중앙집중 / 분산 / 연합형(Federated)
프로세스
(Process)		IT 전략계획(ISP)사업 전략과 연계된 IT 로드맵
IT 투자관리·포트폴리오투자 심의, 사업 선정·중단 결정
IT 서비스 관리(ITSM)서비스 수준·변경·문제 관리
위험·컴플라이언스 관리정보보호 관리체계(ISMS-P), 감사
성과 관리KPI 정의·측정·보고
관계
(Relational)		소통·협업 체계현업–IT 간 정기 협의체, 파트너십
교육·문화IT 이해도 제고, 공동 목표 인식
인센티브성과 연계 보상

3. 주요 프레임워크​

프레임워크초점
COBITIT 거버넌스의 대표 표준 — 거버넌스(EDM)와 관리(APO·BAI·DSS·MEA) 분리, 목표 연계(Goals Cascade)
ITILIT 서비스 관리(ITSM) 모범사례
ISO/IEC 38500IT 거버넌스 국제표준 — 6원칙(책임·전략·취득·성과·적합성·인간행동), EDM 모델
ISO/IEC 20000IT 서비스 관리 인증 표준
BSC성과 측정·전략 실행 도구
ISO 31000 / ISMS-P위험 관리 / 정보보호 관리체계

Ⅲ. 나. IT 거버넌스 효과 측정 지표​

1. BSC 4대 관점별 지표 체계​

   ┌──────────────── **IT BSC 4대 관점** ────────────────┐
   │ **① 기업 기여도**(Corporate Contribution)            │
   │    "IT가 사업 가치에 얼마나 기여했는가" — 경영진 관점 │
   │ **② 고객(이용자) 지향**(User Orientation)            │
   │    "이용자가 만족하는가" — 현업 관점                  │
   │ **③ 운영 우수성**(Operational Excellence)            │
   │    "효율적으로 운영되는가" — IT 운영 관점             │
   │ **④ 미래 지향**(Future Orientation)                  │
   │    "미래 역량을 갖추는가" — 학습·성장 관점            │
   └────────────────────────────────────────────────────┘
관점측정 지표
① 기업 기여도· IT 투자수익률(ROI), NPV, IRR, 회수기간
· 매출 대비 IT 투자 비율, IT 비용 절감액
· 전략 과제 달성률, IT 투자의 사업 목표 기여도
· 신규 사업·서비스의 IT 기여 매출
② 고객(이용자) 지향· 이용자 만족도(정기 설문), NPS
· SLA 준수율, 서비스 요청 처리 시간
· 시스템 활용률·이용 빈도
· 현업 요구사항 반영률·리드타임
③ 운영 우수성· 시스템 가용률(99.9%), 장애 건수·MTTR
· 배포 빈도·변경 실패율(DORA 지표)
· 프로젝트 일정·예산 준수율
· 자원 활용률, 단위 업무당 IT 비용
· 보안 사고 건수, 취약점 조치율, 컴플라이언스 준수율
④ 미래 지향· IT 인력 역량·자격 보유율, 교육 이수 시간
· 신기술 도입·적용률, R&D 투자 비율
· 아키텍처 표준 준수율, 기술부채 수준
· IT 인력 이직률, 직무 만족도

2. 영역별 지표 매핑​

IT 거버넌스 영역대표 측정 지표
전략적 정합성사업전략 연계 과제 비율, IT 투자 중 전략 과제 비중, ISP 이행률
가치 전달투자 대비 편익 실현률(사후 평가), ROI, 프로젝트 성공률
위험 관리보안 사고 건수·손실액, 위험 평가 수행률, 잔여 위험 수준, 감사 지적사항 조치율
자원 관리자원 활용률, IT 인력 1인당 지원 사용자 수, 자산 현황 정확도
성과 측정KPI 달성률, 정기 보고 이행률, 성숙도 수준

Ⅳ. 다. IT 거버넌스 효과 측정 방법론​

1. 주요 방법론 개관​

   ┌────────────────────────────────────────────────────────┐
   │ **① 성숙도 모델**   : "우리 수준은 어느 단계인가"(정성)  │
   │ **② IT BSC**       : "전략이 실행되는가"(균형 성과)      │
   │ **③ 재무 평가**    : "투자 가치가 있는가"(정량)          │
   │ **④ 벤치마킹**     : "타사 대비 어떤가"(상대 평가)       │
   │ **⑤ 감사·진단**    : "규정을 준수하는가"(적합성)         │
   └────────────────────────────────────────────────────────┘

2. ① 성숙도 모델 (Maturity Model)​

항목내용
개념거버넌스 프로세스의 성숙 수준을 단계로 평가하여 현 수준과 목표 수준의 격차(Gap)를 도출
모델COBIT 성숙도 모델(0~5단계: 부재–초기–반복–정의–관리–최적화)
CMMI, ISO/IEC 33000(SPICE)
절차평가 범위 정의 → 프로세스별 현 수준 진단(인터뷰·문서 검토) → 목표 수준 설정 → 격차 분석 → 개선 로드맵
장점개선 방향이 명확, 타 조직과 비교 가능, 경영진 소통 용이
한계정성적 평가로 주관 개입, 수준 상승이 곧 성과 향상은 아님

3. ② IT BSC (Balanced Scorecard)​

   [전략 맵(Strategy Map) — 인과관계 연결]
   **④ 미래 지향**(역량 확보) ──► **③ 운영 우수성**(효율·품질)
                                        │
                                        ▼
                            **② 이용자 지향**(만족도 향상)
                                        │
                                        ▼
                            **① 기업 기여도**(가치 창출)
   ⇒ 하위 관점의 개선이 상위 관점 성과로 이어지는 **인과 논리**를 검증
항목내용
개념재무 지표에 편중되지 않고 4대 관점의 균형 있는 성과 측정, 전략과 실행의 연결
절차① 비전·전략 정의 → ② 관점별 전략 목표 도출 → ③ 인과관계(전략 맵) 구성 → ④ KPI·목표치 설정 → ⑤ 실행과제 정의 → ⑥ 측정·환류
장점전략과 지표의 논리적 연결, 단기·장기 균형, 비재무 가치 반영
한계KPI 설정·데이터 수집 부담, 인과관계 검증 곤란

4. ③ 재무적 평가 방법​

기법내용
ROI(투자수익률)(편익 − 비용) / 비용 × 100 — 직관적이나 무형 효과 반영 곤란
NPV(순현재가치)미래 현금흐름을 현재가치로 할인 후 투자비 차감 — 0보다 크면 타당
IRR(내부수익률)NPV=0이 되는 할인율 — 자본비용과 비교
회수기간(Payback)투자비 회수 소요 기간 — 단순·직관적, 회수 이후 효과 미반영
TCO(총소유비용)도입·운영·폐기까지 전 생애주기 비용 — 클라우드 전환 판단에 필수
TVO / IETotal Value of Opportunity, 정보경제학(Information Economics) — 무형 가치·위험 가중치 반영
EVA(경제적 부가가치)세후영업이익 − 자본비용 — 주주 가치 관점
실물옵션(Real Option)불확실성 하의 미래 선택권 가치 반영(신기술 투자 평가)

5. ④ 벤치마킹 / ⑤ 감사·진단​

방법론내용
벤치마킹동종 업계 IT 투자 비율·서비스 수준·인력 규모 비교(Gartner·IDC 지표), 상대적 위치 파악
IT 감사정보시스템 감리, 내부 감사, 외부 회계감사의 IT 부문 — 규정 준수와 통제 유효성 검증
인증·심사ISO/IEC 20000(서비스), ISMS-P(보안), ISO 27001 — 제3자 검증을 통한 객관성 확보
국내 제도정보시스템 운영 성과평가, IT 투자성과 평가, EA 성숙도 평가

6. 방법론 비교 및 통합 적용​

비교 기준성숙도 모델IT BSC재무 평가벤치마킹감사·인증

Ⅴ. 결론​

IT 거버넌스의 본질은 "IT에 대한 의사결정 권한과 책임을 명확히 하여, IT가 사업 가치에 기여하도록 방향을 잡고 감독하는 것" 이며, 그 성패는 경영진의 실질적 참여에 달려 있다. IT 부서만의 활동으로는 전략적 정합성을 확보할 수 없기 때문이다.

효과 측정에서 유의할 점은 재무 지표만으로는 IT의 가치를 온전히 측정할 수 없다는 것이다. 보안 강화·품질 향상·역량 축적 같은 무형 효과가 IT 가치의 상당 부분을 차지하므로, IT BSC로 4대 관점을 균형 있게 측정하고 성숙도 모델로 프로세스 역량을, 재무 평가로 개별 투자를 검증하는 다면적 접근이 필요하다.

실무적으로는 ① 측정 지표를 과도하게 늘리지 말고 전략과 직결된 핵심 지표에 집중하고, ② 사전 평가뿐 아니라 사후 편익 실현 검증(Benefit Realization) 을 반드시 수행하며, ③ 측정 결과를 투자 우선순위 조정과 개선 과제로 환류하는 순환 체계를 갖추어야 한다. 측정 자체가 목적이 되면 거버넌스는 형식화되고 만다.
