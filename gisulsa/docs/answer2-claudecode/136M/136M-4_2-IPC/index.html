IPC(Inter Process Communication, 프로세스 간 통신)

Ⅰ. 개요​

1. IPC의 필요성​

운영체제는 프로세스마다 독립된 주소공간을 할당하여 상호 침범을 차단한다. 이 격리는 안정성과 보안을 보장하지만, 동시에 프로세스 간 데이터 교환을 불가능하게 만든다. 따라서 OS가 안전하게 통제된 통신 수단을 제공해야 하며, 이것이 IPC이다.

Ⅱ. 가. IPC의 개념과 목적​

1. 개념​

IPC는 서로 독립된 주소공간을 갖는 프로세스들이 데이터를 교환하고 동작을 동기화할 수 있도록 운영체제가 제공하는 메커니즘이다.

   [프로세스 격리와 IPC]
   ┌──── Process A ────┐          ┌──── Process B ────┐
   │  독립된 주소공간   │   ✕직접  │  독립된 주소공간   │
   │  (Code/Data/Heap/ │  접근불가 │  (Code/Data/Heap/ │
   │   Stack)          │          │   Stack)          │
   └─────────┬─────────┘          └─────────┬─────────┘
             │                              │
             └──────► **커널(OS) 제공 IPC** ◄┘
                파이프 / 메시지 큐 / 공유 메모리 / 소켓 / 시그널

2. IPC의 목적​

목적내용
① 데이터 전달·공유프로세스 간 정보 교환(계산 결과, 명령, 상태)
② 동기화(Synchronization)실행 순서 제어 및 공유 자원의 상호배제
③ 이벤트 통지특정 사건 발생을 다른 프로세스에 알림(시그널)
④ 자원 공유메모리·파일 등 자원을 여러 프로세스가 공유
⑤ 모듈화·계산 속도 향상기능을 여러 프로세스로 분할하여 병렬 처리, 유지보수성 향상
⑥ 안정성·보안통제된 경로로만 통신 → 한 프로세스 장애가 전체로 확산되지 않음(브라우저 탭 분리, MSA)
⑦ 편의성서로 다른 언어·플랫폼으로 작성된 프로그램 간 협업

3. IPC의 분류​

   ┌──────────────── IPC 분류 ────────────────┐
   │ **① 메시지 전달(Message Passing) 방식**   │
   │    파이프, 메시지 큐, 소켓, 시그널        │
   │    · 커널을 경유 → **안전하나 복사 오버헤드**│
   │    · 동기화가 상대적으로 단순              │
   ├───────────────────────────────────────────┤
   │ **② 공유 메모리(Shared Memory) 방식**     │
   │    공유 메모리, 메모리 맵 파일             │
   │    · 커널 경유 없음 → **가장 빠름**         │
   │    · **동기화를 직접 구현해야 함**          │
   └───────────────────────────────────────────┘
   ※ 통신 범위 : **로컬(동일 시스템)** vs **원격(네트워크 — 소켓·RPC)**

Ⅲ. 나. IPC 주요 기법 3가지​

1. 공유 메모리(Shared Memory)​

  • 개념: 여러 프로세스가 동일한 물리 메모리 영역을 각자의 주소공간에 매핑하여 공유하는 방식. 커널을 거치지 않고 직접 읽고 쓰므로 가장 빠르다.
   ┌──── Process A ────┐              ┌──── Process B ────┐
   │  가상 주소공간     │              │  가상 주소공간     │
   │   ┌───────────┐   │              │   ┌───────────┐   │
   │   │ 매핑 영역  │───┼──┐      ┌────┼───│ 매핑 영역  │   │
   │   └───────────┘   │  │      │    │   └───────────┘   │
   └───────────────────┘  ▼      ▼    └───────────────────┘
                    ┌──────────────────┐
                    │ **물리 공유 메모리**│  ← 커널이 생성, 양쪽에 매핑
                    └──────────────────┘
   [흐름] shmget/shm_open(생성) → shmat/mmap(매핑) → **직접 read/write**
          → shmdt(해제) → shmctl(제거)
   ⚠ **동기화 없이 동시 접근 시 데이터 훼손** → 세마포어·뮤텍스 필수 병행
항목내용
장점최고 속도(커널 개입·데이터 복사 없음), 대용량 데이터 교환에 최적
단점동기화를 직접 구현해야 함(가장 큰 부담), 한 프로세스의 오류가 공유 데이터 훼손, 로컬 전용
활용DBMS 버퍼 캐시, 대용량 영상·이미지 처리, 고성능 서버, 프로세스 간 대량 데이터 전달

2. 메시지 큐(Message Queue)​

  • 개념: 커널이 관리하는 큐 자료구조에 메시지를 넣고 꺼내는 방식. 메시지에 타입(Type) 을 부여할 수 있어 선택적 수신이 가능하며, 비동기 통신을 지원한다.
   Process A(송신)                                 Process B(수신)
       │  msgsnd(타입 1, "데이터")                      │
       └──────────► ┌──── **커널 메시지 큐** ────┐ ◄────┘
                    │ [타입1|메시지] [타입2|메시지]│  msgrcv(타입 1)
                    │ [타입1|메시지] ...          │  → **타입 1만 선택 수신 가능**
                    └────────────────────────────┘
   [특징] · **비동기** : 송신자는 수신자를 기다리지 않고 계속 실행
          · **영속성** : 프로세스가 종료되어도 큐와 메시지는 커널에 유지
          · **메시지 경계 보존** : 스트림이 아닌 단위(레코드) 전송
항목내용
장점비동기·느슨한 결합, 메시지 타입별 선택 수신, 메시지 경계 유지, 다대다 통신 가능, 송수신 시점 분리
단점커널을 경유하는 복사 오버헤드(공유 메모리보다 느림), 메시지 크기·큐 용량 제한, 큐 관리 필요
활용작업 큐(Job Queue), 로그 수집, 이벤트 처리, 분산 시스템의 메시지 브로커(Kafka·RabbitMQ)로 개념 확장

3. 파이프(Pipe)​

  • 개념: 한 프로세스의 출력을 다른 프로세스의 입력으로 연결하는 단방향 데이터 스트림 통로. 커널 버퍼를 이용하며, 파일 디스크립터로 접근한다.
   [익명 파이프(Anonymous Pipe)] — **부모-자식 등 혈연 관계 프로세스 간**
   Process A ──write(fd[1])──► ┌── 커널 버퍼 ──┐ ──read(fd[0])──► Process B
                               └───────────────┘
   예) 쉘 파이프라인 :  `ps -ef | grep java | wc -l`

   [명명 파이프(Named Pipe / FIFO)] — **무관한 프로세스 간에도 사용 가능**
   파일 시스템에 **경로를 가진 특수 파일**로 존재 (mkfifo)
   Process A ──► /tmp/myfifo ──► Process B   (서로 관계 없어도 통신 가능)
항목내용
장점구현이 매우 단순, 파일 I/O 인터페이스 그대로 사용, 커널이 동기화 자동 처리(버퍼 가득 차면 블로킹)
단점기본적으로 단방향(양방향은 파이프 2개 필요), 익명 파이프는 혈연 관계 제한, 버퍼 크기 제한, 데이터가 스트림이라 메시지 경계가 없음
활용쉘 명령어 연결, 부모-자식 프로세스 간 결과 전달, 로그 스트림 전달

4. 기타 주요 IPC 기법​

기법내용
소켓(Socket)네트워크를 통한 통신 — 서로 다른 시스템 간 통신 가능. TCP/UDP 소켓, 유닉스 도메인 소켓(로컬 고속) → 분산 시스템·MSA의 기반
시그널(Signal)이벤트 발생을 비동기적으로 통지(SIGINT·SIGTERM·SIGKILL) — 데이터 전달 불가, 단순 알림용
RPC / gRPC원격 프로시저를 로컬 함수처럼 호출 — 분산 환경의 고수준 IPC
메모리 맵 파일파일을 메모리에 매핑하여 공유(mmap)

5. 기법 비교​

비교 기준공유 메모리메시지 큐파이프소켓
속도가장 빠름보통보통느림(네트워크)
커널 경유매핑 후 없음있음있음있음
방향성양방향양방향단방향양방향
동기화직접 구현 필수커널이 처리커널이 처리커널이 처리
데이터 형태메모리 블록메시지 단위스트림스트림/데이터그램
통신 범위로컬로컬로컬원격 가능
결합도강함약함(비동기)중간약함
데이터 크기대용량 적합제한 있음버퍼 제한제한 없음
적합 상황대량 데이터 고속 교환비동기 작업 분배단순 순차 처리분산 시스템

Ⅳ. 다. 공유 자원의 충돌·일관성 문제 해결을 위한 동기화 기법​

1. 문제 상황 — 경쟁 조건(Race Condition)​

   [문제] 공유 변수 count = 10 에 대해 두 프로세스가 동시에 증가 연산

   Process A                    Process B
   ① read count (10)
                                ② read count (10)   ← 아직 A가 저장 전
   ③ count = 10 + 1 = 11
                                ④ count = 10 + 1 = 11
   ⑤ write count (11)
                                ⑥ write count (11)
   ⇒ 두 번 증가했으므로 **12**여야 하지만 결과는 **11** — **갱신 손실**

   [원인] `count++` 는 원자적이지 않음(읽기 → 연산 → 쓰기의 3단계)
   [해결] **임계구역(Critical Section)** 을 상호배제로 보호

2. 임계구역 문제의 해결 요건​

요건내용
상호배제(Mutual Exclusion)임계구역에는 최대 1개 프로세스만 진입
진행(Progress)임계구역이 비어 있으면 대기자 중 하나는 반드시 진입
한정 대기(Bounded Waiting)기아(Starvation) 없이 유한 시간 내 진입 보장

3. 주요 동기화 기법​

(1) 뮤텍스(Mutex)​

   lock(m)   : m이 unlocked → locked 전환 후 진입
               m이 locked   → 대기(Blocking) 또는 회전(Spin)
   [임계구역 수행]
   unlock(m) : **소유한 스레드만 해제 가능**(Ownership)
항목내용
개념상호배제 전용의 이진 잠금 객체 — 소유권(Ownership) 개념 보유
구현Test-and-Set, CAS(Compare-And-Swap) 등 하드웨어 원자 명령
장점구현 단순, 오버헤드 작음, 소유권으로 오용 방지
단점자원 1개만 관리, 스핀락은 CPU 낭비, 우선순위 역전 발생 가능
활용공유 변수·자료구조 보호

(2) 세마포어(Semaphore)​

   **P(wait) 연산**              **V(signal) 연산**
   S = S − 1;                    S = S + 1;
   if (S < 0)                    if (S ≤ 0)
       block(대기큐 삽입);           wakeup(대기큐에서 1개 깨움);
   ※ P·V 연산은 반드시 **원자적(Atomic)** 으로 수행

   [생산자-소비자 문제 적용]
   세마포어 : empty = N(빈 슬롯), full = 0(찬 슬롯), mutex = 1
   [Producer]              [Consumer]
   P(empty);               P(full);
   P(mutex);               P(mutex);
     버퍼에 삽입              버퍼에서 추출
   V(mutex);               V(mutex);
   V(full);                V(empty);
   ⇒ **계수 세마포어(empty·full)는 순서 제어**, **이진 세마포어(mutex)는 상호배제**
항목내용
개념정수 카운터 기반 동기화 도구 — 최대 N개 프로세스의 동시 접근 허용
유형이진 세마포어(초기값 1, 상호배제) / 계수 세마포어(초기값 N, 자원 풀 관리)
장점다중 자원 관리, 실행 순서 제어(Signaling) 가능, 프로세스 간(IPC) 사용 가능
단점소유권 없음 → 다른 프로세스가 V 연산 가능(오용), P/V 누락·순서 오류 시 교착상태·기아
활용DB 커넥션 풀, 생산자-소비자, 프로세스 간 동기화

(3) 모니터(Monitor)​

   monitor SharedResource {
       shared_data;                 ← 외부 직접 접근 불가(캡슐화)
       condition c;                 ← 조건변수

       procedure P1() { ... c.wait();   ... }   // 잠금 반납 후 대기
       procedure P2() { ... c.signal(); ... }   // 대기자 1개 깨움
   }
   ┌──── 진입 큐 ────┐
   │ P1 P2 P3 → **1개만 내부 진입**(컴파일러·런타임이 자동 보장) │
   └─────────────────┘
   ※ **Mesa 방식**(signal-and-continue) : 깨어난 후 조건 재확인 필요
     → 반드시 **`while` 루프로 조건 검사**(if 사용 시 Lost Wakeup 위험)
항목내용
개념공유 데이터와 조작 프로시저를 하나의 캡슐로 묶고, 상호배제를 언어·컴파일러가 자동 보장하는 고수준 동기화 구조체
장점상호배제 자동 보장, 캡슐화로 오용 방지, 가독성·유지보수성 우수
단점언어·런타임 지원 필요, 유연성 낮음
구현 사례Java synchronized + wait()/notify(), C# lock/Monitor, Python threading.Condition

5. 기타 동기화 기법 및 고려사항​

기법내용
스핀락(Spinlock)대기하지 않고 회전 — 임계구역이 매우 짧을 때(커널) 효율적
읽기-쓰기 락(RW Lock)읽기는 동시 허용, 쓰기는 배타 → 읽기 위주 워크로드 성능 향상

파일 락(flock/fcntl)프로세스 간 파일 단위 잠금
분산 락Redis·ZooKeeper 기반 — 분산 시스템의 상호배제
문제대응 방안

Ⅴ. 결론​

IPC는 프로세스 격리라는 안정성의 이점을 유지하면서도 협업을 가능하게 하는 운영체제의 핵심 메커니즘이며, 기법 선택은 속도·데이터 크기·결합도·통신 범위의 Trade-off에 따라 결정된다. 즉 대용량 고속 교환은 공유 메모리, 비동기 느슨한 결합은 메시지 큐, 단순 순차 연결은 파이프, 원격 통신은 소켓이 적합하다.

특히 공유 메모리는 가장 빠른 대신 동기화를 전적으로 개발자가 책임져야 한다는 점이 핵심이며, 이 지점에서 뮤텍스·세마포어·모니터 등 동기화 기법이 필수적으로 결합된다. 세마포어는 표현력이 가장 크지만 P/V 연산의 오용으로 교착상태를 유발하기 쉬우므로, 실무에서는 모니터나 언어가 제공하는 고수준 병행 도구를 우선 사용하는 것이 바람직하다.

나아가 최근에는 마이크로서비스 아키텍처에서 프로세스 간 통신이 네트워크 기반(gRPC·메시지 브로커)으로 확장되면서, 로컬 IPC의 개념이 분산 시스템의 통신 패턴으로 발전하고 있다. 이 경우 동기화 문제 역시 분산 락과 최종적 일관성 문제로 확장되므로, IPC와 동기화의 기본 원리를 이해하는 것은 분산 시스템 설계의 토대가 된다.
