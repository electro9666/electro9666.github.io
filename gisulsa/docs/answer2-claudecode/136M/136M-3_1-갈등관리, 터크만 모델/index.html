IT 프로젝트의 갈등관리와 터크만 팀 발달 모델

Ⅰ. 개요​

1. 프로젝트에서 갈등의 불가피성​

IT 프로젝트는 다양한 이해관계자(발주자·현업·개발자·협력사) 가 제한된 자원과 일정 안에서 협업하므로, 갈등은 예외가 아니라 필연적 현상이다. PMBOK도 갈등을 프로젝트 관리의 정상적 요소로 규정하며, PM의 핵심 역량으로 갈등 관리(Conflict Management) 를 제시한다.

2. 갈등 인식의 변화​

   [전통적 관점]  갈등 = 나쁜 것 → **제거 대상**
        ↓
   [인간관계 관점] 갈등 = 자연스러운 것 → 수용
        ↓
   [**상호작용 관점**(현대)] 갈등 = **적정 수준에서는 성과를 촉진** → **관리 대상**

Ⅱ. 가. 갈등과 프로젝트 성과의 관계​

1. 갈등 수준과 성과의 관계 — 역U자 곡선​

   프로젝트
    성과 │              ┌─────╮  ← **최적 갈등 수준**
         │            ╱         ╲
         │          ╱             ╲
         │        ╱                 ╲
         │      ╱                     ╲
         └────┴───────────┴─────────────┴──────► 갈등 수준
           **과소 갈등**   **적정 갈등**   **과다 갈등**
           (A 구간)        (B 구간)       (C 구간)
구간갈등 수준조직 특성성과
A: 과소낮음무관심·침체, 집단사고(Groupthink), 변화 저항, 문제 은폐낮음
B: 적정중간활발한 토론, 다양한 대안 검토, 창의적 문제해결, 자기 점검최고
C: 과다높음대립·불신, 의사소통 단절, 정치화, 인력 이탈낮음

2. 갈등의 유형별 영향​

유형내용성과에 미치는 영향
순기능적 갈등(Functional / Task Conflict)과업·기술·방법론에 대한 견해 차이긍정 — 더 나은 대안 도출, 리스크 사전 식별, 의사결정 품질 향상
역기능적 갈등(Dysfunctional / Relationship Conflict)감정·인격·신뢰에 관한 대립부정 — 팀워크 붕괴, 정보 공유 중단, 이직·사기 저하
프로세스 갈등역할·책임·절차에 대한 이견초기에는 긍정, 지속되면 부정

PM의 핵심 과제: 갈등을 없애는 것이 아니라, ① 과업 갈등은 활성화하고, ② 관계 갈등으로 전이되지 않도록 차단하며, ③ 적정 수준으로 조절하는 것이다.

3. IT 프로젝트에서의 구체적 영향​

영향 영역순기능역기능
품질설계 대안 검토로 아키텍처 품질 향상검토 회피·형식적 합의로 결함 잠복
일정위험 조기 식별로 지연 예방의사결정 지연, 재작업 증가
범위요구사항 명확화과업 변경 분쟁, 범위 확대(Scope Creep)
팀상호 학습·역량 향상핵심 인력 이탈, 생산성 급감

Ⅲ. 나. 갈등의 요인과 해결 전략​

1. 갈등의 주요 요인​

   [갈등 발생 빈도 — Thamhain & Wilemon 연구 기준]
   ① **일정(Schedule)**        ← 가장 빈번
   ② **우선순위(Priority)**
   ③ **인적 자원(Manpower)**
   ④ 기술적 견해(Technical Opinion)
   ⑤ 관리 절차(Procedure)
   ⑥ 원가(Cost)
   ⑦ 개인적 성향(Personality) ← 빈도는 낮으나 **해결이 가장 어려움**
구분요인IT 프로젝트에서의 구체적 양상
과업 관련일정 압박비현실적 납기, 지연에 따른 책임 공방
자원 경쟁핵심 개발자·인프라 자원의 배분 갈등
우선순위 충돌현업 부서 간 요구사항 우선순위 대립
기술적 견해 차이아키텍처·프레임워크 선정, 신기술 도입 여부
관계·구조역할·책임 모호R&R 불명확 → 업무 떠넘기기, 중복
의사소통 부족정보 비대칭, 왜곡·지연된 정보 전달
조직 문화 차이발주사–수행사, 정규직–협력사 간 문화 충돌
다중 보고 체계매트릭스 조직에서 기능 관리자와 PM의 지시 충돌
이해관계요구사항 변경과업 범위·추가 비용에 대한 발주자–수행사 대립
목표 불일치발주자(품질·기능) vs 수행사(수익성·일정)
성과 평가·보상기여도 인정, 인센티브 배분

2. 갈등 해결 전략 — Thomas-Kilmann 모델​

   자기 주장(Assertiveness)
      높음 │  **경쟁**(Force)          **협력**(Collaborate)
           │   내가 이긴다              **모두가 이긴다(Win-Win)**
           │
           │            **타협**(Compromise)
           │             일부씩 양보(Lose-Lose 가능)
           │
      낮음 │  **회피**(Withdraw)       **수용**(Accommodate)
           │   미루기·철수              상대에게 양보
           └─────────────────────────────────────────► 협력(Cooperativeness)
                낮음                              높음
전략내용적용 상황결과
협력·문제해결
(Collaborate / Confront)		근본 원인을 규명하고 모두가 만족하는 해법 도출중요하고 시간 여유가 있을 때, 장기 관계가 중요할 때Win-Win — PMBOK 권장 최선의 방법
타협
(Compromise / Reconcile)		양측이 일부씩 양보하여 중간점 합의힘이 대등, 시간 제약, 임시 해결 필요Lose-Lose(부분 만족)
강요·경쟁
(Force / Direct)		권한으로 한쪽 입장 관철긴급 상황, 안전·법규 문제, 신속 결정 필요Win-Lose — 감정 앙금 잔존
완화·수용
(Smooth / Accommodate)		차이보다 공통점을 강조, 상대에 양보사안이 사소하거나 관계 유지가 더 중요Lose-Win(일시적)
회피·철수
(Withdraw / Avoid)		갈등 상황에서 물러남·연기사소한 사안, 냉각기 필요, 정보 부족근본 미해결 — 최후의 수단

Ⅳ. 다. 터크만(Tuckman)의 팀 발달 5단계 모델​

1. 개념​

터크만 모델(1965, 1977년 5단계로 확장)은 팀이 형성되어 성과를 내기까지 거치는 발달 단계를 설명하는 모델로, 각 단계별 갈등의 양상과 리더십 스타일이 달라져야 함을 시사한다.

2. 5단계 상세​

   성과 │                                    ┌──────╮
        │                              ╱─────┘      │
        │                        ╱────                ╲
        │        ╲          ╱───                        ╲
        │  ╲      ╲    ╱───                              ╲
        └───┴──────┴────────┴──────────┴──────────┴────────► 시간
        **Forming  Storming  Norming   Performing  Adjourning**
         (형성기)  (**격동기**) (규범기)  (성과기)   (해산기)
                    ▲ 갈등 최고조 — **PM 개입이 가장 중요한 시점**
단계특징팀원의 상태갈등 양상PM의 역할·리더십
① 형성기
(Forming)		팀 구성 초기, 상호 탐색불안·기대 공존, 예의를 지키며 갈등 회피, PM에 의존표면적 갈등 없음(잠재)지시형(Directing) — 목표·역할·규칙 명확 제시, 방향 제공, 상호 소개
② 격동기
(Storming)		갈등이 표면화되는 가장 어려운 단계역할·권한 다툼, 방법론 이견, 리더십에 대한 저항, 하위 그룹 형성갈등 최고조 — 과업·관계 갈등 동시 발생, 이 단계를 넘지 못하면 팀 실패코칭형(Coaching) — 갈등을 억압하지 말고 표출·중재, 경청과 조정, 공동 목표 재확인, 문제해결 전략 적용
③ 규범기
(Norming)		규범·역할 정립, 응집력 형성상호 신뢰 형성, 협력 시작, 팀 정체성 확립갈등 감소, 건설적 논의로 전환지원형(Supporting) — 참여 유도, 규범 정착 지원, 의사결정 위임 시작
④ 성과기
(Performing)		최고 생산성 발휘자율적 문제해결, 상호 보완, 높은 몰입순기능적(과업) 갈등만 존재위임형(Delegating) — 권한 위임, 장애 요소 제거, 성과 인정·동기 부여
⑤ 해산기
(Adjourning)		프로젝트 종료·팀 해체성취감과 상실감 공존, 미래 불안갈등보다 정서적 이슈마무리 지원 — 성과 인정·포상, 교훈 정리, 지식 이전, 경력 전환 지원

3. 모델의 실무적 시사점​

시사점내용
격동기는 필수 과정격동기를 회피하거나 억압하면 갈등이 잠복해 후반부에 더 크게 폭발 → 초기에 표출·해소시키는 것이 유리
리더십 스타일 전환단계에 따라 지시 → 코칭 → 지원 → 위임으로 전환(상황적 리더십). 성과기에도 지시형을 유지하면 팀 자율성 저해
단계 역행 가능팀원 교체·범위 변경·PM 교체 시 이전 단계로 회귀 → 재형성 과정 필요
단계 가속킥오프 워크숍, 팀 빌딩, 그라운드 룰 조기 수립으로 형성기·격동기 단축 가능
IT 프로젝트 적용단기 프로젝트·프리랜서 중심 팀은 성과기 도달 전 종료되는 경우가 많음 → 초기 단계 관리의 중요성 더욱 큼

Ⅴ. 결론​

프로젝트 갈등은 제거해야 할 병리 현상이 아니라, 적정 수준에서 관리되면 오히려 의사결정 품질을 높이는 자원이다. 따라서 PM의 역할은 갈등의 제거가 아니라 ① 과업 갈등은 촉진하되 관계 갈등으로의 전이를 차단하고, ② 역U자 곡선의 최적 구간을 유지하는 것이다.

해결 전략 측면에서는 문제해결(협력) 전략이 근본적이고 지속가능한 최선이며, 회피·강요는 갈등을 일시적으로 덮을 뿐이므로 긴급 상황 등 제한적으로만 사용해야 한다. 무엇보다 갈등의 상당수는 역할 모호성과 의사소통 부족에서 비롯되므로, RACI와 의사소통 계획을 통한 사전 예방이 사후 해결보다 훨씬 효과적이다.

아울러 터크만 모델이 시사하듯 격동기의 갈등은 팀이 성숙하기 위한 필수 관문이므로, PM은 이를 억압하지 말고 적극적으로 표면화하여 중재하고, 팀 성숙도에 맞추어 지시형에서 위임형으로 리더십을 전환해야 한다. 결국 갈등 관리 역량은 기술적 관리 기법이 아니라 PM의 대인관계·리더십 역량의 문제이며, 이것이 프로젝트 성공을 좌우하는 핵심 요소이다.
