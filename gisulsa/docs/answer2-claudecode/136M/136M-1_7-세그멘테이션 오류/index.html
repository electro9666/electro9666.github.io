세그멘테이션 오류(Segmentation Fault)

Ⅰ. 개요​

세그멘테이션 오류는 프로세스가 접근 권한이 없거나 할당되지 않은 메모리 영역에 접근할 때, MMU(메모리 관리 장치) 가 이를 탐지하여 커널에 알리고 커널이 SIGSEGV 시그널로 프로세스를 강제 종료시키는 메모리 보호 오류이다.

Ⅱ. 발생 메커니즘​

   [메모리 접근 시 검사 흐름]
   프로세스가 주소 접근 → **MMU가 페이지 테이블 조회**
        │
        ├─ 매핑 없음 / 권한 위반(R·W·X) → **페이지 폴트 발생**
        │        │
        │        └─► 커널 판단 : 정상적 요구 페이징? ──► 페이지 적재(정상)
        │                        **불법 접근?** ──► **SIGSEGV 전달 → 프로세스 종료**
        └─ 정상 → 접근 허용

   [프로세스 주소공간과 위반 사례]
   Stack  ← 스택 오버플로(무한 재귀)로 가드 페이지 침범
   Heap   ← 해제된 포인터(UAF)·이중 해제·힙 오버플로
   Data
   **Code(읽기 전용)** ← 문자열 상수 수정 시도
   **NULL 페이지(0번지)** ← **NULL 포인터 역참조**(가장 흔한 원인)

Ⅲ. 주요 원인과 대응 방안​

원인사례대응
NULL 포인터 역참조p = NULL; *p = 10;포인터 사용 전 NULL 검사
댕글링 포인터(UAF)free(p) 후 *p 접근해제 후 p = NULL, 스마트 포인터
버퍼 오버플로배열 범위 초과 접근경계 검사, strncpy·안전 함수 사용
읽기 전용 영역 수정char *s="abc"; s[0]='A';const 사용, 배열로 선언
스택 오버플로무한 재귀, 거대 지역 배열재귀 깊이 제한, 힙 할당 전환
초기화되지 않은 포인터쓰레기 값 참조선언 시 초기화
이중 해제(Double Free)free(p) 2회해제 후 NULL 대입
진단 도구내용
GDB코어 덤프(core) 분석으로 오류 발생 지점·스택 추적
Valgrind메모리 누수·잘못된 접근 동적 탐지
ASan(AddressSanitizer)컴파일러 삽입 계측으로 고속 탐지(-fsanitize=address)
정적 분석Coverity·cppcheck로 사전 탐지

Ⅳ. 결론​

세그멘테이션 오류는 버그가 아니라 OS의 메모리 보호가 정상 작동한 결과이며, 이를 통해 프로세스 간 침범과 시스템 손상을 막는다. 다만 동일한 메모리 오류가 탐지되지 않으면 곧 보안 취약점(RCE) 이 되므로, ① 해제 후 NULL 대입·경계 검사 등 방어적 코딩, ② ASan·Valgrind를 CI에 통합한 상시 검증, ③ 근본적으로는 Rust의 소유권 모델처럼 언어 차원에서 메모리 안전성을 강제하는 접근이 확산되고 있다.
