VXLAN

문제​

8.VXLAN(Virtual eXtensible LAN)

Ⅰ. 개요​

VXLAN(Virtual eXtensible LAN) 은 L2 이더넷 프레임을 L3 UDP 패킷에 캡슐화(MAC-in-UDP) 하여 IP 네트워크 위에 가상의 L2 오버레이 네트워크를 구성하는 네트워크 가상화 기술이다(RFC 7348). 24bit VNI(VXLAN Network Identifier) 를 사용하여 약 1,600만 개(2²⁴) 의 논리 네트워크를 제공한다.

   [등장 배경 — 기존 VLAN의 한계]
   ① **VLAN ID 12bit → 최대 4,094개** ⇒ 대규모 멀티테넌트 클라우드에 부족
   ② **L2 도메인이 물리 스위치에 종속** ⇒ **VM 라이브 마이그레이션 제약**
      (다른 랙·다른 DC로 이동 시 IP/MAC 유지 불가)
   ③ **STP(Spanning Tree)** 로 인해 **링크 절반이 유휴** ⇒ 대역폭 낭비
   ④ 스위치 **MAC 주소 테이블 고갈**(테넌트 VM 폭증)
        ▼
   [**VXLAN**]
   "**L2를 L3 위에 띄운다**"(Overlay)
   · **VNI 24bit → 1,600만 세그먼트**
   · **물리 토폴로지와 논리 네트워크의 완전 분리(Decoupling)**
   · L3 라우팅(ECMP) 활용 → **모든 링크 액티브 사용**

Ⅱ. VXLAN의 구성요소 및 패킷 구조​

1. 주요 구성요소​

구성요소내용
VTEP(VXLAN Tunnel End Point)캡슐화·역캡슐화 수행 주체. 하드웨어(스위치) 또는 소프트웨어(하이퍼바이저 vSwitch)로 구현. 오버레이와 언더레이의 경계
VNI(VXLAN Network Identifier)24bit 세그먼트 식별자 — 테넌트/논리망 구분(VLAN ID 대응)
Underlay NetworkVTEP 간 IP 도달성을 제공하는 물리 L3 망(주로 Spine-Leaf 구조 + ECMP)
Overlay NetworkVTEP 간 터널로 형성되는 논리 L2 망
VXLAN GatewayVXLAN ↔ VLAN(L2 GW) / 외부 라우팅(L3 GW) 연결
Control PlaneMAC/IP 학습·광고 — Flood & Learn 또는 EVPN-BGP(권장)

2. 패킷 캡슐화 구조​

   [**VXLAN 캡슐화 (MAC-in-UDP)** — 오버헤드 **50 Byte**]

   ┌────────────────── **Outer(언더레이)** ──────────────────┐
   │ Outer MAC (14B) │ Outer IP (20B) │ **UDP (8B)**         │
   │  VTEP 간 L2/L3   │ VTEP 출발/목적지 │ **Dst Port 4789**  │
   │                                    │ Src Port=내부 해시 │
   │                                    │ (**ECMP 부하분산**) │
   ├──────────────────────────────────────────────────────────┤
   │ **VXLAN Header (8B)** : Flags │ **VNI (24bit)** │ Rsvd   │
   ├──────────── **Inner(오버레이) = 원본 프레임** ───────────┤
   │ Inner MAC │ Inner IP │ Payload(FCS)                      │
   └──────────────────────────────────────────────────────────┘

   ⇒ **MTU 고려 필수** : 언더레이 MTU를 **최소 1,550B(권장 9,000 Jumbo)** 로 설정

3. 동작 흐름​

   [**VM-A(랙1) → VM-B(랙2) 통신**]

   ① VM-A가 이더넷 프레임 송신 (동일 L2로 인식)
        ▼
   ② **VTEP-1**이 프레임 수신 → **VNI 부여 + VXLAN/UDP/IP 캡슐화**
        ▼
   ③ **언더레이 L3 망**을 통해 일반 IP 패킷으로 라우팅(ECMP 부하분산)
        ▼
   ④ **VTEP-2**가 수신 → **역캡슐화** → VNI에 매핑된 포트로 전달
        ▼
   ⑤ VM-B 수신 (물리 경로는 L3였으나 **VM은 같은 LAN으로 인식**)

   ※ **BUM 트래픽**(Broadcast/Unknown Unicast/Multicast) 처리
      · **Multicast 모드** : VNI별 멀티캐스트 그룹 사용(언더레이 PIM 필요)
      · **Ingress Replication(HER)** : 유니캐스트 복제 전송(구성 단순)
      · **EVPN 모드** : **BGP로 사전 광고 → 플러딩 자체를 최소화**(권장)

Ⅳ. 장단점 및 활용​

구분내용
장점· 대규모 멀티테넌시(1,600만 세그먼트) — 퍼블릭 클라우드 필수
· 물리망과 논리망 분리 → VM/컨테이너 라이브 마이그레이션 자유
· STP 제거 — L3 ECMP로 전 링크 액티브 활용(대역폭 2배↑)
· 언더레이는 표준 IP 망이면 충분 → 기존 장비 활용, 벤더 중립
· DC 간(DCI) L2 확장 가능 → 재해복구·클러스터 구성
단점·고려사항· 50B 오버헤드 → MTU 미조정 시 단편화·성능 저하(Jumbo Frame 필수)
· 캡슐화·역캡슐화 CPU 부하(SW VTEP) → 하드웨어 오프로드 필요
· 트러블슈팅 난이도 상승(오버레이/언더레이 이중 구조, 패킷 가시성 저하)
· 기본 사양에 암호화 없음 → 필요 시 IPSec/MACsec 병행
· Flood&Learn 방식은 멀티캐스트 의존 → EVPN 도입 권장
활용 분야내용
클라우드 데이터센터테넌트별 네트워크 격리, IaaS 가상 네트워크(VPC) 구현
컨테이너 네트워크Kubernetes CNI(Flannel/Calico VXLAN 백엔드) — 노드 간 Pod 통신
SDN/NFVNSX·ACI 등 오버레이 SDN의 데이터플레인
DCI(데이터센터 간 연결)원격지 DC 간 L2 확장 → DR/이중화
캠퍼스 네트워크SD-Access 등 정책 기반 세그멘테이션(마이크로세그멘테이션)

Ⅴ. 결론​

VXLAN은 "L2의 유연성과 L3의 확장성을 동시에 확보" 하기 위한 해법으로, 물리 네트워크(Underlay)와 논리 네트워크(Overlay)를 분리함으로써 클라우드 데이터센터의 확장성·이동성·멀티테넌시 문제를 일거에 해결했다는 점에서 의의가 크다. 현재는 Spine-Leaf 언더레이 + VXLAN-EVPN 오버레이가 데이터센터 네트워크의 사실상 표준 아키텍처(De-facto Standard) 로 정착되었다.

실무 도입 시 가장 흔한 실패 요인은 MTU 설정 누락이다. 50Byte의 캡슐화 오버헤드를 고려하지 않으면 대용량 전송 시 단편화가 발생해 성능이 급격히 저하되므로, 언더레이 전 구간에 Jumbo Frame(9,000B) 설정이 선행되어야 한다. 또한 컨트롤 플레인은 Flood&Learn이 아닌 EVPN-BGP를 채택하여 불필요한 플러딩과 멀티캐스트 의존성을 제거하는 것이 바람직하다.

한편 VXLAN은 자체 암호화를 제공하지 않으므로, DC 간 연결(DCI)이나 신뢰할 수 없는 구간을 경유하는 경우 IPSec/MACsec을 병행해야 하며, 오버레이로 인해 저하되는 가시성을 보완하기 위해 플로우 기반 모니터링(sFlow/IPFIX)과 오버레이-언더레이 상관분석 체계를 함께 구축해야 한다.
