ISMP 기본 구성

문제​

10.정보시스템마스터플랜(ISMP)의 기본 구성 내용(단계별 활동, 세부내용, 산출물)

Ⅰ. 개요​

ISMP(Information System Master Plan, 정보시스템 마스터플랜) 는 특정 정보화 사업의 발주 전에 업무 및 정보기술 요구사항을 상세히 분석·정의하여 명확한 제안요청서(RFP)를 작성하고, 적정 사업규모(예산)를 산정하기 위해 수행하는 사업 단위의 상세 기획 활동이다.

   [등장 배경]
   · **불명확한 RFP** → 사업자 제안 시 요구사항 해석 상이
   · 착수 후 **요구사항 폭증·변경** → **과업 분쟁, 적자 사업, 품질 저하**
   · 규모 산정 근거 부재 → **부적정 예산 편성**
        ▼
   [**ISMP**]
   "**발주자가 무엇을 원하는지 먼저 확정한 뒤 발주한다**"
   · 근거 : **SW진흥법 / 「정보시스템 구축·운영 지침」(행안부 고시)**
   · **일정 규모 이상 공공 SW사업은 ISMP 수행 권고·의무화**
구분ISP(정보화전략계획)ISMP(정보시스템 마스터플랜)
대상 범위기관 전체의 중장기 정보화단위 사업(개별 시스템)
목적정보화 비전·과제 도출·로드맵RFP 작성 + 사업규모 산정
요구사항 수준개괄적(To-Be 모델 수준)상세(기능 목록·화면·인터페이스 단위)
기간3~6개월 이상2~4개월
산출물 활용중장기 계획, 예산 요구제안요청서(RFP), 사업비 산정 근거
관계ISP의 과제 → ISMP로 상세화 → 구축사업 발주

Ⅱ. ISMP의 기본 구성 (단계별 활동·세부내용·산출물)​

 ┌────────────────── **ISMP 4단계 절차** ──────────────────┐
 │                                                         │
 │ **1단계. 프로젝트 착수 및 참여자 확정**                 │
 │      (수행계획 수립 · 조직 구성)                        │
 │                    ▼                                    │
 │ **2단계. 정보시스템 방향성 수립**                       │
 │      (경영·IT 환경분석 → 목표시스템 방향 정의)          │
 │                    ▼                                    │
 │ **3단계. 업무 및 정보기술 요구사항 분석**  ★핵심        │
 │      (업무 요구 + 정보기술 요구 상세 분석)              │
 │                    ▼                                    │
 │ **4단계. 정보시스템 구조 및 요건 정의**                 │
 │      (아키텍처 정의 · **RFP 작성 · 규모/예산 산정**)    │
 └─────────────────────────────────────────────────────────┘

1. 1단계 : 프로젝트 착수 및 참여자 확정​

활동세부내용산출물
프로젝트 착수목적·범위·기간 확정, 추진 배경 및 제약 확인ISMP 수행계획서
참여자 확정발주기관 담당자·현업 부서·수행사 인력 확정, R&R 정의프로젝트 조직도, 참여자 명단
환경 준비사무공간·산출물 표준·의사소통 체계 수립의사소통 계획서, WBS
착수보고착수보고회, 이해관계자 공유착수보고서

2. 2단계 : 정보시스템 방향성 수립​

활동세부내용산출물
경영환경 분석조직 비전·전략, 관련 법·제도·정책 분석, 상위계획(ISP) 연계경영환경 분석서
현행 업무 분석AS-IS 업무 프로세스·문제점 도출, 이해관계자 인터뷰현행 업무 분석서
현행 정보시스템 분석응용·데이터·인프라 현황, 재사용 가능 자산 식별현행 시스템 분석서
선진사례·기술동향 분석국내외 벤치마킹, 신기술 적용 가능성벤치마킹 결과서
개선기회 및 방향 정의GAP 분석, 목표시스템 비전·목표·추진방향 설정정보시스템 방향성 정의서, 개선과제 목록

3. 3단계 : 업무 및 정보기술 요구사항 분석 (핵심 단계)​

활동세부내용산출물
업무 요구사항 분석TO-BE 업무 프로세스 설계, 업무 기능 분해(기능 계층도), 업무 규칙 정의TO-BE 업무 프로세스 정의서, 업무 기능 분해도
업무 요구사항 상세화기능별 입력·처리·출력 정의, 화면·보고서 목록, 업무량(트랜잭션) 추정업무 요구사항 정의서(기능 목록)
정보기술 요구사항 분석성능·보안·가용성·인터페이스·데이터·품질 등 비기능 요구 정의정보기술 요구사항 정의서
데이터 요구사항 분석개념 데이터 모델, 주요 엔터티·코드·데이터 이관(마이그레이션) 범위개념 데이터 모델, 데이터 요구사항 정의서
인터페이스 요구사항내·외부 연계 대상·방식·주기인터페이스 정의서, 연계 구성도
요구사항 검증·확정현업 검토·워크숍, 우선순위(MoSCoW) 부여, 기준선(Baseline) 확정요구사항 추적표(RTM), 요구사항 확정 확인서

4. 4단계 : 정보시스템 구조 및 요건 정의​

활동세부내용산출물
정보시스템 아키텍처 정의응용·데이터·기술(인프라)·보안 아키텍처 설계, 구성도목표시스템 아키텍처 정의서
시스템 요건 정의HW/SW 규격·수량, 네트워크·보안 장비 요건시스템 도입 요건 정의서, 장비 내역서
사업 규모 산정기능점수(FP) 기반 SW 개발비 산정, HW/SW 구매비, 감리비 등사업규모 산정서(FP 산정 내역), 사업비 산출 내역서
제안요청서(RFP) 작성사업 개요·범위, 요구사항 명세(SFR/PER/SIR/DAR/SER/QUR 등), 평가 기준, 계약 조건제안요청서(RFP) ← 최종 목적물
이행계획 수립단계별 추진 일정, 위험 분석 및 대응, 조직·예산 계획이행계획서, 위험관리 계획서
성과지표 정의사업 성과지표(KPI), 검수 기준성과관리 계획서
최종 보고결과 보고 및 승인최종보고서

Ⅲ. 요구사항 명세 체계 (RFP 반영 기준)​

분류코드내용
기능 요구사항SFR시스템이 제공해야 할 업무 기능
성능 요구사항PER응답시간, TPS, 동시 사용자
인터페이스 요구사항SIR내·외부 시스템 연계
데이터 요구사항DAR데이터 구축·이관·품질
테스트 요구사항TER시험 절차·환경·기준
보안 요구사항SER인증·암호화·접근통제·개인정보
품질 요구사항QUR신뢰성·사용성·유지보수성
제약 요구사항COR법·표준·기술 제약
프로젝트 관리 요구사항PMR일정·인력·품질관리
프로젝트 지원 요구사항PSR교육·기술이전·하자보수

Ⅳ. 기대효과 및 성공요인​

구분내용
기대효과· 명확한 RFP → 제안서 품질 및 비교 평가 객관성 향상
· 요구사항 사전 확정 → 착수 후 과업 변경·분쟁 최소화
· FP 기반 적정 사업비 산정 → 저가 수주·적자 사업 방지
· 발주기관의 사업관리 역량 강화, 감리·검수 기준 확보
성공요인·고려사항· 현업 참여 확보 — 요구사항의 원천은 업무 담당자
· 적정 기간·예산 배정(형식적 단기 수행 시 실효성 상실)
· ISP와의 정합성 유지(중복·상충 방지)
· 요구사항의 검증 가능성(정량화) 확보
· ISMP 산출물의 차기 구축사업 인수인계 및 추적성 유지
· 과도한 상세화로 기술적 대안 차단 방지(What 중심 기술)

Ⅴ. 결론​

ISMP는 "발주자가 스스로 무엇을 원하는지 명확히 정의한 후 발주한다" 는 원칙을 제도화한 것으로, 공공 SW사업의 고질적 문제인 불명확한 요구사항, 과업 변경 분쟁, 부적정 대가 산정을 근원적으로 해소하기 위한 장치이다.

핵심은 3단계(업무 및 정보기술 요구사항 분석) 이다. 이 단계에서 요구사항이 기능 목록·화면·인터페이스 수준까지 상세화되고 우선순위와 검증 기준이 확정되어야, 4단계의 FP 기반 사업비 산정과 RFP 작성이 실질적 근거를 갖게 된다. 반대로 이 단계가 형식적으로 수행되면 ISMP는 문서만 남고 착수 후 요구사항이 다시 폭증하는 결과를 낳는다.

따라서 실무적으로는 ① 현업 담당자의 실질적 참여 보장, ② 요구사항의 정량적·검증 가능한 기술, ③ ISMP 산출물(RTM·기능목록)의 구축사업 단계 승계가 성공의 관건이다. 아울러 과업심의위원회 제도와 연계하여, ISMP에서 확정한 기준선을 근거로 변경 요구의 적정성과 추가 대가를 심의함으로써 발주자–수행사 간 공정한 계약 관계를 확립하는 것이 바람직하다.
