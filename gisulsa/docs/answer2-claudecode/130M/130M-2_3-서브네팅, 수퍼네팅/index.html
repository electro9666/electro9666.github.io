서브네팅, 수퍼네팅

문제​

3.네트워크 서브네팅(subnetting)과 관련하여 아래 사항들을 설명하시오.
1) 수퍼네팅(supernetting)과 서브네팅(subnetting) 개념을 설명하시오.
2) 192.168.100.0/24 네트워크 대역을 동일한 IP 개수를 가진 4개의 서브넷(Subnet)으로분할하고자 한다.해당 절차에 대해서 상세히 설명하고, 서브넷 마스크 값을구하시오.
그리고 하나의 서브넷에서 할당 가능한 IP 수량을 제시하시오

Ⅰ. 개요​

1. IP 주소 체계와 등장 배경​

IP 주소는 네트워크 ID(Network Part) 와 호스트 ID(Host Part) 로 구성되며, 이 경계를 정하는 것이 서브넷 마스크(Subnet Mask) 이다. 초기 클래스풀(Classful) 주소 체계는 A(/8)·B(/16)·C(/24)의 고정된 경계만 허용하여 심각한 주소 낭비를 초래했다.

   [**클래스풀 주소 체계의 한계**]

   호스트 300대가 필요한 조직의 경우
        ├─ **C클래스(/24, 254개)** → 부족
        └─ **B클래스(/16, 65,534개)** → 할당 시 **65,000개 이상 낭비**

   ⇒ ① **IP 주소 고갈 가속**
     ② 하나의 네트워크에 수만 호스트 → **브로드캐스트 폭주**
     ③ 라우팅 테이블 폭증(경로 수 급증)
        ▼
   [**해결책**]
   **CIDR**(Classless Inter-Domain Routing, RFC 1519)
   — 클래스 경계를 없애고 **가변 길이 프리픽스(/n)** 사용
        ├─ **서브네팅** : 큰 네트워크를 **잘게 나눔**(Divide)
        └─ **수퍼네팅** : 여러 네트워크를 **하나로 묶음**(Aggregate)

2. 서브넷 마스크의 원리​

   [**서브넷 마스크 = 네트워크 부분을 1로 표시**]

   IP 주소     : 192 . 168 . 100 .  10
                 11000000.10101000.01100100.00001010
   마스크(/24) : 255 . 255 . 255 .   0
                 11111111.11111111.11111111.00000000
                 └────── 네트워크 부분 ──────┘└호스트┘

   **AND 연산** ⇒ 네트워크 주소 = **192.168.100.0**

   ※ **프리픽스(/n)** = 마스크에서 연속된 **1의 개수**

Ⅱ. 서브네팅과 수퍼네팅의 개념​

1. 서브네팅 (Subnetting)​

구분내용
정의하나의 큰 네트워크를 호스트 비트의 일부를 네트워크 비트로 차용(Borrow) 하여 여러 개의 작은 논리적 네트워크(서브넷)로 분할하는 기법
원리호스트 비트 → 서브넷 비트로 전환 ⇒ 프리픽스 길이 증가(/24 → /26)
비트 변화네트워크 부분 확장, 호스트 부분 축소
목적· IP 주소 낭비 최소화
· 브로드캐스트 도메인 축소 → 트래픽 감소·성능 향상
· 부서·기능별 논리적 분리 → 보안(ACL) 및 관리 용이
· 장애 영향 범위 국소화
관련 기술FLSM(고정 길이 서브넷 마스크) / VLSM(가변 길이 서브넷 마스크 — 필요 호스트 수에 따라 서로 다른 크기로 분할)

2. 수퍼네팅 (Supernetting)​

구분내용
정의연속된 여러 개의 네트워크를 하나의 큰 네트워크 주소로 통합하여 표현하는 기법. 경로 집약(Route Aggregation/Summarization) 이라고도 함
원리네트워크 비트를 호스트 비트로 반환 ⇒ 프리픽스 길이 감소(/24 × 4 → /22)
비트 변화네트워크 부분 축소, 호스트 부분 확장
목적· 라우팅 테이블 크기 축소 → 라우터 메모리·검색 부하 감소
· 라우팅 정보 교환량(업데이트) 감소 → 수렴 속도 향상
· 내부 네트워크 변동을 외부에 은닉(안정성)
· 클래스 경계를 넘는 대규모 주소 할당 가능
전제 조건① 통합 대상 네트워크가 연속(Contiguous) 일 것
② 주소 블록이 2ⁿ 개수의 경계에 정렬될 것
③ 동일한 방향(같은 상위 라우터) 으로 라우팅될 것
   [**수퍼네팅 예시**]

   192.168.**0**.0/24   →  11000000.10101000.000000**00**.00000000
   192.168.**1**.0/24   →  11000000.10101000.000000**01**.00000000
   192.168.**2**.0/24   →  11000000.10101000.000000**10**.00000000
   192.168.**3**.0/24   →  11000000.10101000.000000**11**.00000000
                            └─── 공통 22bit ───┘└가변2bit┘

   ⇒ **192.168.0.0/22** (마스크 **255.255.252.0**) 하나로 통합
   ⇒ 라우팅 테이블 항목 **4개 → 1개**

3. 서브네팅 vs 수퍼네팅 비교​

비교 기준서브네팅(Subnetting)수퍼네팅(Supernetting)
동작분할(1 → N)통합(N → 1)
비트 이동호스트 비트 → 네트워크 비트네트워크 비트 → 호스트 비트
프리픽스 길이증가(/24 → /26)감소(/24 → /22)
서브넷 마스크길어짐(255.255.255.192)짧아짐(255.255.252.0)
네트워크 개수증가감소
네트워크당 호스트 수감소증가
주 목적IP 절약, 브로드캐스트 도메인 축소, 보안 분리라우팅 테이블 축소, 경로 집약
적용 주체조직 내부 네트워크 설계자ISP·백본 라우터(BGP 경로 집약)
적용 계층LAN 내부 설계WAN·인터넷 라우팅
공통점모두 CIDR(클래스리스) 기반, 마스크 조작을 통한 주소 효율화 기법

Ⅲ. 192.168.100.0/24 를 4개 서브넷으로 분할​

1. 주어진 조건 분석​

   [**원본 네트워크**]
   · 네트워크 주소 : **192.168.100.0/24**
   · 서브넷 마스크 : **255.255.255.0**
   · 클래스        : **C클래스**(사설 IP 대역)
   · 전체 IP 개수  : **2⁸ = 256개** (192.168.100.0 ~ 192.168.100.255)
   · 할당 가능 호스트 : 256 − 2 = **254개**

   [**요구사항**]
   · **동일한 IP 개수**를 가진 **4개의 서브넷**으로 분할 (**FLSM 방식**)

2. 분할 절차 (5단계)​

[1단계] 필요한 서브넷 비트 수 산정​

   [**공식**]  **2ⁿ ≥ 필요한 서브넷 개수**   (n = 차용할 호스트 비트 수)

   n = 1 → 2¹ = 2개   (부족)
   **n = 2 → 2² = 4개  ✔ (요구사항 충족)**
   n = 3 → 2³ = 8개   (과다)

   ⇒ **호스트 비트에서 2비트를 차용(Borrow)** 한다.

[2단계] 새로운 프리픽스 및 서브넷 마스크 산출​

   [**프리픽스 계산**]
   **새 프리픽스 = 기존 프리픽스 + 차용 비트 수 = /24 + 2 = /26**

   [**비트 구조 변화**]

   기존 (/24)
   11111111.11111111.11111111.**00000000**
   └───── 네트워크 24bit ─────┘└호스트 8bit┘

   변경 (/26)
   11111111.11111111.11111111.**11**000000
   └───── 네트워크 24bit ─────┘└─┘└호스트┘
                          **서브넷 2bit**  **6bit**

   [**4옥텟 값 계산**]
   **11000000**(2) = 128 + 64 = **192**

   ┌─────────────────────────────────────────────┐
   │ ★ **서브넷 마스크 = 255.255.255.192  (/26)** │
   └─────────────────────────────────────────────┘

[3단계] 서브넷 블록 크기(증분값) 산출​

   [**공식**]  **블록 크기 = 2^(남은 호스트 비트 수) = 256 − 마스크 옥텟 값**

   · 남은 호스트 비트 : 32 − 26 = **6bit**
   · **블록 크기 = 2⁶ = 64**
   · 검산 : 256 − 192 = **64**  ✔

   ⇒ 서브넷은 **64씩 증가**하는 경계에서 시작한다.
     (0, 64, 128, 192)

[4단계] 서브넷별 주소 범위 산출​

   [**서브넷 분할 결과**]

   ┌──────┬────────────────────┬──────────────┬──────────────┬──────────────┐
   │ 구분 │  **네트워크 주소**  │ **첫 호스트** │**마지막 호스트**│**브로드캐스트**│
   ├──────┼────────────────────┼──────────────┼──────────────┼──────────────┤
   │ **①** │ 192.168.100.**0**/26  │ .**1**        │ .**62**       │ .**63**       │
   │ **②** │ 192.168.100.**64**/26 │ .**65**       │ .**126**      │ .**127**      │
   │ **③** │ 192.168.100.**128**/26│ .**129**      │ .**190**      │ .**191**      │
   │ **④** │ 192.168.100.**192**/26│ .**193**      │ .**254**      │ .**255**      │
   └──────┴────────────────────┴──────────────┴──────────────┴──────────────┘

   [**서브넷 비트 값 확인** — 4옥텟 이진 표현]
   ① **00**000000 = 0     ② **01**000000 = 64
   ③ **10**000000 = 128   ④ **11**000000 = 192
        ↑↑ 서브넷 식별 2비트 (00/01/10/11 = 4가지)

[5단계] 서브넷당 할당 가능 IP 수량 산출​

   [**공식**]  **할당 가능 호스트 수 = 2^(호스트 비트 수) − 2**

   · 호스트 비트 : **6bit**
   · 전체 주소 수 : **2⁶ = 64개**
   · **제외 주소 2개**
        ├─ **네트워크 주소**(호스트 비트가 모두 0) — 네트워크 자체 식별
        └─ **브로드캐스트 주소**(호스트 비트가 모두 1) — 전체 전송용

   ┌──────────────────────────────────────────────────┐
   │ ★ **할당 가능 IP 수 = 2⁶ − 2 = 64 − 2 = 62개**    │
   └──────────────────────────────────────────────────┘

   [**검산**]
   62개 × 4개 서브넷 = **248개** (실제 할당 가능)
   원본 /24 : 254개 → **6개 감소**
   ⇒ 서브넷 수만큼 네트워크/브로드캐스트 주소가 추가 소모되기 때문
     (증가분 : 서브넷 3개 × 2개 = 6개)

3. 최종 답안 정리​

항목결과
원본 네트워크192.168.100.0/24 (255.255.255.0)
차용 비트 수2비트 (2² = 4개 서브넷)
새 프리픽스/26

블록(증분) 크기64

★ 서브넷당 할당 가능 IP 수62개
서브넷 목록192.168.100.0/26, 64/26, 128/26, 192/26

4. 실제 할당 예시​

   [**부서별 서브넷 설계 예시**]

   **서브넷 ① 192.168.100.0/26**   → **영업부**
        · 게이트웨이 : 192.168.100.1
        · 호스트     : 192.168.100.2 ~ .62  (61대)
        · 브로드캐스트 : 192.168.100.63

   **서브넷 ② 192.168.100.64/26**  → **개발부**
        · 게이트웨이 : 192.168.100.65
        · 호스트     : 192.168.100.66 ~ .126

   **서브넷 ③ 192.168.100.128/26** → **서버 존(DMZ)**
   **서브넷 ④ 192.168.100.192/26** → **관리/예비**

   ※ 각 서브넷 간 통신은 **라우터(또는 L3 스위치)** 경유 →
     **ACL로 부서 간 접근 통제** 가능

Ⅳ. 관련 개념 및 실무 고려사항​

1. VLSM (가변 길이 서브넷 마스크)​

   [**FLSM(본 문제) vs VLSM**]

   **FLSM** : 모두 동일 크기(**/26 × 4**) — 단순하나 **낭비 발생**
        예) 호스트 5대만 필요한 지사에도 62개 할당 → **57개 낭비**

   **VLSM** : 필요량에 맞춰 **서로 다른 크기**로 분할
        192.168.100.0/25    (126개) → 본사 LAN
        192.168.100.128/26  (62개)  → 지사
        192.168.100.192/27  (30개)  → 서버존
        192.168.100.224/28  (14개)  → 관리망
        192.168.100.240/30  (2개)   → **라우터 간 P2P 링크**
   ⇒ **큰 것부터 순서대로 할당**하는 것이 원칙

3. 실무 고려사항​

고려사항내용
① 향후 확장성현재 필요량만 고려하면 재설계 발생 → 성장률 30~50% 여유 반영
② VLAN과의 매핑서브넷 = 브로드캐스트 도메인 ⇒ 1 VLAN : 1 서브넷 원칙
③ 라우팅 설계서브넷 간 통신은 L3 라우팅 필요(라우터/L3 스위치, SVI 구성)
④ 보안 분리서브넷 경계에 ACL·방화벽 적용 → 부서·존(Zone) 간 접근 통제, 마이크로세그멘테이션
⑤ DHCP 설계서브넷별 스코프(Pool) 분리, 게이트웨이·DNS 옵션 설정, Relay Agent 구성
⑥ 주소 체계 표준화IPAM(IP Address Management) 도구로 중앙 관리, 문서화
⑦ 경로 집약 고려지사 서브넷을 연속 배치해야 수퍼네팅(경로 요약) 가능
⑧ IPv6 전환IPv6는 주소 고갈 문제가 없어 일반적으로 /64 고정 서브넷 사용 → 서브네팅의 목적이 주소 절약에서 논리적 분리로 이동

Ⅴ. 결론​

서브네팅과 수퍼네팅은 CIDR라는 동일한 원리(가변 프리픽스)를 서로 반대 방향으로 적용한 기법이다. 서브네팅은 호스트 비트를 네트워크 비트로 차용하여 나누는 것(프리픽스 증가) 이고, 수퍼네팅은 네트워크 비트를 호스트 비트로 반환하여 합치는 것(프리픽스 감소) 이다. 따라서 두 기법은 대립하는 것이 아니라, 조직 내부는 서브네팅으로 잘게 나누어 관리하고, 외부(ISP·백본)에는 수퍼네팅으로 요약하여 광고하는 계층적 주소 설계로 함께 사용된다.

본 문제의 계산 결과는 ① 4개 서브넷을 위해 2비트 차용 → ② 프리픽스 /26 → ③ 서브넷 마스크 255.255.255.192 → ④ 블록 크기 64 → ⑤ 서브넷당 할당 가능 IP 62개 로 요약된다. 계산 시 가장 유의할 점은 각 서브넷마다 네트워크 주소와 브로드캐스트 주소 2개가 반드시 제외된다는 것이며, 이로 인해 원본 /24의 254개가 4개 서브넷 합계 248개로 6개 감소하는 것이 서브네팅의 불가피한 비용이다.

실무적 관점에서 서브네팅의 진정한 가치는 IP 주소 절약을 넘어선 "브로드캐스트 도메인 축소와 보안 분리" 에 있다. 하나의 대형 네트워크는 ARP·브로드캐스트 트래픽이 전 구간에 전파되어 성능을 저하시키고, 한 대의 감염 호스트가 전체 네트워크로 확산될 수 있다. 서브넷으로 분할하면 트래픽이 국소화되고 서브넷 경계에서 ACL·방화벽 통제가 가능해진다. 이것이 최근 제로트러스트와 마이크로세그멘테이션의 기초가 되는 설계 원리이다.

향후 IPv6 환경에서는 주소 공간이 사실상 무한하므로 절약 목적의 정교한 서브네팅은 불필요해지고 /64 고정 서브넷이 표준이 된다. 그러나 논리적 분리·보안 통제·라우팅 효율화라는 서브네팅의 본질적 목적은 그대로 유지되며, 경로 집약(수퍼네팅)의 중요성은 오히려 주소 공간 확대에 따라 더욱 커질 것이다.
