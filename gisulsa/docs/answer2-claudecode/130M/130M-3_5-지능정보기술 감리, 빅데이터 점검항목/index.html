지능정보기술 감리, 빅데이터 점검항목

문제​

5.인공지능 등 지능정보 기술에 비현실적인 감리기준을 해결하기 위해 지능정보기술감리실무 가이드(한국지능정보사회진흥원, 2023년)를 발간했다.그 중 빅데이터 정보화사업의분석·설계 단계별, 영역별 점검 항목에 대하여 설명하시오.

Ⅰ. 개요​

1. 지능정보기술 감리 실무 가이드의 발간 배경​

「지능정보기술 감리 실무 가이드」(한국지능정보사회진흥원, 2023.2) 는 빅데이터·AI·클라우드 등 지능정보기술 기반 정보화사업의 특성을 반영한 감리 점검 기준을 제시한 실무 지침이다.

   [**발간 배경 — 기존 감리기준의 한계**]

   기존 정보시스템 감리기준은 **트랜잭션 처리 중심의 전통 시스템**을 전제
        │  · **정형 데이터 · 확정적 요구사항 · 폭포수 개발**
        ▼
   ⚠ **지능정보기술 사업에 적용 시 발생하는 괴리**

   ① **산출물 불일치** — 화면설계서·프로그램목록 중심 점검
        ⇒ 빅데이터 사업은 **데이터 파이프라인·모델**이 핵심 산출물
   ② **요구사항의 비확정성** — AI/분석은 **탐색적·실험적** 수행
        ⇒ 착수 시점에 기능 명세를 확정하기 어려움
   ③ **성능 판정 기준 부재** — "정확도 90%"의 적정성을 판단할 근거 없음
   ④ **데이터 품질 점검 항목 부재** — 시스템은 정상이나 **데이터가 쓸모없는** 경우
   ⑤ **비결정적 결과** — 동일 입력에 다른 결과 → **전통적 시험 기준 적용 곤란**
        ▼
   [**지능정보기술 감리 실무 가이드**]
   · **빅데이터 정보화사업 감리 점검 가이드**
   · **클라우드 정보화사업 감리 점검 가이드**
   · **운영 및 유지관리 사업 감리 점검 가이드**
   ⇒ **"기술 특성에 맞는 현실적 감리기준"** 제시

2. 정보시스템 감리의 기본 체계​

구분내용
감리의 정의발주자·사업자가 아닌 제3자(감리법인) 가 정보시스템의 효율성·안전성 향상 및 품질 확보를 위해 점검·평가하고 문제점 개선을 권고하는 활동(전자정부법 제57조)
감리 시점요구정의 → 설계 → 종료 단계 감리(3단계 감리가 원칙, 사업 특성에 따라 조정)
감리 영역① 사업관리, ② 응용시스템, ③ 데이터베이스, ④ 시스템구조·보안(기본 4대 영역)
점검 기준① 산출물의 충실성(작성 여부·완전성)
② 상호 일관성(전·후 산출물 추적성)
③ 요구사항 충족성
④ 적법성·표준 준수
감리 결과부적합·개선권고·협의조정 판정 → 시정조치 요구 및 확인

Ⅱ. 빅데이터 정보화사업의 특성과 감리 관점​

2. 전통 사업과의 감리 관점 차이​

구분전통 정보화사업 감리빅데이터 사업 감리
핵심 점검 대상기능(화면·프로그램)데이터와 데이터 흐름(파이프라인)
요구사항 성격확정적·기능 중심탐색적, 분석 목표·활용 시나리오 중심
품질 기준기능 정상 동작데이터 품질 + 분석 결과의 유용성
주요 산출물화면설계서·프로그램목록·ERD데이터 흐름도·데이터 표준·품질 진단서·분석 모델 정의서
성능 기준응답시간·TPS처리량(배치 시간)·모델 정확도·재현율
위험 요소일정·범위데이터 확보 실패·품질 미달·개인정보 침해
핵심 리스크미완성완성했으나 활용 불가(데이터가 쓸모없음)

2. 분석 단계 점검항목 (영역별)​

분석 단계의 핵심 감리 관점 : "이 사업이 실현 가능한가" — 특히 데이터를 실제로 확보할 수 있는지, 품질이 목적에 부합하는지를 조기에 확인하는 것이 가장 중요하다.

가. ① 사업관리 영역​

점검항목점검 내용
사업수행계획의 적정성사업 목표·범위·일정·인력이 RFP 및 제안서와 일치하는가
조직 및 역할 정의데이터 분석가·데이터 엔지니어 등 전문 인력이 계획대로 투입되었는가, 현업 참여 체계가 있는가
위험관리 계획데이터 미확보·품질 미달·법적 제약 등 빅데이터 고유 위험이 식별·관리되는가
의사소통·이해관계자 관리데이터 제공 부서·외부 기관과의 협의 체계 및 협조 확보 여부
일정관리데이터 확보 지연이 후속 분석 일정에 미치는 영향이 반영되었는가

나. ② 요구사항 영역​

점검항목점검 내용
요구사항 도출의 충실성현업 인터뷰·워크숍을 통해 분석 요구가 충분히 도출되었는가
분석 목적의 명확성"무엇을 알고자 하는가" 가 구체적으로 정의되었는가(막연한 "AI 도입" 아님)
요구사항 정의서 작성기능·비기능(성능·보안·품질) 요구가 측정 가능한 형태로 기술되었는가
요구사항 추적성RFP → 제안서 → 요구사항정의서 → 산출물의 추적표(RTM) 가 관리되는가
범위 적정성데이터 확보 가능성·기간을 고려할 때 요구 범위가 실현 가능한가

다. ③ 데이터 영역 (수집·연계·품질) — 핵심​

점검항목점검 내용
원천 데이터 현황 분석대상 데이터의 소재·보유기관·형식·주기·규모가 조사되었는가
데이터 확보 가능성실제 제공 가능 여부(협조·계약·법적 근거) 가 확인되었는가 — 미확인 시 사업 최대 위험
데이터 품질 현황 진단원천 데이터의 결측·중복·이상치·정합성 이 사전 진단되었는가
데이터 충분성분석 목적 달성에 필요한 데이터의 양·기간·항목이 충분한가
연계 대상·방식 분석내·외부 연계 대상, 연계 방식(API·파일·DB링크)·주기·용량 이 분석되었는가
데이터 표준 현황기관의 데이터 표준·공통코드 현황과 표준 미준수 항목이 식별되었는가
메타데이터 현황데이터 사전·정의서 존재 여부, 의미 파악 가능성
비정형 데이터 처리 가능성텍스트·이미지·로그 등의 처리·정제 방안이 검토되었는가

라. ④ 분석·모델 영역​

점검항목점검 내용
분석 과제 정의분석 과제가 업무 목표 및 성과지표(KPI)와 연계되어 도출되었는가
분석 기법 선정의 타당성목적·데이터 특성에 적합한 알고리즘·기법이 선정되었는가, 선정 근거가 제시되었는가
분석 목표 수준 정의정확도·재현율 등 목표 성능이 정량적·현실적으로 정의되었는가
선행 사례·타당성 검토유사 사례·PoC 결과를 통해 실현 가능성이 검증되었는가
분석 결과 활용 방안분석 결과가 어떤 업무 의사결정에 어떻게 사용될지 정의되었는가
학습데이터 확보 방안지도학습 시 레이블링 계획·품질 관리 방안이 수립되었는가

마. ⑤ 응용·활용 영역​

점검항목점검 내용
활용 시나리오 정의사용자·활용 시점·활용 방식이 구체적으로 정의되었는가
사용자 요구 반영시각화·조회 요구가 실제 사용자 관점에서 도출되었는가
기존 시스템 연계 요구분석 결과를 소비할 업무 시스템과의 연계 요구가 식별되었는가
개방·공유 요구공공데이터 개방·Open API 제공 요구 및 관련 기준 반영 여부

바. ⑥ 시스템구조 영역​

점검항목점검 내용
데이터 규모·증가율 분석현재 및 향후 데이터 볼륨·증가 추이가 산정되었는가
성능 요구사항 정의배치 처리 시간·조회 응답시간·동시 사용자 등이 정량 정의되었는가
현행 인프라 분석기존 인프라의 수용 가능성 및 제약이 분석되었는가
클라우드 도입 검토확장성·비용 관점에서 클라우드/온프레미스 방식이 비교 검토되었는가

사. ⑦ 보안·개인정보 영역​

점검항목점검 내용
법적 요건 검토개인정보보호법·신용정보법·저작권법 등 관련 법령 준수 요건이 식별되었는가
개인정보 포함 여부 식별수집 대상 데이터에 개인정보·민감정보 포함 여부가 전수 확인되었는가
처리 근거 확보수집·이용·제공의 법적 근거(동의·법령·가명처리) 가 확보되었는가
개인정보 영향평가(PIA)대상 사업인 경우 영향평가 수행 계획이 수립되었는가
비식별·가명처리 요구가명처리 필요 범위 및 적정성 검토 계획 여부
보안 요구사항 정의접근통제·암호화·데이터 반출 통제 요구가 정의되었는가

3. 설계 단계 점검항목 (영역별)​

설계 단계의 핵심 감리 관점 : "분석 단계에서 정의한 요구가 설계에 빠짐없이 반영되었는가(추적성)" 와 "설계대로 구현했을 때 목표 품질·성능을 달성할 수 있는가(실현 가능성)"

가. ① 사업관리 영역​

점검항목점검 내용
진척관리 적정성WBS 대비 실제 진척률과 산출물 완성도가 일치하는가
변경관리요구사항·범위 변경이 공식 절차(변경통제) 로 처리되고 기준선이 갱신되었는가
품질보증 활동설계 검토(인스펙션·워크스루) 가 수행되고 결함이 조치되었는가
위험 대응 이행분석 단계에서 식별한 데이터 확보 위험의 대응이 실제 이행되었는가
산출물 관리형상관리·버전관리가 이루어지고 산출물 간 일관성이 유지되는가

나. ② 요구사항 영역​

점검항목점검 내용
요구사항 반영 완전성요구사항정의서의 모든 항목이 설계 산출물에 반영되었는가(누락 여부)
추적성 유지RTM을 통해 요구사항 ↔ 설계 산출물 ↔ 시험 케이스가 연결되는가
비기능 요구 반영성능·보안·품질 요구가 설계에 구체적으로 반영되었는가

다. ③ 데이터 영역 — 핵심​

점검항목점검 내용
데이터 수집 설계원천별 수집 방식(배치/실시간)·주기·오류 처리·재수집 방안이 설계되었는가
연계(인터페이스) 설계인터페이스 정의서(항목·형식·프로토콜·인증·오류 처리)가 작성되었는가, 연계 기관과 합의되었는가
데이터 표준 설계용어·도메인·코드 표준이 정의되고 전 산출물에 일관 적용되었는가
데이터 모델 설계개념·논리·물리 모델이 단계적으로 작성되고 상호 일관한가, 정규화/역정규화 근거가 타당한가
데이터 레이크/DW 구조 설계저장 계층(Raw–Refined–Mart) 구조, 파티셔닝·파일 포맷(Parquet 등)·압축 설계의 적정성
데이터 품질 관리 설계품질 기준(완전성·유일성·유효성·일관성·정확성·적시성) 및 품질 검증 규칙(Rule)·측정 지표가 설계되었는가
데이터 정제·전처리 설계결측·이상치·중복 처리 규칙이 명시적으로 정의되었는가
메타데이터·계보 설계메타데이터 관리 및 데이터 리니지(Lineage) 추적 방안이 설계되었는가
데이터 생명주기 설계보관 주기·아카이빙·파기 방안이 법적 요건에 맞게 설계되었는가
이관(마이그레이션) 설계기존 데이터 이관 범위·방식·검증 방안이 수립되었는가

라. ④ 분석·모델 영역​

점검항목점검 내용
분석 모델 설계서 작성분석 과제별 입력 변수·알고리즘·파라미터·산출 결과가 명시되었는가
학습·검증 데이터 설계학습/검증/시험 데이터 분리 방안, 교차검증 방법이 정의되었는가
피처(변수) 설계파생 변수 생성 규칙과 선정 근거가 문서화되었는가
모델 성능 평가 기준정확도·정밀도·재현율·F1·AUC/RMSE 등 평가지표와 합격 기준이 정의되었는가
결과 검증 방안분석 결과의 업무적 타당성 검증 절차(현업 검토)가 설계되었는가
모델 운영·재학습 설계성능 모니터링·재학습 주기·모델 버전 관리(MLOps) 방안이 설계되었는가
편향·설명가능성 고려학습 데이터 편향 검토 및 결과 설명 방안(XAI) 이 고려되었는가
처리 성능 설계대용량 데이터에 대한 분산 처리·병렬화 설계의 적정성

마. ⑤ 응용·활용 영역​

점검항목점검 내용
화면·시각화 설계사용자 요구에 부합하는 대시보드·차트 설계가 이루어졌는가, UI 표준·웹 접근성(KWCAG) 을 준수하는가
API·서비스 설계분석 결과 제공 API 규격·인증·유량 제어가 설계되었는가
업무 시스템 연계 설계결과 데이터의 소비 방식과 연계 인터페이스가 정의되었는가
사용자 권한 설계데이터 등급별 조회 권한·마스킹 정책이 설계되었는가

바. ⑥ 시스템구조 영역​

점검항목점검 내용
아키텍처 설계 적정성수집–저장–처리–분석–서비스 계층 구조가 요구사항을 충족하도록 설계되었는가
용량 산정(Capacity)데이터 증가율을 반영한 스토리지·노드 수·메모리 산정 근거가 타당한가
성능 설계배치 처리 시간·조회 응답 목표 달성을 위한 인덱싱·파티셔닝·캐싱 설계
확장성 설계수평 확장(Scale-out) 가능 구조인가, 클라우드 자동확장 설계 여부
가용성·복구 설계이중화·백업·복구(RTO/RPO) 방안이 데이터 규모에 맞게 설계되었는가
기술 스택 적정성도입 솔루션의 호환성·라이선스·기술 지원·유지보수성 검토
운영·모니터링 설계파이프라인 작업 스케줄링·실패 감지·알림·로그 수집 방안

사. ⑦ 보안·개인정보 영역​

점검항목점검 내용
접근 통제 설계데이터 등급별 접근 권한 및 최소권한 원칙 적용 설계
암호화 설계저장·전송 구간 암호화, 키 관리 방안(검증필 암호모듈 사용)
가명·비식별 처리 설계가명처리 항목·기법(마스킹·범주화·k-익명성) 및 적정성 평가 절차가 설계되었는가
재식별 위험 검토결합·분석 과정에서의 재식별 가능성 검토 및 통제 방안
로그·감사 설계접속기록·다운로드 이력 보관(법정 기간) 및 이상행위 탐지
데이터 반출 통제분석 결과 반출 심사 절차(분석 환경 격리, 결과값만 반출)
개인정보 파기 설계목적 달성 후 파기 절차 및 시점이 설계되었는가

Ⅳ. 감리 수행 시 고려사항​

고려사항내용
① 데이터 확보 위험의 조기 점검빅데이터 사업 실패의 최대 원인은 데이터 미확보이므로, 분석 단계에서 실제 데이터 샘플을 확인하고 제공 협의 결과를 문서로 검증해야 함
② "산출물 존재"가 아닌 "내용의 실효성" 점검데이터 품질진단서가 있어도 실제 진단 결과와 개선계획이 없으면 무의미 → 형식 점검을 넘어선 실질 점검
③ 정량 목표의 타당성 검증"정확도 95%"가 데이터 여건상 달성 가능한지, 어떤 기준으로 측정하는지를 함께 점검
④ 탐색적 특성의 인정분석·AI는 사전에 결과를 확정할 수 없음 → 요구사항 미확정 자체를 부적합으로 판정하기보다, 단계적 구체화 절차와 변경관리의 적정성을 점검
⑤ 개인정보 이슈의 우선 점검데이터 결합·가명처리는 위법 시 사업 중단으로 직결 → 분석 단계에서 반드시 법적 근거 확인
⑥ 운영 이후를 고려한 점검구축 완료 후 데이터 갱신·모델 재학습 체계가 없으면 곧 무용지물 → 운영 지속성 설계를 설계 단계에서 점검
⑦ 감리인의 전문성 확보빅데이터·AI 감리는 도메인·기술 이해가 필수 → 전문 감리인 투입 및 기술 자문 활용

Ⅴ. 결론​

「지능정보기술 감리 실무 가이드」의 발간 취지는 "전통 정보화사업의 감리 잣대를 빅데이터·AI 사업에 그대로 적용할 때 발생하는 괴리를 해소한다" 는 데 있다. 전통 감리는 화면·프로그램 등 기능 산출물을 중심으로 점검하지만, 빅데이터 사업의 실질적 산출물은 데이터 파이프라인·데이터 품질·분석 모델이므로 점검 대상 자체가 달라져야 한다.

빅데이터 사업 감리에서 가장 중요한 점검 관점은 "데이터 확보 가능성과 품질" 이다. 실무에서 빅데이터 사업이 실패하는 주된 원인은 시스템 구축의 실패가 아니라, 구축은 완료되었으나 담을 데이터가 없거나 품질이 목적에 미달하여 활용되지 못하는 것이다. 따라서 감리인은 분석 단계에서 실제 데이터 샘플과 제공 협의 결과를 반드시 확인하고, 확보 위험이 크면 조기에 범위 조정을 권고해야 한다. 설계가 완료된 뒤에 데이터 문제가 드러나면 사업 전체를 되돌려야 하기 때문이다.

두 번째 핵심은 "분석·AI 사업의 탐색적 특성을 감리 기준에 어떻게 반영할 것인가" 이다. 분석 결과는 사전에 확정할 수 없으므로, 요구사항이 미확정이라는 사실 자체를 부적합으로 판정하는 것은 비현실적이다. 대신 감리는 ① 목표 성능이 정량적·현실적으로 정의되었는지, ② 단계적 구체화 절차와 변경관리가 적절히 작동하는지, ③ 결과가 미달할 경우의 대응 방안이 마련되었는지를 점검하는 방향으로 전환되어야 한다. 이것이 가이드가 말하는 "현실적 감리기준" 의 실질적 의미이다.

세 번째로 강조할 점은 개인정보·법적 요건 점검의 우선순위이다. 데이터 결합·가명처리는 위법 시 사업 자체가 중단되고 기관이 제재를 받는 치명적 리스크이므로, 기술적 완성도보다 우선하여 분석 단계에서 처리 근거와 영향평가 수행 여부를 확인해야 한다.

마지막으로, 빅데이터 사업 감리는 구축 시점의 완성도만이 아니라 "운영 지속 가능성"을 함께 점검해야 한다. 데이터가 갱신되지 않고 모델이 재학습되지 않으면 시스템은 개통 직후부터 노후화된다. 따라서 설계 단계에서 데이터 갱신 체계, 품질 상시 관리, 모델 성능 모니터링과 재학습 체계(MLOps) 가 설계되었는지 확인하는 것이, 빅데이터 사업 감리가 전통 감리와 구별되는 가장 중요한 부가가치라 할 수 있다.
