블록 암호화 알고리즘

문제​

6.블록 암호화 알고리즘

Ⅰ. 개요​

블록 암호(Block Cipher) 는 평문을 고정 길이의 블록(64·128bit 등) 단위로 나누어, 동일한 비밀키로 각 블록을 암·복호화하는 대칭키 암호 알고리즘이다. 스트림 암호가 비트·바이트 단위로 처리하는 것과 대비된다.

   [**블록 암호의 기본 구조**]

   평문 ──(블록 분할 + **패딩**)──▶ P1 P2 P3 ... Pn
                                     │
              **비밀키 K** ──▶ [**키 확장(Key Schedule)**] ──▶ K1..Kr
                                     ▼
                        [**라운드 함수 r회 반복**]
                        **혼돈(Confusion)** : S-Box(치환)
                        **확산(Diffusion)** : P-Box(전치)/MixColumn
                                     ▼
   암호문 ◀── C1 C2 C3 ... Cn   (**운용모드**에 따라 블록 간 연쇄)

   ※ Shannon의 원리 : **혼돈 + 확산**의 반복으로 통계적 분석 차단

Ⅱ. 블록 암호의 구조 유형​

구조원리특징대표 알고리즘
Feistel 구조블록을 좌·우 반으로 분할, 한쪽에 라운드 함수 적용 후 XOR·교환을 r회 반복· 암·복호화 구조 동일(키 순서만 역순) → 구현 경제적
· 라운드 함수가 역함수일 필요 없음
· 한 라운드에 절반만 변환 → 라운드 수 多 필요		DES, 3DES, SEED, Blowfish, Camellia
SPN 구조
(Substitution-Permutation)		전체 블록에 치환(S-Box) → 전치(P-Box) → 키 XOR 를 반복· 한 라운드에 전 블록 변환 → 확산 빠름, 병렬성 우수
· 복호화 시 역함수 별도 구현 필요
· 하드웨어 구현 효율 높음		AES, ARIA, SHARK, Serpent
ARX 구조덧셈(Add)·회전(Rotate)·XOR 만 사용S-Box 없이 경량·고속, 부채널 내성 유리LEA, HIGHT, Speck

Ⅲ. 주요 블록 암호 알고리즘 비교​

알고리즘개발블록키 길이라운드구조특징
DES미국 (1977)64bit56bit16Feistel키 길이 부족 → 전수조사로 해독, 폐기
3DES미국64bit112/168bit48FeistelDES 3회 적용(EDE), 속도 저하, 단계적 퇴출
AES(Rijndael)미국 NIST (2001)128bit128/192/25610/12/14SPN세계 표준, HW 가속(AES-NI), 고속·안전
SEED한국 KISA (1999)128bit128/256bit16Feistel국내 표준(TTA·ISO/IEC 18033), 금융·전자상거래
ARIA한국 국정원·학계 (2004)128bit128/192/25612/14/16SPN국가 표준(KS), 공공기관 의무 적용, AES와 유사 구조
HIGHT한국 (2006)64bit128bit32ARX/Feistel경량 암호 — RFID·센서 등 저전력 환경
LEA한국 KISA (2013)128bit128/192/25624/28/32ARX고속 경량 암호, IoT·모바일, ISO/IEC 29192
IDEA / Blowfish / Camellia국제64/128bit128bit 등-FeistelPGP, 일본 표준(Camellia) 등

Ⅳ. 운용 모드(Mode of Operation)​

블록 암호는 한 블록만 처리하므로, 긴 평문 처리를 위해 블록 간 연결 방식(운용 모드) 이 반드시 필요하다.

모드원리특징
ECB(Electronic Codebook)각 블록을 독립 암호화병렬 처리 가능하나 같은 평문 → 같은 암호문, 패턴 노출 → 사용 금지
CBC(Cipher Block Chaining)직전 암호문과 XOR 후 암호화, IV 필요패턴 은닉, 암호화는 순차(병렬 불가), 오류 전파 2블록, 패딩 오라클 주의
CFB / OFB블록 암호를 스트림 암호처럼 사용패딩 불필요, OFB는 오류 전파 없음
CTR(Counter)카운터 값을 암호화한 키스트림과 XOR완전 병렬·랜덤 액세스 가능, 패딩 불필요, Nonce 재사용 절대 금지
GCM(Galois/Counter)CTR + GHASH 인증 태그기밀성 + 무결성·인증 동시 제공(AEAD) — TLS 1.3 표준, 고속
CCM / XTSCTR+CBC-MAC / 디스크 전용경량 AEAD / 저장장치 전체 암호화(BitLocker 등)
   [**모드 선택 실무 지침**]
   ✕ **ECB** ─ 어떤 경우에도 사용 금지(이미지 윤곽 노출 사례)
   △ **CBC** ─ 레거시 호환, **MAC 별도 결합 필수**(Encrypt-then-MAC)
   ○ **GCM** ─ **기본 권장**(TLS·VPN·API) — 인증 암호(AEAD)
   ○ **XTS** ─ 디스크·저장장치 암호화

Ⅴ. 특징·공격 기법 및 활용​

구분내용
장점· 공개키 대비 연산 속도 100~1,000배 빠름 → 대용량 데이터 암호화에 적합
· 알고리즘 공개·검증으로 안전성 신뢰(Kerckhoffs 원칙)
· HW 가속(AES-NI) 지원으로 성능 우수
단점· 키 배송(Key Distribution) 문제 → 공개키·키교환(ECDH)과 하이브리드 사용
· 사용자 n명 시 키 개수 n(n-1)/2 로 폭증
· 부인방지·전자서명 불가(대칭키의 한계)
· 패딩·IV·Nonce 오용 시 취약(실무 사고의 주원인)
주요 공격차분 공격(Differential), 선형 공격(Linear), 전수조사(Brute-force), 중간자 만남 공격(MITM, 2DES), 부채널 공격(전력·시간·캐시), 패딩 오라클
활용TLS/SSL 세션 암호, VPN(IPSec), 디스크 암호화, DB 컬럼 암호화, 파일 암호화, 무선(WPA2/3-AES), 공인전자문서, 금융 IC카드
국내 적용 기준내용
국가 암호 정책공공기관은 검증필 암호모듈(KCMVP) 및 국산 알고리즘(SEED·ARIA·LEA·HIGHT) 사용
개인정보 안전성 확보조치 기준고유식별정보·비밀번호 등 안전한 암호 알고리즘 적용 의무
권고 키 길이대칭키 128bit 이상(2030년 이후 고려 시 256bit 권장)

Ⅵ. 결론​

블록 암호는 정보보호의 기밀성을 담보하는 가장 기본적이고 실용적인 수단으로, 현재는 AES(국제)와 ARIA·SEED·LEA(국내) 가 사실상 표준으로 자리 잡았다. DES는 키 길이 부족으로 이미 폐기되었고 3DES 역시 퇴출 단계이므로, 레거시 시스템의 알고리즘 현행화가 실무적 과제이다.

실무에서 유의할 핵심은 "알고리즘의 안전성보다 운용의 안전성이 사고를 좌우한다" 는 점이다. AES를 쓰더라도 ECB 모드 사용, IV 고정, CTR Nonce 재사용, 키 하드코딩 같은 오용이 있으면 암호는 무력화된다. 따라서 ① AEAD 모드(GCM) 기본 채택, ② IV/Nonce의 난수성·유일성 보장, ③ HSM/KMS 기반 키 관리와 정기 키 교체가 반드시 함께 설계되어야 한다.

향후에는 양자컴퓨터 대응이 변수이다. 공개키 암호는 Shor 알고리즘으로 근본적 위협을 받는 반면, 블록 암호는 Grover 알고리즘에 의해 실효 강도가 절반으로 감소하는 수준이므로 키 길이를 2배(AES-256)로 확대하면 대응 가능하다. 따라서 PQC 전환기에도 블록 암호는 AES-256/ARIA-256으로의 강화를 통해 계속 핵심 역할을 수행할 것이다.
