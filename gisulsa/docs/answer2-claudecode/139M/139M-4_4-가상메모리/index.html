가상메모리(Virtual Memory)

Ⅰ. 개요​

1. 개념 및 목적​

가상메모리는 보조기억장치의 일부를 주기억장치처럼 사용하여, 물리 메모리 크기의 제약 없이 프로그램을 실행할 수 있게 하는 기법이다. 프로세스마다 독립된 가상 주소공간을 제공함으로써 다중 프로그래밍 정도(Degree of Multiprogramming)를 높이고 프로세스 간 메모리 보호를 실현한다.

2. 동작 기반 원리​

 [논리주소]      ┌─────────┐      [물리주소]
  프로세스  ───► │ MMU/TLB │ ───►  주기억장치(RAM)
   (Virtual)     └────┬────┘         │
                      │ Page Fault   │ 없으면
                      ▼              ▼
              페이지 테이블 참조 → 보조기억장치(Swap 영역)에서 반입
  • 구역성(Locality) 원리: 시간 구역성(최근 참조 재참조)과 공간 구역성(인접 주소 참조)에 의해, 전체 프로그램이 아닌 일부만 적재해도 정상 실행이 가능하다는 것이 가상메모리의 이론적 근거이다.

Ⅱ. 가. 가상메모리 관리기법​

1. 주소 공간 분할 기법​

기법원리특징
페이징(Paging)가상·물리 공간을 동일 크기 블록(Page/Frame) 으로 분할외부 단편화 없음, 내부 단편화 발생, 논리적 의미 무시
세그멘테이션(Segmentation)프로그램을 논리 단위(코드·데이터·스택) 로 가변 분할내부 단편화 없음, 외부 단편화 발생, 보호·공유 용이
페이지드 세그멘테이션세그먼트를 다시 페이지로 분할두 기법의 장점 결합, 주소변환 2단계로 오버헤드 증가

2. 주소변환 및 성능 지원 기법​

기법내용
페이지 테이블가상 페이지 → 물리 프레임 매핑, 유효비트·보호비트·수정비트(Dirty)·참조비트 관리
다단계 페이지 테이블테이블을 계층화하여 미사용 구간의 테이블 생성 생략(테이블 크기 절감)
역페이지 테이블(IPT)프레임 기준 단일 테이블 유지 → 프로세스 수와 무관하게 크기 고정
TLB(Translation Lookaside Buffer)최근 주소변환 결과를 캐싱하는 연관 메모리 → 변환 지연 대폭 감소
유효 접근시간EAT = h × (TLB+메모리) + (1−h) × (테이블+메모리), 페이지 폴트율 반영

3. 반입(Fetch) 기법​

기법내용
요구 페이징(Demand Paging)참조 시점에 반입 — 불필요한 적재 없음, 초기 페이지 폴트 다발
예상 페이징(Prepaging)참조될 것으로 예측되는 페이지를 미리 반입 — 예측 실패 시 낭비

4. 배치(Placement) 기법 — 세그멘테이션·가변 분할​

기법원리특징
First Fit처음 만나는 충분한 공간에 배치속도 빠름
Best Fit가장 작은 잔여공간이 남는 곳잔여공간 최소, 미세 조각 다량 발생
Worst Fit가장 큰 공간에 배치큰 잔여공간 유지, 대형 요청 수용 곤란
Next Fit이전 탐색 위치부터 검색탐색 편중 완화

5. 교체(Replacement) 기법​

기법원리특징
OPT(최적)가장 나중에 참조될 페이지 교체이론적 최적(구현 불가), 성능 비교 기준
FIFO가장 먼저 적재된 페이지 교체단순, Belady의 이상현상 발생
LRU가장 오래 참조되지 않은 페이지 교체성능 우수, 참조시간 추적 오버헤드
LFU참조 횟수가 가장 적은 페이지 교체초기 적재 페이지에 불리
NUR / Clock(Second Chance)참조비트·수정비트로 근사 LRU 구현오버헤드 적어 실제 OS에서 채택
Working Set일정 시간(Δ) 내 참조 페이지 집합 유지스래싱 방지에 효과적
PFF(Page Fault Frequency)폴트 발생 빈도에 따라 프레임 수 동적 조절적응적 관리

6. 할당(Allocation) 기법​

구분내용
고정 / 가변 할당프로세스당 프레임 수를 고정하거나 실행 중 조정
균등 / 비례 할당프로세스 수로 균등 분배 또는 프로세스 크기에 비례 분배
전역 / 지역 교체전체 프레임에서 희생자 선택(전역) vs 자기 프레임 내에서만 선택(지역)

7. 스래싱(Thrashing)​

  • 개념: 다중 프로그래밍 정도가 과도해져 페이지 교체에만 CPU를 소모하고 실제 처리량이 급감하는 현상
  • 대응: Working Set 모형, PFF, 다중 프로그래밍 정도 조절(일부 프로세스 Suspend), 물리 메모리 증설

Ⅲ. 나. 가상메모리 단편화 유형​

1. 단편화의 개념​

단편화(Fragmentation) 는 메모리가 할당·해제를 반복하는 과정에서 사용 가능한 공간이 존재하나 실제로 활용할 수 없는 상태를 말한다.

 [내부 단편화 — 페이징]              [외부 단편화 — 세그멘테이션]
 Page 크기 4KB, 요청 10KB            할당 요청 6KB
 ┌────┬────┬────────────┐           ┌───┬─────┬───┬───────┬───┐
 │4KB │4KB │2KB + 2KB낭비│          │사용│빈3KB│사용│빈4KB │사용│
 └────┴────┴────────────┘           └───┴─────┴───┴───────┴───┘
   마지막 페이지 내부에 낭비          총 빈공간 7KB > 6KB 이나
                                     연속되지 않아 할당 불가

2. 단편화 유형​

유형발생 원인발생 기법특징
내부 단편화
(Internal)		고정 크기 블록 할당 시 요청 크기와의 차이만큼 블록 내부에 잔여공간 발생페이징, 고정 분할, Buddy System평균 페이지 크기의 1/2 낭비 (프로세스당 마지막 페이지)
외부 단편화
(External)		가변 크기 할당·해제 반복으로 작은 빈 공간이 비연속적으로 산재세그멘테이션, 가변 분할총량은 충분하나 연속 공간 확보 불가
테이블 단편화
(Table Fragmentation)		페이지 테이블 자체가 주기억장치를 점유하는 관리 오버헤드페이징(특히 소형 페이지)페이지 크기 축소 시 테이블 크기 급증

3. 보조 개념 — 관련 낭비 요인​

항목내용
Swap 공간 단편화스왑 영역에서도 동일하게 단편화 발생 → 입출력 성능 저하
가상 주소공간 단편화큰 연속 가상영역 할당(mmap) 실패 — 64bit에서는 완화
TLB 미스 증가페이지 수 증가 → TLB 커버리지 감소 → 변환 오버헤드

Ⅳ. 다. 단편화 최소화 방안​

1. 내부 단편화 최소화​

방안내용
적정 페이지 크기 선택페이지가 작으면 내부 단편화↓·테이블 크기↑, 크면 반대 → Trade-off 균형점 결정
다중 페이지 크기 지원Huge Page(2MB·1GB) + 일반 페이지 혼용 → 대용량 영역은 큰 페이지, 소형은 작은 페이지
Slab / Slub Allocator동일 크기 객체 전용 캐시를 유지하여 커널 객체 할당 낭비 제거
크기별 프리리스트요청 크기 계층(Size Class)별 풀 관리(Segregated Fit)
Buddy System 보완2의 거듭제곱 할당의 낭비를 Slab과 병용하여 완화

2. 외부 단편화 최소화​

방안내용
페이징 채택고정 크기 프레임 사용으로 외부 단편화 원천 제거(가장 근본적 해법)
압축(Compaction)사용 중 블록을 한쪽으로 이동하여 빈 공간을 하나로 통합 — 이동 비용·중단시간 큼
통합(Coalescing)해제 시 인접 빈 공간을 즉시 병합
배치 기법 선택Best Fit의 미세조각 문제 → First Fit·Next Fit 또는 Segregated Fit 활용
페이지드 세그멘테이션세그먼트를 페이지 단위로 분할하여 외부 단편화 제거 + 논리적 보호 유지

3. 테이블 단편화 및 오버헤드 최소화​

방안내용
다단계 페이지 테이블미사용 주소구간의 하위 테이블을 생성하지 않음
역페이지 테이블(IPT)물리 프레임 수에 비례하는 단일 테이블로 크기 고정
해시 페이지 테이블희소 주소공간에 효율적
TLB 최적화TLB 적중률 향상, Huge Page로 TLB 커버리지 확대, ASID로 문맥교환 시 무효화 최소화

4. 운영·응용 수준 방안​

방안내용
메모리 풀 / Arena 할당응용에서 미리 확보한 블록 내에서 재사용 → 할당·해제 반복 감소
객체 재사용Object Pool, 커넥션 풀로 빈번한 할당 회피
압축 메모리(zswap/zram)스왑 대상 페이지를 압축 저장하여 실효 메모리 확대
메모리 압축·이주Memory Compaction(Linux), 페이지 마이그레이션으로 연속 공간 확보
Garbage Collection관리형 런타임에서 Compacting GC로 힙 단편화 해소
용량 계획워크로드별 메모리 사용 프로파일링, 적정 물리 메모리 산정으로 스래싱 예방
NUMA 고려노드 지역성 확보로 원격 접근 지연 최소화

Ⅴ. 결론​

가상메모리는 구역성 원리에 기반한 요구 페이징과 교체 기법을 통해 물리 메모리 한계를 극복하고 프로세스 보호를 제공하는 핵심 기법이다. 그러나 페이징은 내부 단편화와 테이블 오버헤드를, 세그멘테이션은 외부 단편화를 필연적으로 수반하므로, 실제 운영체제는 페이지드 세그멘테이션과 다단계 페이지 테이블·TLB를 결합하여 이를 완화한다.

단편화 최소화의 핵심은 페이지 크기 선택의 Trade-off를 워크로드에 맞게 결정하는 것이며, 실무적으로는 대용량 메모리 워크로드에 Huge Page와 메모리 풀을 적용하고 커널 수준에서는 Slab 할당자를 활용하는 것이 효과적이다. 아울러 단편화보다 성능에 치명적인 것은 스래싱이므로, Working Set 기반 용량 산정과 다중 프로그래밍 정도 관리가 선행되어야 한다.
