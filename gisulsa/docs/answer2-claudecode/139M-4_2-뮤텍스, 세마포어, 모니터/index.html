프로세스 동기화 기법 — 뮤텍스(Mutex), 세마포어(Semaphore), 모니터(Monitor)

Ⅰ. 개요​

1. 동기화의 필요성​

다중 프로세스·스레드가 공유자원(Critical Section) 에 동시 접근하면 실행 순서에 따라 결과가 달라지는 경쟁 조건(Race Condition) 이 발생한다. 이를 방지하기 위해 상호배제를 보장하는 동기화 기법이 필요하다.

2. 임계구역 문제의 해결 요건​

요건내용
상호배제(Mutual Exclusion)임계구역에는 최대 1개 프로세스만 진입
진행(Progress)임계구역이 비어 있으면 대기자 중 하나는 반드시 진입
한정 대기(Bounded Waiting)무한 대기(Starvation) 없이 유한 시간 내 진입 보장
 do {
     ┌──── entry section ────┐   ← lock / P(wait) / monitor 진입
     │    Critical Section   │   ← 공유자원 접근
     └──── exit section ─────┘   ← unlock / V(signal) / monitor 이탈
        remainder section
 } while (true);

Ⅱ. 뮤텍스(Mutex)​

1. 개념​

뮤텍스(Mutual Exclusion Lock) 는 오직 하나의 스레드만 자원을 점유하도록 보장하는 이진 잠금(Locking) 객체이다. 잠금을 획득한 주체만 해제할 수 있는 소유권(Ownership) 개념을 갖는 것이 핵심 특징이다.

2. 동작 원리​

 lock(m)   : m이 unlocked → locked로 전환하고 진입
             m이 locked   → 대기(Blocking) 또는 회전(Spin)
 unlock(m) : 소유 스레드만 해제 가능 → 대기 스레드 중 하나 깨움
  • 원자적 연산 기반: Test-and-Set, Compare-and-Swap(CAS), Fetch-and-Add 등 하드웨어 원자 명령으로 구현
  • 구현 변형: 스핀락(Spinlock — 짧은 임계구역, 커널), 재귀 뮤텍스(Recursive), 읽기-쓰기 락(RW Lock)

3. 특징​

항목내용
상태Locked / Unlocked (2가지)
소유권있음 — 획득한 스레드만 해제 가능
용도상호배제 전용
적용 범위주로 동일 프로세스 내 스레드 간
장점구현 단순, 오버헤드 작음, 소유권으로 오용 방지
단점자원 1개만 관리, 스핀락은 CPU 낭비, 우선순위 역전 발생 가능

Ⅲ. 세마포어(Semaphore)​

1. 개념​

세마포어는 Dijkstra가 제안한 정수형 카운터 기반 동기화 도구로, 사용 가능한 자원의 개수를 관리하여 최대 N개의 프로세스가 동시에 자원에 접근하도록 허용한다.

2. 동작 원리 — P/V 연산​

 P(wait) 연산                     V(signal) 연산
 ────────────────                 ─────────────────
 S = S − 1;                       S = S + 1;
 if (S < 0)                       if (S ≤ 0)
     block(자신을 대기큐로);          wakeup(대기큐의 프로세스 1개);

P·V 연산은 반드시 원자적(Atomic) 으로 실행되어야 하며, 이는 하드웨어 명령 또는 커널의 인터럽트 금지로 보장한다.

3. 유형​

유형초기값용도
이진 세마포어(Binary)1상호배제 — 뮤텍스와 유사한 역할
계수 세마포어(Counting)N자원 풀 관리(DB 커넥션 N개, 버퍼 슬롯)

4. 활용 — 생산자·소비자 문제​

 세마포어 : empty = N(빈 슬롯), full = 0(채워진 슬롯), mutex = 1

 [Producer]                        [Consumer]
 P(empty);                         P(full);
 P(mutex);                         P(mutex);
   버퍼에 삽입                        버퍼에서 추출
 V(mutex);                         V(mutex);
 V(full);                          V(empty);
  • 계수 세마포어(empty·full)는 실행 순서 제어(Signaling) 를, 이진 세마포어(mutex)는 상호배제를 담당한다.

5. 특징 및 한계​

항목내용
장점다중 자원 관리 가능, 순서 제어(Signaling) 지원, 프로세스 간(IPC) 사용 가능
단점소유권 없음 → 다른 프로세스가 V 연산 가능(오용 위험)
P/V 호출 누락·순서 오류 시 교착상태·기아 발생
저수준 도구로 코드 분산 → 유지보수·디버깅 곤란

Ⅳ. 모니터(Monitor)​

1. 개념​

모니터는 Hoare·Brinch Hansen이 제안한 고수준 동기화 구조체로, 공유 데이터와 이를 조작하는 프로시저를 하나의 캡슐로 묶고, 동시에 하나의 프로세스만 모니터 내부에서 활동하도록 컴파일러·언어 차원에서 상호배제를 자동 보장한다.

2. 구조​

 monitor SharedResource {
     shared_data;                      ← 외부 직접 접근 불가(캡슐화)
     condition c;                      ← 조건변수

     procedure P1() { ... c.wait(); ... }
     procedure P2() { ... c.signal(); ... }
     initialization_code();
 }
        ┌──────── 진입 큐(Entry Queue) ────────┐
        │  P1  P2  P3 ...  → 1개만 내부 진입    │
        └──────────────────────────────────────┘
                     조건변수 대기 큐 : c.wait()로 진입, c.signal()로 해제

3. 조건변수(Condition Variable)​

연산내용
wait()모니터 잠금을 반납하고 조건 큐에서 대기(다른 프로세스 진입 허용)
signal()대기 중인 프로세스 1개를 깨움(대기자 없으면 무효과 — 세마포어와 달리 누적되지 않음)
broadcast()대기 중인 모든 프로세스를 깨움
  • Hoare(Signal-and-Wait): signal 호출자가 즉시 양보 → 조건 보장이 확실
  • Mesa(Signal-and-Continue): 호출자가 계속 실행 → 깨어난 측은 조건 재확인 필요 → while 루프로 조건 검사 필수

4. 특징​

항목내용
장점상호배제 자동 보장, 캡슐화로 오용 방지, 코드 가독성·유지보수성 우수
단점언어·런타임 지원 필요, 유연성 낮음, 조건변수 오사용 시 여전히 교착 가능
구현 사례Java synchronized + wait()/notify()/notifyAll(), C# lock/Monitor, Python threading.Condition

Ⅴ. 세 기법의 비교​

비교 기준뮤텍스(Mutex)세마포어(Semaphore)모니터(Monitor)
추상화 수준저수준저수준고수준(언어 지원)
상태·값Locked / Unlocked정수 카운터(0~N)잠금 + 조건변수
관리 자원 수1개N개1개(모니터 단위)
소유권있음(획득자만 해제)없음있음(내부 활동 프로세스)
주요 기능상호배제상호배제 + 순서 제어(Signaling)상호배제 + 조건 동기화
상호배제 보장프로그래머 책임프로그래머 책임컴파일러·런타임 자동
신호 누적해당 없음누적됨(카운터 증가)누적 안 됨(signal 유실 가능)
적용 범위스레드 간(프로세스 내)프로세스 간(IPC) 가능동일 프로세스 내
오류 위험낮음높음(P/V 누락·순서 오류)낮음
성능가장 빠름보통(문맥교환 발생)보통(구현에 따라 오버헤드)
대표 활용공유 변수 보호커넥션 풀, 생산자·소비자객체 단위 동기화(Java)

관계 정리​

 [세마포어] ──초기값 1로 제한──► [이진 세마포어] ≈ 뮤텍스(소유권 제외)
 [뮤텍스 + 조건변수] ──캡슐화──► [모니터]

Ⅵ. 사용 시 고려사항​

문제내용대응 방안
교착상태(Deadlock)상호배제·점유대기·비선점·순환대기 4조건 성립잠금 획득 순서 통일, 타임아웃, 계층적 락, 은행원 알고리즘
기아(Starvation)특정 프로세스가 계속 진입 실패FIFO 대기큐, 공정성(Fair) 락, 우선순위 에이징
우선순위 역전저순위 스레드가 락 점유로 고순위 지연우선순위 상속(Priority Inheritance), 우선순위 상한
성능 저하락 경합·문맥교환 비용임계구역 최소화, 락 분할(Sharding), 읽기-쓰기 락, Lock-Free(CAS)·원자 변수
Lost Wakeupsignal이 wait보다 먼저 발생조건을 while 루프로 재확인(Mesa 방식)
설계 원칙저수준 도구 직접 사용 시 오류율 상승가능하면 모니터·고수준 병행 라이브러리 활용

Ⅶ. 결론​

세 기법은 모두 상호배제를 목적으로 하지만, 뮤텍스는 단일 자원의 배타적 점유, 세마포어는 다중 자원 관리와 실행 순서 제어, 모니터는 캡슐화를 통한 안전한 고수준 동기화로 역할이 구분된다. 세마포어는 표현력이 가장 크지만 P/V 연산의 오용으로 교착상태를 유발하기 쉬우므로, 실무에서는 모니터나 언어·라이브러리가 제공하는 고수준 병행 도구를 우선 사용하는 것이 바람직하다.

동기화의 핵심 원칙은 임계구역을 최소화하고 잠금 획득 순서를 일관되게 유지하는 것이며, 최근에는 락 경합 자체를 회피하는 불변 객체·메시지 전달·Lock-Free 자료구조 등 설계 차원의 접근이 확대되고 있다.
