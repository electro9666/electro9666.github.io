네트워크 서브네팅(Subnetting)과 VLSM 설계

Ⅰ. 개요​

IP 주소는 유한 자원이므로 주소 공간의 효율적 활용과 라우팅 테이블 축약이 네트워크 설계의 핵심 과제이다. 서브네팅은 하나의 네트워크를 분할하여 주소 효율·보안·관리성을 높이고, 슈퍼네팅은 연속된 네트워크를 통합하여 라우팅 효율을 높인다. VLSM은 서브넷별로 서로 다른 마스크를 적용하여 주소 낭비를 최소화하는 기법이다.

        분 할 (Subnetting)                  통 합 (Supernetting)
 192.168.0.0/22 ──► /23, /24, /25    192.168.0.0/24 + 1.0/24 ──► /23
   Prefix 증가, 네트워크 수 증가        Prefix 감소, 라우팅 항목 감소

Ⅱ. 가. 슈퍼네팅과 서브네팅의 개념​

1. 서브네팅(Subnetting)​

서브네팅은 호스트 비트의 일부를 네트워크 비트로 전환하여 하나의 네트워크를 복수의 논리적 하위 네트워크로 분할하는 기법이다.

  • 원리: 프리픽스 길이 증가(/24 → /25) → 네트워크 수 2ⁿ배 증가, 서브넷당 호스트 수 감소
  • 목적: IP 주소 효율적 할당, 부서·업무별 네트워크 분리, 브로드캐스트 도메인 축소, 보안 정책(VLAN·ACL) 적용, 장애 파급 범위 축소
 192.168.0.0/24  (호스트 254개)
        ├── 192.168.0.0/25    (호스트 126개)
        └── 192.168.0.128/25  (호스트 126개)

2. 슈퍼네팅(Supernetting)​

슈퍼네팅은 연속된 복수 네트워크의 공통 상위 비트를 기준으로 하나의 큰 네트워크로 집약하는 기법으로, 경로 집약(Route Aggregation) / CIDR이라고도 한다.

  • 원리: 프리픽스 길이 감소(/24 → /22) → 여러 경로를 하나의 광고 항목으로 통합
  • 목적: 라우팅 테이블 항목 축소, 라우팅 업데이트 트래픽 감소, 경로 탐색 속도 향상, 주소 고갈 완화(Classful 주소체계 탈피)
 192.168.0.0/24 ┐
 192.168.1.0/24 ├──► 192.168.0.0/22   (상위 22bit 공통)
 192.168.2.0/24 │      11000000.10101000.000000|00.00000000
 192.168.3.0/24 ┘                            └─ 공통 프리픽스 22bit

3. 비교​

비교 기준서브네팅(Subnetting)슈퍼네팅(Supernetting)
목적네트워크 분할네트워크 통합·집약
프리픽스 길이증가(/22 → /24)감소(/24 → /22)
네트워크 수증가감소
서브넷 마스크길어짐짧아짐
비트 전환호스트 비트 → 네트워크 비트네트워크 비트 → 호스트 비트
라우팅 테이블항목 증가항목 감소
적용 위치조직 내부(LAN 설계)조직 경계·ISP(BGP 광고)
주요 효과주소 효율·보안·관리성라우팅 효율·확장성
전제 조건충분한 호스트 비트연속된 주소 블록(비트 경계 정렬)

VLSM(Variable Length Subnet Mask): 하나의 대역을 요구 호스트 수에 따라 서로 다른 마스크로 분할하는 기법. FLSM(고정 길이) 대비 주소 낭비를 크게 줄인다.

Ⅲ. 나. 192.168.0.0/22 대역의 VLSM 분할 설계​

1. 가용 주소 공간 분석​

 192.168.0.0/22
 · 전체 주소 범위 : 192.168.0.0 ~ 192.168.3.255
 · 전체 주소 수   : 2^(32−22) = 2^10 = 1,024개
 · 서브넷 마스크  : 255.255.252.0

2. 요구사항별 소요 블록 산정​

각 부서는 네트워크 주소와 브로드캐스트 주소 2개를 제외한 호스트 수를 충족해야 하므로, 필요 호스트 + 2 이상을 만족하는 최소 2의 거듭제곱 블록을 산정한다.

부서필요 호스트필요 주소 수
(호스트+2)		최소 블록
(2ⁿ)		호스트 비트PrefixSubnet Mask가용 호스트

영업팀2502522568/24255.255.255.0254

 소요 주소 총계 = 512 + 256 + 128 + 128 = 1,024개
 가용 주소 총계 = 1,024개   ⇒  /22 대역을 낭비 없이 정확히 소진

3. VLSM 할당 원칙​

VLSM은 주소 중첩과 단편화를 방지하기 위해 다음 원칙을 준수한다.

  1. 요구 호스트 수가 큰 서브넷부터 내림차순으로 할당 (개발팀 → 영업팀 → 인사팀 → 보안팀)
  2. 각 블록의 시작 주소는 자신의 블록 크기 경계에 정렬(/23은 0·2·4…, /25는 0·128 배수)
  3. 이전 블록의 브로드캐스트 주소 다음 주소부터 이어서 할당
 192.168.0.0/22 (1,024)
   ├── 개발팀 /23 : 192.168.0.0   ~ 192.168.1.255   (512개)
   ├── 영업팀 /24 : 192.168.2.0   ~ 192.168.2.255   (256개)
   ├── 인사팀 /25 : 192.168.3.0   ~ 192.168.3.127   (128개)
   └── 보안팀 /25 : 192.168.3.128 ~ 192.168.3.255   (128개)

6. 검증​

검증 항목결과
주소 중첩(Overlap)없음 — 각 블록이 연속·비중첩으로 배치
블록 경계 정렬/23은 0의 배수(0.0), /24는 2.0, /25는 3.0·3.128 — 모두 정렬 충족
요구 호스트 충족4개 부서 모두 충족(여유 각 10·4·1·1개)
주소 활용률1,000 / 1,024 = 97.7% — 낭비 최소
경로 집약상위 라우터에서 192.168.0.0/22 단일 경로로 집약 광고 가능

Ⅳ. VLSM 설계 시 고려사항​

고려사항내용
확장성 여유 부족본 설계는 /22 대역을 100% 소진하여 예비 주소가 없음. 게이트웨이·서버·프린터·AP·네트워크 장비 IP를 감안하면 실제로는 부족할 수 있으므로, /21 이상 대역 확보 또는 부서별 인원 재산정이 필요
대규모 우선 할당반드시 호스트 수가 많은 서브넷부터 할당해야 단편화·중첩 방지
예약 주소네트워크·브로드캐스트 주소는 호스트에 할당 불가, 게이트웨이용 주소(통상 .1) 별도 예약
프로토콜 요건VLSM 경로 광고를 위해 Classless 라우팅 프로토콜(OSPF, EIGRP, BGP, RIPv2) 필수 — RIPv1은 지원 불가
보안 분리서브넷을 VLAN·ACL·방화벽 정책과 1:1 연계하여 부서 간 접근 통제
라우팅 효율하위는 VLSM으로 세분화하되 상위로는 /22 슈퍼네팅으로 집약하여 라우팅 테이블 최소화
주소 관리IPAM 도구로 대역 할당 이력 관리, DHCP 풀과 고정 IP 구간 분리
향후 전환IPv6 병행 계획(듀얼 스택) 및 사설 대역 중복 회피(M&A 시 대역 충돌) 검토

Ⅴ. 결론​

서브네팅은 프리픽스를 늘려 네트워크를 분할함으로써 주소 효율성·보안성·관리성을 높이고, 슈퍼네팅은 프리픽스를 줄여 경로를 집약함으로써 라우팅 테이블과 갱신 트래픽을 감소시키는 상반된 방향의 기법이다.

주어진 192.168.0.0/22 대역은 VLSM을 적용하여 개발팀 192.168.0.0/23(255.255.254.0), 영업팀 192.168.2.0/24(255.255.255.0), 인사팀 192.168.3.0/25(255.255.255.128), 보안팀 192.168.3.128/25(255.255.255.128) 로 분할하면 4개 부서의 요구를 모두 충족하면서 주소 활용률 97.7%를 달성한다.

다만 본 설계는 예비 주소가 전무하므로, 실무 적용 시에는 네트워크 장비·서버용 주소와 향후 인원 증가분을 반영하여 /21 이상의 대역을 확보하거나 부서별 소요를 재산정해야 하며, VLSM 적용을 위해 OSPF 등 Classless 라우팅 프로토콜과 VLAN·ACL 정책을 함께 설계해야 한다.
