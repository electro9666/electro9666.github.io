벡터 데이터베이스의 HNSW와 IVF 동작원리

Ⅰ. 개요​

1. 벡터 데이터베이스와 ANN의 필요성​

벡터 데이터베이스는 텍스트·이미지를 임베딩한 고차원 벡터를 저장하고, 질의 벡터와 의미적으로 유사한 벡터를 검색하는 DB이다. RAG·추천·이미지 검색의 핵심 인프라이다.

   [문제] 정확한 최근접 이웃(k-NN) 탐색 = **전수 비교 O(N×D)**
          1억 개 × 768차원 → 질의 1건에 수 초~수십 초 소요 (실시간 서비스 불가)
          + **차원의 저주**로 인덱스 효율 급감
   [해법] **ANN(Approximate Nearest Neighbor, 근사 최근접 이웃)**
          → **정확도를 약간 희생하는 대신 속도를 수백~수천 배 향상**

2. ANN 인덱스의 분류​

계열원리대표
그래프 기반벡터 간 근접 관계를 그래프로 연결 후 탐색HNSW, NSG
클러스터(역색인) 기반벡터 공간을 분할하고 일부 영역만 탐색IVF, IVF-PQ
해시 기반유사 벡터를 같은 버킷으로 해싱LSH
트리 기반공간 분할 트리Annoy, KD-Tree
양자화벡터 압축으로 메모리·연산 절감PQ, SQ

Ⅱ. HNSW(Hierarchical Navigable Small World)의 동작원리​

1. 개념​

HNSW는 스킵 리스트(Skip List)의 계층 구조와 NSW(Navigable Small World) 그래프를 결합한 그래프 기반 ANN 인덱스이다. 상위 계층은 희소한 장거리 연결(고속 이동), 하위 계층은 조밀한 근거리 연결(정밀 탐색) 로 구성하여, 로그 시간에 근접 이웃을 찾는다.

2. 구조​

   [계층 구조 — 상위일수록 노드 수가 적고 연결이 김]

   Layer 2   ●───────────────────────●            ← 희소(장거리 점프)
              ╲                     ╱
   Layer 1    ●────────●───────────●──────●       ← 중간 밀도
               ╲      ╱ ╲         ╱      ╱
   Layer 0    ●──●──●──●──●──●──●──●──●──●        ← **모든 벡터 포함(조밀)**
              └────────── 최종 정밀 탐색 ─────────┘

   ※ 각 노드의 최대 계층은 **지수 분포 확률로 무작위 결정**
     (레벨 L에 속할 확률 ∝ exp(−L/mL)) ⇒ 상위로 갈수록 노드 수 급감

3. 탐색(Search) 과정​

   ① **최상위 계층의 진입점(Entry Point)** 에서 시작
        │
   ② 현재 노드의 이웃 중 **질의 벡터와 더 가까운 노드로 이동**(탐욕 탐색)
        │  더 가까운 이웃이 없으면 → 해당 계층의 지역 최적점 도달
        ▼
   ③ **한 계층 아래로 하강**, 그 지점을 진입점으로 다시 탐욕 탐색 반복
        │
   ④ **Layer 0 도달** → **efSearch 크기의 후보 큐**를 유지하며 정밀 탐색
        │  (단순 탐욕이 아닌 우선순위 큐 기반 Best-First Search)
        ▼
   ⑤ 상위 k개 결과 반환    ⇒ 평균 시간복잡도 **O(log N)**

4. 구축(Insert) 과정 및 주요 파라미터​

단계내용
① 레벨 결정지수 분포 난수로 새 노드의 최대 레벨 결정
② 진입·탐색최상위부터 하강하며 각 계층에서 가장 가까운 이웃 탐색
③ 연결 생성각 계층에서 M개의 이웃과 양방향 연결
④ 가지치기(Heuristic)이웃이 최대치 초과 시, 단순 최근접이 아닌 방향 다양성을 고려해 연결 선별 → 그래프의 탐색 가능성(Navigability) 유지
파라미터의미영향
M노드당 최대 연결 수↑ 정확도·메모리 ↑, 구축 시간 ↑ (통상 16~48)
efConstruction구축 시 탐색 후보 크기↑ 그래프 품질·정확도 ↑, 구축 시간 ↑
efSearch검색 시 후보 큐 크기↑ 정확도(Recall) ↑, 검색 속도 ↓ — 런타임 조절 가능

5. 특징​

구분내용
장점최고 수준의 검색 속도·정확도(Recall), 별도 학습 불필요, 점진적 삽입 가능, efSearch로 런타임 속도-정확도 조절
단점메모리 사용량 매우 큼(원본 벡터 + 그래프 연결 정보), 삭제 처리 비효율(소프트 삭제 후 재구축 필요), 구축 시간 김

Ⅲ. IVF(Inverted File Index)의 동작원리​

1. 개념​

IVF는 텍스트 검색의 역색인(Inverted Index) 개념을 벡터에 적용한 기법으로, 전체 벡터 공간을 클러스터로 분할하고 각 클러스터의 중심(Centroid)을 색인으로 삼아, 질의와 가까운 일부 클러스터만 탐색함으로써 비교 대상을 대폭 축소한다.

2. 구조 및 구축 과정​

   [① 학습(Training) — k-means 클러스터링]
   전체 벡터 → **nlist개의 클러스터**로 분할 → 각 클러스터 중심(Centroid) 산출

   [② 색인(Indexing)]
   ┌──── Centroid 목록(색인) ────┬──── 역색인 리스트(Inverted List) ────┐
   │  C1  ●                      │ → [v3, v17, v42, v88, ...]           │
   │  C2  ●                      │ → [v1, v25, v61, ...]                │
   │  C3  ●                      │ → [v7, v33, v54, v90, ...]           │
   │  ...                        │                                       │
   └─────────────────────────────┴───────────────────────────────────────┘
   ※ 각 벡터는 **가장 가까운 Centroid의 리스트에 소속**(보로노이 셀 분할)

3. 탐색(Search) 과정​

   [질의 벡터 q]
        │
   ① **q와 모든 Centroid(nlist개) 간 거리 계산**
        │   (nlist는 통상 수천 개 → 부담 적음)
        ▼
   ② 가장 가까운 **nprobe개의 클러스터 선택**
        │   예) nlist=1024, nprobe=8 → 전체의 약 0.8%만 탐색
        ▼
   ③ 선택된 클러스터의 **역색인 리스트 내 벡터들과만 정밀 거리 계산**
        │
        ▼
   ④ 상위 k개 반환

   [경계 문제] q가 클러스터 경계에 위치하면 **인접 클러스터의 실제 최근접 이웃을 놓침**
              → **nprobe를 늘려 완화**(정확도 ↑, 속도 ↓)
   [보로노이 분할 시각화]
      ┌──────┬──────┬──────┐
      │  C1  │  C2  │  C3  │     ● q(질의)가 C2에 속하지만
      │   ●  │  ●●q │  ●   │       실제 최근접은 C3에 있을 수 있음
      ├──────┼──────┼──────┤       ⇒ nprobe=2 이상으로 인접 셀 포함
      │  C4  │  C5  │  C6  │
      └──────┴──────┴──────┘

4. 주요 파라미터 및 변형​

파라미터의미영향
nlist클러스터 개수↑ 클러스터당 벡터 수 감소 → 탐색 빠름, 단 Centroid 비교 비용 ↑ (권장 ≈ √N)
nprobe탐색할 클러스터 수↑ 정확도(Recall) ↑, 속도 ↓ — 런타임 조절 가능
변형내용
IVF-Flat원본 벡터 그대로 저장 — 정확도 높으나 메모리 큼
IVF-PQ(Product Quantization)벡터를 부분공간으로 나눠 양자화 압축 → 메모리 수십 배 절감, 대규모에 필수
IVF-SQ스칼라 양자화(float32 → int8)

5. 특징​

구분내용
장점메모리 효율 우수(특히 PQ 결합 시), 구축 속도 빠름, 대규모 데이터셋에 적합, 디스크 기반 운영 가능
단점사전 학습(k-means) 필요 — 데이터 분포 변화 시 재학습, 클러스터 경계 문제로 Recall 손실, 동일 정확도 기준 HNSW보다 느림

Ⅳ. HNSW와 IVF 비교​

비교 기준HNSWIVF
접근 방식그래프 탐색(이웃 따라 이동)공간 분할(클러스터 선택 후 탐색)
자료구조계층적 근접 그래프Centroid + 역색인 리스트
탐색 원리상위 계층에서 대략 이동 → 하위에서 정밀 탐색가까운 클러스터 선별 → 내부 전수 비교
시간복잡도O(log N)O(nlist + N×nprobe/nlist)
사전 학습불필요필요(k-means)
검색 속도매우 빠름(동일 Recall 기준 우위)보통
정확도(Recall)높음중간(경계 문제, nprobe로 보완)
메모리 사용매우 큼(그래프 연결 + 원본 벡터)작음(PQ 결합 시 대폭 절감)
구축 시간김짧음
데이터 추가점진적 삽입 용이추가 가능하나 분포 변화 시 재학습 필요
삭제비효율(소프트 삭제·재구축)상대적으로 용이
조절 파라미터M, efConstruction, efSearchnlist, nprobe
적합 규모수백만~수천만(메모리 허용 범위)수억 이상 대규모
적합 상황낮은 지연·높은 정확도 요구(실시간 RAG·추천)대용량·메모리 제약, 비용 우선
대표 활용Elasticsearch, Qdrant, Weaviate, pgvectorFAISS, Milvus 대규모 컬렉션

하이브리드 접근​

   [IVF-PQ + HNSW 결합 — 대규모 실무 구성]
   ① **Centroid 탐색에 HNSW 적용** → nlist가 매우 클 때 Centroid 비교 비용 절감
   ② 선택된 클러스터에서 **PQ 압축 벡터로 1차 후보 추출**(빠르고 메모리 효율적)
   ③ **재순위화(Re-ranking)** : 후보에 대해서만 원본 벡터로 정밀 거리 재계산
   ⇒ 속도·메모리·정확도를 동시에 확보하는 실무 표준 구성

Ⅴ. 결론​

HNSW와 IVF는 "모든 벡터를 비교하지 않는다"는 동일한 목표에 대한 서로 다른 전략이다. HNSW는 그래프를 따라 지능적으로 이동하여 최고의 속도-정확도를 제공하지만 메모리 비용이 크고, IVF는 공간을 나누어 일부만 탐색하여 메모리 효율과 확장성이 뛰어나지만 경계 문제와 사전 학습 부담이 있다.

따라서 실무 선택 기준은 ① 데이터 규모가 수천만 이하이고 지연시간이 중요하면 HNSW, ② 수억 규모이거나 메모리·비용 제약이 크면 IVF-PQ, ③ 대규모이면서 정확도도 필요하면 IVF-PQ로 후보를 추리고 원본 벡터로 재순위화하는 하이브리드를 적용하는 것이다.

아울러 어떤 인덱스를 쓰든 Recall과 지연시간(P99)을 실제 데이터로 측정하여 efSearch·nprobe를 튜닝해야 하며, 궁극적으로 검색 품질은 인덱스보다 임베딩 모델의 품질과 청킹 전략에 더 크게 좌우된다는 점을 함께 고려해야 한다.
