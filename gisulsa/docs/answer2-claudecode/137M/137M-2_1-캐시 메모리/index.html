캐시 메모리(Cache Memory)의 쓰기 정책과 일관성

Ⅰ. 개요​

1. 캐시 메모리의 개념​

캐시 메모리는 CPU와 주기억장치 간 속도 격차(Memory Wall) 를 완화하기 위해, 자주 사용되는 데이터를 CPU 가까이에 보관하는 고속 소용량 기억장치이다. 참조 지역성(시간·공간 지역성) 에 기반해 동작하며, 계층적으로 L1–L2–L3로 구성된다.

2. 성능 지표​

평균 접근시간 = 적중률 × 캐시 접근시간 + (1−적중률) × 주기억 접근시간

   [메모리 계층]
   레지스터 ─ **L1(코어 전용)** ─ **L2** ─ **L3(코어 공유)** ─ 주기억장치 ─ 보조기억장치
   ◄─ 빠름·소용량·고가                                      대용량·저가 ─►

Ⅱ. 가. 캐시 쓰기 정책(Write Policy)​

CPU가 데이터를 쓸 때 캐시와 주기억장치의 값을 어떻게 동기화할 것인가에 대한 정책이다.

1. 쓰기 적중(Write Hit) 시 정책​

   [Write-Through]                     [Write-Back]
   CPU ──► 캐시 ──► 주기억(즉시 반영)   CPU ──► 캐시(**Dirty Bit=1**)
        (항상 동시에 갱신)                        │ 교체될 때만
                                                 └──► 주기억(지연 반영)
비교 기준Write-Through(즉시 쓰기)Write-Back(나중 쓰기)
동작캐시와 주기억을 항상 동시 갱신캐시만 갱신, 블록 교체 시점에 주기억 반영
관리 비트불필요Dirty Bit(변경 여부 표시) 필요
일관성항상 일치(구현 단순, 안전)일시적 불일치 발생
쓰기 성능낮음(매 쓰기마다 메모리 접근)높음(반복 쓰기를 캐시에서 흡수)
버스 트래픽많음적음
장애 시데이터 손실 없음전원 장애 시 Dirty 데이터 손실 위험
보완 기법쓰기 버퍼(Write Buffer) 로 지연 은닉주기적 플러시, NVRAM
적합 환경다중 프로세서, 신뢰성 우선, I/O 공유단일 프로세서·쓰기 집중 워크로드(대부분의 현대 CPU)

2. 쓰기 실패(Write Miss) 시 정책​

정책내용통상 조합
Write-Allocate(Fetch-on-Write)해당 블록을 캐시로 적재한 후 쓰기 수행 → 이후 재접근 시 적중 기대Write-Back과 결합
No-Write-Allocate(Write-Around)캐시를 거치지 않고 주기억에 직접 쓰기Write-Through와 결합

3. 관련 정책 — 교체 알고리즘​

  • LRU(가장 오래 미사용, 지역성 반영 우수), FIFO, LFU, Random(구현 단순, 하드웨어에서 실용적)

Ⅲ. 나. 캐시 일관성(Cache Coherence) 문제의 원인과 해결 방법​

1. 문제의 개념 및 원인​

캐시 일관성 문제란 다중 프로세서(멀티코어) 환경에서 각 코어가 동일한 주소의 데이터를 자신의 전용 캐시(L1/L2)에 복사본으로 보유할 때, 한 코어의 갱신이 다른 코어에 반영되지 않아 서로 다른 값을 보게 되는 현상이다.

   [문제 발생 시나리오]
   초기 : 주기억 X = 10
   ┌────────────┐   ┌────────────┐
   │  Core 1    │   │  Core 2    │
   │ 캐시 X = 10│   │ 캐시 X = 10│   ← 두 코어가 X를 각자 캐싱
   └─────┬──────┘   └─────┬──────┘
     X = 20 으로 갱신          │
   ┌─────▼──────┐   ┌─────▼──────┐
   │ 캐시 X =**20**│   │ 캐시 X =**10**│  ← **불일치(Incoherence)!**
   └────────────┘   └────────────┘   Core 2는 낡은 값(Stale Data) 사용
원인내용
데이터 복사본의 다중 존재각 코어의 전용 캐시에 동일 데이터가 중복 보관
Write-Back 정책갱신이 주기억에 즉시 반영되지 않아 불일치 구간 발생
프로세스 이주(Migration)프로세스가 다른 코어로 이동하며 이전 캐시의 값과 충돌
I/O·DMA 활동DMA가 캐시를 우회해 주기억을 직접 갱신
False Sharing서로 다른 변수가 동일 캐시 라인에 있어 불필요한 무효화 유발(성능 저하)

2. 일관성 유지 요건​

요건내용
쓰기 전파(Write Propagation)한 캐시의 변경이 다른 캐시에 전달되어야 함
쓰기 직렬화(Write Serialization)동일 주소에 대한 쓰기 순서를 모든 코어가 동일하게 관찰

3. 해결 방법​

(1) 하드웨어 기법 — 스누핑(Snooping) 프로토콜​

  • 원리: 모든 캐시 컨트롤러가 공유 버스를 감시(Snoop) 하며, 다른 코어의 쓰기 트랜잭션을 감지하면 자신의 복사본을 처리한다. 버스 기반 소규모 시스템에 적합하다.
방식내용
Write-Invalidate(무효화)쓰기 발생 시 다른 캐시의 복사본을 무효화 → 이후 접근 시 최신값 재적재. 트래픽 적음, 사실상 표준
Write-Update(갱신)쓰기 값을 모든 캐시에 브로드캐스트하여 갱신 → 읽기 지연 적으나 버스 트래픽 과다

(2) MESI 프로토콜 (대표적 무효화 기반 프로토콜)​

   각 캐시 라인의 4가지 상태
   ┌─────────────┬──────────────────────────────────────────┐
   │ **M**odified │ 수정됨 — 나만 보유, 주기억과 불일치(Dirty)│
   │ **E**xclusive│ 배타적 — 나만 보유, 주기억과 일치(Clean)  │
   │ **S**hared   │ 공유됨 — 여러 캐시가 보유, 주기억과 일치  │
   │ **I**nvalid  │ 무효 — 사용 불가(다른 코어가 갱신함)      │
   └─────────────┴──────────────────────────────────────────┘
   [전이 예] S 상태에서 쓰기 → 다른 캐시에 무효화 신호(BusRdX) → **M 상태**로 전이
            M 상태 라인을 타 코어가 읽기 요청 → 주기억에 반영 후 **S 상태**로 전이
   ※ 확장: **MOESI**(Owned 추가 — 캐시 간 직접 전달로 메모리 접근 감소), MESIF(Intel)

(3) 디렉터리(Directory) 기반 프로토콜​

  • 원리: 각 메모리 블록마다 어느 캐시가 복사본을 보유하는지 디렉터리에 기록하고, 갱신 시 해당 캐시에만 선택적으로 무효화 메시지 전송.
  • 특징: 브로드캐스트가 없어 확장성이 우수 → 코어 수가 많은 대규모 시스템(NUMA·매니코어)에 사용. 단, 디렉터리 저장공간과 접근 지연이 추가된다.

(4) 소프트웨어·기타 기법​

기법내용
캐시 불가 영역 지정공유 변수·I/O 영역을 Non-cacheable로 설정
컴파일러 지원공유 데이터 식별 후 캐싱 배제, volatile 키워드
메모리 배리어·동기화fence 명령, 뮤텍스·원자적 연산(CAS)으로 순서 보장
False Sharing 회피캐시 라인 정렬(Padding), 코어별 지역 변수 사용
캐시 플러시문맥 교환·DMA 전후 캐시 무효화·플러시

4. 스누핑 vs 디렉터리 비교​

비교 기준스누핑디렉터리
통신 방식브로드캐스트(버스 감시)점대점(Point-to-Point) 메시지
확장성낮음(버스 대역폭 병목)높음
지연낮음(소규모에서 빠름)상대적으로 큼(디렉터리 조회)
저장 오버헤드없음디렉터리 저장공간 필요
적용소규모 멀티코어(SMP)대규모 매니코어·NUMA

Ⅳ. 결론​

캐시 쓰기 정책은 성능(Write-Back)과 일관성·안전성(Write-Through)의 Trade-off 문제이며, 현대 프로세서는 성능을 위해 Write-Back + Write-Allocate를 기본 채택하고 그 결과로 발생하는 불일치를 MESI 계열 일관성 프로토콜로 해결한다.

멀티코어가 보편화된 현재, 일관성 유지는 하드웨어가 자동 처리하지만 False Sharing이나 과도한 캐시 라인 경합은 여전히 소프트웨어의 성능을 크게 좌우한다. 따라서 개발자는 ① 공유 변수 최소화와 코어별 지역 데이터 활용, ② 캐시 라인 정렬을 통한 False Sharing 회피, ③ 메모리 배리어와 원자적 연산의 정확한 사용을 통해 하드웨어 일관성 메커니즘의 비용을 줄여야 한다. 나아가 코어 수 증가에 따라 스누핑의 확장 한계가 명확해지면서 디렉터리 기반·NUMA 인지 설계의 중요성이 커지고 있다.
