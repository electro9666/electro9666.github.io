전자상거래 정보시스템의 SLA(Service Level Agreement)

Ⅰ. 개요​

1. SLA의 개념​

SLA는 서비스 제공자와 이용자(고객) 간에 제공할 서비스의 수준을 정량적 지표로 합의하고, 측정·보고·보상 방법까지 문서화한 계약이다. 개발이 완료된 시스템을 운영으로 전환할 때 운영 품질의 객관적 기준선이 된다.

2. 전자상거래 시스템의 특수성​

(A)기업은 전자상거래 시스템을 운영하므로, 24×365 무중단, 이벤트·명절 트래픽 급증, 결제·개인정보 보안, 응답속도가 매출에 직결되는 특성이 있다. 따라서 SLA 지표도 이러한 비즈니스 특성을 반영해야 한다.

Ⅱ. 가. SLA 구성요소와 절차​

1. SLA 구성요소​

   ┌──────────── SLA 문서 체계 ────────────┐
   │ ① 서비스 개요·범위(대상 시스템·시간대) │
   │ ② **서비스 수준 지표(SLI)와 목표(SLO)** │
   │ ③ 측정 방법·주기·도구                 │
   │ ④ 역할과 책임(R&R), 제외 조건          │
   │ ⑤ 보고 체계 및 검토 주기               │
   │ ⑥ **보상·제재(Penalty/Incentive)**     │
   │ ⑦ 변경·분쟁 해결 절차, 계약 기간       │
   └───────────────────────────────────────┘
   [연관 개념] **SLA**(고객과의 계약) ⊃ **OLA**(내부 조직 간 합의)
                                      ⊃ **UC**(외부 공급자와의 계약)
구성요소상세 내용
서비스 범위·대상대상 시스템·업무, 서비스 시간대(24×365 / 업무시간), 지원 채널
서비스 수준 항목가용성·성능·장애대응·보안 등 측정 가능한 지표(SLI)
목표 수준(SLO)지표별 목표값(예: 가용률 99.9%), 최소 허용 수준(Minimum)
측정 방법측정 도구(APM·모니터링), 산식, 측정 주기, 데이터 출처
역할·책임(R&R)고객·제공자 각각의 의무, 협조 사항
제외 조건계획된 정기점검, 천재지변, 고객 귀책, 제3자 회선 장애
보고 체계월간 서비스 보고서, 정기 검토회의(Service Review)
보상·제재미달 시 감액(Service Credit), 초과 달성 시 인센티브
변경 관리지표·목표 조정 절차, 재협상 조건

2. SLA 수립·운영 절차​

 ① 서비스 정의·분석 ─► ② 지표(SLI) 선정 ─► ③ **목표수준(SLO) 설정**
 (업무 중요도 분석)      (측정가능성 검토)     (현행 실적·벤치마킹 기반)
        │                                              │
        ▼                                              ▼
 ⑦ 개선·재협상 ◄─ ⑥ 평가·보고 ◄─ ⑤ 측정·모니터링 ◄─ ④ SLA 체결·합의
        └────────────── 지속적 개선(PDCA) ──────────────┘
단계주요 활동산출물
① 서비스 정의·분석대상 서비스 식별, 업무 중요도(BIA), 이해관계자 요구 파악서비스 카탈로그
② 지표 선정측정 가능하고 고객 체감과 연결된 지표 선정(SMART 원칙)SLI 목록
③ 목표수준 설정현행 실적·업계 수준 분석 후 달성 가능한 목표 설정, 비용 균형 검토SLO 정의서
④ 체결·합의보상·제외조건 협의, 계약 체결, 관계자 공유·교육SLA 계약서, OLA
⑤ 측정·모니터링모니터링 도구 구축, 실시간 수집, 임계 경보측정 데이터, 대시보드
⑥ 평가·보고월간 실적 집계, 미달 원인 분석, 정기 검토회의서비스 수준 보고서
⑦ 개선·재협상개선과제 도출·이행, 환경 변화 반영해 지표·목표 조정개선계획서, 개정 SLA
  • 성공 요건: 지표는 적정 개수(10~20개 내외) 로 제한, 고객이 체감하는 항목 위주, 측정 데이터의 객관성·자동 수집 확보

Ⅲ. 나. (A)기업 특성을 고려한 영역별 SLA 평가지표와 측정방법​

1. 하드웨어(서버·스토리지) 영역​

평가지표산식·정의목표(예시)측정방법
서버 가용률(총시간 − 장애시간)/총시간 × 10099.9% 이상(월 43분 이내)모니터링 솔루션(Zabbix·CloudWatch) 자동 수집
CPU 사용률피크 시간대 평균 사용률80% 미만 유지리소스 모니터링 5분 단위 수집, 월 평균·피크 산출
스토리지 사용률사용 용량 / 총 용량80% 미만일 1회 수집, 임계 초과 시 증설
디스크 I/O 응답시간평균 Latency10ms 이하스토리지 성능 모니터링
장비 장애 복구시간(MTTR)장애 접수~복구 완료 평균2시간 이내ITSM 티켓 시각 기록
부품 교체 소요시간장애 부품 교체 완료4시간 이내(계약 시 유지보수 SLA)유지보수 업체 접수·완료 시각

(A)기업 반영: 전자상거래는 이벤트·명절 트래픽 급증이 발생하므로, 피크 대비 자원 여유율(Headroom) 과 오토스케일 확장 소요시간(예: 5분 이내) 을 별도 지표로 포함한다.

2. 소프트웨어(애플리케이션·DBMS) 영역​

평가지표산식·정의목표(예시)측정방법
서비스 가용률정상 응답 시간 / 총 서비스 시간99.9% 이상외부 합성 모니터링(Synthetic) 1분 주기 헬스체크
화면 응답시간주요 화면 평균 응답시간상품조회 2초 / 결제 3초 이내APM(제니퍼·Pinpoint)으로 트랜잭션 구간 측정
트랜잭션 처리량(TPS)초당 처리 건수피크 시 1,000 TPS 보장APM·WAS 로그 집계
결제 성공률결제 성공 / 결제 시도 × 10099.5% 이상결제 로그 집계(PG 연동 결과 포함)
오류율(Error Rate)HTTP 5xx 건수 / 총 요청0.1% 미만웹서버·APM 로그
배치 작업 완료율정시 완료 배치 / 전체 배치99% 이상(정산·정합성 배치)스케줄러 로그, 완료 시각 확인
DB 쿼리 응답시간슬로우 쿼리(3초 초과) 건수일 10건 이하DB 모니터링·슬로우 쿼리 로그
장애 처리 시간등급별 대응·복구 시간1등급 30분 내 대응, 2시간 내 복구ITSM 티켓(접수–착수–복구 시각)
변경·배포 품질배포 후 롤백 발생률5% 미만CI/CD 파이프라인 이력

(A)기업 반영: 매출과 직결되는 결제·주문 트랜잭션은 일반 조회보다 엄격한 목표(가용률 99.95%, 성공률 99.5%) 를 적용하고, 장바구니·검색 등은 완화 적용하는 서비스 등급별 차등 SLA를 설계한다.

3. 네트워크 영역​

평가지표산식·정의목표(예시)측정방법
회선 가용률(총시간 − 회선 장애시간)/총시간99.95% 이상회선사업자 통계 + 자체 SNMP 모니터링
네트워크 지연(Latency)구간별 RTT 평균내부 5ms / 외부 50ms 이하Ping·SNMP·NMS 수집(5분 주기)
패킷 손실률손실 패킷 / 전송 패킷0.1% 미만NMS 지속 측정
대역폭 사용률피크 사용량 / 계약 대역폭70% 미만트래픽 모니터링, 초과 시 증설
회선 장애 복구시간장애 발생~복구2시간 이내(이중화 시 절체 30초)회선사업자 장애 리포트
CDN 캐시 적중률캐시 응답 / 전체 요청90% 이상CDN 콘솔 통계
DDoS 방어 대응시간공격 탐지~차단 적용5분 이내보안관제 로그

(A)기업 반영: 전자상거래는 외부 이용자 접속이 핵심이므로 내부망 지표보다 인터넷 회선 이중화·CDN 적중률·DDoS 대응을 중점 지표로 삼는다.

4. 종합 측정·보고 체계​

   [수집]                    [집계·분석]              [보고·조치]
   NMS(네트워크)  ──┐
   자원 모니터링    ─┼──► **통합 대시보드** ──► 월간 SLA 보고서 ──► 정기 검토회의
   APM(애플리케이션)─┤     (자동 집계·시각화)      (미달 항목 원인분석)  (개선과제·보상)
   ITSM(장애·요청)  ─┘
   ※ 측정 데이터는 **자동 수집을 원칙**으로 하여 객관성·신뢰성 확보(수기 집계 최소화)
등급SLA 달성률조치
우수목표 100% 이상인센티브 지급 검토
정상목표 달성유지
미흡목표 미달원인 분석·개선계획 제출
불량최소 수준 미달서비스 크레딧(감액) 적용, 재발방지 대책

Ⅳ. 결론​

SLA의 본질은 처벌 수단이 아니라 서비스 품질에 대한 공통 언어를 만들고 지속적으로 개선하는 관리 도구이다. 따라서 지표는 측정 가능하고 고객이 체감하는 항목 중심으로 최소화하고, 데이터는 자동 수집하여 객관성을 확보해야 한다.

(A)기업과 같은 전자상거래 시스템에서는 특히 ① 결제·주문 등 매출 직결 서비스에 엄격한 목표를 차등 적용하고, ② 이벤트성 트래픽 급증에 대비한 확장성 지표(오토스케일 시간·자원 여유율) 를 포함하며, ③ CDN·DDoS 등 외부 접속 품질 지표를 중점 관리해야 한다. 아울러 운영 전환 초기에는 실측 데이터가 부족하므로 일정 기간 시범 측정 후 목표치를 조정하는 유예 기간을 두고, 정기 검토를 통해 SLA를 지속적으로 현행화하는 것이 바람직하다.
