공공부문 초거대 AI 도입·활용 가이드라인 2.0

Ⅰ. 개요​

1. 가이드라인의 배경 및 목적​

「공공부문 초거대 AI 도입·활용 가이드라인」(행정안전부·디지털플랫폼정부위원회)은 공공기관이 초거대 AI를 안전하고 효과적으로 도입·활용하도록 개념·기술요소·도입절차·보안 고려사항을 제시한 지침이다. 2.0 버전은 생성형 AI 확산과 RAG·에이전트 등 기술 진화를 반영하고, 실제 도입 사례와 구축 유형별 선택 기준을 보강하였다.

2. 필요성​

  • 공공 업무의 특수성 — 정확성·설명책임·개인정보 보호가 민간보다 엄격
  • 환각·편향·데이터 유출 위험에 대한 일관된 판단 기준 부재
  • 기관별 중복 투자 방지 및 공통 인프라 활용 유도

Ⅱ. 가. 초거대 AI의 개념과 구성요소​

1. 개념​

초거대 AI(Hyperscale AI) 는 대규모 파라미터와 방대한 학습데이터, 대규모 컴퓨팅 자원을 기반으로 사전학습(Pre-training)되어, 별도의 개별 학습 없이도 다양한 과업을 범용적으로 수행할 수 있는 AI를 말한다. 파운데이션 모델(Foundation Model) 의 성격을 가지며, 자연어·이미지·음성을 다루는 멀티모달로 확장되고 있다.

특징내용
범용성하나의 모델로 요약·번역·작성·질의응답 등 다중 과업 수행
창발성(Emergent Ability)규모 확대에 따라 학습하지 않은 능력이 발현
전이학습·적응성파인튜닝·프롬프트만으로 특정 도메인 적용
생성 능력새로운 텍스트·이미지·코드를 생성
한계환각(Hallucination), 최신성 부족, 높은 자원 비용, 설명 곤란

2. 구성요소​

   ┌──────────── ④ 응용·서비스 계층 ────────────┐
   │  민원 응대 / 문서 작성 / 정책 분석 / 코딩    │
   ├──────────── ③ 모델·활용 계층 ──────────────┤
   │  파운데이션 모델 + **프롬프트 / RAG /        │
   │  파인튜닝 / 에이전트**                       │
   ├──────────── ② 데이터 계층 ─────────────────┤
   │  학습데이터, 기관 보유 문서·DB, 벡터DB       │
   ├──────────── ① 인프라 계층 ─────────────────┤
   │  GPU 컴퓨팅, 스토리지, 네트워크(민간·공공 클라우드)│
   └──────────── ⑤ 거버넌스·보안(전 계층 관통) ──┘
        AI 윤리·품질관리·개인정보보호·보안대책
구성요소내용
인프라GPU 등 AI 컴퓨팅 자원, 스토리지, 네트워크 — 자체 구축 / 공공 클라우드 / 민간 SaaS
데이터사전학습 데이터, 기관 고유 데이터(법령·지침·민원 사례), 벡터 임베딩 저장소
모델파운데이션 모델(상용 API·오픈소스·자체 구축), 경량화 모델(sLLM)
응용·서비스업무 적용 서비스, 사용자 인터페이스, 기존 행정시스템 연계
거버넌스·보안AI 활용 정책, 품질·윤리 검증, 개인정보 보호, 접근통제·감사

Ⅲ. 나. 초거대 AI의 기술요소​

구분기술요소내용
모델 기반트랜스포머(Transformer)셀프 어텐션 기반 아키텍처, LLM의 근간
MoE(Mixture of Experts)일부 전문가만 활성화해 파라미터 확대 대비 연산 절감
멀티모달텍스트·이미지·음성·영상 통합 처리
학습·정렬사전학습(Pre-training)대규모 말뭉치로 범용 언어능력 학습
파인튜닝 / PEFT(LoRA)도메인 특화 재학습, 적은 자원으로 효율적 조정
RLHF / 정렬(Alignment)사람 피드백 기반 강화학습으로 유해·부정확 응답 억제
활용 기술프롬프트 엔지니어링지시·예시(Few-shot)·CoT(사고 사슬) 로 성능 향상
RAG(검색 증강 생성)기관 문서를 검색해 근거와 함께 답변 → 환각 감소·최신성 확보·출처 제시(공공에서 가장 중요)
벡터 데이터베이스·임베딩의미 기반 유사도 검색(HNSW·IVF 인덱스)
AI 에이전트·도구 사용외부 시스템 호출을 통한 업무 자동화(MCP·Function Calling)
최적화경량화(양자화·증류·프루닝)sLLM으로 온프레미스 운영 가능, 비용·지연 절감
추론 최적화배칭·캐싱·KV 캐시, 서빙 프레임워크
신뢰성가드레일·필터링유해·개인정보 출력 차단, 프롬프트 인젝션 방어
XAI·출처 표시근거 문서 제시, 생성물 표시(워터마킹)
평가(Evaluation)정확성·유해성·편향 벤치마크, LLM-as-a-Judge

공공 적용의 핵심: 정확성과 책임성이 요구되므로 파인튜닝보다 RAG를 우선 검토하는 것이 일반적이다. 근거 문서를 함께 제시할 수 있어 설명책임(Accountability) 확보에 유리하기 때문이다.

Ⅳ. 다. 초거대 AI의 도입 절차​

 ① 도입 기획·과제 발굴 ─► ② 도입 유형·모델 선정 ─► ③ 데이터 준비
 (업무 분석·타당성)         (자체/민간/SaaS)        (수집·정제·가명처리)
        │                                                  │
        ▼                                                  ▼
 ⑦ 운영·고도화 ◄─ ⑥ 서비스 구축·검증 ◄─ ⑤ 인프라 구축 ◄─ ④ PoC·실증
 (모니터링·재학습)   (가드레일·연계 검증)   (컴퓨팅·보안)   (효과 검증)
        └───────────── 거버넌스·보안·성과평가 (전 단계 병행) ─────────────┘
단계주요 활동산출물·점검사항
① 도입 기획·과제 발굴업무 분석을 통한 적용 과제 도출(반복·문서 중심 업무 우선), 기대효과·타당성 검토, 예산·조직 확보도입계획서, 과제 우선순위(효과×실현가능성)
② 도입 유형·모델 선정자체 구축 / 민간 클라우드(PaaS) / SaaS 활용 중 선택, 상용 API vs 오픈소스 모델 비교, 보안 등급·데이터 민감도 고려유형 선정 근거, 모델 비교표, CSAP 인증 여부 확인
③ 데이터 준비기관 데이터 수집·정제, 문서 구조화, 개인정보 가명·비식별 처리, 라벨링·품질 검증, 벡터화데이터셋, 개인정보 영향평가(PIA)
④ PoC·실증소규모 시범 적용, 정확도·유용성 평가, 사용자 피드백, 비용 산정PoC 결과보고서, 성능 지표
⑤ 인프라 구축컴퓨팅 자원 확보, 망 분리·보안 구성, 벡터DB·연계 시스템 구축인프라 구성도, 보안성 검토 결과
⑥ 서비스 구축·검증RAG·프롬프트 설계, 가드레일 적용, 기존 행정시스템 연계, 사용자 교육, 보안·품질 검증서비스, 운영 매뉴얼, AI 신뢰성 검증 결과
⑦ 운영·고도화성과 모니터링, 사용자 피드백 반영, 데이터·모델 갱신, 오답 사례 관리, 정기 위험 재평가운영 보고서, 개선계획

도입 유형별 비교​

유형장점단점적합 상황
자체 구축(온프레미스)데이터 외부 유출 없음, 완전 통제고비용, 전문 인력 필요기밀·민감 데이터 처리
민간 클라우드(PaaS)신속 구축, 확장성비용 지속, 일부 종속일반 업무, CSAP 인증 필수
SaaS 활용최저 비용·즉시 사용데이터 통제 제한비민감 업무, 시범 적용

공공 도입 시 핵심 고려사항​

구분내용
보안업무자료의 외부 전송 금지 원칙, 망 분리(N2SF) 정합성, CSAP 인증 클라우드 이용
개인정보개인정보 입력 금지 원칙, 가명처리, 개인정보 영향평가
정확성·책임RAG로 근거 제시, 최종 판단은 담당 공무원(Human-in-the-Loop), 오답 대응 절차
윤리·투명성AI 사용 사실 고지, 생성물 표시, 편향 점검
지속가능성종속(Lock-in) 방지, 표준 인터페이스, 모델 교체 가능성 확보

Ⅴ. 결론​

공공부문의 초거대 AI 도입은 기술 도입이 아니라 업무 혁신 과제로 접근해야 하며, 성공의 관건은 모델 성능보다 기관 고유 데이터의 품질과 구조화 수준에 있다.

따라서 실무적으로는 ① 문서 중심·반복 업무부터 과제를 선별하여 PoC로 효과를 실증하고, ② 환각과 설명책임 문제를 고려해 파인튜닝보다 RAG 기반 구조를 우선 채택하며, ③ 데이터 민감도에 따라 자체 구축–CSAP 클라우드–SaaS를 차등 선택해야 한다. 아울러 ④ 최종 판단 권한은 공무원이 유지(Human Oversight) 하고, ⑤ AI 기본법·개인정보보호법·N2SF 등 관련 제도와의 정합성을 사전에 확보하는 것이 공공 특유의 필수 요건이다.
