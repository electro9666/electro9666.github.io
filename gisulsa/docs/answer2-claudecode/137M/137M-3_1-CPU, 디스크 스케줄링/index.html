운영체제 스케줄링 기법 — CPU 스케줄링과 디스크 스케줄링

Ⅰ. 개요​

1. 스케줄링의 필요성​

컴퓨터 시스템의 자원(CPU·디스크)은 유한한데 이를 요구하는 프로세스·요청은 다수이므로, 어떤 요청을 어떤 순서로 처리할 것인가를 결정하는 스케줄링이 필요하다. 목표는 처리량(Throughput) 극대화, 응답·대기시간 최소화, 공정성 확보이다.

Ⅱ. 가. CPU 스케줄링과 디스크 스케줄링의 개념​

1. CPU 스케줄링(CPU Scheduling)​

  • 개념: 준비 큐(Ready Queue)에 있는 여러 프로세스 중 다음에 CPU를 할당받을 프로세스를 선택하는 활동. 단기 스케줄러(Short-term Scheduler)가 담당한다.
   [프로세스 상태 전이]
   생성 ──► **준비(Ready)** ──**디스패치**──► 실행(Running) ──► 종료
              ▲    ▲                          │    │
              │    └──── 시간 할당량 만료 ─────┘    │ I/O 요청
              └──── I/O 완료 ──── **대기(Waiting)** ◄┘
   ※ 선점(Preemptive) : 실행 중 강제 회수 가능 / 비선점(Non-preemptive) : 자발적 반납까지 점유
평가 기준내용
CPU 이용률CPU가 일하는 시간 비율 (↑)
처리량(Throughput)단위시간당 완료 프로세스 수 (↑)
반환시간(Turnaround)제출~완료 총 시간 (↓)
대기시간(Waiting)준비 큐에서 대기한 시간 (↓)
응답시간(Response)요청~첫 응답 시간 (↓, 대화형에서 중요)
  • 주요 기법: FCFS, SJF, SRT, 우선순위, 라운드로빈(RR), 다단계 큐·다단계 피드백 큐(MLFQ)

2. 디스크 스케줄링(Disk Scheduling)​

  • 개념: 디스크 입출력 요청 큐에서 탐색시간(Seek Time)과 회전지연(Rotational Latency)을 최소화하도록 서비스 순서를 결정하는 활동.
   [디스크 접근 시간]
   **접근시간 = 탐색시간(Seek) + 회전지연(Rotational Latency) + 전송시간(Transfer)**
                 ▲ 가장 큼(헤드 이동)   ▲ 두 번째(섹터 회전)   작음
   ⇒ 디스크 스케줄링의 1차 목표 = **탐색시간 최소화**

   [디스크 구조]
   ┌─────────────┐  트랙(Track) : 동심원
   │ ◎ 스핀들     │  실린더(Cylinder) : 여러 플래터의 동일 트랙 집합
   │  ─ 헤드 ──►  │  섹터(Sector) : 트랙의 분할 단위(최소 전송 단위)
   └─────────────┘
  • 주요 기법: FCFS, SSTF, SCAN(엘리베이터), C-SCAN, LOOK/C-LOOK, SLTF, N-Step SCAN

3. 두 스케줄링의 비교​

비교 기준CPU 스케줄링디스크 스케줄링
대상 자원CPU(프로세서)디스크 입출력 장치
스케줄 단위프로세스·스레드I/O 요청(트랙·섹터 번호)
최적화 목표대기·반환시간 최소화, 공정성탐색시간·회전지연 최소화
핵심 변수CPU 버스트 시간헤드 위치와 요청 트랙 간 거리
선점 가능성선점/비선점 모두 존재대부분 비선점(요청 단위 처리)
기아 위험SJF·우선순위에서 발생SSTF에서 발생(먼 트랙 요청)
대응 기법에이징(Aging), RRSCAN·C-SCAN(방향 순회)

Ⅲ. 나. SJF와 SRT​

1. SJF(Shortest Job First, 최단 작업 우선)​

  • 개념: 준비 큐의 프로세스 중 CPU 버스트 시간이 가장 짧은 프로세스를 먼저 실행하는 비선점 스케줄링. 일단 CPU를 할당하면 완료까지 반납하지 않는다.

2. SRT(Shortest Remaining Time, 최소 잔여시간 우선)​

  • 개념: SJF의 선점형 버전. 새 프로세스가 도착했을 때 그 프로세스의 버스트 시간이 현재 실행 중인 프로세스의 잔여 시간보다 짧으면 즉시 선점한다.

3. 동작 예시​

   [프로세스]  P1(도착0, 버스트7)  P2(도착2, 버스트4)  P3(도착4, 버스트1)  P4(도착5, 버스트4)

   [SJF - 비선점]
   0        7      8        12          16
   │   P1   │  P3  │   P2   │    P4     │   ← P1은 도착 시 유일 → 끝까지 실행
   평균 대기시간 = (0 + 6 + 3 + 7) / 4 = **4.0**

   [SRT - 선점]
   0   2      4  5      7        11       16
   │P1 │  P2  │P3│  P2  │   P4   │   P1   │  ← 잔여시간 짧은 작업이 계속 선점
   평균 대기시간 = (9 + 1 + 0 + 2) / 4 = **3.0**   ⇒ **SRT가 더 우수**

4. SJF와 SRT 비교​

비교 기준SJFSRT
선점 여부비선점(Non-preemptive)선점(Preemptive)
선택 기준전체 버스트 시간이 가장 짧은 것잔여 실행시간이 가장 짧은 것
판단 시점CPU가 비었을 때새 프로세스 도착 시마다 재평가
평균 대기시간비선점 중 최적(이론적 최소)SJF보다 더 짧음
문맥교환적음많음(오버헤드 증가)
기아(Starvation)긴 작업에 발생더 심각하게 발생
응답시간상대적으로 김짧은 작업에 유리
적용일괄 처리(Batch) 시스템시분할·대화형 시스템
공통 문제내용 및 해결
실행시간 예측 불가실제로는 버스트 시간을 알 수 없음 → 지수 평균(Exponential Averaging) 으로 예측: τₙ₊₁ = α·tₙ + (1−α)·τₙ
기아 현상긴 작업이 무한 대기 → 에이징(Aging) 으로 대기시간에 비례해 우선순위 상향

Ⅳ. 다. SSTF와 SLTF​

1. SSTF(Shortest Seek Time First, 최단 탐색시간 우선)​

  • 개념: 현재 헤드 위치에서 가장 가까운 트랙의 요청을 먼저 처리하여 탐색시간(헤드 이동거리)을 최소화하는 기법. 디스크 스케줄링의 SJF에 해당한다.
   [요청 큐] 98, 183, 37, 122, 14, 124, 65, 67   (현재 헤드 : 53)

   [FCFS]  53→98→183→37→122→14→124→65→67       총 이동 = **640 트랙**
   [SSTF]  53→**65**→67→37→14→98→122→124→183   총 이동 = **236 트랙**
            └ 가장 가까운 요청부터 순차 선택 ⇒ 이동거리 대폭 감소

   [문제] 헤드 근처에 요청이 계속 유입되면 **먼 트랙(183)은 무한 대기 = 기아**
   [해결] **SCAN**(한 방향 끝까지 진행 후 반대 방향), **C-SCAN**(한 방향만·끝에서 복귀)

2. SLTF(Shortest Latency Time First, 최소 지연시간 우선)​

  • 개념: 동일 트랙(실린더) 내의 요청들에 대해, 디스크 회전 방향 기준으로 헤드에 가장 먼저 도달할 섹터부터 처리하여 회전지연(Rotational Latency)을 최소화하는 기법. 섹터 큐잉(Sector Queuing) 이라고도 한다.
   [동일 트랙 내 섹터 요청] 8, 2, 6, 4  (헤드가 현재 섹터 1 지점, 회전 방향 →)

        ┌──────── 트랙(원형) ────────┐
        │  1 → **2** → 3 → **4** →   │  회전 순서대로 처리
        │  5 → **6** → 7 → **8** → 1 │
        └────────────────────────────┘
   처리 순서 : **2 → 4 → 6 → 8**  (회전 1바퀴로 모두 처리)
   ↔ 요청 순서(8→2→6→4)대로 처리하면 **여러 바퀴 회전 필요** = 지연 급증

3. SSTF와 SLTF 비교​

비교 기준SSTFSLTF
최적화 대상탐색시간(Seek Time) — 헤드의 반경 방향 이동회전지연(Rotational Latency) — 플래터 회전 대기
판단 기준현재 헤드 트랙과의 거리현재 회전 위치 기준 도달 순서(각도)
적용 단위트랙(실린더) 간 이동동일 트랙 내 섹터 순서
전제 조건여러 트랙에 요청 분산동일 트랙에 다수 요청 집중
기아 발생발생(먼 트랙 요청)발생하지 않음(1회전 내 모두 처리)
대표 대안SCAN, C-SCAN, LOOK(회전 최적화 전용)
적용 관계1차 적용(트랙 결정)2차 적용(트랙 내 섹터 순서 결정)

상호 관계: 두 기법은 경쟁 관계가 아니라 계층적 보완 관계이다. 먼저 SSTF·SCAN 계열로 어느 트랙을 갈지 정하고, 해당 트랙 내에서 SLTF로 어느 섹터부터 읽을지 정한다. 이를 결합한 것이 SPTF(Shortest Positioning Time First — 탐색+회전 총 시간 최소화) 로, 현대 디스크 컨트롤러가 내부적으로 사용한다.

Ⅴ. 최신 환경에서의 변화​

환경스케줄링 관점의 변화
SSD탐색시간·회전지연이 없음 → SSTF·SLTF의 의미 소멸. NOOP·none·mq-deadline 등 단순 스케줄러 사용, 병렬 큐(NVMe 다중 큐) 활용이 핵심
멀티코어CPU 스케줄링에서 부하 분산·캐시 친화성(Affinity) 중요, CFS 등 공정 스케줄러
클라우드·컨테이너리소스 격리(cgroup), QoS 클래스 기반 스케줄링
실시간 시스템RM(Rate Monotonic)·EDF 등 마감시간 보장 스케줄링

Ⅵ. 결론​

CPU 스케줄링과 디스크 스케줄링은 자원은 다르지만 "제한된 자원을 어떤 순서로 배분할 것인가"라는 동일한 문제를 다루며, 공통적으로 효율성과 공정성의 Trade-off에 직면한다. SJF·SRT와 SSTF는 각각 대기시간과 탐색시간을 최소화하는 최적 기법이지만, 모두 기아(Starvation)라는 대가를 치르므로 실무에서는 에이징·SCAN 계열로 보완한다.

또한 SJF·SRT는 미래 실행시간을 알 수 없다는 근본적 한계가 있어 예측 기법과 함께 사용되며, 최근 SSD 확산으로 디스크 스케줄링의 물리적 최적화는 의미가 축소되고, 대신 병렬 큐 활용과 지연 편차(Tail Latency) 관리로 관심이 이동하고 있다. 즉 스케줄링 설계의 본질은 알고리즘 자체가 아니라 해당 시스템의 자원 특성과 서비스 목표에 부합하는 정책을 선택하는 것이다.
