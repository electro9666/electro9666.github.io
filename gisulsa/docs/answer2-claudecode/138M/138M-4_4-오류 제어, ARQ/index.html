데이터 통신의 오류 제어(Error Control) 기술

Ⅰ. 개요​

1. 오류 제어의 필요성​

전송 매체의 잡음·감쇠·간섭으로 인해 데이터는 비트 오류(단일 비트 오류·버스트 오류) 를 겪는다. 신뢰성 있는 전송을 보장하려면 오류를 검출하고, 정정하거나 재전송하는 오류 제어가 필수적이다.

2. 오류 제어 방식 분류​

                    [오류 제어]
            ┌───────────┴────────────┐
     **오류 검출 + 재전송**        **오류 정정(전진 정정)**
        = **ARQ**(Backward EC)        = **FEC**(Forward EC)
     정지-대기 / Go-Back-N /       해밍코드 / 리드-솔로몬 /
     선택적 재전송(SR)              컨볼루션 / LDPC / 터보코드
        ▲ 역채널 필요, 지연 가변      ▲ 역채널 불필요, 대역 오버헤드

Ⅱ. 가. 오류 검출과 오류 정정의 개념​

1. 오류 검출(Error Detection)​

  • 개념: 전송된 데이터에 오류가 발생했는지 여부만 판별하는 기법. 송신 측이 원본으로부터 잉여 비트(Redundancy Bit) 를 생성해 함께 전송하고, 수신 측이 재계산하여 비교한다.
기법원리특징
패리티 비트1의 개수를 짝수/홀수로 맞추는 1비트 추가구현 단순, 짝수 개 오류 검출 불가
블록 합 검사(2차원 패리티)행·열 방향 패리티검출률 향상, 일부 정정 가능
체크섬(Checksum)데이터를 블록 단위로 합산 후 1의 보수 전송TCP/IP·UDP 사용, 연산 단순, 검출력 낮음
CRC(순환중복검사)데이터를 다항식으로 보고 생성 다항식으로 나눈 나머지(FCS) 를 부가버스트 오류 검출력 매우 우수, HW 구현 용이 → 이더넷·HDLC 표준

2. 오류 정정(Error Correction)​

  • 개념: 수신 측이 재전송 없이 오류의 위치를 찾아 스스로 복원하는 기법(FEC). 잉여 비트를 더 많이 부가하는 대신 지연을 제거한다.
기법원리특징
해밍코드패리티 비트를 특정 위치에 배치해 오류 비트 위치(신드롬) 산출단일 비트 오류 정정, 2비트 검출(SEC-DED) → ECC 메모리
리드-솔로몬(RS)심볼 단위 블록 부호버스트 오류에 강함 → CD/DVD, QR코드, 위성
컨볼루션 부호 + 비터비상태 기계 기반 연속 부호화이동통신·무선
터보코드 / LDPC반복 복호로 샤논 한계에 근접LTE·5G 표준 채널 부호

3. 오류 검출 vs 오류 정정 비교​

비교 기준오류 검출(+ARQ)오류 정정(FEC)
목적오류 유무 판별 후 재전송 요구수신 측이 자체 복원
잉여 비트적음(오버헤드 낮음)많음(대역폭 소모 큼)
지연재전송에 따른 가변 지연(RTT 의존)일정·짧음(재전송 없음)
역채널필요(ACK/NAK)불필요 (단방향 가능)
적합 환경오류율 낮고 지연 허용 가능(유선·TCP)재전송 곤란(위성·방송·실시간 스트리밍), 고오류 무선
구현 복잡도낮음높음(복호기 연산)
대표 사례TCP, HDLC, 이더넷 CRC5G LDPC, 위성통신, 저장장치 ECC

실제 시스템은 HARQ(Hybrid ARQ) 처럼 FEC로 1차 정정 후 실패 시 재전송하는 혼합 방식을 사용한다(LTE·5G).

Ⅲ. 나. 정지-대기 ARQ와 Go-Back-N ARQ의 개념 및 수행절차​

1. 정지-대기(Stop-and-Wait) ARQ​

  • 개념: 송신 측이 한 개의 프레임을 보낸 후 그에 대한 ACK를 받을 때까지 대기하고, 수신 후 다음 프레임을 전송하는 가장 단순한 ARQ. 윈도우 크기 = 1.
   송신                                수신
    │── Frame 0 ──────────────────────►│  수신·오류검사 정상
    │◄──────────────────── ACK 1 ──────│  (다음 기대 번호 응답)
    │── Frame 1 ──────────────────────►│  오류 발생 / 분실
    │        ⏱ 타임아웃 만료            │
    │── Frame 1 (재전송) ─────────────►│  정상 수신
    │◄──────────────────── ACK 0 ──────│
    ※ 순서번호는 **1비트(0/1)** 만으로 충분(중복 프레임 식별용)

수행 절차

단계송신 측수신 측
①프레임 전송 후 사본 보관, 타이머 시작프레임 수신
②ACK 대기(다음 프레임 전송 불가)오류 검사(CRC)
③ACK 수신 → 사본 폐기, 순서번호 반전정상 → ACK 전송 / 오류 → 폐기(또는 NAK)
④타임아웃 시 재전송중복 프레임 수신 시 폐기 후 ACK 재전송
  • 문제 유형별 처리: 프레임 분실 → 타임아웃 재전송 / ACK 분실 → 타임아웃 재전송 후 수신 측이 중복 검출·폐기 / ACK 지연 → 불필요 재전송 발생

2. Go-Back-N ARQ​

  • 개념: 송신 측이 ACK를 기다리지 않고 윈도우 크기 N만큼 연속 전송하다가, 오류가 발생하면 오류 프레임과 그 이후 전송된 모든 프레임을 재전송하는 슬라이딩 윈도우 방식. 수신 윈도우 크기 = 1(순서대로만 수용).
   송신 윈도우 N=4
    │── F0 ─► │── F1 ─► │── F2 ─► │── F3 ─►
    │◄ ACK1   │  F1 오류(분실)      │
    │                    수신 측 : F2, F3는 순서 어긋남 → **모두 폐기**, ACK1 반복 전송
    │  타임아웃(또는 NAK1) 발생
    │── F1 ─► │── F2 ─► │── F3 ─►   ← **F1부터 전부 재전송(Go-Back-N)**
   ※ 순서번호 m비트 → 송신 윈도우 최대 **2^m − 1**

수행 절차

단계내용
①송신 측이 윈도우 범위 내 프레임을 연속 전송, 각 프레임 사본 보관·타이머 운용
②수신 측은 순서대로 도착한 프레임만 수용, 어긋나면 폐기하고 마지막 정상 수신 다음 번호로 ACK(누적 확인응답)
③송신 측이 ACK 수신 → 윈도우 슬라이딩, 해당 프레임 사본 폐기
④타임아웃 또는 NAK 수신 시 → 해당 프레임부터 이후 전송분 전체 재전송
  • 누적 ACK(Cumulative ACK): ACK n은 "n−1까지 모두 정상 수신, 다음은 n을 기대"를 의미 → 일부 ACK 분실도 후속 ACK로 보완 가능

Ⅳ. 다. 정지-대기 ARQ와 Go-Back-N ARQ 비교​

비교 기준정지-대기 ARQGo-Back-N ARQ
송신 윈도우1N (최대 2^m − 1)
수신 윈도우11 (순서대로만 수용)
순서번호1비트(0, 1)m비트
전송 방식한 개 전송 후 대기(Half-duplex 유사)연속 전송(파이프라이닝)
채널 이용률매우 낮음 — U = Tf/(Tf+2Tp) = 1/(1+2a)높음 — U = N/(1+2a) (N ≥ 1+2a면 100%)
재전송 범위해당 프레임 1개오류 프레임 이후 전체(불필요 재전송 발생)
버퍼 요구량송·수신 각 1개(최소)송신 N개, 수신 1개
구현 복잡도매우 단순중간(윈도우·타이머 관리)
오류율 높은 환경재전송 1개로 손실 적으나 처리량 자체가 낮음재전송 폭증으로 효율 급락
지연·대역 큰 환경(위성)매우 비효율(대기 시간 지배)상대적으로 우수
적용 사례단순 임베디드·저속 링크, TFTPHDLC, 초기 TCP 계열
   [채널 이용률 비교 — a = Tp/Tf (전파지연/전송시간)]
   a = 1 인 경우
   Stop-and-Wait : U = 1/(1+2×1) = **33%**
   Go-Back-N(N=4): U = 4/(1+2×1) = **100%(상한)**
   ⇒ 대역폭-지연 곱(BDP)이 클수록 윈도우 방식의 우위가 결정적

선택적 재전송(Selective Repeat)과의 관계​

항목Go-Back-NSelective Repeat
재전송오류 이후 전부오류 프레임만
수신 버퍼1개N개(순서 재정렬 필요)
효율오류율 높으면 급락오류율 높아도 효율 유지
복잡도낮음높음
윈도우 제약2^m − 12^(m−1)

Ⅴ. 결론​

오류 제어는 검출 후 재전송(ARQ) 과 자체 정정(FEC) 이라는 두 축으로 구성되며, 채널 특성에 따라 선택이 달라진다. ARQ 내에서도 정지-대기는 구현이 단순하나 대역폭-지연 곱이 큰 환경에서 채널 이용률이 치명적으로 낮고, Go-Back-N은 파이프라이닝으로 효율을 크게 개선하지만 오류율이 높으면 불필요 재전송이 급증하는 한계가 있다.

따라서 실무 설계 시에는 ① BDP(대역폭×지연)와 오류율을 함께 고려하여 윈도우 크기와 방식을 결정하고, ② 무선·위성처럼 오류율과 지연이 모두 큰 환경에서는 FEC로 1차 정정 후 잔여 오류만 재전송하는 HARQ를 적용하며, ③ TCP처럼 선택적 확인응답(SACK) 을 결합해 Go-Back-N의 비효율을 보완하는 접근이 바람직하다. 5G가 LDPC와 HARQ를 결합해 초저지연·초신뢰를 달성한 것이 이러한 설계 원칙의 대표적 구현 사례이다.
