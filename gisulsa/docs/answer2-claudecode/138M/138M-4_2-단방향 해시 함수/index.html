단방향 해시 함수(One-way Hash Function)

Ⅰ. 개요​

1. 개념​

단방향 해시 함수는 임의 길이의 입력(Message)을 고정 길이의 출력(Digest) 으로 변환하되, 출력에서 입력을 역산할 수 없는(One-way) 함수이다. 무결성 검증과 비밀번호 저장의 기본 수단이다.

2. 안전성 요건​

요건내용
역상 저항성(Preimage Resistance)해시값 h로부터 원문 m을 찾기 어려움
제2 역상 저항성(2nd Preimage)주어진 m과 같은 해시를 갖는 m′를 찾기 어려움
충돌 저항성(Collision Resistance)h(m₁)=h(m₂)인 임의의 쌍을 찾기 어려움
눈사태 효과(Avalanche)입력 1비트 변경 시 출력의 약 50%가 변화

Ⅱ. 가. 단방향 해시 함수의 문제점​

구분문제점내용
① 충돌(Collision)비둘기집 원리상 충돌은 필연적으로 존재MD5·SHA-1은 실제 충돌 생성이 가능해 위조 문서·인증서 제작 가능 → 사용 금지
② 생일 공격생일 역설로 n비트 해시의 충돌 탐색 복잡도가 2^(n/2) 로 감소128비트 해시는 실질 64비트 안전성 → 최소 256비트(SHA-256) 권고
③ 무차별 대입·사전 공격동일 입력 → 항상 동일 출력(결정적)흔한 비밀번호를 미리 계산해 대입하면 즉시 복원
④ 레인보우 테이블사전 계산된 해시 대응표로 대량 비밀번호 일괄 복원아래 Ⅲ 참조
⑤ 연산 속도가 빠름원래 장점인 고속성이 비밀번호 저장 시에는 취약점GPU·ASIC으로 초당 수십억 회 대입 가능 → 의도적 저속화(Key Stretching) 필요
⑥ 길이 확장 공격Merkle-Damgård 구조(MD5·SHA-1·SHA-2)의 구조적 취약h(secret‖m)을 알면 h(secret‖m‖pad‖m′) 계산 가능 → HMAC 또는 SHA-3 사용
⑦ 동일 비밀번호 노출같은 비밀번호는 같은 해시DB 유출 시 동일 비밀번호 사용자 그룹이 즉시 식별

Ⅲ. 나. Rainbow Table​

1. 개념​

레인보우 테이블은 가능한 평문과 해시값의 대응 관계를 환원 함수(Reduction Function)로 연결한 체인(Chain) 형태로 압축 저장하여, 시간과 저장공간의 Trade-off(TMTO: Time-Memory Trade-Off) 로 해시를 역산하는 사전 계산 공격 기법이다.

2. 동작 원리​

   [체인 생성 — 사전 계산 단계]
   평문 P1 ──H──► 해시 h1 ──R1──► 평문 P2 ──H──► h2 ──R2──► P3 … ──► Pn
   저장 : **시작점 P1과 종점 Pn만 저장**(중간값은 버림 → 저장공간 대폭 절감)
          ※ R(환원함수)은 복호화가 아니라 해시값을 평문 형식으로 '변환'하는 함수
          ※ 단계마다 다른 R을 사용(R1,R2,…) → 체인 충돌·병합 감소 = '레인보우'

   [탐색 — 공격 단계]
   목표 해시 h ──R──► 평문 ──H──► … 반복하며 저장된 **종점과 일치** 여부 확인
        일치 시 → 해당 체인의 시작점부터 재계산 → **원본 평문 복원**

3. 특징 및 대응​

항목내용
장점(공격자)전수 대입보다 훨씬 빠름, 전체 사전 저장 대비 저장공간 획기적 절감
한계문자 집합·길이 범위별로 테이블을 따로 생성해야 함, 솔트가 있으면 무력화
핵심 대응솔트(Salt) 적용 — 사용자마다 다른 값이 결합되어 사전 계산 테이블 자체가 무용지물
보조 대응키 스트레칭, 페퍼(Pepper), 긴 비밀번호 정책, MFA

Ⅳ. 다. 해시 솔트(Salt)와 키 스트레칭(Key Stretching)​

1. 해시 솔트(Salt)​

  • 개념: 비밀번호 해시 계산 시 사용자마다 서로 다른 무작위 값(Salt)을 결합하여 해시하는 기법. Hash(Password ‖ Salt)
   [솔트 미적용]                        [솔트 적용]
   user A : pw="1234" → h(1234)=X       user A : salt=a1b2 → h(1234‖a1b2)=X₁
   user B : pw="1234" → h(1234)=X       user B : salt=c3d4 → h(1234‖c3d4)=X₂
   ⇒ 동일 해시 노출, 레인보우 테이블 즉시 적용   ⇒ **해시값 상이, 사전 계산 불가**
항목내용
효과레인보우 테이블·사전 공격 무력화, 동일 비밀번호 사용자 식별 방지, 공격자가 계정별로 개별 공격 수행하도록 강제
구현 원칙① 사용자마다 고유(Unique), ② 암호학적 난수(CSPRNG)로 생성, ③ 길이 최소 16바이트 이상, ④ 비밀이 아니어도 되며 해시와 함께 저장 가능
한계솔트만으로는 무차별 대입(Brute-force) 자체를 막지 못함 → 키 스트레칭 병행 필수
페퍼(Pepper)솔트와 달리 DB가 아닌 별도 안전한 위치(HSM·환경변수)에 보관하는 비밀 값 → DB만 유출되면 크래킹 불가

2. 키 스트레칭(Key Stretching)​

  • 개념: 해시 연산을 의도적으로 수만~수십만 회 반복하거나 메모리를 대량 사용하도록 만들어, 검증 1회의 비용은 감내 가능한 수준으로 두되 공격자의 대량 대입 비용을 기하급수적으로 증가시키는 기법.
   h = H(H(H(…H(pw ‖ salt)…)))   ← 반복 횟수(Work Factor) 조절 가능
   정상 로그인 : 1회 검증 ≈ 0.1~0.5초 (사용자 체감 미미)
   공격자      : 10억 개 후보 × 0.1초 ⇒ **현실적으로 불가능**
   ※ 하드웨어 발전에 맞춰 **Work Factor를 주기적으로 상향** 조정
알고리즘특징
PBKDF2반복 횟수 기반, 표준화(NIST·RFC 8018)·호환성 우수. GPU 병렬화에 상대적으로 취약
bcryptBlowfish 기반, Cost Factor로 조절, 솔트 내장. 메모리 사용 적음
scrypt메모리 하드(Memory-hard) — 대용량 메모리 요구로 ASIC·GPU 공격 비용 급증
Argon2Password Hashing Competition 우승(2015), 현재 권고 표준. 시간·메모리·병렬성 파라미터 조절, Argon2id 권장
  • 조합 원칙: Argon2id(Password ‖ Salt, 시간·메모리 파라미터) + 별도 보관 Pepper 가 현재 권고되는 비밀번호 저장 방식이며, 단순 SHA-256 1회 해시는 부적합하다.

Ⅴ. 라. 해시함수의 활용​

활용 분야내용
비밀번호 저장평문·암호화 대신 복호화 불가능한 해시 저장(Salt + Key Stretching 필수)
무결성 검증파일·펌웨어 다운로드 검증(체크섬), DB 변조 탐지, 로그 위변조 방지
전자서명·인증서메시지 다이제스트에 서명(성능·안전성 확보), X.509 인증서 서명, 코드 서명
메시지 인증(MAC)HMAC — 공유키 기반 무결성 + 인증(길이 확장 공격 방어), API 서명(AWS SigV4)
블록체인블록 헤더 연결(이전 블록 해시), 작업증명(PoW), 머클 트리(효율적 무결성 검증), 주소 생성
자료구조·성능해시 테이블(O(1) 탐색), 캐시 키, 로드밸런싱의 일관된 해싱(Consistent Hashing), 분산 DB 샤딩
중복 제거·식별스토리지 De-duplication, 파일 식별자, 콘텐츠 주소 지정(CAS), Git의 커밋·객체 ID
보안 운영악성코드 시그니처(IoC), 화이트리스트 검증, 디지털 포렌식의 증거 무결성(해시값 봉인)
프라이버시가명처리(암호학적 해시 기반 일방향 처리), 개인정보 안전성 확보조치상 일방향 암호화
키 유도KDF(HKDF)로 마스터 키에서 세션 키 파생, TLS 키 스케줄

알고리즘 선택 기준​

용도권고
일반 무결성·서명SHA-256/384/512, SHA-3 (MD5·SHA-1 사용 금지)
메시지 인증HMAC-SHA-256 이상
비밀번호 저장Argon2id, bcrypt, scrypt, PBKDF2(충분한 반복 횟수)
고속 비암호학적 용도MurmurHash·xxHash (해시 테이블 전용, 보안 용도 금지)

Ⅵ. 결론​

단방향 해시 함수는 무결성과 인증의 기반 기술이지만, 충돌·생일 공격·레인보우 테이블, 그리고 "너무 빠르다"는 역설적 취약점을 안고 있다. 따라서 용도에 따라 요구되는 성질이 다르다는 점을 명확히 인식해야 한다.

실무 원칙은 ① 무결성·서명에는 SHA-256 이상의 고속 해시를, ② 비밀번호 저장에는 반드시 솔트와 키 스트레칭을 적용한 전용 알고리즘(Argon2id 등) 을 사용하며, ③ MD5·SHA-1 등 취약 알고리즘의 전면 폐기와 Crypto-Agility(알고리즘 교체 용이성) 확보를 설계에 반영하는 것이다. 나아가 양자컴퓨팅 시대에는 Grover 알고리즘으로 해시 안전성이 절반 수준(2^(n/2))으로 감소하므로, 최소 SHA-384 이상 채택 등 사전 대비가 필요하다.
