IT 인프라 확장에 따른 공격 표면·공격 벡터와 측면 이동

Ⅰ. 개요​

1. 배경​

클라우드·재택근무·IoT·SaaS 확산으로 조직의 자산이 경계(Perimeter) 외부로 분산되면서, 관리되지 않는 노출 지점이 급증하고 있다. 이에 따라 방어 전략도 경계 방어에서 공격 표면 관리(ASM)와 내부 확산 차단(제로 트러스트) 중심으로 전환되고 있다.

2. 침해 흐름 관점​

   [정찰] → **공격 표면 식별** → **공격 벡터로 초기 침투** → 거점 확보
                                                    │
   [목표 달성] ← 데이터 유출·암호화 ← 권한 상승 ← **측면 이동(Lateral Movement)**

Ⅱ. 가. 공격 표면(Attack Surface)과 공격 벡터(Attack Vector)​

1. 공격 표면(Attack Surface)​

  • 정의: 공격자가 시스템에 접근·침투를 시도할 수 있는 모든 진입점(Entry Point)의 총합. "어디를 공격할 수 있는가"를 나타내는 정적·구조적 노출 범위이다.
유형구성 요소확장 요인
디지털외부 공개 IP·포트·도메인, 웹 애플리케이션·API, 클라우드 스토리지·관리 콘솔, 소스코드 저장소멀티 클라우드, API 우선 개발, 섀도 IT
물리서버실·단말·USB·네트워크 포트, 폐기 장비지사·데이터센터 확대
인적(Human)임직원·협력사 인력의 계정·권한, 사회공학 대상재택근무, 인력 이동
공급망오픈소스 라이브러리, SaaS, 협력사 연결(VPN)아웃소싱·SaaS 확대
아이덴티티계정·토큰·키·인증서, 서비스 계정클라우드 권한 폭증(과다 권한)

2. 공격 벡터(Attack Vector)​

  • 정의: 공격자가 공격 표면을 통해 실제로 침투하는 경로·수단·기법. "어떻게 공격하는가"를 나타내는 동적·행위적 개념이다.
벡터 유형사례
사회공학피싱·스피어피싱, 비즈니스 이메일 침해(BEC), 스미싱, MFA 피로 공격
자격증명유출 계정 재사용(Credential Stuffing), 무차별 대입, 세션 토큰 탈취
취약점 익스플로잇미패치 서버(VPN·웹서버), 제로데이, 웹 취약점(SQLi·XSS·SSRF)
설정 오류공개 클라우드 버킷, 기본 계정·기본 포트, 과다 권한 IAM
악성코드랜섬웨어, 트로이목마, 드라이브바이 다운로드
공급망오픈소스 패키지 변조, 협력사·MSP 경유 침투
내부자권한 오남용, 퇴직자 계정 미회수

3. 비교 및 관계​

비교 기준공격 표면공격 벡터
의미공격 가능한 지점의 집합(Where)공격 수행 경로·수단(How)
성격정적·구조적동적·행위적
관점방어자 관점(자산 노출 범위)공격자 관점(침투 방법)
관리 방법ASM/EASM(자산 식별·축소), 불필요 서비스 제거위협 인텔리전스, ATT&CK TTP 기반 탐지
관계표면이 넓을수록 벡터의 선택지가 증가하나의 표면에 다수 벡터가 존재
대응 원칙최소화(Minimization)차단·탐지(Detection)
   [비유] 공격 표면 = 건물의 모든 문·창문(진입 가능 지점)
          공격 벡터 = 열쇠 복제 / 유리 파손 / 배관 침입(실제 침투 방법)

4. 공격 표면 관리(ASM) 방안​

  • 식별: EASM 도구로 외부 노출 자산 상시 스캐닝, 섀도 IT·미등록 자산 발굴, SBOM으로 SW 구성요소 관리
  • 축소: 불필요 포트·서비스 폐쇄, 기본 계정 제거, 최소 권한(Least Privilege), 노출 관리 콘솔 IP 제한
  • 강화: 패치·취약점 관리 자동화, 보안 설정 기준(CIS Benchmark) 준수, MFA 전면 적용
  • 검증: 정기 모의해킹·침투 테스트(BAS), CTEM(지속적 위협 노출 관리) 체계 운영

Ⅲ. 나. 측면 이동(Lateral Movement)의 단계별 메커니즘과 주요 기법​

1. 개념​

측면 이동은 공격자가 초기 침투로 확보한 거점에서 내부 네트워크의 다른 시스템으로 수평 확산하며 권한과 접근 범위를 넓혀가는 활동이다. 침해사고에서 초기 침투 이후 실제 피해가 발생하는 핵심 구간이며, 랜섬웨어의 전사 확산도 이 단계에서 이루어진다.

2. 단계별 메커니즘​

   [초기 거점]
       │
   ① 정찰(Discovery) ──► 내부 네트워크·계정·자산 파악
       │                  (AD 조회, 포트 스캔, 공유 폴더 탐색)
   ② 자격증명 획득(Credential Access) ──► 계정·해시·티켓 탈취
       │                  (LSASS 덤프, 키로깅, 평문 저장 자격증명)
   ③ 권한 상승(Privilege Escalation) ──► 로컬→도메인 관리자
       │                  (취약점, 잘못된 ACL, 위임 설정 악용)
   ④ **이동·실행(Lateral Movement)** ──► 원격 시스템 접속·코드 실행
       │                  (RDP, SMB, WMI, PsExec, WinRM, SSH)
   ⑤ 지속성 확보(Persistence) ──► 백도어·계정 생성·스케줄 작업
       │                  (C2 채널 유지, GPO 변조)
   ⑥ 목표 달성(Impact) ──► 데이터 수집·유출, 랜섬웨어 배포
단계목적주요 활동
① 정찰내부 지형 파악AD 열거(BloodHound), 네트워크 스캔, 공유 자원·서버 목록 수집
② 자격증명 획득이동 수단 확보Mimikatz LSASS 덤프, NTDS.dit 탈취, 브라우저·설정파일 내 저장 credential
③ 권한 상승통제 범위 확대커널·서비스 취약점, Kerberoasting, DCSync, 취약한 서비스 권한
④ 이동·실행타 시스템 장악원격 실행 프로토콜 악용, 스케줄 작업·서비스 생성
⑤ 지속성재접속 보장백도어 계정, WMI 이벤트 구독, 웹셸, C2 비콘
⑥ 목표 달성실제 피해데이터 스테이징·압축·유출(Exfiltration), 백업 삭제 후 암호화

3. 주요 기법(MITRE ATT&CK 매핑)​

기법내용ATT&CK
Pass-the-Hash(PtH)평문 비밀번호 없이 NTLM 해시만으로 인증T1550.002
Pass-the-Ticket(PtT)탈취한 Kerberos 티켓(TGT/TGS) 재사용T1550.003
Golden / Silver TicketKRBTGT 계정 해시로 위조 TGT 생성 → 도메인 전체 장악T1558
Kerberoasting서비스 계정 티켓을 오프라인 크래킹T1558.003
원격 서비스 악용RDP, SMB(관리 공유), WMI, WinRM, SSH를 통한 접속·실행T1021
PsExec·원격 도구정상 관리도구로 원격 코드 실행 → LotL(Living off the Land) 로 탐지 회피T1569
DCSync / DCShadow도메인 컨트롤러 복제 권한 악용해 전체 계정 해시 획득T1003.006
내부 스피어피싱장악한 내부 계정으로 동료에게 악성 메일 발송(신뢰 악용)T1534
소프트웨어 배포 도구 악용SCCM·패치관리 서버 장악 → 전사 일괄 악성코드 배포T1072
공유 자원 감염네트워크 공유·스크립트·이미지 변조T1080

4. 대응 방안​

계층대응 방안
네트워크마이크로 세그멘테이션, 업무망·서버망 분리, 동서(East-West) 트래픽 통제, 불필요 SMB/RDP 차단
계정·인증최소 권한·관리자 계정 분리(Tier Model), PAM(특권계정 관리·세션 기록), MFA, 로컬 관리자 암호 랜덤화(LAPS)
자격증명 보호Credential Guard, LSASS 보호, 캐시된 자격증명 최소화, 서비스 계정 강한 암호·gMSA
탐지EDR/XDR 행위 기반 탐지, 비정상 인증 패턴(NTLM 이상, 다수 호스트 로그인) 분석, UEBA, 허니 계정·허니팟
아키텍처제로 트러스트(모든 접근 검증, 암묵적 신뢰 제거), 자산·ID 중심 통제
운영패치 관리, 침해 가정(Assume Breach) 기반 모의훈련, 백업의 오프라인·불변(Immutable) 보관, IR 플레이북

Ⅳ. 결론​

IT 인프라 확장은 필연적으로 공격 표면의 확대를 수반하며, 넓어진 표면은 곧 공격 벡터의 다양화로 이어진다. 그러나 실제 피해 규모를 결정하는 것은 초기 침투 자체가 아니라 내부에서의 측면 이동을 얼마나 조기에 차단·탐지하는가이다.

따라서 방어 전략은 ① ASM·CTEM으로 노출 자산을 지속 식별·축소하고, ② 초기 침투는 불가피하다는 전제(Assume Breach) 하에 마이크로 세그멘테이션과 특권계정 통제로 확산 경로를 끊으며, ③ 정상 도구를 악용하는 LotL 공격에 대응하기 위해 시그니처가 아닌 TTP·행위 기반 탐지(EDR·UEBA) 를 강화하는 방향으로 전환되어야 한다. 이것이 경계 방어의 한계를 보완하는 제로 트러스트 아키텍처의 실질적 구현이다.
