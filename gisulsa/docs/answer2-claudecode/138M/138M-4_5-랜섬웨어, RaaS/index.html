랜섬웨어와 RaaS(Ransomware as a Service)

Ⅰ. 개요​

1. 배경​

랜섬웨어는 데이터를 암호화해 금전을 요구하는 공격으로, 최근 RaaS 등장에 따라 기술적 진입장벽이 사라지고 공격이 산업화·분업화되었다. 여기에 이중·삼중 갈취(Double/Triple Extortion) 가 결합되어 백업만으로는 피해를 막을 수 없는 국면에 이르렀다.

2. 위협 동향​

   [랜섬웨어 진화]
   1세대 : 단순 암호화 → 백업으로 복구 가능
   2세대 : **데이터 유출 후 암호화**(이중 갈취) → 백업으로도 유출 협박 방어 불가
   3세대 : + DDoS·고객/규제기관 통보 협박(삼중 갈취)
   4세대 : **암호화 생략, 데이터 탈취 후 협박만**(Exfiltration-only) + AI 활용 정교화

Ⅱ. 가. 랜섬웨어와 RaaS의 개념 및 비교​

1. 랜섬웨어(Ransomware)​

  • 정의: 시스템·파일을 암호화하거나 접근을 차단(Locker) 한 뒤, 복호화 키 제공을 대가로 금전(주로 암호화폐)을 요구하는 악성코드.
  • 유형: 암호화형(Crypto), 화면잠금형(Locker), 유출 협박형(Leakware/Doxware), 파괴형(Wiper — 복구 불가, 파괴가 목적)

2. RaaS(Ransomware as a Service)​

  • 정의: 랜섬웨어 개발자가 악성코드·인프라·협상 지원을 구독형 서비스로 제공하고, 실제 공격을 수행하는 제휴사(Affiliate) 가 이를 이용해 공격 후 수익을 분배하는 범죄 비즈니스 모델.
   [RaaS 생태계 — 범죄의 분업화]
   ┌──────────────┐  악성코드·빌더·C2·유출사이트·협상채널 제공
   │ **운영자**    │──────────────────────────────────┐
   │ (Operator)   │◄─── 수익 배분 (통상 20~30%) ─────┤
   └──────────────┘                                  │
   ┌──────────────┐  침투·확산·실행 담당              │
   │ **제휴사**    │──────────► [피해 조직] ──────────┘
   │ (Affiliate)  │            몸값 70~80% 수취
   └──────────────┘
   ┌──────────────┐
   │ IAB(초기접근  │  탈취 계정·VPN 접근권 판매
   │  브로커)      │  → 제휴사가 구매하여 즉시 침투
   └──────────────┘
  • 제공 요소: 랜섬웨어 빌더·복호화 도구, C2 인프라, 유출 사이트(Leak Site), 협상 포털·고객지원, 대시보드·통계, 백신 우회 모듈
  • 과금 모델: 월 구독형, 수익 배분형(Affiliate), 일회성 라이선스, 지분 참여형

3. 랜섬웨어와 RaaS 비교​

비교 기준랜섬웨어RaaS
개념악성코드(공격 도구)서비스·비즈니스 모델
관점기술적 산출물범죄 생태계·유통 구조
수행 주체개발자 = 공격자(동일인)개발자와 실행자 분리(운영자/제휴사)
진입장벽높음(개발 역량 필요)매우 낮음(구독·구매만으로 가능)
확산 속도제한적폭발적(제휴사 수만큼 동시 다발)
수익 구조공격자 전액운영자·제휴사·IAB 분배
대응 난이도시그니처·행위 탐지변종 양산·TTP 다양화로 탐지 곤란
추적상대적으로 단순분업으로 책임 주체 특정 곤란
대표 사례WannaCry, PetyaLockBit, ALPHV/BlackCat, Cl0p, Conti

핵심 시사점: RaaS는 랜섬웨어를 "기술 문제"에서 "산업화된 조직범죄 문제"로 전환시켰으며, 이로 인해 공격 빈도·표적 다양성이 급증했다.

Ⅲ. 나. 주요 감염 경로 및 암호화 동작 원리​

1. 주요 감염 경로​

경로상세 내용비중·특징
피싱 이메일악성 첨부(문서 매크로·ISO·LNK), 악성 링크가장 전통적, 사회공학 결합
취약점 익스플로잇VPN·방화벽·원격접속 장비, 웹서버, 파일전송 솔루션(MOVEit)의 미패치·제로데이최근 최다 경로, 대규모 피해 유발
RDP·원격접속인터넷 노출 RDP의 취약 계정·크리덴셜 스터핑중소기업 주요 침투 경로
초기접근 브로커(IAB)사전 탈취된 계정·VPN 접근권 구매 후 즉시 침투RaaS 생태계 특유
공급망 공격SW 업데이트 서버·MSP·협력사 경유1회 침투로 다수 피해
웹·기타드라이브바이 다운로드, 악성 광고, 불법 SW·USB개인·소규모 대상

2. 공격 및 암호화 동작 원리​

   ① 침투 ─► ② 정찰·권한상승 ─► ③ **측면 이동** ─► ④ **백업 삭제·보안 무력화**
                                                            │
   ⑦ 협박·유출 ◄── ⑥ **암호화 실행** ◄── ⑤ **데이터 탈취(Exfiltration)** ◄┘
   ※ 실제 암호화는 **가장 마지막**에 수행 — 그 이전 잠복 기간(수일~수주)이 탐지의 골든타임
단계내용
④ 무력화볼륨 섀도 복사본(VSS) 삭제, 백업 서버·스냅샷 파괴, 백신·EDR 중지, 안전모드 부팅
⑤ 탈취민감 데이터 압축·분할 후 클라우드 스토리지로 유출 → 이중 갈취 근거 확보
⑥ 암호화파일 암호화 후 확장자 변경, 랜섬노트 생성

하이브리드 암호화 구조

   [파일 암호화]  대칭키(AES-256) — **빠른 속도**로 대량 파일 처리
        │
   [키 보호]      대칭키를 **공격자의 공개키(RSA-2048/4096)** 로 암호화하여 파일에 첨부
        │
   [복호화 조건]  공격자만 보유한 **개인키(Private Key)** 필요 ⇒ 자체 복호화 사실상 불가능
   ※ 부분 암호화(Intermittent Encryption) : 파일 일부만 암호화해 **속도↑·탐지 회피**
  • 키 관리: 피해자별로 서로 다른 대칭키 생성 → 한 피해자의 키 유출이 다른 피해자 복구로 이어지지 않음
  • 회피 기법: 특정 국가 키보드 레이아웃 감지 시 미실행, 샌드박스 탐지, LotL(정상 도구 악용), 코드 서명 위조

Ⅳ. 다. 피해 예방 및 침해사고 발생 시 대응 절차​

1. 예방 대책​

계층대책
백업(최후 보루)3-2-1-1-0 원칙 — 사본 3개, 매체 2종, 오프사이트 1개, 오프라인·불변(Immutable) 1개, 복구 검증 오류 0
백업 서버 망 분리·별도 계정, 정기 복구 훈련
취약점 관리인터넷 노출 자산(VPN·방화벽·웹) 우선 패치, EASM으로 노출 자산 상시 점검
계정·접근통제MFA 전면 적용(특히 VPN·RDP·관리자), 최소 권한, PAM, RDP 인터넷 직접 노출 금지
네트워크마이크로 세그멘테이션(측면 이동 차단), 관리망 분리, 불필요 SMB 차단
엔드포인트EDR/XDR 행위 기반 탐지, 응용프로그램 허용목록, 매크로 차단, 스크립트 제어
메일·웹첨부·URL 샌드박스 분석, DMARC·SPF, 위협 인텔리전스 연동
탐지대량 파일 변경·VSS 삭제·비정상 대량 아웃바운드 트래픽 탐지 룰, 허니팟 파일
사람·프로세스정기 모의훈련·교육, IR 플레이북 및 비상연락체계 정비, 사이버 보험 검토
공급망협력사 보안 요구사항, SBOM, 제3자 접근 통제

2. 침해사고 발생 시 대응 절차​

   ① 탐지·초동분석 ─► ② **격리·확산차단** ─► ③ 신고·보고 ─► ④ 원인분석(포렌식)
                                                                    │
        ⑦ 재발방지·개선 ◄── ⑥ 서비스 정상화 ◄── ⑤ **복구(백업 기반)** ◄┘
단계주요 조치유의사항
① 탐지·초동침해 범위·감염 시스템 식별, CSIRT 소집, 대응팀 가동침착한 상황 판단, 성급한 재부팅 금지
② 격리·차단감염 시스템 네트워크 분리, 공유 폴더·계정 차단, 백업 시스템 즉시 격리, 손상된 계정 비밀번호 일괄 변경전원 종료보다 네트워크 차단 우선(메모리 내 키·증거 보존)
③ 신고·보고KISA(118)·한국인터넷진흥원 신고, 경찰(사이버수사대), 경영진 보고
개인정보 유출 시 개인정보위·정보주체 통지(법정 기한 준수)		정보통신망법·개인정보보호법상 신고 의무 확인
④ 원인분석디지털 포렌식(증거 보전 — 이미징·해시), 최초 침투 경로(Patient Zero)·랜섬웨어 종류 식별, 유출 데이터 범위 확인증거 훼손 방지, 필요 시 전문기관 지원 요청
⑤ 복구취약점 제거·계정 정리 후 깨끗한 환경에 백업 복구, 무료 복호화 도구 확인(No More Ransom 프로젝트), 단계적 복원감염 원인 제거 전 복구 시 재감염 — 복구 전 취약점 조치 필수
⑥ 정상화서비스 재개, 집중 모니터링, 잔존 백도어 점검재침투 시도 대비 감시 강화
⑦ 재발방지원인별 개선과제 도출, 통제 보완, 훈련·교육, 대내외 커뮤니케이션사후 보고서 작성, 유사 자산 일괄 점검

3. 몸값 지불에 대한 판단​

관점내용
원칙지불 권장하지 않음 — 복구 보장 없음(지불해도 완전 복구율 낮음), 재공격 표적화, 범죄조직 자금 지원
법적 리스크제재 대상 조직에 대한 지불은 법적 문제 소지, 국가별 규제 강화 추세
현실적 고려인명·핵심 인프라 관련 등 불가피한 상황은 법률·수사기관 협의 하에 판단

Ⅴ. 결론​

RaaS의 확산으로 랜섬웨어는 소수 전문가의 공격에서 누구나 수행 가능한 산업화된 범죄로 변모했으며, 이중 갈취가 보편화되면서 "백업만 있으면 된다"는 대응 공식은 더 이상 유효하지 않다.

따라서 대응 전략은 ① 불변(Immutable)·오프라인 백업과 복구 훈련으로 가용성을 보장하고, ② 동시에 데이터 유출 자체를 차단하기 위해 암호화·DLP·비정상 아웃바운드 탐지를 강화하며, ③ 실제 암호화 이전의 잠복·측면 이동 구간을 EDR과 세그멘테이션으로 조기 차단하는 데 집중해야 한다. 아울러 ④ VPN·원격접속 장비의 신속한 패치와 MFA 적용이 최근 침투 경로 통계상 가장 비용 대비 효과가 큰 조치이며, ⑤ 사고를 전제로 한 IR 플레이북과 정기 훈련이 실제 피해 규모를 결정한다.
