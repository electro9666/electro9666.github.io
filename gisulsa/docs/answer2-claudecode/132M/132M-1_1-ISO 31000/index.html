ISO 31000

문제​

1.ISO 31000

Ⅰ. 개요​

ISO 31000은 조직의 규모·업종·유형에 관계없이 적용할 수 있는 리스크 관리(Risk Management)의 국제 표준 지침이다. 특정 산업에 국한되지 않는 범용 프레임워크로서, 리스크를 "목표에 대한 불확실성의 영향" 으로 정의한다.

   [등장 배경]
   리스크 관리가 **부서별·영역별로 분산**(재무·안전·IT·법무)
        │  · 조직 전체의 리스크 총량 파악 불가
        │  · 위협(부정적 영향)만 관리 → **기회 상실**
        ▼
   [**ISO 31000**] (2009 제정 → **2018 개정**)
   · **전사적·통합적 리스크 관리(ERM)** 체계
   · 리스크 = **부정적 영향 + 긍정적 영향(기회)** 모두 포함
   · **인증 표준이 아닌 지침(Guideline)** — 조직 특성에 맞게 적용

Ⅱ. ISO 31000의 구조 — 3대 구성요소​

 ┌────── **① 원칙**(Principles) ── "왜, 무엇을 지향하는가" ──────┐
 │            핵심 : **가치의 창출과 보호**                       │
 │   통합적 · 구조적/포괄적 · 맞춤형 · 포용적 ·                   │
 │   동적 · 최선의 가용정보 · 인적/문화적 요소 · **지속적 개선**   │
 └───────────────────────┬────────────────────────────────────────┘
                         ▼
 ┌────── **② 프레임워크**(Framework) ── "어떻게 조직에 심는가" ──┐
 │   **리더십과 의지표명(Leadership & Commitment)** ← **중심**     │
 │        │                                                       │
 │   **통합(Integration) → 설계(Design) → 실행(Implementation)**   │
 │        **→ 평가(Evaluation) → 개선(Improvement)**  (PDCA)       │
 └───────────────────────┬────────────────────────────────────────┘
                         ▼
 ┌────── **③ 프로세스**(Process) ── "실제로 어떻게 수행하는가" ──┐
 │   적용범위·상황·기준 설정                                      │
 │        ▼                                                       │
 │   **리스크 평가(Assessment)** = 식별 → 분석 → 평가             │
 │        ▼                                                       │
 │   **리스크 대응(Treatment)**                                    │
 │   ※ 전 과정에 걸쳐 **의사소통·협의**, **모니터링·검토**, 기록   │
 └────────────────────────────────────────────────────────────────┘

Ⅲ. 리스크 관리 프로세스 상세​

단계내용
적용범위·상황·기준 설정대상 범위 정의, 내·외부 상황 분석, 리스크 수용 기준(Risk Criteria) 설정
리스크 식별(Identification)리스크 원천·사건·원인·잠재적 결과 도출 — 누락 시 이후 전 과정 무의미
리스크 분석(Analysis)발생 가능성 × 영향도 산정, 기존 통제 효과 반영 → 리스크 수준 도출
리스크 평가(Evaluation)분석 결과를 수용 기준과 비교 → 대응 필요성·우선순위 결정
리스크 대응(Treatment)아래 5가지 대응 전략 선택·실행, 잔여 리스크(Residual Risk) 확인
의사소통·협의이해관계자와 전 과정에서 지속 소통
모니터링·검토리스크 변화·통제 유효성 상시 감시
기록·보고근거 문서화, 경영진 보고
리스크 대응 전략내용
회피(Avoid)리스크 발생 활동 자체를 중단·미실시
감소·완화(Reduce)통제 도입으로 발생 가능성·영향도 축소
전가·공유(Transfer/Share)보험·아웃소싱·계약을 통한 이전
수용(Accept)대응 비용 > 효과인 경우 의도적으로 감수
활용(Take/Pursue)기회 추구를 위해 의도적으로 리스크 감수 ← ISO 31000의 특징

Ⅳ. 특징 및 활용​

구분내용
장점· 전사적 통합 관리 — 부서별 사일로 해소
· 기회 측면 포함 — 위협 관리를 넘어 가치 창출
· 업종·규모 무관 범용 적용
· 타 ISO 표준(27001·22301·9001)과 용어·구조 정합
한계· 인증 표준이 아님(ISO 27001과 달리 제3자 인증 불가)
· 구체적 기법 미제시 → ISO 31010(리스크 평가 기법) 병행 필요
· 조직 문화·경영진 의지 없이는 형식화
관련 표준·제도내용
ISO 31010리스크 평가 기법(브레인스토밍·FMEA·HAZOP·보우타이·시나리오 분석 등)
ISO Guide 73리스크 관리 용어 정의
ISO 27005정보보안 리스크 관리 — ISO 31000을 정보보안에 특화
COSO ERM내부통제 중심 ERM 프레임워크(상호 보완)
활용 분야전사 리스크 관리(ERM), 정보보안·개인정보 위험평가, 프로젝트 리스크 관리(PMBOK 연계), 사업연속성(ISO 22301), 공급망·ESG 리스크

Ⅴ. 결론​

ISO 31000은 "리스크는 회피 대상이 아니라 관리 대상이며, 위협뿐 아니라 기회도 포함한다" 는 관점 전환을 제시한 국제 지침으로, 원칙–프레임워크–프로세스의 3층 구조를 통해 리스크 관리를 조직 경영에 내재화한다.

실무 적용에서 가장 중요한 것은 경영진의 리더십과 의지표명이다. 프레임워크의 중심에 이것이 놓인 이유는, 리스크 관리가 별도 부서의 업무가 아니라 모든 의사결정에 통합되어야 하기 때문이다. 다만 ISO 31000은 인증 표준이 아니고 구체적 기법을 제시하지 않으므로, ISO 31010의 평가 기법과 ISO 27001·27005 등 영역별 표준을 결합하여 실행력을 확보하는 것이 바람직하다.
