TPM(Trusted Platform Module)

문제​

8.TPM(Trusted Platform Module)

Ⅰ. 개요​

TPM(신뢰 플랫폼 모듈) 은 TCG(Trusted Computing Group) 가 표준화한 하드웨어 기반 보안 칩으로, 암호키를 안전하게 생성·저장하고 플랫폼의 무결성을 측정·증명하는 신뢰의 근원(Root of Trust) 역할을 수행한다.

   [등장 배경 — 소프트웨어 보안의 한계]
   키·인증서를 **디스크·메모리에 소프트웨어로 저장**
        │  · OS가 감염되면 **키 탈취 = 전면 침해**
        │  · 부팅 단계 악성코드(**부트킷·루트킷**)는 OS 백신이 탐지 불가
        │  · 디스크 탈취 시 오프라인 공격 가능
        ▼
   [**TPM**] **OS와 독립된 하드웨어**에 신뢰의 기반을 둠
   · 키가 **칩 외부로 나오지 않음**(Non-exportable)
   · 부팅 과정을 **측정·기록**하여 변조 탐지
        ▼
   표준 : **TCG TPM 2.0**(ISO/IEC 11889), **Windows 11 필수 요구사항**

Ⅱ. 구성 및 동작 원리​

 ┌──────────────── **TPM 칩 내부 구조** ────────────────┐
 │  **암호 프로세서**                                    │
 │   ├ **RNG**(진성 난수 생성기) — 예측 불가 키 생성      │
 │   ├ **해시 엔진**(SHA-256)                            │
 │   ├ **비대칭 암호 엔진**(RSA·ECC) · 대칭(AES)          │
 │   └ **키 생성기**                                     │
 │                                                       │
 │  **비휘발성 메모리**(NV Storage)                      │
 │   ├ **EK**(Endorsement Key) — 제조 시 각인, **칩 고유**│
 │   ├ **SRK**(Storage Root Key) — 키 계층의 최상위       │
 │   └ 인증서·정책 데이터                                │
 │                                                       │
 │  **휘발성 메모리**                                    │
 │   └ **PCR**(Platform Configuration Register)          │
 │        부팅 구성요소의 **해시값 누적 저장**(0~23번)    │
 │                                                       │
 │  **I/O 인터페이스**(LPC/SPI/I2C)                       │
 └───────────────────────────────────────────────────────┘
        ※ **키가 칩 밖으로 나오지 않고, 연산도 칩 내부에서 수행**

■ 측정 부팅(Measured Boot)의 동작​

   [**신뢰 사슬**(Chain of Trust) — 한 단계씩 측정 후 실행]

   **CRTM**(신뢰 측정의 근원, 변경 불가 코드)
        │ ① BIOS/UEFI 펌웨어 **해시 측정** → **PCR에 기록** → 실행
        ▼
   **UEFI 펌웨어**
        │ ② 부트로더 **측정 → PCR 기록** → 실행
        ▼
   **부트로더**
        │ ③ OS 커널 **측정 → PCR 기록** → 실행
        ▼
   **OS 커널** → 드라이버·애플리케이션

   ⇒ **PCR 값 = 부팅 전 과정의 무결성 지문**
   ⇒ 한 단계라도 변조되면 **PCR 값이 달라짐** → 탐지 가능
PCR 활용내용
Sealing(봉인)특정 PCR 값일 때만 복호화 가능하도록 키를 봉인
→ 변조된 시스템에서는 BitLocker 키가 해제되지 않음
Attestation(원격 증명)PCR 값에 AIK로 서명하여 원격 서버에 제출 → 단말 무결성 원격 검증
Binding(결속)특정 TPM에 종속된 키로 암호화 → 다른 기기에서 복호화 불가

Ⅲ. 주요 기능 및 키 구조​

기능내용
① 암호키 생성·보관하드웨어 RNG로 키 생성, 개인키가 칩 외부로 반출 불가
② 무결성 측정·보고부팅 구성요소 해시를 PCR에 누적 기록
③ 봉인·해제(Seal/Unseal)시스템 상태가 일치할 때만 데이터 복호화
④ 원격 증명(Remote Attestation)플랫폼 상태를 서명하여 제3자에게 증명
⑤ 난수 생성암호학적 안전 난수 제공
⑥ 단조 카운터·타임스탬프롤백 공격 방지(카운터는 감소 불가)
⑦ 장치 식별EK 기반 고유 하드웨어 식별자
키 종류내용
EK(Endorsement Key)제조 시 칩에 영구 각인, 칩의 신원 — 직접 서명에 사용하지 않음(프라이버시)
SRK(Storage Root Key)소유권 설정 시 생성, 키 계층의 루트 — 하위 키를 감싸서(Wrapping) 보호
AIK / AK(Attestation Key)원격 증명 전용 서명키 — EK 노출 방지를 위한 별칭 키
사용자 키애플리케이션이 생성·사용하는 키(SRK 하위에 계층적으로 보호)

Ⅳ. 활용 및 비교​

활용 분야내용
디스크 암호화BitLocker·LUKS — 볼륨 암호화 키를 TPM에 봉인 → 디스크만 탈취해도 복호화 불가
보안 부팅Secure Boot + Measured Boot → 부트킷·루트킷 탐지·차단
인증서·키 저장Windows Hello, 인증서 개인키 보관, VPN·Wi-Fi 인증서
장치 무결성 증명제로트러스트의 단말 신뢰 평가, MDM·NAC 연계
DRM·라이선스기기 종속 라이선스
패스워드리스 인증FIDO2·패스키의 하드웨어 인증기 역할
클라우드·서버vTPM(가상 TPM), 기밀 컴퓨팅(Confidential Computing) 기반
비교TPMHSMTEE(SGX·TrustZone)보안토큰
형태메인보드 내장 칩전용 장비·카드CPU 내 격리 실행영역휴대형(USB·스마트카드)
주 목적플랫폼 무결성·키 보관대량 암호 연산·키 관리코드·데이터 실행 중 보호개인 인증·서명
성능낮음(초당 연산 제한)매우 높음높음낮음
비용매우 저렴(수 달러)매우 높음CPU 포함저렴
이동성없음(기기 고정)없음없음있음
대표 용도BitLocker·측정 부팅인증기관·금융 결제기밀 컴퓨팅공동인증서
구분내용
장점· 하드웨어 기반 → 소프트웨어 공격에 강함
· 키 반출 불가(Non-exportable)
· 부팅 단계부터의 무결성 검증 — OS 백신이 못 하는 영역
· 매우 저렴하고 대부분 PC에 내장
단점· 연산 성능 낮음 — 대량 암호화 부적합(키 보호용)
· 물리적 공격 가능성(콜드부트·버스 스니핑·부채널)
· 기기 종속 → 메인보드 교체 시 키 복구 불가 → 복구키 백업 필수
· 펌웨어 취약점 발생 사례(ROCA 등)
· 프라이버시 우려 — 고유 식별자에 의한 추적 가능성

Ⅴ. 결론​

TPM은 "소프트웨어는 소프트웨어를 완전히 검증할 수 없다" 는 한계를 하드웨어로 해결하는 신뢰의 근원(Root of Trust) 이다. 키를 칩 외부로 반출하지 않고, 부팅 과정을 PCR에 측정·기록함으로써 OS가 실행되기 이전 단계부터의 무결성을 보장한다는 점이 백신·EDR 같은 소프트웨어 보안과 근본적으로 다른 가치이다.

주의할 점은 TPM이 암호 가속기가 아니라 키 보관·무결성 증명 장치라는 것이다. 연산 성능이 낮으므로 대량 암호화는 CPU가 수행하고, TPM은 그 마스터 키를 봉인·보호하는 역할 분담이 표준 구성이다.

실무 도입 시 가장 중요한 고려사항은 복구 대책이다. TPM은 기기에 종속되므로 메인보드 고장·교체 시 봉인된 데이터를 영구히 잃을 수 있다. 따라서 BitLocker 등 적용 시 복구키를 반드시 별도 안전 보관해야 한다. 또한 Windows 11이 TPM 2.0을 필수 요구사항으로 지정하면서 사실상 모든 신규 단말이 이 기능을 갖추게 되었으므로, 향후에는 제로트러스트 환경에서 단말의 무결성을 원격 증명하는 기반 인프라로서 활용 가치가 더욱 커질 것으로 전망된다.
