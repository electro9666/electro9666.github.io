마이데이터 전송 보안

문제​

4.최근 개인정보보호위원회는 마이데이터 전송 시 개인정보의 안전한 처리를 보장하기 위한 가이드(마이데이터 전송 보안 안내서, 2023.09.)을 발간하였다.이와 관련하여 다음을 설명하시오.
가.전송대상 개인정보 보호책임자의 지정
나.전송대상 개인정보처리시스템의 접근 관리
다.전송대상 개인정보관리 및 재해, 재난 대비 조치

Ⅰ. 개요​

1. 배경​

개인정보 전송요구권(마이데이터) 은 정보주체가 자신의 개인정보를 본인 또는 제3자에게 전송하도록 요구할 수 있는 권리로, 데이터 활용을 촉진하는 동시에 개인정보가 기관 간 대량·상시로 이동하게 만든다.

   [마이데이터의 구조와 새로운 위험]

   **[정보주체]** ──전송 요구──▶ **[정보제공자]**(은행·통신사 등)
                                        │  대량 개인정보 보유
                                        │ **API 전송**
                                        ▼
                              **[정보수신자]**(마이데이터 사업자)
                                        │
                              **[중계기관]**(중계 전문기관)

   [기존 대비 새로운 위험]
   · **상시·대량 전송** → 한 번의 침해로 **광범위 유출**
   · **API가 상시 개방** → 새로운 공격 표면
   · **다자간 참여**(제공자·수신자·중계기관) → **책임 소재 불명확**
   · **본인 확인 오류 시 타인 정보 전송** → 치명적 사고
        ▼
   [**마이데이터 전송 보안 안내서**](개인정보보호위원회, 2023.09.)
   근거 : **개인정보보호법 제35조의2**(전송요구권), 동법 시행령,
          **개인정보의 안전성 확보조치 기준**(고시)

2. 안내서의 목적 및 체계​

항목내용
목적마이데이터 전송 과정에서 개인정보의 안전한 처리 보장 — 유출·오전송·변조 방지
적용 대상정보제공자, 정보수신자, 중계기관 등 전송에 관여하는 모든 개인정보처리자
기본 원칙① 정보주체 통제권 보장, ② 최소 전송, ③ 책임 명확화, ④ 전 과정 안전성 확보, ⑤ 추적 가능성
핵심 통제 영역관리적(책임자 지정·내부관리계획) + 기술적(접근통제·암호화·전송보안) + 물리적(시설·재해 대비)

Ⅱ. 가. 전송대상 개인정보 보호책임자의 지정​

1. 지정의 필요성​

   [왜 별도의 책임 체계가 필요한가]

   마이데이터는 **여러 기관이 관여**하는 구조
        │  · 정보제공자 : "우리는 요구에 따라 보냈을 뿐"
        │  · 정보수신자 : "우리는 받은 것뿐"
        │  · 중계기관   : "우리는 전달만 했을 뿐"
        ▼
   사고 발생 시 **책임 소재 불명확 → 대응 지연 → 피해 확대**
        ▼
   ⇒ **각 주체별로 책임자를 명확히 지정**하고
      **권한·역할·상호 협력 체계**를 사전에 규정해야 함

2. 개인정보 보호책임자(CPO)의 지정​

항목내용
법적 근거개인정보보호법 제31조(개인정보 보호책임자의 지정), 시행령 제32조
지정 의무개인정보처리자는 CPO를 지정해야 하며, 마이데이터 참여 기관은 전송 업무를 포함한 책임 범위를 명확히 해야 함
지정 요건· 사업주 또는 대표자, 또는
· 임원(임원이 없는 경우 개인정보 처리 관련 업무 담당 부서의 장)
· 일정 요건 기관은 독립성·전문성 요건(경력 등) 충족 필요
독립성 보장· 업무 수행 시 부당한 지시를 받지 않도록 보장
· 대표자·이사회에 직접 보고할 수 있는 체계
· 업무 수행을 이유로 불이익 금지
자격·전문성개인정보 보호 관련 경력·지식 보유, 지속적 교육

3. 마이데이터 전송 관련 CPO의 역할​

역할세부 내용
① 전송 업무 총괄· 전송요구 접수 → 본인확인 → 전송 → 이력관리 전 과정 관리·감독
· 전송 대상 정보의 범위 적정성 확인(최소 전송 원칙)
② 내부관리계획 수립·시행· 전송 업무를 포함한 개인정보 내부관리계획 수립
· 전송 관련 세부 절차·기준 문서화
· 연 1회 이상 이행 여부 점검
③ 안전조치 이행 점검· 접근권한·암호화·접속기록 등 안전성 확보조치 준수 여부 점검
· 전송 API의 보안 취약점 점검 확인
④ 실태 점검·개선· 개인정보 처리 실태 정기 조사
· 위반 사항 발견 시 즉시 개선 조치
⑤ 정보주체 권리 보장· 전송요구·철회·열람 등 권리 행사 창구 운영
· 고충 처리 및 피해 구제
⑥ 침해사고 대응· 유출·오전송 발생 시 신고(개인정보보호위원회·KISA)·통지 총괄
· 72시간 이내 신고 등 법정 절차 이행
⑦ 교육전송 업무 담당자 대상 정기 개인정보 보호 교육
⑧ 기관 간 협력· 정보제공자–수신자–중계기관 간 책임 범위 협의·문서화
· 사고 시 공동 대응 체계 구축

4. 담당자 지정 및 책임 체계​

   [**책임 체계의 계층 구조**]

   **[대표자·경영진]** ── 최종 책임, 자원 지원
        ▼
   **[개인정보 보호책임자(CPO)]** ── 총괄·감독, 독립적 보고 권한
        ▼
   **[전송 업무 담당 부서·담당자]**
        ├─ **전송요구 접수·본인확인 담당**
        ├─ **전송 시스템 운영·보안 담당**
        ├─ **접근권한 관리 담당**
        └─ **접속기록 점검 담당**
        ▼
   **[개인정보취급자]** ── 최소 인원 지정, **취급자 목록 관리**

   ※ **직무 분리** : 권한 부여자 ≠ 시스템 운영자 ≠ 로그 점검자
   ※ 각 담당자의 **역할·책임(R&R)을 내부관리계획에 명시**
관리 항목내용
개인정보취급자 지정전송 업무 수행에 필요한 최소 인원만 지정, 목록 작성·관리
책임 명문화담당자별 역할·권한·책임을 문서화, 보안서약서 징구
인사 변동 관리담당자 변경·퇴직 시 즉시 권한 회수 및 인수인계
기관 간 계약정보제공자–수신자–중계기관 간 책임 범위·사고 시 조치를 계약·협약에 명시

Ⅲ. 나. 전송대상 개인정보처리시스템의 접근 관리​

1. 접근 관리 체계​

 ┌────────── **마이데이터 전송 시스템 접근 통제 계층** ──────────┐
 │                                                               │
 │  **① 계정·권한 관리** — 누구에게 무엇을 허용할 것인가          │
 │  **② 인증 강화**      — 정말 본인인가                          │
 │  **③ 접근 경로 통제** — 어디서 접근할 수 있는가                │
 │  **④ 전송 구간 보안** — API·네트워크 보호                      │
 │  **⑤ 접속기록 관리**  — 무엇을 했는지 추적 가능한가            │
 │  **⑥ 정기 점검**      — 통제가 실제로 작동하는가               │
 └───────────────────────────────────────────────────────────────┘

2. 계정 및 접근권한 관리​

항목내용
최소 권한 원칙· 업무 수행에 필요한 최소한의 권한만 부여
· 전송 대상 정보 범위를 직무별로 차등 부여
계정 발급· 개인별 고유 계정 발급, 공용 계정 사용 금지
· 계정 발급·변경·말소 시 책임자 승인 및 기록 보관
권한 부여·변경·말소· 신청 → 승인 → 부여 절차 문서화
· 인사이동·퇴직 시 지체 없이 권한 변경·회수
· 권한 부여 내역 최소 3년 보관
정기 검토접근권한의 적정성을 정기 점검(과다 권한·미사용 계정 회수)
특권 계정 관리시스템 관리자·DBA 계정 별도 통제, 사용 시 승인·기록

3. 인증 및 접근 경로 통제​

항목내용
비밀번호 정책· 복잡도 기준(문자 종류·길이) 적용
· 정기적 변경, 일정 횟수 실패 시 계정 잠금
다중 인증(MFA)· 외부 접속·관리자 접속 시 안전한 인증수단 적용
· OTP·인증서·생체 등 2가지 이상 요소
외부 접속 통제· VPN 등 안전한 접속수단을 통해서만 접근 허용
· 인터넷을 통한 직접 접속 차단
IP 접근 제한· 허용된 IP 대역에서만 접속 가능하도록 제한
· 정보제공자–수신자 간 상호 IP 화이트리스트
접속 시간 제한업무 시간 외 접속 제한, 일정 시간 미사용 시 자동 로그아웃
망 분리·분리 환경개인정보처리시스템은 업무망과 분리, 인터넷망 직접 연결 차단
물리적 접근 통제전산실 출입통제·출입기록 관리, CCTV

4. 전송 구간(API) 보안​

   [**API 전송 보안 통제 흐름**]

   [정보수신자]                              [정보제공자]
        │  ① **전송요구 및 본인확인**             │
        │     - 정보주체의 **명확한 동의·요구**    │
        │     - **안전한 본인확인 수단**           │
        ▼                                        │
   ② **기관 인증** ──── 상호 인증(mTLS·인증서) ──▶│
        │              **API 키·토큰**(OAuth 2.0) │
        │              ※ **접근토큰 유효기간 제한**│
        ▼                                        ▼
   ③ **전송 요청** ─── **HTTPS(TLS 1.2 이상)** ──▶│
        │                                        │ ④ **권한 검증**
        │                                        │   - 전송 범위 확인
        │                                        │   - **최소 전송 원칙**
        ◀──── ⑤ **암호화된 데이터 전송** ─────────│
        │                                        │
   ⑥ **양측 모두 접속기록 생성·보관**            ⑥
항목내용
전송 구간 암호화· TLS 1.2 이상을 적용한 HTTPS 전송 의무
· 안전한 암호 알고리즘·키 길이 적용(취약 알고리즘 금지)
상호 인증정보제공자–수신자 간 기관 인증(인증서·mTLS), 위장 전송 방지
API 인증·인가· OAuth 2.0 등 표준 인가 체계 활용
· 접근토큰의 유효기간 제한·주기적 갱신
· 토큰 탈취 대비 폐기 절차
전송 범위 검증전송요구서에 명시된 항목·기간에 한정하여 전송(과다 전송 금지)
본인확인 강화· 정보주체 본인 여부를 안전한 수단으로 확인
· 오전송(타인 정보 전송) 방지가 최우선
API 보안 점검취약점 진단, 비정상 호출 탐지(Rate Limit·이상 패턴), 로그 모니터링
저장 시 암호화전송받은 개인정보 저장 시 고유식별정보·비밀번호 등 암호화

5. 접속기록 관리​

항목내용
기록 항목계정, 접속일시, 접속지 정보(IP), 처리한 정보주체 정보, 수행 업무(조회·전송·수정·삭제 등)
보관 기간최소 1년 이상
· 5만 명 이상 정보주체의 개인정보 처리, 고유식별정보·민감정보 처리, 기간통신사업자의 경우 최소 2년 이상
정기 점검월 1회 이상 접속기록 점검 — 비정상 접속·대량 조회·권한 외 접근 확인
위·변조 방지접속기록의 위조·변조·도난·분실 방지 조치(별도 저장소·무결성 검증·백업)
이상행위 탐지대량 다운로드·심야 접속·비정상 IP 등 자동 탐지·경보 체계

Ⅳ. 다. 전송대상 개인정보관리 및 재해·재난 대비 조치​

1. 전송대상 개인정보의 관리​

■ 개인정보 생애주기별 관리​

   ① **수집·보유** ── 전송에 필요한 **최소 항목**만
        ▼
   ② **전송요구 접수** ── 정보주체 확인, 요구 내역 기록
        ▼
   ③ **전송** ── 암호화 전송, **전송 이력 기록**
        ▼
   ④ **보관** ── 암호화 저장, 접근통제, **보유기간 설정**
        ▼
   ⑤ **파기** ── 목적 달성·보유기간 경과 시 **지체 없이 파기**
                 (복구 불가능한 방법, **파기 기록 보관**)
관리 항목내용
최소 수집·전송 원칙· 전송요구 범위에 한정하여 최소한으로 전송
· 목적에 불필요한 항목 수집·보관 금지
목적 외 이용 금지전송받은 개인정보를 동의받은 목적 외로 이용·제공 금지
암호화· 고유식별정보·비밀번호·바이오정보 등 저장 시 암호화
· 전송 시 전송 구간 암호화
· 암호키 안전 관리(별도 보관·접근통제·주기적 변경)
보유기간 관리· 항목별 보유기간 설정 및 관리
· 보유기간 경과 시 자동 파기 체계
파기· 복원 불가능한 방법으로 파기(완전 삭제·물리적 파괴)
· 파기 사실·방법·시점 기록 보관
전송 이력 관리· 누구에게·언제·무엇을 전송했는지 이력 기록
· 정보주체가 자신의 전송 내역을 확인할 수 있도록 제공
정보주체 통지전송 사실·내역의 통지, 전송요구 철회 시 즉시 중단
위탁·제3자 제공 관리처리 위탁 시 위탁계약·수탁자 관리·감독
악성프로그램 대응백신 설치·자동 업데이트, 보안 패치 적용

2. 재해·재난 대비 조치​

   [**재해·재난 대비의 목적**]

   개인정보 안전성 = **기밀성 + 무결성 + 가용성**
        │
        │  화재·지진·수해·정전·시스템 장애·**랜섬웨어**
        ▼
   · **개인정보의 멸실·훼손** → 정보주체 권리 침해, 서비스 불가
   · **전송 서비스 중단** → 마이데이터 생태계 전체 영향
        ▼
   ⇒ **위기대응 매뉴얼 + 백업·복구 체계**로 **가용성·무결성 확보**
   ※ 근거 : **개인정보의 안전성 확보조치 기준** 제11조(재해·재난 대비 안전조치)

■ 세부 조치 사항​

구분조치 내용
① 위기대응 매뉴얼 마련· 화재·홍수·단전 등 재해·재난 발생 시 대응 절차 수립
· 개인정보처리시스템 보호를 위한 조치 절차 문서화
· 비상연락체계, 역할·책임(R&R) 명시
· 정기적인 점검·모의 훈련 실시
② 백업 및 복구 계획· 개인정보 및 시스템의 정기 백업(백업 주기·범위·방법 정의)
· 백업 데이터의 암호화 저장
· 원격지·물리적 분리 장소 보관(동일 재해권 회피)
· 복구 절차 수립 및 정기 복구 시험(복구 가능 여부 실증)
· RTO/RPO 목표 설정
③ 이중화·가용성 확보· 개인정보처리시스템·전송 API 서버 이중화
· 네트워크·전원(UPS·비상발전) 이중화
· 필요 시 재해복구시스템(DRS) 구축
④ 물리적 보호· 전산실 소방설비·항온항습·누수 감지
· 출입통제, 침수 대비 위치 선정
⑤ 랜섬웨어 대비· 불변 백업(Immutable Backup), 오프라인·망분리 백업
· 3-2-1 백업 원칙(3벌·2매체·1오프사이트)
· 백업 데이터의 감염 여부 검증
⑥ 침해사고 대응· 유출 인지 시 정보주체 통지 및 개인정보보호위원회·KISA 신고
· 법정 기한 준수(인지 후 72시간 이내)
· 피해 최소화 조치, 원인 분석·재발 방지 대책
⑦ 서비스 연속성· 전송 서비스 중단 시 정보주체 안내 절차
· 기관 간 공동 대응·복구 협력 체계
⑧ 점검·개선· 대응 체계의 정기 점검(연 1회 이상)
· 훈련 결과를 매뉴얼에 환류
   [**백업·복구 체계 설계**]

   **원본 시스템**(운영)                **백업 저장소**
   ┌──────────────┐                  ┌──────────────┐
   │ 개인정보 DB   │──정기 백업──────▶│ **암호화 백업** │
   │ 전송 API 로그 │  (일/주 단위)     │ 접근통제 적용  │
   └──────────────┘                  └──────┬───────┘
          │                                  │ **원격지 보관**
          │ 재해 발생                        ▼
          ▼                          ┌──────────────┐
   **서비스 중단**  ◀── 복구 ─────────│ **원격 백업지** │
                    (RTO 내)          │ (물리적 분리)  │
                                      └──────────────┘
   ※ **복구 시험을 하지 않은 백업은 백업이 아니다** → 정기 복구 훈련 필수

Ⅴ. 종합 및 고려사항​

1. 3대 영역의 통합적 관계​

   ┌─── **가. 책임자 지정**(관리적 통제) ───┐
   │  "**누가 책임지고 관리하는가**"          │
   │   → 모든 통제의 **거버넌스 기반**        │
   └────────────────┬───────────────────────┘
                    ▼
   ┌─── **나. 접근 관리**(기술적 통제) ─────┐
   │  "**권한 없는 자의 접근을 막는가**"      │
   │   → 유출 **예방**(Prevention)            │
   └────────────────┬───────────────────────┘
                    ▼
   ┌─── **다. 관리·재해 대비**(복원력) ─────┐
   │  "**사고가 나도 데이터를 지키는가**"     │
   │   → 무결성·**가용성 확보**(Recovery)     │
   └─────────────────────────────────────────┘

   ⇒ **예방(접근통제)만으로는 부족** — 책임 체계와 복구 체계가 함께 필요

2. 고려사항​

고려사항내용
① 오전송 방지가 최우선마이데이터 최대 위험은 해킹이 아니라 본인확인 오류로 인한 타인 정보 전송 → 본인확인 절차의 이중 검증
② 책임 범위의 사전 합의정보제공자–수신자–중계기관 간 계약·협약으로 책임 범위 명문화 — 사고 후 협의는 불가능
③ 최소 전송 원칙의 실질화"전송 가능하니 다 보낸다"가 아니라 요구 범위에 엄격히 한정
④ API 보안이 핵심 공격면상시 개방 API → 취약점 진단·이상 호출 탐지·토큰 관리 상시화
⑤ 접속기록의 실효성기록만 하고 점검하지 않으면 무의미 → 월 1회 이상 점검 의무 이행, 자동 분석
⑥ 복구 시험의 필수성백업은 있으나 복구를 한 번도 해보지 않은 사례 다수 → 정기 복구 훈련
⑦ 정보주체 통제권 실질 보장전송 내역 조회·철회를 쉽게 — 다크패턴 금지, 철회 즉시 반영
⑧ 제도 정합성개인정보보호법·안전성 확보조치 기준·신용정보법(금융 마이데이터), ISMS-P 인증과 연계

Ⅵ. 결론​

마이데이터는 정보주체의 데이터 주권을 실현하는 제도인 동시에, 개인정보가 기관 간에 상시·대량으로 이동하게 만드는 구조적 위험을 수반한다. 「마이데이터 전송 보안 안내서」는 이 위험을 관리적·기술적·물리적 통제로 체계화한 실무 기준이다.

세 영역은 각기 다른 역할을 수행한다. ① 개인정보 보호책임자의 지정은 거버넌스의 기반으로, 다자간 참여 구조에서 책임 소재를 명확히 하고 독립적 감독 권한을 보장한다. ② 접근 관리는 예방적 통제로, 최소 권한·MFA·IP 제한·전송 구간 암호화·접속기록을 통해 권한 없는 접근과 과다 전송을 차단한다. ③ 개인정보 관리와 재해·재난 대비는 복원력으로, 최소 전송·암호화·파기와 함께 백업·복구·이중화를 통해 가용성과 무결성을 지킨다.

실무적으로 가장 유의해야 할 점은 세 가지이다. 첫째, 마이데이터의 최대 위험은 외부 해킹이 아니라 본인확인 오류로 인한 오전송이다. 아무리 강력한 암호화를 적용해도 엉뚱한 사람에게 정확하게 전송하면 그것이 곧 유출이므로, 본인확인 절차의 신뢰성이 최우선 통제점이 된다. 둘째, 다자간 구조에서 책임 범위를 사전에 계약으로 명문화해야 한다. 사고가 발생한 뒤에 책임을 협의하는 것은 불가능하다. 셋째, 접속기록과 백업은 "만드는 것"이 아니라 "점검하고 복구해 보는 것" 이 실효성의 기준이다. 월 1회 이상의 접속기록 점검과 정기적인 복구 시험이 이루어지지 않으면, 형식적 준수에 그칠 뿐 실제 사고에는 무력하다.

궁극적으로 마이데이터 전송 보안은 규제 준수 비용이 아니라 서비스의 신뢰 기반이다. 한 번의 대규모 오전송이나 유출은 개별 기관을 넘어 마이데이터 생태계 전체에 대한 국민 신뢰를 훼손하므로, 참여 기관 모두가 공동 책임 의식을 갖고 통제 수준을 상향 평준화하는 것이 제도의 지속 가능성을 결정한다.
