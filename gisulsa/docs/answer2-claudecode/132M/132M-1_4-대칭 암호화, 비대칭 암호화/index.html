대칭 암호화, 비대칭 암호화

문제​

4.대칭 암호화와 비대칭 암호화

Ⅰ. 개요​

암호화는 키의 사용 방식에 따라 대칭키 암호(관용 암호) 와 비대칭키 암호(공개키 암호) 로 구분된다. 두 방식은 대체 관계가 아니라 속도와 키 분배라는 서로 다른 문제를 해결하는 상호 보완 관계이다.

   [핵심 차이 — 키의 구조]

   **대칭 암호**                        **비대칭 암호**
   ┌──────┐   같은 키 K   ┌──────┐    ┌──────┐  공개키/개인키 쌍  ┌──────┐
   │ 송신 │──암호화──▶──복호화──│ 수신 │    │ 송신 │──**수신자 공개키**──▶│ 수신 │
   └──────┘               └──────┘    └──────┘   **수신자 개인키**  └──────┘
      ▲                       ▲                        로 복호화
      └── **사전에 키 공유 필요** ──┘        └── **공개키는 공개해도 안전** ──┘
          = **키 분배 문제** ✕                    = 키 분배 문제 해결 ○

Ⅱ. 대칭 암호화 (Symmetric Encryption)​

1. 개념 및 원리​

암호화와 복호화에 동일한 비밀키를 사용하는 방식으로, 혼돈(Confusion)과 확산(Diffusion) 원리에 기반한 치환·전치 연산의 반복으로 구성된다.

유형내용알고리즘
블록 암호고정 크기 블록 단위 암호화(64·128비트)AES, SEED·ARIA·LEA(국산), 3DES, Blowfish
스트림 암호비트·바이트 단위 실시간 암호화ChaCha20, RC4(취약), A5/1
블록 암호 운용 모드특징
ECB블록 독립 암호화 — 동일 평문 → 동일 암호문 → 사용 금지
CBC이전 암호문과 XOR — 패턴 은닉, 순차 처리
CTR카운터 암호화 후 XOR — 병렬 처리 가능
GCM(권장)CTR + 인증 태그 — 기밀성 + 무결성 동시 제공(AEAD)

2. 특징​

구분내용
장점· 연산 속도 매우 빠름 — 비대칭 대비 수백~수천 배
· 대용량 데이터 암호화에 적합
· 키 길이가 짧아도 높은 안전성(AES-128 ≈ RSA-3072)
단점· 키 분배 문제 — 사전에 안전하게 키를 공유해야 함
· 키 관리 부담 — n명이 서로 통신 시 n(n−1)/2 개의 키 필요
· 부인방지 불가 — 양측이 같은 키를 가지므로 송신자 특정 불가

Ⅲ. 비대칭 암호화 (Asymmetric Encryption)​

1. 개념 및 원리​

수학적으로 연관된 공개키·개인키 쌍을 사용하며, 한쪽으로 암호화한 것은 다른 쪽으로만 복호화된다. 일방향 함수(소인수분해·이산대수·타원곡선)의 계산 비대칭성에 안전성의 근거를 둔다.

   [**두 가지 용도** — 어떤 키로 암호화하는가에 따라 목적이 달라짐]

   **① 기밀성 확보**(암호화)
   송신자 ──[**수신자의 공개키**로 암호화]──▶ 수신자 ──[**수신자 개인키**로 복호화]
   ⇒ **수신자만 열 수 있음**

   **② 인증·부인방지**(전자서명)
   송신자 ──[**송신자의 개인키**로 서명]──▶ 수신자 ──[**송신자 공개키**로 검증]
   ⇒ **송신자만 만들 수 있음** → 신원 확인·부인방지
알고리즘기반 문제용도·특징
RSA소인수분해암호화·서명 모두 가능, 2048비트 이상 권장
ECC / ECDSA타원곡선 이산대수짧은 키로 동등 안전성(256비트 ≈ RSA-3072) → 모바일·IoT 적합
Diffie-Hellman / ECDHE이산대수키 교환 전용, PFS(전방위 안전성) 제공
ElGamal이산대수암호화·서명
DSA / KCDSA이산대수전자서명 전용(국산 KCDSA)
PQC(ML-KEM, ML-DSA)격자 문제양자내성 — 향후 전환 대상

2. 특징​

구분내용
장점· 키 분배 문제 해결 — 공개키는 공개해도 안전
· 키 개수 감소 — n명 통신 시 2n 개만 필요
· 전자서명 → 인증·무결성·부인방지 제공
· PKI 기반 신뢰 체계 구축 가능
단점· 연산 속도 매우 느림 → 대용량 데이터 부적합
· 키 길이가 길어 오버헤드 큼
· 공개키 진위 확인 필요 → 인증서(CA) 인프라 필수
· 중간자 공격(MITM) 위험 — 공개키 위조 시 무력화
· 양자컴퓨팅(Shor 알고리즘)에 취약

Ⅳ. 두 방식의 비교 및 결합 활용​

1. 종합 비교​

비교 기준대칭 암호화비대칭 암호화
키 구조단일 비밀키(양측 공유)공개키 + 개인키 쌍
키 분배어려움(사전 공유 필요)용이(공개키 배포)
필요 키 개수(n명)n(n−1)/22n
연산 속도매우 빠름느림(수백~수천 배)
적합 데이터대용량소량(키·해시값)
제공 보안 서비스기밀성기밀성 + 인증·부인방지
부인방지불가가능(전자서명)
키 길이(동등 안전성)AES-128RSA-3072 / ECC-256
주요 용도데이터·디스크·DB 암호화, 통신 구간 암호화키 교환·전자서명·인증서
대표 알고리즘AES, SEED, ARIA, LEA, ChaCha20RSA, ECC, DH, ElGamal

2. 하이브리드 방식 — 실무의 표준​

   [**전자봉투 / TLS의 기본 구조**]

   ① **세션키(대칭키) 생성** ── 1회용 난수 키 K
   ② **원문 암호화** ────── **K로 대칭 암호화**(고속 처리)  ← 대칭의 장점
   ③ **세션키 암호화** ──── **수신자 공개키로 K를 암호화**   ← 비대칭의 장점
   ④ **전송** ───────── [암호문 + 암호화된 K]
   ⑤ **수신자** ─────── 개인키로 K 복원 → K로 원문 복호화

   ⇒ **속도(대칭) + 안전한 키 분배(비대칭)** 를 모두 확보
   ⇒ 적용 : **TLS/HTTPS**, S/MIME, PGP, **전자봉투**, VPN(IPSec)
결합 요소담당
대칭 암호(AES-GCM)실제 데이터 암호화 — 기밀성·성능
비대칭 암호(ECDHE)세션키 교환 — 키 분배·PFS
비대칭 서명(RSA/ECDSA)서버 인증서 검증 — 인증·부인방지
해시(SHA-256)무결성 검증

Ⅴ. 결론​

대칭 암호화와 비대칭 암호화의 차이는 결국 "속도"와 "키 분배"의 상충으로 요약된다. 대칭 암호는 빠르지만 키를 안전하게 나눠 가질 방법이 없고, 비대칭 암호는 키 분배를 해결하지만 느리다. 따라서 실무에서는 두 방식을 배타적으로 선택하지 않고, 하이브리드(전자봉투) 방식으로 결합하여 사용하는 것이 사실상의 표준이다.

또한 두 방식은 제공하는 보안 서비스 자체가 다르다는 점이 중요하다. 대칭 암호는 기밀성만 제공하는 반면, 비대칭 암호는 전자서명을 통해 인증·무결성·부인방지까지 제공하므로, 전자계약·전자문서 유통에서는 비대칭 암호가 필수이다.

향후 과제는 양자내성이다. Shor 알고리즘은 소인수분해와 이산대수를 다항 시간에 해결하므로 RSA·ECC 등 비대칭 암호가 근본적으로 위협받는 반면, 대칭 암호는 Grover 알고리즘에 의해 실효 키 길이가 절반으로 감소하는 수준에 그친다. 따라서 ① 대칭 암호는 AES-256으로 상향, ② 비대칭 암호는 PQC(ML-KEM·ML-DSA)로 단계적 전환하는 것이 실무적 대응 방향이며, 전환기에는 기존 알고리즘과 PQC를 병용하는 하이브리드 방식이 권고된다.
