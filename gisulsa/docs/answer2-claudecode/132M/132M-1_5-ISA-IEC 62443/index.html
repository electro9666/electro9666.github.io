ISA/IEC 62443

문제​

5.ISA/IEC 62443

Ⅰ. 개요​

ISA/IEC 62443은 산업제어시스템(ICS)·운영기술(OT) 환경의 사이버보안 국제표준으로, 제품 개발자·시스템 통합자·자산 소유자 각 주체의 보안 요구사항을 체계적으로 규정한다.

   [등장 배경 — IT 보안으로는 OT를 지킬 수 없다]
   과거 : 제어망은 **물리적으로 폐쇄(Air-gap)** → 보안 불필요 인식
        ▼
   **스마트팩토리·IIoT** 확산 → **IT-OT 융합**, 원격 유지보수 연결
   **Stuxnet**(2010) 이후 제어시스템 겨냥 공격 현실화
        ▼
   [문제] IT 보안 관행을 OT에 그대로 적용 불가
   · **가용성 최우선**(IT는 기밀성 우선) — 공정 중단 = 막대한 손실·인명 위험
   · **패치·재기동 곤란**(24×365 가동), 레거시 장비 수명 20년 이상
        ▼
   [**ISA/IEC 62443**] OT 특성을 반영한 **전주기·전주체 보안 표준**
   근거·연계 : **정보통신기반보호법**(주요정보통신기반시설), NIST SP 800-82,
              **N2SF**, 산업부·과기정통부 OT 보안 가이드

Ⅱ. IT 보안과 OT 보안의 차이​

비교 기준IT 보안OT 보안
우선순위기밀성 → 무결성 → 가용성(C-I-A)가용성 → 무결성 → 기밀성(A-I-C)
최우선 목표정보 유출 방지공정 중단·인명 사고 방지(HSE)
가동 요구계획 정지 가능24×365 무중단
패치신속 적용정지 곤란 → 보상 통제 필요
장비 수명3~5년10~20년 이상(레거시 다수)
프로토콜TCP/IP 표준Modbus·DNP3·PROFINET 등 인증·암호화 미지원
실시간성초 단위 허용밀리초 단위 결정성 요구

Ⅲ. ISA/IEC 62443의 구조​

 ┌─── **Part 1. 일반**(General) ────────────────────────────────┐
 │  1-1 용어·개념·모델                                          │
 ├─── **Part 2. 정책·절차**(Policies & Procedures) ─────────────┤
 │  **2-1 자산 소유자의 보안 프로그램(IACS 보안관리체계)**       │
 │  2-3 패치 관리 / 2-4 **서비스 제공자(SI) 요구사항**           │
 ├─── **Part 3. 시스템**(System) ───────────────────────────────┤
 │  3-2 **위험평가 및 시스템 설계 — 존/컨듀잇, SL 결정**         │
 │  3-3 **시스템 보안 요구사항 및 보안수준(FR 7개)**             │
 ├─── **Part 4. 컴포넌트**(Component) ──────────────────────────┤
 │  4-1 **제품 개발 보안 생애주기(SDL)**                         │
 │  4-2 **컴포넌트 기술 보안 요구사항**                          │
 └───────────────────────────────────────────────────────────────┘

   [**적용 주체별 매핑**]
   **자산 소유자**(운영기업) → Part **2-1**, 3-2
   **시스템 통합자**(SI)     → Part **2-4**, 3-3
   **제품 공급자**(벤더)     → Part **4-1**, 4-2

Ⅳ. 핵심 개념​

1. 존(Zone)과 컨듀잇(Conduit)​

   [**네트워크 분할(Segmentation)** — 62443의 핵심 설계 원리]

   ┌─ **Level 4~5 : 기업망(IT)** ─── ERP·인터넷 ──────────────┐
   │            ║ **컨듀잇**(방화벽·단방향 게이트웨이)         │
   ├─ **Level 3.5 : DMZ** ── 데이터 히스토리안·패치 서버 ─────┤
   │            ║ **컨듀잇**                                   │
   ├─ **Level 3 : 운영 관리(OT)** ── MES·SCADA 서버 ──────────┤
   │            ║                                              │
   ├─ **Level 2 : 감시 제어** ── HMI·엔지니어링 워크스테이션 ─┤
   ├─ **Level 1 : 기본 제어** ── **PLC·DCS·RTU** ─────────────┤
   ├─ **Level 0 : 현장 장치** ── 센서·액추에이터 ─────────────┤
   └───────────────────────────────────────────────────────────┘
        ※ **Purdue 모델** 기반 계층 구조

   **존(Zone)**    : 동일한 보안 요구사항을 갖는 **자산의 논리적 그룹**
   **컨듀잇(Conduit)** : 존 간 **통신 경로** — 여기에 **보안 통제를 집중**
   ⇒ 침해 발생 시 **다른 존으로의 확산 차단**(피해 국지화)

2. 보안수준 (SL: Security Level)​

수준방어 대상 공격자특성
SL 0특별한 요구사항 없음—
SL 1우연한·비의도적 침해실수·오조작 방지
SL 2낮은 자원·일반적 기술의 의도적 공격단순 해커
SL 3중간 자원·ICS 전문 기술 보유 공격전문 해커·조직
SL 4막대한 자원·고도 기술(국가 지원)APT·국가 배후

SL-T(목표) → SL-C(제품·시스템 능력) → SL-A(실제 달성) — 위험평가로 존별 SL-T를 정하고, 이를 충족하는 제품·설계를 선택한다.

3. 7대 기본 요구사항 (FR: Foundational Requirements)​

FR요구사항내용
FR 1식별 및 인증 제어(IAC)사용자·기기·소프트웨어 프로세스 식별·인증
FR 2사용 제어(UC)인가된 권한 범위 내 사용 통제, 최소 권한
FR 3시스템 무결성(SI)데이터·소프트웨어 위·변조 방지, 악성코드 대응
FR 4데이터 기밀성(DC)정보 유출 방지, 암호화
FR 5제한된 데이터 흐름(RDF)존/컨듀잇 기반 분할, 불필요 통신 차단
FR 6사건에 대한 적시 대응(TRE)이벤트 로깅·모니터링·침해 대응
FR 7자원 가용성(RA)DoS 대응·백업·복구 — OT의 최우선 요구

Ⅴ. 적용 절차 및 고려사항​

   ① **자산 식별**(Asset Inventory) — 제어 장비·네트워크·SW 목록화
        ▼  ※ OT는 자산 파악 자체가 어려움 → **수동적 자산 탐지** 활용
   ② **초기 위험평가** — 고수준 위협·영향(HSE·생산 중단) 분석
        ▼
   ③ **존/컨듀잇 설계** — 기능·위험 기준 분할, 통신 경로 정의
        ▼
   ④ **존별 목표 보안수준(SL-T) 결정**
        ▼
   ⑤ **상세 위험평가** — 잔여 위험 식별
        ▼
   ⑥ **보안 요구사항 도출·설계·구축** — FR 1~7 기반 통제 적용
        ▼
   ⑦ **운영·유지관리** — 패치·모니터링·사고 대응·교육
        ▼
   ⑧ **정기 재평가** — 설비 변경 시 재검증(PDCA)
고려사항내용
① 가용성 최우선보안 통제가 공정을 중단시키면 안 됨 → 차단(Prevention)보다 탐지(Detection) 우선, 수동 모니터링
② 패치 곤란 대응정지 불가 설비 → 보상 통제(망 분리·화이트리스트·가상 패치)
③ 레거시 장비인증·암호화 미지원 프로토콜 → 컨듀잇에 보안 게이트웨이 배치
④ 원격 유지보수벤더 원격 접속이 최대 침투 경로 → PAM·일회성 승인·세션 녹화
⑤ 이동 매체 통제USB를 통한 감염(Stuxnet) → 매체 통제·검역 키오스크
⑥ IT-OT 협업보안 우선순위가 다름 → 공동 거버넌스·역할 정의
⑦ 공급망 보안제품 공급자에 62443-4-1/4-2 인증 요구, SBOM 확보
⑧ 인증 제도제품 IEC 62443-4-2 인증, 조직 62443-2-1 인증(ISASecure 등)

Ⅵ. 결론​

ISA/IEC 62443은 "IT 보안 관행을 그대로 OT에 적용할 수 없다" 는 문제의식에서 출발한 표준으로, 가용성과 안전(HSE)을 최우선으로 하는 산업제어 환경의 특수성을 반영한다. 그 핵심 설계 원리는 존과 컨듀잇을 통한 네트워크 분할이며, 이는 침해를 완전히 막을 수 없다는 전제 하에 피해를 국지화하는 현실적 접근이다.

또한 이 표준의 중요한 특징은 자산 소유자·시스템 통합자·제품 공급자 각각의 책임을 분리 규정했다는 점이다. OT 보안은 운영 기업 혼자 달성할 수 없으며, 제품 단계의 보안 개발(4-1)과 통합 단계의 보안 설계(2-4) 가 함께 이루어져야 한다. 따라서 실무적으로는 설비 조달 시 62443-4-2 인증 제품을 요구하는 것이 가장 효과적인 출발점이 된다.

국내에서도 주요정보통신기반시설 보호와 스마트팩토리 확산에 따라 OT 보안 요구가 커지고 있다. 적용 시 유의할 점은 위험평가로 존별 목표 보안수준(SL-T)을 차등 설정하여, 모든 구간에 동일 통제를 적용하는 과투자를 피하고 핵심 제어 구간(Level 0~1)에 자원을 집중하는 것이다.
