TF-IDF 계산

문제​

3.다음과 같이 형태소 분석을 통하여 문서별로 단어의 횟수가 식별되었다.각 문서의 TFIDF(Term Frequency Inverse Document Frequency)를 식별하기 위한 계산 과정과 그 결과를 설명하시오.
(단, Inverse Document Frequency 계산시 log 를 취하여 구하되 Document Frequency 값을 임의로 가공하지 않아야 하며, 주어진 10g 값만을 활용한다.)

[답안 작성 전제] 본 문제는 문서별 단어 출현 횟수 표와 주어진 log 값이 제시되는 계산형 문항이나, 본 문제 파일에는 해당 표가 포함되어 있지 않다. 따라서 아래에서는 ① TF-IDF의 일반적 계산 절차와 산식을 제시하고, ② 대표적 형태의 예시 데이터를 가정하여 전체 계산 과정을 완결적으로 시연한다. 실제 시험에서는 주어진 표의 수치와 log 값을 그대로 대입하면 동일한 절차로 답안을 완성할 수 있다.

Ⅰ. 개요​

1. TF-IDF의 개념​

TF-IDF(Term Frequency – Inverse Document Frequency) 는 문서 집합에서 특정 단어가 특정 문서를 얼마나 잘 대표하는가(중요도) 를 수치화하는 단어 가중치 산정 기법이다.

   [등장 배경 — 단순 빈도(TF)만 쓸 때의 문제]

   문서에서 가장 많이 나오는 단어는?
        │  "그리고", "있다", "**데이터**"(전 문서에 공통 출현)
        ▼
   · **모든 문서에 흔한 단어는 변별력이 없음**
   · 빈도만으로는 **문서의 특징을 대표하는 단어를 찾을 수 없음**
        ▼
   [**TF-IDF의 착안**]
   "**이 문서에는 자주 나오지만(TF↑),
     다른 문서에는 잘 안 나오는(DF↓) 단어가 중요하다**"
        ▼
   **TF-IDF = TF × IDF**
   ⇒ 흔한 단어는 **IDF가 0에 수렴하여 자동으로 제거**

2. 구성 요소​

구성명칭의미
TF(Term Frequency)단어 빈도특정 문서 내에서 해당 단어가 출현한 횟수 → 클수록 그 문서에서 중요
DF(Document Frequency)문서 빈도전체 문서 중 해당 단어가 출현한 문서의 수 → 클수록 흔한 단어
IDF(Inverse DF)역문서 빈도DF의 역수에 log를 취한 값 → 희소할수록 큰 값(변별력)
N전체 문서 수문서 집합의 크기

Ⅱ. 계산 산식​

1. 기본 산식​

   ┌───────────────────────────────────────────────────────────┐
   │                                                           │
   │  **TF(t, d)**  = 문서 d에서 단어 t의 **출현 횟수**          │
   │                                                           │
   │  **DF(t)**     = 단어 t가 출현한 **문서의 개수**            │
   │                                                           │
   │  **IDF(t)**    = **log ( N / DF(t) )**                     │
   │                       N : 전체 문서 수                     │
   │                                                           │
   │  **TF-IDF(t, d) = TF(t, d) × IDF(t)**                      │
   │                                                           │
   └───────────────────────────────────────────────────────────┘

2. 문제 조건의 해석 (중요)​

조건의미
"log를 취하여 구하되"IDF = log(N / DF) 형태를 사용
"DF 값을 임의로 가공하지 않아야 하며"· 스무딩(Smoothing)을 적용하지 말 것
· 즉 log(N / (1 + DF)) 나 log(N/DF) + 1 같은 변형 공식 사용 금지
· DF를 있는 그대로 분모에 대입
"주어진 log 값만을 활용한다"문제에서 제시한 log 값 표만 사용하여 계산
(예: log 3 = 0.48, log 1.5 = 0.18, log 1 = 0)
   [**IDF 변형 공식 — 본 문제에서는 사용하지 않음**]

   ✕ **스무딩 IDF** : log( N / (1 + DF) )      ← DF 가공
   ✕ **Add-1 IDF**  : log( N / DF ) + 1        ← 값 가공
   ✕ **sklearn 기본** : log( (1+N) / (1+DF) ) + 1
   ○ **본 문제**    : **log( N / DF )**  ← 순수 정의식

3. TF의 정규화 방식 (참고)​

방식산식특징
원시 빈도(Raw Count)TF = 출현 횟수본 문제 적용 — "단어의 횟수가 식별되었다"
정규화 빈도TF = 출현 횟수 / 문서 내 총 단어 수문서 길이 차이 보정
로그 정규화TF = 1 + log(출현 횟수)과도한 빈도의 영향 완화
최대값 정규화TF = 출현 횟수 / 최대 빈도0~1 범위로 조정

Ⅲ. 계산 과정 및 결과 (예시 데이터 적용)​

1. 주어진 데이터 (가정)​

   [**형태소 분석 결과 — 문서별 단어 출현 횟수**]

   ┌──────────┬──────┬──────┬──────┐
   │ 단어\문서 │ **D1** │ **D2** │ **D3** │
   ├──────────┼──────┼──────┼──────┤
   │ **인공지능** │  3   │  2   │  0   │
   │ **데이터**   │  2   │  3   │  1   │
   │ **학습**     │  1   │  0   │  0   │
   │ **보안**     │  0   │  0   │  4   │
   └──────────┴──────┴──────┴──────┘

   **전체 문서 수 N = 3**

   [**주어진 log 값**]
   log 1 = 0        log 1.5 = 0.18        log 3 = 0.48

2. [1단계] TF 산출​

TF는 표에 주어진 출현 횟수를 그대로 사용한다.

단어TF(D1)TF(D2)TF(D3)
인공지능320
데이터231
학습100
보안004

3. [2단계] DF 산출​

DF는 해당 단어가 출현한 "문서의 개수" 이다. 출현 횟수의 합이 아님에 유의한다.

   [**DF 산출 방법**]
   출현 횟수가 **1 이상이면 1개 문서로 계수**(횟수는 무관)

   **인공지능** : D1(3회 ○), D2(2회 ○), D3(0회 ✕)  → **DF = 2**
   **데이터**   : D1(2회 ○), D2(3회 ○), D3(1회 ○)  → **DF = 3**
   **학습**     : D1(1회 ○), D2(0회 ✕), D3(0회 ✕)  → **DF = 1**
   **보안**     : D1(0회 ✕), D2(0회 ✕), D3(4회 ○)  → **DF = 1**
단어출현 문서DF
인공지능D1, D22
데이터D1, D2, D33
학습D11
보안D31

4. [3단계] IDF 산출​

   **IDF(t) = log ( N / DF(t) )**,   N = 3

   **인공지능** : log(3 / 2) = **log 1.5 = 0.18**
   **데이터**   : log(3 / 3) = **log 1   = 0**     ← 전 문서 출현 → 변별력 없음
   **학습**     : log(3 / 1) = **log 3   = 0.48**
   **보안**     : log(3 / 1) = **log 3   = 0.48**
단어DFN / DFIDF해석
인공지능23/2 = 1.50.18일부 문서에만 출현 → 보통 변별력
데이터33/3 = 10모든 문서에 출현 → 변별력 없음
학습13/1 = 30.48한 문서에만 출현 → 높은 변별력
보안13/1 = 30.48한 문서에만 출현 → 높은 변별력

핵심 관찰 : "데이터" 는 총 6회로 가장 많이 출현하지만, 모든 문서에 나타나므로 IDF = 0이 되어 TF-IDF 값이 0이 된다. 이것이 TF-IDF가 불용어(Stopword)와 흔한 단어를 자동으로 걸러내는 원리이다.

5. [4단계] TF-IDF 산출​

   **TF-IDF(t, d) = TF(t, d) × IDF(t)**

   [**문서 D1**]
   인공지능 : 3 × 0.18 = **0.54**
   데이터   : 2 × 0    = **0**
   학습     : 1 × 0.48 = **0.48**
   보안     : 0 × 0.48 = **0**

   [**문서 D2**]
   인공지능 : 2 × 0.18 = **0.36**
   데이터   : 3 × 0    = **0**
   학습     : 0 × 0.48 = **0**
   보안     : 0 × 0.48 = **0**

   [**문서 D3**]
   인공지능 : 0 × 0.18 = **0**
   데이터   : 1 × 0    = **0**
   학습     : 0 × 0.48 = **0**
   보안     : 4 × 0.48 = **1.92**

6. 최종 결과 (TF-IDF 행렬)​

단어IDFD1D2D3
인공지능0.180.540.360
데이터0000
학습0.480.4800
보안0.48001.92

7. 결과 해석​

   [**문서별 대표 키워드 도출**]

   **D1** : 최고값 **인공지능(0.54)** > 학습(0.48)
            ⇒ **"인공지능·학습"** 을 다루는 문서

   **D2** : 최고값 **인공지능(0.36)**
            ⇒ **"인공지능"** 중심 문서 (D1보다 관련도 낮음)

   **D3** : 최고값 **보안(1.92)** ← 전체 최고값
            ⇒ **"보안"** 을 강하게 다루는 문서
            (한 문서에만 4회 집중 출현 → TF·IDF 모두 높음)

   [**주요 시사점**]
   ① **"데이터"는 총 6회로 최다 출현이나 TF-IDF = 0**
      → 모든 문서에 나타나 **문서 구별에 기여하지 못함**
      → TF-IDF가 **흔한 단어를 자동 제거**함을 보여주는 사례

   ② **"보안"이 최고 가중치(1.92)**
      → **높은 TF(4회) × 높은 IDF(0.48)** 의 결합
      → **"특정 문서에 집중적으로 출현하는 희소 단어"** 가
        가장 강력한 문서 식별자임을 확인

Ⅳ. TF-IDF의 특징 및 활용​

1. 장단점​

구분내용
장점· 계산이 단순·직관적, 해석 가능
· 불용어·흔한 단어를 자동으로 억제(별도 사전 불필요)
· 학습 데이터가 필요 없는 비지도 방식
· 문서 검색·분류에서 강력한 기준선(Baseline) 성능
단점· 단어의 의미·문맥을 반영하지 못함(동의어·다의어 구분 불가)
· 단어 순서 무시(Bag of Words) → "개가 사람을 물다" = "사람이 개를 물다"
· 희소 행렬(Sparse Matrix) — 어휘 수만큼 차원 증가
· 문서 길이 편향(정규화 미적용 시 긴 문서 유리)
· 신규 문서 추가 시 IDF 재계산 필요

2. 활용 분야​

활용내용
정보 검색(IR)검색 질의와 문서의 유사도 산정 → BM25로 발전
문서 분류·군집화TF-IDF 벡터를 입력으로 SVM·나이브베이즈 분류
키워드 추출문서별 TF-IDF 상위 단어 = 대표 키워드
문서 유사도코사인 유사도로 문서 간 유사성 측정 → 추천·중복 탐지
추천 시스템콘텐츠 기반 필터링(뉴스·논문 추천)
텍스트 요약중요 문장 선별의 가중치
스팸 필터링스팸 특징 단어 가중치

3. 발전 및 대안 기법​

   [**텍스트 표현 기법의 발전**]

   **TF-IDF**(1970s) ── 빈도 기반, 의미 반영 ✕
        ▼
   **BM25** ── TF 포화·문서 길이 정규화 반영 → **검색 엔진 표준**
        ▼
   **Word2Vec / GloVe**(2013) ── **의미 유사도** 반영(정적 임베딩)
        ▼
   **BERT / Transformer 임베딩** ── **문맥 반영 동적 임베딩**
        ▼
   **하이브리드 검색** — **TF-IDF/BM25(키워드) + 벡터 검색(의미)**
        ⇒ 현재 **RAG 시스템의 표준 구성**
   ※ TF-IDF는 여전히 **정확한 키워드 매칭**에서 강점 → 대체가 아닌 **병용**

4. 적용 시 고려사항​

고려사항내용
① 전처리 품질형태소 분석·어간 추출·불용어 제거가 결과 품질을 좌우(한국어는 특히 형태소 분석 중요)
② TF 정규화문서 길이 편차가 크면 정규화 TF 또는 로그 TF 적용
③ IDF 스무딩실무에서는 DF=0인 신규 단어의 0 나눗셈 방지를 위해 스무딩 적용
(단, 본 문제는 명시적으로 금지)
④ 차원 축소어휘가 많으면 SVD·LSA로 차원 축소
⑤ 벡터 정규화문서 벡터를 L2 정규화 후 코사인 유사도 산정
⑥ 의미 검색 병행동의어·문맥이 중요하면 임베딩 기반 벡터 검색과 하이브리드 구성

Ⅴ. 결론​

TF-IDF는 "이 문서에는 자주 나오지만 다른 문서에는 드물게 나오는 단어가 그 문서를 가장 잘 대표한다" 는 단순하지만 강력한 직관을 수식화한 기법이다. 계산은 ① TF(문서 내 출현 횟수) 산출 → ② DF(출현 문서 수) 산출 → ③ IDF = log(N/DF) 산출 → ④ TF × IDF 의 4단계로 이루어진다.

계산 시 가장 유의할 점은 DF의 정의이다. DF는 단어의 총 출현 횟수가 아니라 그 단어가 나타난 문서의 개수이므로, 한 문서에 10번 나와도 DF는 1로 계수된다. 또한 본 문제처럼 "DF를 임의로 가공하지 말라" 는 조건이 있는 경우, 실무에서 흔히 쓰는 스무딩 공식(1+DF)이 아닌 순수 정의식 log(N/DF) 를 적용해야 한다.

계산 결과가 보여주는 핵심 통찰은 "모든 문서에 출현하는 단어의 IDF는 log(N/N) = log 1 = 0이 되어 TF-IDF가 0이 된다" 는 점이다. 위 예시에서 "데이터"가 총 6회로 최다 출현했음에도 가중치가 0이 된 것이 이를 보여준다. 즉 TF-IDF는 별도의 불용어 사전 없이도 변별력 없는 단어를 수학적으로 자동 제거하며, 이것이 이 기법의 가장 우아한 특성이다.

반대로 가장 높은 가중치를 받는 단어는 "특정 문서에 집중 출현하면서 다른 문서에는 없는 희소 단어"(예시의 "보안", 1.92)이며, 이러한 단어가 곧 문서의 대표 키워드가 된다.

다만 TF-IDF는 단어의 의미와 순서를 반영하지 못하는 Bag-of-Words 기법이라는 근본적 한계를 갖는다. 따라서 현대의 검색·추천 시스템에서는 TF-IDF/BM25 기반 키워드 검색과 임베딩 기반 의미 검색을 결합한 하이브리드 방식이 표준으로 자리 잡고 있다. 특히 RAG 시스템에서 TF-IDF 계열은 정확한 고유명사·용어 매칭에서 벡터 검색보다 우수하므로, 대체 관계가 아닌 상호 보완 관계로 활용하는 것이 바람직하다.
