스택, 큐, 리스트

문제​

6.선형 자료 구조인 스택, 큐, 리스트의 자료 입출력 원리를 설명하시오.

Ⅰ. 개요​

1. 선형 자료구조의 개념​

선형 자료구조(Linear Data Structure) 는 데이터가 일렬로 나열되어 각 원소가 앞·뒤로 하나의 이웃만 갖는 구조이다. 스택·큐·리스트는 대표적인 선형 자료구조로, 입출력이 허용되는 위치와 순서 규칙에 따라 구분된다.

   [자료구조의 분류]
   ┌── **선형**(Linear) ── 1:1 관계
   │     **리스트**(배열·연결리스트) · **스택** · **큐** · 데크
   └── **비선형**(Non-linear) ── 1:N, N:M 관계
         트리 · 그래프 · 힙

   [**세 자료구조의 본질적 차이 — 입출력 위치**]

   **스택(Stack)**      : 입력·출력이 **같은 쪽 끝(top)** 에서만  → **LIFO**
   **큐(Queue)**        : 입력은 **뒤(rear)**, 출력은 **앞(front)** → **FIFO**
   **리스트(List)**     : **임의의 위치**에서 입력·출력 가능       → 제약 없음
                          ⇒ 스택·큐는 **리스트에 제약을 가한 특수 형태**

Ⅱ. 스택 (Stack)​

1. 개념 및 입출력 원리​

스택은 한쪽 끝(top)에서만 삽입과 삭제가 이루어지는 자료구조로, 나중에 들어간 데이터가 먼저 나오는 LIFO(Last-In First-Out) 원리를 따른다.

   [**스택의 입출력 원리 — LIFO**]

              **push**(삽입)        **pop**(삭제)
                  │                    ▲
                  ▼                    │
              ┌───────┐            ┌───────┐
    top ────▶ │   D   │  ◀── top ──│   D   │ ← **가장 나중에 넣은 것이**
              ├───────┤            ├───────┤    **가장 먼저 나옴**
              │   C   │            │   C   │
              ├───────┤            ├───────┤
              │   B   │            │   B   │
              ├───────┤            ├───────┤
              │   A   │            │   A   │ ← bottom (가장 먼저 넣음)
              └───────┘            └───────┘
              **입구 = 출구**(한쪽 끝만 개방)

   [동작 예시]  push(A) → push(B) → push(C) → pop() → pop()
                결과 : **C, B 순으로 출력**, 스택에는 A만 남음
   [비유] 접시 쌓기, 프링글스 통, 되돌리기(Undo) 이력

2. 주요 연산​

연산기능시간복잡도
push(x)top 위치에 데이터 삽입O(1)
pop()top 위치의 데이터 삭제 및 반환O(1)
peek() / top()top 데이터를 삭제하지 않고 조회O(1)
isEmpty()스택이 비었는지 확인O(1)
isFull()(배열 구현 시) 가득 찼는지 확인O(1)
예외 상황내용
스택 오버플로(Overflow)가득 찬 스택에 push 시도 → 재귀 호출 무한 반복 시 발생
스택 언더플로(Underflow)빈 스택에서 pop 시도

3. 활용​

활용내용
함수 호출 관리호출 스택(Call Stack) — 함수 복귀 주소·지역변수 저장, 재귀 호출의 기반
되돌리기(Undo)편집기의 작업 이력 관리
수식 계산중위 → 후위 표기 변환, 후위 표기식 계산
괄호 검사여는 괄호 push, 닫는 괄호 시 pop하여 짝 검증
웹 브라우저 뒤로 가기방문 이력 저장
DFS(깊이 우선 탐색)그래프 탐색 시 경로 저장
인터럽트 처리실행 문맥 저장·복원

Ⅲ. 큐 (Queue)​

1. 개념 및 입출력 원리​

큐는 한쪽 끝(rear)에서 삽입하고 반대쪽 끝(front)에서 삭제하는 자료구조로, 먼저 들어간 데이터가 먼저 나오는 FIFO(First-In First-Out) 원리를 따른다.

   [**큐의 입출력 원리 — FIFO**]

    **dequeue**(삭제)                              **enqueue**(삽입)
         ▲                                              │
         │                                              ▼
    ┌────────┬────────┬────────┬────────┬────────┐
    │   A    │   B    │   C    │   D    │        │
    └────────┴────────┴────────┴────────┴────────┘
      ▲ **front**                    ▲ **rear**
      (출구)                          (입구)

   ⇒ **입구와 출구가 서로 반대편** → **먼저 들어온 순서대로 처리**

   [동작 예시]  enqueue(A) → enqueue(B) → enqueue(C) → dequeue() → dequeue()
                결과 : **A, B 순으로 출력**, 큐에는 C만 남음
   [비유] 매표소 줄서기, 은행 번호표, 프린터 인쇄 대기열

2. 주요 연산​

연산기능시간복잡도
enqueue(x)rear에 데이터 삽입O(1)
dequeue()front의 데이터 삭제 및 반환O(1)
front() / peek()front 데이터 조회(삭제 없이)O(1)
isEmpty() / isFull()공백·포화 상태 확인O(1)

3. 큐의 변형​

   [**선형 큐의 문제와 원형 큐**]

   **[선형 큐]** — 배열 구현 시
   ┌───┬───┬───┬───┬───┐
   │ ✕ │ ✕ │ C │ D │   │   ✕ = dequeue된 빈 공간
   └───┴───┴───┴───┴───┘
     0   1   2   3   4
                 ▲ rear   ⇒ **앞쪽에 공간이 있어도 rear가 끝에 도달하면**
             ▲ front         **더 이상 삽입 불가**(**메모리 낭비**)

   **[원형 큐]**(Circular Queue) — 해결책
        ┌─── 0 ───┐
      4           1      배열의 끝과 처음을 **논리적으로 연결**
        │  **원형** │      rear = (rear + 1) % size
      3           2      ⇒ **공간 재활용 가능**
        └─── ─────┘
종류내용
선형 큐기본 형태 — 배열 구현 시 공간 낭비 문제
원형 큐(Circular)배열의 끝과 시작을 연결(모듈러 연산) → 공간 효율
우선순위 큐(Priority)입력 순서가 아닌 우선순위가 높은 것부터 출력 — 힙(Heap)으로 구현, O(log n)
데크(Deque, 이중 종단 큐)양쪽 끝 모두에서 삽입·삭제 가능 → 스택·큐 모두로 활용 가능

4. 활용​

활용내용
작업 스케줄링CPU 스케줄링(FCFS), 프로세스 준비 큐
버퍼·대기열프린터 인쇄 대기열, 키보드 입력 버퍼, 네트워크 패킷 큐
메시지 큐Kafka·RabbitMQ — 비동기 처리, 시스템 간 결합도 완화
BFS(너비 우선 탐색)그래프·트리 레벨 순회
콜센터·티켓 시스템선착순 처리
부하 분산·트래픽 완충요청 폭주 시 대기열로 처리량 조절

Ⅳ. 리스트 (List)​

1. 개념 및 입출력 원리​

리스트는 데이터를 순서(위치)에 따라 나열한 자료구조로, 스택·큐와 달리 임의의 위치에서 삽입·삭제·조회가 가능하다. 구현 방식에 따라 선형 리스트(배열) 와 연결 리스트(Linked List) 로 구분된다.

   [**리스트의 입출력 원리 — 위치 기반 자유 접근**]

              insert(2, X)                    delete(1)
                   │                              │
                   ▼                              ▼
   ┌────┬────┬────┬────┬────┐        ┌────┬────┬────┬────┐
   │ A  │ B  │ C  │ D  │    │   ──▶  │ A  │ **X** │ B  │ C  │ D │
   └────┴────┴────┴────┴────┘        └────┴────┴────┴────┘
     0    1    2    3                   ⇒ **임의 위치 삽입·삭제 가능**
                                          (뒤 원소들은 **이동** 필요)

2. 선형 리스트 (배열, Array List)​

   [**메모리 구조 — 연속 할당**]

   메모리 주소 : 100  104  108  112  116
                ┌────┬────┬────┬────┬────┐
                │ A  │ B  │ C  │ D  │    │
                └────┴────┴────┴────┴────┘
   인덱스        [0]  [1]  [2]  [3]

   ⇒ **주소 = 시작주소 + (인덱스 × 자료크기)** → **O(1) 임의 접근**
   ⇒ 그러나 중간 삽입·삭제 시 **뒤 원소 전체 이동** → **O(n)**

   [삽입 시 이동]
   insert(1, X) →  A │  → │ B │ C │ D  (뒤로 밀기)
                   A │ X │ B │ C │ D
항목내용
메모리연속된 공간에 순차 할당
접근인덱스로 직접 접근 — O(1)
삽입·삭제중간 위치 시 원소 이동 필요 — O(n)
장점임의 접근 빠름, 메모리 오버헤드 없음, 캐시 지역성 우수
단점크기 변경 곤란(정적 배열), 삽입·삭제 비용 큼, 연속 공간 필요

3. 연결 리스트 (Linked List)​

   [**메모리 구조 — 노드와 포인터**]

   **[단일 연결 리스트]**
   head
    │
    ▼
   ┌─────┬───┐   ┌─────┬───┐   ┌─────┬───┐
   │  A  │ ●─┼──▶│  B  │ ●─┼──▶│  C  │ ∅ │
   └─────┴───┘   └─────┴───┘   └─────┴───┘
    데이터 링크    ※ 메모리상 **물리적으로 흩어져 있어도**
                     **링크로 논리적 순서 유지**

   [**삽입 원리 — 링크만 변경**]
   A와 B 사이에 X 삽입
   ┌─────┬───┐        ┌─────┬───┐
   │  A  │ ●─┼──┐     │  B  │ ●─┼──▶
   └─────┴───┘  │     └─────┴───┘
                │      ▲
                │  ┌─────┬───┐
                └─▶│  X  │ ●─┘   ⇒ **원소 이동 없이 O(1)**
                   └─────┴───┘      (단, 위치 탐색은 O(n))
종류구조
단일 연결 리스트각 노드가 다음 노드만 가리킴 → 역방향 탐색 불가
이중 연결 리스트이전·다음 노드 모두 가리킴 → 양방향 탐색, 메모리 추가 소요
원형 연결 리스트마지막 노드가 첫 노드를 가리킴 → 순환 순회
항목내용
메모리불연속 할당, 노드 단위 동적 생성
접근처음부터 순차 탐색 — O(n)(인덱스 접근 불가)
삽입·삭제위치를 알면 링크만 변경 — O(1)
장점동적 크기 조절, 삽입·삭제 효율적, 연속 공간 불필요
단점임의 접근 불가, 포인터 저장 공간 추가 필요, 캐시 효율 낮음

Ⅴ. 세 자료구조의 종합 비교​

1. 입출력 원리 비교​

비교 기준스택(Stack)큐(Queue)리스트(List)
입출력 원리LIFO(후입선출)FIFO(선입선출)자유 접근(제약 없음)
삽입 위치top(한쪽 끝)rear(뒤)임의 위치
삭제 위치top(같은 쪽 끝)front(앞)임의 위치
입구/출구동일반대편제약 없음
주요 연산push / pop / peekenqueue / dequeueinsert / delete / get
접근 제한top만 접근 가능front·rear만모든 원소 접근 가능
삽입·삭제 복잡도O(1)O(1)배열 O(n) / 연결 O(1)*
탐색 복잡도O(n)O(n)배열 O(1) / 연결 O(n)
대표 활용함수 호출·Undo·DFS스케줄링·버퍼·BFS범용 데이터 관리
비유접시 쌓기줄서기목록·명단

*연결 리스트의 삽입·삭제는 위치를 이미 알고 있는 경우 O(1), 탐색 포함 시 O(n)

2. 상호 관계​

   [**리스트가 기본, 스택·큐는 제약을 가한 형태**]

   **리스트**(List) ── 임의 위치 입출력 자유
        │
        ├── **입출력을 한쪽 끝으로 제한** ────▶ **스택**(LIFO)
        │
        ├── **입력은 뒤, 출력은 앞으로 제한** ─▶ **큐**(FIFO)
        │
        └── **양쪽 끝 입출력 허용** ──────────▶ **데크**(Deque)
                                              ⇒ 스택·큐 **모두 구현 가능**

   ⇒ **제약을 가하는 이유**
      · **구현 단순화** → 오류 가능성 감소
      · **핵심 연산 O(1) 보장** → 성능 예측 가능
      · **문제의 의미에 부합**(순서 규칙 자체가 요구사항인 경우)

3. 배열 기반 vs 연결 기반 구현 비교​

구분배열 기반 구현연결 기반 구현
메모리 할당연속·정적(또는 동적 배열)불연속·동적
크기사전 지정(초과 시 재할당)가변
임의 접근O(1)O(n)
삽입·삭제O(n)(이동 필요)O(1)(링크 변경)

② 실제 성능은 캐시 영향이론상 O(1)인 연결 리스트가 캐시 지역성 때문에 배열보다 느릴 수 있음

⑦ 언어 제공 라이브러리 활용Java Deque(스택 권장), LinkedList, ArrayList, Python collections.deque 등 검증된 구현 사용

Ⅶ. 결론​

스택·큐·리스트는 모두 선형 자료구조이지만, 입출력이 허용되는 위치에 따라 완전히 다른 성질을 갖는다. 스택은 입구와 출구가 같아 LIFO, 큐는 입구와 출구가 반대여서 FIFO, 리스트는 위치 제약이 없어 자유로운 접근이 가능하다.

이 세 구조의 관계를 이해하는 핵심은 "리스트가 기본이고, 스택과 큐는 리스트에 의도적으로 제약을 가한 특수 형태" 라는 점이다. 언뜻 제약은 손실처럼 보이지만, 그 대가로 핵심 연산의 O(1) 성능 보장과 구현의 단순화, 그리고 문제 의미에 대한 정확한 표현을 얻는다. 함수 호출 관리에 스택을, 작업 대기열에 큐를 쓰는 이유는 성능 때문만이 아니라 그 순서 규칙 자체가 문제의 요구사항이기 때문이다.

실무 선택의 기준은 "어떤 연산이 가장 빈번한가" 이다. 조회·인덱스 접근이 많으면 배열 기반, 중간 삽입·삭제가 빈번하면 연결 기반을 택하되, 이론적 복잡도만으로 판단해서는 안 된다. 연결 리스트는 O(1) 삽입이 가능하지만 캐시 지역성이 낮아 실제로는 배열보다 느린 경우가 많다는 점을 유념해야 한다.

끝으로 이러한 기초 자료구조는 현대 시스템 아키텍처에도 그대로 확장된다. 메시지 큐(Kafka·RabbitMQ)는 큐의 FIFO 원리를 분산 환경으로 확장한 것이고, 함수 호출 스택은 모든 프로그램 실행의 기반이며, 스택 오버플로는 여전히 대표적 보안 취약점이다. 따라서 자료구조의 입출력 원리에 대한 정확한 이해는 알고리즘 구현을 넘어 시스템 설계와 보안 판단의 기초가 된다.
