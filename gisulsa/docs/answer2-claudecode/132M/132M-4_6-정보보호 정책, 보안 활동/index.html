정보보호 정책, 보안 활동

문제​

6.A 기업의 경영진은 임직원들의 증가로 인해 정보보안의 필요성을 인식하고 정보보안 부서의 신설과 정보보안 체계를 수립하고자 한다.다음을 설명하시오.
가.정보보호 정책의 개념
나.정보보호 시점별 보안 활동(Security Action Cycle)
다.정보보안 전문가의 역할과 역량

Ⅰ. 개요​

1. 배경​

A 기업과 같이 조직 규모가 확대되면 정보 자산과 접근 주체가 급증하고, 기존의 개인 역량과 관행에 의존한 보안 관리로는 통제가 불가능해진다.

   [조직 성장에 따른 보안 관리의 전환 필요성]

   **소규모 조직**                        **조직 확대 후**
   · 소수 인원, 상호 신뢰            →   · **접근 주체·권한 급증**
   · 담당자 개인 역량에 의존         →   · **속인적 관리의 한계**
   · 구두·관행 기반 통제             →   · **일관된 기준 부재 → 통제 공백**
   · 사고 발생 시 개별 대응          →   · **내부자 위협·실수 증가**
        ▼
   [필요] **문서화된 정책 + 조직 + 체계적 활동**
        ▼
   ┌─────────────────────────────────────────────┐
   │ **정보보호 정책** ── 무엇을 지킬 것인가(기준)  │
   │ **보안 활동**     ── 어떻게 지킬 것인가(실행)  │
   │ **보안 전문가**   ── 누가 지킬 것인가(주체)    │
   └─────────────────────────────────────────────┘
   근거 : **ISO/IEC 27001**(ISMS), **ISMS-P 인증**, 개인정보보호법
          안전성 확보조치 기준(**내부관리계획 수립 의무**)

Ⅱ. 가. 정보보호 정책의 개념​

1. 개념 및 정의​

정보보호 정책(Information Security Policy) 이란 조직이 보호해야 할 정보 자산과 보안 목표를 정의하고, 이를 달성하기 위한 경영진의 의지와 기본 방향, 원칙, 역할과 책임을 문서로 명시한 최상위 규범이다.

관점내용
성격조직 내 최상위 보안 규범 — 모든 보안 활동의 근거
수립 주체최고경영진(CEO)의 승인 필수 → 강제력의 원천
대상전 임직원 및 외부 협력사·수탁자
핵심 기능① 의사결정 기준 제공, ② 책임과 권한 명확화, ③ 위반 시 제재 근거, ④ 대외 신뢰 확보
법적 근거개인정보보호법 안전성 확보조치 기준(내부관리계획), 정보통신망법, ISMS-P 인증 기준
   [**정보보호 정책의 3대 요건**]

   **① 경영진의 승인과 지지**
        · CEO 승인·서명 → **조직 전체에 대한 강제력**
        · 자원(예산·인력) 배분의 근거
   **② 명확성과 실행 가능성**
        · 모호한 선언이 아닌 **구체적·준수 가능한 내용**
   **③ 지속적 갱신**
        · 조직·기술·법규 변화 반영 → **연 1회 이상 검토**

2. 정보보호 정책의 체계 (계층 구조)​

 ┌──────────── **정보보호 정책 문서 체계** ────────────┐
 │                                                     │
 │  **[1단계] 정보보호 정책서**(Policy)                 │
 │      · **최상위 문서** — 경영진 승인                 │
 │      · 보안 목표·기본 원칙·적용 범위·역할과 책임     │
 │      · **"무엇을 왜 보호하는가"**(What / Why)        │
 │      · 간결(수 페이지), **잘 변하지 않음**           │
 │            ▼                                        │
 │  **[2단계] 정보보호 지침**(Standard/Guideline)       │
 │      · 정책을 **영역별로 구체화**                    │
 │      · 접근통제 지침, 암호화 지침, 인적보안 지침,    │
 │        물리보안 지침, 사고대응 지침 등               │
 │      · **"어떤 기준을 지킬 것인가"**(Standard)       │
 │            ▼                                        │
 │  **[3단계] 절차서·매뉴얼**(Procedure)                │
 │      · **실무 수행 절차 상세**                       │
 │      · 계정 발급 절차, 백업 절차, 침해대응 절차      │
 │      · **"어떻게 수행할 것인가"**(How)               │
 │            ▼                                        │
 │  **[4단계] 양식·기록**(Form/Record)                  │
 │      · 신청서·점검표·대장·로그                       │
 │      · **이행 증거**(Evidence) — 인증·감사 대응      │
 └─────────────────────────────────────────────────────┘

   ※ **상위 문서일수록 추상적·안정적**, **하위로 갈수록 구체적·가변적**

3. 정보보호 정책의 주요 구성 내용​

구성 항목내용
① 목적 및 적용 범위정책의 목적, 적용 대상(조직·인원·자산·시스템), 적용 지역
② 정보보호 목표기밀성·무결성·가용성(CIA) 확보 목표, 사업 목표와의 연계
③ 경영진의 의지 표명CEO의 정보보호 의지 선언 및 지원 약속
④ 정보보호 원칙최소 권한, 직무 분리, 알 필요성, 기본 거부, 심층 방어
⑤ 조직 및 역할·책임CISO·CPO·정보보호 조직·부서별 책임, 정보보호위원회
⑥ 자산 관리정보자산 식별·분류·등급별 보호 수준
⑦ 위험 관리위험평가 수행 주기·방법, 수용 기준
⑧ 영역별 보호 정책인적·물리적·기술적 보안, 접근통제, 암호, 개발보안, 공급망
⑨ 사고 대응 및 연속성침해사고 대응, 업무연속성(BCP)
⑩ 준수 및 제재법규 준수, 위반 시 제재 규정, 감사
⑪ 교육 및 인식정기 보안 교육 의무
⑫ 정책 관리제·개정 절차, 검토 주기(연 1회 이상), 공표·배포

4. 수립 절차 및 성공 요건​

   ① **경영진 의지 확보** — 정보보호 필요성 인식·자원 승인
        ▼
   ② **현황 분석** — 정보자산 식별, 현행 보안 수준 진단, 법규 요건 파악
        ▼
   ③ **위험 평가**(Risk Assessment) — 위협·취약점 식별, 위험도 산정
        ▼
   ④ **정책 초안 작성** — 목표·원칙·범위·역할 정의
        ▼
   ⑤ **의견 수렴·검토** — 관련 부서 협의, 실행 가능성 검증
        ▼
   ⑥ **경영진 승인·공표** — CEO 서명, 전사 공지
        ▼
   ⑦ **하위 지침·절차 수립** — 영역별 구체화
        ▼
   ⑧ **교육·이행** — 전 임직원 교육, 서약서 징구
        ▼
   ⑨ **점검·개선**(연 1회 이상) — 준수 여부 점검 → 정책 갱신(**PDCA**)
성공 요건내용
경영진 스폰서십정책의 강제력은 경영진의 승인에서 나옴 — 없으면 문서에 그침
실행 가능성현실에서 지킬 수 없는 정책은 우회 행위를 조장
명확한 책임역할·책임이 불명확하면 아무도 책임지지 않음
지속적 갱신변화 미반영 시 사문화(Dead Document)
교육·인식알지 못하는 정책은 지켜지지 않음

Ⅲ. 나. 정보보호 시점별 보안 활동 (Security Action Cycle)​

1. 개념​

Security Action Cycle(보안 활동 주기)은 보안 사고를 중심으로 시간의 흐름에 따라 수행되는 보안 활동을 4단계로 구분한 모델로, 사고 발생 전(예방·억제)과 발생 후(탐지·대응·복구) 의 활동을 체계적으로 배치한다.

   [**Security Action Cycle — 시점별 보안 활동**]

                          **보안 사고 발생 시점**
                                  │
   ◀──────── 사고 이전 ───────────┼──────── 사고 이후 ────────▶
                                  │
   ┌──────────┐   ┌──────────┐   │   ┌──────────┐  ┌──────────┐
   │**① 억제** │──▶│**② 예방** │───┼──▶│**③ 탐지** │─▶│**④ 교정** │
   │Deterrence│   │Prevention│   │   │Detection │  │Correction│
   ├──────────┤   ├──────────┤   │   ├──────────┤  ├──────────┤
   │ 심리적    │   │ 기술적·   │   │   │ 사고를    │  │ 복구 및   │
   │ 위협      │   │ 물리적    │   │   │ 발견·인지 │  │ 재발방지  │
   │ "하지 마라"│   │ "못 하게" │   │   │ "알아낸다"│  │ "되돌린다"│
   └──────────┘   └──────────┘   │   └──────────┘  └────┬─────┘
        ▲                        │                       │
        └───────── **환류(Feedback)** — 개선 사항 반영 ────┘

   ※ **예방이 실패할 것을 전제로 탐지·교정을 준비**하는 것이 핵심
      (**완벽한 예방은 불가능** → 심층 방어)

2. 단계별 보안 활동​

■ ① 억제 (Deterrence) — 사고 이전, 심리적 통제​

항목내용
목적위반 행위를 시도하지 않도록 심리적으로 단념시킴
성격비물리적·심리적 통제 — 가장 저비용·고효율
주요 활동· 정보보호 정책·규정 공표 및 주지
· 위반 시 제재 규정 명시(징계·법적 조치)
· 보안 서약서 징구
· 정기 보안 교육·인식 제고(캠페인·포스터)
· 모니터링 사실의 사전 고지("모든 접속은 기록됩니다")
· CCTV·경고 표지판 설치
· 위반 사례 공유(익명화)
효과내부자 위협 억제에 특히 효과적 — 적발 가능성 인식이 억제력
A기업 적용임직원 증가 → 전사 보안 교육 및 서약서 제도부터 시행

■ ② 예방 (Prevention) — 사고 이전, 실질적 차단​

항목내용
목적위반 행위 자체가 물리적·기술적으로 불가능하도록 차단
성격가장 핵심적인 통제 — 사고를 실제로 막음
관리적 예방· 정보보호 정책·지침·절차 수립
· 접근권한 관리(최소 권한·직무 분리·정기 검토)
· 인적 보안(채용 시 배경 확인, 퇴직 시 권한 회수)
· 위험평가·보안 요구사항 사전 반영(설계 단계)
기술적 예방· 접근통제(인증·MFA·IAM), 암호화(저장·전송)
· 방화벽·IPS·WAF·NAC, 망분리
· 백신·EDR, 패치 관리, DLP·DRM
· 시큐어 코딩, 취약점 진단
물리적 예방출입통제(카드·생체), 전산실 이중 출입통제, 잠금장치, 매체 반출입 통제
한계완벽한 예방은 불가능 — 신규 취약점·내부자·사회공학 공격
A기업 적용계정·권한 관리 체계 구축(최소 권한), 방화벽·백신, 전산실 출입통제

■ ③ 탐지 (Detection) — 사고 발생 시점, 신속 인지​

항목내용
목적예방을 우회한 침해·이상 행위를 신속히 발견·인지
중요성탐지가 늦을수록 피해 확산 — 침해 후 인지까지 평균 수개월 소요 사례 다수
주요 활동· 로그 수집·통합 분석(SIEM)
· 침입탐지(IDS)·EDR·NDR, 이상행위 분석(UEBA)
· 접속기록 정기 점검(개인정보 처리시스템 월 1회 이상)
· 파일 무결성 모니터링(FIM)
· 취약점 스캐닝, 모의 해킹
· 보안 관제(24×365), 위협 인텔리전스 연계
· 내부 감사·정기 점검, 위반 신고 채널 운영
핵심 지표MTTD(평균 탐지 시간) — 짧을수록 우수
A기업 적용로그 중앙 수집(SIEM) 및 정기 점검 체계 우선 구축

■ ④ 교정 (Correction) — 사고 이후, 대응·복구·개선​

항목내용
목적피해 확산 차단 → 정상 복구 → 재발 방지
주요 활동· 초동 대응 — 침해 시스템 격리·차단, 계정 잠금
· 증거 보전 — 로그·이미지 확보(디지털 포렌식, 연계보관성)
· 원인 분석 — 침투 경로·취약점 규명
· 복구 — 시스템·데이터 복구(백업 활용), 서비스 재개
· 신고·통지 — KISA·개인정보보호위원회 신고(72시간 이내), 정보주체 통지
· 재발 방지 대책 수립·이행
· 정책·절차 개선 → ①·② 단계로 환류
핵심 지표MTTR(평균 복구 시간), 재발률
사전 준비침해사고 대응 절차서(CERT), 비상연락망, 모의 훈련, 백업·DR 체계
A기업 적용침해사고 대응 절차 수립 및 백업 체계 확보

3. 통제 유형과의 연계​

Security Action Cycle통제 시점통제 유형대표 수단
① 억제(Deterrence)사고 전억제 통제정책·제재 규정·교육·경고
② 예방(Prevention)사고 전예방 통제접근통제·암호화·방화벽·출입통제
③ 탐지(Detection)사고 시탐지 통제로그·SIEM·IDS·감사·CCTV
④ 교정(Correction)사고 후교정·복구 통제백업·복구·패치·재발방지
   [**심층 방어(Defense in Depth)와의 관계**]

   "**어떤 단일 통제도 완벽하지 않다**"
        ▼
   억제가 실패하면 → **예방**이 막고
   예방이 뚫리면   → **탐지**가 발견하고
   탐지 이후에는   → **교정**이 복구한다
        ▼
   ⇒ 4단계는 **선택이 아니라 모두 갖추어야 하는 다층 방어**
   ⇒ 특히 **예방에만 투자하고 탐지·대응을 소홀히 하는 것이
      실무에서 가장 흔한 오류**

4. A기업 적용 방안 (단계적 구축)​

단계우선 과제
1단계(기반)정보보호 정책 수립·경영진 승인, 보안 조직(CISO) 지정, 자산 식별·위험평가
2단계(억제·예방)보안 교육·서약, 계정·권한 관리 체계, 방화벽·백신·백업, 출입통제
3단계(탐지)로그 중앙 수집(SIEM), 정기 점검·취약점 진단, 접속기록 점검
4단계(교정)침해사고 대응 절차·조직(CERT), 모의 훈련, BCP/DR
5단계(고도화)ISMS-P 인증 취득, 제로트러스트, 지속적 개선(PDCA)

Ⅴ. 결론​

A 기업과 같이 조직이 성장하는 단계에서 정보보안 체계를 수립할 때 반드시 인식해야 할 것은, 보안은 솔루션을 도입하는 문제가 아니라 정책·활동·인력이라는 세 요소를 함께 갖추는 체계의 문제라는 점이다.

정보보호 정책은 모든 보안 활동의 최상위 규범으로서, 그 강제력은 경영진의 승인에서 나온다. 정책–지침–절차–양식의 4단계 문서 체계를 통해 상위의 원칙이 하위의 실무 절차로 구체화되어야 하며, 실행 불가능한 이상적 정책은 오히려 우회 행위를 조장한다는 점에서 현실적 실행 가능성이 무엇보다 중요하다.

Security Action Cycle은 보안 활동을 억제 → 예방 → 탐지 → 교정의 시점별로 배치한 모델로, 그 핵심 통찰은 "완벽한 예방은 불가능하다" 는 전제이다. 실무에서 가장 흔한 오류는 방화벽·백신 등 예방 통제에만 투자하고 탐지와 대응 체계를 소홀히 하는 것이다. 침해가 발생한 뒤 이를 인지하기까지 수개월이 걸리는 사례가 빈번한 현실을 고려하면, 로그 중앙 수집과 정기 점검이라는 탐지 역량, 그리고 사고 대응 절차와 백업이라는 교정 역량이 예방 못지않게 중요하다. 특히 억제(교육·서약·제재 규정)는 가장 저비용으로 내부자 위협을 줄이는 효과적 수단이므로, A기업처럼 임직원이 급증하는 조직에서 우선적으로 시행할 가치가 있다.

정보보안 전문가의 역량에서 강조할 점은 기술적 역량만으로는 충분하지 않다는 것이다. 특히 CISO에게 요구되는 가장 중요한 능력은 경영진을 설득하는 커뮤니케이션 역량이다. 보안 투자는 매출을 창출하지 않으므로, 기술 용어가 아니라 "이 위험이 실현되면 얼마의 손실과 어떤 법적 책임이 발생하는가"라는 비즈니스 언어로 설명할 수 있어야 자원을 확보할 수 있다. 또한 보안 담당자는 조직의 모든 정보에 접근할 수 있는 강력한 권한을 보유하므로, 직업 윤리와 중립성이 기술 역량 못지않은 필수 자질이 된다.

실무적으로 A기업에 권고할 순서는 ① 정책 수립과 CISO 지정으로 거버넌스를 먼저 확립하고, ② 위험평가를 통해 우선순위를 도출한 뒤, ③ 억제·예방·탐지·교정의 4단계 활동을 단계적으로 구축하며, ④ 부족한 전문 역량은 외부 서비스(MSSP·컨설팅)로 보완하는 것이다. 궁극적으로는 ISMS-P 인증 취득을 통해 체계의 완결성을 객관적으로 검증받고, PDCA 기반의 지속적 개선 체계로 정착시키는 것이 바람직하다.
