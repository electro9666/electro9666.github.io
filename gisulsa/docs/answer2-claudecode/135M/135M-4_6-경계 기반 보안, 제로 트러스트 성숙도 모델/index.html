경계 기반 보안과 제로 트러스트 성숙도 모델 2.0

Ⅰ. 개요​

1. 보안 패러다임의 전환​

전통적 보안은 "내부는 신뢰, 외부는 불신" 이라는 경계(Perimeter) 개념에 기반했으나, 클라우드·재택근무·모바일·SaaS 확산으로 경계 자체가 소멸하면서 이 전제가 무너졌다.

   [경계 기반 보안 — 성곽 모델(Castle-and-Moat)]
   ┌────── 외부(불신) ──────┐
   │        인터넷          │
   └───────────┬────────────┘
        **방화벽·IPS·VPN**  ← 단일 방어선(성벽)
   ┌───────────┴────────────┐
   │     내부(**무조건 신뢰**) │  ← **한 번 통과하면 자유롭게 이동**
   │  서버·DB·업무시스템     │
   └────────────────────────┘
        ▼ 문제
   ① 내부 침투 시 **측면 이동 차단 불가**
   ② 클라우드·재택근무로 **보호 대상이 경계 밖에 존재**
   ③ **내부자 위협·탈취된 계정**에 무방비

   [**제로 트러스트**]
   "**Never Trust, Always Verify**" — 위치와 무관하게 **매 접근마다 검증**

Ⅱ. 경계 기반 보안과 제로 트러스트 비교​

1. 개념 정의​

  • 경계 기반 보안(Perimeter Security): 신뢰할 수 있는 내부 네트워크와 신뢰할 수 없는 외부를 경계 장비로 분리하고, 경계 통과 여부로 접근을 통제하는 모델
  • 제로 트러스트(Zero Trust): 어떤 사용자·기기·네트워크도 기본적으로 신뢰하지 않으며, 모든 접근 요청을 지속적으로 검증하고 최소 권한만 부여하는 보안 모델(NIST SP 800-207)

2. 상세 비교​

비교 기준경계 기반 보안제로 트러스트
기본 전제내부는 신뢰, 외부는 불신어디도 신뢰하지 않음, 침해를 가정(Assume Breach)
신뢰 판단 기준네트워크 위치(내부망 여부)신원·기기 상태·행위 맥락(위치 무관)
검증 시점최초 진입 시 1회모든 요청마다 지속 검증(세션 중에도 재평가)
보호 대상네트워크 경계데이터·자산(리소스) 자체
권한 부여광범위·지속적(내부 자유 이동)최소 권한·한시적(JIT/JEA)
네트워크 구조평면적 대형 네트워크마이크로 세그멘테이션(세분화)
측면 이동차단 불가(내부 자유 이동)차단(세그먼트 간 검증)
원격 접근VPN(접속 시 내부망 전체 접근)ZTNA(애플리케이션 단위 접근)
가시성경계 트래픽 중심(내부는 미가시)전 구간 로깅·분석(동서 트래픽 포함)
적합 환경온프레미스 중심, 고정 사무실클라우드·하이브리드·원격근무
주요 한계내부 침투 시 무력화, 경계 소멸구축 복잡도·비용, 레거시 통합 곤란

3. 제로 트러스트 핵심 원칙 (NIST SP 800-207)​

원칙내용
① 명시적 검증(Verify Explicitly)신원·기기·위치·서비스·데이터 분류 등 가용한 모든 정보로 매번 인증·인가
② 최소 권한(Least Privilege)필요한 최소 범위·최소 시간만 접근 허용(JIT·JEA)
③ 침해 가정(Assume Breach)이미 침해되었다고 가정 → 폭발 반경(Blast Radius) 최소화, 세분화·암호화·모니터링
   [제로 트러스트 논리 구조 — NIST SP 800-207]
   ┌──────────── **제어 평면(Control Plane)** ────────────┐
   │  **PDP**(정책 결정 지점)                              │
   │   = **정책 엔진(PE)** + **정책 관리자(PA)**            │
   │   입력: 신원·기기 상태·위협 인텔리전스·행위 분석·     │
   │         컴플라이언스·요청 맥락                        │
   └────────────────────┬─────────────────────────────────┘
                 정책 결정 │ **지속적 재평가**
   ┌────────────────────▼─────────────────────────────────┐
   │             **데이터 평면(Data Plane)**                │
   │  주체(사용자/기기) ──► **PEP**(정책 시행 지점) ──► 자원 │
   │                        (게이트웨이·프록시·에이전트)     │
   └───────────────────────────────────────────────────────┘

Ⅲ. 제로 트러스트 성숙도 모델 2.0 (CISA ZTMM v2.0)​

1. 개요​

미국 CISA(사이버보안·인프라보안국) 가 2023년 발표한 ZTMM(Zero Trust Maturity Model) 2.0 은 조직이 제로 트러스트로 전환하는 과정을 5개 기둥(Pillar)과 4단계 성숙도로 구조화한 로드맵이다. 국내 「제로트러스트 가이드라인 2.0」(과기정통부)도 이를 참조하여 수립되었다.

2. 5대 기둥(Pillars)과 3대 교차 기능​

   ┌────────────────────────────────────────────────────────────┐
   │  ①      │  ②      │  ③      │  ④      │  ⑤              │
   │ **신원** │ **기기** │ **네트워크**│**애플리케이션**│ **데이터**  │
   │(Identity)│(Devices)│(Networks)│& 워크로드  │  (Data)      │
   │         │         │         │           │              │
   ├─────────┴─────────┴─────────┴───────────┴──────────────┤
   │  **교차 기능(Cross-Cutting Capabilities)**                 │
   │  · **가시성 및 분석**(Visibility and Analytics)            │
   │  · **자동화 및 오케스트레이션**(Automation & Orchestration)│
   │  · **거버넌스**(Governance)                                │
   └────────────────────────────────────────────────────────────┘
기둥핵심 내용
① 신원(Identity)사용자·서비스 계정의 강력한 인증(MFA·피싱 저항 인증), 통합 ID 관리(IdP), 지속적 인증, 특권계정 관리(PAM)
② 기기(Devices)모든 기기의 인벤토리 관리, 접근 시 기기 상태(패치·EDR·암호화) 검증, 비관리 기기 통제
③ 네트워크(Networks)마이크로 세그멘테이션, 모든 트래픽 암호화(mTLS), VPN → ZTNA 전환, 동서 트래픽 통제
④ 애플리케이션·워크로드애플리케이션 단위 접근통제, DevSecOps 통합, 워크로드 신원(SPIFFE), 지속적 취약점 관리
⑤ 데이터(Data)데이터 분류·태깅, 저장·전송 암호화, DLP, 데이터 접근 권한 세분화·감사
가시성·분석전 구간 로그 수집, UEBA·행위 분석, 위협 인텔리전스 연계
자동화·오케스트레이션정책 자동 시행(Policy as Code), 이상 탐지 시 자동 격리·권한 회수(SOAR)
거버넌스정책 수립·감독, 컴플라이언스, 위험 관리

3. 4단계 성숙도​

   **① Traditional** ──► **② Initial** ──► **③ Advanced** ──► **④ Optimal**
      (전통)              (초기)             (진전)             (최적)
   수동·정적           일부 자동화        중앙집중·자동화     완전 자동화·동적
   ※ **v1.0 대비 v2.0의 주요 변화 : "Initial" 단계 신설**
     → 전통에서 진전으로 가는 **점진적 전환 경로**를 명확히 제시
단계특징예시(신원 기둥 기준)
① 전통(Traditional)수동 구성·정적 정책, 사일로화된 관리, 암묵적 신뢰 존재비밀번호 단독 인증, 수동 계정 관리
② 초기(Initial)일부 자동화 시작, 기본 통합 착수, 최소 수준의 가시성MFA 부분 도입, 일부 시스템 SSO 연동
③ 진전(Advanced)중앙집중식 가시성·정책 관리, 기둥 간 통합, 자동화된 대응전사 SSO·MFA, 위험 기반 조건부 접근
④ 최적(Optimal)완전 자동화·동적 정책, 실시간 위험 평가로 지속 조정, 전 기둥 통합지속적 인증, 실시간 신뢰 점수 기반 자동 권한 조정
   [성숙도 진화 방향 — 공통 축]
   가시성   : 없음 ────► 부분 ────► 중앙집중 ────► **실시간 통합**
   자동화   : 수동 ────► 일부 ────► 자동화 ────► **완전 자동·동적**
   정책     : 정적 ────► 부분동적 ► 중앙관리 ────► **적응형(Adaptive)**
   최소권한 : 광범위 ──► 축소 ────► 세분화 ────► **JIT/JEA**

Ⅳ. 제로 트러스트 아키텍처 도입 시 고려사항​

1. 전략·거버넌스 측면​

고려사항내용
점진적 전환전면 전환은 비현실적 — 기존 경계 보안을 즉시 폐기하지 말고 병행 운영하며 단계적 이행
성숙도 진단 우선ZTMM 기준으로 현 수준을 5개 기둥별로 평가 → 격차 분석 → 로드맵 수립
우선순위 결정핵심 자산(Crown Jewels)과 고위험 접근 경로부터 적용, 전면 확산은 이후
경영진 지원대규모·장기 과제이므로 최고경영진의 명확한 스폰서십과 예산 확보
명확한 목표 설정"제로 트러스트 도입" 자체가 목표가 아니라 해결하려는 위험을 특정

2. 기술·아키텍처 측면​

고려사항내용
자산·데이터 식별이 출발점무엇을 보호할지 모르면 정책을 세울 수 없음 → 자산 인벤토리·데이터 분류가 선행 필수
신원 중심 설계제로 트러스트의 핵심 축은 네트워크가 아닌 신원(Identity) → IdP 통합, 피싱 저항 MFA 우선 도입
레거시 시스템 통합현대적 인증·암호화를 지원하지 않는 시스템 다수 → 프록시·게이트웨이로 감싸는 방식 적용, 불가 시 격리
정책 엔진의 단일 장애점PDP 장애 시 전체 접근 마비 → 이중화·고가용성 설계 필수
성능·지연매 요청 검증으로 지연 증가 가능 → 캐싱·토큰 유효기간 최적화
가시성 확보로그 수집 범위 확대에 따른 저장·분석 비용 → 중요도 기반 수집 정책

3. 운영·조직 측면​

고려사항내용
사용자 경험(UX)과도한 인증 요구는 업무 저해·우회 사용(섀도 IT) 유발 → 위험 기반 적응형 인증으로 마찰 최소화
정책 정교화의 어려움초기에 과도하게 엄격하면 업무 차단 → 모니터링 모드로 먼저 운영 후 점진적 강제
운영 역량지속 모니터링·정책 조정 인력 필요 → 교육 및 자동화(SOAR) 로 부담 경감
비용솔루션 도입·통합 비용 → 위험 기반 우선순위로 단계적 투자
문화 변화"내부는 안전하다"는 인식 전환, 전 구성원 대상 커뮤니케이션

4. 국내 제도 연계 고려사항​

제도연계 사항
N2SF(국가 망 보안체계)기존 망분리에서 데이터 등급 기반 통제로 전환 — 제로 트러스트가 핵심 개념으로 반영됨
제로트러스트 가이드라인 2.0과기정통부·KISA 발간, 국내 환경에 맞는 성숙도 모델·적용 사례 제시
ISMS-P접근통제·계정관리 인증 항목과 정합성 확보
CSAP클라우드 이용 시 보안 인증 요건 충족

5. 단계적 도입 로드맵​

   [1단계] **현황 진단** : ZTMM 5개 기둥별 성숙도 평가, 자산·데이터 분류
        ▼
   [2단계] **신원 강화** : IdP 통합, **전사 MFA(피싱 저항)**, 특권계정 PAM
        │  → **가장 효과가 크고 비용 대비 효율이 높은 출발점**
        ▼
   [3단계] **접근 전환** : VPN → **ZTNA**, 애플리케이션 단위 접근통제
        ▼
   [4단계] **네트워크 세분화** : 마이크로 세그멘테이션, 동서 트래픽 통제·암호화
        ▼
   [5단계] **가시성·자동화** : 통합 로깅·UEBA, **SOAR 기반 자동 대응**
        ▼
   [6단계] **최적화** : 실시간 위험 기반 **적응형 정책**, 지속적 검증

Ⅴ. 결론​

경계 기반 보안은 "내부는 안전하다"는 더 이상 성립하지 않는 전제 위에 서 있어, 클라우드·원격근무 환경에서는 구조적으로 무력화된다. 실제 대형 침해사고 대부분이 경계 통과 이후의 측면 이동에서 피해가 확대되었다는 점이 이를 입증한다.

제로 트러스트는 이에 대해 신뢰의 근거를 "네트워크 위치"에서 "검증된 신원과 맥락"으로 이동시키는 해법을 제시하며, CISA ZTMM 2.0은 이를 5개 기둥과 4단계 성숙도로 구조화하여 실행 가능한 로드맵을 제공한다. 특히 v2.0에서 Initial 단계를 신설한 것은, 전통 환경에서 급격히 전환하기 어려운 현실을 반영한 실용적 개선이다.

도입 시 핵심 유의점은 ① 제로 트러스트는 제품이 아니라 전략·여정이므로 단일 솔루션 구매로 달성되지 않으며, ② 자산·데이터 식별이 선행되지 않으면 정책 수립 자체가 불가능하고, ③ 신원(Identity) 강화가 가장 효과적인 출발점이라는 것이다. 아울러 ④ 과도한 통제는 사용자 우회를 초래하므로 위험 기반 적응형 인증으로 균형을 잡아야 한다.

국내에서는 N2SF가 망분리 중심에서 데이터 등급 기반 제로 트러스트 개념으로 전환되고 있어, 공공·민간 모두 성숙도 진단 → 신원 강화 → ZTNA 전환 → 세분화 → 자동화의 단계적 여정을 계획적으로 추진해야 할 시점이다.
