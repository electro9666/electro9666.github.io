확장성 해싱(Extendible Hashing)

Ⅰ. 개요​

1. 배경 — 정적 해싱의 한계​

정적 해싱(Static Hashing) 은 버킷 수가 고정되어 있어, 데이터가 증가하면 오버플로 체인이 길어져 검색 성능이 O(1)에서 급격히 저하되고, 반대로 데이터가 적으면 저장공간이 낭비된다. 이를 해결하기 위해 데이터량에 따라 버킷 수를 동적으로 조절하는 동적 해싱(Dynamic Hashing) 이 등장했다.

   [정적 해싱]                        [**확장성 해싱**]
   버킷 수 고정                        데이터 증가 시 **필요한 버킷만 분할**
   오버플로 → **체인 증가**            **전체 재해싱(Rehashing) 불필요**
   → 검색 성능 저하                    → **O(1) 성능 유지**
   → 재구성 시 전체 재해싱(중단)       → 점진적 확장(무중단)

Ⅱ. 가. 확장성 해싱의 개념 및 구성요소​

1. 개념​

확장성 해싱은 디렉터리(Directory) 를 두어 해시값의 접두 비트(Prefix) 로 버킷을 참조하고, 오버플로 발생 시 해당 버킷만 분할하며 필요할 때만 디렉터리를 2배로 확장하는 동적 해싱 기법이다.

2. 구성요소​

   ┌──────────────────────────────────────────────────────────┐
   │ **① 해시 함수** : 키 → **긴 비트열(예: 32비트)** 생성       │
   │      ※ 전체를 쓰지 않고 **앞에서부터 필요한 만큼만 사용**   │
   ├──────────────────────────────────────────────────────────┤
   │ **② 전역 깊이(Global Depth, d)**                          │
   │      디렉터리가 사용하는 **접두 비트 수** → 디렉터리 크기 = **2^d** │
   ├──────────────────────────────────────────────────────────┤
   │ **③ 디렉터리(Directory)**                                 │
   │      2^d개의 엔트리, 각 엔트리는 **버킷 포인터** 보유       │
   ├──────────────────────────────────────────────────────────┤
   │ **④ 버킷(Bucket)** : 실제 레코드 저장 (용량 제한)          │
   ├──────────────────────────────────────────────────────────┤
   │ **⑤ 지역 깊이(Local Depth, d')**                          │
   │      각 버킷이 **실제로 구별에 사용하는 비트 수**           │
   │      · **d' = d** : 이 버킷을 가리키는 디렉터리 엔트리 1개   │
   │      · **d' < d** : **2^(d−d')개 엔트리가 이 버킷을 공유**   │
   └──────────────────────────────────────────────────────────┘

3. 구조 예시 (버킷 용량 = 2)​

   전역 깊이 d = 2  →  디렉터리 엔트리 4개(2² = 4)

   디렉터리                버킷
   ┌─────┐
   │ 00  │───┐        ┌──────────────────┐
   ├─────┤   ├───────►│ **버킷 A** (d'=1) │  ← 00, 01이 **공유**
   │ 01  │───┘        │  키: 0001, 0110  │     (d'=1 < d=2)
   ├─────┤            └──────────────────┘
   │ 10  │───────────►┌──────────────────┐
   ├─────┤            │ **버킷 B** (d'=2) │  ← 10 전용
   │ 11  │───┐        │  키: 1001        │
   └─────┘   │        └──────────────────┘
             └───────►┌──────────────────┐
                      │ **버킷 C** (d'=2) │  ← 11 전용
                      │  키: 1101, 1110  │
                      └──────────────────┘

4. 검색·삽입 동작​

   [**검색(Search)**]  — 항상 **디스크 접근 2회**(디렉터리 1 + 버킷 1)
   ① 키 → 해시값 계산 (예: h(key) = 1101 0110 …)
   ② **상위 d비트 추출** (d=2 → "11")
   ③ 디렉터리[11] → 버킷 C 포인터 획득
   ④ 버킷 C에서 레코드 탐색 → **O(1)**

   [**삽입(Insert)**]
   ① 검색과 동일하게 대상 버킷 결정
   ② 버킷에 여유 있음 → **삽입 완료**
   ③ 버킷 가득 참(Overflow) → **버킷 분할** 수행 ↓

Ⅲ. 나. 충돌 회피 기법 — 버킷 분할과 디렉터리 확장​

1. 확장성 해싱의 충돌 처리 원리​

확장성 해싱은 체이닝·개방주소법처럼 충돌을 "수용"하는 것이 아니라, 버킷을 분할하여 충돌 자체를 해소한다.

   [오버플로 발생 시 처리 분기]
   버킷이 가득 참
        │
        ├─ **Case 1 : 지역 깊이 d' < 전역 깊이 d**
        │     → **버킷만 분할**(디렉터리 확장 불필요)
        │       · d' 를 1 증가
        │       · 새 버킷 생성 후 레코드 재분배
        │       · 해당 버킷을 가리키던 디렉터리 엔트리를 두 버킷으로 재배정
        │
        └─ **Case 2 : 지역 깊이 d' = 전역 깊이 d**
              → **디렉터리를 2배 확장 후 버킷 분할**
                · d 를 1 증가 → 디렉터리 크기 2^d → 2^(d+1)
                · 기존 엔트리를 복사(포인터 복제)
                · 해당 버킷만 분할하고 d' 증가

2. Case 1 — 버킷 분할만 수행 (디렉터리 유지)​

   [분할 전]  d = 2,  버킷 A (d'=1) 가득 참
   ┌─────┐
   │ 00  │──┐     ┌─────────────────┐
   ├─────┤  ├────►│ 버킷 A (d'=1)   │ ← 가득 참
   │ 01  │──┘     │ 0001, 0110      │
   └─────┘        └─────────────────┘

   [분할 후]  **디렉터리 크기 변화 없음**, A의 d' = 2로 증가
   ┌─────┐        ┌─────────────────┐
   │ 00  │───────►│ **버킷 A** (d'=2) │ ← 앞 2비트 "00"
   ├─────┤        │ 0001            │
   │ 01  │───┐    └─────────────────┘
   └─────┘   │    ┌─────────────────┐
             └───►│ **버킷 A2**(d'=2) │ ← 앞 2비트 "01"
                  │ 0110            │
                  └─────────────────┘
   ⇒ **비용이 적은 분할** — 확장성 해싱의 효율성 핵심

3. Case 2 — 디렉터리 확장 후 버킷 분할​

   [확장 전]  d = 2,  버킷 C (d'=2) 가득 참 → d' = d 이므로 디렉터리 확장 필요
   ┌─────┐
   │ 11  │───────►│ 버킷 C (d'=2) : 1101, 1110 | 새 키 1111 삽입 시도 → 오버플로

   [확장 후]  **d = 3** → 디렉터리 크기 4 → **8**
   ┌──────┐
   │ 000  │──┐
   │ 001  │──┼──► 버킷 A  (d'=1)   ← 기존 포인터 **복제**(버킷은 그대로)
   │ 010  │──┤
   │ 011  │──┘
   │ 100  │──┬──► 버킷 B  (d'=2)
   │ 101  │──┘
   │ 110  │─────► **버킷 C** (d'=3)  ← 앞 3비트 "110" : 1101, 1110
   │ 111  │─────► **버킷 C2**(d'=3)  ← 앞 3비트 "111" : 1111
   └──────┘
   ⇒ **디렉터리만 2배가 되고, 실제 분할된 버킷은 C 하나뿐**
     (다른 버킷들은 포인터만 복제되어 재해싱 발생하지 않음)

4. 삭제 및 축소(Contraction)​

상황처리
버킷 병합두 동반 버킷(Buddy Bucket) 의 레코드 합이 한 버킷에 들어가면 병합 후 d' 감소
디렉터리 축소모든 버킷의 d' < d 가 되면 디렉터리를 절반으로 축소(d 감소)

5. 다른 충돌 해결 기법과 비교​

기법원리특징
체이닝(Chaining)충돌 시 연결 리스트로 연결구현 단순, 데이터 증가 시 체인이 길어져 성능 저하
개방 주소법(선형·이차 탐사)다른 빈 슬롯 탐색클러스터링 발생, 적재율 한계
확장성 해싱디렉터리 + 버킷 분할O(1) 유지, 전체 재해싱 불필요. 단, 디렉터리 메모리 필요
선형 해싱(Linear Hashing)디렉터리 없이 버킷을 순차적으로 분할디렉터리 오버헤드 없음, 단 오버플로 체인 일시 발생
비교 기준확장성 해싱선형 해싱
디렉터리필요(2^d 크기)불필요
분할 대상오버플로가 발생한 버킷순차적으로 정해진 버킷(오버플로와 무관)
검색 성능항상 2회 접근(균일)대체로 1회, 오버플로 시 추가
공간 효율디렉터리 메모리 소요우수
편향 데이터디렉터리 급증 가능상대적으로 안정

Ⅳ. 특징 및 활용​

구분내용
장점① 전체 재해싱 없이 점진적 확장 → 서비스 중단 없음
② 검색 시 디스크 접근 2회로 일정(O(1) 보장)
③ 오버플로 버킷만 분할하여 분할 비용 최소화
④ 데이터 감소 시 축소 가능(공간 회수)
단점① 디렉터리 저장공간 필요(2^d, 메모리 상주 필요)
② 해시값이 편향되면 디렉터리가 급격히 증가(특정 접두사 집중)
③ 디렉터리 배가 시 일시적 비용 발생
④ 범위 검색·정렬 순회 불가(해싱의 공통 한계)
활용데이터베이스 인덱스(등가 조회), 파일 시스템, 대용량 키-값 저장소, 분산 시스템의 데이터 배치
개선 방향해시 함수의 균일 분포 확보(편향 방지), 디렉터리 압축, 일관된 해싱(Consistent Hashing) 과의 조합(분산 환경)

Ⅴ. 결론​

확장성 해싱은 "전체를 다시 만들지 않고 필요한 부분만 나눈다" 는 원리로 정적 해싱의 확장성 문제를 해결한 대표적 동적 해싱 기법이며, 디렉터리와 지역 깊이라는 두 장치를 통해 대부분의 오버플로를 버킷 분할만으로 처리한다는 점이 핵심이다.

실무 적용 시에는 ① 해시 함수의 균일한 분포 확보가 성능을 좌우한다는 점(편향 시 디렉터리 폭증), ② 디렉터리가 메모리에 상주해야 O(1)이 보장된다는 점, ③ 범위 검색이 필요하면 B+트리를 선택해야 한다는 점을 함께 고려해야 한다.

즉 단건 등가 조회(=) 위주라면 확장성 해싱, 범위·정렬 조회가 필요하면 B+트리를 선택하는 것이 자료구조 설계의 기본 판단 기준이며, 디렉터리 오버헤드가 부담스러운 환경에서는 선형 해싱이 대안이 될 수 있다.
