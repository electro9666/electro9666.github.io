IT 프로젝트 관리(IT Project Management)

Ⅰ. 개요​

1. 프로젝트의 정의​

프로젝트는 고유한 제품·서비스·결과를 창출하기 위해 한시적으로 수행되는 활동이다(PMBOK). 한시성(Temporary) 과 고유성(Unique) 이라는 두 가지 본질적 특성을 가지며, 이 때문에 정형화된 운영(Operation)과 구별된다.

2. IT 프로젝트의 특수성​

   [일반 프로젝트]              [**IT 프로젝트**]
   물리적 산출물 → 진척 가시적    **무형의 소프트웨어** → 진척 파악 곤란
   요구사항 비교적 안정적         **요구사항 변경 빈번**(Scope Creep)
   기술 성숙                     **기술 변화 주기 짧음**(AI·클라우드)
   인력 대체 가능                **핵심 인력 의존도 높음**
        ⇒ IT 프로젝트는 **불확실성과 변경 관리**가 성패를 좌우

Ⅱ. 가. IT 프로젝트 관리의 개념​

1. 정의​

IT 프로젝트 관리란 정보시스템의 기획·개발·구축 프로젝트에서 이해관계자의 요구를 충족시키기 위해 지식·기술·도구·기법을 프로젝트 활동에 적용하는 관리 활동이다.

2. 관리 목표 — 제약 조건의 균형​

   [전통적 삼중 제약(Triple Constraint)]
                **범위(Scope)**
                     ╱ ╲
                   ╱     ╲
        **일정** ╱ **품질** ╲ **원가**
              (Time)      (Cost)
   ⇒ 한 요소를 변경하면 **반드시 다른 요소에 영향**
     예) 범위 확대 → 일정 지연 또는 원가 증가 또는 품질 저하

   [확장 제약 — PMBOK]
   범위·일정·원가 + **품질·자원·리스크** 의 균형

3. PMBOK 지식 영역과 성과 영역​

구분내용
10대 지식영역
(PMBOK 6판)		통합·범위·일정·원가·품질·자원·의사소통·리스크·조달·이해관계자 관리
8대 성과영역
(PMBOK 7판)		이해관계자, 팀, 개발방식·생애주기, 기획, 프로젝트 작업, 인도, 측정, 불확실성
패러다임 변화7판에서 프로세스 기반 → 원칙·성과 기반으로 전환 — 애자일·하이브리드 수용

4. 관리 방식(개발 생애주기)​

방식특징적합 상황
예측형(Waterfall)범위를 사전 확정, 순차 진행요구사항 명확·규제 산업
적응형(Agile)짧은 반복으로 점진 인도요구 불확실·변경 빈번
하이브리드인프라는 예측형, 응용은 애자일대형 공공사업 등 실무 다수

Ⅲ. 나. IT 프로젝트 관리 프로세스​

1. 5대 프로세스 그룹​

 ┌─── **① 착수(Initiating)** ───┐
 │  프로젝트 헌장, 이해관계자 식별 │
 └──────────────┬───────────────┘
 ┌──────────────▼───────────────┐
 │  **② 기획(Planning)**         │◄──────────┐
 │  범위·WBS·일정·원가·품질·      │           │ 변경 발생 시
 │  자원·의사소통·리스크·조달 계획 │           │ 재계획(반복)
 └──────────────┬───────────────┘           │
 ┌──────────────▼───────────────┐           │
 │  **③ 실행(Executing)**        │───────────┤
 │  산출물 생성, 팀 관리, 품질보증 │           │
 └──────────────┬───────────────┘           │
 ┌──────────────▼───────────────┐           │
 │  **④ 감시·통제(Monitoring)**   │───────────┘
 │  **성과 측정(EVM)**, 변경통제,  │

 └──────────────┬───────────────┘

 └──────────────────────────────┘

2. 프로세스별 주요 활동 및 산출물​

프로세스주요 활동핵심 산출물
① 착수프로젝트 목적·타당성 확인, PM 지정, 이해관계자 식별·분석프로젝트 헌장(Charter), 이해관계자 등록부
② 기획요구사항 수집 → 범위기술서 → WBS 작성(100% Rule) → 활동 정의·순서·기간 산정 → 일정(CPM) → 원가 산정·예산 → 품질·자원·의사소통·리스크·조달 계획프로젝트 관리계획서, WBS, 일정 기준선, 원가 기준선, 위험관리대장
③ 실행작업 지시·수행, 팀 확보·개발, 품질보증(QA), 정보 배포, 조달 수행인도물, 작업성과 데이터, 변경요청
④ 감시·통제EVM 기반 성과 측정, 범위·일정·원가 통제, 품질통제(QC), 통합변경통제(CCB), 리스크 감시성과보고서, 변경 승인·기각 기록, 예측치(EAC)
⑤ 종료최종 인도물 인수, 검수, 계약 종결, 자원 해제, 교훈(Lessons Learned) 정리·이관검수확인서, 최종 보고서, 교훈 저장소

3. 핵심 관리 기법​

기법내용
WBS인도물 중심 계층 분할, 100% Rule·MECE, 모든 계획의 기준
CPM(주공정법)최장 경로 산출 → 여유 없는 경로 집중 관리, 일정 단축(Crashing·Fast Tracking)
EVM(획득가치관리)SV = EV−PV, CV = EV−AC, SPI = EV/PV, CPI = EV/AC, EAC = BAC/CPI
→ 일정·원가 성과를 하나의 지표 체계로 통합 관리
리스크 관리식별 → 정성·정량 분석(P-I Matrix·몬테카를로) → 대응계획 → 감시
변경 통제CCB 승인 없는 변경 금지, 영향도 분석 후 기준선 갱신

Ⅳ. 다. 프로젝트 관리·프로그램 관리·포트폴리오 관리 비교​

1. 계층 구조​

   ┌──────────────── **포트폴리오(Portfolio)** ────────────────┐

   │  │  상호 관련된 프로젝트 묶음 → **통합 편익(Benefit)** │   │
   │  │  ┌──────────┐ ┌──────────┐ ┌──────────┐          │   │
   │  │  │**프로젝트**│ │**프로젝트**│ │**프로젝트**│          │   │
   │  │  │ 인프라 구축│ │ 응용 개발 │ │ 데이터 이행│          │   │
   │  │  │ "**일을 올바르게**"(Doing things RIGHT)│          │   │
   │  │  └──────────┘ └──────────┘ └──────────┘          │   │
   │  └──────────────────────────────────────────────────┘   │

          (전략 기여도만 있으면 됨)

2. 비교표​

비교 기준프로젝트 관리프로그램 관리포트폴리오 관리
정의고유한 결과물 산출을 위한 한시적 활동 관리상호 관련된 프로젝트 그룹의 조정 관리전략 목표 달성을 위한 프로젝트·프로그램·운영의 집합 관리
핵심 질문"일을 올바르게 하는가"
(Doing things right)		"편익을 실현하는가""올바른 일을 하는가"
(Doing the right things)
초점인도물(Deliverable) 산출편익(Benefit) 실현전략 정합성·투자 가치 극대화
범위명확히 정의되고 점진적 상세화구성 프로젝트를 포괄, 변화 수용적조직 전략 변화에 따라 지속 변동
성공 기준범위·일정·원가·품질 준수, 고객 만족통합 편익 실현, 시너지 창출투자수익률(ROI), 전략 목표 기여도, 포트폴리오 균형
관리 대상작업(Task)·자원·일정프로젝트 간 의존성·자원 충돌·인터페이스투자 우선순위·자원 배분·리스크 총량
기간한시적(명확한 시작·종료)프로젝트보다 장기상시·지속적(조직이 존속하는 한)
변화에 대한 태도변경을 통제(기준선 유지)변화를 수용·조정변화를 적극 활용(전략 재조정)
관리자 역할PM — 팀 관리, 실행 지휘프로그램 관리자 — 프로젝트 간 조정, 편익 관리포트폴리오 관리자 — 선정·우선순위·중단 결정
주요 의사결정어떻게 완수할 것인가어떤 순서·조합으로 편익을 낼 것인가무엇을 할 것인가, 무엇을 중단할 것인가
모니터링 관점진척률·성과지표(EVM)편익 실현 로드맵전략 KPI, 자원 활용률, 투자 균형
거버넌스프로젝트 스폰서·CCB프로그램 운영위원회경영진·투자심의위원회

3. IT 분야 적용 예시​

   [포트폴리오] "디지털 전환 포트폴리오"
        │  → 전략 기여도·ROI 기반으로 투자 우선순위 결정, 저성과 과제 중단
        ├─ [**프로그램**] "차세대 정보시스템 구축 프로그램"
        │       │  → 프로젝트 간 데이터·인터페이스 의존성 조정, 통합 오픈 시점 관리
        │       ├─ [프로젝트] 클라우드 인프라 구축
        │       ├─ [프로젝트] 핵심 업무 응용 개발
        │       └─ [프로젝트] 레거시 데이터 이행
        ├─ [**프로그램**] "AI 전환(AX) 프로그램"
        └─ [프로젝트] 사내 협업도구 도입 (독립 프로젝트)

4. 상호 관계 및 시사점​

관점시사점
계층적 정렬프로젝트 성공이 곧 조직 성공은 아니다 — 전략과 무관한 프로젝트는 완벽히 수행해도 가치가 없다
자원 경쟁 조정개별 프로젝트가 최적화를 추구하면 자원 충돌 발생 → 프로그램·포트폴리오 계층에서 조정 필요
중단 결정프로젝트 관리는 완수를 지향하나, 포트폴리오 관리는 "중단(Kill)" 결정이 핵심 기능
성과 측정 시점프로젝트는 종료 시점, 프로그램은 편익 실현 시점, 포트폴리오는 지속적 측정

Ⅴ. 결론​

IT 프로젝트 관리는 범위·일정·원가·품질의 제약 속에서 이해관계자 요구를 충족시키는 활동이며, 특히 IT 분야는 무형성·요구사항 변경·기술 변화라는 특수성 때문에 변경 통제와 리스크 관리가 성패를 좌우한다.

프로젝트·프로그램·포트폴리오는 계층적 보완 관계로, 프로젝트는 "일을 올바르게(효율성)", 포트폴리오는 "올바른 일을(효과성)" 담당한다. 따라서 조직은 개별 프로젝트 관리 역량뿐 아니라 전략과 프로젝트를 연결하는 상위 관리 체계를 함께 갖추어야 한다.

실무적으로는 ① WBS를 모든 계획의 기준선으로 삼고, ② EVM으로 일정·원가 성과를 정량 관리하며, ③ CCB를 통한 엄격한 변경 통제로 Scope Creep을 방지하고, ④ 요구 불확실성이 큰 영역에는 애자일을 접목한 하이브리드 방식을 적용하는 것이 효과적이다. 나아가 프로젝트 종료 시 교훈을 조직 자산으로 축적하여 후속 프로젝트에 환류하는 체계가 조직의 프로젝트 관리 성숙도를 결정한다.
