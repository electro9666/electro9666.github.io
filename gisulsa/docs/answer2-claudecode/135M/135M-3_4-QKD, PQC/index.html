양자 암호 기술 — QKD와 PQC

Ⅰ. 개요​

1. 양자 컴퓨팅의 위협​

양자컴퓨터가 실용화되면 Shor 알고리즘에 의해 소인수분해·이산대수 문제 기반의 공개키 암호(RSA·ECC·DH)가 무력화된다. 또한 Grover 알고리즘은 대칭키·해시의 안전성을 절반 수준으로 감소시킨다.

   [양자 위협의 구조]
   **Shor 알고리즘**  → RSA·ECC·DH **완전 해독 가능** (공개키 암호 붕괴)
   **Grover 알고리즘** → 대칭키·해시 **탐색 시간 √N로 단축**
                        (AES-128 → 실질 64비트, **AES-256·SHA-384 이상 권고**)

   [**HNDL 공격**(Harvest Now, Decrypt Later)]
   현재 암호문을 **미리 수집·저장** → 양자컴퓨터 확보 후 복호화
   ⇒ **장기 기밀성이 필요한 데이터는 지금 당장 대응해야 함**

2. 대응 기술의 두 갈래​

접근기술원리
물리학적 해법QKD(양자키분배)양자역학 법칙으로 도청 자체를 탐지
수학적 해법PQC(양자내성암호)양자컴퓨터로도 풀기 어려운 수학 문제 사용

Ⅱ. 가. 양자키분배(QKD: Quantum Key Distribution)​

1. 개념​

QKD는 양자역학의 원리를 이용하여 두 사용자가 안전하게 비밀키를 공유하는 기술이다. 암호화 자체가 아니라 키를 안전하게 나누어 갖는 과정에 초점을 두며, 도청 시도가 있으면 물리적으로 반드시 흔적이 남아 탐지된다.

2. 이론적 기반​

양자역학 원리QKD에서의 역할
불확정성 원리(Heisenberg)양자 상태를 측정하면 상태가 교란되어 원래 값을 알 수 없음
복제 불가능 정리(No-Cloning)미지의 양자 상태는 완벽히 복제할 수 없음 → 도청자가 몰래 복사 불가
양자 얽힘(Entanglement)얽힌 입자 간 상관관계 이용(E91 프로토콜)

3. 동작 원리 — BB84 프로토콜​

   [송신자 Alice]                              [수신자 Bob]
   ① 무작위 비트 + 무작위 기저(+, ×) 선택
      → **광자(Photon)의 편광 상태로 인코딩**하여 전송
                    ──── 양자 채널 ────►
                                          ② 무작위 기저로 측정
   ③ ◄─── **공개 채널**로 사용한 기저만 공개(비트값은 비공개) ───►
   ④ **기저가 일치한 경우의 비트만 남김**(약 50%) → **원시 키(Raw Key)**
   ⑤ 일부 비트를 공개 비교 → **오류율(QBER) 측정**
        │
        ├─ QBER 낮음 → 도청 없음 → 오류정정·**보안성 증폭** → **최종 비밀키**
        └─ **QBER 높음 → 도청 탐지 → 키 폐기 후 재수행**
   ⑥ 확보된 키로 **대칭키 암호(AES) 또는 One-Time Pad** 통신

   ※ 도청자 Eve가 광자를 측정하면 **복제 불가·측정 교란**으로 오류율이 상승
     → **도청 사실이 물리적으로 드러남**

4. 주요 기술 및 특징​

구분내용
프로토콜BB84(편광 기반, 최초·대표), B92, E91(얽힘 기반), CV-QKD(연속변수)
전송 매체광섬유(수십~수백 km), 위성 QKD(중국 묵자호 — 장거리 실현)
핵심 장비단일광자 생성·검출기, 양자 난수 생성기(QRNG), 양자 중계기
장점정보이론적 안전성(계산 능력과 무관), 도청 탐지 가능, 양자컴퓨터에도 안전
한계① 전송 거리 제약(광자 손실, 중계기 미성숙)
② 전용 광케이블·장비 필요 → 고비용
③ 점대점(P2P) 통신만 가능 — 인터넷 전면 적용 곤란
④ 인증 문제 — 중간자 공격 방지를 위해 별도의 인증 수단 필요
⑤ 장비 구현상의 부채널 공격 취약점

Ⅲ. 나. 양자내성암호(PQC: Post-Quantum Cryptography)​

1. 개념​

PQC는 양자컴퓨터로도 효율적으로 풀 수 없다고 알려진 수학적 난제에 기반한 차세대 공개키 암호 알고리즘이다. 기존 통신 인프라를 그대로 사용하면서 알고리즘만 교체하면 되므로 현실적 대응책으로 평가된다.

2. 기반 수학 문제 및 알고리즘 계열​

계열기반 난제특징대표 알고리즘
격자 기반(Lattice)최단 벡터 문제(SVP), LWE성능·크기 균형 우수 → 주력 채택CRYSTALS-Kyber, Dilithium
해시 기반(Hash)해시 함수의 일방향성안전성 신뢰도 높음, 서명 크기 큼SPHINCS+, XMSS
부호 기반(Code)오류 정정 부호 복호 문제오랜 검증 이력, 키 크기 매우 큼Classic McEliece
다변수 기반(Multivariate)다변수 2차 방정식서명 짧음, 일부 방식 안전성 논란Rainbow(해독됨)
동종사상 기반(Isogeny)타원곡선 동종사상키 작음, SIKE 해독으로 신뢰 하락SIKE(2022 해독)

3. NIST 표준화 현황​

   [NIST PQC 표준화 경과]
   2016 공모 시작 → 3라운드 평가 → **2022년 최종 선정** → **2024년 8월 표준 공표**

   ┌─────────────────────────────────────────────────────────┐
   │ **FIPS 203 : ML-KEM**  (CRYSTALS-Kyber 기반)             │
   │   → **키 캡슐화(KEM)** — 키 교환용, **주력 표준**          │
   │ **FIPS 204 : ML-DSA**  (CRYSTALS-Dilithium 기반)         │
   │   → **전자서명** — 주력 표준                              │
   │ **FIPS 205 : SLH-DSA** (SPHINCS+ 기반)                   │
   │   → 전자서명 — **해시 기반 백업 옵션**(격자 문제 대비)     │
   │ (추가) FN-DSA(Falcon) — 서명, 표준화 진행 중             │
   └─────────────────────────────────────────────────────────┘

4. 특징​

구분내용
장점① 기존 인프라·프로토콜에 소프트웨어 교체만으로 적용
② 거리 제약 없음 — 인터넷 전 구간 적용 가능
③ 저비용(전용 장비 불필요), 다자간 통신 가능
④ 인증 기능 자체 제공(전자서명)
한계① 계산적 안전성 — 새로운 수학적 공격 발견 시 무력화 가능(SIKE·Rainbow 해독 사례)
② 키·서명 크기 증가 → 대역폭·저장공간 부담, 임베디드·IoT 제약
③ 성능 오버헤드, 구현 부채널 공격 가능성
④ 전환 과정의 복잡성과 비용

Ⅳ. 다. QKD와 PQC 비교​

1. 종합 비교표​

비교 기준QKD(양자키분배)PQC(양자내성암호)
기반 원리양자물리 법칙(불확정성·복제불가)수학적 난제(격자·해시·부호)
안전성 근거정보이론적 안전성(무조건적)계산적 안전성(조건부)
양자컴퓨터 대응원리적으로 안전현재까지 안전(새 공격 발견 시 위험)
도청 탐지가능(물리적으로 흔적 발생)불가능(사후 탐지 불가)
적용 대상키 분배(교환)만키 교환 + 전자서명·인증
인프라 요구전용 광케이블·양자 장비 필수기존 인프라 그대로 사용
거리 제약있음(수십~수백 km, 중계기 필요)없음(인터넷 전역)
비용매우 높음(장비·회선)낮음(SW 교체 중심)
통신 형태점대점(P2P) 중심다자간·전역 가능
인증(MITM 방어)별도 인증 수단 필요(자체 인증 불가)자체 제공(서명)
표준화ITU-T·ETSI 규격화 진행NIST FIPS 203/204/205 확정(2024)
성숙도·상용화실증·특수망 중심(국방·금융 전용회선)상용 전환 본격화(TLS·브라우저 적용)
주요 한계거리·비용·인증·확장성키 크기·성능·수학적 안전성 불확실

2. 상호 보완 관계​

   [QKD와 PQC는 경쟁이 아닌 **역할 분담**]

   **QKD** : "물리적으로 보호된 특정 구간의 키 분배"
        → 국방·정부 전용망, 금융 기관 간 백본, 데이터센터 간 연결
             ▲ 고비용·거리 제약을 감수할 만큼 **기밀성이 절대적인 구간**

   **PQC** : "인터넷 전역의 범용 암호"
        → 웹(TLS), 전자서명, 코드 서명, IoT, 모바일
             ▲ **거리·비용 제약 없이 광범위 적용**

   [**하이브리드 접근**]
   ① QKD로 분배한 키를 **PQC 인증과 결합**하여 중간자 공격 방어
   ② TLS에서 **기존 ECDH + PQC(ML-KEM) 동시 사용**
      → 어느 한쪽이 깨져도 안전(현재 브라우저·CDN 실제 적용 중)

Ⅴ. 전환 전략 및 고려사항​

단계내용
① 암호 자산 식별(Crypto Inventory)조직 내 어떤 시스템이 어떤 암호를 사용하는지 전수 파악 — 전환의 출발점
② 위험 우선순위 결정데이터의 기밀 유지 필요 기간을 기준으로 우선순위 산정
→ 장기 보존 데이터(의료·국방·금융)는 HNDL 공격 대응을 위해 최우선 전환
③ 하이브리드 전환기존 알고리즘 + PQC 병행 적용(안전성 보수적 확보), 상호운용성 검증
④ Crypto-Agility 확보암호 알고리즘을 쉽게 교체할 수 있는 구조로 설계 — 향후 PQC 알고리즘이 깨질 경우 대비
⑤ 공급망 대응하드웨어·상용SW·인증서 체계(PKI)의 벤더 로드맵 확인
⑥ 성능 검증키·서명 크기 증가에 따른 대역폭·지연·저장공간 영향 측정
국내 동향내용
정책과기정통부·국정원 양자내성암호 전환 마스터플랜 추진, 2035년 전환 목표
검증KCMVP 등 검증필 암호모듈 체계의 PQC 확대
산업통신사 중심 QKD 실증망 구축, 금융·국방 시범 적용

Ⅵ. 결론​

양자 위협에 대한 대응은 먼 미래의 과제가 아니라 현재의 과제이다. HNDL 공격으로 인해 오늘 전송한 암호문이 미래에 복호화될 수 있으므로, 장기 기밀성이 요구되는 데이터는 즉시 대응해야 한다.

QKD와 PQC는 경쟁 기술이 아니라 적용 영역이 다른 상호 보완 관계이다. QKD는 물리적 안전성이 절대적으로 필요한 특정 구간(국방·기관 간 백본) 에, PQC는 인터넷 전역의 범용 암호 체계에 각각 적합하며, 실제로는 QKD의 인증 취약점을 PQC로 보완하는 결합 방식이 유효하다.

실무 전환 전략의 핵심은 ① 암호 자산 전수 식별, ② 데이터의 기밀 유지 기간에 따른 우선순위 결정, ③ 기존 알고리즘과 PQC의 하이브리드 적용, 그리고 무엇보다 ④ Crypto-Agility 확보이다. PQC 역시 계산적 안전성에 기반하므로 언젠가 깨질 수 있다는 전제하에, 알고리즘을 신속히 교체할 수 있는 아키텍처를 갖추는 것이 가장 근본적인 대비책이다.
