크리덴셜 스터핑

문제​

10.크리덴셜 스터핑(Credential stuffing)

Ⅰ. 개요​

크리덴셜 스터핑(Credential Stuffing) 은 다른 사이트에서 유출된 계정정보(ID/PW) 목록을 확보한 뒤, 이를 자동화 봇으로 다수의 다른 사이트 로그인에 대량 대입하여 계정을 탈취하는 공격이다. 사용자의 계정 재사용(Password Reuse) 습관을 악용한다는 점에서, 취약점이 아니라 정상적인 로그인 기능을 그대로 이용하는 공격이라는 특징이 있다.

   [배경]
   · 대규모 개인정보 유출 사고 빈발 → **다크웹에 유출 DB 유통**
   · 사용자의 **약 60~70%가 동일 비밀번호를 여러 사이트에 재사용**
   · **자동화 도구**(Sentry MBA, OpenBullet) + **프록시/봇넷** 대중화
   · 로그인 API는 **정상 기능**이므로 시그니처 기반 탐지 곤란
        ▼
   [**크리덴셜 스터핑**]
   · **성공률은 0.1~2%로 낮으나**, 대입 규모가 수백만 건이므로
     **절대적 탈취 계정 수는 매우 큼**

Ⅱ. 공격 절차 및 유사 공격과의 구분​

 ┌─────────── **크리덴셜 스터핑 공격 절차** ───────────┐
 │                                                     │
 │  **① 크리덴셜 수집**                                 │
 │     다크웹·해킹 포럼에서 **유출 계정 DB 구매/수집**   │
 │     (Combo List : id:pw 형태 수백만~수억 건)         │
 │           ▼                                         │
 │  **② 대상 선정·정찰**                                │
 │     로그인 API 구조·응답 분석, **CAPTCHA 유무 확인**  │
 │           ▼                                         │
 │  **③ 자동화 도구 설정**                              │
 │     봇 스크립트 + **프록시/봇넷으로 IP 분산**         │
 │     + **User-Agent 위조**, 요청 간격 랜덤화           │
 │           ▼                                         │
 │  **④ 대량 로그인 시도**(Stuffing)                    │
 │     성공/실패 응답 차이로 **유효 계정 식별**          │
 │           ▼                                         │
 │  **⑤ 계정 탈취 후 악용**(Account Takeover, ATO)      │
 │     · 포인트·마일리지·상품권 **환금**                 │
 │     · 등록 카드로 **부정 결제**                       │
 │     · 개인정보 추가 수집 → **2차 피싱·사기**          │
 │     · 계정 자체를 **재판매**                          │
 └─────────────────────────────────────────────────────┘
비교 기준크리덴셜 스터핑무차별 대입(Brute Force)패스워드 스프레이
입력 데이터유출된 실제 ID/PW 쌍가능한 모든 조합 생성흔한 비밀번호 소수
대입 방식1계정 1~2회 시도1계정에 수만 회 시도다수 계정에 동일 PW 시도
성공률0.1~2%(낮지만 대량)매우 낮음(강한 PW 시)낮음
탐지 난이도높음(계정별 실패 1회)낮음(계정 잠금에 걸림)중간
차단 대응계정 잠금 효과 제한적계정 잠금이 효과적IP·계정 상관분석 필요
핵심 원인비밀번호 재사용약한 비밀번호약한·기본 비밀번호

Ⅲ. 대응 방안​

 ┌──────────── **다계층 방어(Defense in Depth)** ────────────┐
 │                                                            │
 │  **① 인증 강화** ── **MFA·FIDO2**(가장 효과적)             │
 │           ▼                                                │
 │  **② 봇 탐지·차단** ── CAPTCHA · **디바이스 핑거프린팅**    │
 │           ▼                                                │
 │  **③ 속도·이상행위 제어** ── Rate Limit · **위험기반 인증** │
 │           ▼                                                │
 │  **④ 크리덴셜 위생** ── **유출 PW 대조**·재사용 차단        │
 │           ▼                                                │
 │  **⑤ 탐지·대응** ── 로그인 이상탐지 · **이상거래탐지(FDS)** │
 └────────────────────────────────────────────────────────────┘
대응 계층세부 방안
① 인증 강화(근본)· MFA(다중요소인증) 적용 — 크리덴셜 스터핑의 가장 확실한 차단책
· FIDO2/패스키(Passkey) — 비밀번호 자체를 제거, 피싱 내성
· 고위험 거래 시 재인증(Step-up Authentication)
② 봇 탐지·차단· CAPTCHA / reCAPTCHA v3(위험 점수 기반, UX 저해 최소화)
· 디바이스 핑거프린팅, JS 챌린지
· 봇 관리 솔루션·WAF, 위협 인텔리전스 기반 악성 IP·프록시 차단
③ 속도·위험 기반 제어· Rate Limiting — IP·계정·세션 단위 시도 횟수 제한
· 적응형/위험기반 인증(RBA) — 신규 IP·해외 접속·낯선 디바이스 시 추가 인증
· 점진적 지연(Exponential Backoff), 계정 잠금(단, DoS 악용 주의)
④ 크리덴셜 위생· 유출 비밀번호 DB 대조(Have I Been Pwned 등) → 가입·변경 시 차단
· 비밀번호 재사용 금지 안내, 패스워드 관리자 사용 권장
· 유출 정황 계정 강제 비밀번호 재설정
· NIST SP 800-63B 권고 — 길이 중심, 주기적 강제 변경은 지양
⑤ 탐지·모니터링· 로그인 실패율 급증·분산 IP 패턴 실시간 탐지(SIEM)
· 성공 로그인의 이상 징후 분석(불가능한 이동, 다중 계정 동일 디바이스)
· FDS 연계 — 탈취 후 부정 결제·포인트 환금 차단
· 사용자에게 로그인 알림·최근 접속 이력 제공
⑥ 응답 설계· 로그인 실패 메시지를 "아이디 또는 비밀번호가 올바르지 않습니다" 로 통일
→ 계정 존재 여부 노출(User Enumeration) 방지
법·제도 관점내용
개인정보보호법안전성 확보조치 — 접근통제·접속기록 보관, 침해사고 시 신고·통지 의무
ISMS-P인증 및 권한관리, 이상행위 탐지·대응 통제항목
책임 소재사업자 자체는 해킹당하지 않았더라도, 탐지·차단 조치 미흡 시 관리 책임 인정 사례 존재

Ⅳ. 특징 및 시사점​

구분내용
공격의 특징· 취약점이 아닌 정상 기능 악용 → 패치로 해결 불가
· 자사 보안이 완벽해도 타사 유출로 피해 발생(외부 의존적 리스크)
· 계정당 시도 횟수가 적어 전통적 계정 잠금 정책 무력화
· AI·프록시 발전으로 봇 탐지 우회 고도화
피해 영향포인트·마일리지 탈취, 부정 결제, 개인정보 2차 유출, 브랜드 신뢰 훼손, 집단분쟁·과징금
주요 표적이커머스·항공 마일리지·게임 아이템·OTT 구독·간편결제 등 환금성 높은 서비스

Ⅴ. 결론​

크리덴셜 스터핑은 시스템의 취약점이 아니라 사용자의 비밀번호 재사용 습관을 공격 표면으로 삼는다는 점에서 기존 웹 공격과 근본적으로 다르다. 즉 자사 시스템에 아무런 취약점이 없어도 타사에서 발생한 유출로 인해 피해를 입을 수 있는 구조적 위협이므로, 패치나 취약점 진단만으로는 결코 방어할 수 없다.

가장 효과적인 대응은 비밀번호 하나에 인증을 의존하지 않는 것이다. MFA를 적용하면 유출된 크리덴셜이 정확하더라도 로그인이 차단되며, 궁극적으로는 FIDO2/패스키를 통해 비밀번호 자체를 제거하는 것이 근본 해법이다.

다만 전 사용자에게 MFA를 강제하면 이탈률이 증가하므로, 실무적으로는 평상시에는 마찰 없는 로그인을 제공하되 위험 점수가 높은 시도(신규 디바이스·해외 IP·비정상 속도)에만 추가 인증을 요구하는 위험기반 인증(RBA) 이 보안과 사용성의 균형점이다. 여기에 유출 비밀번호 DB 대조를 통한 사전 차단과 탈취 이후 단계를 막는 FDS 연계를 결합한 다계층 방어가 필요하다.
