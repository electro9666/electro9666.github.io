파운데이션 모델

문제​

4.인공지능 분야에서 파운데이션(Foundation) 모델의 개념, 특징, 기반기술 및 구현시 법적·환경적·사회적 측면의 고려사항에 대하여 설명하시오.

Ⅰ. 파운데이션 모델의 개념​

1. 정의​

파운데이션 모델(Foundation Model) 은 대규모의 광범위한 데이터를 자기지도학습(Self-supervised Learning)으로 사전학습하여, 다양한 하위 과업(Downstream Task)에 적응(Adaptation)시킬 수 있는 범용 기반 인공지능 모델이다. 2021년 스탠퍼드 HAI(CRFM) 가 처음 명명하였다.

   [**패러다임 전환 — Task별 모델에서 범용 기반 모델로**]

   **[기존] Task-specific 모델**
   번역 데이터 ──▶ 번역 모델
   요약 데이터 ──▶ 요약 모델      ⇒ **과업마다 별도 데이터·모델**
   분류 데이터 ──▶ 분류 모델         (데이터 수집·학습 비용 반복)

   **[전환] Foundation Model**
                     ┌──▶ 번역 (Fine-tuning / Prompting)
   **대규모 데이터**   │
   (텍스트·이미지) ──▶ **파운데이션** ──┼──▶ 요약
   **자기지도학습**    **모델**        ├──▶ 분류
   (라벨 불필요)                     ├──▶ 코드 생성
                                     └──▶ 질의응답
   ⇒ **한 번 학습, 다양하게 활용**(One Model, Many Tasks)
   ⇒ **범용성(Homogenization) + 창발성(Emergence)**

2. 등장배경​

배경내용
아키텍처 혁신Transformer(2017, "Attention is All You Need") — 병렬 처리 가능, 대규모 확장에 적합
자기지도학습라벨링 없이 원시 데이터 자체에서 학습 신호 생성 → 인터넷 규모 데이터 활용 가능
컴퓨팅 발전GPU/TPU 대규모 클러스터, 분산 학습 기술 성숙
스케일링 법칙모델·데이터·컴퓨팅을 키우면 성능이 예측 가능하게 향상(Kaplan et al., Chinchilla)
창발적 능력 발견일정 규모 이상에서 학습하지 않은 능력이 갑자기 출현(In-context Learning, 추론)

3. 주요 파운데이션 모델​

유형대표 모델
언어(LLM)GPT 시리즈(OpenAI), Claude(Anthropic), Gemini(Google), LLaMA(Meta), HyperCLOVA X(네이버), Exaone(LG)
비전CLIP, DINOv2, SAM(Segment Anything)
생성(이미지)Stable Diffusion, DALL·E, Midjourney
멀티모달GPT-4o, Gemini, Claude — 텍스트·이미지·음성 통합
코드Codex, Code Llama
과학·바이오AlphaFold(단백질 구조 예측)

Ⅱ. 파운데이션 모델의 특징​

1. 핵심 특징​

 ┌────────── **파운데이션 모델의 5대 특징** ──────────┐
 │                                                    │
 │ **① 대규모성(Scale)**                               │
 │    · **파라미터 수십억~수조 개**                     │
 │    · 학습 데이터 **수조 토큰**, 컴퓨팅 수천 GPU·개월  │
 │    · **스케일링 법칙** — 규모↑ → 성능↑(예측 가능)     │
 │                                                    │
 │ **② 범용성(Generality / Homogenization)**           │
 │    · **하나의 모델이 다수 과업 수행**                │
 │    · 과업별 재학습 없이 **프롬프트만으로 적응**       │
 │    · 단점 : **단일 실패점** — 모델 결함이 전 분야 전파 │
 │                                                    │
 │ **③ 창발성(Emergence)**                             │
 │    · 규모가 임계점을 넘으면 **학습하지 않은 능력 출현**│
 │    · **In-context Learning**(예시만 보고 수행)       │
 │    · **CoT 추론**(단계적 사고), 산술·다국어 능력      │
 │    · ⇒ **예측 불가능성** → 안전성 검증의 어려움       │
 │                                                    │
 │ **④ 적응성(Adaptability)**                          │
 │    · **Fine-tuning · PEFT(LoRA) · 프롬프트 · RAG**   │
 │    · 소량 데이터로 **특정 도메인 특화** 가능          │
 │                                                    │
 │ **⑤ 멀티모달성(Multimodality)**                     │
 │    · 텍스트·이미지·음성·영상을 **통합 표현 공간에**    │
 │    · 모달 간 변환·이해(이미지 설명, 음성 대화)        │
 └────────────────────────────────────────────────────┘

2. 특징의 양면성​

특징긍정적 측면부정적 측면
대규모성높은 성능·일반화 능력막대한 비용·전력, 소수 빅테크 독점
범용성개발 생산성 획기적 향상단일 실패점 — 편향·결함이 전 산업 전파
창발성예상 못한 유용한 능력예측 불가 → 안전성 사전 검증 곤란
적응성도메인 특화 용이파인튜닝으로 안전장치 무력화 가능
멀티모달성풍부한 상호작용딥페이크 등 오남용 위험 확대

3. 기존 AI 모델과의 비교​

비교 기준기존 AI 모델파운데이션 모델
학습 데이터과업별 라벨링 데이터대규모 비라벨 데이터(자기지도)
적용 범위단일 과업다수 과업(범용)
개발 방식과업마다 처음부터 학습사전학습 + 적응
데이터 요구량과업당 대량 라벨 필요소량(Few-shot) 또는 불필요(Zero-shot)
파라미터 규모수백만~수천만수십억~수조
개발 주체개별 기업·연구실빅테크·국가 단위(자본 집약)
성능 한계과업 데이터에 종속창발적 능력 발현

Ⅲ. 파운데이션 모델의 기반기술​

1. 전체 기술 스택​

 ┌──────── **파운데이션 모델 기술 스택** ────────┐
 │                                               │
 │ **[응용·적응 계층]**                           │
 │  **프롬프트 엔지니어링** · **RAG** · Agent      │
 │  **Fine-tuning / PEFT(LoRA)** · Function Call │
 │                    ▲                          │
 │ **[정렬(Alignment) 계층]**                     │
 │  **SFT**(지도 미세조정) · **RLHF/RLAIF**        │

 │ **[모델 아키텍처 계층]**                        │

 │  **분산학습**(데이터·모델·파이프라인 병렬)      │

 │ **[인프라 계층]**                               │
 │  **GPU/TPU 클러스터** · 고속 인터커넥트         │
 │  **분산 스토리지** · MLOps · 체크포인팅         │
 │                    ▲                          │
 │ **[데이터 계층]**                               │
 │  **웹 크롤링 코퍼스**(Common Crawl) · 정제·중복제거│
 │  **토크나이제이션** · 데이터 큐레이션           │
 └───────────────────────────────────────────────┘

2. 핵심 기반기술 상세​

가. Transformer 아키텍처​

   [**Self-Attention 메커니즘 — 핵심 원리**]

   입력 : "은행 에서 돈 을 인출 했다"
                ▲
   각 단어가 **모든 단어와의 관련도(Attention)** 를 계산
                ▼
   **Attention(Q,K,V) = softmax(QKᵀ / √d_k) · V**
   · **Q**(Query) : 내가 찾는 정보
   · **K**(Key)   : 각 단어가 가진 색인
   · **V**(Value) : 실제 전달할 정보

   ⇒ "은행"이 "돈·인출"과 강하게 연결 → **문맥적 의미 파악**
   ⇒ RNN과 달리 **순차 처리 불필요 → 완전 병렬화**
     ⇒ **대규모 학습이 가능해진 결정적 이유**

   [주요 구성]
   · **Multi-Head Attention** — 여러 관점에서 동시 주목
   · **Positional Encoding** — 순서 정보 부여
   · **Feed Forward Network** · Layer Normalization · Residual
아키텍처 유형특징대표 모델
Encoder-only양방향 문맥 이해 → 분류·이해BERT
Decoder-only다음 토큰 예측 → 생성GPT·LLaMA·Claude
Encoder-Decoder입력 이해 + 출력 생성 → 번역·요약T5, BART
MoE(Mixture of Experts)토큰마다 일부 전문가만 활성화 → 파라미터 대비 연산 효율Mixtral, GPT-4 계열(추정)

나. 학습 기술​

기술내용
자기지도학습
(Self-supervised)		· Causal LM : 다음 토큰 예측(GPT 계열)
· MLM : 마스킹된 토큰 복원(BERT)
· 대조학습 : 이미지-텍스트 쌍 정렬(CLIP)
⇒ 라벨링 없이 인터넷 규모 데이터 학습 가능
분산 학습· 데이터 병렬(DP/FSDP) — 데이터를 나눠 처리
· 모델 병렬(Tensor Parallel) — 모델을 나눠 배치
· 파이프라인 병렬 — 레이어를 단계별 분할
· ZeRO — 옵티마이저 상태 분산으로 메모리 절감
스케일링 법칙손실(Loss)은 모델 크기·데이터량·컴퓨팅의 멱법칙으로 감소
Chinchilla 법칙 — 모델 크기와 데이터량의 최적 비율 존재
효율화 기법Mixed Precision(FP16/BF16), Flash Attention, Gradient Checkpointing

다. 정렬(Alignment) 기술​

   [**정렬 파이프라인 — 유용하고 안전한 모델 만들기**]

   **① 사전학습(Pre-training)**
      대규모 코퍼스로 **언어 능력 습득**
      ⇒ 아직 "도움이 되도록" 학습되지 않음
              ▼
   **② SFT**(Supervised Fine-Tuning, 지도 미세조정)
      고품질 **지시-응답 쌍**으로 학습
      ⇒ 지시를 따르는 능력 습득
              ▼
   **③ 선호 학습**(Preference Learning)
      · **RLHF** — 인간 선호 데이터로 **보상모델** 학습 후 강화학습(PPO)
      · **RLAIF** — AI가 피드백 생성(Constitutional AI)
      · **DPO** — 보상모델 없이 **직접 선호 최적화**(단순·안정)
      ⇒ **유용성(Helpful)·정직성(Honest)·무해성(Harmless)** 확보
              ▼
   **④ 가드레일·안전장치**
      입출력 필터링, **레드팀 테스트**, 시스템 프롬프트

라. 적응(Adaptation) 기술​

기술내용특징
프롬프트 엔지니어링Zero/Few-shot, CoT(단계적 사고), ReAct학습 불필요, 즉시 적용
RAG
(검색증강생성)		외부 지식베이스 검색 → 근거와 함께 생성환각 감소, 최신 정보 반영, 출처 제시
Fine-tuning도메인 데이터로 전체 파라미터 재학습성능 높음, 비용·자원 큼
PEFT / LoRA일부 저랭크 행렬만 학습(0.1~1% 파라미터)비용 대폭 절감, 다중 어댑터 운용
Function Calling / Agent외부 도구·API 호출로 행동 수행실제 업무 자동화
모델 경량화양자화(INT8/INT4), 지식 증류, 프루닝온디바이스·엣지 배포

Ⅳ. 구현 시 고려사항​

1. 법적 측면​

 ┌────────── **법적 쟁점 지도** ──────────┐
 │                                        │
 │ **[학습 단계]**                         │
 │  · **저작권** — 웹 크롤링 데이터 적법성  │
 │  · **개인정보** — 학습데이터 내 개인정보 │
 │  · **TDM 면책** 범위                    │
 │            ▼                           │
 │ **[모델 단계]**                         │
 │  · **모델 자체의 지식재산권** 귀속       │
 │  · 오픈소스 **라이선스 준수**(LLaMA 등)  │
 │            ▼                           │
 │ **[서비스 단계]**                       │
 │  · **생성물의 저작권** 귀속·침해 여부    │
 │  · 프롬프트 입력 데이터의 **재학습 여부** │
 │  · **책임 소재**(제공자 vs 이용자)       │
 │            ▼                           │
 │ **[규제 준수]**                         │
 │  · **EU AI Act** GPAI 의무              │
 │  · **韓 AI 기본법**(2026 시행)           │
 └────────────────────────────────────────┘
법적 쟁점내용대응 방안
① 저작권 침해· 웹 크롤링 데이터의 무단 이용

Ⅴ. 결론​

파운데이션 모델은 "과업마다 모델을 만드는" 기존 AI 개발 방식을 "하나의 범용 모델을 다양하게 적응시키는" 방식으로 전환한 패러다임 혁신이다. 그 핵심 동력은 Transformer 아키텍처가 제공한 병렬 학습 가능성과 자기지도학습이 열어준 인터넷 규모 데이터 활용, 그리고 스케일링 법칙이 보장한 예측 가능한 성능 향상이라는 세 요소의 결합이다.

그러나 파운데이션 모델의 가장 중요한 특성은 범용성이 곧 위험의 집중을 의미한다는 점이다. 하나의 모델이 의료·금융·교육·법률에 모두 사용되므로, 모델에 내재된 편향이나 결함은 특정 분야에 국한되지 않고 전 산업으로 동시에 전파된다. 스탠퍼드 HAI가 이를 동질화(Homogenization)의 위험이라 지적한 이유이며, 이것이 파운데이션 모델에 대해 개별 AI 시스템보다 훨씬 엄격한 안전성·투명성 요구가 제기되는 근거이다.

창발성 역시 양면적이다. 규모가 임계점을 넘으면 학습하지 않은 능력이 출현하는 현상은 기술적 성취인 동시에 "무엇을 할 수 있는지 사전에 알 수 없다" 는 근본적 안전성 문제를 야기한다. 전통적 소프트웨어처럼 명세 기반 검증이 불가능하므로, 레드팀 테스트·안전 벤치마크·배포 후 모니터링이라는 경험적 접근에 의존할 수밖에 없다.

법적 측면에서 가장 시급한 쟁점은 학습데이터의 저작권과 개인정보이다. NYT vs OpenAI 소송이 상징하듯 웹 크롤링 데이터의 적법성은 아직 결론이 나지 않았으며, EU AI Act가 GPAI 제공자에게 학습데이터 요약 공개를 의무화하면서 투명성 요구는 법적 강제 사항이 되었다. 우리나라도 AI 기본법(2026 시행) 으로 생성형 AI 표시 의무와 고영향 AI 규율을 도입하므로, 도입 기업은 모델 카드·데이터시트 확보와 규제 매핑을 선제적으로 준비해야 한다.

환경적 측면에서 실무자가 자주 간과하는 사실은 누적 환경 부하가 학습보다 추론에서 훨씬 크다는 점이다. 학습은 1회성이지만 추론은 서비스 수명 내내 수십억 건 발생하므로, 과업 난이도에 맞는 적정 크기 모델 라우팅, 프롬프트 캐싱, 양자화·경량화가 비용 절감인 동시에 실질적 탄소 저감 수단이 된다. "무조건 큰 모델"이 아니라 목적에 맞는 최소 모델을 선택하는 것이 기술적·환경적으로 모두 옳다.

사회적으로는 언어·문화 주권 문제가 우리나라에 특히 중요하다. 영어·서구 중심 데이터로 학습된 모델은 한국어 성능뿐 아니라 한국의 사회적 맥락과 가치 판단에서 편향을 보일 수 있으므로, HyperCLOVA X·Exaone 같은 소버린 AI 역량 확보는 산업 경쟁력을 넘어 문화적 자율성의 문제이다.

실무 도입 전략으로는 자체 개발은 극소수만 가능하므로, 대부분의 기업에게는 "상용 API + RAG" 또는 "오픈소스 모델 + LoRA 파인튜닝"이 현실적 선택이다. 판단 기준은 데이터 민감도·비용·성능 요구·규제 준수·내부 MLOps 역량의 다섯 축이며, 민감 업무는 온프레미스 sLLM으로, 일반 업무는 상용 API로 처리하는 하이브리드 구조가 균형점이 된다. 어떤 방식을 택하든 RAG를 통한 환각 억제와 중요 의사결정에 대한 인간 검토 게이트는 반드시 확보되어야 하며, 이것이 파운데이션 모델을 실제 업무에 안전하게 적용하는 최소 요건이다.
