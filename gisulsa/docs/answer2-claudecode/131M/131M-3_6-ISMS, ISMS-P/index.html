ISMS, ISMS-P

문제​

6.정보보호 및 개인정보보호 인증제도(ISMS, Information Security Management System)에 대하여 다음을 설명하시오.
가.ISMS와 ISMS-P 차이점
나.ISMS 의무 대상 기준

Ⅰ. 개요​

1. 개념​

구분개념
ISMS
(정보보호 관리체계)		조직의 정보자산을 보호하기 위해 수립·운영하는 정보보호 관리체계가 인증 기준에 적합한지 심사하여 인증을 부여하는 제도
ISMS-P
(정보보호 및 개인정보보호 관리체계)		ISMS의 정보보호 관리체계에 더하여, 개인정보의 생애주기(수집~파기) 전반에 대한 보호조치까지 포함하여 인증하는 제도

2. 제도 연혁 및 근거​

   [제도 연혁]

   **2001** 정보보호 관리체계(**ISMS**) 인증 시행 — 방송통신위원회
        ▼
   **2011** 개인정보보호 관리체계(**PIMS**) 인증 도입 — 행정안전부
        ▼
   **2013** PIPL 인증 신설 → **인증제도 중복·기업 부담 논란**
        ▼
   **2018.11** ★**ISMS-P로 통합**★
     · ISMS + PIMS 통합, **과기정통부·개인정보보호위원회 공동 고시**
     · 인증기관 : **KISA**, 금융보안원 등
        ▼
   **2023~** 인증기준 개정(융합·클라우드 반영), **간편인증** 도입 논의

   [법적 근거]
   · **정보통신망법 제47조**(정보보호 관리체계 인증)
   · **개인정보보호법 제32조의2**(개인정보보호 인증)
   · **정보보호 및 개인정보보호 관리체계 인증 등에 관한 고시**

3. 인증체계 구조​

 ┌──────── **ISMS-P 인증 운영 체계** ────────┐
 │                                           │
 │ **[정책기관]**                             │
 │  과학기술정보통신부 · **개인정보보호위원회** │
 │        ▼ (제도 총괄·고시)                  │
 │ **[인증기관]**                             │
 │  **KISA**(한국인터넷진흥원) · 금융보안원   │
 │        ▼ (인증서 발급·사후관리)            │
 │ **[심사기관]**                             │
 │  KISA · 금융보안원 · **한국정보통신진흥협회**│
 │  · 한국정보통신기술협회(TTA) · 개인정보보호협회│
 │        ▼ (심사 수행)                       │
 │ **[신청기관]**                             │
 │  의무 대상 기업 · 자율 신청 기업            │

Ⅱ. ISMS와 ISMS-P의 차이점​

1. 인증기준 체계 비교​

 ┌──────────── **ISMS / ISMS-P 인증기준 구조** ────────────┐
 │                                                          │
 │ **[1. 관리체계 수립 및 운영]** — **16개 항목**             │
 │   1.1 관리체계 기반 마련 (6)                             │
 │   1.2 위험관리 (4)                                       │
 │   1.3 관리체계 운영 (3)                                  │
 │   1.4 관리체계 점검 및 개선 (3)                          │
 │        ↕ **PDCA 순환 구조** ─── **ISMS·ISMS-P 공통**      │
 │                                                          │
 │ **[2. 보호대책 요구사항]** — **64개 항목**                 │
 │   2.1 정책·조직·자산 관리 (3)   2.2 인적 보안 (6)         │
 │   2.3 외부자 보안 (4)          2.4 물리 보안 (7)          │
 │   2.5 인증 및 권한관리 (6)     2.6 접근통제 (7)           │
 │   2.7 암호화 적용 (2)          2.8 정보시스템 도입·개발 (6)│
 │   2.9 시스템·서비스 운영관리(7) 2.10 시스템·서비스 보안관리(9)│
 │   2.11 사고 예방 및 대응 (5)   2.12 재해복구 (2)          │
 │        ↑ **ISMS·ISMS-P 공통**                            │
 │ ─────────────────────────────────────────────────────    │
 │ **[3. 개인정보 처리단계별 요구사항]** — **21개 항목**       │
 │   3.1 개인정보 **수집** 시 보호조치 (7)                   │
 │   3.2 개인정보 **보유·이용** 시 보호조치 (5)              │
 │   3.3 개인정보 **제공** 시 보호조치 (4)                   │
 │   3.4 개인정보 **파기** 시 보호조치 (3)                   │
 │   3.5 **정보주체 권리보호** (3)                           │
 │        ↑ ★**ISMS-P에만 적용**★                           │
 │                                                          │
 │ ⇒ **ISMS** = 1 + 2 = **80개 항목**                        │
 │ ⇒ **ISMS-P** = 1 + 2 + 3 = **101개 항목**                 │
 └──────────────────────────────────────────────────────────┘

비교 기준ISMSISMS-P

보호 대상정보자산 전반(기밀성·무결성·가용성)정보자산 + 개인정보(정보주체 권리 포함)
인증기준 영역1. 관리체계 + 2. 보호대책1 + 2 + 3. 개인정보 처리단계별 요구사항
인증기준 개수80개101개(+21개)
관점기업의 정보자산 보호(조직 관점)정보자산 보호 + 정보주체 권리 보호(개인 관점)
핵심 추가 영역—개인정보 수집·보유·제공·파기·권리보호 전 생애주기
근거 법령정보통신망법 제47조정보통신망법 제47조 + 개인정보보호법 제32조의2
소관 부처과학기술정보통신부과기정통부 + 개인정보보호위원회(공동)
의무 여부법적 의무 대상 존재자율 신청(의무 아님)
적합 대상개인정보를 거의 취급하지 않는 기업
(B2B 인프라, 클라우드 IaaS 일부)		개인정보를 대량 처리하는 기업
(포털·쇼핑몰·게임·금융·의료)
인증 마크ISMS 마크ISMS-P 마크(상위 인증으로 인식)

인증 유효기간3년(공통)3년(공통)

갱신심사유효기간 만료 전(공통)유효기간 만료 전(공통)

3. 관계 및 선택 기준​

   [**ISMS와 ISMS-P의 관계 — 포함 관계**]

   ┌─────────────────────────────────────────┐
   │  **ISMS-P**(101개)                       │
   │  ┌───────────────────────────────────┐  │
   │  │  **ISMS**(80개)                    │  │
   │  │  · 1. 관리체계 수립·운영 (16)      │  │
   │  │  · 2. 보호대책 요구사항 (64)       │  │
   │  └───────────────────────────────────┘  │
   │  + **3. 개인정보 처리단계별 요구사항 (21)**│
   └─────────────────────────────────────────┘

   ⇒ **ISMS-P는 ISMS를 포함하는 상위 인증**
   ⇒ **ISMS-P 취득 시 ISMS 의무도 자동 충족**
   ⇒ 인증 범위(Scope)는 신청기관이 선택 가능
      (전사 / 특정 서비스 / 특정 사업부)
상황권장 인증
법적 의무 대상이며 개인정보 처리 적음ISMS
개인정보를 대량 처리하는 B2C 서비스ISMS-P
공공 입찰·대외 신뢰도 제고 목적ISMS-P(가점 우대)
이미 ISMS 보유, 개인정보 규제 대응 필요ISMS → ISMS-P 전환·확대

Ⅲ. ISMS 의무 대상 기준​

1. 법적 근거​

   **정보통신망법 제47조 제2항** 및 **동법 시행령 제49조**

   "다음 각 호의 어느 하나에 해당하는 자는 **정보보호 관리체계
    인증을 받아야 한다**"
        ▼
   ① **ISP**(정보통신망서비스 제공자)
   ② **IDC**(집적정보통신시설 사업자)
   ③ **일정 규모 이상**의 정보통신서비스 제공자
      (매출액·이용자 수 기준)

2. 의무 대상 기준 상세​

 ┌────────── **ISMS 인증 의무 대상 기준** ──────────┐
 │                                                  │
 │ **[유형 ①] ISP — 정보통신망서비스 제공자**         │
 │   · **서울특별시 및 모든 광역시**에서 정보통신망   │
 │     서비스를 제공하는 자                          │
 │   · 예 : **기간통신사업자**(KT·SKT·LGU+ 등)       │
 │   ⇒ **매출·이용자 수와 무관하게 의무**             │
 │                                                  │
 │ **[유형 ②] IDC — 집적정보통신시설 사업자**         │
 │   · **타인의 정보통신서비스 제공을 위하여**        │
 │     **집적정보통신시설을 운영·관리하는 자**        │
 │   · 예 : **데이터센터 사업자**, 코로케이션 사업자  │
 │   ⇒ 원칙적으로 **매출·이용자 수와 무관하게 의무**  │
 │     (단, 영세 사업자 예외 규정 존재)              │
 │                                                  │
 │ **[유형 ③] 일정 규모 이상 정보통신서비스 제공자**   │
 │                                                  │
 │  **(가) 연매출액 또는 세입 1,500억원 이상**이면서   │
 │       다음 중 **하나 이상** 해당                   │
 │       · **상급종합병원**(의료법 제3조의4)          │
 │       · **재학생 수 1만명 이상**인 학교            │
 │         (고등교육법 제2조)                        │
 │                                                  │
 │  **(나) 정보통신서비스 부문 전년도 매출액**         │
 │       **100억원 이상**                            │
 │                                                  │
 │  **(다) 전년도 말 기준 직전 3개월간**              │
 │       **일일평균 이용자 수 100만명 이상**          │
 └──────────────────────────────────────────────────┘

3. 의무 대상 기준 요약표​

유형대상기준비고
① ISP정보통신망서비스 제공자서울 및 모든 광역시에서 서비스 제공규모 무관
② IDC집적정보통신시설 사업자타인의 서비스 제공을 위한 시설 운영규모 무관(예외 有)
③-가상급종합병원연매출·세입 1,500억원 이상의료법 제3조의4
③-가대학교연매출·세입 1,500억원 이상
+ 재학생 1만명 이상		고등교육법 제2조
③-나정보통신서비스 제공자정보통신서비스 부문 매출 100억원 이상전년도 기준
③-다정보통신서비스 제공자일일평균 이용자 100만명 이상전년도 말 직전 3개월 평균

4. 의무 대상 제외 및 예외​

구분내용
제외 대상· 전자금융거래법에 따라 금융보안원 인증 등 별도 관리체계 인증을 받은 경우(일부 대체 인정)
· 「의료법」상 의료기관 중 상급종합병원 외 기관(매출 요건 미충족)
· 소기업·영세 사업자(기준 미달)
인증 범위의무 대상은 해당 정보통신서비스 전체를 범위로 포함해야 함
미이행 시 제재정보통신망법 제76조 — 3,000만원 이하 과태료
· 인증 미취득, 인증 취소 후 미재취득 시 부과
· 매년 반복 부과 가능
사후관리 의무인증 후 연 1회 사후심사 미이행 시 인증 취소 가능

5. 인증 절차​

 ┌──────── **ISMS/ISMS-P 인증 절차** ────────┐
 │                                           │
 │ **① 준비 단계**(신청기관)                  │
 │   · 관리체계 구축·운영 (**최소 2개월 이상 운영**)│
 │   · 위험분석·보호대책 이행                 │
 │        ▼                                  │
 │ **② 인증 신청**                            │
 │   · 신청서·명세서 제출, **인증범위 확정**   │
 │        ▼                                  │
 │ **③ 계약 체결·심사팀 구성**                 │
 │        ▼                                  │
 │ **④ 심사**                                 │
 │   · **최초심사** : 인증기준 **전체 심사**    │
 │   · 서면심사 + **현장심사**                 │

Ⅴ. 결론​

ISMS와 ISMS-P의 차이는 "무엇을 보호 대상으로 보는가" 에 있다. ISMS가 조직의 정보자산을 기밀성·무결성·가용성 관점에서 보호하는 데 초점을 둔다면, ISMS-P는 여기에 정보주체의 권리 보호라는 개인 관점을 추가하여 개인정보의 수집·보유·제공·파기 전 생애주기와 정보주체 권리보장까지 21개 항목으로 확장한 것이다. 따라서 ISMS-P는 ISMS를 포함하는 상위 인증이며, ISMS-P 취득 시 ISMS 의무도 자동 충족된다.

의무 대상 기준의 핵심은 ① ISP·IDC는 규모와 무관하게 의무, ② 정보통신서비스 부문 매출 100억원 이상 또는 일일평균 이용자 100만명 이상, ③ 매출·세입 1,500억원 이상의 상급종합병원·재학생 1만명 이상 대학으로 요약된다. 미이행 시 3,000만원 이하 과태료가 매년 반복 부과될 수 있으므로, 대상 여부 판단은 매년 전년도 실적을 기준으로 점검해야 한다.

다만 실무적으로 가장 경계해야 할 것은 "인증을 위한 인증" 이다. 심사 기간에만 관리체계를 가동하고 이후 방치하면, 인증서는 있으나 실제 보안 수준은 개선되지 않는 형식화 현상이 발생한다. 실제로 ISMS 인증을 보유한 기업에서도 대형 침해사고가 반복 발생한 사례가 이를 방증한다.

따라서 ISMS-P의 실질적 가치는 인증서 취득이 아니라 인증기준 1영역이 요구하는 PDCA 순환(관리체계 수립 → 운영 → 점검 → 개선)을 조직에 내재화하는 것에 있다. 이를 위해서는 ① 자산·위험평가의 정기적 갱신, ② 로그·자산·취약점 관리의 자동화(SIEM·CMDB), ③ 모의훈련을 통한 대응체계 실효성 검증이 병행되어야 한다.

끝으로 향후에는 클라우드 책임 공유 모델, AI 시스템 통제, SBOM 기반 공급망 보안 등 새로운 위협에 대응하기 위해 인증기준이 지속 개정될 것으로 예상되며, 기업은 ISMS-P·ISO 27001·CSAP 등 중복 인증을 통합 관리체계(IMS)로 일원화하여 대응 효율을 높이는 전략이 필요하다.
