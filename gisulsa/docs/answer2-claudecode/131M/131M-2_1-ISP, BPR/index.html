ISP, BPR

문제​

1.ISP(Information Strategic Planning)와 BPR(Business Process Reengineering)의 개념과 수행절차를 비교 설명하고, 기업에서 이 두 가지가 상호 보완적으로 활용하기 위한 방안을 설명하시오.

Ⅰ. 개요​

1. ISP와 BPR의 개념​

구분개념
ISP
(정보화 전략계획)		경영전략과 연계하여 조직의 정보화 목표를 설정하고, 이를 달성하기 위한 정보시스템·데이터·기술·조직 아키텍처와 중장기 이행계획을 수립하는 활동
BPR
(업무 프로세스 재설계)		고객가치 관점에서 기존 업무 프로세스를 근본적으로 재검토하여, 비용·품질·속도의 획기적 개선을 목표로 프로세스를 근본적·급진적으로 재설계하는 활동(Hammer & Champy, 1990)

2. 등장배경 및 상호 관계​

   [등장배경]
   · 1990년대 — **IT 투자는 늘었으나 성과는 미미**("생산성 역설")
     ⇒ 원인 : **낡은 프로세스를 그대로 전산화**(Paving the cowpath)
   · **Hammer** : "IT로 기존 프로세스를 자동화하지 말고, **프로세스 자체를 다시 설계**하라"
        ▼
   [**본질적 관계**]

     **경영전략(Business Strategy)**
              │
      ┌───────┴────────┐
      ▼                ▼
   **BPR**          **ISP**
   (**무엇을** 어떻게    (**어떤 정보시스템**으로
    일할 것인가)         지원할 것인가)
      │                │
      └───────┬────────┘
              ▼
      **프로세스와 시스템의 정합성**
   ⇒ BPR 없는 ISP = **비효율의 전산화**
   ⇒ ISP 없는 BPR = **실행수단 없는 청사진**

Ⅱ. ISP와 BPR의 수행절차​

1. ISP 수행절차​

 ┌──────────────── **ISP 수행절차** ────────────────┐
 │                                                  │
 │ **① 환경분석**                                    │
 │    · 경영전략·비전 분석, **외부 환경**(법제도·기술) │
 │    · 국내외 **선진사례(Best Practice) 벤치마킹**   │
 │           ▼                                      │
 │ **② 현황분석(AS-IS)**                             │
 │    · 업무·정보시스템·데이터·인프라·조직 현황       │
 │    · **문제점 및 개선기회 도출**(Gap 분석)         │
 │           ▼                                      │
 │ **③ 목표모델 수립(TO-BE)**                        │
 │    · **정보화 비전·목표·전략과제** 정의            │
 │    · **EA 관점 4대 아키텍처** 설계                 │
 │      (업무·데이터·응용·기술 아키텍처)              │
 │           ▼                                      │
 │ **④ 이행계획 수립**                               │
 │    · 과제 도출·**우선순위 평가**(시급성·중요도)     │
 │    · **로드맵**(단계별), **소요예산·조직·위험관리** │
 │    · **BC/ROI 분석**(비용효과 분석)                │
 └──────────────────────────────────────────────────┘
   ※ 공공 : **「정보화사업 사전협의」·EA 기반 ISP/ISMP** 수행

2. BPR 수행절차​

 ┌──────────────── **BPR 수행절차** ────────────────┐
 │                                                  │
 │ **① 착수·비전 수립**                              │
 │    · **경영진 스폰서십** 확보, 변화 필요성 공유    │
 │    · **혁신 목표 설정**(예 : 리드타임 50% 단축)    │
 │           ▼                                      │
 │ **② 대상 프로세스 선정**                          │
 │    · **핵심(Core) 프로세스** 식별, 고객가치 기준   │
 │           ▼                                      │
 │ **③ AS-IS 프로세스 분석**                         │
 │    · 프로세스 맵핑, **부가가치 분석**(VA/NVA)      │
 │    · **병목·중복·대기 구간** 식별                  │
 │           ▼                                      │
 │ **④ TO-BE 프로세스 재설계**                       │
 │    · **근본적 재설계**(Zero-base), 단계 통합·병렬화 │
 │    · **IT를 Enabler로 활용**(자동화·정보 공유)     │
 │           ▼                                      │
 │ **⑤ 실행 및 정착**                                │
 │    · 파일럿 → 전사 확산, **조직·평가체계 개편**    │
 │    · **변화관리(Change Management)**, 성과 모니터링│
 └──────────────────────────────────────────────────┘

Ⅲ. ISP와 BPR의 비교​

1. 종합 비교​

비교 기준ISPBPR
목적정보시스템 청사진 수립업무 프로세스 혁신
대상정보시스템·데이터·기술·조직업무 프로세스
관점IT 관점(How to support)업무 관점(What & How to work)
변화 강도점진적·계획적(Incremental)급진적·근본적(Radical, Zero-base)
핵심 산출물TO-BE 아키텍처·이행 로드맵·ISP 보고서TO-BE 프로세스 맵·조직 개편안
주요 기법EA, Gap 분석, BC/ROI, 우선순위 매트릭스프로세스 맵핑, VA 분석, 벤치마킹, ESIA
주도 조직CIO·정보화 부서CEO·현업 부서(전사 혁신조직)
기간36개월 (중장기 35년 계획)6개월~2년 (실행 포함)
성공요인경영전략 연계, 실행 가능성경영진 의지, 변화관리
리스크계획이 문서로만 존재(Shelf-ware)급진적 변화에 따른 조직 저항·실패율 높음(약 70%)
관련 기법EA, ITA, ISMP, IT 거버넌스PI, TQM, Six Sigma, BPM

2. 공통점​

공통점내용
경영전략 연계양자 모두 경영전략에서 출발하여 정합성 확보를 전제
AS-IS → TO-BE 접근현황 진단 후 목표모델을 설계하는 Gap 분석 방법론 공유
전사적 관점부서 최적화가 아닌 전사 최적화 지향
경영진 지원 필수조직·프로세스 변경을 수반하므로 Top-down 추진 필요
변화관리 필요이해관계자 저항 극복이 성패의 핵심 변수

Ⅳ. 상호 보완적 활용 방안​

1. 통합 추진 모델​

 ┌──────── **BPR-ISP 통합 추진 모델(BPR/ISP 동시 수행)** ────────┐
 │                                                               │
 │  **[Phase 1] 공통 환경·현황 분석**                             │
 │    경영전략 분석 → 업무·시스템 **AS-IS 통합 진단**             │
 │    ⇒ **단일 현황분석**으로 중복 조사 제거                      │
 │              ▼                                                │
 │  **[Phase 2] BPR — 프로세스 우선 재설계**                      │
 │    **TO-BE 프로세스 확정** ("일하는 방식"을 먼저 결정)         │
 │              ▼  (프로세스 요구사항 전달)                       │
 │  **[Phase 3] ISP — 프로세스 지원 시스템 설계**                 │
 │    TO-BE 프로세스를 **지원하는 정보시스템 아키텍처** 도출       │
 │    (업무 → 데이터 → 응용 → 기술 아키텍처)                      │
 │              ▼                                                │
 │  **[Phase 4] 통합 이행계획**                                   │
 │    프로세스 개선과제 + 시스템 구축과제를 **하나의 로드맵**으로  │
 │    · **동일 우선순위 체계**, 상호 선후행 관계 반영             │
 │              ▼                                                │
 │  **[Phase 5] 실행·정착**                                       │
 │    시스템 구축 + **변화관리·조직개편·성과지표(KPI)** 동시 추진  │
 └───────────────────────────────────────────────────────────────┘

   **핵심 원칙 : "프로세스가 먼저, 시스템이 나중"**
   (Process First, System Follows)

2. 단계별 보완 방안​

구분보완 방안기대효과
① 계획 단계· BPR을 ISP의 선행 또는 병행 과제로 편성
· 통합 TFT 구성 — 현업(BPR) + 정보화(ISP) + 컨설턴트
· 공통 AS-IS 분석 수행으로 중복 제거		조사 공수 절감,
진단 결과 일관성
② 설계 단계· TO-BE 프로세스를 ISP의 업무 아키텍처(BA) 입력값으로 사용
· ISP의 기술적 실현가능성을 BPR 설계에 피드백
· 프로세스-시스템 매트릭스로 커버리지 검증		프로세스와 시스템의
정합성 확보
③ 이행 단계· 통합 우선순위 평가 — 프로세스 개선 없이 시스템만 구축하는 과제 배제
· 선후행 관계 정의 — 프로세스 확정 → 시스템 개발
· 파일럿 동시 적용 후 확산		투자 효율성 제고,
재작업 방지
④ 운영 단계· BPM 도입으로 TO-BE 프로세스를 시스템에 내재화
· 프로세스 마이닝으로 실제 수행 이력 분석 → 지속 개선
· EA 현행화 및 정기 ISP 재수립(3~5년)		일회성 혁신 → 지속적 개선
(CPI) 체계 전환
⑤ 조직·문화· CEO 스폰서십 + CIO의 실행 책임 명확화
· 프로세스 오너(Process Owner) 지정
· KPI·평가체계를 TO-BE 프로세스에 정렬		조직 저항 완화,
변화 정착

3. 실패 사례와 시사점​

실패 유형원인보완 방향
ISP 단독 수행비효율적 AS-IS 프로세스를 그대로 전산화BPR 선행으로 프로세스 정비 후 시스템화
BPR 단독 수행TO-BE 프로세스를 지원할 시스템 부재 → 수작업 회귀ISP 연계로 실행수단 확보
순차적 단절 수행BPR 종료 후 수년 뒤 ISP 착수 → 결과 진부화동시·연속 수행, 산출물 직접 연계
문서로만 존재이행계획에 예산·조직 미반영예산 편성·조직 개편과 연동, 이행점검 체계

Ⅴ. 결론​

ISP와 BPR은 "무엇을 어떻게 할 것인가(BPR)" 와 "그것을 무엇으로 지원할 것인가(ISP)" 라는 서로 다른 질문에 답하는 활동이지만, 실제로는 분리해서 성공할 수 없는 한 쌍의 활동이다.

역사적으로 IT 투자 실패의 대표적 원인은 낡은 프로세스를 그대로 전산화한 것(Paving the cowpath) 이었다. 이는 ISP만 수행했을 때 발생하는 전형적 실패이며, 반대로 BPR만 수행하면 재설계된 프로세스를 뒷받침할 시스템이 없어 결국 기존 방식으로 회귀한다.

따라서 실무적 정답은 "프로세스가 먼저, 시스템이 나중(Process First, System Follows)" 이라는 순서를 지키되, 두 활동을 하나의 사업으로 통합 발주하여 동시에 수행하는 것이다. 이때 BPR의 TO-BE 프로세스가 ISP의 업무 아키텍처 입력값이 되고, ISP의 기술적 실현가능성이 다시 BPR 설계를 검증하는 양방향 피드백 구조가 형성되어야 한다.

끝으로 최근에는 디지털 전환(DX) 환경에서 두 활동의 성격이 변화하고 있다. 3~5년 단위의 대규모 일괄 계획보다는, 프로세스 마이닝으로 실제 프로세스를 상시 진단하고, 클라우드·BPM 기반으로 신속히 반영하는 지속적 개선(Continuous Improvement) 체계로 진화하는 것이 바람직하다. 즉 ISP·BPR은 일회성 프로젝트가 아니라 조직의 상시 역량으로 내재화되어야 한다.
