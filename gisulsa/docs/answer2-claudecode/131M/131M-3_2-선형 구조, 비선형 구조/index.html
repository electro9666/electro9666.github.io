선형 구조, 비선형 구조

문제​

2.데이터 구조(Data Structure)에 대하여 다음을 설명하시오.
가.선형 구조(Linear Structure)의 개념 및 유형
나.비선형 구조(Non-Linear Structure)의 개념 및 유형
다.선형 구조(Linear Structure)와 비선형 구조(Non-Linear Structure) 비교

Ⅰ. 개요​

1. 데이터 구조의 개념 및 분류​

데이터 구조(Data Structure) 는 데이터를 효율적으로 저장·검색·관리하기 위해 데이터 간의 논리적 관계와 물리적 저장 방식을 정의한 체계이다. 원소 간의 인접 관계(1:1 vs 1:N/N:M) 에 따라 선형 구조와 비선형 구조로 대별된다.

   [**데이터 구조 전체 분류 체계**]

   **데이터 구조(Data Structure)**
        │
        ├── **단순 구조**(Primitive) — 정수·실수·문자·논리
        │
        └── **복합 구조**(Non-Primitive)
              │
              ├── ★**선형 구조**(Linear) — **원소 간 1:1 관계**
              │     · **배열**(Array)  · **연결 리스트**(Linked List)
              │     · **스택**(Stack)  · **큐**(Queue)  · **데크**(Deque)
              │
              ├── ★**비선형 구조**(Non-Linear) — **1:N, N:M 관계**
              │     · **트리**(Tree)   · **그래프**(Graph)
              │     · **힙**(Heap)     · **해시 테이블**(Hash Table)
              │
              └── **파일 구조**(File) — 순차·색인·직접 파일

   ⇒ 구분 기준 : **"한 원소가 몇 개의 원소와 인접하는가"**

2. 데이터 구조 선택의 중요성​

   · 알고리즘 성능은 **자료구조 선택에 의해 결정**된다
     예) 검색 : 배열 O(n) → **이진탐색트리 O(log n)** → **해시 O(1)**
   · **"프로그램 = 자료구조 + 알고리즘"**(Niklaus Wirth)
   · 잘못된 자료구조 선택은 **알고리즘 최적화로 만회 불가**

Ⅱ. 선형 구조(Linear Structure)의 개념 및 유형​

1. 개념​

선형 구조는 데이터 원소들이 일렬로 나열되어, 각 원소가 앞·뒤로 최대 하나의 이웃만을 갖는(1:1 대응) 자료구조이다. 선행자(Predecessor)와 후속자(Successor)가 유일하며, 순차적 순회(Traversal) 가 한 번에 완료된다.

   [**선형 구조의 본질 — 1:1 인접 관계**]

   ┌───┐   ┌───┐   ┌───┐   ┌───┐   ┌───┐
   │ A │───│ B │───│ C │───│ D │───│ E │
   └───┘   └───┘   └───┘   └───┘   └───┘
    첫    ← 각 원소는 **앞뒤로 하나씩만 연결** →   끝

   · **선행자·후속자가 유일**
   · **순회 경로가 하나** → 한 번의 순회로 전체 방문
   · **구현이 단순**, 메모리 사용 예측 가능

2. 선형 구조의 유형​

유형개념입출력 특성시간복잡도
배열
(Array)		연속된 메모리 공간에 동일 타입 데이터를 순차 저장, 인덱스로 접근임의 위치 접근·삽입·삭제접근 O(1)
삽입·삭제 O(n)
연결 리스트
(Linked List)		노드(데이터+포인터)를 링크로 연결, 물리적 불연속임의 위치 삽입·삭제접근 O(n)
삽입·삭제 O(1)*
스택
(Stack)		한쪽 끝(top)에서만 삽입·삭제 → LIFOpush / popO(1)
큐
(Queue)		rear에서 삽입, front에서 삭제 → FIFOenqueue / dequeueO(1)
데크
(Deque)		양쪽 끝 모두에서 삽입·삭제 가능양단 입출력O(1)

*위치를 이미 알고 있는 경우

   [**선형 구조 유형별 입출력 원리**]

   **[배열]** — 인덱스 기반 직접 접근
   ┌───┬───┬───┬───┐   주소 = 시작주소 + (인덱스 × 크기)
   │ A │ B │ C │ D │   ⇒ **O(1) 임의 접근**, 캐시 지역성 우수
   └───┴───┴───┴───┘   ⇒ 중간 삽입 시 **뒤 원소 전체 이동 O(n)**
     0   1   2   3

   **[연결 리스트]** — 포인터 기반 순차 접근
   head→┌───┬─┐  ┌───┬─┐  ┌───┬─┐
        │ A │●┼─▶│ B │●┼─▶│ C │∅│
        └───┴─┘  └───┴─┘  └───┴─┘
   ⇒ **링크만 변경**하여 삽입·삭제 O(1), 동적 크기
   ⇒ 인덱스 접근 불가 → **탐색 O(n)**

   **[스택]** — LIFO        **[큐]** — FIFO
   push↓  ↑pop             enqueue↓        ↑dequeue
   ┌───┐                   ┌───┬───┬───┐
   │ C │← top              │ A │ B │ C │
   │ B │                   └───┴───┴───┘
   │ A │                    front      rear
   └───┘                   ⇒ **입구·출구가 반대**
   ⇒ **입구=출구**

   **[데크]** — 양단 입출력
   ⇄┌───┬───┬───┬───┐⇄   ⇒ 스택·큐 **모두 구현 가능**
    └───┴───┴───┴───┘

3. 선형 구조의 활용​

자료구조주요 활용
배열행렬 연산, 이미지 픽셀, 정렬·이진탐색, 룩업 테이블
연결 리스트동적 메모리 관리, LRU 캐시, 다항식 표현, 해시 체이닝
스택함수 호출 스택·재귀, Undo, 수식 계산(후위표기), DFS, 괄호 검사
큐CPU 스케줄링(FCFS), 프린터 버퍼, 메시지 큐(Kafka), BFS
데크슬라이딩 윈도우 최대값, 양방향 작업 큐, 브라우저 히스토리

Ⅲ. 비선형 구조(Non-Linear Structure)의 개념 및 유형​

1. 개념​

비선형 구조는 하나의 원소가 여러 개의 원소와 연결될 수 있는(1:N 또는 N:M) 계층적·망형 자료구조이다. 데이터 간 계층 관계나 네트워크 관계를 표현하며, 순회 경로가 여러 개이므로 별도의 순회 알고리즘(DFS·BFS) 이 필요하다.

   [**비선형 구조의 본질 — 1:N / N:M 인접 관계**]

   **[트리 — 1:N 계층 관계]**        **[그래프 — N:M 망형 관계]**

            ┌───┐                        ┌───┐───────┌───┐
            │ A │                        │ A │       │ B │
            └─┬─┘                        └─┬─┘╲     ╱└─┬─┘
        ┌─────┴─────┐                      │   ╲   ╱   │
      ┌─▼─┐       ┌─▼─┐                  ┌─▼─┐  ╲ ╱  ┌─▼─┐
      │ B │       │ C │                  │ C │───╳───│ D │
      └─┬─┘       └───┘                  └───┘  ╱ ╲  └───┘
    ┌───┴───┐                                  ╱   ╲
  ┌─▼─┐   ┌─▼─┐                          **사이클 존재 가능**
  │ D │   │ E │                          **방향성 有/無**
  └───┘   └───┘
  **사이클 없음**, 부모 유일

   · 한 원소가 **여러 이웃**을 가짐
   · **순회 경로가 다수** → **DFS·BFS 알고리즘 필요**
   · **계층·관계·연결망** 표현에 최적

2. 비선형 구조의 유형​

가. 트리 (Tree)​

사이클이 없는 연결 그래프로, 하나의 루트(Root)에서 시작하여 부모-자식 관계로 계층을 이루는 구조이다. 노드 수가 N이면 간선 수는 항상 N-1이다.

트리 종류특징활용
이진 트리(Binary Tree)각 노드의 자식이 최대 2개트리 알고리즘의 기본
이진 탐색 트리(BST)좌 < 부모 < 우 정렬 규칙탐색·삽입·삭제 평균 O(log n)
균형 이진 트리
(AVL, Red-Black)		회전으로 높이 균형 유지최악에도 O(log n) 보장, Java TreeMap
B-Tree / B+Tree다진 균형 트리, 디스크 I/O 최소화DBMS 인덱스, 파일 시스템
힙(Heap)완전 이진 트리 + 부모-자식 대소 관계우선순위 큐, 힙 정렬 O(n log n)
트라이(Trie)문자열을 문자 단위 경로로 저장자동완성, 사전 검색
   [**트리 순회(Traversal) — 비선형을 선형으로 방문**]

            ┌───┐
            │ A │           **전위**(Pre-order)  : **A** → B → D → E → C
            └─┬─┘             (루트 → 좌 → 우)   ⇒ 트리 복사·구조 출력
        ┌─────┴─────┐
      ┌─▼─┐       ┌─▼─┐     **중위**(In-order)   : D → B → E → **A** → C
      │ B │       │ C │       (좌 → 루트 → 우)   ⇒ **BST에서 정렬 결과**
      └─┬─┘       └───┘
    ┌───┴───┐               **후위**(Post-order) : D → E → B → C → **A**
  ┌─▼─┐   ┌─▼─┐               (좌 → 우 → 루트)   ⇒ 트리 삭제·수식 계산
  │ D │   │ E │
  └───┘   └───┘             **레벨**(Level-order): A → B → C → D → E
                              (**BFS**, 큐 사용)  ⇒ 계층별 처리

나. 그래프 (Graph)​

정점(Vertex)과 간선(Edge)의 집합 G = (V, E) 으로, 원소 간 임의의 관계(N:M) 를 표현하는 가장 일반적인 비선형 구조이다.

분류 기준종류설명
방향성무방향 그래프간선에 방향 없음 (친구 관계)
방향 그래프(Digraph)간선에 방향 존재 (팔로우, 작업 순서)
가중치가중 그래프간선에 비용·거리 부여 (도로망)
연결성연결/비연결 그래프모든 정점이 연결되어 있는가
사이클DAG(비순환 방향 그래프)사이클 없음 → 위상 정렬, 작업 스케줄링
밀도희소/밀집 그래프간선 수에 따라 표현 방식 선택 기준
   [**그래프 표현 방식 비교**]

   **[인접 행렬]**(Adjacency Matrix)   **[인접 리스트]**(Adjacency List)
       A  B  C  D                       A → [B, C]
   A [ 0  1  1  0 ]                     B → [A, D]
   B [ 1  0  0  1 ]                     C → [A, D]
   C [ 1  0  0  1 ]                     D → [B, C]
   D [ 0  1  1  0 ]

   공간 : **O(V²)**                     공간 : **O(V+E)**
   간선 확인 : **O(1)**                 간선 확인 : O(degree)
   ⇒ **밀집 그래프**에 유리             ⇒ **희소 그래프**에 유리(일반적)
주요 그래프 알고리즘용도복잡도
DFS / BFS탐색, 연결요소, 최단경로(무가중)O(V+E)
Dijkstra최단 경로(음수 없음)O(E log V)
Bellman-Ford최단 경로(음수 허용)O(VE)
Kruskal / Prim최소 신장 트리(MST)O(E log V)
위상 정렬(DAG)작업 순서 결정O(V+E)

다. 해시 테이블 (Hash Table)​

키(Key)를 해시 함수로 변환하여 저장 위치를 직접 계산하는 구조로, 논리적으로는 키-값의 비선형 사상(Mapping) 관계를 표현한다.

항목내용
성능평균 O(1) 탐색·삽입·삭제 / 최악 O(n)
충돌 해결체이닝(연결 리스트), 개방 주소법(선형·이차 탐사, 이중 해싱)
활용DB 인덱스, 캐시, 딕셔너리(Map), 중복 검사, 블록체인

3. 비선형 구조의 활용​

자료구조주요 활용
트리파일 시스템 디렉터리, 조직도, DOM 트리, XML/JSON 구조, 의사결정트리
B+TreeRDBMS 인덱스, 파일 시스템(NTFS, ext4)
힙우선순위 큐, 스케줄러, Dijkstra 알고리즘
그래프SNS 관계망, 내비게이션 경로탐색, 네트워크 토폴로지, 추천 시스템, 지식 그래프
DAG작업 스케줄링(Airflow), 빌드 의존성, 블록체인·Git 커밋 이력
해시 테이블캐시(Redis), 심볼 테이블, 무결성 검증

Ⅳ. 선형 구조와 비선형 구조의 비교​

1. 종합 비교표​

비교 기준선형 구조(Linear)비선형 구조(Non-Linear)
원소 관계1:1(선행자·후속자 유일)1:N(트리), N:M(그래프)
데이터 배열일렬 순차 나열계층적·망형 배치
순회 방식단일 경로 순차 순회다중 경로 — DFS·BFS 필요
순회 완료1회 순회로 전체 방문여러 경로 탐색 필요, 방문 표시 필수

3. 상호 관계 및 변환​

   [**두 구조는 대립이 아니라 상호 보완·변환 관계**]

   **① 비선형 → 선형 변환**
      트리 순회(Pre/In/Post-order) ⇒ **선형 시퀀스로 출력**
      · 트리를 배열로 표현 : **힙**(부모 i, 자식 2i+1, 2i+2)
      · 그래프 위상 정렬 ⇒ **선형 작업 순서**

   **② 선형 구조가 비선형 구현의 도구**
      · **DFS 구현 → 스택**(선형) 사용
      · **BFS 구현 → 큐**(선형) 사용
      · 인접 리스트 = **배열 + 연결 리스트**
      ⇒ **"비선형 구조의 탐색은 선형 구조로 수행된다"**

   **③ 선택 기준**
      데이터 간 관계가 **순서뿐**       ⇒ **선형 구조**
      데이터 간 관계가 **계층·연결망** ⇒ **비선형 구조**

Ⅴ. 결론​

선형 구조와 비선형 구조의 구분은 단순한 분류가 아니라 "데이터 간의 관계를 어떻게 모델링할 것인가" 라는 설계 판단의 문제이다. 선형 구조는 순서(Sequence)를, 비선형 구조는 관계(Relationship)를 표현하며, 해결하려는 문제의 본질이 둘 중 무엇인가에 따라 선택이 결정된다.

주목할 점은 두 구조가 상호 배타적이지 않다는 것이다. DFS는 스택으로, BFS는 큐로 구현되며, 힙은 완전 이진 트리를 배열로 표현한다. 즉 비선형 구조의 논리적 관계를 선형 구조의 물리적 저장·처리 메커니즘으로 실현하는 것이 실제 구현의 모습이며, 트리 순회는 결국 비선형 데이터를 선형 시퀀스로 사상하는 과정이다.

성능 관점에서 비선형 구조의 결정적 이점은 탐색 복잡도에 있다. 선형 구조의 순차 탐색 O(n)은 데이터가 커질수록 급격히 악화되지만, 균형 트리는 O(log n), 해시 테이블은 O(1) 을 제공한다. B+Tree가 모든 상용 DBMS의 인덱스 구조로 채택된 이유도 디스크 I/O 횟수를 트리 높이(3~4단계)로 제한할 수 있기 때문이다.

다만 이론적 복잡도만으로 판단해서는 안 된다. 연결 리스트는 O(1) 삽입이 가능하지만 캐시 지역성이 낮아 실제로는 배열보다 느린 경우가 많으며, 데이터 규모가 작으면 단순한 배열의 순차 탐색이 해시 테이블보다 빠를 수 있다. 따라서 실무 선택 기준은 "어떤 연산이 가장 빈번한가" 와 "데이터 규모가 어느 정도인가" 라는 두 축으로 판단해야 한다.

끝으로 이러한 자료구조 개념은 현대 시스템 아키텍처에도 그대로 확장된다. 메시지 큐(Kafka)는 큐의 FIFO를 분산 환경으로, DBMS 인덱스는 B+Tree를, 블록체인과 Git은 DAG를, SNS 추천은 그래프 알고리즘을 각각 실현한 것이다. 자료구조에 대한 정확한 이해는 알고리즘 구현을 넘어 시스템 설계 전반의 기초 판단력을 형성한다.
