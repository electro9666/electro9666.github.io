페이징, 세그멘테이션

문제​

5.운영체제 메모리 관리 기법 중 페이징 기법과 세그멘테이션 기법의 개념을 설명하고, 두 기법에 대하여 비교 설명하시오.

Ⅰ. 개요​

1. 메모리 관리의 개념 및 필요성​

메모리 관리(Memory Management) 는 한정된 물리 메모리를 다수의 프로세스가 효율적·안전하게 공유하도록, 메모리의 할당·회수·보호·주소 변환을 수행하는 운영체제의 핵심 기능이다.

   [등장배경 — 연속 할당 방식의 한계]

   **[초기] 연속 할당(Contiguous Allocation)**
   ┌────────┬──────────┬─────┬──────────┬─────┐
   │  OS    │ 프로세스A│ 빈  │ 프로세스B│ 빈  │
   └────────┴──────────┴─────┴──────────┴─────┘
                        ▲                  ▲
                   **외부 단편화**(Fragmentation)
   ⇒ 빈 공간 총합은 충분하나 **연속 공간이 없어 할당 불가**
   ⇒ 프로세스 크기 > 물리 메모리 시 **실행 불가**
        ▼
   [해결 방향] **불연속 할당(Non-Contiguous Allocation)**
   · 프로세스를 **조각내어 흩어진 공간에 적재**
   · **가상 메모리(Virtual Memory)** 로 물리 메모리 한계 극복
        ▼
   ┌──────────────┬──────────────────┐
   │ **페이징**    │ **세그멘테이션**   │
   │ (고정 크기)   │ (가변 크기, 논리)  │
   └──────────────┴──────────────────┘

2. 가상 메모리와 주소 변환​

   [**주소 변환의 기본 구조**]

   프로세스(CPU)              **MMU**                 물리 메모리
   **논리 주소**    ────▶  (Memory Management  ────▶  **물리 주소**
   (Logical/Virtual)         Unit) 하드웨어           (Physical)
                              │
                       **매핑 테이블 참조**
                     (페이지 테이블/세그먼트 테이블)

   ⇒ 프로세스는 **연속된 자기만의 주소 공간**을 보지만,
      실제로는 **물리 메모리 곳곳에 흩어져** 있음
   ⇒ **프로세스 간 메모리 격리(보호)** 자동 달성

Ⅱ. 페이징 기법 (Paging)​

1. 개념​

페이징(Paging) 은 논리 주소 공간을 동일한 크기의 페이지(Page)로 분할하고, 물리 메모리를 같은 크기의 프레임(Frame)으로 나누어, 페이지를 임의의 프레임에 적재하는 불연속 메모리 할당 기법이다.

용어정의
페이지(Page)논리(가상) 주소 공간의 고정 크기 분할 단위 (일반적으로 4KB)
프레임(Frame)물리 메모리의 고정 크기 분할 단위 (페이지와 동일 크기)
페이지 테이블페이지 번호 → 프레임 번호 매핑 정보 (프로세스마다 보유)
MMU주소 변환을 수행하는 하드웨어
TLB페이지 테이블의 캐시(Translation Lookaside Buffer)

2. 주소 변환 구조​

 ┌────────────── **페이징 주소 변환** ──────────────┐
 │                                                  │
 │ **[논리 주소]**                                   │
 │  ┌─────────────┬───────────────┐                 │
 │  │ **페이지 번호**│ **오프셋(d)**   │               │
 │  │    (p)      │  (변위)        │                │
 │  └──────┬──────┴───────┬───────┘                 │
 │         │              │                         │
 │         ▼              │  ※ 오프셋은 **그대로 사용**│
 │  **[페이지 테이블]**     │    (페이지 크기가 동일하므로)│
 │  ┌─────┬──────────┐    │                         │
 │  │페이지│ **프레임** │    │                         │
 │  │  0  │    5     │    │                         │
 │  │  1  │    2     │    │                         │
 │  │**p**│  **f**   │────┼──┐                      │
 │  │  3  │    7     │    │  │                      │
 │  └─────┴──────────┘    │  │                      │
 │                        │  │                      │
 │ **[물리 주소]**          ▼  ▼                      │
 │  ┌─────────────┬───────────────┐                 │
 │  │**프레임 번호**│ **오프셋(d)**   │                │
 │  │    (f)      │               │                 │
 │  └─────────────┴───────────────┘                 │
 │                                                  │
 │  물리주소 = **f × 페이지크기 + d**                 │
 └──────────────────────────────────────────────────┘
   [**논리↔물리 메모리 매핑 예시**]

   **[논리 메모리]**              **[물리 메모리]**
   ┌──────────┐                  ┌──────────┐ 0
   │ Page 0   │──────┐           │  ...     │
   ├──────────┤      │           ├──────────┤ 2 ◀─┐
   │ Page 1   │──┐   │           │**Page 1** │    │
   ├──────────┤  │   │           ├──────────┤    │
   │ Page 2   │──┼─┐ │           │  ...     │    │
   ├──────────┤  │ │ │           ├──────────┤ 5 ◀┼─┐
   │ Page 3   │──┼─┼─┼──┐        │**Page 0** │    │ │
   └──────────┘  │ │ │  │        ├──────────┤    │ │
                 │ │ └──┼───────▶│  ...     │    │ │
   **연속적으로**  │ │    │        ├──────────┤ 7 ◀┼─┼─┐
   **보임**       │ └────┼───────▶│**Page 2** │    │ │ │
                 └──────┼───────▶├──────────┤    │ │ │
                        │        │**Page 3** │◀───┘ │ │
                        └───────▶└──────────┘      │ │
                                 **물리적으로 흩어짐**  │ │
   ⇒ **외부 단편화 없음** (프레임 크기가 모두 동일)
   ⇒ 마지막 페이지에서 **내부 단편화** 발생(평균 페이지 크기의 1/2)

3. 특징 및 장단점​

구분내용
장점· 외부 단편화 완전 제거 — 모든 프레임 크기가 동일
· 메모리 할당·회수 단순(빈 프레임 리스트 관리)
· 가상 메모리 구현 용이(Demand Paging)
· 페이지 단위 공유·보호 가능
· 프로세스 크기 > 물리 메모리여도 실행 가능
단점· 내부 단편화 발생(마지막 페이지, 평균 페이지 크기 / 2)
· 페이지 테이블 저장 공간 오버헤드(프로세스마다 필요)
· 주소 변환 시 메모리 접근 2회(테이블 + 실제 데이터) → TLB로 완화
· 논리적 의미 단위와 무관하게 분할 → 코드·데이터가 페이지 경계에 걸침

4. 성능 개선 기법​

기법내용
TLB
(Translation Lookaside Buffer)		최근 사용 페이지 테이블 항목의 하드웨어 캐시 → 적중 시 1회 접근으로 변환 완료
EAT = h×(TLB+M) + (1−h)×(TLB+2M), 적중률 h는 통상 95~99%
다단계 페이지 테이블64bit 주소 공간의 거대한 테이블을 계층화(2~5단계) → 사용하지 않는 영역 테이블 미생성
역페이지 테이블(IPT)프레임 기준으로 하나의 테이블만 유지 → 공간 절약, 탐색은 해시로
거대 페이지(Huge Page)2MB·1GB 페이지 → TLB 미스 감소, 대용량 메모리 DB·VM에 활용
요구 페이징
(Demand Paging)		필요한 페이지만 적재, 없으면 페이지 폴트(Page Fault) → 디스크에서 로드
페이지 교체 알고리즘LRU, FIFO, Optimal, Clock(2차 기회) — 프레임 부족 시 희생 페이지 선정
   [**요구 페이징과 페이지 폴트 처리**]

   ① CPU가 페이지 참조 → 페이지 테이블의 **유효 비트 = 0**(Invalid)
        ▼
   ② **페이지 폴트 트랩** 발생 → OS로 제어 이전
        ▼
   ③ 디스크(백킹 스토어)에서 **해당 페이지 탐색**
        ▼
   ④ 빈 프레임 확보(없으면 **페이지 교체 알고리즘**으로 희생자 선정)
        ▼
   ⑤ 페이지를 프레임에 적재 → **페이지 테이블 갱신**(유효 비트 = 1)
        ▼
   ⑥ 중단된 명령어 **재실행**

   ※ **스래싱(Thrashing)** : 페이지 폴트가 과다하여 **실제 작업보다
     페이지 교체에 CPU를 소모** → **작업 집합(Working Set) 모델**,
     **PFF(페이지 폴트 빈도) 기반 프레임 할당**으로 대응

Ⅲ. 세그멘테이션 기법 (Segmentation)​

1. 개념​

세그멘테이션(Segmentation) 은 프로그램을 코드·데이터·스택·힙 등 논리적 의미 단위인 세그먼트(Segment)로 분할하고, 각 세그먼트를 가변 크기로 물리 메모리에 적재하는 기법이다. 사용자의 프로그램 관점(논리 구조)을 그대로 반영한다는 점이 핵심이다.

용어정의
세그먼트(Segment)논리적 의미 단위의 가변 크기 분할 (Code, Data, Stack, Heap, 함수, 배열 등)
세그먼트 테이블세그먼트 번호 → (기준 주소 Base, 한계 Limit) 매핑
기준 주소(Base)세그먼트의 물리 메모리 시작 주소
한계(Limit)세그먼트의 길이 — 범위 검사(보호) 에 사용

2. 주소 변환 구조​

 ┌───────────── **세그멘테이션 주소 변환** ─────────────┐
 │                                                      │
 │ **[논리 주소]**                                       │
 │  ┌──────────────┬───────────────┐                    │
 │  │**세그먼트 번호**│ **오프셋(d)**   │                  │
 │  │     (s)      │               │                    │
 │  └──────┬───────┴───────┬───────┘                    │
 │         │               │                            │
 │         ▼               │                            │
 │  **[세그먼트 테이블]**    │                            │
 │  ┌────┬────────┬──────┐ │                            │
 │  │세그│**Limit** │**Base**│ │                          │
 │  │  0 │  1000  │ 1400 │ │                            │
 │  │**s**│ **L**  │ **B** │ │                           │
 │  │  2 │   400  │ 4300 │ │                            │
 │  └────┴───┬────┴───┬──┘ │                            │
 │           │        │    │                            │
 │           ▼        │    ▼                            │
 │      ┌─────────────┴────────┐                        │
 │      │  **d < Limit ?**      │ ← ★**범위 검사(보호)**  │
 │      └───┬──────────────┬───┘                        │
 │       **YES**         **NO**                          │
 │          │              │                            │
 │          ▼              ▼                            │
 │  물리주소 = **B + d**   **트랩 발생**                   │
 │                      (Segmentation Fault)            │
 │                                                      │
 │  ※ 페이징과 달리 **오프셋 크기 검증이 반드시 필요**      │
 │    (세그먼트 크기가 제각각이므로)                       │
 └──────────────────────────────────────────────────────┘
   [**논리 구조를 그대로 반영하는 세그멘테이션**]

   **[프로그램의 논리 구조]**        **[물리 메모리]**
   ┌──────────────┐                ┌──────────────┐
   │ **Code**(코드)│───────┐        │   OS         │
   │  Seg 0       │       │        ├──────────────┤
   ├──────────────┤       │        │ **Data**(Seg1)│
   │ **Data**(전역)│──┐    │        ├──────────────┤
   │  Seg 1       │  │    │        │  **빈 공간**  │◀ 외부
   ├──────────────┤  │    └───────▶├──────────────┤  단편화
   │ **Stack**    │──┼─┐           │ **Code**(Seg0)│
   │  Seg 2       │  │ │           ├──────────────┤
   ├──────────────┤  │ │           │  빈 공간     │
   │ **Heap**     │──┼─┼──┐        ├──────────────┤
   │  Seg 3       │  │ │  │        │ **Stack**(Seg2)│
   └──────────────┘  │ │  └───────▶├──────────────┤
                     └─┼──────────▶│ **Heap**(Seg3)│
                       └──────────▶└──────────────┘

   ⇒ **의미 단위 보존** → 세그먼트별 **차등 보호 권한** 설정 가능
      (Code = Read/Execute, Data = Read/Write, Stack = Read/Write)
   ⇒ 크기가 제각각 → **외부 단편화 발생**

3. 특징 및 장단점​

구분내용
장점· 논리적 의미 단위 유지 → 사용자·컴파일러 관점과 일치
· 세그먼트별 보호 권한 차등 설정(RWX) — 보안에 유리
· 모듈 단위 공유 용이(공유 라이브러리를 하나의 세그먼트로)
· 내부 단편화 없음(필요한 크기만 할당)
· 세그먼트 동적 크기 변경 가능(스택·힙 확장)
단점· 외부 단편화 발생 — 가변 크기로 인해 빈 공간이 조각남
· 압축(Compaction) 필요 → 비용 큼
· 배치 알고리즘 필요(First-fit, Best-fit, Worst-fit)
· 세그먼트가 크면 통째로 적재해야 함(스와핑 비용 큼)
· 주소 변환 시 범위 검사 추가 오버헤드

Ⅳ. 페이징과 세그멘테이션의 비교​

1. 종합 비교표​

비교 기준페이징(Paging)세그멘테이션(Segmentation)
분할 기준고정 크기(물리적 분할)가변 크기(논리적 의미 단위)

분할 주체운영체제(사용자 인식 못 함)컴파일러·사용자(논리 구조 반영)

2. 핵심 차이의 본질​

   [**두 기법의 철학적 차이**]

   **페이징** ── "**메모리 관리 효율**"을 위한 **물리적 관점**
   · 시스템(OS)의 편의 중심
   · "메모리를 어떻게 낭비 없이 나눌 것인가"
   · **외부 단편화 해결**이 목표
        ▼ 결과 : **관리는 쉽지만 의미가 사라짐**

   **세그멘테이션** ── "**프로그램 구조 반영**"을 위한 **논리적 관점**
   · 사용자·컴파일러의 관점 중심
   · "프로그램의 의미 단위를 어떻게 보존할 것인가"
   · **보호·공유의 정밀성**이 목표
        ▼ 결과 : **의미는 살지만 관리가 어려움**

   ⇒ **Trade-off** : **관리 효율성 ↔ 논리적 표현력**
   ⇒ 해법 : **두 기법의 결합**(세그멘테이션-페이징 혼합)

Ⅴ. 혼합 기법 및 실무 적용​

1. 세그멘테이션-페이징 혼합 기법 (Paged Segmentation)​

 ┌────── **세그멘테이션 + 페이징 혼합 구조** ──────┐
 │                                                 │
 │ **[논리 주소]**                                  │
 │ ┌────────┬────────┬────────┐                    │
 │ │**세그(s)**│**페이지(p)**│**오프셋(d)**│           │
 │ └───┬────┴────┬───┴────┬───┘                    │
 │     │         │        │                        │
 │     ▼         │        │                        │
 │ **[세그먼트 테이블]**   │        │                 │
 │  세그 s → **페이지 테이블 주소** + Limit           │
 │     │         │        │                        │
 │     └────────▶▼        │                        │
 │       **[페이지 테이블]** │                        │
 │        페이지 p → **프레임 f**                     │
 │                 │      │                        │
 │                 ▼      ▼                        │
 │        **물리주소 = f × 페이지크기 + d**            │
 │                                                 │
 │ ★ **세그먼트를 다시 페이지로 분할**                 │
 │   ⇒ 세그멘테이션의 **논리적 보호·공유** 확보        │
 │   ⇒ 페이징의 **외부 단편화 제거** 확보              │
 │   ⇒ 단점 : **주소 변환 단계 증가**(테이블 2회 참조)  │
 │           → **TLB로 완화**                        │
 └─────────────────────────────────────────────────┘
항목내용
개념프로그램을 논리적 세그먼트로 나눈 뒤, 각 세그먼트를 다시 고정 크기 페이지로 분할
장점외부 단편화 없음(페이징) + 논리적 보호·공유(세그멘테이션)
단점테이블 2단계 참조 → 주소 변환 오버헤드, 구현 복잡
적용Intel x86 보호모드(세그먼트 + 페이징 2단계), MULTICS

2. 현대 운영체제의 실제 구현​

   [**현대 OS는 사실상 '페이징 중심'**]

   · **x86-64 Long Mode** — 세그멘테이션 사실상 **무력화**
     (세그먼트 Base = 0, Limit = 전체 → **Flat Memory Model**)
   · **Linux/Windows** — **4단계~5단계 페이징** 사용
     (PML4 → PDPT → PD → PT → Frame)
   · 논리적 구분(코드/데이터/스택)은 **세그먼트가 아닌
     페이지 속성(NX bit, RW bit)** 으로 구현

   ⇒ **"세그멘테이션의 보호 기능을 페이지 단위 권한 비트가 대체"**
   ⇒ 이유 : 하드웨어 단순화, **이식성**, **64bit 광대한 주소 공간**
현대 기술내용
NX/XD 비트페이지 단위 실행 금지 → 버퍼 오버플로 공격 방어(DEP)
ASLR주소 공간 무작위 배치 → 공격자의 주소 예측 방해
Copy-on-Writefork 시 페이지 공유, 쓰기 시점에만 복사 → 프로세스 생성 고속화
메모리 매핑 파일파일을 페이지 단위로 주소 공간에 매핑(mmap)
Huge Page2MB/1GB 페이지 → TLB 미스 감소, DB·가상화 성능 향상
가상화 EPT/NPT게스트-호스트 2단계 주소 변환(중첩 페이징)

3. 실무 고려사항​

고려사항내용
① 페이지 크기 결정작으면 내부 단편화↓ 테이블 크기↑ / 크면 반대 → 워크로드 특성에 따라 선택(대용량 DB는 Huge Page)
② TLB 최적화참조 지역성을 높이는 코드·자료구조 설계, Huge Page로 TLB 커버리지 확대
③ 스래싱 방지작업 집합 크기 ≤ 할당 프레임 수 유지, 다중 프로그래밍 정도 조절, 메모리 증설
④ 보안NX 비트·ASLR·스택 카나리 병행 — 페이지 권한만으로는 불충분
⑤ 컨테이너·클라우드cgroup 메모리 제한, OOM Killer 정책, 오버커밋(Overcommit) 설정
⑥ 성능 진단페이지 폴트율·Major/Minor Fault 구분, vmstat·sar로 스와핑 모니터링

Ⅵ. 결론​

페이징과 세그멘테이션은 동일한 문제(연속 할당의 한계)에 대해 서로 다른 관점에서 접근한 해법이다. 페이징은 "메모리를 어떻게 낭비 없이 관리할 것인가"라는 시스템의 관점에서 고정 크기 분할을 택해 외부 단편화를 제거했고, 세그멘테이션은 "프로그램의 논리 구조를 어떻게 보존할 것인가"라는 사용자의 관점에서 가변 크기 의미 단위 분할을 택해 정밀한 보호와 공유를 얻었다.

두 기법의 Trade-off는 명확하다. 페이징은 관리가 쉽지만 논리적 의미가 사라지고, 세그멘테이션은 의미를 보존하지만 외부 단편화라는 근본적 관리 부담을 안는다. 이 때문에 역사적으로 두 기법을 결합한 세그멘테이션-페이징 혼합 방식(세그먼트를 다시 페이지로 분할)이 등장했으며, Intel x86 보호모드가 대표적 사례이다.

그러나 현대 운영체제의 실제 구현은 사실상 페이징 일변도이다. x86-64 Long Mode에서 세그멘테이션은 Base=0, Limit=최대인 Flat Memory Model로 무력화되었고, Linux·Windows 모두 4~5단계 다단계 페이징만을 사용한다. 이는 세그멘테이션이 제공하던 논리적 보호 기능을 페이지 단위 권한 비트(NX/RW 비트)가 충분히 대체할 수 있게 되었고, 64bit의 광대한 주소 공간에서 하드웨어 단순화와 이식성이 더 중요해졌기 때문이다.

따라서 실무적 관점에서 기술사가 주목해야 할 것은 두 기법의 우열이 아니라, 페이징 기반 위에서 성능과 보안을 어떻게 최적화할 것인가이다. 성능 측면에서는 TLB 적중률이 사실상 메모리 성능을 좌우하므로 참조 지역성을 높이는 설계와 Huge Page 활용이, 보안 측면에서는 NX 비트·ASLR·페이지 권한 관리가 핵심 과제이다. 또한 컨테이너·가상화 환경에서는 2단계 주소 변환(EPT/NPT)의 오버헤드와 cgroup 메모리 제한 정책이 새로운 관리 이슈로 부상하고 있다.

결국 메모리 관리 기법의 발전사는 "물리적 효율성과 논리적 표현력 사이의 균형을 찾아온 과정" 이며, 현대 시스템은 페이징의 효율성을 기반으로 하되 페이지 속성을 통해 세그멘테이션의 논리적 보호 기능을 흡수한 형태로 수렴했다고 평가할 수 있다.
