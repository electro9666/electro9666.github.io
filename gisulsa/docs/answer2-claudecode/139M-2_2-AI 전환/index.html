AX 추진을 위한 파인튜닝·RAG와 RLHF·RAFT 학습 파이프라인

Ⅰ. 개요​

1. AX(AI Transformation) 추진 배경​

AX는 AI를 업무 프로세스와 의사결정 체계에 내재화하는 전사적 전환이다. A기업이 LLM 기반 시스템을 구축하려면 범용 모델을 자사 도메인 지식과 정책에 정렬(Alignment) 시키는 것이 핵심 과제이다.

2. 두 가지 정렬 축​

LLM 정렬은 "무엇을 아는가(지식)" 와 "어떻게 답하는가(행동·형식)" 로 구분되며, 전자는 RAG, 후자는 파인튜닝이 담당한다.

              [ 범용 LLM ]
                    │
   ┌────────────────┴────────────────┐
 지식 보강                        행동 정렬
  RAG (외부 검색)              Fine-Tuning (가중치 갱신)
  최신성·출처·저비용            형식·톤·도메인 추론·정책 준수
   └──────── 결합: RAFT / Agentic RAG ────────┘

Ⅱ. 가. 파인튜닝과 RAG의 개념 및 역할​

1. 파인튜닝(Fine-Tuning)​

  • 개념: 사전학습 모델을 도메인 데이터로 추가 학습하여 모델 파라미터(가중치)를 갱신하는 기법
  • 방식: Full Fine-Tuning, PEFT(LoRA·QLoRA·Adapter), 지시학습(Instruction Tuning)
  • 역할: 출력 형식·문체 표준화, 도메인 용어·추론 패턴 내재화, 지연시간·토큰비용 절감(짧은 프롬프트), 정책 준수 행동 학습

2. RAG(Retrieval-Augmented Generation)​

  • 개념: 질의와 관련된 외부 지식을 검색하여 프롬프트에 주입한 후 생성하는 기법(모델 가중치 불변)
  • 구성: 문서 적재 → Chunking → 임베딩 → Vector DB → 검색(Hybrid) → Re-ranking → 생성
  • 역할: 최신·비공개 사내 지식 반영, 환각 억제와 출처(Citation) 제공, 권한별 접근통제, 즉시 갱신·삭제

3. 비교 및 역할 분담​

비교 기준파인튜닝RAG
변경 대상모델 가중치입력 컨텍스트
지식 최신성재학습 필요(지연)실시간 반영
출처 제시불가가능(추적성 확보)
초기 비용GPU 학습비용 높음검색 인프라 구축
운영 비용추론 토큰 적어 저렴컨텍스트 증가로 토큰 증가
환각 억제간접적직접적
데이터 통제학습 후 삭제 곤란문서 단위 삭제·권한관리 용이
적합 과제형식·문체·도메인 추론사실 기반 QA, 규정·매뉴얼 조회

결론적 판단: "지식은 RAG, 행동은 파인튜닝"이 원칙이며, A기업은 RAG 우선 구축 → 성능 한계 구간에 PEFT 적용하는 순서가 비용 효율적이다.

Ⅲ. 나. RLHF 기반 파이프라인과 RAFT 기반 파이프라인 비교​

1. RLHF(Reinforcement Learning from Human Feedback) 파이프라인​

인간 선호를 보상 신호로 학습하여 유용성·무해성(Helpful·Harmless) 을 정렬한다.

① 사전학습 모델(Base LLM)
        ↓
② SFT(Supervised Fine-Tuning) : 시연 데이터로 지시 이행 학습
        ↓
③ 선호 데이터 수집 : 동일 질의 응답쌍에 대한 인간 순위 부여
        ↓
④ 보상모델(Reward Model) 학습 : 선호 순위를 스칼라 보상으로 회귀
        ↓
⑤ 강화학습(PPO) : 보상 최대화 + KL 페널티로 원본 이탈 억제
        ↓
⑥ 평가·레드팀 → 배포   (대안: DPO/ORPO로 RM·PPO 단계 단순화)

2. RAFT(Retrieval Augmented Fine-Tuning) 파이프라인​

검색 결과가 포함된 상태에서 답하는 능력 자체를 학습시켜, RAG 환경에 특화된 모델을 만든다.

① 도메인 문서 코퍼스 준비
        ↓
② Q-A 쌍 생성(LLM 자동생성 + 검수)
        ↓
③ 학습 컨텍스트 구성
    · Oracle Document(정답 근거 문서)
    · Distractor Document(무관·유사 문서) 의도적 혼입
        ↓
④ CoT 형태 정답 작성 : 근거 인용 + 추론 과정 + 결론
        ↓
⑤ SFT 수행 : 정답 근거 선별 + Distractor 무시 학습
        ↓
⑥ RAG 파이프라인 결합 평가(정확도·인용 충실도)

3. 비교​

비교 기준RLHF 파이프라인RAFT 파이프라인
목적인간 선호·가치 정렬도메인 지식 활용 능력 정렬
학습 신호인간 선호 순위 → 보상모델근거 문서 + CoT 정답(지도학습)
학습 방식SFT + RL(PPO/DPO)SFT 중심(RL 불필요)
핵심 기법보상모델, KL 제약Distractor 혼입 학습
데이터 구축라벨러 다수 필요, 고비용·장기문서 기반 자동생성, 상대적 저비용
개선 효과유해성 감소, 지시 이행·응답 품질검색 노이즈 견고성, 인용 정확도
한계보상 해킹(Reward Hacking), 재현성 낮음도메인 종속, 코퍼스 변경 시 재학습
적용 시점범용 모델·서비스 정책 정렬사내 지식 기반 QA 고도화

4. A기업 적용 방안​

단계조치
1단계사내 문서 RAG 구축 + 지시 정렬된 상용/오픈 모델 활용
2단계검색 노이즈로 오답 발생 시 RAFT로 근거 선별 능력 강화
3단계응답 톤·거절 정책 등 행동 이슈는 DPO 기반 경량 선호학습 적용
공통평가셋(정확도·인용률·거절률) 구축, 데이터 거버넌스·PII 필터 선행

Ⅳ. 결론​

파인튜닝과 RAG는 대체재가 아니라 행동 정렬과 지식 공급이라는 상호보완 수단이다. RLHF는 가치·선호 정렬에, RAFT는 검색 기반 지식 활용 정렬에 특화되므로 목적에 따라 선택해야 한다. A기업은 RAG로 지식 최신성과 추적성을 먼저 확보하고, 정량 평가로 병목을 식별한 뒤 RAFT·DPO를 단계적으로 적용하는 것이 투자 효율과 리스크 관리 측면에서 타당하다.
