PLM, LLM 훈련 과정

문제​

4.자연어 언어모델에서의 PLM(Pre-trained Language Model)의 특성을 설명하고, 이모델이 최종 LLM(Large Language Model)으로 만들어지는 과정에 대하여 훈련특성을중심으로 설명하시오.

Ⅰ. 개요​

1. 배경​

전통적 자연어처리는 과업마다 별도의 모델을 처음부터 학습해야 했고, 과업별 대규모 레이블 데이터가 필수였다. PLM(사전학습 언어모델) 은 레이블 없는 방대한 말뭉치로 언어 자체를 먼저 학습한 뒤, 소량의 데이터로 각 과업에 적응시키는 전이학습(Transfer Learning) 패러다임을 확립했다.

   [패러다임 전환]
   **과업별 개별 학습**                    **사전학습 + 미세조정**
   과업마다 모델 설계·데이터 구축     →   **하나의 PLM → 다수 과업 전이**
   대규모 레이블 데이터 필수          →   **비지도(자기지도) 사전학습** 활용
   과업 간 지식 공유 불가             →   **범용 언어 표현 재사용**
        ▼
   **Transformer**(2017) → **BERT·GPT**(2018) → **Scaling Law**(2020)
        ▼
   [**LLM**] 규모(파라미터·데이터·연산) 확대 → **창발적 능력(Emergent Ability)** 발현

2. PLM과 LLM의 관계​

   **PLM** ⊃ 개념적 상위      "사전학습된 언어모델"이라는 **방법론적 범주**
   **LLM** = **초거대 PLM**   수십억~수조 파라미터 + 정렬(Alignment)을 거친 모델
   ⇒ **모든 LLM은 PLM이지만, 모든 PLM이 LLM은 아니다**

Ⅱ. PLM(사전학습 언어모델)의 특성​

1. 구조적 특성​

특성내용
Transformer 기반자기주의(Self-Attention) 로 문장 내 모든 토큰 간 관계를 병렬 계산 → 장거리 의존성 포착, GPU 병렬화 용이
자기지도학습(Self-supervised)레이블 없이 텍스트 자체에서 학습 신호 생성 → 웹 규모 데이터 활용 가능
문맥 기반 표현(Contextual Embedding)Word2Vec의 고정 벡터와 달리 문맥에 따라 단어 표현이 변화("배"→ 과일/신체/선박 구분)
전이 가능성(Transferability)사전학습된 언어 지식을 다양한 하위 과업에 재사용
토크나이저서브워드 분절(BPE·WordPiece·SentencePiece)로 미등록어(OOV) 문제 완화

2. 사전학습 목적함수(Pre-training Objective)에 따른 유형​

유형구조학습 목표대표 모델강점 과업
인코더형(Auto-Encoding)Transformer 인코더MLM(Masked LM) — 가려진 토큰 복원
+ NSP		BERT, RoBERTa, ELECTRA이해(NLU) — 분류·개체명·QA
디코더형(Auto-Regressive)Transformer 디코더CLM(Causal LM) — 다음 토큰 예측GPT 계열, LLaMA생성(NLG) — 대화·작문·코드
인코더-디코더형(Seq2Seq)인코더+디코더Span Corruption — 구간 복원T5, BART변환 — 번역·요약
   [학습 방식 비교]
   **MLM(BERT)** : "정보관리 [MASK] 는 어렵다"  → [MASK] = "기술사"
                    **양방향 문맥** 모두 사용 → 이해에 강함

   **CLM(GPT)**  : "정보관리 기술사 는" → 다음 토큰 "어렵다" 예측
                    **좌→우 단방향** → **생성에 자연스러움**, 확장성 우수
   ⇒ **LLM의 주류는 CLM(디코더형)** — 생성·In-context Learning에 유리

3. 규모 확대에 따른 특성 (Scaling Law)​

특성내용
Scaling Law성능이 모델 파라미터·데이터량·연산량에 대해 멱법칙(Power Law) 으로 향상
Chinchilla 최적파라미터만 키우는 것보다 데이터와 균형(파라미터 1 : 토큰 약 20)이 효율적
창발적 능력(Emergent Ability)일정 규모를 넘으면 학습하지 않은 능력이 갑자기 발현 — 다단계 추론, 산술, 지시 이해
In-context Learning가중치 갱신 없이 프롬프트의 예시만으로 과업 수행(Zero/Few-shot)
CoT(Chain-of-Thought)"단계적으로 생각하라"는 유도로 추론 성능 급상승

Ⅲ. PLM에서 LLM으로: 훈련 과정​

1. 전체 훈련 파이프라인​

   ┌─ **① 데이터 수집·정제** ────────────────────────────────────┐
   │  웹·도서·논문·코드 → 중복 제거·품질 필터링·유해물 제거      │
   │  개인정보 제거, 언어 비율 조정 → **수조 토큰 규모**          │
   └───────────────────────┬─────────────────────────────────────┘
                           ▼
   ┌─ **② 사전학습**(Pre-training) ── **PLM 완성** ───────────────┐
   │  목표 : **다음 토큰 예측(CLM)** — 자기지도                   │
   │  자원 : 수천 GPU × 수개월, **비용의 90% 이상 차지**          │
   │  결과 : **범용 언어 능력 + 세계 지식** 획득                  │
   │  ※ 그러나 **"문서를 이어 쓰는 모델"** — 지시를 따르지 못함   │
   └───────────────────────┬─────────────────────────────────────┘
                           ▼
   ┌─ **③ 지시 미세조정**(SFT / Instruction Tuning) ──────────────┐
   │  데이터 : **(지시, 모범 답변)** 쌍 — 사람이 작성, 수만~수십만│
   │  목표 : **지시를 이해하고 응답하는 형식** 학습               │
   │  결과 : **대화형 모델**로 전환 (Instruct 모델)               │
   └───────────────────────┬─────────────────────────────────────┘
                           ▼
   ┌─ **④ 정렬**(Alignment) — **RLHF / DPO** ─────────────────────┐
   │  ⓐ 동일 질문에 여러 응답 생성 → **사람이 선호도 순위 부여**  │
   │  ⓑ **보상 모델(RM)** 학습 — 사람의 선호를 점수로 근사        │
   │  ⓒ **강화학습(PPO)** 으로 정책(LLM) 최적화                   │
   │     ※ **DPO** : 보상 모델 없이 선호쌍으로 직접 최적화(경량)  │
   │  목표 : **유용성(Helpful)·정직성(Honest)·무해성(Harmless)**  │
   └───────────────────────┬─────────────────────────────────────┘
                           ▼
   ┌─ **⑤ 도메인 적응·확장** ─────────────────────────────────────┐
   │  **계속 사전학습**(Domain-Adaptive), **PEFT/LoRA** 경량 조정  │
   │  **RAG** 결합, **도구 사용(Function Calling)**, 컨텍스트 확장 │
   └───────────────────────┬─────────────────────────────────────┘
                           ▼
   ┌─ **⑥ 평가·안전성 검증·배포** ────────────────────────────────┐
   │  벤치마크(MMLU 등) · **레드팀 테스트** · 가드레일 · 경량화    │
   └──────────────────────────────────────────────────────────────┘

2. 단계별 훈련 특성 비교​

구분② 사전학습③ SFT④ 정렬(RLHF/DPO)
학습 방식자기지도(비지도)지도학습강화학습 / 선호 최적화
데이터레이블 없는 수조 토큰(지시, 답변) 쌍 수만~수십만선호 비교쌍 수만~수십만
데이터 출처웹·도서·코드 크롤링사람이 작성(고비용)사람의 선호 라벨링
목적함수다음 토큰 예측(Cross-Entropy)답변 토큰에 대한 Cross-Entropy보상 최대화 + KL 제약
연산 비용압도적(90% 이상)낮음(수 GPU-일)중간
획득 능력언어 능력·세계 지식지시 수행·응답 형식인간 가치 정렬·안전성
핵심 과제데이터 품질·연산 인프라데이터 품질이 양보다 중요보상 해킹·과도한 회피

3. 각 단계의 훈련 기술 특성​

단계주요 기술
데이터 처리중복 제거(MinHash), 품질 분류기, 유해·개인정보 필터, 데이터 오염(벤치마크 유출) 방지
사전학습 최적화혼합정밀도(BF16), ZeRO·FSDP, 3D 병렬화(데이터·텐서·파이프라인), 그래디언트 체크포인팅, 학습률 스케줄(Warmup + Cosine)
아키텍처 개선RoPE(위치 인코딩), RMSNorm, SwiGLU, GQA/MQA(추론 메모리 절감), MoE(전문가 혼합으로 연산 효율화)
SFT지시 데이터 다양성 확보, LIMA 가설(소수 고품질이 대량 저품질보다 우수), 다중 턴 대화 구성
정렬RLHF(RM + PPO), DPO(보상모델 불요), RLAIF/Constitutional AI(AI 피드백), KL 페널티로 원 모델 이탈 방지
효율적 적응(PEFT)LoRA/QLoRA — 전체 가중치 동결 후 저랭크 행렬만 학습 → 비용 수백분의 1
추론 최적화양자화(INT8/INT4), 지식 증류, KV 캐시, 스펙큘러티브 디코딩
능력 확장RAG(외부 지식 검색), 도구 호출, 긴 컨텍스트, 멀티모달 확장, 추론 특화 학습(RLVR·검증 가능 보상)

4. 파인튜닝 vs RAG vs 프롬프트 — 적용 판단​

방법적합한 상황특징
프롬프트 엔지니어링즉시 적용, 소규모 조정비용 최소, 지식 추가 불가
RAG최신·기관 고유 지식, 출처 제시 필요문서만 갱신하면 반영, 환각 억제
PEFT(LoRA)문체·형식·도메인 어투 적응저비용 미세조정
전체 파인튜닝·계속 사전학습특수 도메인(의료·법률) 언어 자체가 다름고비용, 대량 도메인 코퍼스 필요

Ⅳ. 이슈 및 고려사항​

이슈내용 및 대응
환각(Hallucination)확률적 생성의 본질적 한계 → RAG로 근거 제공, 출처 표시, 불확실성 표현 학습
파국적 망각(Catastrophic Forgetting)미세조정 시 기존 능력 상실 → 낮은 학습률·LoRA·리허설 데이터 혼합
정렬세(Alignment Tax)안전성 강화로 유용성·창의성 저하 → KL 제약 조절, 균형 평가
보상 해킹(Reward Hacking)보상 모델의 허점을 파고드는 응답(장황함 선호 등) → RM 정기 갱신, 다중 평가
데이터 저작권·개인정보학습데이터의 적법성 쟁점 → 출처 관리·옵트아웃·라이선스 검증
편향학습 데이터의 사회적 편향 반영 → 데이터 다양성, 편향 평가·완화
막대한 자원·환경 비용사전학습 비용·탄소 배출 → 오픈 모델 활용 + PEFT, 경량화, MoE
보안프롬프트 인젝션, 학습데이터 추출 공격, 모델 탈취 → 가드레일·입출력 필터링
평가의 어려움정답이 없는 생성 결과 → 벤치마크 + LLM-as-a-Judge + 사람 평가 병행, 벤치마크 오염 주의

Ⅴ. 결론​

PLM은 "레이블 없는 대규모 말뭉치로 언어 자체를 먼저 학습하고, 그 표현을 여러 과업에 전이한다" 는 자기지도 전이학습 패러다임이며, Transformer 구조와 문맥 기반 표현이 그 기술적 기반이다. 여기에 규모(Scaling) 가 더해지면서 In-context Learning과 추론 능력 같은 창발적 능력이 나타난 것이 LLM의 본질이다.

그러나 사전학습만 마친 모델은 "문서를 이어 쓰는 기계"에 불과하다. 이를 실제로 사용 가능한 LLM으로 만드는 것은 ③ 지시 미세조정(SFT)으로 지시 수행 능력을 부여하고, ④ RLHF/DPO로 인간의 가치와 정렬시키는 후속 단계이다. 즉 연산 비용의 90% 이상은 사전학습에 들어가지만, 사용자가 체감하는 품질과 안전성은 상대적으로 적은 비용의 SFT·정렬 단계에서 결정된다는 점이 LLM 훈련의 핵심 통찰이다.

실무적으로 개별 기관이 사전학습부터 수행하는 것은 비현실적이므로, ① 검증된 오픈 모델을 기반으로 ② RAG로 기관 지식을 결합하고 ③ 필요 시 LoRA 등 PEFT로 경량 적응시키는 전략이 합리적이다. 이때 파인튜닝은 "형식과 문체"를, RAG는 "지식과 최신성"을 담당한다는 역할 구분을 명확히 해야 하며, 환각·저작권·프롬프트 인젝션 등의 위험에 대비한 가드레일과 평가 체계를 함께 설계하는 것이 도입 성패를 좌우한다.
