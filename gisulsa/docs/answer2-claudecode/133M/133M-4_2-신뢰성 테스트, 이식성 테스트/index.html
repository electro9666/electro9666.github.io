신뢰성 테스트, 이식성 테스트

문제​

2.정보시스템 개발과 운영 단계에서 수행되는 소프트웨어 테스트의 종류를 쓰고, 이중신뢰성 테스트와 이식성 테스트의 세부 활동에 대하여 각각 설명하시오.

Ⅰ. 개요​

1. 배경​

소프트웨어 테스트는 결함을 발견하여 품질을 확인하는 활동이다. 그러나 실무에서는 기능 테스트에 편중되고, 신뢰성·이식성 등 비기능 품질은 운영 단계에 이르러서야 문제로 드러나는 경우가 많다.

   [테스트 편중의 결과]
   기능 시험 통과 → 운영 전환
        │  · 장시간 운영 시 **메모리 누수·성능 저하**
        │  · 장애 발생 시 **복구 실패**
        │  · OS·브라우저·클라우드 전환 시 **동작 불능**
        ▼
   [해법] **ISO/IEC 25010**(SQuaRE) 품질 특성 기반의
          **비기능 테스트를 개발 단계부터 계획적으로 수행**

2. 관련 표준​

표준내용
ISO/IEC 25010(SQuaRE)제품 품질 모델 — 8대 품질 특성(기능적합성·성능효율성·호환성·사용성·신뢰성·보안성·유지보수성·이식성)
ISO/IEC 25023품질 측정 지표(Metrics)
ISO/IEC/IEEE 29119소프트웨어 테스트 국제표준(프로세스·문서·기법)
GS 인증(TTA)국내 SW 품질 인증 — 25010 기반 시험

Ⅱ. 소프트웨어 테스트의 종류​

1. 분류 체계​

 ┌──────────── **테스트 분류 관점** ────────────┐
 │                                              │
 │ **① 시각(누가)**   확인(Verification) /       │
 │                    검증(Validation)          │
 │ **② 실행 여부**    정적 / 동적                │
 │ **③ 시스템 지식**  화이트박스 / 블랙박스      │
 │ **④ 개발 단계**    단위 → 통합 → 시스템 → 인수│
 │ **⑤ 목적(품질특성)** 기능 / **비기능**         │
 │ **⑥ 운영 단계**    회귀 / 스모크 / 확인       │
 └──────────────────────────────────────────────┘

2. 개발 단계별 테스트 (V-모델)​

   요구분석 ─────────────────────────▶ **인수 테스트**(사용자 요구 충족)
        ↘                            ↗
     시스템설계 ────────────────▶ **시스템 테스트**(전체 통합·비기능)
          ↘                      ↗
       상세설계 ──────────▶ **통합 테스트**(모듈 간 인터페이스)
            ↘                ↗
          구현 ───────▶ **단위 테스트**(개별 모듈)
단계테스트내용
단위(Unit)개별 모듈·함수화이트박스, 개발자 수행, 커버리지 측정
통합(Integration)모듈 간 인터페이스상향식·하향식·빅뱅, 스텁·드라이버 활용
시스템(System)전체 시스템기능 + 비기능 테스트 집중 수행
인수(Acceptance)사용자 관점알파·베타 테스트, 계약 요건 충족 확인

3. 기법에 따른 분류​

구분기법내용
정적 테스트코드 리뷰·워크스루·인스펙션, 정적 분석실행 없이 결함 발견, 조기 검출
동적 테스트 — 블랙박스동등분할·경계값 분석, 결정표, 상태전이, 유스케이스, 페어와이즈내부 구조 무관, 명세 기반
동적 테스트 — 화이트박스구문·분기·조건·MC/DC 커버리지, 경로 테스트내부 로직 기반, 커버리지 측정
경험 기반오류 추정, 탐색적 테스트, 체크리스트숙련자의 경험 활용

4. 목적(품질특성)에 따른 분류 — ISO/IEC 25010 기준​

품질 특성테스트 종류검증 내용
기능 적합성기능 테스트요구된 기능의 완전성·정확성·적절성
성능 효율성성능 테스트(부하·스트레스·내구성·스파이크)응답시간·처리량·자원 사용률
호환성호환성·상호운용성 테스트타 시스템과 공존·데이터 교환
사용성사용성 테스트, 접근성 테스트학습·조작 용이성, 웹 접근성(KWCAG)
신뢰성★ 신뢰성 테스트성숙성·가용성·결함허용성·복구성
보안성보안 테스트(취약점 진단·모의해킹)기밀성·무결성·부인방지·인증
유지보수성유지보수성 평가(정적 분석)모듈성·재사용성·분석성·변경성·시험성
이식성★ 이식성 테스트적응성·설치성·대체성

5. 운영 단계 테스트​

테스트내용
회귀 테스트(Regression)변경 후 기존 기능의 정상 동작 확인 — 운영 단계 핵심
스모크 테스트배포 직후 핵심 기능 동작 여부 신속 확인
확인 테스트(Confirmation)결함 수정이 실제로 해결되었는지 재확인
A/B 테스트·카나리 테스트실제 이용자 대상 점진적 검증
운영 환경 모니터링 기반 테스트카오스 엔지니어링, 합성 모니터링(Synthetic)

Ⅲ. 신뢰성 테스트 (Reliability Testing)​

1. 개념 및 목적​

신뢰성 테스트란 소프트웨어가 명시된 조건에서 명시된 기간 동안 요구된 기능을 오류 없이 수행하는 능력을 검증하는 시험이다.

   [ISO/IEC 25010 — **신뢰성의 4대 부특성**]
   ┌────────────────┬──────────────────────────────────────────┐
   │ **① 성숙성**    │ 정상 운영 상태에서 **신뢰성 요구를 충족**  │
   │  (Maturity)     │ → 장시간 안정 동작, 낮은 결함 발생률      │
   │ **② 가용성**    │ 필요할 때 **사용 가능한 상태 유지**        │
   │  (Availability) │ → 가동률(%), 무중단 운영                  │
   │ **③ 결함 허용성**│ **결함·장애 발생 시에도 동작 지속**        │
   │  (Fault Tolerance)│ → 이중화·우회·부분 기능 유지            │
   │ **④ 복구성**    │ 장애 후 **데이터 복구·정상 상태 회복**     │
   │  (Recoverability)│ → RTO/RPO 달성                          │
   └────────────────┴──────────────────────────────────────────┘

2. 세부 활동​

① 성숙성 테스트 (Maturity Test)​

활동내용
내구성(장시간) 테스트
(Endurance / Soak)		· 장시간(24~72시간 이상) 연속 부하 인가
· 메모리 누수(Memory Leak) 여부 — 힙 사용량의 지속 증가 감시
· 커넥션 누수(DB·소켓), 파일 핸들 누수
· 응답시간의 점진적 저하 여부
결함 밀도·발생률 측정· MTBF(평균 무장애 시간) 측정
· 결함 밀도(KLOC당 결함 수), 결함 검출률
· 신뢰성 성장 모델(Rayleigh·Gompertz) 적용 — 잔존 결함 예측
반복 실행 테스트동일 시나리오 대량 반복 수행 → 간헐적 결함 검출
경계·예외 입력 테스트비정상 입력·경계값에서의 비정상 종료 여부
자원 고갈 테스트메모리·디스크·CPU 한계 상황에서의 동작

② 가용성 테스트 (Availability Test)​

활동내용
가동률 측정· 가용성 = MTBF / (MTBF + MTTR) × 100(%)
· 목표(예: 99.9%) 대비 실측
무중단 운영 검증· 무중단 배포(롤링·블루그린) 중 서비스 지속 여부
· 온라인 백업·패치 중 서비스 영향 확인
클러스터·이중화 검증노드 추가·제거 시 서비스 지속, 세션 유지
계획 중단 최소화 확인정기 점검·유지보수 시 중단 시간 측정

③ 결함 허용성 테스트 (Fault Tolerance Test)​

활동내용
장애 주입 테스트
(Fault Injection)		· 의도적 장애 발생 — 서버 다운, 프로세스 강제 종료(kill), 네트워크 단절
· 디스크 오류, DB 연결 차단, CPU·메모리 과부하 주입
절체(Failover) 테스트· 주 시스템 장애 시 대기 시스템 자동 전환 확인
· 전환 소요 시간 측정(목표 대비)
· 전환 중 트랜잭션 손실 여부
부분 장애 대응 확인· 일부 기능 장애 시 나머지 서비스 지속(Graceful Degradation)
· 회로차단기(Circuit Breaker)·재시도·타임아웃 동작 확인
· 폴백(Fallback) 응답 제공 여부
오류 처리 검증예외 발생 시 비정상 종료 없이 오류 메시지 반환, 로그 기록
카오스 엔지니어링운영 환경에서 의도적 장애 실험으로 복원력 검증

④ 복구성 테스트 (Recoverability Test)​

활동내용
장애 복구 테스트· 장애 발생 → 복구 절차 수행 → 정상화까지 시간 측정
· RTO(목표 복구 시간) 충족 여부
데이터 복구 테스트· 백업본으로 데이터 복원 정상 수행 확인
· RPO(허용 데이터 손실) 충족 여부
· 데이터 정합성 검증(건수·체크섬)
트랜잭션 무결성 검증처리 중 장애 발생 시 롤백·재처리 정상 동작, 중복·유실 없음
재해복구(DR) 시험DR 센터로 전환 → 서비스 정상 확인 → 원복(Failback)
자동 재시작 확인프로세스 비정상 종료 시 자동 재기동, 상태 복원
MTTR 측정평균 복구 시간 산출 → 개선 목표 설정

3. 신뢰성 측정 지표​

지표산식·의미
MTBF평균 무장애 시간 — 총 가동시간 / 장애 건수
MTTF평균 고장 시간(비수리계)
MTTR평균 복구 시간 — 총 복구시간 / 장애 건수
가용성MTBF / (MTBF + MTTR)
결함 밀도결함 수 / KLOC(또는 FP)
고장률(λ)단위 시간당 고장 발생 확률
RTO / RPO복구 목표 시간 / 복구 목표 시점

Ⅳ. 이식성 테스트 (Portability Testing)​

1. 개념 및 목적​

이식성 테스트란 소프트웨어가 다른 하드웨어·소프트웨어·운영 환경으로 이전되거나 전환될 수 있는 능력을 검증하는 시험이다.

   [ISO/IEC 25010 — **이식성의 3대 부특성**]
   ┌────────────────┬──────────────────────────────────────────┐
   │ **① 적응성**    │ **다양한 환경에 적응**할 수 있는 능력      │
   │  (Adaptability) │ → OS·브라우저·DBMS·클라우드·해상도       │
   │ **② 설치성**    │ **설치·제거가 성공적이고 용이**한 능력     │
   │  (Installability)│ → 설치·업그레이드·롤백·삭제             │
   │ **③ 대체성**    │ 동일 목적의 **다른 제품으로 대체 가능**    │
   │  (Replaceability)│ → 데이터 호환·표준 준수·마이그레이션     │
   └────────────────┴──────────────────────────────────────────┘

2. 세부 활동​

① 적응성 테스트 (Adaptability Test)​

활동내용
운영체제 호환성 시험· 지원 대상 OS 및 버전별 동작 확인(Windows·Linux 배포판·macOS)
· OS별 파일 경로·구분자·인코딩·권한 체계 차이 검증
· 32/64비트, CPU 아키텍처(x86·ARM) 차이
브라우저·클라이언트 호환성· 주요 브라우저·버전별 화면 표시·기능 동작(크로스브라우징)
· 모바일 단말·OS 버전·해상도별 반응형 동작
· 접근성 보조기술(스크린리더) 호환
DBMS·미들웨어 호환성· 지원 DBMS 종류·버전별 동작(Oracle·PostgreSQL·MySQL)
· SQL 문법·데이터 타입·트랜잭션 차이 검증
· WAS·JDK 버전별 동작
하드웨어·자원 환경 적응· 저사양~고사양 환경에서의 동작
· 메모리·CPU·디스크 자원 변동 시 정상 동작
클라우드·가상화 환경 적응· 온프레미스 → 클라우드 전환 시 동작
· 컨테이너(Docker·K8s) 환경 구동
· 하드코딩된 IP·경로·호스트명 제거 여부 ← 이식성 저해의 최대 원인
국제화·지역화(i18n/L10n)· 언어·문자셋(UTF-8)·날짜/시간·통화·정렬 순서

· 코드 수정 없이 설정만으로 환경 전환 가능한가

② 설치성 테스트 (Installability Test)​

활동내용
설치 절차 시험· 정상 설치 성공 여부, 설치 소요 시간
· 설치 매뉴얼대로 수행 가능한지(문서 정확성 검증)
· 필수 선행 조건(라이브러리·런타임) 자동 확인·안내
다양한 환경 설치지원 대상 모든 OS·버전 조합에서 설치 시험
설치 옵션 시험전체·사용자 정의·최소 설치, 설치 경로 변경, 무인(Silent) 설치
업그레이드 시험· 이전 버전에서 업그레이드 시 데이터·설정 유지
· 버전 건너뛰기 업그레이드
롤백·재설치 시험· 설치 실패 시 정상 롤백, 시스템 원상 복구
· 재설치·복구 설치
제거(Uninstall) 시험· 완전 제거 여부 — 잔여 파일·레지스트리·서비스 확인
· 사용자 데이터 보존·삭제 선택
설치 후 검증설치 직후 기본 동작 확인(스모크), 기본 설정값 적정성
비정상 상황 시험디스크 공간 부족, 권한 부족, 설치 중단(전원 차단) 시 동작

활동내용

· 표준 프로토콜 준수(REST·SOAP·ODBC/JDBC)

Ⅴ. 두 테스트의 비교 및 수행 시 고려사항​

1. 비교​

비교 기준신뢰성 테스트이식성 테스트
검증 질문"오래·안정적으로 동작하는가""다른 환경에서도 동작하는가"
부특성성숙성·가용성·결함허용성·복구성적응성·설치성·대체성

주된 위험서비스 중단·데이터 손실전환 실패·재개발 비용

2. 수행 시 고려사항​

고려사항내용
① 요구사항의 정량화 선행"안정적이어야 한다"가 아니라 "가용성 99.9%, RTO 2시간, MTBF 720시간" 처럼 측정 가능한 목표가 있어야 시험 가능
② 운영 환경과 동일한 시험 환경축소 환경 시험은 신뢰성 결과를 왜곡 → 최대한 동일 구성 확보
③ 충분한 시험 기간 확보내구성 테스트는 최소 24~72시간 — 일정 압박 시 가장 먼저 생략되는 항목
④ 환경 조합의 우선순위화이식성 시험의 모든 조합은 불가능 → 점유율·중요도 기준 우선순위, 페어와이즈 기법으로 조합 축소
⑤ 자동화반복 수행이 필수 → CI/CD 파이프라인 연계, 컨테이너 기반 환경 매트릭스 자동 구성
⑥ 설계 단계 반영이식성은 시험으로 확보되지 않음 → 환경 설정 외부화·표준 준수·추상화 계층을 설계 단계에 반영
⑦ 복구 시험의 실효성백업은 있으나 복구를 한 번도 해보지 않은 조직이 많음 → 정기 복구 훈련 의무화
⑧ 클라우드 환경 특수성이식성 = 멀티 클라우드 전환 가능성 → CSP 종속 서비스 사용 시 락인 위험 평가
⑨ GS 인증·감리 연계공공 SW는 GS 인증 시험 항목과 감리 점검 항목에 신뢰성·이식성 포함 → 사전 대비

Ⅵ. 결론​

소프트웨어 테스트는 개발 단계별(단위·통합·시스템·인수), 기법별(정적·블랙박스·화이트박스), 목적별(기능·비기능) 로 분류되며, 이 중 ISO/IEC 25010의 8대 품질 특성에 대응하는 비기능 테스트가 시스템의 운영 품질을 실질적으로 결정한다.

신뢰성 테스트는 "시간의 시험" 이다. 성숙성(장시간 안정성)·가용성(가동률)·결함허용성(장애 중 지속)·복구성(장애 후 회복)의 네 부특성에 대해, 장시간 내구성 시험으로 메모리 누수를 잡고, 장애 주입과 절체 시험으로 결함허용성을 확인하며, 실제 복구 훈련으로 RTO·RPO 달성을 입증하는 것이 핵심 활동이다.

이식성 테스트는 "환경의 시험" 이다. 적응성(다양한 OS·브라우저·DBMS·클라우드)·설치성(설치·업그레이드·제거)·대체성(데이터 호환·마이그레이션)을 검증하며, 실무에서 이식성을 가장 크게 저해하는 요인은 하드코딩된 IP·경로·환경 종속 값이다.

두 테스트에서 공통적으로 강조할 점은 "측정 가능한 목표가 선행되어야 한다" 는 것이다. 정량화되지 않은 비기능 요구사항은 시험할 수 없고, 시험하지 않은 품질은 반드시 운영 단계에서 문제로 드러난다. 또한 신뢰성은 장시간 시험 자원을, 이식성은 다양한 환경 자원을 요구하므로 일정·예산 압박 시 가장 먼저 축소되는 영역이지만, 이때 절감한 비용은 운영 장애와 전환 실패의 형태로 수십 배가 되어 돌아온다.

따라서 실무적으로는 ① 요구사항 정의 단계에서 신뢰성·이식성 목표를 정량화하고, ② 이식성은 시험이 아닌 설계(설정 외부화·표준 준수)로 확보하며, ③ 컨테이너와 CI/CD를 활용해 환경 매트릭스 시험과 장애 주입 시험을 자동화하는 것이 가장 효과적인 접근이다.
