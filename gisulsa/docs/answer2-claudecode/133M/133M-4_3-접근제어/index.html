접근제어

문제​

3.정보보호 방법을 암호화와 접근제어로 크게 분류할 때, 접근제어에 대하여 그개념과정책, 절차, 그리고 이를 구현하는 메커니즘에 대하여 설명하시오.

Ⅰ. 개요​

1. 정보보호의 두 축 — 암호화와 접근제어​

   ┌──────────── **정보보호의 기본 접근** ────────────┐
   │                                                  │
   │  **암호화**(Cryptography)                         │
   │   "**접근하더라도 이해할 수 없게**"                │
   │   · 데이터 자체를 변환 → 기밀성·무결성            │
   │   · 저장·전송 중 보호에 강점                      │
   │   · 한계 : **연산 시 복호화 필요**, 키 관리 부담   │
   │                                                  │
   │  **접근제어**(Access Control)                     │
   │   "**권한 없는 자는 아예 접근하지 못하게**"        │
   │   · 주체의 자원 접근을 **인가 여부로 통제**        │
   │   · **보안의 1차 방어선**, 모든 통제의 기반        │
   │   · 한계 : 통제 우회 시 원본 그대로 노출          │
   │        ▼                                         │
   │  ⇒ **상호 보완** — 접근제어로 막고, 뚫려도        │
   │     암호화로 무력화하는 **다층 방어(Defense in Depth)** │
   └──────────────────────────────────────────────────┘

Ⅱ. 접근제어의 개념​

1. 정의​

접근제어(Access Control) 란 주체(Subject) 가 객체(Object) 에 대해 수행하는 접근 행위(Access) 를 보안 정책에 따라 허용하거나 거부하는 통제 활동이다.

   [접근제어의 3요소]

   **주체(Subject)**          **접근(Access)**         **객체(Object)**
   ─────────────           ─────────────          ─────────────
   사용자·프로세스           읽기(Read)              파일·DB·테이블
   서비스 계정               쓰기(Write)             시스템·장비
   디바이스·AI 에이전트      실행(Execute)           네트워크·설비
        │                   삭제(Delete)                  ▲
        │                                                 │
        └────▶ [**참조 모니터**(Reference Monitor)] ──────┘
                     │ 보안 정책에 따라 판단
                     ▼
              **허용(Permit) / 거부(Deny)** + **감사 기록**

2. 접근제어의 3단계 (AAA)​

단계내용질문
① 식별(Identification)주체가 자신이 누구인지 제시"당신은 누구인가?" — ID 제시
② 인증(Authentication)제시한 신원이 진짜인지 확인"정말 본인인가?" — 비밀번호·생체·인증서
③ 인가(Authorization)인증된 주체에게 어떤 권한을 부여할지 결정"무엇을 할 수 있는가?" — 권한 부여
(+) 책임추적성(Accounting)모든 행위를 기록하여 사후 추적"무엇을 했는가?" — 감사 로그
인증 요소(Factor)종류
지식(Something you know)비밀번호, PIN, 보안 질문
소유(Something you have)OTP, 스마트카드, 인증서, 단말
존재(Something you are)지문·홍채·얼굴 등 생체정보
행위·위치서명 패턴, 접속 위치·시간
다중 인증(MFA)서로 다른 요소 2개 이상 조합

3. 접근제어의 기본 원칙​

원칙내용
최소 권한(Least Privilege)업무 수행에 필요한 최소한의 권한만 부여
직무 분리(Separation of Duty)중요 업무를 분할하여 1인 단독 수행 방지(요청자 ≠ 승인자)
알 필요성(Need to Know)알아야 할 필요가 있는 정보만 접근
기본 거부(Deny by Default)명시적으로 허용되지 않은 것은 모두 거부
책임 추적성(Accountability)모든 접근을 개인 단위로 식별·기록(공용 계정 금지)
완전 중재(Complete Mediation)모든 접근을 예외 없이 검사

Ⅲ. 접근제어 정책 (Policy)​

1. 접근제어 정책의 유형​

   ┌──── **강제적**(MAC) ── 시스템이 결정, 소유자 변경 불가 ────┐
   │  · 보안 등급(Label) 기반, **군·정부 기밀** 환경             │
   ├──── **임의적**(DAC) ── **소유자**가 권한 부여 결정 ─────────┤
   │  · 유연하나 **권한 전파 통제 곤란**, 일반 OS·파일시스템     │
   ├──── **역할 기반**(RBAC) ── **직무 역할**에 권한 부여 ───────┤
   │  · **기업·공공의 사실상 표준**                              │
   ├──── **속성 기반**(ABAC) ── 다양한 **속성·상황** 조합 ───────┤
   │  · 세밀·동적, **제로트러스트의 기반**                       │
   └────────────────────────────────────────────────────────────┘

2. 정책별 상세 비교​

구분MAC
(강제적 접근통제)		DAC
(임의적 접근통제)		RBAC
(역할기반 접근통제)		ABAC
(속성기반 접근통제)
권한 결정 주체시스템·보안관리자자원 소유자관리자(역할 정의)정책 엔진(규칙)
판단 기준보안 등급(Label)
주체 인가등급 vs 객체 분류등급		소유자의 재량사용자에게 부여된 역할주체·객체·환경 속성 조합
유연성낮음(경직)높음중간매우 높음
관리 편의성중간낮음(권한 산재)높음(역할 단위 관리)낮음(정책 복잡)
대표 모델Bell-LaPadula(기밀성)
Biba(무결성)		ACL, 소유권 모델RBAC0~3, NIST RBACXACML, 제로트러스트
장점강력한 기밀성 보장, 정보 흐름 통제구현 단순, 사용자 자율조직 구조와 정합, 인사이동 대응 용이상황 인지형 세밀 통제
단점유연성 부족, 운영 부담트로이목마 취약, 권한 확산역할 폭발(Role Explosion)정책 설계·성능 부담
적용 예군·국가기밀, 등급 분류 시스템Windows/Unix 파일 권한ERP·행정정보시스템·기업 IAM클라우드·API·제로트러스트

3. 주요 접근제어 모델​

모델내용
Bell-LaPadula(BLP)기밀성 중심
No Read Up(상위 등급 읽기 금지) + No Write Down(하위 등급 쓰기 금지)
Biba무결성 중심 — BLP의 반대
No Read Down + No Write Up
Clark-Wilson상용 무결성 — 잘 구성된 트랜잭션과 직무 분리 강조
Chinese Wall(Brewer-Nash)이해충돌 방지 — 경쟁사 정보 동시 접근 차단(컨설팅·금융)
RBAC 계층 모델RBAC0(기본) → RBAC1(역할 계층) → RBAC2(제약: 직무분리) → RBAC3(통합)

4. 접근제어 정책 수립 시 고려사항​

고려사항내용
자산 중요도 기반 차등모든 자산에 동일 통제 적용 불가 → 정보 등급 분류 선행
법·규제 요건 반영개인정보보호법 안전성 확보조치 기준(접근권한 관리), ISMS-P, 전자금융감독규정
조직 구조와의 정합역할 정의는 인사·직무 체계와 연계되어야 유지 가능
정책의 문서화·승인접근권한 부여·변경·회수 기준을 내부관리계획에 명시

Ⅳ. 접근제어 절차 (Process)​

1. 접근권한 생애주기 관리​

   ① **정보자산 식별·등급 분류**
        │  보호 대상 자산 목록화, 중요도·민감도 등급 부여
        ▼
   ② **접근제어 정책 수립**
        │  정책 유형(RBAC 등) 결정, **역할·권한 매트릭스** 정의
        │  직무 분리 규칙, 승인 체계 정의
        ▼
   ③ **권한 신청·승인**(Provisioning)
        │  · 사용자 **접근권한 신청서** 제출(사유·기간 명시)
        │  · **직속 상급자 + 자산 관리자 승인**(이중 승인)
        │  · **최소 권한 원칙** 적용 검토
        ▼
   ④ **계정·권한 부여**
        │  · **고유 계정 발급**(공용 계정 금지), 초기 비밀번호 강제 변경
        │  · 역할 할당, **유효기간 설정**(임시 권한은 자동 만료)
        │  · 부여 이력 기록
        ▼
   ⑤ **인증·접근 통제**(Enforcement)
        │  · 접근 시마다 **식별 → 인증 → 인가** 수행
        │  · MFA 적용, 접속 위치·시간 제한
        │  · **모든 접근 로그 기록**
        ▼
   ⑥ **모니터링·감사**
        │  · **접속기록 점검**(개인정보 처리시스템은 **월 1회 이상 점검** 의무)
        │  · 이상행위 탐지(비정상 시간·대량 조회·권한 외 접근 시도)
        ▼
   ⑦ **권한 정기 검토·재인증**(Recertification)
        │  · **반기·연 1회 이상 권한 적정성 재검토**
        │  · 미사용 계정·과다 권한 식별 → 회수
        │  · **권한 누적(Privilege Creep)** 제거
        ▼
   ⑧ **권한 변경·회수**(De-provisioning)
        │  · **인사이동 시 기존 권한 회수 후 신규 부여**(추가 부여 금지)
        │  · **퇴직·계약 종료 시 즉시 계정 차단**  ← **가장 빈번한 통제 실패 지점**
        │  · 외부 인력·협력사 계정의 **사업 종료 시 일괄 회수**
        ▼
   ⑨ **개선·환류** → ②로 순환(PDCA)

2. 단계별 핵심 통제 포인트​

단계통제 포인트빈번한 실패 사례
권한 신청·승인사유의 타당성, 이중 승인형식적 승인, 일괄 신청
권한 부여최소 권한, 유효기간"일단 넓게" 부여 후 방치
접근 통제MFA, 세션 관리관리자 계정 MFA 미적용
모니터링로그 완전성, 정기 점검로그는 쌓이나 아무도 보지 않음
정기 검토실질적 재검토명단 확인만 하는 형식적 검토
회수즉시성퇴직자 계정 미삭제, 협력사 계정 잔존

Ⅴ. 접근제어 구현 메커니즘​

1. 논리적(기술적) 메커니즘​

계층메커니즘내용
인증 메커니즘비밀번호 정책복잡도·주기적 변경·재사용 금지·계정 잠금
MFA / OTP지식+소유+존재 조합, 관리자 계정 필수 적용
인증서(PKI)공개키 기반 강력 인증, 상호 인증
생체 인증지문·홍채·얼굴 — FIDO 기반
SSO / 통합인증SAML·OAuth 2.0·OIDC, 케르베로스(Kerberos)
인가 메커니즘ACL(접근제어목록)객체 기준 — "이 파일에 누가 접근 가능한가"
Capability List주체 기준 — "이 사용자가 무엇에 접근 가능한가"
접근제어 행렬(Access Matrix)주체×객체 권한 표 — ACL·CL의 개념적 원형
보안 레이블MAC 구현 — 등급·구획(Compartment)
정책 엔진(PDP/PEP)XACML 기반 — 정책결정점(PDP)과 정책시행점(PEP) 분리
시스템 통제OS 접근통제파일 권한, SELinux·AppArmor(강제적 접근통제 구현)
DBMS 접근통제GRANT/REVOKE, 뷰(View) 를 통한 컬럼·행 제한, 행 수준 보안(RLS), 감사(Audit)
애플리케이션 접근통제메뉴·기능·데이터 권한, 화면 항목 마스킹
네트워크 통제방화벽·ACLIP·포트 기반 접근 통제, 기본 차단 정책
NAC단말 인증·보안 상태 점검 후 네트워크 접속 허용
VPN·전용선원격 접근의 안전 채널
망분리 / N2SF업무망·인터넷망 분리, 등급별 접근 통제
마이크로세그멘테이션서버·워크로드 간 세밀한 통신 통제
특권 계정 관리PAM(Privileged Access Management)관리자 계정 비밀번호 금고, 세션 녹화, 명령어 통제, 사용 시점 승인(Just-in-Time)
통합 관리IAM / IGA계정 생애주기 자동화(프로비저닝·디프로비저닝), 권한 검토 워크플로
데이터 보호 연계DRM·DLP문서 암호화·권한 통제, 반출 차단
DB 접근제어 솔루션쿼리 통제·마스킹·감사
감사·추적로그·SIEM접근 기록 수집·상관분석, 위·변조 방지 보관
UEBA사용자 행위 기반 이상 접근 탐지

2. 물리적·관리적 메커니즘​

구분메커니즘
물리적출입통제 장치(카드·생체), 전산실 이중 출입통제, CCTV, 잠금장치, 방문자 관리, 매체 반출입 통제
관리적내부관리계획, 접근권한 관리대장, 보안 서약, 직무 분리 규정, 정기 권한 검토 절차, 교육·훈련

3. 제로트러스트 기반 접근제어 (최신 동향)​

   [**경계 기반**]                    [**제로트러스트**]
   "내부망은 신뢰"                 → "**절대 신뢰하지 말고 항상 검증**"
   1회 인증 후 광범위 접근         → **모든 요청마다 재검증**
   네트워크 위치가 신뢰 기준       → **정체성(Identity)이 새로운 경계**
   정적 권한                       → **동적·상황 인지형 권한(ABAC)**
        ▼
   **핵심 구성** : 강력한 인증(MFA) + **최소 권한** +
                  **마이크로세그멘테이션** + **지속적 검증·모니터링**
   근거 : NIST SP 800-207, 국내 **제로트러스트 가이드라인**, **N2SF**
구성요소역할
PEP(정책시행점)실제 접근을 허용·차단하는 지점(게이트웨이·에이전트)
PDP(정책결정점)정책 엔진 — 주체·기기·상황 신뢰도를 평가하여 결정
신뢰 평가 요소사용자 인증 강도, 단말 보안 상태, 위치·시간, 행위 이상 여부

Ⅵ. 고려사항​

고려사항내용
① 보안과 업무 편의성의 균형과도한 통제는 우회 행위 유발(권한 공유·계정 대여) → SSO·JIT 권한으로 편의성 확보
② 역할 폭발(Role Explosion) 관리RBAC 확장 시 역할 수가 급증 → 역할 계층화, 역할 마이닝, ABAC 부분 도입
③ 특권 계정이 최대 위험관리자 계정 침해 = 전면 침해 → PAM 도입·세션 녹화·MFA 필수
④ 퇴직·이동자 권한 회수의 즉시성실무에서 가장 빈번한 감사 지적 사항 → 인사 시스템과 IAM 자동 연계
⑤ 정기 검토의 실질화형식적 검토 방지 → 미사용 계정·과다 권한 자동 리포트 제공
⑥ 클라우드 환경 확장IAM 설정 오류가 클라우드 사고의 대다수 → 과도한 정책(:) 금지, 공개 자원 점검 자동화
⑦ 비인간 주체(NHI) 관리서비스 계정·API 키·AI 에이전트 권한 관리 → 키 순환, 최소 권한, 만료 정책
⑧ 암호화와의 결합접근제어 우회 시 대비 → 저장·전송 암호화, DB 컬럼 암호화·마스킹 병행
⑨ 로그의 실효성기록만 하고 점검하지 않으면 무의미 → 자동 분석·경보 체계, 개인정보 처리시스템은 월 1회 이상 점검 의무
⑩ 개인정보 특칙개인정보 처리자 접근권한 최소화, 접속기록 1년(중요 시 2년) 이상 보관, 위·변조 방지

Ⅶ. 결론​

접근제어는 암호화와 함께 정보보호의 양대 축을 이루되, 그 성격이 다르다. 암호화가 "접근하더라도 이해할 수 없게" 만드는 사후적 방어라면, 접근제어는 "애초에 접근하지 못하게" 하는 1차 방어선이며, 인증·인가·감사의 전 과정을 포괄하는 모든 보안 통제의 기반이 된다.

정책 측면에서는 MAC(등급 기반)·DAC(소유자 재량)·RBAC(역할 기반)·ABAC(속성 기반) 중 조직 특성에 맞는 선택이 필요하다. 실무에서는 조직 구조와 정합성이 높고 관리가 용이한 RBAC이 기본이 되며, 클라우드·원격근무 환경에서는 상황을 반영한 동적 통제가 가능한 ABAC이 결합되는 추세이다.

절차 측면의 핵심은 접근권한을 부여하는 것이 아니라 회수하고 검토하는 것이다. 실제 감사에서 지적되는 대부분의 문제는 권한 부여 절차의 미비가 아니라 퇴직자 계정 미삭제, 인사이동 시 기존 권한 잔존, 형식적인 정기 검토에서 발생한다. 따라서 인사 시스템과 IAM의 자동 연계를 통한 즉시 회수 체계가 무엇보다 중요하다.

메커니즘 측면에서는 논리적·물리적·관리적 통제가 계층적으로 결합되어야 하며, 특히 특권 계정 관리(PAM) 가 최우선 투자 대상이다. 관리자 계정 하나의 침해가 전체 시스템 장악으로 이어지기 때문이다.

끝으로, 재택근무·클라우드·API 연계가 보편화되면서 "내부망은 안전하다"는 경계 기반 전제가 무너졌다. 따라서 접근제어의 패러다임은 네트워크 위치가 아니라 정체성(Identity)을 경계로 삼고, 모든 요청을 매번 검증하는 제로트러스트로 이동하고 있다. 여기에 서비스 계정과 AI 에이전트 같은 비인간 주체(NHI)의 권한 관리라는 새로운 과제가 더해지고 있으며, 이는 향후 접근제어 설계에서 반드시 고려해야 할 영역이다.
