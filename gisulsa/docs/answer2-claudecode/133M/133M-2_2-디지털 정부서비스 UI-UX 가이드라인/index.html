디지털 정부서비스 UI/UX 가이드라인

문제​

2."디지털 정부서비스 UI/UX 가이드라인"(2024.2, 행정안전부)은 디지털 서비스를구성하는사용자 인터페이스(User Interface; UI)와 사용자 경험(User Experience; UX) 품질에큰 영향을 주는 요소에 대하여 행정기관 및 공공기관이 준수해야 할 세부사항을제시한다. 이와 관련하여 다음을 설명하시오.
가.목적 및 주요특징
나.가이드라인의 구조(구성요소)
다.적용대상 및 기준
라.가이드라인의 활용방법

Ⅰ. 개요​

1. 배경​

공공 웹·앱은 기관별로 개별 발주·개별 설계되어 화면 구성·용어·절차가 제각각이었고, 이용자는 기관을 옮길 때마다 사용법을 다시 배워야 했다. 또한 복잡한 인증 절차·행정 용어·접근성 미흡이 디지털 소외를 심화시켰다.

   [기존 공공 디지털 서비스의 문제]
   기관마다 다른 화면·용어·절차     → **학습 비용 반복**
   행정 편의 중심 정보 구조         → **이용자가 원하는 정보 탐색 곤란**
   복잡한 본인확인·설치 요구        → **중도 이탈**
   접근성·모바일 대응 미흡          → **디지털 격차**
        ▼
   **「디지털플랫폼정부」** 실현 · **「지능정보화 기본법」** 접근성 의무
        ▼
   [**디지털 정부서비스 UI/UX 가이드라인**(2024.2, 행정안전부)]
   ⇒ **"기관 중심"에서 "국민 중심"으로**, **일관된 사용자 경험** 제공

2. 관련 근거​

근거내용
전자정부법전자정부서비스의 이용자 중심 설계·품질 관리 의무
지능정보화 기본법 제46조웹 접근성 준수 의무(장애인·고령자 접근 보장)
행정기관 웹사이트 구축·운영 지침웹사이트 표준·품질 기준
한국형 웹 콘텐츠 접근성 지침(KWCAG) 2.2접근성 기술 표준

Ⅱ. 가. 목적 및 주요 특징​

1. 목적​

목적내용
① 국민 중심의 서비스 실현기관 조직도가 아닌 국민의 업무·생애주기 관점으로 서비스 구성
② 일관된 사용자 경험 제공기관이 달라도 동일한 조작 방식·용어·화면 패턴 → 학습 비용 최소화
③ 서비스 품질 상향 평준화기관 역량 차이에 따른 품질 편차 해소
④ 포용성(접근성) 확보장애인·고령자·저숙련층 등 누구나 이용 가능한 서비스
⑤ 구축 효율성 제고검증된 표준 패턴·컴포넌트 재사용 → 설계 시간·비용 절감
⑥ 발주·검수 기준 제공사업 발주 시 명확한 UI/UX 요구사항과 검수 근거 마련

2. 주요 특징​

특징내용
원칙 + 실행지침의 2단 구조추상적 원칙에 그치지 않고 구체적 준수사항·적용 예시(Do/Don't) 제시
모바일 우선(Mobile First)이용의 대다수가 모바일 → 반응형·모바일 기준 설계를 기본 전제로
접근성 내재화접근성을 사후 점검 항목이 아니라 설계 원칙으로 통합
쉬운 언어(Plain Language)행정·법령 용어를 국민이 이해하는 표현으로 전환
디자인 시스템 연계컴포넌트·패턴을 재사용 가능한 자산으로 제공(디자인 시스템 기반)
점검 가능한 체크리스트각 항목을 자가진단·검수용 체크리스트로 제공
최소 기준 성격강제 규격이 아닌 준수해야 할 최소 수준 — 기관 특성에 따른 확장 허용

3. 핵심 설계 원칙​

   [국민 중심 UI/UX 5대 지향점]
   ┌────────────────┬──────────────────────────────────────┐
   │ **① 이해 용이** │ 쉬운 용어, 명확한 안내, 예측 가능한 흐름│
   │ **② 접근 포용** │ 장애·연령·기기·환경에 관계없는 접근     │
   │ **③ 일관성**    │ 기관 간 동일한 패턴·용어·아이콘         │
   │ **④ 효율성**    │ 최소 단계·최소 입력, 불필요한 절차 제거 │
   │ **⑤ 신뢰·안전** │ 정확한 정보, 안전한 처리, **다크패턴 금지**│
   └────────────────┴──────────────────────────────────────┘

Ⅲ. 나. 가이드라인의 구조(구성요소)​

1. 전체 체계​

2. 주요 구성요소별 내용​

구성 영역주요 지침 내용
정보구조(IA)·내비게이션국민 관점의 메뉴 분류(조직 중심 금지), 3단계 이내 접근, 현재 위치 표시, 일관된 메뉴 배치
레이아웃·그리드반응형 그리드, 모바일·태블릿·PC 브레이크포인트, 주요 정보 우선 배치
색상·타이포그래피명도 대비 4.5:1 이상, 색상만으로 정보 전달 금지, 최소 글자 크기·행간, 확대 대응
버튼·링크충분한 터치 영역(44px 이상 권장), 주·부 버튼 위계, 명확한 레이블("확인"보다 "신청하기")
입력 폼(핵심)입력 항목 최소화, 명확한 레이블·플레이스홀더 구분, 실시간 유효성 검사, 자동완성 지원, 오류 시 원인과 해결방법 제시
알림·오류 메시지무엇이/왜/어떻게 3요소, 기술적 오류코드 노출 금지, 진행 상태 피드백
표·목록모바일에서 가로 스크롤 대응, 정렬·필터 제공, 핵심 열 우선
검색오타 보정, 유의어·자연어 검색, 검색 결과 없음 시 대안 제시
인증·본인확인불필요한 설치·플러그인 요구 금지, 다양한 인증 수단 제공, 절차 단계 표시
접근성KWCAG 2.2 준수 — 대체 텍스트, 키보드 접근, 초점 이동, 스크린리더 대응, 자막
콘텐츠·언어쉬운 우리말, 한자어·약어 지양, 능동형 문장, 문장 길이 제한
다크패턴 금지자동 결제 유도, 숨겨진 해지, 거짓 긴급성 등 기만적 설계 금지

Ⅳ. 다. 적용대상 및 기준​

1. 적용 대상​

구분내용
적용 기관중앙행정기관·지방자치단체·공공기관 등 행정·공공기관
적용 서비스국민·기업이 이용하는 웹사이트, 모바일 앱, 키오스크 등 디지털 서비스
적용 시점신규 구축·전면 개편(재구축) 사업에 우선 적용
기존 서비스는 고도화·개선 시 단계적 적용
적용 제외·완화내부 업무시스템(직원 전용), 특수 목적 시스템은 기관 판단으로 선택 적용
   [적용 판단 흐름]
   대상 서비스인가? (대국민 디지털 서비스)
        │ Yes
        ▼
   신규 구축·전면 개편인가?  ──Yes──▶ **필수 적용**(RFP에 명시)
        │ No
        ▼
   부분 개선·운영 중         ──────▶ **단계적 적용**(개선 시 반영)
        │
        ▼
   내부 업무·특수 시스템     ──────▶ **선택 적용**(원칙 참조)

2. 적용 기준(수준)​

준수 수준내용
필수(Must)법적 의무 사항 — 웹 접근성(KWCAG), 개인정보 보호, 다크패턴 금지 등 → 반드시 준수
권장(Should)품질 향상을 위한 표준 패턴 — 특별한 사유가 없으면 준수
선택(May)서비스 특성에 따라 선택 적용
적용 기준 원칙내용
최소 기준가이드라인은 상한이 아닌 하한 — 기관은 더 높은 수준으로 확장 가능
서비스 특성 반영획일적 적용이 아닌 업무 유형(신청·조회·납부)별 맞춤 적용
기존 자산 고려기관 고유 브랜드·디자인 시스템이 있는 경우 원칙과 충돌하지 않는 범위에서 조화
점진적 이행예산·일정 제약 시 우선순위(접근성 → 핵심 업무 흐름 → 세부 요소) 기준 단계 적용

Ⅴ. 라. 가이드라인의 활용방법​

1. 사업 생애주기별 활용​

   ① **기획 단계**
        │  · 현행 서비스 **UI/UX 자가진단**(체크리스트) → 개선 과제 도출
        │  · 사용자 조사(인터뷰·행태 분석)로 **개선 목표 설정**
        ▼
   ② **발주(RFP) 단계**  ★ 가장 중요한 활용 지점
        │  · **RFP 요구사항에 가이드라인 준수 명시**(필수 항목 목록화)
        │  · 산출물 요구 — 화면설계서, **접근성 준수 결과**, 사용성 테스트 보고서
        │  · 평가 항목에 UI/UX 품질 반영
        ▼
   ③ **설계 단계**
        │  · **컴포넌트·패턴 재사용**으로 화면설계
        │  · 프로토타입 제작 → **사용성 테스트(UT)** 로 조기 검증
        ▼
   ④ **구현 단계**
        │  · 퍼블리싱 시 **접근성 코드 규칙**(대체텍스트·레이블·초점) 준수
        │  · 반응형·크로스브라우징 구현
        ▼
   ⑤ **검수·감리 단계**
        │  · **체크리스트 기반 검수**, 접근성 자동·수동 진단
        │  · **웹 접근성 품질인증** 취득 검토
        ▼
   ⑥ **운영·개선 단계**
        │  · 이용 로그·이탈률·**이용자 피드백** 분석
        │  · 정기 진단 → 개선 반영(**지속적 UX 개선 체계**)

2. 주체별 활용 방법​

주체활용 방법
발주 기관(담당 공무원)· RFP 요구사항 작성 근거로 활용
· 사업자 산출물 검수 기준
· 기관 내 서비스 자가진단·개선계획 수립
수행 사업자(설계자·개발자)· 화면 설계·퍼블리싱의 실무 표준
· 컴포넌트 재사용으로 설계 공수 절감
· Do/Don't 사례로 리뷰 기준 확보
감리·품질 담당· 점검 항목(체크리스트) 으로 적합성 판단
· 접근성 법적 의무 이행 여부 확인
기관 정책 부서· 기관 디자인 시스템 수립의 기준
· 서비스 품질 평가 지표 반영

3. 효과적 활용을 위한 고려사항​

고려사항내용
① 발주 단계 반영이 핵심개발 완료 후 요구하면 재작업 비용 급증 → RFP·과업지시서에 명시해야 실효성 확보
② 체크리스트의 형식화 경계"체크만 하고 실제 사용성은 나쁜" 사례 방지 → 실제 이용자 대상 사용성 테스트(UT) 병행
③ 접근성은 사후 점검이 아닌 설계 요소완성 후 접근성 보정은 비용 과다 → 설계 단계부터 내재화
④ 디자인 시스템으로 자산화사업마다 새로 만들지 말고 기관·범정부 공통 컴포넌트 축적·재사용
⑤ 기관 정체성과의 균형일관성이 곧 획일화는 아님 — 구조·패턴은 표준, 브랜드 표현은 자율
⑥ 지속 개선 체계일회성 구축이 아닌 이용 데이터 기반 상시 개선(A/B 테스트, 이탈 분석)
⑦ 조직 역량 확보담당자 교육, UX 전문 인력 확보 또는 자문 활용

Ⅵ. 결론​

디지털 정부서비스 UI/UX 가이드라인은 "기관마다 다른 서비스"를 "국민에게 하나로 느껴지는 서비스"로 전환하려는 정책 도구이다. 그 본질은 화면을 예쁘게 만드는 규칙이 아니라, 정보구조·용어·절차·접근성이라는 서비스의 뼈대를 국민 관점으로 재정렬하는 데 있다.

실효성을 좌우하는 것은 세 가지이다. 첫째, 발주 단계에서 RFP 요구사항으로 명문화해야 한다. 설계·개발이 끝난 뒤의 요구는 재작업 비용으로 인해 형식적 반영에 그친다. 둘째, 접근성을 설계 원칙으로 내재화해야 한다. 접근성은 법적 의무일 뿐 아니라 모든 이용자의 사용성을 함께 높이는 기반이다. 셋째, 체크리스트 준수를 넘어 실제 이용자 대상 사용성 테스트로 검증해야 한다. 가이드라인 준수와 실제 사용 편의는 자동으로 일치하지 않는다.

궁극적으로 이 가이드라인은 범정부 디자인 시스템으로 자산화될 때 가치가 극대화된다. 검증된 컴포넌트와 패턴이 축적되면 개별 기관은 설계 비용을 절감하면서 동시에 품질을 확보할 수 있으며, 이것이 디지털플랫폼정부가 지향하는 "국민 중심의 일관된 디지털 경험" 의 실질적 구현 방식이다.
