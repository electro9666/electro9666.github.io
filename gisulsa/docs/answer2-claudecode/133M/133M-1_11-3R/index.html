3R (Reverse Engineering, Restructuring, Reengineering)

문제​

11.소프트웨어 유지보수 향상 및 비용절감을 위한 3R을 설명하시오.

Ⅰ. 개요​

3R은 기존 소프트웨어 자산을 폐기·재구축하지 않고 재활용하여 유지보수성을 높이고 비용을 절감하는 세 가지 기법 — 역공학(Reverse Engineering)·재구조화(Restructuring)·재공학(Reengineering) — 을 말한다. 여기에 재사용(Reuse) 을 포함해 폭넓게 다루기도 한다.

   [등장 배경 — 레거시의 딜레마]
   SW 총비용의 **약 70%가 유지보수 단계**에 집중
   문서 부재 · 잦은 패치로 **구조 열화(Software Aging)** · 담당자 이직
        ▼
   **전면 재개발** → 비용·기간·위험 과다, 축적된 업무 규칙 유실
   **방치**       → 유지보수비 지속 증가, 변경 불가
        ▼
   [**3R**] **기존 자산을 살리면서 품질을 회복**하는 중간 전략

Ⅱ. 3R의 구성 및 상호 관계​

                    **[재공학 — Reengineering]**
      ┌──────────────────────────────────────────────────────┐
      │                                                      │
      │   기존 시스템                          개선 시스템     │
      │        │                                    ▲        │
      │        │ **① 역공학**              **③ 순공학**       │
      │        │ (Reverse)                 (Forward)         │
      │        ▼                                    │        │
      │   설계·분석 정보 ──▶ **② 재구조화** ──▶ 개선 설계     │
      │   (추상화 수준 ↑)     (Restructuring)                 │
      │                     동일 수준 내 구조 개선            │
      └──────────────────────────────────────────────────────┘
      ※ **역공학 = 추상화 수준 상승**, **재구조화 = 동일 수준 변환**,
         **재공학 = 역공학 + 재구조화 + 순공학의 전체 사이클**
구분역공학(Reverse Engineering)재구조화(Restructuring)재공학(Reengineering)
정의기존 코드·시스템을 분석하여 설계·명세 등 상위 정보를 추출기능은 그대로 두고 코드·데이터의 구조·형태를 개선역공학·재구조화·순공학을 결합해 시스템을 재탄생
방향Bottom-Up(코드 → 설계)동일 수준 변환전체 생명주기 순환
기능 변경없음(분석만)없음(외부 동작 불변)있을 수 있음(개선·확장)
산출물데이터 모델·프로세스 모델·소스 문서개선된 소스·데이터 구조개선된 신규 시스템
기법코드 분석, DB 스키마 추출, CFG/DFD 생성, 문서 재생성리팩토링, 코드 정규화, GOTO 제거, DB 정규화, 모듈 분할마이그레이션, 언어·플랫폼 전환, 아키텍처 현대화
비용·위험낮음중간높음

Ⅲ. 각 기법의 상세​

1. 역공학 (Reverse Engineering)​

유형내용
논리 역공학소스코드 → 프로그램 로직·업무 규칙 추출
데이터 역공학DB/파일 → 논리·개념 데이터 모델(ERD) 복원
프로세스 역공학실행 흐름 → 프로세스 모델·호출 관계도
UI 역공학화면 → 화면 설계서·흐름도
활용문서 부재 레거시 분석, 영향도 분석, 인수인계, 마이그레이션 사전 분석
유의타사 SW 역공학은 저작권·라이선스 위반 소지 → 적법성 검토 필수

2. 재구조화 (Restructuring)​

유형내용
코드 재구조화리팩토링 — 중복 제거, 긴 함수 분할, 명명 개선, GOTO 제거(구조적 프로그래밍화)
데이터 재구조화정규화·반정규화, 데이터 타입·코드체계 표준화
문서 재구조화산출물 최신화·표준 양식 정비
효과가독성·이해도 향상 → 유지보수 공수 감소, 결함 밀도 감소, 변경 용이성 확보
전제회귀 테스트 체계 필수 — 기능 불변을 보장할 자동화 테스트가 없으면 위험

3. 재공학 (Reengineering)​

유형내용
재문서화(Redocumentation)현행 시스템의 문서 재생성 — 가장 낮은 수준의 재공학
데이터 마이그레이션파일 → RDBMS, 계층형 DB → 관계형 DB
플랫폼 전환메인프레임 → 오픈/클라우드(Rehost·Replatform), COBOL → Java
아키텍처 현대화모놀리식 → MSA·컨테이너, 화면 계층 분리
절차① 현행 분석 → ② 역공학(설계 복원) → ③ 재구조화(구조 개선) → ④ 순공학(구현) → ⑤ 테스트·전환

4. 재사용 (Reuse) — 보완 개념​

유형내용
재사용 수준코드 → 함수·클래스 → 컴포넌트·라이브러리 → 프레임워크 → 아키텍처·패턴
접근합성 중심(Composition-based) — 부품 조립 / 생성 중심(Generation-based) — 코드 생성기
효과개발 생산성·품질 향상, 검증된 자산 활용으로 결함 감소

Ⅳ. 효과 및 적용 시 고려사항​

기대 효과내용
유지보수 비용 절감구조 개선으로 변경 공수·결함 수정 시간 단축
자산 보존축적된 업무 규칙(Business Rule) 유실 방지 — 재개발의 최대 위험 회피
위험 저감전면 재구축 대비 점진적·단계적 개선 가능
수명 연장시스템 생애주기 연장으로 투자 회수 극대화
고려사항내용
경제성 판단유지보수비 > 재구축비이거나 구조 열화가 심하면 3R보다 재개발이 유리 → 사전 타당성 분석
회귀 테스트 확보기능 불변을 증명할 자동화 테스트가 3R의 전제조건
점진적 적용빅뱅 전환 금지 → 스트랭글러 패턴 등으로 모듈 단위 단계 적용
우선순위 선정변경 빈도 × 복잡도 × 결함 밀도가 높은 모듈부터
법적 검토상용 SW·타사 자산의 역공학은 저작권·계약 위반 가능
도구 활용정적 분석(SonarQube), 아키텍처 시각화, 커버리지 측정, 코드 클론 탐지
문서·형상 동기화개선 결과가 문서에 반영되지 않으면 재열화 반복

Ⅴ. 결론​

3R은 레거시를 "버릴 것인가, 방치할 것인가"라는 이분법을 넘어, 기존 자산의 가치를 살리면서 품질을 회복하는 현실적 전략이다. 역공학으로 이해하고, 재구조화로 정돈하며, 재공학으로 현대화하는 단계적 접근이 그 골격이다.

실무 성공의 관건은 세 가지다. ① 3R과 재개발 사이의 경제성 판단을 정량적으로 수행할 것, ② 회귀 테스트 자동화를 선행하여 "기능 불변"을 증명할 수 있게 할 것, ③ 스트랭글러 패턴 등으로 점진 전환하여 위험을 통제할 것이다. 특히 최근에는 클라우드 전환·MSA 현대화가 재공학의 주된 형태이므로, 6R 전환 전략과 결합하여 시스템별로 3R 적용 수준을 차등 설계하는 것이 바람직하다.
