문제 4) 소프트웨어 테스트

답)

I. 개요​

소프트웨어 테스트(Software Testing)는 개발된 소프트웨어가 명세된 요구사항을 충족하는지 검증(Verification)하고, 사용자 기대를 만족하는지 확인(Validation)하는 활동이다. 테스트는 결함을 발견하여 소프트웨어 품질을 높이는 핵심 활동이지만, 완벽한 테스트는 불가능하므로 원리에 기반한 체계적 접근이 필요하다.

가. 소프트웨어 테스트의 7대 원리​

1. 7대 원리 개요​

ISTQB(국제 소프트웨어 테스팅 자격위원회)가 정립한 소프트웨어 테스트 7대 원리는 효과적인 테스트 전략 수립의 기반이 된다.

2. 7대 원리 상세 설명​

원리내용시사점
결함 존재 증명테스트는 결함이 존재함을 보일 수 있으나, 결함이 없음을 증명할 수는 없다테스트 통과가 무결함을 보장하지 않음
완벽한 테스트 불가능모든 입력과 경로 조합을 테스트하는 것은 현실적으로 불가능하다위험 기반 우선순위 테스트 필요
초기 집중결함은 개발 초기에 발견할수록 수정 비용이 적다요구사항/설계 단계부터 테스트 활동 시작
결함 집중 (파레토)결함의 80퍼센트는 모듈의 20퍼센트에 집중된다결함 다발 모듈에 테스트 자원 집중
살충제 역설동일 테스트케이스 반복 시 새로운 결함을 찾지 못한다테스트케이스 주기적 검토 및 갱신
정황 의존테스트는 상황(도메인, 위험도)에 따라 다르게 수행된다금융, 의료, 게임 등 도메인별 차등 전략
오류-부재의 궤변결함을 모두 제거해도 요구사항 불일치 시 무용하다검증(Verification)과 확인(Validation) 병행

3. 결함 발견 비용 곡선 (초기 집중 원리)​

결함 수정 비용은 개발 단계가 진행될수록 기하급수적으로 증가한다. 이를 정량화하면 다음과 같다.

Costfix(stage)≈Costbase×rstage,r>1Cost_{fix}(stage) \approx Cost_{base} \times r^{stage}, \quad r > 1Costfix​(stage)≈Costbase​×rstage,r>1

여기서 rrr은 단계별 비용 증가율로, 운영 단계에서 발견된 결함은 요구사항 단계 대비 약 100배의 수정 비용을 초래한다.

나. 화이트박스 테스트와 블랙박스 테스트 비교​

1. 개념 비교​

구분화이트박스 테스트블랙박스 테스트
별칭구조 기반 테스트, 구조적 테스트명세 기반 테스트, 기능 테스트
관점내부 코드 구조와 로직 검증입력 대비 출력의 기능 검증
요구 지식소스 코드 이해 필요코드 불필요, 명세만 필요
수행 주체개발자테스터, QA
적용 단계단위 테스트통합/시스템/인수 테스트
목표 척도코드 커버리지요구사항 커버리지

2. 화이트박스 테스트 기법 (커버리지)​

커버리지 기법정의강도
구문 커버리지모든 실행 문장을 최소 1회 실행약함
결정(분기) 커버리지모든 분기의 참/거짓을 최소 1회 실행중간
조건 커버리지각 조건식의 참/거짓을 최소 1회 실행중간
조건/결정 커버리지조건과 결정을 모두 만족 (MC/DC)강함
경로 커버리지모든 가능한 실행 경로를 실행가장 강함

순환 복잡도(Cyclomatic Complexity)는 독립 경로 수를 정량화한다.

V(G)=E−N+2PV(G) = E - N + 2PV(G)=E−N+2P

여기서 EEE는 간선 수, NNN은 노드 수, PPP는 연결 요소 수이다.

3. 블랙박스 테스트 기법​

기법정의특징
동등 분할입력을 유효/무효 동등 클래스로 분할 후 대표값 선정테스트케이스 수 감소
경계값 분석동등 클래스의 경계 부근 값 집중 검증경계 결함 검출 효과적
원인-결과 그래프입력 원인과 출력 결과의 논리 관계 도식화조합 결함 검출
상태 전이상태 변화와 이벤트 기반 검증상태 기반 시스템에 적합
결정 테이블조건 조합과 행동을 표로 정리복잡한 비즈니스 규칙

4. 통합 비교​

비교 항목화이트박스블랙박스
결함 검출 대상로직 오류, 누락 경로기능 누락, 명세 불일치
장점코드 레벨 정밀 검증사용자 관점 검증
단점명세 누락 검출 불가내부 로직 결함 누락 가능
상호 관계두 기법은 상호 보완적이며 병행 적용이 원칙

다. 동등분할과 경계값분석 테스트 케이스 작성​

1. 명세 분석​

학점 처리 모듈의 명세는 다음과 같다.

항목내용
입력점수(Score), 정수형, 유효 범위 0~100
출력 규칙90 이상 → A, 8089 → B, 7079 → C, 60~69 → D, 60 미만 → F
예외0~100 범위를 벗어나면 → ERROR

2. 동등 분할 (Equivalence Partitioning)​

입력 도메인을 동작이 동일한 동등 클래스로 분할한다. 각 클래스에서 대표값 1개를 선정하여 테스트한다.

(1) 동등 클래스 분할 표​

클래스 ID구분범위 조건기대 출력대표값
EC1 (유효)정상 입력90 ≤ Score ≤ 100A95
EC2 (유효)정상 입력80 ≤ Score ≤ 89B85
EC3 (유효)정상 입력70 ≤ Score ≤ 79C75
EC4 (유효)정상 입력60 ≤ Score ≤ 69D65
EC5 (유효)정상 입력0 ≤ Score ≤ 59F30
EC6 (무효)범위 미만Score < 0ERROR-10
EC7 (무효)범위 초과Score > 100ERROR110

3. 경계값 분석 (Boundary Value Analysis)​

결함은 동등 클래스의 경계에서 자주 발생한다. 각 경계마다 경계값과 경계 ±1 값을 테스트한다. 주요 경계는 -1/0/59/60/69/70/79/80/89/90/100/101 이다.

(4) 동등분할과 경계값분석 비교​

비교 항목동등 분할경계값 분석

목적도메인 전체 커버경계 결함 집중 검출
테스트케이스 수적음 (7개)상대적으로 많음 (13개)
적용 관계두 기법은 함께 적용하는 것이 원칙

결론​

구분핵심 요약
7대 원리테스트의 본질적 한계 인식과 효율적 자원 배분의 기준 제공
기법 선택화이트박스(구조)와 블랙박스(명세)의 상호 보완적 병행 적용
적용동등분할로 효율을 확보하고 경계값분석으로 경계 결함을 정밀 검출

정보관리기술사 관점에서, 소프트웨어 테스트는 단순 결함 발견 활동이 아니라 위험 기반(Risk-Based)으로 자원을 배분하는 품질 보증 전략이다. 특히 시프트 레프트(Shift-Left)를 통한 초기 집중과 테스트 자동화(CI/CD 통합), 그리고 살충제 역설 극복을 위한 테스트케이스의 지속적 진화가 고품질 소프트웨어 확보의 핵심이다.
