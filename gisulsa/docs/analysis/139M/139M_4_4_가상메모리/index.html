문제 4) 가상메모리(Virtual Memory)

답)

I. 개요​

가상메모리(Virtual Memory)는 물리 메모리(RAM)보다 큰 주소 공간을 프로세스에게 제공하기 위해, 보조기억장치(디스크)의 일부를 메모리처럼 활용하는 기억장치 관리 기법이다. CPU가 생성하는 가상 주소(Logical Address)를 MMU(Memory Management Unit)가 물리 주소(Physical Address)로 변환하며, 실제로 참조되는 부분만 메모리에 적재함으로써 다중 프로그래밍 정도(Degree of Multiprogramming)를 높이고 메모리를 효율적으로 사용한다.

구분가상 주소 공간물리 주소 공간
정의프로세스가 인식하는 논리 주소실제 RAM의 물리 주소
크기CPU 비트 수에 의존설치된 RAM 용량에 한정
변환 주체MMU + 페이지 테이블하드웨어 직접 접근
목적큰 주소 공간 환상 제공실제 데이터 저장

II. 가상메모리 관리기법 (가)​

1. 관리기법 분류 체계​

2. 주소 공간 분할 방식​

(1) 페이징 (Paging)​

페이징은 가상 주소 공간과 물리 메모리를 동일한 크기의 고정 블록으로 나누어 관리하는 기법이다. 가상 공간의 블록을 페이지(Page), 물리 공간의 블록을 프레임(Frame)이라 한다.

가상 주소는 페이지 번호(p)와 페이지 내 변위(d)로 구성된다.

Virtual Address=(p,d),Physical Address=f×PageSize+d\text{Virtual Address} = (p, d), \quad \text{Physical Address} = f \times \text{PageSize} + dVirtual Address=(p,d),Physical Address=f×PageSize+d

특징내용
블록 크기고정 크기 (예: 4KB)
단편화내부 단편화 발생, 외부 단편화 없음
장점메모리 관리 단순, 외부 단편화 제거
단점페이지 테이블 공간 오버헤드, 내부 단편화

(2) 세그먼테이션 (Segmentation)​

세그먼테이션은 프로그램을 논리적 단위(코드, 데이터, 스택 등)인 가변 크기의 세그먼트로 분할하는 기법이다. 세그먼트 테이블은 각 세그먼트의 시작 주소(Base)와 크기(Limit)를 보관한다.

Virtual Address=(s,d),d<Limit[s]⇒Physical=Base[s]+d\text{Virtual Address} = (s, d), \quad d < \text{Limit}[s] \Rightarrow \text{Physical} = \text{Base}[s] + dVirtual Address=(s,d),d<Limit[s]⇒Physical=Base[s]+d

특징내용
블록 크기가변 크기 (논리 단위)
단편화외부 단편화 발생, 내부 단편화 없음
장점논리적 보호 및 공유 용이
단점외부 단편화, 가변 크기 관리 복잡

(3) 페이징 + 세그먼테이션 (Paged Segmentation)​

세그먼테이션의 논리적 보호·공유 장점과 페이징의 외부 단편화 제거 장점을 결합한 혼합 기법이다. 세그먼트를 다시 페이지 단위로 분할한다.

비교 항목페이징세그먼테이션페이징+세그먼테이션
블록 크기고정가변세그먼트 가변 + 페이지 고정
단편화내부외부내부 (외부 제거)
논리적 공유곤란용이용이
주소 변환1단계1단계2단계 (오버헤드 큼)

3. 적재 정책: 요구 페이징 (Demand Paging)​

요구 페이징은 프로세스 실행에 실제로 필요한 페이지만을 그 시점에 메모리로 적재하는 정책으로, 참조되지 않은 페이지는 디스크에 둔다. 참조 시 페이지 테이블의 유효 비트(Valid Bit)를 검사한다.

유효 접근 시간(EAT, Effective Access Time)은 페이지 폴트 확률 p에 의해 결정된다.

EAT=(1−p)×tmem+p×tfaultEAT = (1 - p) \times t_{mem} + p \times t_{fault}EAT=(1−p)×tmem​+p×tfault​

정책설명장단점
요구 페이징참조 시점에 적재메모리 절약, 초기 폴트 다수
선반입 페이징미래 참조 예측 적재폴트 감소, 예측 실패 시 낭비

4. 페이지 교체 알고리즘 (Page Replacement)​

물리 프레임이 가득 찬 상태에서 새 페이지 적재 시, 축출할 희생 페이지를 선정하는 알고리즘이다. 다음은 참조열 7 0 1 2 0 3 0 4 (프레임 3개) 기준 비교이다.

알고리즘선정 기준장점단점
FIFO가장 먼저 적재된 페이지 축출구현 단순Belady 모순 발생 가능
LRU가장 오래 참조되지 않은 페이지지역성 반영, 성능 우수타임스탬프/스택 관리 비용
LFU참조 횟수 최저 페이지빈도 기반 합리적과거 빈번한 페이지 잔류 문제
Optimal미래에 가장 늦게 참조될 페이지폴트율 최소 (이론적 하한)미래 예측 불가, 실현 불가능

Belady의 모순(Belady's Anomaly): FIFO에서 프레임 수를 늘려도 페이지 폴트가 오히려 증가하는 현상. LRU·Optimal 등 스택 알고리즘에서는 발생하지 않는다.

// LRU 의사 코드 (참조 시각 기반)
int find_victim_LRU(Frame frames[], int n) {
    int victim = 0;
    for (int i = 1; i < n; i++) {
        if (frames[i].last_used < frames[victim].last_used)
            victim = i;  // 가장 오래된 참조 시각 선택
    }
    return victim;  // 해당 프레임의 페이지를 축출
}

5. 주소 변환 구조: 페이지 테이블과 TLB​

(1) 페이지 테이블 (Page Table)​

페이지 번호를 프레임 번호로 매핑하는 자료구조로, 각 엔트리(PTE)는 프레임 번호와 유효·보호·수정(Dirty)·참조 비트를 보관한다.

페이지 테이블 유형특징
단일 단계단순하나 큰 주소 공간에서 테이블 거대화
다단계(Multilevel)테이블을 페이지화하여 공간 절약
해시(Hashed)64비트 등 희소 주소 공간에 적합
역(Inverted)물리 프레임 기준, 전체 메모리에 단일 테이블

(2) TLB (Translation Lookaside Buffer)​

TLB는 최근 사용된 페이지 변환 정보를 보관하는 고속 캐시(연관 메모리)로, 페이지 테이블을 매번 참조하는 오버헤드를 줄인다.

TLB 적중률 h를 반영한 유효 접근 시간은 다음과 같다.

EAT=h×(ttlb+tmem)+(1−h)×(ttlb+2×tmem)EAT = h \times (t_{tlb} + t_{mem}) + (1 - h) \times (t_{tlb} + 2 \times t_{mem})EAT=h×(ttlb​+tmem​)+(1−h)×(ttlb​+2×tmem​)

III. 가상메모리 단편화 유형 (나)​

1. 단편화 개요​

단편화(Fragmentation)는 메모리 할당·해제 과정에서 사용 불가능한 자투리 공간이 발생하여 메모리 이용률이 저하되는 현상이다.

2. 내부 단편화 (Internal Fragmentation)​

고정 크기 블록(페이지/프레임)을 할당할 때, 실제 필요량보다 큰 블록이 배정되어 블록 내부에 남는 미사용 공간이다.

예시) 페이지 크기 4KB, 프로세스가 9KB 요청
  필요 페이지 수 = ceil(9KB / 4KB) = 3 페이지 = 12KB 할당
  내부 단편화 = 12KB - 9KB = 3KB (마지막 페이지 내부 낭비)

내부 단편화 평균≈PageSize2(프로세스당)\text{내부 단편화 평균} \approx \frac{\text{PageSize}}{2} \quad (\text{프로세스당})내부 단편화 평균≈2PageSize​(프로세스당)

항목내용
발생 환경페이징, 고정 분할 할당
원인블록 크기와 요청량 불일치
영향블록 내부 자투리 공간 낭비

3. 외부 단편화 (External Fragmentation)​

가변 크기 할당·해제를 반복하면 전체 여유 메모리는 충분하지만, 연속된 큰 블록이 없어 할당이 실패하는 현상이다.

항목내용
발생 환경세그먼테이션, 가변 분할 할당
원인할당/해제 반복으로 여유 공간 분산
영향총량 충분해도 연속 블록 확보 실패

4. 내부 vs 외부 단편화 비교​

비교 항목내부 단편화외부 단편화
발생 위치할당 블록 내부할당 블록 사이
발생 방식고정 분할가변 분할
대표 기법페이징세그먼테이션
해결 방안페이지 크기 최적화, 슬랩압축, 페이징, 버디

IV. 가상메모리 단편화 최소화 방안 (다)​

1. 방안 분류​

2. 압축 (Compaction)​

흩어진 사용 중 블록들을 메모리 한쪽으로 이동시켜 여유 공간을 하나의 큰 연속 블록으로 통합하는 기법이다. 외부 단편화를 근본적으로 제거한다.

항목내용
대상외부 단편화
장점큰 연속 공간 확보
단점블록 이동 비용 큼, 실행 중단 발생

3. 페이징 (Paging)​

물리 메모리를 고정 프레임으로 분할하여 비연속 할당을 가능하게 함으로써 외부 단편화 자체를 제거한다. 단, 내부 단편화는 일부 잔존한다.

항목내용
대상외부 단편화 제거
장점비연속 할당, 압축 불필요
단점내부 단편화 잔존, 페이지 테이블 오버헤드

4. 버디 시스템 (Buddy System)​

메모리를 2의 거듭제곱 크기 블록으로 관리하여, 요청 시 적절한 크기까지 절반씩 분할(split)하고, 해제 시 인접한 짝(buddy) 블록과 빠르게 병합(coalesce)하는 기법이다.

버디 주소 계산: 크기 2^k 블록의 buddy 주소
  buddy(addr) = addr XOR 2^k
  → 해제 시 buddy가 비어있으면 즉시 병합하여 큰 블록 복원
항목내용
대상외부 단편화 완화, 빠른 병합
장점빠른 분할·병합, 단편화 관리 용이
단점2의 거듭제곱 강제로 내부 단편화 발생

5. 슬랩 할당 (Slab Allocator)​

동일 크기·동일 타입의 커널 객체를 위한 전용 캐시(슬랩)를 미리 구성하여, 객체 생성·소멸 시 초기화 비용과 단편화를 최소화하는 기법이다. 리눅스 커널 메모리 할당에 사용된다.

항목내용
대상내부 단편화 최소화, 할당 속도
장점객체 재사용, 캐시 지역성, 초기화 절감
단점객체 종류별 캐시 관리 복잡

6. 방안 종합 비교​

기법주 대상 단편화핵심 원리주요 적용
압축외부블록 이동·통합가변 분할 메모리
페이징외부고정 프레임 비연속 할당가상메모리 일반
버디 시스템외부2의 거듭제곱 분할·병합커널 물리 페이지
슬랩내부동일 객체 전용 캐시커널 객체 할당

결론​

가상메모리는 페이징·세그먼테이션·혼합 기법으로 주소 공간을 분할하고, 요구 페이징과 페이지 교체 알고리즘으로 제한된 물리 메모리를 효율적으로 운용하며, 페이지 테이블과 TLB로 주소 변환 성능을 보장한다. 단편화는 고정 분할의 내부 단편화와 가변 분할의 외부 단편화로 구분되며, 압축·페이징·버디 시스템·슬랩 할당 등으로 최소화한다. 정보관리기술사 관점에서는 시스템의 워크로드 특성(객체 크기 분포, 참조 지역성, 메모리 압박 수준)을 정량 분석하여 페이지 크기·교체 정책·할당자를 통합 설계하고, EAT와 폴트율을 측정 지표로 삼아 메모리 계층 전체의 성능과 비용을 균형 있게 최적화하는 역량이 요구된다.
