문제 6) 네트워크 서브네팅(Subnetting)과 VLSM

답)

I. 개요​

IPv4 주소의 고갈과 라우팅 테이블 비대화를 해결하기 위해 클래스 기반 주소 체계는 CIDR(Classless Inter-Domain Routing)로 전환되었다. 서브네팅(Subnetting)은 하나의 네트워크를 여러 작은 네트워크로 분할하고, 슈퍼네팅(Supernetting)은 여러 네트워크를 하나로 통합한다. VLSM(Variable Length Subnet Mask)은 서브넷마다 다른 길이의 마스크를 적용하여 IP 주소 낭비를 최소화하는 기법이다.

구분서브네팅슈퍼네팅
방향큰 망 → 작은 망 (분할)작은 망 → 큰 망 (통합)
마스크길어짐 (호스트 비트 감소)짧아짐 (호스트 비트 증가)
목적망 세분화·격리라우팅 테이블 축소

II. 슈퍼네팅과 서브네팅 개념 (가)​

1. CIDR (Classless Inter-Domain Routing)​

CIDR은 클래스(A/B/C) 경계에 구애받지 않고 네트워크 접두사 길이(Prefix Length)를 임의로 지정하는 주소 체계로, 192.168.0.0/22처럼 IP/Prefix 표기를 사용한다.

항목설명
표기법A.B.C.D/n (n = 네트워크 비트 수)
서브넷 마스크상위 n비트가 1, 나머지 호스트 비트가 0
호스트 수2(32−n)−22^{(32-n)} - 22(32−n)−2 (네트워크·브로드캐스트 제외)
장점클래스 낭비 제거, 경로 집약 가능

2. 서브네팅 (Subnetting)​

서브네팅은 호스트 비트의 일부를 네트워크 비트로 차용(borrow)하여 하나의 네트워크를 다수의 서브넷으로 분할하는 기법이다.

효과설명
브로드캐스트 도메인 축소트래픽·충돌 감소
보안·격리부서별 망 분리
주소 관리계층적 IP 할당

3. 슈퍼네팅 (Supernetting)​

슈퍼네팅은 인접한 여러 네트워크를 짧은 마스크로 묶어 하나의 경로(Route)로 광고함으로써 라우팅 테이블을 축소하는 기법으로, 경로 집약(Route Aggregation)이라고도 한다.

슈퍼네팅 예시: 4개 /24 네트워크 통합
  192.168.0.0/24 ~ 192.168.3.0/24
  공통 상위 비트 = 22비트 동일
  → 192.168.0.0/22 단일 경로로 집약
  → 라우팅 테이블 항목 4개 → 1개

4. 서브네팅 vs 슈퍼네팅 비교​

비교 항목서브네팅슈퍼네팅
비트 이동호스트 → 네트워크네트워크 → 호스트
Prefix 변화증가 (/24 → /26)감소 (/24 → /22)
네트워크 수증가감소
적용 계층조직 내부 망 설계백본·ISP 라우팅
주요 이점격리·관리·보안라우팅 테이블 최적화

III. 192.168.0.0/22 VLSM 분할 (나)​

1. VLSM 개념과 요구사항 분석​

VLSM은 동일 네트워크 내에서 서브넷별 호스트 수요에 맞춰 서로 다른 길이의 마스크를 적용하여 주소 낭비를 최소화하는 기법이다. 핵심 원칙은 호스트 수요가 큰 서브넷부터 순차 할당하는 것이다.

팀요구 호스트필요 호스트 비트필요 주소 수선정 Prefix
개발팀50029=512≥500+22^9=512 \geq 500+229=512≥500+2512/23
영업팀25028=256≥250+22^8=256 \geq 250+228=256≥250+2256/24
보안팀12527=128≥125+22^7=128 \geq 125+227=128≥125+2128/25
인사팀12527=128≥125+22^7=128 \geq 125+227=128≥125+2128/25

2. 기준 네트워크 검증​

192.168.0.0/22
  네트워크 비트 = 22, 호스트 비트 = 10
  주소 수 = 2^10 = 1024개
  범위 = 192.168.0.0 ~ 192.168.3.255
  (셋째 옥텟 22-16=6비트 → 마스크 255.255.252.0)

총 필요 주소 = 512 + 256 + 128 + 128 = 1024개  → /22 대역에 정확히 적합

3. 서브넷별 계산 과정​

(1) 개발팀 (500명 → /23)​

필요 호스트 500명 ≤ 2^9 - 2 = 510  → 호스트 비트 9, Prefix /23
네트워크 주소 : 192.168.0.0/23
서브넷 마스크 : 255.255.254.0  (셋째 옥텟 11111110)
블록 크기    : 512 (192.168.0.0 ~ 192.168.1.255)
사용 가능 호스트: 192.168.0.1 ~ 192.168.1.254  (510개)
브로드캐스트  : 192.168.1.255
다음 시작 주소 : 192.168.2.0

(2) 영업팀 (250명 → /24)​

필요 호스트 250명 ≤ 2^8 - 2 = 254  → 호스트 비트 8, Prefix /24
네트워크 주소 : 192.168.2.0/24
서브넷 마스크 : 255.255.255.0
블록 크기    : 256 (192.168.2.0 ~ 192.168.2.255)
사용 가능 호스트: 192.168.2.1 ~ 192.168.2.254  (254개)
브로드캐스트  : 192.168.2.255
다음 시작 주소 : 192.168.3.0

(3) 보안팀 (125명 → /25)​

필요 호스트 125명 ≤ 2^7 - 2 = 126  → 호스트 비트 7, Prefix /25
네트워크 주소 : 192.168.3.0/25
서브넷 마스크 : 255.255.255.128  (넷째 옥텟 10000000)
블록 크기    : 128 (192.168.3.0 ~ 192.168.3.127)
사용 가능 호스트: 192.168.3.1 ~ 192.168.3.126  (126개)
브로드캐스트  : 192.168.3.127
다음 시작 주소 : 192.168.3.128

(4) 인사팀 (125명 → /25)​

필요 호스트 125명 ≤ 2^7 - 2 = 126  → 호스트 비트 7, Prefix /25
네트워크 주소 : 192.168.3.128/25
서브넷 마스크 : 255.255.255.128
블록 크기    : 128 (192.168.3.128 ~ 192.168.3.255)
사용 가능 호스트: 192.168.3.129 ~ 192.168.3.254  (126개)
브로드캐스트  : 192.168.3.255
다음 시작 주소 : 192.168.4.0 (대역 종료)

5. 주소 공간 배치도​

주소 사용 검증:
  개발 512 + 영업 256 + 보안 128 + 인사 128 = 1024 IP
  192.168.0.0/22 총 1024 IP  → 100% 활용, 주소 낭비 없음

결론​

서브네팅과 슈퍼네팅은 CIDR 체계 하에서 각각 네트워크 분할과 경로 집약을 담당하며, VLSM은 서브넷별 호스트 수요에 맞는 가변 마스크를 적용해 주소 낭비를 최소화한다. 본 문제에서 192.168.0.0/22 대역은 수요가 큰 개발팀(/23)부터 순차 할당하여 영업팀(/24), 보안팀·인사팀(/25)으로 분할되며, 총 1024개 IP를 100% 활용하여 낭비 없이 배분된다. 정보관리기술사 관점에서는 향후 확장성을 고려한 여유 주소 확보, 계층적 주소 설계를 통한 경로 집약 가능성, 그리고 IPv4 고갈에 대비한 IPv6 전환 로드맵을 함께 수립하는 통합 IP 주소 관리 전략이 요구된다.
