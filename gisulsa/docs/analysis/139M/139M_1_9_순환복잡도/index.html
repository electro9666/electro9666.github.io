문제 9) 맥케이브 순환복잡도(McCabe's Cyclomatic Complexity)

답)

I. 개요​

1. 정의​

맥케이브 순환복잡도(Cyclomatic Complexity)는 1976년 토마스 맥케이브(Thomas J. McCabe)가 제안한 소프트웨어 메트릭으로, 프로그램의 제어 흐름 그래프(CFG)를 기반으로 코드의 논리적 복잡도를 정량적으로 측정하는 지표이다.

순환복잡도는 프로그램에 존재하는 선형 독립 경로(Linearly Independent Path)의 수를 의미하며, 이는 코드를 완전히 테스트하기 위해 필요한 최소 테스트 케이스 수와 직결된다.

2. 의의​

의의내용
복잡도 정량화코드의 논리 복잡성을 객관적 수치로 표현
테스트 기준기본 경로 테스트(Basis Path Testing)의 케이스 수 산정
유지보수성 예측복잡도 높을수록 결함 발생·유지보수 비용 증가
품질 게이트코드 리뷰·리팩토링 우선순위 판단 기준

II. 제어 흐름 그래프 (CFG: Control Flow Graph)​

1. 개념​

제어 흐름 그래프는 프로그램의 실행 흐름을 노드(Node)와 엣지(Edge)로 표현한 방향 그래프이다.

구성 요소설명
노드(Node, N)순차적으로 실행되는 명령문(블록)
엣지(Edge, E)제어 흐름의 방향(노드 간 연결)
판단 노드(Predicate Node)조건 분기(if, while 등)를 가진 노드
영역(Region, R)그래프가 평면에서 분할하는 폐쇄 영역(외부 영역 포함)

2. 기본 제어 구조의 CFG 표현​

III. 계산 공식​

1. 세 가지 계산 방법​

순환복잡도 V(G)는 다음 세 가지 방법으로 계산하며, 모두 동일한 값을 산출한다.

방법 1: 엣지-노드 공식​

V(G)=E−N+2PV(G) = E - N + 2PV(G)=E−N+2P

  • E: 엣지(Edge) 수
  • N: 노드(Node) 수
  • P: 연결 요소(Connected Component) 수 (단일 프로그램은 보통 1)

방법 2: 영역 수 기반​

V(G)=R(폐쇄 영역 수 + 외부 영역 1)V(G) = R \quad (\text{폐쇄 영역 수 + 외부 영역 1})V(G)=R(폐쇄 영역 수 + 외부 영역 1)

방법 3: 판단 노드 기반​

V(G)=Ppredicate+1V(G) = P_{\text{predicate}} + 1V(G)=Ppredicate​+1

  • P_predicate: 판단(조건 분기) 노드의 수

2. 세 방법의 관계​

IV. 계산 예제​

1. 예제 코드​

int classify(int score) {
    int grade;
    if (score >= 90) {        // 판단 1
        grade = 1;
    } else {
        if (score >= 70) {    // 판단 2
            grade = 2;
        } else {
            grade = 3;
        }
    }
    return grade;
}

2. 제어 흐름 그래프​

3. 계산 검증 (3가지 방법 일치 확인)​

  • 노드 수 N = 7 (N1~N7)
  • 엣지 수 E = 8 (N1→N2, N2→N3, N2→N4, N4→N5, N4→N6, N3→N7, N5→N7, N6→N7)
  • 연결 요소 P = 1
  • 판단 노드 = 2 (N2, N4)
방법 1) V(G) = E - N + 2P = 8 - 7 + 2(1) = 3
방법 2) V(G) = 영역 수 R = 2(내부 폐쇄영역) + 1(외부) = 3
방법 3) V(G) = 판단노드 + 1 = 2 + 1 = 3

→ 세 방법 모두 V(G) = 3 (일치)

해석: 이 함수를 완전히 테스트하려면 최소 3개의 독립 경로(테스트 케이스)가 필요하다.

  • 경로1: score ≥ 90 (grade=1)
  • 경로2: 70 ≤ score < 90 (grade=2)
  • 경로3: score < 70 (grade=3)

V. 복잡도에 따른 위험도 및 권고 기준​

1. 맥케이브 권고 기준​

V(G) 범위복잡도 수준위험도권고 사항
1 ~ 10단순(Simple)낮음안정적, 유지보수 용이
11 ~ 20보통(Moderate)중간주의 필요, 리뷰 권장
21 ~ 50복잡(Complex)높음리팩토링 검토 필요
50 초과매우 복잡매우 높음테스트 불가 수준, 즉시 분할

일반적으로 모듈당 V(G) ≤ 10을 유지하도록 권장하며, 초과 시 함수 분할(Extract Method)을 통해 복잡도를 낮춘다.

VI. 활용​

1. 테스트 케이스 수 산정​

순환복잡도는 기본 경로 테스트(Basis Path Testing) 에서 보장해야 할 최소 독립 경로 수를 정의한다.

최소 테스트 케이스 수=V(G)\text{최소 테스트 케이스 수} = V(G)최소 테스트 케이스 수=V(G)

2. 유지보수성 및 품질 관리 활용​

활용 분야설명
테스트 커버리지기본 경로 테스트의 케이스 수 산정 근거
결함 예측복잡도 높은 모듈일수록 결함 밀도 높음 → 집중 검토
리팩토링 우선순위V(G) 임계치 초과 모듈 우선 분할 대상 선정
코드 리뷰 기준CI 파이프라인 품질 게이트로 임계치 설정
유지보수 비용 예측복잡도와 유지보수 공수의 양의 상관관계 활용

3. 한계 및 보완​

한계보완 방안
데이터 흐름 복잡도 미반영데이터 복잡도 메트릭 병행
단순 case문 과대평가 가능인지적 복잡도(Cognitive Complexity) 병행
코드 가독성 미측정정성적 코드 리뷰와 결합

VII. 결론​

맥케이브 순환복잡도는 제어 흐름 그래프 기반으로 코드의 논리 복잡도를 정량화하는 대표적 소프트웨어 메트릭으로, V(G)=E-N+2P(또는 영역 수, 판단노드+1)로 산출되며 선형 독립 경로 수이자 기본 경로 테스트의 최소 테스트 케이스 수를 의미한다. 모듈당 V(G)≤10 유지를 권장하며, 초과 시 함수 분할로 복잡도를 관리한다.

정보관리기술사 관점에서는 순환복잡도를 CI/CD 품질 게이트의 정량 지표로 통합하여 복잡도 임계치 초과 모듈을 자동 식별·리팩토링하고, 결함 예측 및 테스트 케이스 산정의 객관적 근거로 활용함으로써 소프트웨어 유지보수성과 신뢰성을 체계적으로 관리하는 역량이 요구된다.
