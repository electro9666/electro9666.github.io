문제 3) Advanced RAG와 Modular RAG 비교

답)

I. 개요​

1. 정의​

RAG(Retrieval-Augmented Generation, 검색증강생성)는 외부 지식베이스에서 관련 정보를 검색(Retrieval)하여 LLM의 생성(Generation)에 결합함으로써, 환각(Hallucination)을 줄이고 최신성·근거성을 확보하는 기법이다.

패러다임정의
Advanced RAGNaive RAG의 한계를 보완하기 위해 검색 전(pre-retrieval)·검색 후(post-retrieval) 최적화를 추가한 고도화 파이프라인
Modular RAGRAG를 독립적 모듈과 오케스트레이션 가능한 패턴으로 재구성하여 유연한 조합·교체·라우팅이 가능한 아키텍처

2. RAG의 진화​

세대특징한계 극복
Naive RAGIndexing → Retrieve → Generate 단순 흐름(기준점)
Advanced RAG쿼리 재작성, 리랭킹, 컨텍스트 압축 추가검색 정확도·노이즈 문제
Modular RAG모듈 단위 분해, 라우팅·반복·적응적 검색경직성·복잡 질의 대응

II. Naive RAG (기준 구조와 한계)​

1. 기본 구조​

2. Naive RAG의 한계​

한계내용
낮은 검색 정밀도청킹 부적절, 의미 불일치로 무관 문서 검색
낮은 재현율관련 문서 누락
컨텍스트 노이즈불필요 정보가 프롬프트 오염 → 답변 품질 저하
고정 파이프라인질의 복잡도에 무관하게 동일 처리

III. Advanced RAG 구조와 특징​

1. 전체 구조 (pre/post-retrieval 최적화)​

2. Pre-Retrieval 최적화​

기법설명
쿼리 재작성(Query Rewriting)모호한 질의를 검색 친화적으로 변환
쿼리 확장(Query Expansion)동의어·관련어 추가로 재현율 향상
HyDE가설 답변 생성 후 그 임베딩으로 검색
청킹 최적화의미 단위 청킹, Sliding Window, 메타데이터 부착
하이브리드 검색키워드(BM25) + 벡터 검색 결합

3. Post-Retrieval 최적화​

기법설명
리랭킹(Re-ranking)Cross-Encoder로 검색 결과 정밀 재정렬
컨텍스트 압축관련 문장만 추출, 토큰 절감
중복 제거유사 청크 통합
Lost-in-the-Middle 대응중요 문서를 프롬프트 앞·뒤 재배치

4. 특징 요약​

  • Naive RAG의 선형 파이프라인은 유지하되, 검색 전후 단계를 보강
  • 검색 품질(정밀도·재현율)과 컨텍스트 품질을 집중 개선
  • 비교적 구현 단순, 기존 RAG에 점진 적용 가능

IV. Modular RAG 구조와 특징​

1. 핵심 개념​

Modular RAG는 RAG를 독립적 기능 모듈(Module) 과 모듈 결합 패턴(Pattern), 그리고 이를 제어하는 오케스트레이션(Orchestration) 계층으로 분해한다.

2. 주요 모듈​

모듈역할
Search다양한 데이터소스(DB, 웹, KG) 검색
Retrieve벡터·하이브리드 검색 수행
Rerank결과 재정렬
Memory대화·이전 검색 결과 저장·재활용
Routing질의 유형별 적절 경로 선택
Fusion다중 검색 결과 융합(RAG-Fusion)
Predict노이즈 제거·요약 후 생성

3. 오케스트레이션 패턴​

패턴설명예시
Iterative검색→생성→재검색 반복다단계 추론
Recursive복잡 질의를 하위 질의로 분해멀티홉 QA
Adaptive검색 필요 여부를 모델이 판단Self-RAG, FLARE
Branching다중 경로 병렬 후 융합RAG-Fusion

4. 특징 요약​

  • 모듈의 추가·교체·재배치 자유(Plug-and-Play) → 높은 유연성·확장성
  • 조건부·반복·적응적 흐름 → 복잡·다단계 질의 대응
  • Advanced RAG의 최적화 기법을 모듈로 포섭(상위호환)
  • 단, 아키텍처 복잡도·운영 비용·지연(latency) 증가

V. Naive / Advanced / Modular RAG 비교​

1. 종합 비교표​

비교 항목Naive RAGAdvanced RAGModular RAG
파이프라인고정 선형선형 + pre/post 최적화모듈형 + 오케스트레이션
검색 흐름1회 검색1회 + 보강반복/조건/적응적
유연성낮음중간높음
복잡 질의 대응어려움제한적우수(멀티홉/추론)
구현 난이도낮음중간높음
지연/비용낮음중간높음
확장성낮음중간높음
대표 기법청킹+검색+생성쿼리재작성, 리랭킹, 압축Self-RAG, RAG-Fusion, 라우팅

2. 포함 관계​

Modular RAG는 Advanced RAG를 특수한 케이스(고정 패턴) 로 포함하는 상위 일반화 구조이다.

VI. 활용 및 적용 고려사항​

1. 적용 시나리오별 선택​

상황권장 패러다임이유
단순 FAQ·사내 문서 검색Advanced RAG구현 단순, 충분한 품질
멀티홉·추론형 질의Modular RAG반복·재귀 검색 필요
다중 데이터소스 통합Modular RAG라우팅·융합 모듈 활용
빠른 응답 우선(저지연)Advanced RAG오케스트레이션 오버헤드 회피
대화형 에이전트Modular RAGMemory·Adaptive 모듈

2. 도입 고려사항​

고려사항내용
평가 체계RAGAS 등으로 신뢰성·정확성·관련성 측정
비용·지연반복 검색·리랭킹의 토큰·호출 비용 관리
보안·거버넌스검색 소스 접근통제, PII 필터링
점진 도입Naive→Advanced→Modular 단계적 진화

VII. 전망 및 결론​

RAG는 Naive에서 Advanced로, 다시 Modular로 진화하며 단순 검색결합을 넘어 추론·라우팅·반복·적응적 제어가 가능한 에이전트형 아키텍처(Agentic RAG) 로 발전하고 있다. Advanced RAG는 검색 전후 최적화로 품질을 높이고, Modular RAG는 모듈화·오케스트레이션으로 복잡 질의와 확장성을 확보한다. 정보관리기술사는 업무 복잡도·지연·비용의 트레이드오프를 평가하여 적정 RAG 패러다임을 선택하고, RAGAS 기반 평가와 보안 거버넌스를 갖춘 신뢰 가능한 생성형 AI 지식 서비스를 설계해야 한다.
