문제 7) 분산 데이터베이스의 투명성(Transparency)

답)

I. 개요​

1. 정의​

분산 데이터베이스(Distributed Database)는 물리적으로 여러 사이트(노드)에 분산 저장되어 있으나 사용자에게는 하나의 논리적 통합 데이터베이스로 보이는 시스템이다.

투명성(Transparency)이란 데이터가 여러 위치에 분산·분할·복제되어 있다는 물리적 복잡성을 사용자나 응용 프로그램에게 감추어, 마치 단일 중앙 집중식 데이터베이스를 사용하는 것처럼 보이게 하는 성질이다.

투명성은 분산 DBMS의 핵심 설계 목표로서, 사용자가 데이터의 물리적 분산 세부사항을 알지 못해도 일관되게 접근할 수 있도록 보장한다.

2. 투명성의 의의​

의의내용
사용 편의성분산 구조를 몰라도 단일 DB처럼 질의 작성 가능
위치 독립성데이터 이전·재배치 시에도 응용 수정 불필요
유지보수성물리적 구조 변경이 논리적 응용과 분리
신뢰성복제·장애 처리를 시스템이 자동 수행

II. 투명성의 전체 유형 체계​

투명성 유형감추는 대상핵심 질문
위치 투명성데이터의 물리적 위치"데이터가 어느 사이트에 있는가?"
분할 투명성데이터의 단편화 방식"데이터가 어떻게 쪼개져 있는가?"
복제 투명성데이터의 복제본 존재"복사본이 몇 개 있는가?"
병행 투명성동시 트랜잭션 간섭"다른 사용자가 동시 접근하는가?"
장애 투명성사이트/통신 장애"어느 노드가 고장났는가?"
접근 투명성지역 DBMS 차이"각 사이트의 DBMS가 무엇인가?"

III. 각 투명성 유형 상세​

1. 위치 투명성 (Location Transparency)​

개념​

데이터가 물리적으로 어느 사이트에 저장되어 있는지 알 필요 없이 논리적 이름만으로 접근할 수 있는 성질이다. 데이터의 물리적 위치가 변경되어도 응용 프로그램은 수정이 필요 없다.

예시​

-- 위치 투명성 보장 (논리명만 사용)
SELECT * FROM EMPLOYEE WHERE dept = '개발팀';

-- 위치 투명성 미보장 (물리 위치 명시 필요)
SELECT * FROM EMPLOYEE@seoul_site WHERE dept = '개발팀';

2. 분할(단편화) 투명성 (Fragmentation Transparency)​

개념​

하나의 논리적 릴레이션이 여러 단편(Fragment)으로 분할되어 분산 저장되어 있어도, 사용자는 분할되지 않은 단일 테이블로 인식하는 성질이다.

단편화 유형​

유형설명예시
수평 분할(Horizontal)행(Row) 기준 분할지역별 고객 데이터 분할
수직 분할(Vertical)열(Column) 기준 분할개인정보/급여정보 분리 저장
혼합 분할(Hybrid)수평+수직 결합지역별·속성별 분할

예시​

사용자가 SELECT * FROM EMPLOYEE를 실행하면, DBMS가 자동으로 두 단편을 UNION하여 통합 결과를 반환한다.

3. 복제 투명성 (Replication Transparency)​

개념​

동일 데이터의 복제본(Replica)이 여러 사이트에 존재해도 사용자는 복제본의 수나 위치를 알 필요 없이 단일 데이터로 취급하는 성질이다. 갱신 시 모든 복제본의 일관성 유지는 시스템이 자동 처리한다.

예시​

장점단점
가용성·읽기 성능 향상갱신 시 일관성 유지 비용 증가
지역 접근으로 응답 단축저장 공간 중복

4. 병행(동시성) 투명성 (Concurrency Transparency)​

개념​

여러 트랜잭션이 동시에 분산 데이터에 접근해도 상호 간섭 없이 직렬 실행한 것과 동일한 결과(직렬성, Serializability)를 보장하는 성질이다.

동시성 제어 기법​

기법설명
분산 잠금(Distributed Locking)사이트 간 잠금 조율, 전역 교착상태 탐지 필요
타임스탬프 순서트랜잭션 타임스탬프 기반 직렬화
2단계 잠금(2PL)확장·축소 단계로 직렬성 보장

5. 장애 투명성 (Failure Transparency)​

개념​

특정 사이트나 통신 링크에 장애가 발생해도 트랜잭션의 원자성(Atomicity)과 일관성이 보장되도록 하는 성질이다. 장애 발생 시에도 분산 트랜잭션은 전체 커밋 또는 전체 롤백된다.

2단계 커밋 (2-Phase Commit)​

전원이 Ready 응답하면 Commit, 하나라도 실패하면 전체 Rollback하여 원자성을 보장한다.

6. 접근/지역사상 투명성 (Local Mapping Transparency)​

개념​

각 사이트가 서로 다른 종류의 지역 DBMS(이기종, Heterogeneous)나 데이터 모델을 사용해도, 사용자는 통일된 인터페이스로 접근할 수 있는 성질이다. 전역 명칭이 각 지역 DBMS의 물리적 표현으로 자동 사상(Mapping)된다.

IV. 투명성 수준 비교​

1. 투명성 수준별 사용자 인식​

수준사용자가 명시해야 하는 정보투명성 정도
분할 투명성없음 (논리명만)가장 높음
위치 투명성단편 식별높음
지역 사상 투명성단편의 물리 위치중간
투명성 없음위치+DBMS+물리 구조가장 낮음

2. 투명성과 분산 DBMS 목표의 관계​

V. 분산 DBMS에서의 의의 및 고려사항​

1. 투명성 제공의 트레이드오프​

투명성이점비용/오버헤드
위치/분할응용 독립성글로벌 디렉터리 관리
복제가용성·성능일관성 동기화 비용
병행데이터 정합성분산 잠금·교착 탐지
장애신뢰성2PC 통신 오버헤드

2. CAP 정리와의 관계​

분산 DB는 일관성(Consistency), 가용성(Availability), 분단 허용성(Partition Tolerance) 중 동시에 셋을 만족할 수 없다(CAP 정리). 복제·장애 투명성을 강하게 제공할수록 일관성 유지 비용이 증가하므로, 시스템 요구사항에 따라 적절한 균형이 필요하다.

VI. 결론​

분산 데이터베이스의 투명성은 물리적으로 분산·분할·복제된 데이터를 사용자에게 단일 논리 DB로 보이게 하는 핵심 추상화 메커니즘이며, 위치·분할·복제·병행·장애·접근 투명성의 6가지 유형이 상호 보완적으로 작동하여 사용 편의성과 신뢰성을 동시에 달성한다.

정보관리기술사 관점에서는 투명성 제공 수준이 높을수록 사용 편의성은 향상되나 글로벌 디렉터리 관리·복제 동기화·2단계 커밋 등 시스템 오버헤드가 증가하므로, CAP 정리와 일관성 모델(강한 일관성 vs 최종 일관성)을 고려하여 업무 요구사항에 맞는 투명성 수준을 설계하는 균형 감각이 요구된다.
