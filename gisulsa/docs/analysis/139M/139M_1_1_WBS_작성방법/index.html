문제 1) WBS(Work Breakdown Structure) 작성방법

답)

I. 개요​

1. 정의​

WBS(Work Breakdown Structure, 작업분해구조)는 프로젝트의 전체 산출물(Deliverable)과 작업 범위를 관리 가능한 단위로 계층적으로 분해하여, 프로젝트가 수행해야 할 작업의 총체를 빠짐없이 시각화한 산출물 지향(Deliverable-Oriented) 분해 구조이다.

PMBOK에서 WBS는 범위관리(Scope Management)의 핵심 산출물로, 프로젝트 범위 기술서(Scope Statement)를 입력으로 받아 작업을 분해하며, 이후 일정·원가·자원·리스크 관리의 공통 기준선(Baseline)이 된다.

2. WBS의 위상 (범위관리 흐름)​

3. WBS의 특징​

특징설명
산출물 지향활동(Activity)이 아닌 인도물(Deliverable) 중심으로 분해
계층적 구조상위에서 하위로 점진적 상세화(Progressive Elaboration)
100% 규칙하위 요소의 합 = 상위 요소 전체 범위
상호배타성작업 간 중복 없이 분할(MECE)
기준선 역할일정·원가·자원·품질 통제의 공통 기준

II. WBS 작성 원칙​

1. 핵심 작성 원칙​

2. 원칙별 상세 설명​

원칙내용위반 시 문제점
100% 규칙하위 레벨 작업의 합은 상위 레벨 작업의 100%를 표현. 누락·초과 모두 금지범위 누락(Scope Gap) 또는 범위 확대(Scope Creep) 발생
상호배타성(MECE)동일 레벨 작업 간 중복 금지이중 산정으로 원가·일정 왜곡
산출물 중심 분해"무엇을 만드는가"로 분해, "어떻게"는 후순위활동 위주 분해 시 누락 위험
8/80 규칙Work Package는 8시간 이상 80시간 이하로 분해너무 크면 통제 불가, 너무 작으면 관리 비용 증가
적정 분해 수준산정·통제·책임 부여가 가능한 수준까지만 분해과도 분해 시 관리 오버헤드

100% 규칙 핵심: WBS의 가장 중요한 원칙으로, 어떤 레벨에서든 하위 구성요소들의 합이 정확히 그 부모 요소의 전체 작업 범위와 같아야 한다.

3. 100% 규칙의 수식적 표현​

특정 부모 노드 PPP의 작업 범위를 하위 자식 노드 CiC_iCi​로 분해할 때:

Scope(P)=∑i=1nScope(Ci),Scope(Ci)∩Scope(Cj)=∅ (i≠j)\text{Scope}(P) = \sum_{i=1}^{n} \text{Scope}(C_i), \quad \text{Scope}(C_i) \cap \text{Scope}(C_j) = \varnothing \ (i \ne j)Scope(P)=∑i=1n​Scope(Ci​),Scope(Ci​)∩Scope(Cj​)=∅ (i=j)

즉 합집합은 전체(100%), 교집합은 공집합(중복 0%) 이어야 한다.

III. WBS 작성 방법 및 절차​

1. 작성 절차​

2. 단계별 상세​

단계활동산출물
1. 범위 분석프로젝트 범위 기술서, 요구사항 검토범위 이해
2. 주요 인도물 식별최종 산출물과 주요 단계 도출Level 1~2 구조
3. 단계적 분해인도물을 하위 구성요소로 점진 상세화중간 레벨
4. Work Package 도출산정·통제 가능 최소 단위까지 분해최하위 레벨
5. 코드 부여계층적 식별 코드(Code of Account) 부여WBS 코드체계
6. Dictionary 작성각 요소 상세 정보 문서화WBS Dictionary
7. 검증/승인100% 규칙 검증, 이해관계자 승인범위 기준선

3. 분해 접근법 비교​

분해 방식설명적합 상황
인도물 기준최종 산출물 → 구성요소 분해산출물이 명확한 SI 프로젝트
단계(Phase) 기준생명주기 단계별 분해 (분석/설계/구현/테스트)폭포수형 개발
하위 프로젝트 기준대규모 프로그램을 서브프로젝트로 분할다지역·다팀 프로젝트
혼합형상위는 단계, 하위는 인도물 기준대부분 실무 프로젝트

WBS 코드작업명레벨유형

3. 표현 방식 비교​

표현 방식장점단점
트리(조직도형)구조 직관적, 발표·보고에 적합항목 많으면 가독성 저하
표(아웃라인형)항목 다수 관리 용이, 도구 연동 쉬움계층 시각성 낮음

V. Work Package와 WBS Dictionary​

1. Work Package (작업 패키지)​

  • WBS의 최하위 분해 요소로 더 이상 분해하지 않는 작업 단위
  • 일정 산정 시 Activity(활동)로 추가 분해되는 출발점
  • 통제계정(Control Account) 과 연계하여 EVM(획득가치관리) 측정 단위로 활용

2. WBS Dictionary (작업분해구조 사전)​

각 WBS 요소에 대한 상세 정보를 기술한 보조 문서로, WBS의 코드만으로는 알 수 없는 작업의 구체적 내용을 정의한다.

항목내용
WBS 코드 / 명칭식별자 및 작업명
작업 기술서수행 작업의 상세 설명
인수 기준산출물 완료 판정 기준(완료 정의, DoD)
책임자(OBS 연계)담당 조직·인력 (Responsible)
일정 정보마일스톤, 시작·종료일
원가 산정예산, 통제계정 코드
필요 자원인력, 장비, 자재
의존 관계선행·후행 작업

VI. WBS의 활용 (일정·원가·자원 산정의 기반)​

1. 통합관리 기반으로서의 WBS​

2. 영역별 활용 상세​

관리 영역WBS 활용 방식
일정 산정Work Package → Activity 분해 → 네트워크 다이어그램 → CPM/PERT로 기간 산정
원가 산정Work Package별 자원·비용 추정 → 상향식 합산(Bottom-up) → 원가 기준선
자원 산정작업별 필요 인력·기술·장비 식별 → 자원 평준화
리스크 식별WBS 요소별 위험 식별로 누락 방지 (RBS 연계)
진척 관리(EVM)통제계정 단위 PV/EV/AC 측정 → SPI/CPI 산출

3. EVM 연계 핵심 지표​

WBS 기반 통제계정에서 측정되는 성과지표:

SPI=EVPV,CPI=EVACSPI = \frac{EV}{PV}, \quad CPI = \frac{EV}{AC}SPI=PVEV​,CPI=ACEV​

  • EVEVEV: 획득가치(완료 작업의 예산가치), PVPVPV: 계획가치, ACACAC: 실제원가
  • SPI/CPI < 1 이면 일정 지연/원가 초과 → WBS 요소 단위로 원인 추적 가능

VII. 작성 시 고려사항 및 결론​

1. 작성 시 고려사항​

구분고려사항
분해 수준과도 분해(관리비용↑) vs 과소 분해(통제 불가) 균형
100% 규칙 검증누락·중복 없는지 레벨별 검증 필수
명명 규칙산출물 중심의 명사형 명칭 사용
변경 관리범위 변경 시 WBS·기준선 형상관리
도구 활용MS Project, Jira, WBS Tool 등 활용

2. 결론​

WBS는 프로젝트 범위를 빠짐없이 정의하고 일정·원가·자원·리스크 관리의 단일 기준선(Single Source of Truth) 을 제공하는 프로젝트 관리의 척추(Backbone)이다. 100% 규칙과 8/80 규칙을 준수한 적정 분해, WBS Dictionary를 통한 명확한 작업 정의, OBS·EVM과의 연계가 프로젝트 성공의 핵심이다. 정보관리기술사는 WBS를 단순 작업 목록이 아닌 범위·일정·원가의 통합관리 기반 구조로 인식하고, 프로젝트 초기에 이해관계자 합의를 통해 견고한 범위 기준선을 수립하도록 설계·관리해야 한다.
