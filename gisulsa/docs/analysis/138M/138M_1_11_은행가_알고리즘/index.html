문제 11) 은행가 알고리즘(Banker's Algorithm)

답)

I. 개요​

1. 교착상태(Deadlock) 개요​

**교착상태(Deadlock)**란 두 개 이상의 프로세스가 서로 상대방이 점유한 자원을 기다리며 무한히 대기하는 상태이다.

Coffman 조건 (4가지 필요충분조건):

조건설명은행가 알고리즘 대응
상호 배제 (Mutual Exclusion)자원은 한 번에 하나의 프로세스만 사용해결 불가 (자원 특성)
점유 대기 (Hold and Wait)자원을 가진 채 다른 자원 대기예방 가능
비선점 (No Preemption)자원을 강제로 빼앗을 수 없음예방 가능
순환 대기 (Circular Wait)프로세스들이 원형으로 대기회피로 방지

2. 교착상태 처리 전략​

3. 은행가 알고리즘 정의​

**은행가 알고리즘(Banker's Algorithm)**은 E.W. Dijkstra(1965)가 제안한 교착상태 회피(Avoidance) 알고리즘으로, 자원 요청 시 해당 요청을 허락해도 시스템이 **안전 상태(Safe State)**를 유지하는지 사전에 검사하여 교착상태를 예방한다.

은행가 비유: 은행이 모든 고객에게 대출을 동시에 해줄 수 없지만, 대출 순서를 잘 조정하면 모든 고객이 대출을 완료할 수 있듯이, OS도 자원 할당 순서를 조정하여 교착상태를 회피한다.

II. 자료구조​

1. 핵심 자료구조 (n개 프로세스, m개 자원 유형)​

2. 자료구조 관계식​

Need[i][j]=Max[i][j]−Allocation[i][j]\text{Need}[i][j] = \text{Max}[i][j] - \text{Allocation}[i][j]Need[i][j]=Max[i][j]−Allocation[i][j]

∑i=0n−1Allocation[i][j]+Available[j]=Total[j]\sum_{i=0}^{n-1} \text{Allocation}[i][j] + \text{Available}[j] = \text{Total}[j]∑i=0n−1​Allocation[i][j]+Available[j]=Total[j]

변수차원의미
Available1×m 벡터현재 가용 자원량
Maxn×m 행렬프로세스별 최대 자원 요구량
Allocationn×m 행렬프로세스별 현재 할당량
Needn×m 행렬프로세스별 추가 필요량 (= Max - Allocation)

III. 안전 상태와 불안전 상태​

1. 안전 상태(Safe State)​

정의: 시스템이 모든 프로세스를 교착상태 없이 종료시킬 수 있는 **안전 순서(Safe Sequence)**가 존재하는 상태

안전 순서 정의: ⟨P1,P2,…,Pn⟩\langle P_1, P_2, \ldots, P_n \rangle⟨P1​,P2​,…,Pn​⟩이 안전 순서이려면:

Need[Pi]≤Available+∑j<iAllocation[Pj]\text{Need}[P_i] \leq \text{Available} + \sum_{j<i} \text{Allocation}[P_j]Need[Pi​]≤Available+∑j<i​Allocation[Pj​]

즉, 각 프로세스 PiP_iPi​의 추가 자원 요구가 현재 가용 자원 + 이전 프로세스들이 반환한 자원의 합보다 작거나 같아야 한다.

2. 안전/불안전 상태 비교​

상태교착상태설명
안전 상태발생 안 함안전 순서가 항상 존재
불안전 상태발생 가능교착상태가 반드시 발생하는 것은 아님
교착상태발생 중불안전 상태의 부분 집합

안전 상태⊂불안전 상태⊂교착상태\text{안전 상태} \subset \text{불안전 상태} \subset \text{교착상태}안전 상태⊂불안전 상태⊂교착상태

IV. 알고리즘 동작 과정​

1. 안전성 알고리즘(Safety Algorithm)​

현재 상태가 안전한지 판단하는 알고리즘:

안전성 알고리즘:

1. Work = Available 복사
   Finish[i] = false (모든 프로세스 i에 대해)

2. 다음 조건을 만족하는 i를 찾는다:
   (a) Finish[i] = false
   (b) Need[i] ≤ Work

   조건을 만족하는 i가 없으면 Step 4로

3. Work = Work + Allocation[i]
   Finish[i] = true
   Step 2로 돌아감

4. 모든 i에 대해 Finish[i] = true이면 → 안전 상태
   그렇지 않으면 → 불안전 상태
def safety_algorithm(available, allocation, need, n, m):
    work = available.copy()
    finish = [False] * n
    safe_sequence = []
    
    count = 0
    while count < n:
        found = False
        for i in range(n):
            if not finish[i]:
                # Need[i] <= Work 검사
                if all(need[i][j] <= work[j] for j in range(m)):
                    # 프로세스 i가 완료 가능
                    for j in range(m):
                        work[j] += allocation[i][j]
                    finish[i] = True
                    safe_sequence.append(i)
                    count += 1
                    found = True
        
        if not found:
            break  # 안전 순서 없음
    
    is_safe = all(finish)
    return is_safe, safe_sequence

2. 자원 요청 알고리즘(Resource-Request Algorithm)​

프로세스 PiP_iPi​가 자원 Requesti\text{Request}_iRequesti​를 요청할 때:

자원 요청 알고리즘 (프로세스 Pi가 Request_i 요청):

1. Request_i ≤ Need[i] 인지 확인
   아니면 → 오류 (최대 요구량 초과)

2. Request_i ≤ Available 인지 확인
   아니면 → Pi 대기 (자원 부족)

3. 자원을 임시 할당 (가상 할당):
   Available    = Available - Request_i
   Allocation[i] = Allocation[i] + Request_i
   Need[i]       = Need[i] - Request_i

4. 안전성 알고리즘 실행:
   → 안전 상태: 실제로 자원 할당 확정
   → 불안전 상태: 임시 할당 취소, Pi 대기

V. 구체적 예제​

1. 초기 상태 설정​

환경: 프로세스 5개 (P0~P4), 자원 3종류 (A, B, C) 전체 자원: A=10, B=5, C=7

초기 상태 행렬:

프로세스Allocation (A,B,C)Max (A,B,C)Need (A,B,C)
P00, 1, 07, 5, 37, 4, 3
P12, 0, 03, 2, 21, 2, 2
P23, 0, 29, 0, 26, 0, 0
P32, 1, 12, 2, 20, 1, 1
P40, 0, 24, 3, 34, 3, 1

Available 계산:

  • Total = (10, 5, 7)
  • Allocated = (0+2+3+2+0, 1+0+0+1+0, 0+0+2+1+2) = (7, 2, 5)
  • Available = (3, 3, 2)

2. 안전성 검사 수행​

초기: Work = (3,3,2), Finish = [F,F,F,F,F]

Step 1: P1 선택 → Need[P1]=(1,2,2) ≤ Work=(3,3,2)? YES
        Work = (3,3,2) + (2,0,0) = (5,3,2), Finish[1]=T
        Safe Sequence: <P1>

Step 2: P3 선택 → Need[P3]=(0,1,1) ≤ Work=(5,3,2)? YES
        Work = (5,3,2) + (2,1,1) = (7,4,3), Finish[3]=T
        Safe Sequence: <P1, P3>

Step 3: P4 선택 → Need[P4]=(4,3,1) ≤ Work=(7,4,3)? YES
        Work = (7,4,3) + (0,0,2) = (7,4,5), Finish[4]=T
        Safe Sequence: <P1, P3, P4>

Step 4: P0 선택 → Need[P0]=(7,4,3) ≤ Work=(7,4,5)? YES
        Work = (7,4,5) + (0,1,0) = (7,5,5), Finish[0]=T
        Safe Sequence: <P1, P3, P4, P0>

Step 5: P2 선택 → Need[P2]=(6,0,0) ≤ Work=(7,5,5)? YES
        Work = (7,5,5) + (3,0,2) = (10,5,7), Finish[2]=T
        Safe Sequence: <P1, P3, P4, P0, P2>

결론: 안전 상태! 안전 순서: P1 → P3 → P4 → P0 → P2

3. 자원 요청 처리 예제​

P1이 (1,0,2) 요청:

1. Request(1,0,2) ≤ Need[P1]=(1,2,2)? → YES

2. Request(1,0,2) ≤ Available=(3,3,2)? → YES

3. 가상 할당:
   Available    = (3,3,2) - (1,0,2) = (2,3,0)
   Allocation[1] = (2,0,0) + (1,0,2) = (3,0,2)
   Need[1]       = (1,2,2) - (1,0,2) = (0,2,0)

4. 안전성 검사:
   Work=(2,3,0)
   P1: Need=(0,2,0) ≤ (2,3,0)? YES → Work=(5,3,2)
   P3: Need=(0,1,1) ≤ (5,3,2)? YES → Work=(7,4,3)
   P4: Need=(4,3,1) ≤ (7,4,3)? YES → Work=(7,4,5)
   P0: Need=(7,4,3) ≤ (7,4,5)? YES → Work=(7,5,5)
   P2: Need=(6,0,0) ≤ (7,5,5)? YES → 완료

결론: 안전! P1의 요청 (1,0,2) 허락
      새 안전 순서: P1 → P3 → P4 → P0 → P2

VI. 은행가 알고리즘의 특성 분석​

1. 장단점​

구분내용
장점교착상태를 사전에 회피하여 시스템 안정성 보장
장점예방 기법 대비 자원 낭비 최소화
장점프로세스를 종료하거나 자원을 선점할 필요 없음
단점프로세스 수(n)와 자원 종류(m)를 사전에 알아야 함
단점최대 자원 요구량(Max)을 사전에 선언해야 함
단점자원 요청마다 O(n²m) 안전성 검사 오버헤드
단점실제 OS에서는 동적 프로세스 생성으로 적용 어려움

2. 알고리즘 복잡도​

알고리즘시간 복잡도공간 복잡도
안전성 알고리즘O(n² × m)O(n × m)
자원 요청 알고리즘O(n² × m)O(n × m)

3. 실제 적용 한계와 대안​

VII. 결론​

핵심 요약내용
알고리즘 목적교착상태 회피(Avoidance): 안전 상태를 항상 유지
핵심 개념안전 상태 = 안전 순서가 존재하는 상태
주요 자료구조Available, Max, Allocation, Need (Need = Max - Allocation)
동작 원리자원 요청 시 가상 할당 후 안전성 검사, 불안전 시 대기
시간 복잡도O(n² × m)
실용성이론적으로 우수하나 실제 OS 적용의 한계 존재

기술사 관점: 은행가 알고리즘은 교착상태 이론의 핵심이자, 자원 관리에서 안전성과 효율성의 균형을 이론적으로 보여주는 알고리즘이다. 실제 운영체제(Linux, Windows)는 교착상태를 무시하거나(Ostrich) 탐지 후 복구 방식을 택하지만, 데이터베이스 시스템(DBMS)과 실시간 시스템에서는 유사한 자원 할당 회피 기법이 실용적으로 적용된다.
