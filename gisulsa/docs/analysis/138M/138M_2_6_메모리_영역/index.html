문제 6) 프로그램 실행 시 메모리 4가지 주요 영역

답)

개요​

운영체제는 프로그램 실행 시 프로세스에게 메모리를 할당하며, 이를 코드(Code), 데이터(Data), 힙(Heap), 스택(Stack)의 4가지 주요 영역으로 구분하여 관리한다. 각 영역은 저장 목적, 생명주기, 접근 방식이 다르며 영역 간 상호작용을 통해 프로그램이 동작한다.

메모리 구조 전체 개요​

영역주소 위치크기관리 주체생존 기간
코드(Code)낮은 주소고정OS/링커프로세스 종료까지
데이터(Data)코드 위고정OS/컴파일러프로세스 종료까지
힙(Heap)데이터 위 (↓ 성장)가변프로그래머명시적 해제까지
스택(Stack)높은 주소 (↑ 성장)가변 (제한)컴파일러/CPU함수 반환까지

가. 코드(Code) 영역​

1. 개념​

코드 영역(텍스트 영역)은 컴파일된 실행 명령어(기계어 코드)가 저장되는 영역으로, 프로그램의 실행 가능한 인스트럭션이 적재된다.

2. 역할과 특징​

특징설명
저장 내용컴파일된 기계어 명령어, 함수 코드
읽기 전용(Read-Only)실행 중 코드 변경 불가 → 쓰기 시 세그멘테이션 폴트(SIGSEGV) 발생
고정 크기컴파일 시 크기 결정, 런타임에 변경 없음
공유 가능동일 프로그램의 여러 프로세스가 코드 영역 공유 가능 (메모리 효율)
위치낮은 가상 주소 영역에 배치
실행 권한Execute(실행) 권한 부여, Write 권한 없음

3. 코드 영역 동작 예시​

// 아래 함수의 기계어 코드가 Code 영역에 저장됨
int add(int a, int b) {
    return a + b;  // → ADD 명령어로 컴파일되어 Code 영역에 적재
}

int main() {
    int result = add(3, 5);  // → CALL add 명령어 (Code 영역의 add 주소로 점프)
    return 0;
}

4. 보안 고려사항​

공격 유형원리대응 방안
코드 삽입 공격코드 영역에 악성 코드 주입 시도읽기 전용(NX bit) 설정
ROP(Return-Oriented Programming)기존 코드 조각(gadget) 재조합ASLR, CFI(Control Flow Integrity)
자가 변조 코드실행 중 코드 영역 변경 시도W^X(Write XOR Execute) 정책

나. 데이터(Data) 영역​

1. 개념​

데이터 영역은 전역 변수(Global Variable)와 정적 변수(Static Variable)가 저장되는 영역으로, 프로그램 시작 시 할당되고 종료 시 해제된다.

2. 데이터 영역의 세분화​

세부 영역저장 내용초기값예시
초기화 데이터초기값이 있는 전역/정적 변수명시된 값int globalVar = 10;
BSS초기값 없는 전역/정적 변수0으로 자동 초기화static int count;
ROdata문자열 리터럴, 상수읽기 전용const char* msg = "Hello";

3. 역할과 특징​

특징설명
고정 크기컴파일 시 크기 결정
프로그램 전 생존프로그램 실행부터 종료까지 메모리 유지
모든 함수에서 접근스코프에 따라 전역 접근 가능
BSS 최적화BSS 영역은 실행 파일에 크기만 기록 (0으로 초기화하므로 실제 데이터 불필요)

4. 데이터 영역 예시​

int globalInit = 100;        // 초기화 데이터 영역
static int staticVar = 50;   // 초기화 데이터 영역
int globalUninit;            // BSS 영역 (자동 0 초기화)
static int staticUninit;     // BSS 영역
const char* greeting = "Hi"; // ROdata 영역 (문자열 리터럴)

int main() {
    static int funcStatic = 5; // 초기화 데이터 영역 (함수 내 static)
    return 0;
}

다. 힙(Heap) 영역​

1. 개념​

힙 영역은 프로그램 실행 중 동적으로 메모리를 할당하고 해제하는 영역으로, 프로그래머가 명시적으로 관리하거나(C/C++) 가비지 컬렉터가 자동으로 관리한다(Java, Python).

2. 역할과 특징​

특징설명
동적 할당런타임에 크기 결정, 필요 시 할당·해제
성장 방향낮은 주소에서 높은 주소 방향으로 확장(↓)
느린 접근 속도스택보다 느림 (포인터를 통한 간접 접근)
큰 메모리 할당 가능스택보다 훨씬 큰 데이터 저장 가능
메모리 단편화할당/해제 반복 시 외부/내부 단편화 발생
수명 관리명시적 해제(free/delete) 또는 GC 필요

3. 힙 동작 메커니즘​

4. 힙 메모리 할당 기법​

기법설명장단점
First Fit첫 번째 충분한 빈 블록 사용빠름, 외부 단편화 발생
Best Fit가장 작은 충분한 빈 블록 사용단편화 최소화, 탐색 느림
Worst Fit가장 큰 빈 블록 사용큰 블록 유지, 단편화 심함
Buddy System2의 거듭제곱 크기로 분할/병합빠른 병합, 내부 단편화
Slab Allocator동일 크기 객체 전용 풀커널 객체 할당에 효율적

5. 힙 관련 문제 유형​

문제원인결과
메모리 누수(Memory Leak)할당 후 해제 누락메모리 고갈, 성능 저하
댕글링 포인터(Dangling Pointer)해제 후 포인터 사용예측 불가 동작, 보안 취약점
이중 해제(Double Free)동일 메모리 두 번 해제힙 구조 손상, 취약점
힙 오버플로우(Heap Overflow)할당 범위 초과 쓰기인접 데이터 손상
외부 단편화할당/해제 반복연속 메모리 부족
// 메모리 누수 예시
void leakExample() {
    int* ptr = (int*)malloc(sizeof(int) * 100);
    // free(ptr) 누락 → 메모리 누수
}

// 올바른 동적 할당
void correctExample() {
    int* ptr = (int*)malloc(sizeof(int) * 100);
    if (ptr == NULL) return;  // NULL 체크
    // ... 사용 ...
    free(ptr);     // 반드시 해제
    ptr = NULL;    // 댕글링 포인터 방지
}

라. 스택(Stack) 영역​

1. 개념​

스택 영역은 함수 호출 시 지역 변수, 매개변수, 반환 주소 등을 저장하는 LIFO(Last In First Out) 구조의 영역으로, 함수 호출과 반환에 따라 자동으로 관리된다.

2. 역할과 특징​

특징설명
LIFO 구조마지막에 쌓인 데이터가 먼저 제거
성장 방향높은 주소에서 낮은 주소 방향으로 확장(↑)
빠른 접근 속도SP(Stack Pointer) 레지스터로 직접 관리
자동 관리함수 호출 시 자동 할당, 반환 시 자동 해제
크기 제한스택 크기 한계 존재 (일반적으로 1~8MB)
스레드별 독립각 스레드는 독립적인 스택 보유

3. 스택 프레임(Stack Frame) 구조​

[높은 주소]
+---------------------------+
|  이전 함수 스택 프레임     |
+---------------------------+  ← 이전 프레임 포인터 (FP)
|  반환 주소 (Return Addr)  |  ← 함수 반환 후 돌아갈 주소
+---------------------------+
|  저장된 프레임 포인터 (SFP)|
+---------------------------+  ← 현재 FP (Frame Pointer)
|  지역 변수 1              |
+---------------------------+
|  지역 변수 2              |
+---------------------------+
|  ...                      |
+---------------------------+  ← SP (Stack Pointer)
[낮은 주소]

4. 함수 호출 시 스택 동작 메커니즘​

5. 재귀 함수와 스택​

// 재귀 함수: 각 호출마다 스택 프레임 생성
int factorial(int n) {
    if (n <= 1) return 1;          // 기저 조건: 스택 해제 시작
    return n * factorial(n - 1);  // 재귀 호출: 스택 프레임 쌓임
}

// factorial(4) 호출 시 스택 변화:
// [factorial(4)] → [factorial(3)] → [factorial(2)] → [factorial(1)]
//  n=4, ret=?       n=3, ret=?       n=2, ret=?       return 1
// ↑ 이후 역순으로 스택 해제 ↑

6. 스택 관련 문제 유형​

문제원인결과
스택 오버플로우(Stack Overflow)깊은 재귀, 큰 지역 변수프로세스 종료 (SIGSEGV)
스택 버퍼 오버플로우배열 범위 초과 쓰기반환 주소 변조 → 코드 실행 취약점
스택 언더플로우비정상적인 POP 연산잘못된 메모리 참조
// 스택 버퍼 오버플로우 예시 (보안 취약점)
void vulnerable(char* input) {
    char buffer[64];          // 스택에 64바이트 할당
    strcpy(buffer, input);    // 길이 체크 없이 복사 → 반환 주소 덮어쓰기 가능
}

// 안전한 코드
void safe(char* input) {
    char buffer[64];
    strncpy(buffer, input, sizeof(buffer) - 1);  // 길이 제한
    buffer[63] = '\0';
}

영역 간 동작 메커니즘​

1. 4가지 영역의 상호작용​

2. 실행 예시로 보는 영역 간 상호작용​

#include <stdlib.h>

int globalCount = 0;          // 데이터 영역 (초기화)
int* sharedBuffer;            // 데이터 영역 (BSS)

void processData(int size) {  // 코드 영역에 함수 기계어 저장
    int localVar = size * 2;  // 스택 영역 (지역 변수)
    
    // 스택의 지역 변수를 사용해 힙에 메모리 할당
    int* dynArray = (int*)malloc(sizeof(int) * localVar);  // 힙 영역
    
    globalCount++;            // 데이터 영역의 전역 변수 수정
    
    // ... 처리 ...
    
    free(dynArray);           // 힙 해제
}                             // 스택 프레임 자동 해제 (localVar, dynArray 소멸)

3. 영역별 비교 종합표​

구분코드 영역데이터 영역힙 영역스택 영역
저장 데이터기계어 명령어전역/정적 변수동적 할당 객체지역 변수, 반환 주소
크기 결정컴파일 시컴파일 시런타임런타임
접근 속도빠름중간느림매우 빠름
크기 제한제한적제한적거의 제한 없음제한적 (1~8MB)
관리 주체OS/링커OS/컴파일러프로그래머/GC컴파일러/CPU
읽기/쓰기읽기 전용읽기/쓰기읽기/쓰기읽기/쓰기
생존 기간프로세스 종료까지프로세스 종료까지명시적 해제까지함수 반환까지
주요 문제ROP 공격전역 상태 경쟁메모리 누수, 단편화스택 오버플로우

결론​

운영체제가 관리하는 4가지 메모리 영역(코드, 데이터, 힙, 스택)은 각각 고유한 역할과 생명주기를 가지며 상호 보완적으로 동작한다. 코드 영역은 실행 명령어를, 데이터 영역은 영구 변수를, 힙은 동적 데이터를, 스택은 함수 실행 컨텍스트를 담당한다. 이 구조에 대한 정확한 이해는 메모리 누수·스택 오버플로우·보안 취약점 방지의 핵심이다.
