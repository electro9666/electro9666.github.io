문제 4) 오류 제어 (Error Control)

답)

개요​

데이터 통신에서 전송 매체의 잡음(Noise), 감쇠(Attenuation), 간섭(Interference) 등으로 인해 비트 오류가 발생할 수 있다. 오류 제어(Error Control)는 이러한 오류를 검출(Detection)하고 정정(Correction)하여 신뢰성 있는 데이터 전송을 보장하는 기술이다.

가. 오류 검출(Error Detection)과 오류 정정(Error Correction)의 개념​

1. 오류 검출 (Error Detection)​

오류 검출은 수신된 데이터에 오류가 있음을 식별하는 기술로, 오류 위치나 내용은 알 수 없으며 재전송 요청(ARQ)을 통해 복구한다.

(1) 패리티 비트 (Parity Bit)​

종류원리한계
단순 패리티1비트의 개수가 짝수/홀수가 되도록 1비트 추가짝수 개 비트 오류 검출 불가
2차원 패리티행·열 각각 패리티 적용1비트 오류 정정 가능, 구현 복잡
VRC문자 단위 수직 패리티단순 오류만 검출

(2) 순환 중복 검사 (CRC, Cyclic Redundancy Check)​

CRC 동작 원리:
1. 송신측: 데이터 비트열을 생성 다항식(Generator Polynomial)으로 나눔
2. 나머지 비트(CRC 값)를 데이터에 추가하여 전송
3. 수신측: 수신 데이터를 동일한 생성 다항식으로 나눔
4. 나머지가 0이면 오류 없음, 아니면 오류 발생

예시) CRC-16: G(x) = x¹⁶ + x¹⁵ + x² + 1
      CRC-32: G(x) = x³² + x²⁶ + ... (이더넷, ZIP 등 사용)
CRC 종류다항식 차수활용
CRC-88비트단거리 통신
CRC-1616비트USB, Bluetooth
CRC-3232비트이더넷, ZIP, PNG
CRC-6464비트ECMA, 고신뢰성 시스템

CRC 특성:

  • 단일 비트 오류 100% 검출
  • 홀수 개 비트 오류 100% 검출
  • 버스트 오류(연속 오류) 검출에 탁월

(3) 체크섬 (Checksum)​

체크섬 계산 예시 (IP 헤더):
1. 헤더를 16비트 단위로 분할
2. 모든 16비트 값을 합산 (1의 보수 덧셈)
3. 합산값의 1의 보수가 체크섬
4. 수신측: 수신 데이터 합산 + 체크섬 = 0xFFFF이면 정상

2. 오류 정정 (Error Correction)​

오류 정정은 오류의 위치를 파악하여 수신측에서 직접 복원하는 기술이다.

(1) 해밍 코드 (Hamming Code)​

패리티 비트 위치: 2의 거듭제곱 위치 (1, 2, 4, 8, ...)

패리티 비트검사 범위
p1 (위치1)비트 1,3,5,7,9,11...
p2 (위치2)비트 2,3,6,7,10,11...
p3 (위치4)비트 4,5,6,7,12,13...

특성: 1비트 오류 정정 가능, 2비트 오류 검출 가능 (SECDED 확장 시)

(2) FEC (Forward Error Correction)​

방식알고리즘활용
컨볼루션 코드Viterbi 복호위성 통신, 초기 Wi-Fi
터보 코드반복 복호3G/4G 이동통신
LDPC 코드소프트 복호5G NR, Wi-Fi 6, DVB
폴라 코드SC 복호5G NR 제어채널
리드-솔로몬다항식 복호CD, DVD, QR코드

3. 오류 검출 vs 오류 정정 비교​

구분오류 검출오류 정정
목적오류 발생 여부 확인오류 위치 파악 및 자체 복원
오버헤드적음많음 (더 많은 잉여 비트)
복구 방법재전송 요청 (ARQ)자체 복원 (FEC)
지연재전송 왕복 지연 발생지연 없음
적합 환경재전송 가능한 유선망위성·방송 등 재전송 불가
예시CRC, 패리티해밍 코드, LDPC

나. Stop-and-Wait ARQ와 Go-Back-N ARQ​

ARQ (Automatic Repeat reQuest) 개요​

ARQ는 오류 검출 후 수신측이 송신측에 재전송을 요청하는 오류 제어 방식이다.

1. Stop-and-Wait ARQ​

개념​

송신측이 1개의 프레임을 전송한 후, ACK(긍정 응답) 또는 NAK(부정 응답)을 받을 때까지 다음 프레임 전송을 중단하고 대기하는 방식이다.

수행 절차​

상세 처리 로직​

[송신측 동작]
1. Frame N 전송
2. 타이머 시작
3. 대기:
   - ACK 수신 시: 다음 프레임 전송
   - NAK 수신 시: Frame N 재전송
   - 타임아웃 시: Frame N 재전송
   - ACK/NAK 손실 → 타임아웃 → 재전송 (수신측 중복 감지)

[수신측 동작]
1. Frame 수신
2. CRC 오류 검사:
   - 정상: ACK N+1 전송, 상위 계층에 데이터 전달
   - 오류: NAK N 전송 또는 무시(묵시적 NAK)
3. 중복 프레임 수신 시: 폐기 후 ACK 재전송

효율성 분석​

전파 지연을 a = Tp/Tf 라 할 때 (Tp: 전파 지연, Tf: 프레임 전송 시간)

효율 η = 1 / (1 + 2a)

예시: 위성 통신 (왕복 270ms), 1Mbps, 1000비트 프레임
  Tf = 1000/10^6 = 1ms
  Tp = 135ms
  a = 135
  η = 1/(1+270) ≈ 0.37% → 매우 비효율적

2. Go-Back-N ARQ​

개념​

슬라이딩 윈도우(Sliding Window) 방식으로 여러 프레임을 연속 전송하며, 오류 발생 시 해당 프레임부터 이후 모든 프레임을 재전송하는 방식이다.

수행 절차​

상세 처리 로직​

[송신측 동작]
1. 윈도우 크기 W (= 2^n - 1) 만큼 연속 전송
2. 각 프레임에 타이머 설정
3. ACK 수신 시: 윈도우 슬라이딩 → 새 프레임 전송
4. NAK or 타임아웃 수신 시:
   - 해당 프레임 번호부터 이후 전송된 모든 프레임 재전송
   - Go-Back-N: N번 프레임부터 다시(Go Back) 전송

[수신측 동작]
1. 순서대로 프레임 수신
2. 오류 없고 순서 맞으면: ACK (N+1) 전송, 버퍼에 저장
3. 순서에 맞지 않는 프레임: 모두 폐기
4. 오류 있는 프레임 수신: NAK 전송 또는 폐기

윈도우 크기와 순서 번호​

순서 번호 비트 수: n비트
윈도우 크기: W = 2^n - 1 (Go-Back-N)

이유: W = 2^n이면 ACK 손실 시 송수신측 혼란
     (새 Frame 0과 재전송 Frame 0 구분 불가)

예시) n=3비트 → 순서번호 0~7 → 윈도우 크기 최대 7

효율성 분석​

효율 η = W / (1 + 2a)   단, W ≥ 1 + 2a인 경우 η = 1

예시: 위성 통신, W=7
  η = 7/(1+270) ≈ 2.58% → Stop-and-Wait의 7배
  
  W가 충분히 크면 (W ≥ 271):
  η = 1 = 100%

다. Stop-and-Wait ARQ와 Go-Back-N ARQ 비교​

1. 핵심 비교표​

비교 항목Stop-and-Wait ARQGo-Back-N ARQ

수신측 버퍼불필요 (1프레임)불필요 (순서 어긋난 프레임 폐기)

3. 효율성 비교 시뮬레이션​

가정: n=3비트 (순서번호 0~7), 오류율 p=0

6. ARQ 방식 선택 기준​

환경권장 방식이유
근거리 LANStop-and-Wait전파 지연 작음
위성 통신Go-Back-N or SR전파 지연 매우 큼
무선 통신 (높은 오류)Selective Repeat불필요한 재전송 최소화
TCP/IP유사 Selective Repeat슬라이딩 윈도우 + 선택적 재전송

결론​

오류 제어는 패리티·CRC 등 검출 기술과 해밍코드·FEC 등 정정 기술로 구성된다. ARQ 방식 중 Stop-and-Wait는 구현이 단순하지만 전파 지연이 큰 환경에서 효율이 크게 저하되며, Go-Back-N ARQ는 슬라이딩 윈도우로 효율을 대폭 향상시키지만 오류 시 불필요한 재전송이 발생한다는 단점이 있다. 실제 TCP에서는 Selective Repeat에 가까운 방식을 채택하여 신뢰성과 효율성을 동시에 확보한다.
