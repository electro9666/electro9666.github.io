  • 문제 3) 분산 데이터베이스 시스템 구축을 위한 데이터베이스 분할

문제 3) 분산 데이터베이스 시스템 구축을 위한 데이터베이스 분할

답)

개요​

분산 데이터베이스 시스템에서 데이터베이스 분할(Database Fragmentation)은 대용량 데이터를 여러 노드에 효율적으로 분산 저장하기 위한 핵심 기법이다. 데이터 분할을 통해 병렬 처리, 부하 분산, 가용성 향상, 성능 최적화를 달성할 수 있다.

가. 데이터베이스 분할 단위​

1. 파티셔닝 (Partitioning)​

개념​

  • 단일 DBMS 내에서 하나의 테이블을 여러 물리적 파티션으로 분리하는 기법
  • 논리적으로는 하나의 테이블로 보이나 물리적으로는 분산 저장

파티셔닝 유형​

유형설명예시
범위 파티셔닝 (Range)컬럼 값의 범위로 분할날짜별, 연도별
해시 파티셔닝 (Hash)해시 함수로 균등 분할고객ID 해시값
목록 파티셔닝 (List)특정 값 목록으로 분할지역(서울, 부산, 대구)
복합 파티셔닝 (Composite)여러 방식 조합범위+해시
라운드로빈 (Round-Robin)순환 방식 균등 분배부하 균형

파티셔닝 구현 예시 (MySQL)​

CREATE TABLE orders (
    order_id    INT NOT NULL,
    order_date  DATE NOT NULL,
    amount      DECIMAL(10,2),
    region      VARCHAR(20)
)
PARTITION BY RANGE (YEAR(order_date)) (
    PARTITION p2022 VALUES LESS THAN (2023),
    PARTITION p2023 VALUES LESS THAN (2024),
    PARTITION p2024 VALUES LESS THAN (2025),
    PARTITION p_future VALUES LESS THAN MAXVALUE
);

파티셔닝 장단점​

구분내용
장점쿼리 성능 향상(파티션 프루닝), 데이터 관리 효율, 백업/복구 용이
단점파티션 키 설계 복잡, 크로스 파티션 쿼리 성능 저하, 인덱스 제약

2. 샤딩 (Sharding)​

개념​

  • 여러 독립적인 DBMS 노드에 데이터를 분산 저장하는 수평 확장(Scale-out) 기법
  • 각 샤드는 완전히 독립된 데이터베이스 인스턴스

샤딩 방식​

방식설명장점단점
범위 기반 샤딩키 범위로 샤드 결정범위 쿼리 효율데이터 편중 가능
해시 기반 샤딩해시함수로 샤드 결정균등 분포범위 쿼리 비효율
디렉토리 기반 샤딩조회 테이블로 샤드 결정유연한 재샤딩조회 오버헤드
지리적 샤딩사용자 위치로 샤드 결정지연시간 최소화지역별 불균형

샤딩 적용 사례​

서비스샤딩 방식샤드 키
Instagram사용자 기반 샤딩User ID
Twitter트윗 ID 해시 샤딩Tweet ID
MongoDB컴파운드 샤드 키복합 키

샤딩 도전 과제​

문제내용해결 방안
핫스팟특정 샤드 과부하해시 샤딩, 샤드 분할
크로스 샤드 조인조인 성능 저하비정규화, 집계 서비스
재샤딩 복잡성데이터 재분배 어려움일관된 해싱(Consistent Hashing)
분산 트랜잭션ACID 보장 어려움2PC, Saga 패턴

3. 프래그먼테이션 (Fragmentation)​

개념​

분산 데이터베이스에서 릴레이션(테이블)을 여러 **프래그먼트(Fragment)**로 분할하여 서로 다른 사이트에 배치하는 기법. 투명성(Transparency)을 유지하면서 데이터를 분산 저장.

프래그먼테이션의 조건 (Correctness Criteria)​

조건설명
완전성 (Completeness)원본 릴레이션의 모든 데이터가 프래그먼트에 존재
재구성 가능성 (Reconstruction)프래그먼트들로 원본 릴레이션을 완전히 복원 가능
비중복성 (Disjointness)동일 데이터가 여러 프래그먼트에 중복 없음 (단, 수직 분할 시 PK 제외)

프래그먼테이션 vs 파티셔닝 vs 샤딩​

구분프래그먼테이션파티셔닝샤딩
범위분산 DB 이론적 개념단일 DBMS 물리적 구현다중 DBMS 분산 구현
위치다수 사이트단일 서버다수 서버
투명성프래그먼테이션 투명성 제공애플리케이션 투명미들웨어로 투명성
표준DDBMS 이론 표준SQL 표준 확장벤더/프레임워크별 상이

나. 수평분할과 수직분할​

1. 수평 분할 (Horizontal Partitioning / Fragmentation)​

개념​

테이블의 **행(Row, Tuple)**을 기준으로 데이터를 분할. 각 파티션은 동일한 컬럼 구조를 가지며 서로 다른 행 집합을 포함.

수평 분할 방법​

(1) 범위 수평 분할 (Range Horizontal Partitioning)​
-- 연도별 범위 수평 분할
CREATE TABLE sales_2023
    CHECK (sale_year = 2023)
    INHERITS (sales);  -- PostgreSQL 방식

CREATE TABLE sales_2024
    CHECK (sale_year = 2024)
    INHERITS (sales);
특성내용
분할 기준컬럼 값의 연속적 범위
적합 데이터시계열 데이터, 순차적 ID
파티션 프루닝범위 조건 쿼리에 효과적
단점데이터 편중(최신 파티션에 집중)
(2) 해시 수평 분할 (Hash Horizontal Partitioning)​
-- PostgreSQL 해시 파티셔닝
CREATE TABLE customers (
    customer_id SERIAL,
    name VARCHAR(100),
    email VARCHAR(200)
) PARTITION BY HASH (customer_id);

CREATE TABLE customers_p0 PARTITION OF customers
    FOR VALUES WITH (MODULUS 4, REMAINDER 0);
CREATE TABLE customers_p1 PARTITION OF customers
    FOR VALUES WITH (MODULUS 4, REMAINDER 1);
CREATE TABLE customers_p2 PARTITION OF customers
    FOR VALUES WITH (MODULUS 4, REMAINDER 2);
CREATE TABLE customers_p3 PARTITION OF customers
    FOR VALUES WITH (MODULUS 4, REMAINDER 3);
특성내용
분할 기준Hash(키) mod N
적합 데이터균등 분산이 필요한 데이터
데이터 분포균일한 분포 보장
단점범위 쿼리 비효율, 재해싱 비용
(3) 목록 수평 분할 (List Horizontal Partitioning)​
-- 지역별 목록 파티셔닝
CREATE TABLE orders PARTITION BY LIST (region);

CREATE TABLE orders_seoul PARTITION OF orders
    FOR VALUES IN ('서울', '강북', '강남');
CREATE TABLE orders_busan PARTITION OF orders
    FOR VALUES IN ('부산', '경남');
CREATE TABLE orders_others PARTITION OF orders
    DEFAULT;
(4) 복합 수평 분할 (Composite Horizontal Partitioning)​

수평 분할 장단점​

구분내용
장점병렬 쿼리 처리로 성능 향상
파티션 단위 데이터 관리(삭제, 아카이브) 용이
특정 파티션 장애 시 다른 파티션 정상 운영
균형 잡힌 스토리지 활용
대용량 데이터 처리 효율
단점파티션 키 이외 컬럼 기반 조회 시 전체 스캔
파티션 간 조인 발생 시 성능 저하
파티션 키 설계 오류 시 성능 역효과
재파티셔닝 시 대규모 데이터 이동 필요

수평 분할 활용 사례​

서비스 유형분할 방법분할 키효과
금융 거래 시스템범위 분할거래일자기간별 조회 성능 향상
전자상거래 주문해시 분할주문ID균등한 부하 분산
물류 관리 시스템목록 분할지역코드지역별 데이터 격리
SNS 게시글복합 분할날짜+사용자시계열+분산 조합

2. 수직 분할 (Vertical Partitioning / Fragmentation)​

개념​

테이블의 **열(Column, Attribute)**을 기준으로 데이터를 분할. 각 파티션은 기본키(PK)와 일부 컬럼만 포함하며 조인으로 원본 재구성 가능.

수직 분할 방법​

(1) 접근 빈도 기반 분할​
-- 원본 테이블
-- product(id, name, price, description, image_data, review_count, inventory)

-- 자주 조회되는 컬럼 (핫 파티션)
CREATE TABLE product_basic (
    id          BIGINT PRIMARY KEY,
    name        VARCHAR(200),
    price       DECIMAL(10,2),
    inventory   INT
);

-- 가끔 조회되는 컬럼 (콜드 파티션)
CREATE TABLE product_detail (
    id          BIGINT PRIMARY KEY REFERENCES product_basic(id),
    description TEXT,
    image_data  BYTEA,
    review_count INT
);
(2) 컬럼스토어(Columnar Storage) 방식​
특성행 기반 (OLTP)열 기반 (OLAP)
저장 방식행 단위 저장컬럼 단위 저장
압축률낮음높음 (동질 데이터)
읽기 성능특정 행 조회 빠름집계/분석 쿼리 빠름
쓰기 성능빠름상대적으로 느림
적용 사례MySQL, PostgreSQLRedshift, BigQuery, ClickHouse
(3) 기능별 도메인 분할​

수직 분할 장단점​

구분내용
장점I/O 효율 향상 (필요한 컬럼만 읽기)
캐시 효율 개선 (버퍼 풀 활용 극대화)
대용량 컬럼(BLOB, TEXT) 분리로 성능 향상
컬럼 단위 압축으로 스토리지 절약
민감 정보 컬럼 별도 관리로 보안 강화
마이크로서비스 분리 기반 구성 가능
단점조인 쿼리 필요로 복잡도 증가
여러 파티션 동시 수정 시 트랜잭션 복잡
스키마 변경 시 파티션 간 일관성 유지 어려움
전체 행 조회 시 조인 오버헤드 발생

수직 분할 활용 사례​

서비스 유형분할 방법효과
전자상거래 상품기본정보/상세정보 분리목록 조회 성능 향상
금융 고객정보인증정보/개인정보 분리보안 강화
DW/분석 시스템컬럼스토어 분리분석 쿼리 고속화
의료 정보 시스템일반정보/민감정보 분리HIPAA 준수, 보안

3. 수평분할 vs 수직분할 비교​

비교 항목수평 분할수직 분할
분할 기준행(Row) 기준열(Column) 기준
파티션 구조동일 컬럼, 다른 행 집합다른 컬럼, 동일 행 참조
재구성 연산UNIONJOIN
스키마 변경컬럼 추가 시 모든 파티션 영향행 추가 시 모든 파티션 영향
주요 목적대용량 데이터 분산, 병렬 처리I/O 최적화, 접근 패턴 최적화
적합 워크로드OLTP, 대용량 삽입/조회OLAP, 분석, 컬럼 선택적 조회
확장성수평 확장(Scale-out)수직 최적화
구현 복잡도중간낮음~중간
샤딩과의 관계샤딩의 이론적 기반마이크로서비스 분리에 활용

4. 혼합 분할 (Mixed/Hybrid Partitioning)​

실제 엔터프라이즈 환경에서는 수평 + 수직 분할을 혼합하여 최적 성능 달성

결론​

데이터베이스 분할은 분산 시스템의 성능과 가용성을 결정하는 핵심 설계 요소이다.

분할 전략선택 기준
파티셔닝단일 DBMS 내 대용량 테이블 관리
샤딩수평 확장이 필요한 대규모 시스템
수평 분할동일 구조의 대용량 데이터 분산
