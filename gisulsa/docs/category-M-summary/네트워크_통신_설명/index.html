04. 네트워크/통신, 키워드로 쭉 훑어보기

1. 프로토콜 — 컴퓨터끼리 어떻게 말을 맞추는가​

네트워크를 이야기할 때 제일 먼저 나오는 게 정보통신 용어 및 교환방식 이에요. 데이터를 전달하는 방식은 크게 두 가지인데, 회선교환 은 통화처럼 처음부터 끝까지 전용 회선을 잡아두는 방식이고, 패킷교환 은 데이터를 잘게 쪼개서(패킷으로 만들어서) 여러 경로로 보내는 방식이에요. 인터넷은 기본적으로 패킷교환 방식이죠.

이렇게 컴퓨터끼리 통신할 때 지켜야 하는 약속을 통신 프로토콜 이라고 해요. 프로토콜을 설계할 때는 오류제어, 혼잡제어, 슬라이딩윈도우 를 반드시 고려해야 해요. 이 세 가지가 통신의 신뢰성을 책임지거든요.

인터넷에서 가장 많이 쓰는 프로토콜이 TCP 예요. TCP로 연결을 맺을 때 TCP 3-way handshake 를 써요. SYN → SYN-ACK → ACK, 이렇게 세 번 주고받으면서 "나 연결할게" "나도 좋아" "알겠어" 하는 거예요. 반대로 연결을 끊을 땐 4-way handshake 를 해요. FIN → ACK → FIN → ACK, 이렇게 네 번이에요. 왜 끊을 때 한 번 더 하냐면, 양쪽이 각각 독립적으로 연결 종료 의사를 밝혀야 하기 때문이에요.

웹에서 쓰는 HTTP 는 편리하지만 평문 전송이라 보안에 취약해요. HTTP 취약점 으로는 스니핑, 중간자 공격 등이 있어요. 그래서 SSL/TLS 암호화를 얹은 HTTPS 를 써야 해요. 요즘 HTTP만 쓰는 사이트는 브라우저가 "안전하지 않음"이라고 경고를 띄워요.

파일 전송도 마찬가지예요. FTP, FTPS, SFTP 를 비교해보면, FTP는 평문 전송이라 보안이 없고, FTPS는 FTP에 SSL/TLS를 얹은 거고, SFTP는 SSH 위에서 파일을 전송하는 전혀 다른 프로토콜이에요. 이름이 비슷해서 혼동하기 쉬운데 FTPS와 SFTP는 완전히 달라요.

통신의 끝단에는 Socket 통신 이 있어요. TCP Socket 은 연결 지향형으로 신뢰성 있는 데이터 전송을 하고, Web Socket 은 HTTP 업그레이드를 통해 브라우저와 서버 간 양방향 실시간 통신을 가능하게 해요. 소켓 통신과 TCP/Web 소켓 을 비교하면, TCP 소켓은 OS 레벨의 네트워크 통신이고 WebSocket은 웹 애플리케이션용 프로토콜이라는 차이가 있어요.

실시간 통신의 꽃은 WebRTC(Web Real-Time Communication) 예요. 브라우저끼리 플러그인 없이 직접 영상통화나 화상회의를 할 수 있게 해주는 API예요. 구글 미트, 화상통화 앱들이 다 이걸 써요. 피어 투 피어(P2P)로 연결하는 게 핵심이에요.

IoT 기기들 사이에서 가벼운 메시지를 주고받는 프로토콜도 있어요. XMPP, CoAP, MQTT 를 비교하면, XMPP는 XML 기반의 메시징 프로토콜, CoAP은 HTTP를 경량화한 IoT 전용 프로토콜, MQTT는 발행-구독(publish-subscribe) 구조로 초경량 메시지를 전달하는 프로토콜이에요. 배터리로 동작하는 센서 기기들엔 MQTT가 제일 적합해요.

좀 덜 알려졌지만 중요한 프로토콜도 있어요. SCTP(Stream Control Transmission Protocol) 는 TCP처럼 신뢰성 있는 전송을 하면서도 여러 스트림을 동시에 처리할 수 있는 프로토콜이에요. 통신망 신호 시스템에 주로 써요. 그리고 공장 현장에서는 MODBUS 프로토콜 을 많이 써요. 산업용 기기들(PLC, 센서, 계측기) 사이의 통신 표준이에요. 1979년에 나왔는데 아직도 현장에서 현역으로 쓰이고 있어요.

2. 라우팅 — 패킷은 어떤 길로 가는가​

패킷이 목적지까지 가려면 어떤 경로로 갈지 결정해야 해요. 이게 라우팅이에요.

거리벡터 라우팅(Distance Vector Routing) 은 각 라우터가 이웃한 라우터들과 정보를 교환하면서 목적지까지의 거리와 방향을 파악하는 방식이에요. 벨만-포드 알고리즘을 기반으로 해요. 구현이 단순하다는 장점이 있지만, 변경 사항이 전파되는 데 시간이 걸리는 "느린 수렴" 문제가 있어요.

라우팅 프로토콜의 대표 주자로 RIP 와 OSPF 를 비교할 수 있어요. RIP(Routing Information Protocol)는 홉 수를 기준으로 경로를 선택하는 거리벡터 방식이고, 최대 홉 수가 15라서 대형 네트워크엔 못 써요. OSPF(Open Shortest Path First)는 링크 상태 정보를 전체 토폴로지에 퍼뜨려서 다익스트라 알고리즘으로 최단 경로를 계산하는 링크상태 방식이에요. 규모가 커지면 OSPF를 써야 해요.

이 두 프로토콜은 모두 같은 자율 시스템(AS) 안에서 쓰는 IGP(Interior Gateway Protocol) 예요. 반면 자율 시스템 사이를 연결하는 게 EGP(Exterior Gateway Protocol) 고, 인터넷에서는 BGP(Border Gateway Protocol)가 사실상 표준이에요. IGP와 EGP 비교는 "내부 라우팅이냐 외부(인터넷) 라우팅이냐"의 차이로 기억하면 돼요.

3. 이동통신 — 선 없이 어떻게 빠르게 통신하는가​

5G 네트워크 의 기술적 특징은 크게 세 가지예요. eMBB(초고속), URLLC(초저지연·초고신뢰), mMTC(대규모 기기 연결)이에요. 4G LTE보다 속도는 20배, 지연은 10분의 1 수준이에요.

5G 특화망(지역 5G) 은 특정 공간(공장, 병원, 항만)에 기업이 직접 구축하는 사설 5G 망이에요. 일반 상용 5G망과 달리 완전한 제어권을 가질 수 있어요. 5G 특화망 네트워크 구축 고려사항 으로는 안정성·신뢰성 확보, 기존 주파수와의 간섭 회피, 보안 설계 등이 중요해요.

5G의 핵심 기술 중 하나가 5G 네트워크 슬라이싱(Network Slicing) 이에요. 하나의 물리 네트워크를 여러 개의 가상 네트워크로 분할해서, 용도별로 맞춤형 품질을 제공하는 기술이에요. 예를 들어 자율주행차에는 초저지연 슬라이스, 영상 스트리밍에는 고대역폭 슬라이스를 할당하는 거예요.

그 다음 세대인 6G 이동통신 은 2030년대 상용화를 목표로 해요. 6G 이동통신기술 서비스, 성능, 주파수 를 보면 테라헤르츠(THz) 주파수 대역을 쓰고, 5G보다 50배 이상 빠른 속도를 목표로 해요. 특히 6G AI-Native Network 개념이 핵심인데, AI가 네트워크 자원 배분과 최적화를 자율적으로 수행해요. AI-RAN 은 무선 접속망(RAN)에 AI를 내재화한 구조예요.

6G에서 빠질 수 없는 게 6G 위성-상공-지상 통합형 네트워크(SATIN) 예요. 위성, 고고도 플랫폼(HAPS), 지상 기지국을 하나로 묶어서 전 지구적 커버리지를 실현하는 개념이에요. 오지, 해상, 항공기 위에서도 끊김 없는 통신이 가능해지는 거죠.

다중 접속 기술로는 비직교 다중접속(NOMA) 이 있어요. 기존 OMA(직교 다중접속)는 사용자마다 서로 다른 자원(주파수, 시간)을 할당했는데, NOMA는 같은 자원을 겹쳐서 여러 사용자에게 동시에 할당하고, 수신 측에서 신호를 분리해내는 방식이에요. 스펙트럼 효율이 올라가는 거예요.

SDR(Software Defined Radio) 는 무선 통신 기능을 하드웨어가 아닌 소프트웨어로 구현하는 기술이에요. 프로그래밍만으로 주파수, 변조 방식, 프로토콜을 바꿀 수 있어서 다양한 통신 표준에 유연하게 대응할 수 있어요.

자동차도 이제 통신 기기가 됐어요. 차량·사물 셀룰러 통신(C-V2X) 는 차량과 차량, 차량과 도로 인프라, 차량과 보행자, 차량과 네트워크 사이의 통신을 LTE/5G 셀룰러 망을 통해 하는 기술이에요. 자율주행의 핵심 인프라예요.

Wi-Fi도 계속 진화하고 있어요. IEEE 802.11bn 은 차세대 Wi-Fi 표준으로, Wi-Fi 8이라고도 불려요. 더 높은 처리량, 더 낮은 지연, 다중 AP 간 협력 통신 등을 목표로 하고 있어요.

4. IoT/센서네트워크 — 사물은 어떻게 연결되는가​

IoT 네트워크 보안 을 이야기할 때 CoAP, MQTT, LwM2M 세 프로토콜이 항상 같이 나와요. CoAP과 MQTT는 앞서 설명했고, LwM2M(Lightweight M2M)은 ETSI 표준으로 IoT 디바이스 원격 관리(등록, 설정, 업데이트)를 위한 프로토콜이에요. 이 세 가지 모두 경량화된 IoT 환경에 맞게 설계됐지만, 보안 설계가 취약하면 공격에 노출될 수 있어요.

수많은 IoT 기기를 식별하는 체계도 필요해요. 객체식별자 기반 IoT 디바이스 식별체계 는 각 기기에 고유한 OID(Object Identifier)를 부여해서 전 세계적으로 유일하게 식별하는 표준이에요.

IoT를 확장한 개념이 행동인터넷(IoB, Internet of Behavior) 이에요. IoT로 수집한 데이터를 인간의 행동 패턴 분석에 활용하는 거예요. 스마트워치가 운동 습관을 추적하거나, 매장에서 고객 동선을 분석하는 것들이 다 IoB의 사례예요.

무선 센서 네트워크 쪽을 보면, WSN(Wireless Sensor Network) 과 애드혹(Ad-hoc) 네트워크 를 비교할 수 있어요. WSN은 센서 노드들이 환경 데이터를 수집해서 베이스 스테이션으로 전달하는 구조고, Ad-hoc 네트워크는 고정된 인프라 없이 노드들이 자율적으로 망을 구성하는 방식이에요. 군사, 재난 현장에서 많이 써요.

WSN의 라우팅 기법 중 무선 센서 네트워크 Itinerary Routing 이 있는데, 이건 이동 에이전트(모바일 에이전트)가 센서 노드를 순회하면서 데이터를 수집하는 방식이에요. 데이터를 중앙으로 모으는 게 아니라 에이전트가 직접 찾아다니는 거죠.

배터리로 오래 쓰는 IoT 기기들을 위한 LPWA(Low Power Wide Area) 기술도 있어요. LoRa, Sigfox, NB-IoT가 대표적인데, 저전력으로 수 킬로미터 거리의 통신이 가능해요. 스마트 미터, 농업 모니터링처럼 배터리 수명이 수년이어야 하는 기기에 딱이에요.

물리 세계와 디지털 세계를 연결하는 개념이 CPS(Cyber-Physical System) 예요. 실제 물리 시스템(공장 기계, 전력망)에 컴퓨팅·통신·제어를 융합한 거예요. CPS 구축 절차 는 요구사항 정의 → 물리 시스템 모델링 → 사이버 시스템 설계 → 통합 및 테스트 순서로 진행해요.

IoT 보안 위협의 대표 사례가 미라이 봇넷 이에요. 보안이 취약한 IoT 기기(CCTV, 공유기 등)를 대량으로 감염시켜 DDoS 공격에 활용한 사건이에요. 이 사건 이후 IoT 보안 7대 원칙(공통보안 7대원칙)이 강조됐는데, 기본 자격 증명 변경, 소프트웨어 업데이트, 암호화 통신 등이 포함돼요.

산업 현장에 IoT를 접목한 게 스마트팩토리시스템(Smart Factory System) 이에요. 센서, CPS, 빅데이터, AI를 통합해서 생산 공정을 자동화하고 실시간으로 모니터링하는 거예요. MODBUS 같은 산업용 통신 프로토콜과 IoT 기술이 만나는 지점이기도 해요.

5. SDN/NFV — 네트워크도 소프트웨어로 정의할 수 있는가​

전통적인 네트워크 장비는 하드웨어와 소프트웨어가 꽉 묶여 있어서, 네트워크 정책을 바꾸려면 장비마다 직접 설정을 바꿔야 했어요. 이걸 바꾼 게 SDN(Software Defined Networking) 이에요.

SDN은 데이터를 실제로 전달하는 제어 평면 과 경로를 결정하는 평면을 분리하고, 중앙 집중식 컨트롤러가 전체 네트워크를 소프트웨어로 제어해요. 컨트롤러와 스위치 사이의 통신 프로토콜이 오픈플로우(OpenFlow) 예요. 컨트롤러가 OpenFlow로 스위치에게 "이 패킷은 이 포트로 내보내"라고 명령하는 거죠.

네트워크 가상화 기술들을 비교하면, VLAN 은 물리 네트워크를 논리적으로 분할하는 기술, VPN 은 공용 네트워크 위에 암호화된 사설 터널을 만드는 기술, NFV(Network Function Virtualization) 는 방화벽, 로드밸런서 같은 네트워크 기능을 소프트웨어로 가상화해서 범용 서버에서 실행하는 기술이에요. VLAN, VPN, NFV 비교 는 기출에도 나온 단골 주제예요.

클라우드 데이터센터에서 VLAN의 한계를 극복하기 위해 나온 게 VXLAN(Virtual eXtensible LAN) 이에요. 일반 VLAN은 최대 4094개까지만 만들 수 있는데, VXLAN은 약 1600만 개의 가상 네트워크를 만들 수 있어요. IP 네트워크 위에 Layer 2 프레임을 캡슐화해서 터널링하는 방식이에요. 대규모 클라우드 환경에서 테넌트 격리가 필요할 때 써요.

6. QoS — 품질을 어떻게 보장하는가​

네트워크에서 모든 패킷을 동등하게 처리하면 영상통화 중에 데이터가 밀려서 끊기는 일이 생겨요. 이걸 방지하는 게 QoS(Quality of Service) 예요.

QoS 방식으로 DiffServ 와 IntServ 를 비교해볼게요. IntServ(Integrated Services)는 각 흐름마다 자원을 예약하는 방식인데(RSVP 프로토콜 사용), 흐름이 많아지면 라우터의 상태 정보가 폭발적으로 늘어서 확장성이 떨어져요. DiffServ(Differentiated Services)는 패킷에 클래스를 표시해서 클래스별로 차등 처리하는 방식이에요. 각 흐름의 상태를 기억하지 않아도 되니까 확장성이 훨씬 좋아요. 대규모 인터넷에서는 DiffServ를 주로 써요.

큐(대기열) 관리 기법인 WFQ(Weighted Fair Queuing) 도 있어요. 여러 트래픽 흐름이 있을 때, 각 흐름에 가중치(Weight)를 부여해서 가중치에 비례한 대역폭을 보장해주는 방식이에요. 예를 들어 음성 트래픽에 가중치 2를 주면, 가중치 1인 데이터 트래픽보다 두 배 더 자주 패킷을 내보내는 거예요.

7. 오류/혼잡제어 — 오류와 막힘을 어떻게 처리하는가​

데이터를 전송하다 보면 오류가 생길 수 있어요. 오류를 검출하는 대표 기법이 CRC(Cyclic Redundancy Check) 예요. 데이터를 특정 다항식으로 나눈 나머지를 함께 전송하고, 수신 측에서 같은 연산을 해서 나머지가 맞는지 확인하는 거예요. 이더넷, USB, ZIP 파일 등 거의 모든 곳에서 쓰이는 검증 방식이에요.

오류가 검출됐을 때 어떻게 처리할지가 ARQ(Automatic Repeat reQuest) 기법이에요. 오류 검출/정정, Stop-and-Wait ARQ, Go-Back-N ARQ 를 비교해볼게요. Stop-and-Wait ARQ는 하나 보내고 ACK 받을 때까지 기다리는 방식이라 효율이 낮아요. Go-Back-N ARQ는 ACK 없이 여러 프레임을 연속으로 보내다가 오류가 생기면 오류 지점부터 전부 다시 보내는 방식이에요. 더 효율적인 Selective Repeat ARQ는 오류 난 프레임만 재전송해요.

이런 여러 프레임을 연속 전송하는 걸 가능하게 하는 게 슬라이딩 윈도우 예요. 한 번에 보낼 수 있는 프레임의 수를 "윈도우"라고 부르고, ACK를 받으면 윈도우가 앞으로 밀려가는(슬라이딩) 방식이에요. 오류 제어, 혼잡 제어, 슬라이딩 윈도우 는 프로토콜 설계의 기본 삼총사예요.

네트워크가 처리할 수 있는 것보다 더 많은 데이터가 들어오면 혼잡(Congestion)이 생겨요. TCP 혼잡제어 메커니즘 은 크게 네 단계로 동작해요. Slow Start(처음엔 천천히 보내기 시작), Congestion Avoidance(임계값에 도달하면 조금씩 늘리기), Fast Retransmit(ACK 3번 못 받으면 즉시 재전송), Fast Recovery(혼잡 감지 후 빠르게 회복)예요. TCP는 이 메커니즘으로 혼잡을 감지하고 윈도우 크기 를 동적으로 조절해요.

8. 기타 네트워크 — 그 밖에 알아야 할 것들​

네트워크의 기본 중의 기본은 OSI 7 Layer 예요. 국제표준화기구(ISO)에서 정한 네트워크 통신 참조 모델로, 물리(1) - 데이터링크(2) - 네트워크(3) - 전송(4) - 세션(5) - 표현(6) - 응용(7) 계층으로 나뉘어요. OSI 7 Layer 각 계층과 특징 을 보면, 각 계층이 바로 아래 계층의 서비스를 이용해서 위 계층에 서비스를 제공하는 구조예요. 실제 인터넷은 TCP/IP 4계층 모델을 써요.

IP 주소를 효율적으로 쓰는 기법이 서브네팅(Subnetting) 과 수퍼네팅(Supernetting) 이에요. 서브네팅은 하나의 큰 네트워크를 작은 서브넷으로 쪼개는 거고, 수퍼네팅(CIDR)은 여러 작은 네트워크를 하나로 합치는 거예요. 라우팅 테이블 크기를 줄이는 데 수퍼네팅이 유용해요.

통신 이론의 기초인 정보이론과 샤논(Shannon)의 정리 도 있어요. 샤논 제1정리(소스 코딩 이론)는 정보의 최소 표현 비트 수를 엔트로피로 정의하고, 샤논 제2정리(채널 용량 정리)는 잡음이 있는 채널에서도 오류 없이 전송할 수 있는 최대 전송 속도(채널 용량)를 구하는 거예요.

ASN.1(Abstract Syntax Notation One) 은 데이터 구조를 플랫폼과 언어에 독립적으로 표현하는 표준 규격이에요. SNMP, X.509 인증서, 이동통신 프로토콜에서 많이 쓰여요. 서로 다른 시스템끼리 데이터 교환할 때 공통 언어 역할을 하는 거예요.

리버스 프록시(Reverse Proxy) 는 클라이언트의 요청을 받아서 내부 서버로 전달하는 중간 서버예요. 내부 서버의 주소를 숨길 수 있어서 보안에 좋고, 여러 서버에 요청을 분산시켜서 부하분산도 돼요. Nginx가 대표적인 리버스 프록시 소프트웨어예요.

Non-blocking I/O 는 I/O 작업이 완료될 때까지 기다리지 않고, 다른 작업을 계속 처리하다가 완료되면 콜백으로 받는 방식이에요. Node.js가 이 방식으로 싱글 스레드로도 대용량 트래픽을 처리할 수 있는 거예요. 전통적인 Blocking I/O는 I/O 완료 때까지 스레드가 멈추니까 스레드가 많이 필요해요.

프레임릴레이(Frame Relay) 는 1980~90년대에 WAN(광역 통신망)에서 많이 쓰던 패킷 교환 프로토콜이에요. ATM보다 오버헤드가 작고 구현이 단순해서 기업 WAN에 인기였는데, 지금은 IP/MPLS로 대체됐어요.

망중립성(Network Neutrality) 은 ISP(인터넷 서비스 제공자)가 모든 인터넷 트래픽을 내용, 서비스, 플랫폼에 상관없이 동등하게 처리해야 한다는 원칙이에요. 망 중립성 정책 이슈 는 4차 산업혁명 시대에도 계속 논쟁 중이에요. 망중립성 이슈(CP 망관리 비용) 는 넷플릭스, 유튜브 같은 CP(Content Provider)가 많은 트래픽을 유발하는데 망 이용료를 내야 하냐는 쟁점이에요.

이와 연결된 개념이 제로 레이팅(Zero Rating) 이에요. 특정 서비스의 데이터 사용량을 요금 계산에서 제외해주는 거예요. OTT 서비스의 제로 레이팅 문제점 은 특정 서비스를 우대하는 거라 망중립성에 위배된다는 논란이 있어요. ISP가 자기 계열사 OTT는 무제한이고 경쟁사 OTT는 데이터가 차감된다면, 그건 공정하지 않은 거잖아요.

NFC(Near Field Communication) 는 10cm 이내의 근거리에서 데이터를 주고받는 무선 통신 기술이에요. 교통카드, 모바일 결제에 쓰이죠. HCE(Host Card Emulation) 는 NFC 결제에서 물리적인 SE(Secure Element) 칩 대신 클라우드 서버에 카드 정보를 저장해서 스마트폰 앱이 신용카드처럼 동작하게 하는 기술이에요. HCE 덕분에 카드사가 SE 칩에 의존하지 않고 NFC 결제 서비스를 만들 수 있게 됐어요.

익명성을 위한 네트워크로 익명 네트워크 TOR(The Onion Routing) 가 있어요. 여러 릴레이 서버를 거치면서 각 단계마다 암호화 레이어를 벗겨내는 방식(양파 껍질처럼)으로 사용자의 신원을 숨기는 거예요. 언론인, 인권 활동가들이 검열을 우회하는 데 쓰이지만, 다크웹 같은 불법 용도로 악용되기도 해요.

모바일 FSO(Free Space Optics) 통신 은 광통신의 일종인데, 광섬유 케이블 대신 자유 공간(허공)에 레이저 빔을 쏴서 데이터를 전송해요. 케이블 없이 수 기가비트 속도의 통신이 가능하지만, 안개나 비에 취약하다는 단점이 있어요.

모바일 엣지 컴퓨팅(Mobile Edge Computing) 은 클라우드를 기지국 근처로 끌어당긴 거예요. 중앙 클라우드까지 데이터를 보내지 않고 기지국 가까이에서 처리하니까 지연이 줄어들어요. 자율주행차나 AR처럼 실시간 처리가 필요한 서비스에 필수적이에요.

해저케이블 에퀴아노(Equiano) 프로젝트 는 구글이 추진하는 대서양-아프리카를 연결하는 해저 광케이블 프로젝트예요. 아프리카의 인터넷 인프라를 확충하고, 지역 간 연결성을 높이기 위한 프로젝트예요.

IBN(Intent-Based Networking) 은 "이런 의도(Intent)로 네트워크를 운영하겠다"고 선언하면 AI와 자동화가 그에 맞게 네트워크를 설정하는 개념이에요. "보안 카메라 트래픽에 우선순위를 줘"라고 말하면 네트워크가 알아서 설정을 바꾸는 거예요. SDN을 더 지능화한 단계라고 볼 수 있어요.

DCI(Data Center Interconnect) 는 지리적으로 분산된 데이터센터들을 고속으로 연결하는 기술이에요. 재해복구(DR), 데이터 복제, 부하 분산을 위해 데이터센터 간 대용량 고속 링크가 필요한데, 그 기술이 DCI예요.

마지막으로 멀티클라우드(MultiCloud) 는 여러 클라우드 서비스(AWS, Azure, GCP 등)를 동시에 사용하는 전략이에요. 특정 벤더에 종속(Vendor Lock-in)되는 걸 피하고, 서비스별로 최적의 클라우드를 골라 쓸 수 있어요. 멀티클라우드 환경에선 네트워크 연결성, 데이터 이동, 일관된 보안 정책 적용이 핵심 기술 과제예요.

이렇게 보면 네트워크/통신은 "데이터가 어떻게 이동하는가"를 다루는 학문이에요. 프로토콜이 통신 규칙을 정의하고, 라우팅이 경로를 결정하고, 이동통신이 무선으로 연결하고, IoT가 사물까지 연결하고, SDN/NFV가 네트워크를 소프트웨어로 제어하고, QoS가 품질을 보장하고, 오류/혼잡 제어가 신뢰성을 유지해요. 기출 키워드들이 결국 이 큰 흐름 안에서 서로 연결돼 있다는 걸 기억하면, 외울 때도 훨씬 수월할 거예요.
