1. CPU/프로세서 — 컴퓨터의 두뇌, 어떻게 일하는가​

컴퓨터의 심장이라고 할 수 있는 CPU는 명령어를 하나씩 받아서 처리하는 장치예요. 근데 한 번에 하나씩 처리하면 너무 느리잖아요? 그래서 나온 개념이 CPU 파이프라인(Pipeline)이에요. 세탁기에서 세탁→헹굼→탈수가 순서대로 겹쳐서 돌아가는 것처럼, CPU도 명령어 인출→해석→실행→저장 단계를 겹쳐서 처리하는 거예요. 파이프라인과 비파이프라인의 처리 시간을 비교하면 파이프라인 방식이 처리량이 훨씬 높다는 게 핵심 포인트예요.

CPU가 빠르게 일하려면 메모리도 따라와야 해요. 그래서 등장한 게 메모리 인터리빙(Memory Interleaving)이에요. 메모리를 여러 모듈로 나눠서 CPU가 여러 모듈에 동시에 접근하도록 해서 병목을 줄이는 기법이죠. 그리고 완전히 새로운 차원의 고속 메모리가 고대역 초고속 메모리(HBM)예요. HBM은 High Bandwidth Memory의 약자로, D램 칩을 수직으로 쌓아 올려서 초고속 데이터 전송이 가능하게 한 거예요. 요즘 AI 가속기나 GPU 옆에 붙어 있는 바로 그 메모리죠.

CPU와 메모리, 그리고 주변 장치를 연결하는 새로운 규격이 CXL(Compute Express Link)이에요. 컴퓨트 익스프레스 링크라고 하는데, CPU와 GPU·메모리·스토리지를 고속으로 연결하는 개방형 인터커넥트 표준이에요. 클라우드 데이터센터에서 메모리 풀링을 가능하게 해주는 기술이기도 해요.

CPU만으로 모든 연산을 처리하기 벅찬 상황이 오면서 GPGPU(General Purpose GPU)가 주목받게 됐어요. 원래 그래픽 처리용이던 GPU를 범용 연산에 쓰는 거예요. CPU, GPGPU를 비교해보면, CPU는 직렬 처리에 최적화된 소수의 강력한 코어를 가지고 있고, GPGPU는 병렬 처리에 특화된 수천 개의 가벼운 코어를 가지고 있어요. 그래서 AI 연산처럼 같은 연산을 수천 번 반복하는 작업엔 GPGPU가 훨씬 유리하죠.

AI 시대가 되면서 GPU/TPU 비교도 시험에 자주 나와요. GPU는 범용 병렬 처리에, TPU는 구글이 만든 딥러닝 전용 가속기인데 행렬 곱셈에 극도로 특화돼 있어요. 둘 다 AI 학습용 프로세서지만 설계 철학이 달라요.

여기서 한 발 더 나간 게 뉴로모픽 칩(Neuromorphic Chip)이에요. 사람의 뇌에 있는 신경망 구조를 하드웨어적으로 모방한 프로세서예요. 기존 폰 노이만 구조와 달리 연산과 메모리가 함께 있어서 에너지 효율이 엄청나고, 이벤트 기반으로 동작해요.

CPU가 여러 작업을 처리하다 보면 갑작스럽게 처리해야 할 일이 생기기도 해요. 이럴 때 쓰는 게 인터럽트(Interrupt) 처리 우선순위예요. 하드웨어나 소프트웨어가 CPU에 "지금 급한 거 있어요!"라고 신호를 보내는 거죠. 멀티프로세스 환경에서는 어떤 인터럽트를 먼저 처리할지 우선순위를 잘 정해야 해요.

CPU 스케줄링은 여러 프로세스 중 어떤 것을 CPU에 올릴지 결정하는 거예요. CPU 스케줄링 SJF/HRN/MLQ/MLFQ가 대표적인 알고리즘들이에요. SJF(Shortest Job First)는 실행 시간이 짧은 것부터, SRT(Shortest Remaining Time)는 남은 시간이 짧은 것부터 처리해요. HRN(Highest Response Ratio Next)은 대기 시간도 반영해서 기아 현상을 줄이고, MLQ(Multi-Level Queue)는 프로세스를 여러 큐로 분류해서 처리해요. MLFQ(Multi-Level Feedback Queue)는 MLQ에 피드백을 더해서 프로세스의 CPU 사용 패턴에 따라 큐를 이동시키는 방식이죠. CPU 스케줄링 SJF/SRT를 디스크 스케줄링과 함께 비교하는 문제도 출제돼요.

스케줄링 과정에서 생기는 고질적인 문제가 우선순위 역전(Priority Inversion)이에요. 낮은 우선순위 프로세스가 자원을 쥐고 있는 동안, 그 자원이 필요한 높은 우선순위 프로세스가 기다려야 하는 상황이에요. 실시간 스케줄링(Real Time Scheduling) 환경에서 특히 위험하고, 해결 기법으로는 우선순위 상속이나 우선순위 천장 프로토콜 같은 게 있어요.

그리고 빠르게 빠질 수 없는 게 CPU 보안 취약점이에요. CPU 보안 취약점 스펙터(Spectre)는 CPU의 분기 예측 기능을 악용해서 다른 프로세스의 메모리를 몰래 읽을 수 있는 아키텍처 보안 취약점이에요. CPU 멜트다운(Meltdown)은 CPU의 비순서 실행(Out-of-Order Execution) 기능을 악용해서 커널 메모리에 접근하는 마이크로 아키텍처 취약점이고요. 두 취약점 모두 CPU의 성능 최적화 기법을 역이용한 거라서 패치하면 성능이 떨어지는 게 딜레마예요.

2. 메모리관리 — 데이터를 어디에 어떻게 넣을 것인가​

프로그램이 실행되면 메모리에 올라가는데, 메모리 안에는 딱 네 가지 영역이 있어요. 메모리영역 Code/Data/Heap/Stack이 바로 그거예요. Code 영역엔 실행할 코드(명령어)가, Data 영역엔 전역변수나 정적변수가, Heap 영역엔 동적으로 할당한 메모리가, Stack 영역엔 함수 호출 정보(지역변수, 리턴 주소)가 들어가요.

메모리를 저장할 때 바이트를 어떤 순서로 배열하느냐에 따라 빅 엔디언과 리틀 엔디언으로 나뉘어요. 빅 엔디언은 높은 주소에 낮은 자리 바이트를 저장하고(숫자를 왼쪽부터), 리틀 엔디언은 낮은 주소에 낮은 자리 바이트를 저장해요(숫자를 오른쪽부터). x86 계열은 리틀 엔디언, 네트워크 프로토콜은 빅 엔디언을 써서, 서로 통신할 때 변환이 필요해요.

메모리를 어떻게 관리하느냐의 핵심 기법이 페이징/세그멘테이션이에요. 페이징은 메모리를 고정 크기 블록(페이지)으로 나눠서 관리하는 거고, 세그멘테이션은 논리적 단위(코드, 데이터, 스택)로 나눠서 관리하는 거예요. 페이징은 내부 단편화, 세그멘테이션은 외부 단편화가 생긴다는 게 차이점이에요.

물리 메모리가 부족할 때 가상 메모리를 쓰는데, 이때 어떤 페이지를 내보낼지 결정하는 게 페이지 교체 알고리즘이에요. FIFO(가장 오래된 것 교체), OPT(앞으로 가장 오래 안 쓸 것 교체), LRU(가장 오래 전에 사용한 것 교체), LFU(가장 적게 사용한 것 교체) 등이 있어요.

페이지 교체를 너무 자주 하게 되면 스레싱(Thrashing)이 발생해요. 프로세스가 실제 작업보다 페이지 교체에 더 많은 시간을 쓰는 상황이에요. CPU 이용률은 뚝 떨어지는데 페이지 폴트는 폭발적으로 늘어나는 거죠. 예방 방법으로는 워킹 셋(Working Set) 모델이나 PFF(Page Fault Frequency) 기법을 써요. 메모리를 넉넉하게 주거나, 다중 프로그래밍 정도를 낮추는 것도 방법이에요.

CPU와 주메모리 사이의 속도 차이를 줄이기 위해 캐시 메모리(Cache Memory)가 중간에 껴 있어요. 자주 쓰는 데이터를 캐시에 넣어두면 빠르게 접근할 수 있거든요. 중요한 게 쓰기 정책인데, Write-Through는 캐시와 메모리를 동시에 쓰고, Write-Back은 캐시만 먼저 쓰고 나중에 메모리에 반영해요. 멀티코어 환경에서는 캐시 일관성 문제도 생겨요. 코어마다 캐시가 있는데 같은 메모리를 여러 코어가 읽고 쓰면 데이터가 달라질 수 있거든요.

그리고 앞서 CPU 섹션에서도 나왔지만 메모리 인터리빙(Memory Interleaving)은 메모리 접근 성능 향상 기법으로도 분류돼요. 메모리를 여러 뱅크로 나눠서 연속된 주소가 서로 다른 뱅크에 들어가도록 하면, CPU가 연속된 데이터를 읽을 때 여러 뱅크에 동시 접근할 수 있어서 빠른 거예요.

마지막으로 동적 메모리 할당이에요. 프로그램 실행 중에 필요한 만큼 힙(Heap)에서 메모리를 malloc/new로 할당받고, 다 쓰면 free/delete로 반환해야 해요. 안 반환하면 메모리 누수(Memory Leak)가 생겨서 프로그램이 점점 메모리를 잡아먹다가 결국 죽어버려요. 해결 방안으로는 스마트 포인터, 가비지 컬렉션, 정적 분석 도구 사용 등이 있어요.

3. 프로세스/스레드 — 프로그램이 살아 움직이는 방법​

실행 중인 프로그램이 프로세스예요. 프로세스 안에서 실제로 일을 하는 실행 단위가 스레드고요. 스레드/멀티스레드, 프로세스 비교를 해보면 프로세스는 독립된 메모리 공간을 갖고, 스레드는 같은 프로세스 안에서 메모리를 공유해요. 그래서 스레드 간 통신은 빠르지만 한 스레드가 잘못되면 다른 스레드도 영향을 받을 수 있어요. 멀티스레드는 하나의 프로세스 안에 여러 스레드를 두는 건데, 응답성과 자원 효율이 좋아져요.

CPU가 한 프로세스(스레드)에서 다른 프로세스(스레드)로 넘어갈 때 컨텍스트 스위칭이 발생해요. 현재 실행 중인 프로세스의 레지스터 값, 프로그램 카운터 같은 상태 정보를 PCB(Process Control Block)에 저장하고, 다음 프로세스의 상태를 복원하는 거예요. 이 과정 자체에 시간이 들어서 너무 자주 발생하면 오버헤드가 커요.

여러 프로세스가 자원을 공유하다 보면 교착상태(Deadlock)가 생길 수 있어요. 프로세스 A는 자원 1을 잡고 자원 2를 기다리고, 프로세스 B는 자원 2를 잡고 자원 1을 기다리는 상황이에요. 서로 양보 안 하고 기다리기만 하는 거죠. 교착상태는 상호 배제, 점유와 대기, 비선점, 순환 대기 네 가지 조건이 모두 성립할 때 발생해요.

교착상태를 회피하는 유명한 알고리즘이 교착상태, 은행가 알고리즘이에요. 은행가 알고리즘(Banker's Algorithm)은 은행이 대출을 해줄 때 나중에도 모든 고객에게 돌려줄 수 있을지 계산하는 것처럼, 자원을 할당하기 전에 "이거 줘도 안전 상태(Safe State)가 유지되나?"를 먼저 확인하는 거예요. 안전하면 주고, 안전하지 않으면 잠시 기다리게 해요.

여러 스레드가 같은 자원에 동시 접근할 때는 동기화가 필요해요. 세마포어(Semaphore)와 모니터(Monitor)가 대표적인 동기화 기법이에요. 세마포어는 카운터 변수로 자원 접근을 제어하는데, 이진 세마포어(뮤텍스)와 카운팅 세마포어로 나뉘어요. 모니터는 Java 같은 언어에서 지원하는 고수준 동기화 구조체로, 한 번에 한 스레드만 모니터 안에 들어갈 수 있어요. 세마포어가 저수준이라 잘못 쓰면 버그가 생기기 쉬운 반면, 모니터는 언어 차원에서 지원하니 더 안전해요.

스핀 락(Read/Write Spin Lock)은 또 다른 동기화 방식이에요. 락이 풀릴 때까지 CPU를 계속 쓰면서 루프를 돌며 기다리는 거예요. 대기 시간이 짧을 때는 컨텍스트 스위칭 비용을 아낄 수 있어서 효율적이지만, 오래 기다려야 하면 CPU를 낭비하는 단점이 있어요. Read/Write Spin Lock은 읽기는 여럿이 동시에, 쓰기는 독점으로 허용하는 더 세밀한 락이에요.

여러 스레드가 공유 자원에 동시 접근할 때 실행 순서에 따라 결과가 달라지는 걸 경쟁조건(Race Condition)이라고 해요. 예를 들어 두 스레드가 같은 변수를 동시에 읽고 증가시키면, 둘 다 같은 값을 읽고 하나씩 더해서 실제론 2가 증가해야 하는데 1만 증가하는 식이에요.

경쟁조건과 연관된 보안 취약점이 TOCTOU(검사시점과 사용시점)예요. 파일 권한을 확인하는 시점(Time Of Check)과 실제로 파일을 사용하는 시점(Time Of Use) 사이에 공격자가 파일을 바꿔치기하는 거예요. 권한 확인 후 실제 사용 전 사이의 타이밍을 노리는 거죠.

프로세스 간에 데이터를 주고받는 방법을 IPC(Inter Process Communication)라고 해요. 주요 기법으로는 공유 메모리(빠르지만 동기화 필요), 메시지 패싱(안전하지만 느림), 파이프(단방향 데이터 스트림)가 있어요. 공유 메모리는 속도가 빠른 대신 동기화 기법(세마포어, 뮤텍스)을 따로 써야 해요.

4. 파일시스템/스토리지 — 데이터를 영구적으로 보관하는 방법​

운영체제의 기본기 중 하나가 파일시스템이에요. Unix 파일시스템, /etc/passwd부터 시작하면, Unix/Linux는 모든 것이 파일이에요. 디바이스도 파일이고, 프로세스 정보도 파일이에요. /etc/passwd는 사용자 계정 정보를 담은 파일인데, 예전엔 여기 비밀번호 해시가 있었지만 지금은 /etc/shadow로 분리돼 있어요.

보안 포렌식 관점에서 중요한 게 파일 슬랙(File Slack)이에요. 파일은 클러스터 단위로 저장되는데, 파일 크기가 클러스터 크기를 딱 맞아 떨어지지 않으면 남는 공간이 생겨요. 이 공간이 슬랙이에요. RAM Slack은 파일의 마지막 섹터에서 남은 부분으로, 메모리에 있던 이전 데이터가 남아있을 수 있고, Disk Slack은 파일이 차지하는 마지막 클러스터에서 사용되지 않는 나머지 섹터예요. 이 슬랙 공간에 지워진 데이터 흔적이 남을 수 있어서 디지털 포렌식에서 중요해요.

여러 디스크를 묶어서 쓰는 방법이 RAID 0, 1, 5, 6이에요. RAID 0은 스트라이핑으로 성능 최대화, 하지만 하나만 고장 나도 전부 날아가요. RAID 1은 미러링으로 같은 데이터를 두 군데 써서 신뢰성을 높이지만 용량이 반으로 줄어요. RAID 5는 분산 패리티를 써서 디스크 하나가 고장 나도 복구 가능하고, 용량 낭비도 적어요. RAID 6은 패리티를 두 개 써서 디스크 두 개가 동시에 고장 나도 버텨요.

스토리지를 연결하는 방법도 다양해요. DAS/NAS/SAN이 그 세 가지예요. DAS(Direct Attached Storage)는 서버에 직접 붙이는 방식이고, NAS(Network Attached Storage)는 네트워크에 연결된 파일 서버 방식이에요. SAN(Storage Area Network)은 별도의 고속 스토리지 전용 네트워크를 구성하는 방식으로, 고성능 엔터프라이즈 환경에서 쓰여요.

데이터를 다루는 방식에 따라 스토리지를 분류하면 블록/파일/오브젝트 스토리지로 나눌 수 있어요. 블록 스토리지는 데이터를 고정 크기 블록으로 나눠 저장하고 RAID나 SAN에서 쓰며, 파일 스토리지는 계층적 디렉토리 구조로 파일을 관리하는 NAS 방식이에요. 오브젝트 스토리지는 데이터를 객체 단위로 저장하고 메타데이터와 함께 flat namespace로 관리하는데, AWS S3 같은 클라우드 스토리지가 대표적이에요.

스토리지 가상화는 여러 개의 물리 스토리지를 마치 하나인 것처럼 논리적으로 추상화하는 거예요. 호스트 기반, 네트워크 기반, 스토리지 기반 가상화로 유형이 나뉘어요. 관리가 편해지고 스토리지 활용률이 올라가는 게 장점이에요.

5. 기타OS — 운영체제와 시스템 이론의 나머지 조각들​

UNIX 운영체제 부팅과정을 살펴보면, 전원이 켜지면 ROM에 있는 BIOS/UEFI가 하드웨어를 점검(POST)하고, 부트로더(GRUB 같은 것)를 실행해요. 부트로더가 커널을 메모리에 올리고, 커널이 시스템을 초기화한 뒤 init 프로세스(PID 1)를 실행해요. init이 각종 데몬과 서비스를 띄우면서 최종적으로 로그인 프롬프트가 나타나는 거죠.

메모리 접근 위반 오류가 세그먼테이션 오류(Segmentation Fault)예요. 프로세스가 접근해서는 안 되는 메모리 영역에 접근하려 할 때 운영체제가 막으면서 발생해요. null 포인터 역참조, 배열 범위 초과 접근, 해제된 메모리 접근 같은 상황에서 많이 일어나요. 이게 앞에서 배운 Code/Data/Heap/Stack 영역과 연결되는데, 정해진 영역을 벗어나면 바로 이 오류가 나는 거예요.

가상화 프로그램 동작방식은 일반 OS와 어떻게 다를까요? 일반 OS는 하드웨어 위에 바로 올라가지만, 응용프로그램 가상화는 OS 위에 하이퍼바이저나 컨테이너 레이어가 추가돼요. 완전 가상화는 게스트 OS가 하드웨어인 줄 알고 돌아가는 방식이고, 반가상화는 게스트 OS가 가상화된 걸 알고 협력하는 방식이에요. 컨테이너(Docker)는 OS 커널을 공유하면서 프로세스 격리만 하는 가벼운 방식이고요.

이론적인 개념으로 유한 오토마타(유한 상태 기계, FSM)가 있어요. 유한한 개수의 상태를 가지고, 입력에 따라 상태가 전이되는 수학적 모델이에요. 운영체제의 프로세스 상태 전이(생성→준비→실행→대기→종료), 네트워크 프로토콜의 상태 머신, 컴파일러의 렉서(어휘 분석기) 등에서 핵심 개념으로 쓰여요.

정규식, 유한오토마타는 서로 깊이 연결돼 있어요. 정규식(Regular Expression)은 문자열의 패턴을 표현하는 형식이고, 유한 오토마타는 그 패턴을 인식하는 기계예요. 실제로 모든 정규식은 동등한 NFA(비결정적 유한 오토마타)로 변환할 수 있고, NFA는 DFA(결정적 유한 오토마타)로 변환할 수 있어요. 정규식 엔진이 내부적으로 이 원리를 써요.

이렇게 보면 컴퓨터구조와 운영체제는 결국 "하드웨어를 어떻게 효율적으로 활용하고, 여러 프로그램이 안전하게 공존하게 하며, 데이터를 어떻게 저장·관리할 것인가"를 다루는 분야예요. CPU가 빠르게 일하고, 메모리를 효율적으로 쓰고, 프로세스들이 사이좋게 자원을 나눠 쓰고, 데이터를 안전하게 저장하는 이 흐름이 전부 연결돼 있다는 걸 기억하면 공부할 때 훨씬 수월할 거예요.
