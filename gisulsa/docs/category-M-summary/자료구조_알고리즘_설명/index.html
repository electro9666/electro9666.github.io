11. 자료구조/알고리즘, 키워드로 쭉 훑어보기

1. 선형자료구조 — 줄 세워서 데이터를 담는 방법​

자료구조를 처음 배울 때 가장 먼저 마주치는 개념이 선형 자료구조와 비선형 자료구조 비교예요. 선형/비선형 구조 개념 및 유형을 통틀어 정리하면, 선형은 데이터가 일직선으로 연결된 구조고 비선형은 계층이나 그물처럼 연결된 구조예요. 둘의 차이를 이해하면 "어떤 상황에 어떤 자료구조를 쓰면 되지?"라는 질문에 바로 답할 수 있어요.

선형자료구조 중에서 가장 유연한 건 다중연결리스트(Multi-linked List)예요. 일반 연결리스트는 다음 노드 포인터가 하나지만, 다중연결리스트는 포인터가 여러 개라서 한 노드에서 여러 방향으로 이동할 수 있어요. 행렬을 희소하게 표현하거나 다차원 데이터를 다룰 때 유용하죠.

스택, 큐, 리스트 입출력 원리는 선형자료구조의 핵심이에요. 먼저 스택(Stack) 작동 알고리즘을 보면, 스택은 LIFO(Last In First Out) 구조예요. 데이터를 집어넣는 게 Push, 꺼내는 게 Pop이죠. 접시를 쌓았다가 위에서부터 꺼내는 것처럼, 가장 나중에 넣은 게 가장 먼저 나와요. 함수 호출 스택, 괄호 짝 검사, 뒤로 가기 기능 같은 것들이 다 스택으로 구현돼요.

큐(Queue)는 FIFO(First In First Out)로 먼저 넣은 게 먼저 나와요. 그런데 배열로 큐를 구현하면 문제가 생겨요. 배열 기반 큐(Queue) 단점/해결을 보면, 앞에서 데이터를 꺼낼 때마다 남은 원소들을 한 칸씩 앞으로 당겨야 하거나(O(n) 비용), 아니면 rear 포인터가 배열 끝까지 가면 앞에 빈 공간이 생겨도 더 이상 못 넣는 문제가 발생해요. 이 문제의 해결책이 원형 큐(Circular Queue)예요. 배열을 원형으로 연결해서 rear가 끝에 닿으면 다시 앞으로 돌아오게 하는 거죠.

큐의 발전형이 우선순위 큐(Priority Queue)예요. 단순히 먼저 들어온 게 먼저 나가는 게 아니라, 우선순위가 높은 데이터가 먼저 나와요. CPU 스케줄링, 응급실 환자 처리, 다익스트라 알고리즘 같은 데서 필수적으로 쓰여요.

우선순위 큐를 효율적으로 구현하는 자료구조가 바로 Heap (Max-heap, Min-heap)이에요. 힙은 완전 이진 트리 기반으로, Max-heap은 부모 노드가 항상 자식 노드보다 크거나 같고, Min-heap은 부모 노드가 항상 자식 노드보다 작거나 같아요. 힙에서 최댓값이나 최솟값을 꺼내는 연산이 O(log n)이라서 우선순위 큐 구현에 딱 맞아요. 힙 자체가 정렬 알고리즘(힙 정렬)으로도 쓰이고, 뒤에 나올 트리 기반 자료구조와도 연결되는 개념이에요.

2. 비선형자료구조 — 계층과 관계를 표현하는 방법​

선형/비선형 구조 개념 및 유형에서 비선형 쪽을 보면, 트리와 그래프가 대표적이에요. 트리는 계층 구조를, 그래프는 임의의 관계망을 표현해요.

트리 중에서 가장 많이 쓰이는 게 이진 탐색 트리예요. 이진 탐색 트리(BST, Binary Search Tree)는 각 노드의 왼쪽 자식은 자신보다 작고, 오른쪽 자식은 자신보다 크다는 규칙을 지켜요. 이 규칙 덕분에 탐색, 삽입, 삭제가 모두 평균 O(log n)에 돼요. 단, 한쪽으로 쏠린 편향 트리가 되면 최악의 경우 O(n)이 돼서 균형 잡힌 트리(AVL 트리, 레드-블랙 트리)가 필요해지죠. 이진 탐색 트리는 뒤에 나올 트리정렬(Tree Sort)의 기반이 되기도 해요.

그래프로 넘어가면 DAG(Directed Acyclic Graph), 위상정렬이 핵심 키워드예요. DAG는 방향이 있고(Directed) 사이클이 없는(Acyclic) 그래프예요. 작업 의존 관계, 과목 선수 관계, 빌드 의존성 같은 것들을 표현할 때 딱 맞아요. DAG에서 "이걸 먼저 하고 저걸 해야 해"라는 순서를 뽑아내는 게 위상정렬(Topology Sort)이에요. 위상정렬은 DAG에서만 적용 가능하고, 사이클이 있으면 순서를 정할 수가 없어요. 예를 들어 빌드 시스템에서 의존 모듈을 올바른 순서로 컴파일하거나, 수업 커리큘럼에서 선수과목 순서를 정할 때 쓰죠.

3. 정렬알고리즘 — 데이터를 순서대로 줄 세우는 방법​

정렬알고리즘은 자료구조 중에서 가장 직관적인 주제예요. 버블정렬, 삽입정렬, 퀵정렬 세 가지를 비교해서 이해하면 절반은 먹고 들어가는 거예요.

버블정렬은 인접한 두 원소를 계속 비교·교환하면서 큰 값을 오른쪽으로 "거품처럼" 밀어내는 방식이에요. 구현은 단순하지만 시간복잡도가 O(n²)이라 느려요. 삽입정렬은 새로운 원소를 이미 정렬된 부분에 올바른 위치에 끼워 넣는 방식이에요. 작은 배열이나 거의 정렬된 데이터에서는 의외로 빠르게 동작해요. 퀵정렬은 피벗(pivot)을 기준으로 데이터를 두 그룹으로 나눠서 재귀적으로 정렬해요. 평균 O(n log n)으로 실제로 가장 빠른 정렬 중 하나예요. 다만 최악의 경우(이미 정렬된 데이터에서 나쁜 피벗 선택) O(n²)이 될 수 있어요.

트리정렬(Tree Sort)은 트리를 활용한 정렬 방식이에요. 데이터를 이진 탐색 트리에 하나씩 삽입한 다음 중위 순회(in-order traversal)를 하면 정렬된 결과가 나와요. 앞서 배운 이진 탐색 트리와 정렬이 만나는 지점이에요. 평균 O(n log n)이지만 편향 트리가 되면 O(n²)이 되는 단점이 있어요.

4. 탐색/그래프알고리즘 — 최적의 길을 찾는 방법​

그래프에서 뭔가를 찾거나 최적 경로를 구하는 알고리즘들을 묶어서 볼게요.

그래프에서 모든 노드를 연결하는 최소 비용의 트리를 MST(Minimum Spanning Tree, 최소신장트리)라고 해요. MST 크루스칼/프림 알고리즘 두 가지가 대표적이에요. **크루스칼(Kruskal)**은 간선 비용을 오름차순으로 정렬해서 사이클이 생기지 않도록 하나씩 추가해요. **프림(Prim)**은 시작 노드에서 출발해서 연결 가능한 가장 싼 간선을 하나씩 추가하는 방식이에요. 통신망 설계나 전기 배선 최적화에 쓰여요.

MST가 "모든 곳을 연결하는 최소 비용"이라면, 최단경로 알고리즘 4가지는 "특정 지점에서 특정 지점까지의 최소 비용 경로"예요. 4가지는 각각 상황에 따라 써요:

  • 다익스트라(Dijkstra): 단일 출발점, 가중치가 양수일 때 최적
  • 벨만-포드(Bellman-Ford): 음수 가중치가 있어도 처리 가능, 음수 사이클 감지도 됨
  • 플로이드-워셜(Floyd-Warshall): 모든 쌍의 최단 경로를 한 번에 구함
  • A*(에이스타): 휴리스틱을 써서 목표 방향으로 빠르게 탐색

여기서 균일비용탐색, A* 알고리즘 비교가 나와요. 균일비용탐색(Uniform Cost Search)은 지금까지의 누적 비용만 보고 탐색하는 반면, A* 알고리즘은 누적 비용 g(n)에 목표까지의 추정 비용 h(n)을 더한 f(n) = g(n) + h(n)으로 탐색해요. 휴리스틱 함수가 좋으면 A*가 훨씬 빠르게 최적해를 찾을 수 있어요. 게임 AI의 경로 탐색이나 내비게이션이 대표적인 응용이에요.

앞 섹션에서 나왔던 위상정렬(Topology Sort)도 그래프 알고리즘이에요. DAG에서 진입 차수(in-degree)가 0인 노드를 순서대로 꺼내는 방식(Kahn's 알고리즘)이나 DFS 기반으로 구현해요. 빌드 시스템, 스프레드시트 수식 계산, 패키지 의존성 해결 같은 곳에 실제로 쓰여요.

AI 탐색 알고리즘 쪽으로 가면 MCTS(Monte Carlo Tree Search)가 있어요. 몬테카를로 트리 탐색은 무작위 시뮬레이션(몬테카를로 샘플링)을 트리 탐색에 결합한 방법이에요. 선택(Selection) → 확장(Expansion) → 시뮬레이션(Simulation) → 역전파(Backpropagation) 네 단계를 반복하면서 유망한 수를 찾아요. 바둑 AI인 AlphaGo가 MCTS를 핵심으로 쓰면서 유명해졌어요. 탐색 공간이 너무 커서 완전 탐색이 불가능할 때 특히 효과적이에요.

진화적 탐색 알고리즘으로는 유전 알고리즘(Genetic Algorithm)이 있어요. 생물의 진화 원리를 모방한 최적화 알고리즘이에요. 개체군(Population) 안에서 선택(Selection) → 교배(Crossover) → 돌연변이(Mutation) 과정을 반복하면서 최적해에 가까워져요. 부모 개체를 선택할 때 적합도에 비례해서 선택 확률을 주는 방식이 **룰렛 휠 선택(Roulette Wheel Selection)**이에요. 파이 조각처럼 각 개체의 적합도 비율대로 원을 나눠서 무작위로 돌려 선택하는 거죠. 유전 알고리즘은 여행하는 세일즈맨 문제(TSP), 스케줄 최적화, 신경망 하이퍼파라미터 튜닝 같은 복잡한 최적화 문제에 쓰여요.

5. 해싱 — 데이터를 빠르게 찾는 방법​

해쉬 알고리즘(Hash Algorithm)은 임의 길이의 입력 데이터를 고정 길이의 출력값으로 변환하는 알고리즘이에요. 해시값/해시함수 구분, 종류, 용도를 정리하면, 해시함수는 변환을 수행하는 함수이고 해시값은 그 결과물이에요. 해쉬 알고리즘 특성 및 종류를 보면 SHA-256, MD5, SHA-3 같은 것들이 있고, 자료구조 용도(해시 테이블)와 보안 용도(비밀번호 저장, 무결성 검증)로 나뉘어요.

해싱의 핵심 특성은 입력이 조금만 바뀌어도 출력값이 완전히 달라진다(눈사태 효과)는 거예요. 그리고 해시값에서 원래 입력을 역으로 계산하기 극히 어렵다는 것도 중요한 특성이에요.

단방향 해시 함수는 바로 이 역방향 계산 불가능성을 활용해요. 비밀번호를 DB에 저장할 때 평문 대신 해시값을 저장해두면, DB가 유출돼도 원래 비밀번호를 알 수 없어요. 그런데 단방향 해시만으로는 문제가 있어요. 자주 쓰는 비밀번호의 해시값을 미리 계산해서 모아둔 Rainbow Table을 이용하면 역조회가 가능하거든요. 이걸 막는 게 Salt예요. 비밀번호에 무작위 문자열(Salt)을 붙여서 해시를 만들면, 같은 비밀번호도 사람마다 해시값이 달라져서 Rainbow Table이 무용지물이 돼요. 한 걸음 더 나아가서 해시 연산을 수천 번 반복하는 Key Stretching을 쓰면 무차별 대입 공격의 속도를 확 늦출 수 있어요.

데이터베이스에서 해싱을 쓸 때 확장성 해싱(Extendible Hashing)이 중요해요. 데이터가 늘어날 때 해시 테이블 크기를 동적으로 늘릴 수 있는 기법이에요. 글로벌 깊이(Global Depth)와 로컬 깊이(Local Depth)를 관리하면서 버킷을 분할하는 방식으로 충돌을 회피해요. 테이블 전체를 재구성하지 않아도 되기 때문에 동적으로 변하는 대용량 데이터를 처리하는 DB에서 유용하게 써요.

6. 복잡도 — 알고리즘의 효율을 측정하는 방법​

지금까지 여러 자료구조와 알고리즘을 살펴봤는데, 이들의 효율을 비교하는 언어가 O-Notation, 알고리즘 복잡도예요.

**O-Notation(빅-오 표기법)**은 입력 크기 n이 커질 때 알고리즘의 실행 시간이나 메모리 사용량이 어떤 비율로 늘어나는지를 나타내요. 최악의 경우를 기준으로 상한(Upper Bound)을 표현하죠. 유형별로 연산시간을 보면:

  • O(1): 상수 시간 — 배열 인덱스 접근, 해시 테이블 검색(충돌 없을 때)
  • O(log n): 로그 시간 — 이진 탐색, 힙 삽입/삭제, 이진 탐색 트리 탐색(균형 잡힌 경우)
  • O(n): 선형 시간 — 배열 순차 탐색, 연결 리스트 순회
  • O(n log n): 선형로그 시간 — 퀵정렬(평균), 트리정렬, 힙 정렬, 병합 정렬
  • O(n²): 이차 시간 — 버블정렬, 삽입정렬, 퀵정렬(최악), 트리정렬(편향)
  • O(2ⁿ): 지수 시간 — 완전 탐색 (MCTS나 유전 알고리즘으로 해결하려는 문제들이 여기에 해당)

앞에서 배운 알고리즘들을 복잡도로 다시 정리하면, 이진 탐색 트리의 O(log n) 탐색, 힙 기반 우선순위 큐의 O(log n) 삽입/삭제, 해시 테이블의 O(1) 접근, MST 알고리즘의 O(E log E)(크루스칼) 같은 수치가 왜 나오는지 자연스럽게 이해가 돼요. 복잡도를 모르면 자료구조를 선택할 때 "그냥 아는 거 쓰면 되지 뭐"가 되는데, 알면 "이 상황에서는 이게 최선"이라는 근거를 가질 수 있어요.

이렇게 보면 자료구조와 알고리즘은 따로따로가 아니에요. 선형자료구조(스택, 큐, 리스트, 힙)가 비선형자료구조(트리, 그래프)의 탐색과 정렬 알고리즘의 기반이 되고, 해시는 O(1) 접근이라는 강력한 복잡도로 모든 영역에서 쓰이고, 복잡도는 이 모든 선택의 언어가 되는 거죠. 기출 키워드들이 이 큰 흐름 안에 있다는 걸 기억하면 개별 키워드도 훨씬 오래 기억에 남을 거예요.
