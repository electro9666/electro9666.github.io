09. 블록체인, 키워드로 쭉 훑어보기

1. 블록체인기본 — 블록체인이 뭐고 어떻게 동작하나요​

자, 먼저 블록체인 개념/작동원리부터 이야기해볼게요. 블록체인이란 데이터를 "블록"이라는 단위로 묶고, 그 블록들을 체인처럼 연결해서 저장하는 구조예요. 핵심은 이 블록 장부를 한 곳에 보관하는 게 아니라 여러 참여자가 나눠서 갖고 있다는 거예요. 이걸 분산원장기술(DLT, Distributed Ledger Technology)이라고 하는데, 중앙 서버 없이 수천 개의 노드가 동일한 장부를 유지하는 방식이에요. 어느 한 곳에서 데이터를 조작하려 해도 나머지 노드들이 다 다르다고 하면 무효가 되는 거죠.

이걸 처음으로 실용화한 게 비트코인이고, 그 다음에 등장한 게 이더리움이에요. 이더리움은 단순한 송금 기록 이상을 할 수 있게 만든 플랫폼이에요. "스마트 컨트랙트"라는 코드를 블록체인 위에 올릴 수 있어서 오픈플랫폼으로 불리죠. 나중에 나올 솔리디티나 DApp 같은 개념들이 전부 이더리움 위에서 돌아가는 거예요.

그런데 블록체인은 유형이 여러 개예요. 누구나 참여할 수 있는 퍼블릭/프라이빗 블록체인 비교가 시험에서 정말 자주 나와요. 블록체인 Public/Private 운영방식을 정리하면, 퍼블릭은 비트코인·이더리움처럼 누구나 노드가 될 수 있고 완전히 탈중앙화되어 있어요. 반면 프라이빗은 허가받은 기관만 참여할 수 있는 폐쇄형이에요. 여기에 두 방식의 장점을 섞은 퍼블릭/프라이빗/하이브리드 블록체인도 있어요. 예를 들어 기업 내부는 프라이빗으로, 외부 검증은 퍼블릭 체인에 연결하는 방식이죠.

그럼 노드들이 "이 블록이 올바르다"고 어떻게 합의하냐? 그게 바로 합의 알고리즘(Consensus Algorithm)이에요. 합의 알고리즘은 분산된 참여자들이 중앙 관리자 없이 동일한 결론에 도달하게 만드는 규칙이에요. 대표적으로 비트코인의 PoW(작업증명), 이더리움의 PoS(지분증명), 하이퍼레저의 PBFT 같은 것들이 있는데, 각각 속도·보안·에너지 효율 면에서 트레이드오프가 달라요.

블록체인을 다른 저장 기술과 비교한 파일/데이터베이스/블록체인 비교도 중요해요. 파일은 단순 저장, 데이터베이스는 중앙 집중 관리, 블록체인은 분산·불변 저장이라는 점이 핵심 차이예요. 특히 "한 번 기록하면 수정이 거의 불가능하다"는 불변성(Immutability)이 블록체인의 가장 큰 특징이죠.

요즘 자주 보이는 웹3.0 개념도 블록체인이 핵심이에요. 웹1.0은 읽기만, 웹2.0은 읽기/쓰기(구글·페이스북 같은 플랫폼 중심), 웹3.0은 읽기/쓰기/소유까지 가능한 탈중앙화 인터넷이에요. 블록체인·NFT·DID·DeFi 같은 기술들이 모두 웹3.0을 이루는 기술 요소예요.

여기서 당연히 보안 이야기도 나오겠죠. 금융권 블록체인 정보보안 이슈를 보면, 은행이나 증권사에서 블록체인을 도입할 때 스마트 컨트랙트 취약점, 개인키 분실, 51% 공격 같은 보안 이슈가 생길 수 있어요. 그래서 블록체인 보안 고려사항으로 기업 도입 시 암호화 알고리즘 선택, 접근 통제, 키 관리 정책을 잘 설계해야 하고, 블록체인 플랫폼 성능/보안 고려사항에는 TPS(초당 거래 처리량), 합의 속도, 네트워크 분리 같은 요소들이 포함돼요.

2. 스마트컨트랙트 — 코드로 계약을 자동 실행한다고요​

스마트 컨트랙트는 계약 조건을 코드로 작성해서 블록체인 위에 올려두면, 조건이 충족됐을 때 자동으로 실행되는 프로그램이에요. 예를 들어 "A가 1 ETH를 보내면 B에게 NFT 소유권이 이전된다"는 조건을 코드로 쓰면, 중간 관리자 없이 자동으로 처리되는 거죠.

이 스마트 컨트랙트를 작성할 때 쓰는 언어가 솔리디티/EVM/DApp 묶음으로 이해하면 돼요. 솔리디티는 이더리움 스마트 컨트랙트를 작성하는 프로그래밍 언어예요. 그 코드가 실행되는 가상 머신이 EVM(Ethereum Virtual Machine)이에요. 블록체인 네트워크의 모든 노드가 동일한 EVM 환경에서 코드를 실행하기 때문에 실행 결과가 항상 일치해요. 그리고 이 스마트 컨트랙트를 활용해서 만드는 탈중앙화 애플리케이션이 DApp(Decentralized Application)이에요. 기존 앱과 달리 백엔드 서버가 블록체인이 되는 구조죠.

근데 스마트 컨트랙트에는 치명적인 문제가 있어요. 한 번 배포되면 수정이 거의 불가능하다는 거예요. 코드에 버그가 있으면 그대로 굳어버리죠. 실제로 2016년 이더리움의 The DAO 해킹 사건처럼 스마트 컨트랙트 취약점으로 수백억 원이 탈취된 사례도 있어요. 그래서 배포 전에 철저하게 검토하는 Smart Contract Audit(스마트 컨트랙트 보안 감사)이 필수예요. 외부 보안 전문가들이 코드를 꼼꼼히 분석해서 재진입 공격(Reentrancy), 정수 오버플로우, 접근 권한 오류 같은 취약점을 잡아내는 거예요. 비용이 꽤 들지만, 해킹당하는 것보다는 훨씬 싸죠.

3. 암호화폐/토큰 — 블록체인 위에서 돈이 움직이는 방식​

비트코인에서 새 코인은 어떻게 만들어질까요? 바로 마이닝(Mining), 즉 채굴을 통해서예요. 채굴은 복잡한 수학 문제를 가장 먼저 푸는 노드가 새 블록을 생성하고 보상으로 비트코인을 받는 과정이에요. 이게 앞서 말한 합의 알고리즘 중 PoW(작업증명, Proof of Work)예요. 엄청난 연산 자원을 소모하기 때문에 에너지 낭비 문제가 있어서, 이더리움은 결국 PoS로 전환했어요.

비트코인에서 거래 유효성을 검사하는 핵심 개념이 UTXO(Unspent Transaction Output)예요. 우리가 은행 잔액을 생각할 때는 "계좌에 100만 원 있다"고 보지만, 비트코인은 다르게 봐요. "이전 거래에서 나한테 온 50만 원짜리 출력 2개가 아직 안 쓰였다"고 보는 거예요. 이 미사용 거래 출력(UTXO)들을 조합해서 새 거래를 만들고, 사용한 UTXO는 소멸하고 새 UTXO가 생기는 방식이에요. 이중지불(double spending)을 방지하는 우아한 구조죠.

블록 안에 담긴 수천 건의 거래 데이터 무결성을 어떻게 효율적으로 검증할까요? 여기서 머클트리(Merkle Tree)가 등장해요. 거래 데이터를 해시로 변환하고, 두 개씩 짝지어 다시 해시를 만들고, 이걸 반복해서 맨 꼭대기의 "머클루트" 하나를 만들어요. 블록 헤더에 이 머클루트만 저장해두면, 특정 거래가 블록에 포함됐는지 전체를 다운로드하지 않고 로그 시간에 검증할 수 있어요. 경량 클라이언트(SPV)가 이 방식으로 작동하죠.

토큰 얘기로 넘어가면, NFT(Non-Fungible Token)은 대체불가능 토큰이에요. 비트코인은 내 1 BTC와 당신의 1 BTC가 완전히 동등하게 교환 가능한 "대체가능" 토큰이죠. 반면 NFT는 각 토큰이 고유한 ID를 가지고 있어서 서로 교환되지 않아요. 디지털 아트, 게임 아이템, 음악 저작권 같은 것들의 소유권을 블록체인 위에 기록하는 데 쓰이죠.

근데 NFT에도 보안 문제가 있어요. NFT 마켓플레이스 보안 취약점인데, OpenSea 같은 NFT 거래소에서 발생한 보안 침해 사례가 기출에 나왔어요. 스마트 컨트랙트 취약점, 피싱 공격, 메타데이터 변조, 서명 검증 우회 같은 공격이 있고, 특히 "무료 NFT를 받으세요" 같은 피싱 서명으로 지갑을 통째로 털리는 사례도 있어요.

탈중앙화 금융 서비스를 통칭하는 개념이 디파이(De-fi)예요. DeFi는 Decentralized Finance의 약자인데, 은행 같은 중개기관 없이 스마트 컨트랙트로 대출·예금·이자·거래소 기능을 구현한 거예요. Uniswap(탈중앙화 거래소), Aave(탈중앙화 대출), Compound(이자 농사) 같은 서비스들이 대표적이에요. 기존 금융보다 접근성은 높지만, 스마트 컨트랙트 해킹이나 가격 조작 리스크가 있어요.

4. 블록체인응용 — 실제 세계에서 블록체인을 어떻게 쓰나요​

퍼블릭 블록체인은 누구나 참여할 수 있어서 기업 입장에서는 쓰기 불편할 때가 많아요. 거래 내용이 다 공개되고, 속도도 느리고, 비용도 들죠. 그래서 기업용으로 만들어진 게 하이퍼레저(Hyperledger)예요. Linux Foundation 주도로 만든 오픈소스 기업용 블록체인 프레임워크인데, 대표적으로 Hyperledger Fabric이 있어요. 허가된 참여자만 접근하고, 합의 알고리즘도 빠른 PBFT 계열을 쓰고, 거래 내용도 채널 단위로 격리할 수 있어서 금융·물류·의료 분야에서 많이 써요.

이제 블록체인으로 신원을 관리하는 이야기로 가볼게요. 기존 인터넷에서 신원 확인은 다 중앙 기관에 의존해요. 네이버 로그인, 카카오 로그인, 공인인증서 같은 것들이죠. 이 중앙 기관이 털리면 내 신원 정보도 다 털려요. 이걸 바꾸려는 게 DID(Decentralized Identity)예요. 분산 ID(Decentralized Identity)라고도 하는데, 개인이 자신의 신원 정보를 직접 소유·통제하고, 블록체인에 DID 문서를 등록해서 제3자 없이 신원을 증명할 수 있어요. W3C에서 표준을 만들고 있고, 국내에서도 PASS·이니셜 같은 서비스가 DID 기반이에요.

이 DID를 활용해서 시스템에 로그인하는 게 블록체인 방식 인증이에요. 공개키 암호화를 기반으로, 내가 개인키로 서명하면 상대방이 블록체인에 등록된 공개키로 검증해요. 아이디/비밀번호가 필요 없고, 중앙 인증 서버도 필요 없는 거죠. 피싱이나 비밀번호 탈취 공격에 강해요.

블록체인 노드들이 서로 데이터를 주고받을 때는 P2P 통신 하이브리드/퓨어 방식을 써요. 퓨어 P2P(Pure P2P)는 모든 노드가 완전히 대등하게 직접 연결하는 방식이에요. 비트코인이 이에 가까운데, 중앙 서버가 없어서 완전한 탈중앙화지만 노드를 발견하고 연결하는 데 시간이 걸려요. 하이브리드 P2P는 노드 발견이나 라우팅 일부에 중앙 서버를 활용하는 방식이에요. 카카오톡처럼 서버가 연결을 도와주되, 실제 통신은 P2P로 하는 거예요. 블록체인에서는 완전한 탈중앙화를 위해 퓨어 P2P를 지향하지만, 현실적으로는 일부 하이브리드 요소를 활용하기도 해요.

마지막으로 블록체인 플랫폼 보안위협/대응을 정리해볼게요. 블록체인을 쓴다고 해서 무조건 안전한 건 아니에요. 대표적인 보안 위협으로는, 전체 해시파워의 51% 이상을 한 주체가 장악하는 51% 공격이 있어요. 이게 성공하면 거래 순서를 조작하거나 이중지불을 할 수 있죠. 또 이클립스 공격(특정 노드를 네트워크에서 고립시키는 것), 스마트 컨트랙트 취약점 악용, 지갑 해킹, 피싱 등이 있어요. 대응 방안으로는 해시파워 분산, 코드 감사, 다중서명(Multi-sig) 지갑, 하드웨어 지갑 사용, 거버넌스 강화 같은 것들이 있어요.

이렇게 보면 블록체인은 "신뢰할 수 있는 중간 기관 없이 어떻게 거래와 합의를 할 수 있을까"라는 질문에 대한 기술적 답변이에요. 분산원장기술로 장부를 나눠 갖고, 합의 알고리즘으로 동의를 이끌어내고, 머클트리와 UTXO로 무결성을 보장하고, 스마트 컨트랙트로 자동 실행을 가능하게 하고, DID와 블록체인 방식 인증으로 신원을 탈중앙화해요. 이더리움이 만든 플랫폼 위에 DeFi와 NFT라는 새로운 경제 시스템이 올라가고, 기업 현장에서는 하이퍼레저가 실용적인 해법을 제공하는 거예요. 이 흐름을 기억하면 키워드들이 서로 어떻게 연결되는지 훨씬 선명하게 보일 거예요.
