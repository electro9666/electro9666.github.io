087번 · 오류 검출 방식

제26회(2025년) 정보시스템감리사 A형 — 시스템 구조

사전 지식​

오류 제어(Error Control)의 분류​

구분방식설명
오류 검출(Error Detection)패리티 비트, 블록 검사(BSC), 체크섬, CRC(다항 코드)오류가 있는지 여부만 판별. 발견 시 재전송 요청(ARQ)
오류 정정(Error Correction)해밍 코드, 상승 코드, BCH, 리드-솔로몬오류 위치를 찾아 수신 측에서 직접 복원(FEC)

주요 오류 검출 방식​

방식원리검출 능력비고
패리티 비트(Parity Bit)문자(바이트)마다 1의 개수가 짝수(우수 패리티) 또는 홀수(기수 패리티)가 되도록 검사 비트 1개 추가홀수 개의 오류만 검출. 짝수 개 오류는 못 잡음가장 단순. 수직 중복 검사(VRC)
블록 검사(BSC, Block Sum Check)여러 문자를 블록으로 묶어 비트 위치별로 패리티를 추가(LRC, 수평 중복 검사). 보통 VRC와 함께 사용패리티 단독보다 검출률 향상. 2차원 검사로 단일 오류는 위치 특정도 가능블록 끝에 BCC(Block Check Character) 부가
다항 코드(Polynomial Code, CRC)데이터를 다항식으로 보고 생성 다항식 G(x) 로 모듈로-2 나눗셈 → 나머지(FCS)를 덧붙여 전송. 수신 측에서 같은 나눗셈을 해 나머지가 0이면 정상연집(burst) 오류 검출에 매우 강함. 이더넷·HDLC·USB 등 실무 표준CRC-16, CRC-32, CRC-CCITT
체크섬(Checksum)데이터 워드들의 합의 1의 보수를 부가간단하나 검출력은 CRC보다 낮음IP·TCP·UDP 헤더 검사
해밍 코드(Hamming Code)2ⁿ 위치에 패리티 비트를 배치, 신드롬으로 오류 위치까지 산출검출 + 정정 가능오류 정정 코드에 해당

코드 체계(데이터 표현 코드)와의 구분​

오류 검출 방식과 혼동하기 쉬운 것이 데이터를 표현하기 위한 코드 체계다. 이들은 문자·숫자를 2진수로 표현하는 규칙일 뿐 오류 검출 기능이 없다.

코드목적오류 검출 기능
BCD 코드10진수 각 자리를 4비트 2진수로 표현(8421 코드). 6비트 BCD는 문자 표현용❌ 없음
ASCII / EBCDIC문자 표현❌ 없음(별도로 패리티 비트를 덧붙여 쓸 수는 있음)
Excess-3, Gray 코드연산 편의·자기보수·인접 코드 변화 최소화❌ 없음
해밍 코드오류 정정 용 코드✅ 검출·정정

즉 "BCD·ASCII·Gray = 표현용 코드", "패리티·BSC·CRC·체크섬 = 검출용 기법", "해밍 = 정정용 코드" 로 세 부류를 분리해 외워야 한다.

문제​

정답​

①

상세 풀이​

1단계 — 문항이 묻는 바를 확정한다.

"데이터 통신에서 사용하는 오류 검출 방식으로 가장 적합하지 않은 것"이므로, 오류 검출 기법이 아닌 것을 찾는다.

2단계 — 보기를 기능별로 분류한다.

보기정체오류 검출 기능분류
① BCD 코드10진수를 4비트 2진수로 표현하는 코드 체계❌ 없음데이터 표현용 코드
② 블록검사블록 단위 수평 패리티(LRC/BCC)✅ 있음오류 검출 기법
③ 다항코드생성 다항식 기반 CRC✅ 있음(연집 오류에 강함)오류 검출 기법
④ 패리티비트1의 개수를 짝/홀로 맞추는 검사 비트✅ 있음(홀수 개 오류)오류 검출 기법

3단계 — 결론.

②·③·④는 모두 정보 비트에 잉여(redundancy) 비트를 부가해 수신 측이 오류 여부를 판정하게 하는 기법이다. 반면 ① BCD 코드는 값을 표현하기 위한 부호화 규칙일 뿐 잉여 비트도, 검사 절차도 없다. 따라서 오류 검출 방식으로 가장 적합하지 않은 것은 ①이다.

보기별 판정​

보기판정근거
① BCD 코드✅ 정답 보기(오류 검출 방식 아님)10진수 한 자리를 4비트로 표현하는 데이터 표현용 코드. 오류 검출을 위한 잉여 비트나 검사 절차가 없음
② 블록검사오답 보기(오류 검출 방식 맞음)블록 단위로 비트 위치별 패리티(LRC)를 계산해 BCC를 부가, 수신 측에서 재계산 비교
③ 다항코드오답 보기(오류 검출 방식 맞음)CRC. 생성 다항식으로 모듈로-2 나눗셈을 수행해 FCS를 붙임. 연집 오류 검출력이 가장 우수
④ 패리티비트오답 보기(오류 검출 방식 맞음)가장 기본적인 오류 검출 기법(VRC). 1의 개수를 짝수/홀수로 맞추는 검사 비트 1개 부가

오답 이유​

  • ② 블록검사 — 오류 검출 방식이 맞으므로 정답이 아니다. 문자 단위 패리티(VRC)는 같은 문자 안에서 짝수 개 오류가 나면 놓치는 약점이 있는데, 블록검사는 여러 문자를 2차원으로 배열해 열 방향으로도 패리티(LRC) 를 계산함으로써 이를 보완한다. 블록 끝에 붙는 검사 문자를 BCC라 하며, 행·열 패리티가 동시에 어긋난 지점으로 단일 비트 오류는 위치까지 특정할 수 있다.
  • ③ 다항코드 — 오류 검출 방식이 맞다. 다항코드는 곧 CRC(Cyclic Redundancy Check) 로, 데이터 비트열을 다항식 계수로 보고 약속된 생성 다항식으로 모듈로-2 나눗셈을 수행한 나머지(FCS)를 프레임 끝에 붙인다. 수신 측이 같은 나눗셈을 해 나머지가 0이면 오류 없음으로 판정한다. 이더넷 FCS(CRC-32), HDLC(CRC-CCITT) 등 거의 모든 데이터링크 프로토콜이 채택한 사실상의 표준 검출 기법이다.
  • ④ 패리티비트 — 오류 검출 방식이 맞다. 데이터 비트의 1의 개수가 짝수가 되도록(우수 패리티) 또는 홀수가 되도록(기수 패리티) 검사 비트 1개를 덧붙인다. 구현이 가장 단순한 대신 짝수 개의 비트가 동시에 뒤집히면 검출하지 못하는 한계가 있어, 실무에서는 블록검사나 CRC와 병용한다.
  • ① BCD 코드가 정답인 이유 — BCD(Binary Coded Decimal)는 10진수 각 자리를 8·4·2·1 가중치의 4비트로 표현하는 수 표현 규칙이다. 예를 들어 10진수 27은 0010 0111로 부호화된다. 여기에는 오류를 발견하기 위한 잉여 비트도, 수신 측 검산 절차도 존재하지 않는다. 다만 "6비트 BCD 코드에 패리티 비트를 더해 7비트로 전송한다"처럼 별도의 패리티를 덧붙여 쓸 수는 있는데, 그 경우 오류를 검출하는 주체는 BCD가 아니라 추가된 패리티 비트다. 따라서 BCD 코드 자체는 오류 검출 방식으로 볼 수 없다.

핵심 정리​

  • 오류 검출 기법: 패리티 비트(VRC), 블록검사(LRC/BCC), 체크섬, 다항코드(CRC). 공통점은 잉여 비트 부가 + 수신 측 재계산 비교.
  • 오류 정정 코드: 해밍 코드, BCH, 리드-솔로몬 — 위치까지 찾아 스스로 복원(FEC).
  • BCD·ASCII·Gray·Excess-3는 데이터 표현용 코드이며 그 자체로 오류 검출 기능이 없다.
  • 연집(burst) 오류 검출에는 CRC(다항코드) 가 가장 강하며, 패리티 비트는 짝수 개 오류를 놓친다.
