083번 · 다단계 피드백 큐

제26회(2025년) 정보시스템감리사 A형 — 시스템 구조

사전 지식​

CPU 스케줄링 알고리즘 분류​

유형알고리즘특징
비선점FCFS도착 순서대로 처리, 호위 효과(convoy effect) 발생
비선점SJF실행 시간이 짧은 작업 우선, 평균 대기시간 최소이나 기아 발생
선점SRT(SRTF)SJF의 선점형
선점Round Robin타임 퀀텀 단위 순환, 대화형 시스템에 적합
선점/비선점Priority우선순위 순, 기아 → 에이징(aging)으로 보완
선점다단계 큐(MLQ)큐를 여러 개 두고 프로세스를 고정 배정
선점다단계 피드백 큐(MLFQ)큐 간 이동 허용

다단계 큐(Multi-level Queue, MLQ)​

  • 준비 큐를 성격별로 여러 개 로 분할한다. 예: 시스템 프로세스 큐 > 대화형 프로세스 큐 > 배치 프로세스 큐.
  • 각 큐는 자신만의 스케줄링 알고리즘 을 가질 수 있다(예: 상위 큐는 RR, 최하위 배치 큐는 FCFS).
  • 큐 사이에는 우선순위가 있어, 상위 큐가 비어 있을 때만 하위 큐가 CPU를 받는다(고정 우선순위 선점 방식).
  • 치명적 한계: 프로세스가 처음 배정된 큐에 영구히 고정 된다. 성격이 잘못 분류되면 되돌릴 수 없고, 하위 큐 프로세스는 기아(starvation) 에 빠지기 쉽다.

다단계 피드백 큐(Multi-level Feedback Queue, MLFQ)​

MLQ의 고정 배정 문제를 해결하기 위해 큐 간 이동(feedback) 을 허용한 방식이다. 이름의 'Feedback'이 바로 이 이동을 뜻한다.

구성 요소설명
큐의 개수n개 (보통 우선순위가 높을수록 타임 퀀텀이 짧음)
큐별 알고리즘큐마다 다르게 설정 가능 (상위 RR, 최하위 FCFS가 전형)
큐별 타임 퀀텀큐마다 다르게 설정 가능 (예: Q0=8ms, Q1=16ms, Q2=FCFS)
강등(demotion)할당된 타임 퀀텀을 다 쓰고도 끝나지 않으면 한 단계 낮은 큐로 내려감 → CPU 바운드 작업 자연 식별
승격(promotion)하위 큐에서 오래 대기하면 상위 큐로 올림(에이징) → 기아 방지
큐 간 선택항상 비어 있지 않은 가장 높은 우선순위 큐 부터 서비스

동작 예시(Q0: RR q=8, Q1: RR q=16, Q2: FCFS):

새 프로세스 → Q0 진입
  8ms 안에 종료? → 완료 (I/O 바운드·대화형 작업이 여기서 빨리 끝남)
  8ms 초과?      → Q1으로 강등
     16ms 안에 종료? → 완료
     16ms 초과?      → Q2로 강등 (FCFS로 처리)
  Q2에서 장시간 대기 → 에이징으로 Q1·Q0로 승격 (기아 방지)

이렇게 하면 사전 정보(실행 시간 예측) 없이도 짧은 작업·대화형 작업은 자동으로 높은 우선순위를 유지하고, 긴 계산 작업은 아래로 내려가 SJF와 유사한 효과를 낸다. 그래서 MLFQ는 "가장 범용적인 스케줄러"로 불리며 실제 유닉스/리눅스·윈도우 스케줄러의 기반이 되었다.

문제​

정답​

③

상세 풀이​

"가장 적절하지 않은 것"을 고르는 유형이므로, 각 보기가 MLFQ의 정의에 부합하는지 판정한다.

1단계 — MLFQ의 정의적 특징 3가지를 정리한다.

  1. 큐가 여러 개이고, 큐마다 스케줄링 알고리즘과 타임 퀀텀을 독립적으로 설정할 수 있다.
  2. 큐 간 우선순위가 있어, 비어 있지 않은 최상위 큐 가 먼저 CPU를 얻는다.
  3. 프로세스가 큐 사이를 이동(승격/강등) 한다 ← 이것이 MLQ와 구별되는 '피드백'의 본질.

2단계 — 보기 ③을 검증한다.

③ 프로세스는 CPU를 할당받기까지 처음 배정된 큐에 계속 머무르며, 다른 큐로 이동할 수 없다.

이는 다단계 큐(MLQ) 의 설명이다. MLFQ는 정확히 이 제약을 없애기 위해 고안된 기법이므로, MLFQ 설명으로는 명백히 틀렸다.

구분다단계 큐(MLQ)다단계 피드백 큐(MLFQ)
큐 간 이동불가(고정)가능(승격·강등)
기아 대응어려움에이징으로 해결
분류 근거프로세스 유형(시스템/대화형/배치)실제 CPU 사용 행태(관측 기반)
보기 ③에 해당✅ 해당❌ 해당 안 됨

3단계 — 나머지 보기가 모두 MLFQ의 참인 속성임을 확인한다.

①(큐별 알고리즘 상이), ②(큐별 타임 퀀텀 상이), ④(최상위 비어있지 않은 큐 우선)는 모두 위 정의 1·2에 그대로 대응한다.

따라서 적절하지 않은 설명은 ③이다.

보기별 판정​

보기판정근거
① 각 큐는 서로 다른 스케줄링 알고리즘 운용 가능오답 보기(옳은 설명)상위 큐는 RR, 최하위 큐는 FCFS를 쓰는 것이 전형적 구성
② 큐마다 다른 타임 퀀텀 설정 가능오답 보기(옳은 설명)우선순위가 낮을수록 퀀텀을 크게 주어 문맥 교환 비용을 줄임
③ 처음 배정된 큐에 계속 머무르며 이동 불가✅ 정답 보기(틀린 설명)'Feedback'의 정의가 곧 큐 간 이동. 이동이 없는 것은 MLQ
④ 최상위 큐가 비어 있지 않으면 항상 그 큐의 프로세스에 CPU 할당오답 보기(옳은 설명)큐 간에는 고정 우선순위 선점 방식이 적용됨

오답 이유​

  • ① — 틀린 설명이 아니다. MLFQ는 큐 단위로 스케줄링 정책을 달리 둘 수 있으며, 대화형 작업이 많은 상위 큐에는 응답시간이 좋은 RR을, CPU 바운드 작업이 몰리는 최하위 큐에는 문맥 교환이 적은 FCFS를 배치하는 것이 표준적인 설계다. 따라서 '적절하지 않은 설명'이 아니다.
  • ② — 역시 옳다. 상위 큐일수록 퀀텀을 짧게(예: 8ms) 주어 응답성을 높이고, 하위 큐일수록 길게(예: 16ms, 32ms) 주어 긴 계산 작업이 잦은 선점으로 오버헤드를 겪지 않게 한다. 큐마다 퀀텀이 다른 것이 MLFQ의 표준 구성이다.
  • ④ — 옳다. MLFQ에서 큐 선택은 엄격한 우선순위(strict priority) 방식이므로, 상위 큐에 실행 가능한 프로세스가 하나라도 있으면 하위 큐는 CPU를 받지 못한다. 하위 큐의 기아는 큐 선택 규칙을 바꾸는 대신 에이징(승격) 으로 해결한다. 그러므로 이 서술 자체는 정확하다.
  • ③이 왜 틀렸는지 다시 정리하면 — MLFQ의 본질은 "프로세스의 과거 행동을 관찰해 우선순위를 동적으로 재조정"하는 것이다. 타임 퀀텀을 소진하면 강등되고, 오래 기다리면 승격된다. 올바른 서술은 "프로세스는 CPU 사용 행태에 따라 다른 큐로 이동(강등·승격)할 수 있다"이며, 보기 ③처럼 이동을 금지하면 그것은 MLFQ가 아니라 다단계 큐(MLQ)가 된다.

핵심 정리​

  • MLQ vs MLFQ의 유일한 결정적 차이는 '큐 간 이동 가능 여부' 다. 'Feedback' = 이동.
  • MLFQ는 큐별로 알고리즘과 타임 퀀텀을 독립 설정 할 수 있고, 큐 간에는 비어 있지 않은 최상위 큐 우선 규칙이 적용된다.
  • 타임 퀀텀 소진 시 강등, 장시간 대기 시 에이징 승격 → 실행 시간을 미리 몰라도 짧은 작업을 우선 처리(SJF 근사)하며 기아를 방지한다.
  • "가장 적절하지 않은 것" 유형에서는 정답 보기가 곧 틀린 설명 임에 유의한다.
