096번 · netstat 옵션과 백도어 탐지

제26회(2025년) 정보시스템감리사 A형 — 시스템 구조

사전 지식​

네트워크 상태 확인 명령어 개요​

명령용도
pingICMP Echo로 상대 호스트 도달 여부·왕복 지연 확인
traceroute / tracert목적지까지의 경유 라우터(홉) 추적
nslookup / digDNS 질의 및 레코드 확인
arpARP 캐시(IP ↔ MAC 매핑) 조회, ARP 스푸핑 점검
route라우팅 테이블 조회·설정
netstat연결 상태·수신 대기 포트·라우팅 테이블·프로토콜 통계 확인
ss리눅스에서 netstat을 대체하는 소켓 통계 도구(더 빠름)
ipconfig / ifconfig / ip인터페이스 IP 설정 조회

netstat 주요 옵션​

netstat(network statistics)은 옵션에 따라 전혀 다른 정보를 보여 준다. 시험에서는 이 옵션별 출력 대상을 구분할 수 있는지를 묻는다.

옵션출력 내용비고
-a모든(all) 연결과 수신 대기(LISTENING) 포트옵션 없이 실행하면 ESTABLISHED 연결만 보임
-n주소·포트를 이름 해석 없이 숫자(numeric) 로 표시DNS/서비스명 조회를 생략 → 빠르고 실제 IP·포트가 그대로 보임
-an위 둘의 결합 — 모든 연결·리스닝 포트를 IP:포트 숫자로가장 널리 쓰이는 점검 조합
-r라우팅 테이블(= route print)네트워크 경로 확인
-s프로토콜별 통계(statistics) — TCP/UDP/IP/ICMP 송수신 패킷 수, 오류 수연결 목록은 나오지 않음
-pWindows: 프로토콜 지정(netstat -p tcp) / Linux: PID·프로세스명 표시플랫폼별 의미가 달라 주의
-oWindows: 연결별 소유 프로세스 ID(PID) 표시-ano 조합으로 프로세스 추적
-bWindows: 연결을 만든 실행 파일 이름 표시(관리자 권한 필요)
-e이더넷 인터페이스 통계(바이트·패킷 수)

TCP 소켓 상태 값​

netstat -an 출력의 State 열에서 보게 되는 대표 값이다.

상태의미
LISTENING해당 포트에서 접속을 기다리는 중 — 서버(또는 백도어)가 열어 둔 포트
ESTABLISHED연결이 수립되어 데이터 송수신 중
SYN_SENT / SYN_RECEIVED3-way 핸드셰이크 진행 중
TIME_WAIT / CLOSE_WAIT종료 절차 진행·대기

백도어(Back door)와 포트 점검​

백도어는 정상 인증을 우회해 시스템에 접근할 수 있게 만든 통로이며, 트로이목마는 정상 프로그램으로 위장해 설치되면서 백도어를 심는 악성코드다.

백도어의 흔적점검 방법
알려지지 않은 포트가 LISTENING 상태로 열려 있음netstat -an 으로 리스닝 포트 목록 확인
외부 C&C 서버로 ESTABLISHED 연결이 유지됨netstat -an 의 Foreign Address 확인
해당 연결을 만든 프로세스가 수상함Windows netstat -ano → PID → 작업관리자 / Linux netstat -anp

특히 -n(숫자 표시) 이 중요한 이유는, 이름 해석을 하면 포트 번호가 http, microsoft-ds 같은 서비스명으로 치환되어 비표준 포트를 식별하기 어렵고, 역방향 DNS 조회 때문에 출력이 느려지며, 조회 과정에서 오히려 정보가 왜곡될 수 있기 때문이다.

상세 풀이​

1단계 — 요구사항 정리​

문항이 요구하는 것은 "백도어가 정보를 빼내는지 확인할 때 사용하는 상태 확인" 명령이다. 확인해야 할 대상은 두 가지다.

확인 대상필요한 정보
백도어가 열어 둔 포트LISTENING 상태의 포트 목록
외부로 나가는 연결ESTABLISHED 연결의 원격 IP·포트

2단계 — 옵션 대응​

필요 정보필요한 옵션
수립된 연결뿐 아니라 대기 중인 포트까지 전부-a (기본 실행은 ESTABLISHED만 표시)
비표준 포트 번호와 실제 외부 IP를 있는 그대로-n (서비스명·호스트명 치환 방지)

두 요구를 동시에 만족하는 조합이 netstat -an 이다.

3단계 — 실제 출력으로 확인​

C:\> netstat -an

Active Connections
  Proto  Local Address        Foreign Address      State
  TCP    0.0.0.0:135          0.0.0.0:0            LISTENING
  TCP    0.0.0.0:445          0.0.0.0:0            LISTENING
  TCP    0.0.0.0:31337        0.0.0.0:0            LISTENING   ← 의심스러운 리스닝 포트
  TCP    192.168.0.10:49876   203.0.113.55:4444    ESTABLISHED ← 의심스러운 외부 연결
  • 업무상 쓰이지 않는 포트가 LISTENING 이면 백도어가 대기 중일 가능성이 있다.
  • 알 수 없는 외부 IP로 ESTABLISHED 연결이 유지되면 정보 유출 경로일 수 있다.

4단계 — 후속 조치(참고)​

포트를 발견한 뒤 어떤 프로세스인지 특정하려면 Windows는 netstat -ano 로 PID를 얻어 작업관리자·tasklist로 대조하고, Linux는 netstat -anp(또는 ss -anp)로 프로세스명을 함께 본다. 다만 문항이 묻는 "정보를 빼내는지 확인(상태 확인)" 단계의 표준 명령은 netstat -an 이다.

따라서 정답은 ①이다.

보기별 판정​

보기판정근거
① netstat -an✅ 정답모든 연결 + 리스닝 포트를 숫자 IP:포트로 표시 → 비정상 포트·외부 연결 탐지에 최적
② netstat -p❌ 오답Windows에서는 프로토콜 지정 옵션(-p tcp처럼 인자 필수), Linux에서는 PID 표시. 단독으로는 백도어 점검 목적에 부합하지 않음
③ netstat -r❌ 오답라우팅 테이블 출력. 연결 상태 정보가 없음
④ netstat -s❌ 오답프로토콜별 통계(패킷 수·오류 수) 출력. 개별 연결이나 포트 목록이 없음

오답 이유​

  • ② netstat -p — 플랫폼에 따라 의미가 갈리는 옵션이다. Windows에서는 -p proto 형태로 표시할 프로토콜을 한정하는 옵션이어서(netstat -p tcp) 인자 없이 단독 사용하면 오류가 난다. Linux에서는 -p가 연결별 PID/프로그램명을 보여 주므로 유용하지만, 그것만으로는 -a가 없어 LISTENING 포트가 표시되지 않고 -n이 없어 포트가 서비스명으로 치환된다. 즉 백도어 점검에 쓰려면 -anp처럼 조합해야 하며, 보기의 형태 그대로는 목적을 달성할 수 없다.

  • ③ netstat -r — 라우팅 테이블만 출력한다(Windows의 route print와 동일한 내용). 목적지 네트워크·넷마스크·게이트웨이·인터페이스·메트릭이 나열될 뿐, 어떤 포트가 열려 있고 누구와 연결되어 있는지에 대한 정보가 전혀 없다. 경로가 이상하게 조작되었는지(라우팅 변조) 점검할 때는 쓸모가 있으나, 문항이 묻는 "백도어의 연결 상태 확인"과는 용도가 다르다.

  • ④ netstat -s — 프로토콜별 누적 통계를 출력한다. IP/ICMP/TCP/UDP 각각의 수신·송신 패킷 수, 재전송 수, 오류·폐기 수 등 집계 수치만 나오고, 개별 연결(누구와, 어느 포트로) 은 전혀 나타나지 않는다. 트래픽 이상 징후를 총량 관점에서 짚어 볼 수는 있어도, 특정 백도어 포트나 외부 C&C 연결을 짚어내지는 못한다.

  • 정리하면 ②·③·④는 모두 "연결·포트 목록"이 아닌 다른 정보(프로토콜 한정/경로/통계)를 보여 준다. 백도어 탐지의 핵심인 LISTENING 포트 + 외부 ESTABLISHED 연결을 숫자 그대로 볼 수 있는 것은 -a와 -n을 함께 준 ① 뿐이다.

핵심 정리​

  • netstat -an = 모든(-a) 연결·리스닝 포트를 숫자(-n)로 → 백도어·트로이목마가 열어 둔 비정상 포트와 외부 연결을 찾는 기본 명령.
  • -a 없이 실행하면 ESTABLISHED만 보여 리스닝 중인 백도어를 놓치고, -n 없이 실행하면 포트가 서비스명으로 치환되어 비표준 포트를 식별하기 어렵다.
  • 옵션 구분: -r 라우팅 테이블, -s 프로토콜 통계, -e 인터페이스 통계, -o PID(Windows), -b 실행파일명(Windows), -p 프로토콜 지정(Windows) / 프로세스 표시(Linux).
  • 프로세스까지 특정하려면 Windows netstat -ano + tasklist, Linux netstat -anp 또는 ss -anp 로 이어서 점검한다.
