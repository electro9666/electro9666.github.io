107번 · L2TP와 SSTP의 보안 프로토콜

제26회(2025년) 정보시스템감리사 A형 — 보안

사전 지식​

1. VPN 터널링 프로토콜 비교​

프로토콜계층캡슐화/전송기밀성·인증 제공 수단특징
PPTP2계층GRE + TCP 1723MPPE(RC4), MS-CHAP구현 간단, 현재 안전성 취약
L2F2계층UDP 1701자체 암호화 없음Cisco 개발, PPTP와 통합되어 L2TP로 발전
L2TP2계층UDP 1701자체 암호화 없음 → IPSec과 결합(L2TP/IPSec)PPTP+L2F 통합 표준(RFC 2661)
IPSec3계층AH/ESP, IKE(UDP 500/4500)ESP 암호화, AH 무결성, IKE 인증·키교환전송 모드/터널 모드
SSTP전송·응용 경계TCP 443 위의 SSL/TLSSSL/TLSMicrosoft 개발, HTTPS 포트라 방화벽 통과 용이

2. L2TP가 IPSec을 필요로 하는 이유​

L2TP는 이름 그대로 "터널링"만 담당하는 프로토콜이다. PPP 프레임을 UDP 1701로 캡슐화해 전달할 뿐, 암호화·무결성·상호 인증 기능이 전혀 없다. 따라서 실무에서는 다음과 같이 L2TP/IPSec 조합으로 사용한다.

계층담당
IPSec(ESP)기밀성(암호화), 무결성, 재전송 방지, 상호 인증(사전공유키 또는 인증서)
L2TPPPP 세션 터널링, 사용자 인증(PAP/CHAP/MS-CHAPv2), 다중 프로토콜 전달

동작 순서: IKE로 IPSec SA 수립 → IPSec 보호 채널 안에서 L2TP 터널 수립 → PPP 세션 개통.

3. SSTP가 TLS를 사용하는 방식​

SSTP(Secure Socket Tunneling Protocol)는 Microsoft가 Windows Server 2008 / Windows Vista SP1부터 제공한 프로토콜로, PPP 트래픽을 HTTPS(TCP 443) 위의 SSL/TLS 채널에 실어 전달한다.

특징내용
포트TCP 443 — 일반 HTTPS와 동일해 방화벽·프록시 통과율이 매우 높음
보안SSL/TLS가 기밀성·무결성·서버 인증(인증서) 제공
장점NAT·방화벽 친화적, 인증서 기반 서버 검증
단점TCP 위에 TCP를 얹어 재전송이 중첩되는 TCP meltdown 가능성

4. 함께 정리할 인증/원격접속 프로토콜 (혼동 주의)​

프로토콜정체
PAPPPP의 평문 패스워드 인증 방식. 암호화 기능이 아니라 취약한 인증 방식
CHAP챌린지-응답 기반 PPP 인증
SSH원격 셸 접속용 보안 프로토콜(TCP 22). VPN 터널링 표준 수단이 아님
RADIUS / TACACS+AAA(인증·인가·계정관리) 서버 프로토콜

문제​

정답​

①

상세 풀이​

각 프로토콜이 보안 서비스(기밀성·인증)를 어디서 얻는지를 확인하면 된다.

  1. L2TP — RFC 2661 표준 자체에 암호화 기능이 없다. 따라서 기밀성과 상호 인증을 얻기 위해 IPSec(ESP) 와 결합해 L2TP/IPSec 형태로 운용한다. Windows, macOS, iOS의 기본 VPN 설정에도 "L2TP/IPSec"이라는 항목명이 그대로 노출된다.

  2. SSTP — 이름의 "Secure Socket"이 곧 SSL(Secure Sockets Layer)/TLS를 가리킨다. PPP 데이터를 TCP 443의 TLS 세션에 캡슐화해 전송하므로 기밀성·무결성·서버 인증을 TLS가 담당한다.

따라서 올바른 짝은 L2TP – IPSec, SSTP – TLS, 즉 보기 ①이다.

나머지 보기는 다음과 같이 어긋난다.

  • PAP는 애초에 암호화 프로토콜이 아니라 PPP의 평문 인증 방식이므로 기밀성 제공 수단이 될 수 없다.
  • SSH는 원격 셸 및 포트 포워딩용 프로토콜로, L2TP나 SSTP의 보안 계층으로 쓰이지 않는다.
  • IPSec을 SSTP에 붙이거나 TLS를 L2TP에 붙이는 조합은 표준으로 정의되어 있지 않다.

보기별 판정​

보기판정근거
① L2TP – IPSec, SSTP – TLS✅ 정답L2TP는 자체 암호화 부재 → IPSec 결합(L2TP/IPSec), SSTP는 TCP 443의 SSL/TLS 사용
② L2TP – PAP, SSTP – SSH❌ 오답PAP는 평문 인증 방식(암호화 기능 없음), SSH는 VPN 터널링 보안 계층이 아님
③ L2TP – TLS, SSTP – PAP❌ 오답두 프로토콜의 보안 수단이 서로 뒤바뀌고 PAP가 잘못 배치됨
④ L2TP – SSH, SSTP – IPSec❌ 오답L2TP는 IPSec, SSTP는 TLS가 정답. 양쪽 모두 틀림

오답 이유​

  • ② L2TP – PAP, SSTP – SSH — PAP(Password Authentication Protocol) 는 PPP 링크에서 사용자 ID와 패스워드를 평문으로 전송하는 가장 취약한 인증 방식이다. 기밀성 제공은커녕 스니핑에 그대로 노출된다. SSH는 TCP 22번의 원격 셸 프로토콜로, 포트 포워딩으로 유사 터널을 만들 수는 있어도 SSTP의 구성 요소가 아니다.

  • ③ L2TP – TLS, SSTP – PAP — L2TP를 TLS로 보호하는 것은 표준 조합이 아니다. L2TP는 UDP 1701 기반이고 표준 결합 상대는 IPSec이다. 또한 SSTP의 보안은 이름부터 "Secure Socket"인 TLS가 담당하며 PAP와는 무관하다. 두 항목 모두 오배치다.

  • ④ L2TP – SSH, SSTP – IPSec — 정답의 두 항목을 모두 다른 프로토콜로 바꿔 놓은 보기다. L2TP의 짝은 SSH가 아니라 IPSec이고, SSTP의 짝은 IPSec이 아니라 TLS다. IPSec은 3계층에서 IP 패킷을 보호하는 프로토콜로, TCP 443 위에서 동작하는 SSTP와 결합할 구조가 아니다.

핵심 정리​

  • L2TP는 자체 암호화가 없다 → 반드시 IPSec과 결합(L2TP/IPSec, UDP 1701 + IKE 500/4500).
  • SSTP의 "Secure Socket" = SSL/TLS. TCP 443 포트를 사용해 방화벽 통과가 쉽다.
  • PPTP는 MPPE(RC4) 기반으로 현재 안전성이 낮고, OpenVPN과 IKEv2/IPSec가 현대적 대안이다.
  • PAP/CHAP는 인증 방식, SSH는 원격 셸 프로토콜로 VPN 터널의 보안 계층이 아니다 — 보기에 섞여 나오면 소거 대상.
