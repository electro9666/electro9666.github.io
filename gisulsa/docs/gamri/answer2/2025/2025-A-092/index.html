092번 · CRC 회로의 생성다항식

제26회(2025년) 정보시스템감리사 A형 — 시스템 구조

사전 지식​

CRC(Cyclic Redundancy Check)의 원리​

CRC는 데이터 링크 계층의 대표적인 오류 검출(error detection) 기법이다. 비트열을 계수가 0 또는 1인 다항식으로 보고, 모듈로-2 산술(자리올림 없는 덧셈 = XOR) 로 나눗셈을 수행한다.

단계내용
① 생성다항식 선택차수 n인 생성다항식 G(x) 를 송·수신 측이 공유
② 0 채우기원본 데이터 M(x) 뒤에 n개의 0을 붙임 = M(x)·xⁿ
③ 나눗셈M(x)·xⁿ ÷ G(x) 를 모듈로-2로 수행
④ FCS 부착나머지(n비트) = FCS(Frame Check Sequence) 를 데이터 뒤에 붙여 전송
⑤ 검사수신 측이 수신 프레임 전체를 G(x)로 나눠 나머지가 0이면 정상

대표적인 표준 생성다항식: CRC-16 x¹⁶ + x¹⁵ + x² + 1, CRC-CCITT x¹⁶ + x¹² + x⁵ + 1, CRC-32 x³² + x²⁶ + … + x + 1.

비트열 ↔ 다항식 대응​

다항식비트열비트 수
x⁴ + x² + 11 0 1 0 15 (= 차수 4 + 1)
x² + 11 0 13
x⁴ + x³ + x1 1 0 1 05
x³ + x1 0 1 04

차수가 n이면 비트열 길이는 n+1, 나머지(FCS) 길이는 n이다.

시프트 레지스터 + XOR 로 만드는 CRC 하드웨어​

모듈로-2 나눗셈은 LFSR(Linear Feedback Shift Register) 로 그대로 구현된다. 회로를 읽을 때 규칙은 다음 세 가지다.

회로 요소생성다항식에서의 의미
시프트 레지스터(사각형)의 개수 = n최고차항 xⁿ 의 차수. 동시에 FCS(나머지)의 비트 수
피드백 선 자체 (최종 단 출력 → 입력단 XOR)상수항 1 과 최고차항 xⁿ 의 쌍
k번째 레지스터 뒤에 삽입된 XOR항 x^k (레지스터는 데이터가 들어오는 쪽부터 1, 2, 3 … 으로 셈)

※ 유효한 CRC 생성다항식은 상수항 1을 반드시 가져야 한다. 상수항이 없으면 G(x) = x·G'(x) 로 인수분해되어 마지막 비트의 오류를 잡지 못하고, 회로상으로도 피드백 루프가 성립하지 않는다.

문제​

정답​

①

상세 풀이​

1단계 — 회로의 신호 흐름 파악​

그림의 화살표는 오른쪽 → 왼쪽 방향이다. 오른쪽 끝의 "데이터" 입력부터 따라가면 다음과 같다.

데이터 입력 → [XOR_A] → [레지스터1] → [레지스터2] → [XOR_B] → [레지스터3] → [레지스터4] → 출력
                  ↑                                       ↑                               │
                  └───────────────────────────────────────┴───────────────────────────────┘
                                          (하단 피드백 선)
  • 사각형(시프트 레지스터)은 총 4개.
  • XOR 게이트는 2개: 하나는 데이터 입력단(XOR_A), 다른 하나는 레지스터 2개를 지난 위치(XOR_B).
  • 맨 왼쪽 레지스터의 출력이 아래쪽 선을 타고 되돌아와 두 XOR에 모두 공급된다(피드백).

2단계 — 회로 요소를 항으로 환산​

회로 관찰대응 규칙도출되는 항
시프트 레지스터 4개레지스터 수 = 최고 차수 nx⁴
최종단 출력 → 입력단 XOR_A 로 되돌아가는 피드백 선피드백 자체가 상수항1
데이터 입력 쪽에서 세어 2번째 레지스터 뒤에 놓인 XOR_Bk번째 레지스터 뒤의 XOR = x^k, 여기서 k = 2x²
그 외 위치(1·3번째 레지스터 뒤)에는 XOR 없음해당 항의 계수 0x³, x¹ 항 없음

세 항을 합치면

G(x) = x⁴ + x² + 1        (비트열 10101)

3단계 — 나눗셈으로 회로 동작 검증​

이 회로가 실제로 10101(= x⁴ + x² + 1)로 나눈 나머지를 만들어 내는지, 데이터 1101을 예로 모듈로-2 나눗셈으로 확인한다. 차수가 4이므로 뒤에 0을 4개 붙인 1101 0000을 나눈다.

단계현재 피제수 앞 5비트선두 비트연산결과(나머지 4비트)
111010111010 ⊕ 101011111
211110 (비트6 0 내림)111110 ⊕ 101011011
310110 (비트7 0 내림)110110 ⊕ 101010011
400110 (비트8 0 내림)0XOR 없이 시프트0110

→ FCS = 0110, 전송 프레임 = 1101 0110

수신 측 검증:

단계현재 피제수 앞 5비트선두 비트연산결과
111010111010 ⊕ 101011111
211111 (비트6 1 내림)111111 ⊕ 101011010
310101 (비트7 1 내림)110101 ⊕ 101010000
400000 (비트8 0 내림)0XOR 없이 시프트0000

나머지가 0000이므로 오류 없음으로 판정된다. 레지스터 4개짜리 회로가 4비트 나머지를 만들어 내는 것과도 일치한다.

따라서 정답은 ①이다.

보기별 판정​

보기판정근거
① x⁴ + x² + 1✅ 정답레지스터 4개(x⁴) + 2번째 레지스터 뒤 XOR(x²) + 피드백(1)에 정확히 일치
② x² + 1❌ 오답차수 2 → 레지스터가 2개여야 한다. 그림은 4개
③ x⁴ + x³ + x❌ 오답차수 4는 맞지만 XOR이 3번째·1번째 레지스터 뒤에 있어야 하고, 상수항 1이 없어 CRC 생성다항식으로 부적합
④ x³ + x❌ 오답차수 3 → 레지스터 3개. 역시 상수항이 없다

오답 이유​

  • ② x² + 1 — 최고 차수가 2이므로 하드웨어는 시프트 레지스터 2개와 입력단 XOR 1개로 구성된다. 그림은 레지스터가 명백히 4개이고 XOR도 2개이므로 규모 자체가 맞지 않는다. "레지스터 개수 = 최고 차수"라는 첫 번째 규칙만 적용해도 즉시 탈락한다. 참고로 이 다항식은 FCS가 2비트뿐이어서 검출력도 매우 약하다.

  • ③ x⁴ + x³ + x — 레지스터 개수(4)는 그림과 일치하지만 XOR의 위치가 다르다. x³ 항은 3번째 레지스터 뒤, x¹ 항은 1번째 레지스터 뒤에 XOR이 있어야 하는데, 그림의 XOR은 2번째 레지스터 뒤에 하나뿐이다. 더 근본적으로 이 다항식은 x(x³ + x² + 1) 로 인수분해되어 상수항이 0이다. 상수항이 없는 생성다항식은 최하위 비트(마지막 비트)의 단일 오류를 검출하지 못하므로 CRC 생성다항식으로 쓰지 않으며, 입력단 XOR로 피드백이 들어오는 그림의 구조와도 모순된다.

  • ④ x³ + x — 최고 차수가 3이므로 레지스터가 3개여야 한다(그림은 4개). 또한 x(x² + 1) 로 상수항이 0이라 ③과 같은 이유로 생성다항식 자격을 갖추지 못한다. 차수와 상수항 두 가지 모두에서 어긋난다.

  • 요약하면, ① 만이 "레지스터 4개 = x⁴", "2번째 레지스터 뒤 XOR = x²", "피드백 = 1" 이라는 세 관찰을 모두 만족한다.

핵심 정리​

  • 레지스터 개수 = 생성다항식의 최고 차수 = FCS(나머지) 비트 수. 그림에서 사각형 개수만 세면 차수가 바로 나온다.
  • XOR 게이트의 위치가 중간 항의 차수다. 데이터가 들어오는 쪽부터 세어 k번째 레지스터 뒤의 XOR은 x^k 항을 뜻한다.
  • **입력단으로 되돌아오는 피드백 선은 상수항 1**에 해당한다. 유효한 CRC 생성다항식은 항상 상수항 1을 가지므로, 상수항이 없는 보기(x⁴+x³+x, x³+x)는 그 자체로 탈락 후보다.
  • CRC는 모듈로-2 나눗셈(XOR) 이며, 수신 측에서 프레임 전체를 G(x)로 나눠 나머지 0이면 오류 없음으로 판정한다.
