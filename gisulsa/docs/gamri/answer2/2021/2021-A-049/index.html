049번 · 시퀀스 다이어그램으로 본 브로커(Broker) 패턴

제22회(2021년) 정보시스템감리사 A형 — 소프트웨어 공학

사전 지식​

1. 브로커 패턴의 구조​

브로커(Broker) 패턴은 분산 환경에서 클라이언트와 서버(서비스 제공자) 사이에 중개자(broker)를 두어, 클라이언트가 서버의 위치·구현 기술을 몰라도 서비스를 호출할 수 있게 하는 아키텍처 패턴이다(POSA 1권, Bass 외 『Software Architecture in Practice』 3판).

구성 요소역할
Client서비스를 요청하는 애플리케이션
Client-side proxy원격 호출을 로컬 호출처럼 보이게 함. 요청을 마샬링(pack) 하여 브로커로 전달
Broker서버 등록·위치 탐색(find server), 요청을 적절한 서버로 전달, 응답 반환
Server-side proxy요청을 언마샬링(unpack) 하여 실제 서비스 호출
Server실제 서비스 구현

대표 사례: CORBA의 ORB, Java RMI, 메시지 브로커, 서비스 레지스트리 기반 호출.

2. 품질 속성 측면의 장단점​

구분내용
modifiability서버의 위치·구현이 바뀌어도 클라이언트는 브로커 인터페이스만 알므로 영향이 없다(중개자 전술, 위치 투명성)
availability서버 하나가 실패하면 브로커가 다른(복제) 서버로 요청을 재지정할 수 있다
performance브로커가 부하가 적은 서버로 요청을 분배할 수 있다
interoperability·portability이기종 플랫폼·언어로 작성된 서비스를 연동
약점간접 계층 추가로 인한 지연, 브로커가 병목·단일 장애점이 될 수 있음, 초기 구축 복잡도, 테스트 어려움

즉 브로커는 "가용성·성능을 높일 수 있는 수단을 제공하는" 동시에 "간접화 비용을 치르는" 양면성을 가진다.

상세 풀이​

시퀀스 다이어그램을 따라가면 다음과 같다.

객체메시지해석
Asend_request() → B클라이언트가 요청
Bpack_data(), forward_request() → C클라이언트 측 프록시: 마샬링 후 브로커로 전달
Cfind_server(), call_service() → D브로커: 서버 위치 탐색 후 호출
Dunpack_data(), run_service() → E서버 측 프록시: 언마샬링 후 서비스 실행
E—서버

pack/unpack과 find_server의 조합은 전형적인 브로커 패턴이다.

  1. ① "분산 애플리케이션 개발 복잡도를 증가" → 브로커는 통신·위치 탐색·마샬링을 프록시와 브로커가 대신 처리하므로 애플리케이션 개발자가 느끼는 분산 복잡도를 감소시킨다. → 부적절.
  2. ② "동일한 환경에서의 서비스 실행 지원" → 브로커의 목적은 서로 다른(이기종·분산) 환경의 서비스를 투명하게 연결하는 것이다. → 부적절.
  3. ③ "여러 서비스를 하나의 동일한 언어로 개발하는 것이 일반적" → 프록시가 마샬링/언마샬링을 담당하므로 서비스별로 서로 다른 언어·플랫폼으로 개발할 수 있다(상호운용성). → 부적절.
  4. ④ "modifiability, availability, performance 측면에서 바람직" → 위치 투명성으로 변경 용이성, 장애 서버 대신 다른 서버로 재지정하는 가용성, 부하 분산을 통한 성능 향상 수단을 제공한다. → 가장 적절 = 정답

논점: 브로커는 간접 계층을 추가하므로 호출 1건의 지연(latency)은 늘어나고, 브로커 자체가 단일 장애점이 될 수 있다는 약점도 교재에 함께 제시된다. 따라서 ④는 "항상 성능·가용성이 좋아진다"는 뜻이 아니라, 브로커가 제공하는 재지정·부하 분산 능력을 근거로 한 서술로 이해해야 한다. 나머지 세 보기는 명백히 틀렸으므로 "가장 적절한 것"으로 ④가 선택된다.

보기별 판정​

보기판정근거
① 분산 개발 복잡도 증가오답프록시·브로커가 분산 통신을 은닉 → 복잡도 감소
② 동일한 환경에서의 실행 지원오답이기종·분산 환경 간 연동이 목적
③ 하나의 동일한 언어로 개발이 일반적오답마샬링으로 언어·플랫폼 독립
④ modifiability, availability, performance 측면에서 바람직✅ 정답위치 투명성(변경 용이), 서버 재지정(가용성), 부하 분산(성능)

오답 이유​

  • ①: 브로커 패턴은 "원격 호출을 로컬 호출처럼" 만드는 것이 핵심이다. 시스템 전체 구성 요소는 늘지만, 개발자가 직접 다뤄야 하는 네트워크 통신·서버 탐색 로직은 인프라로 흡수되므로 분산 애플리케이션 개발 복잡도는 줄어든다.
  • ②·③: 클라이언트와 서버 사이에 표준화된 요청 형식(마샬링)이 있으므로, 서버는 다른 OS·다른 언어로 구현되어도 된다. CORBA가 IDL로 C++·Java 서비스를 서로 호출하게 한 것이 대표 예다.

핵심 정리​

  • pack_data → find_server → unpack_data 흐름 = 클라이언트 프록시 → 브로커 → 서버 프록시 = 브로커 패턴.
  • 장점: 위치 투명성·변경 용이성, 이기종 상호운용성, 서버 재지정을 통한 가용성, 부하 분산을 통한 성능.
  • 약점: 간접화 지연, 브로커 병목·단일 장애점, 테스트 어려움.
