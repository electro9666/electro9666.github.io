067번 · 부양가족이 없는 사원 — NOT EXISTS 상관 부질의

제22회(2021년) 정보시스템감리사 A형 — 데이터베이스

사전 지식​

1. EXISTS / NOT EXISTS​

  • EXISTS (부질의): 부질의 결과가 한 행이라도 있으면 참.
  • NOT EXISTS (부질의): 부질의 결과가 공집합이면 참.
  • 결과 행의 존재 여부만 보므로 SELECT 목록은 *로 쓰는 것이 관례다.
  • 좌변 피연산자 없이 WHERE NOT EXISTS (...) 형태로 쓴다.

2. IN / NOT IN​

  • 열 IN (부질의), 열 NOT IN (부질의) 형태로 좌변에 비교할 열이 반드시 필요하다.
  • 부질의 SELECT 목록은 비교 대상과 같은 도메인의 단일 열이어야 한다.

3. 상관 부질의(correlated subquery)​

부질의 안에서 바깥 질의의 열(여기서는 EMPLOYEE.SSN)을 참조하면, 바깥 행마다 부질의가 다시 평가된다.

①

상세 풀이​

DEPENDENT.ESSN이 EMPLOYEE.SSN을 참조하는 외래키이므로, 사원과 부양가족을 잇는 조건은 SSN = ESSN이다. 빈칸 구조는 WHERE ㉮ (SELECT ㉯ FROM DEPENDENT WHERE ㉰)로 ㉮ 앞에 비교할 열이 없다.

SELECT NAME
FROM   EMPLOYEE
WHERE  NOT EXISTS (SELECT *
                   FROM   DEPENDENT
                   WHERE  SSN = ESSN);

바깥 사원 행마다 "그 사원의 SSN을 ESSN으로 가진 부양가족 행"을 찾고, 하나도 없을 때만 이름을 출력한다. 요구사항 "부양가족이 없는 사원"과 정확히 일치한다.

보기별 판정​

보기판정근거
① NOT EXISTS / * / SSN=ESSN✅ 정답상관 부질의로 해당 사원의 부양가족 존재 여부를 검사
② NOT IN / * / NAME=DEPNAME오답NOT IN 좌변 열 없음, *는 단일 열 비교 불가, 조인 조건도 틀림(사원 이름 ≠ 부양가족 이름)
③ NOT IN / ESSN / SSN=ESSN오답WHERE NOT IN (...)은 좌변 열이 없어 문법 오류. SSN NOT IN (SELECT ESSN FROM DEPENDENT)로 써야 성립
④ NOT EXISTS / ESSN / NAME=DEPNAME오답조인 조건이 이름 비교라 의미가 틀림 — 사원 이름과 같은 이름의 부양가족이 없는지를 검사하게 됨

오답 이유​

  • ②·④: NAME = DEPNAME은 "사원 이름과 부양가족 이름이 같은가"를 비교할 뿐, 외래키 관계(SSN–ESSN)를 따르지 않는다. 사원과 부양가족의 연결은 키로 해야 한다.
  • ③: 조건과 SELECT 목록은 그럴듯하지만, 빈칸 구조상 NOT IN 앞에 비교할 열(SSN)이 없어 SQL 문법에 맞지 않는다. 참고로 SSN NOT IN (SELECT ESSN FROM DEPENDENT)(비상관)로 쓰면 올바른 대안 질의가 된다. 단, 부질의 결과에 NULL이 섞이면 NOT IN은 결과가 공집합이 되는 함정이 있는데, 이 스키마에서는 ESSN이 NOT NULL이라 그 문제는 없다.

핵심 정리​

  • "~이 없는" 질의 → NOT EXISTS (SELECT * ... WHERE 바깥키 = 안쪽외래키).
  • EXISTS는 좌변 없이, IN은 좌변 열 + 단일 열 부질의로 쓴다.
  • 테이블 간 연결 조건은 기본키–외래키(SSN = ESSN)로 건다.
