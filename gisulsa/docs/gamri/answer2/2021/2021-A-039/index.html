039번 · UML 상태머신 다이어그램의 전이(Transition) 표기법

제22회(2021년) 정보시스템감리사 A형 — 소프트웨어 공학

사전 지식​

1. 상태머신 다이어그램 기본 요소​

요소표기의미
상태(State)모서리가 둥근 사각형객체가 조건을 만족하며 머무는 상황
전이(Transition)화살표한 상태에서 다른 상태로의 이동
초기/종료 상태검은 원 / 테두리 있는 검은 원시작·끝

2. 전이 레이블 문법 (UML 2.x)​

trigger [guard] / effect\text{trigger}\ [\text{guard}]\ /\ \text{effect}trigger [guard] / effect
구성표기의미예
trigger (event)이름 그대로전이를 일으키는 이벤트coinInserted
guard대괄호 [ ]참일 때만 전이가 일어나는 조건[amount >= price]
effect (action)슬래시 / 뒤전이하는 동안 수행하는 행위/ dispense()

세 요소는 모두 생략할 수 있지만, 쓸 때는 순서(trigger → [guard] → / effect)와 구분자가 고정이다.

예: coinInserted [amount >= price] / dispense() — 동전 투입 이벤트가 발생했고 금액이 충분하면, 상품을 내보내면서 다음 상태로 전이한다.

문제​

정답​

②

상세 풀이​

지문은 전이 레이블의 세 구성요소를 순서대로 설명한다.

  1. "trigger 이벤트가 발생하였을 때" → trigger
  2. "guard 조건이 만족하면 전이가 일어나는데" → [guard] — 대괄호
  3. "전이하면서 effect를 수행한다" → / effect — 슬래시 뒤

따라서 (가)에는 trigger [guard] / effect가 들어간다. 정답은 ②.

보기별 판정​

보기판정근거
① trigger [guard] effect오답effect 앞 슬래시 누락 — effect가 trigger/guard와 구분되지 않음
② trigger [guard] / effect✅ 정답UML 표준 문법 그대로
③ trigger / [guard] effect오답슬래시가 guard 앞에 있어 guard가 effect 영역에 들어감
④ trigger / [guard] / effect오답슬래시가 두 번 — 문법에 없는 형태

오답 이유​

  • ①: 슬래시는 "여기서부터 행위(effect)"라는 구분자다. 없으면 effect가 트리거 이름의 일부처럼 읽힌다.
  • ③: / 뒤는 모두 effect로 해석되므로, guard가 조건이 아니라 행위의 일부가 되어 버린다.
  • ④: 구분자 /는 effect 앞에 한 번만 쓴다.

참고로 상태 내부의 행위는 entry / 행위, do / 행위, exit / 행위처럼 쓰며, 여기서도 / 뒤가 행위라는 규칙은 같다.

핵심 정리​

  • 전이 레이블 = trigger [guard] / effect — 이벤트, 대괄호 조건, 슬래시 뒤 행위.
  • 대괄호 = 조건, 슬래시 = 행위 시작. 세 요소 모두 생략 가능하지만 순서는 고정.
  • 상태 내부 행위: entry /, do /, exit /.
