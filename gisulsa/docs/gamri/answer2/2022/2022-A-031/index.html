031번 · 컴포넌트 기반 개발(CBD) — 버틀러 그룹의 컴포넌트 성숙 단계

제23회(2022년) 정보시스템감리사 A형 — 소프트웨어 공학

사전 지식​

1. 버틀러 그룹(Butler Group)의 성숙 모델​

영국 IT 분석기관 버틀러 그룹(문제에는 'Burtler'로 오기)은 조직이 컴포넌트를 활용하는 수준이 기술 단위 → 업무 단위 → 조직 표준으로 발전한다는 6단계 성숙 모델을 제시했다. 국내 CBD 교재·기술사 자료에 널리 인용된다.

단계명칭특징재사용 단위
1GUI 콘트롤 이용 단계버튼·그리드 등 화면 컨트롤(VBX/ActiveX 등)을 가져다 씀화면 부품
2구현 개념 이용 단계DB 접근, 통신, 로깅 등 기술적 기능을 컴포넌트로 사용기술 컴포넌트
3비즈니스 개념 이용 단계고객·주문 등 업무 개념을 컴포넌트로 설계업무 컴포넌트
4컴포넌트 재사용 단계업무 컴포넌트를 여러 시스템에서 체계적으로 재사용프로젝트 간 재사용
5기업 표준 단계컴포넌트 아키텍처·저장소·프로세스가 전사 표준으로 정착전사 자산
6CBD 성숙 단계조립 중심 개발이 일상화되고 지속 개선조직 역량

출처 메모: 버틀러 그룹 원문 보고서는 이번에 직접 확인하지 못했다. 위 단계 구분은 국내 CBD 교재·자료에 널리 인용되는 형태를 따랐고, 공식 정답(①)과도 일치한다.

2. 순서를 외우는 요령​

  • 1~3단계: 무엇을 컴포넌트로 쓰는가 — 화면(GUI) → 기술(구현) → 업무(비즈니스). 추상화 수준이 올라간다.
  • 4~6단계: 조직이 컴포넌트를 어떻게 관리하는가 — 재사용 → 표준화 → 성숙. 관리 범위가 넓어진다.

정답​

①

상세 풀이​

보기 항목을 성숙 모델에 대응시키면 다음과 같다.

단계항목
1가. GUI 콘트롤 이용 단계
2다. 구현 개념 이용 단계
3라. 비즈니스 개념 이용 단계
4마. 컴포넌트 재사용 단계
5바. 기업 표준 단계
6나. CBD 성숙 단계

따라서 가 – 다 – 라 – 마 – 바 – 나 → ①.

네 보기는 모두 '가'로 시작해 '나'로 끝나므로, 실제로 가려야 할 것은 두 쌍이다.

  1. 다(구현) vs 라(비즈니스): 기술적 부품을 먼저 쓰고, 업무 개념을 컴포넌트로 뽑아내는 것은 그다음이다. → 다 → 라 (②·④ 탈락)
  2. 마(재사용) vs 바(기업 표준): 재사용 경험이 쌓여야 전사 표준으로 제도화할 수 있다. → 마 → 바 (③ 탈락)

보기별 판정​

보기순서판정근거
①가-다-라-마-바-나✅ 정답화면 → 기술 → 업무 → 재사용 → 표준 → 성숙
②가-라-다-마-바-나오답비즈니스 개념을 구현 개념보다 앞에 둠
③가-다-라-바-마-나오답기업 표준을 재사용보다 앞에 둠
④가-라-다-바-마-나오답두 쌍 모두 순서가 뒤바뀜

오답 이유​

  • ②: 업무 컴포넌트를 설계하려면 업무 도메인 분석과 인터페이스 설계 역량이 필요하다. 조직은 대개 DB 접근·통신 같은 기술 컴포넌트로 먼저 경험을 쌓은 뒤 업무 개념으로 올라간다.
  • ③: 표준은 실제 재사용 경험을 제도화한 결과다. 재사용 실적 없이 먼저 전사 표준을 선포하는 것은 성숙 모델의 흐름과 반대다.
  • ④: ②와 ③의 오류를 모두 가진다.

핵심 정리​

  • 버틀러 그룹 CBD 성숙 6단계: GUI 콘트롤 이용 → 구현 개념 이용 → 비즈니스 개념 이용 → 컴포넌트 재사용 → 기업 표준 → CBD 성숙.
  • 앞 3단계는 추상화 수준(화면 → 기술 → 업무), 뒤 3단계는 관리 범위(재사용 → 표준 → 성숙)가 올라간다.
  • "기술 다음 업무, 재사용 다음 표준" 두 쌍의 순서만 잡으면 ①이 나온다.
