064번 · 체크포인트 기반 회복(REDO / UNDO)

제24회(2023년) 정보시스템감리사 A형 — 데이터베이스

사전 지식​

1. 로그 기반 회복의 두 연산​

연산대상목적
REDO(재수행)장애 전에 COMMIT된 트랜잭션커밋된 변경이 디스크에 반영되지 않았을 수 있으므로 다시 적용 → 지속성 보장
UNDO(취소)장애 시점까지 COMMIT되지 않은 트랜잭션미완료 변경이 디스크에 반영됐을 수 있으므로 되돌림 → 원자성 보장

2. 체크포인트(checkpoint)​

체크포인트 시점에 메모리 버퍼의 변경 내용과 로그를 디스크에 강제 기록한다. 따라서 체크포인트 이전에 이미 완료(커밋)된 트랜잭션은 회복 시 아무 작업도 필요 없다. 회복 범위가 체크포인트 이후로 줄어드는 것이 핵심 효과다.

3. 트랜잭션 유형별 조치​

유형시작완료(COMMIT)조치
①체크포인트 이전체크포인트 이전없음
②체크포인트 이전체크포인트 이후, 장애 이전REDO
③체크포인트 이전장애 시점까지 미완료UNDO
④체크포인트 이후장애 이전REDO
⑤체크포인트 이후장애 시점까지 미완료UNDO

문제​

정답​

①

상세 풀이​

그림의 각 트랜잭션을 위 표에 대응시킨다.

트랜잭션시작종료유형회복 조치
T1체크포인트 이전체크포인트 이전①없음
T2체크포인트 이전체크포인트 이후·장애 이전 완료②REDO
T3체크포인트 이전장애 시점까지 진행 중③UNDO
T4체크포인트 이후장애 이전 완료④REDO
T5체크포인트 이후장애 시점까지 진행 중⑤UNDO
  • REDO 대상 = T2, T4
  • UNDO 대상 = T3, T5
  • T1은 체크포인트 때 이미 디스크에 반영되었으므로 대상이 아니다.

따라서 "T2, T4 트랜잭션은 재수행한다"는 ①이 정답이다.

보기별 판정​

보기판정근거
① T2, T4 재수행✅ 정답두 트랜잭션 모두 장애 전에 커밋 → REDO
② T2, T4 취소오답커밋된 트랜잭션을 취소하면 지속성 위반
③ T3, T4, T5 재수행오답T3·T5는 미완료 → UNDO 대상. T2가 REDO 목록에서 빠짐
④ T3, T4, T5 취소오답T4는 커밋 완료 → REDO 대상. UNDO는 T3, T5뿐

오답 이유​

  • ②: 커밋 여부가 회복 방향을 결정한다. 커밋된 T2·T4를 취소하면 사용자에게 완료를 통보한 결과가 사라진다.
  • ③·④: T3, T4, T5를 한데 묶은 것은 "체크포인트 이후에 걸쳐 있는 트랜잭션" 정도의 기준으로, 커밋 여부를 구분하지 않은 것이다. T4는 완료 → REDO, T3·T5는 미완료 → UNDO로 방향이 서로 다르다.

핵심 정리​

  • 커밋됨 → REDO, 미커밋 → UNDO, 체크포인트 이전 완료 → 조치 없음.
  • 체크포인트는 회복 탐색 범위를 줄여 준다.
  • 이 문제: REDO = T2, T4 / UNDO = T3, T5 / 무시 = T1.
