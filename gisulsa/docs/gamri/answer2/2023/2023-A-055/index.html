055번 · ER 모델의 약한 개체(weak entity)

제24회(2023년) 정보시스템감리사 A형 — 데이터베이스

사전 지식​

1. 강한 개체와 약한 개체​

구분강한 개체(Strong/Regular entity)약한 개체(Weak entity)
키 속성자신의 키 속성을 가짐자신의 키 속성이 없음
식별 방법자신의 키로 식별소유 개체(owner entity)의 키 + 부분 키(partial key) 로 식별
표기단일 사각형이중 사각형, 부분 키는 점선 밑줄

2. 식별 관계(Identifying relationship)​

  • 약한 개체를 그 소유 개체(식별 개체) 와 연결하는 관계 타입. 이중 마름모로 표기한다.
  • 약한 개체는 소유 개체 없이는 식별될 수 없으므로 식별 관계에 대해 항상 전체 참여(total participation) 한다(이중선).

예: EMPLOYEE(강한 개체) — DEPENDENTS_OF(식별 관계) — DEPENDENT(약한 개체, 부분 키 Name). 부양가족은 직원 번호 + 부양가족 이름으로 식별되며, 모든 부양가족은 반드시 어떤 직원에 속해야 한다.

3. 존재 종속과 약한 개체의 관계​

  • 약한 개체는 소유 개체에 존재 종속(existence dependency) 된다.
  • 그러나 역은 성립하지 않는다. 존재 종속이 있다고 해서 모두 약한 개체는 아니다. 예를 들어 DRIVER_LICENSE는 PERSON에 존재 종속이지만 자신의 키(면허번호)가 있으므로 강한 개체다.
약한 개체⇒존재 종속(O),존재 종속⇒약한 개체(X)\text{약한 개체} \Rightarrow \text{존재 종속} \quad(\text{O}), \qquad \text{존재 종속} \Rightarrow \text{약한 개체} \quad(\text{X})약한 개체⇒존재 종속(O),존재 종속⇒약한 개체(X)

정답​

상세 풀이​

"옳지 않은 것"을 고르는 문항이다.

  1. ① 자기 자신의 키 속성을 가지지 않는 개체 타입 = 약한 개체 타입. → 정의 그대로. 옳음.
  2. ② 약한 개체를 소유(강한) 개체와 연결하는 관계 = 식별 관계. → 옳음.
  3. ③ "약한 개체가 식별 관계에 대해 전체 참여 제약을 가질 필요는 없다." → 틀림. 약한 개체는 소유 개체의 키를 빌려야만 식별될 수 있으므로, 모든 약한 개체 인스턴스가 식별 관계에 참여해야 한다. 즉 항상 전체 참여다. → 정답.
  4. ④ "모든 존재 종속이 약한 개체 타입이 될 필요는 없다." → 존재 종속이지만 자신의 키를 가진 강한 개체가 있을 수 있으므로 옳음.

보기별 판정​

보기판정근거
① 자신의 키 속성이 없는 개체 = 약한 개체오답 보기(옳은 설명)약한 개체의 정의
② 약한 개체와 강한 개체를 연결하는 관계 = 식별 관계오답 보기(옳은 설명)식별 관계의 정의(이중 마름모)
③ 식별 관계에 전체 참여할 필요 없음✅ 정답(옳지 않은 설명)약한 개체는 식별 관계에 항상 전체 참여
④ 모든 존재 종속이 약한 개체일 필요는 없음오답 보기(옳은 설명)존재 종속이면서 자기 키가 있는 강한 개체 존재 가능

오답 이유​

  • ①: Elmasri·Navathe 교재의 정의 "Entity types that do not have key attributes of their own are called weak entity types"와 일치한다.
  • ②: 교재의 "identifying relationship of the weak entity type"과 일치한다.
  • ③: 교재는 "A weak entity type always has a total participation constraint (existence dependency) with respect to its identifying relationship"이라고 명시한다. 전체 참여가 없다면 소유 개체가 없는 약한 개체 인스턴스가 존재하게 되어 식별 자체가 불가능하다.
  • ④: 교재는 이어서 "not every existence dependency results in a weak entity type"이라고 하며, 운전면허(DRIVER_LICENSE)처럼 자체 키를 가진 존재 종속 개체의 예를 든다.

핵심 정리​

  • 약한 개체 = 자신의 키 없음 → 소유 개체 키 + 부분 키로 식별.
  • 약한 개체는 식별 관계에 항상 전체 참여(이중선) — "필요 없다"는 틀린 서술.
  • 약한 개체 ⇒ 존재 종속이지만, 존재 종속 ⇏ 약한 개체.
  • 표기: 약한 개체 이중 사각형, 식별 관계 이중 마름모, 부분 키 점선 밑줄.
