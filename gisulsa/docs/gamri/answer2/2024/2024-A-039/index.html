039번 · ISO/IEC 5055의 소스코드 품질 특성

제25회(2024년) 정보시스템감리사 A형 — 소프트웨어 공학

사전 지식​

1. ISO/IEC 5055:2021은 무엇인가​

정식 명칭은 ISO/IEC 5055:2021 — Information technology — Software measurement — Software quality measurement — Automated source code quality measures(자동화된 소스코드 품질 측정)다.

  • 제정 배경: OMG 산하 CISQ(Consortium for Information & Software Quality) 가 만든 ASCQM(Automated Source Code Quality Measures) 명세를 국제표준으로 승격한 것이다.
  • 측정 방식: 소스코드에 존재하는 심각한 약점(weakness) 을 정적 분석으로 탐지하고 그 개수를 세는 방식으로 품질을 정량화한다.
  • 특징: 소프트웨어의 운영 중 행위(behavior) 가 아니라 내부 구조(internal, structural aspects) 에서 직접 품질을 측정하는 최초의 ISO 표준이다.
  • CWE 연계: 각 측정에 포함된 약점은 모두 MITRE의 CWE(Common Weakness Enumeration) 에 등재된 항목이며, CWE는 ITU 표준이기도 하다. 즉 5055는 "CWE 중에서 가장 심각한 것들을 골라 품질 특성별로 묶은 목록"에 가깝다.

2. ISO/IEC 5055가 정의하는 4개 품질 특성​

특성원어측정 대상 약점의 예
신뢰성Reliability자원 누수, null 역참조, 예외 미처리, 초기화되지 않은 변수 사용, 동시성 결함
보안성SecuritySQL 인젝션 가능 코드, 하드코딩된 자격증명, 입력 검증 누락, 안전하지 않은 암호 사용
성능 효율성Performance Efficiency반복문 내부의 비효율적 DB 호출, 불필요한 객체 생성, 인덱스 미사용 쿼리 패턴
유지보수성Maintainability과도한 순환 복잡도, 중복 코드, 과도한 결합도, 죽은 코드, 지나치게 긴 모듈

암기 요령: R-S-P-M (Reliability, Security, Performance efficiency, Maintainability). 이 넷은 ISO/IEC 25010의 8개 품질 특성 중 4개를 골라낸 것이다.

3. ISO/IEC 25010과의 관계 — 8개 중 4개만 선택​

ISO/IEC 25010(제품 품질 모델)의 8개 품질 특성과 5055의 포함 여부를 대조하면 다음과 같다.

#ISO/IEC 25010 품질 특성ISO/IEC 5055 포함 여부이유
1Functional Suitability(기능 적합성)✕요구사항과의 일치 여부이므로 요구 명세 없이 코드만으로 판정 불가
2Performance Efficiency(성능 효율성)○비효율 코드 패턴을 정적으로 탐지 가능
3Compatibility(호환성)✕다른 제품·환경과의 상호운용은 실행 환경 의존
4Usability(사용성)✕사용자와 UI의 상호작용을 통해서만 평가 가능. 코드에 "사용하기 어려움"이라는 약점 패턴이 존재하지 않음
5Reliability(신뢰성)○자원 누수·예외 미처리 등 장애 유발 코드 패턴 탐지 가능
6Security(보안성)○CWE 기반 취약 코드 패턴 탐지 가능
7Maintainability(유지보수성)○복잡도·중복·결합도 등 구조적 지표로 측정 가능
8Portability(이식성)✕대상 플랫폼 정보가 있어야 판정 가능

선택 기준은 단 하나 — "소스코드만 보고 자동으로 측정할 수 있는가"다. 사용성·기능 적합성·호환성·이식성은 모두 코드 외부의 정보(사용자, 요구 명세, 실행 환경, 대상 플랫폼) 를 필요로 하므로 제외되었다.

4. 관련 표준 계보 정리​

표준대상특징
ISO/IEC 9126소프트웨어 제품 품질25010의 전신. 6개 특성(기능성·신뢰성·사용성·효율성·유지보수성·이식성)
ISO/IEC 25010 (SQuaRE 계열)제품 품질 + 사용 품질제품 품질 8개 특성. 9126을 확대·개정
ISO/IEC 25023품질 측정25010 특성별 측정 지표(metric) 정의
ISO/IEC 5055소스코드 품질25010의 4개 특성을 약점 개수로 자동 측정
ISO/IEC 25000 계열품질 요구·평가 전반SQuaRE 프레임워크
CWE (MITRE, ITU 표준)소프트웨어 약점 사전5055가 참조하는 약점 식별 체계

5. 혼동하기 쉬운 인접 개념​

착각실제
5055는 25010을 대체한다대체가 아니라 25010의 부분집합을 코드 수준에서 자동 측정하는 보완 표준
Usability는 어느 품질 표준에도 없다ISO/IEC 25010의 8개 특성 중 하나다. 다만 5055에는 없다
Portability가 5055에 있다없다. 대상 플랫폼 정보가 필요하므로 자동 측정 불가
5055는 취약점(vulnerability)만 다룬다보안성은 4개 특성 중 하나일 뿐이고, 신뢰성·성능 효율성·유지보수성도 동등하게 다룬다

상세 풀이​

"ISO/IEC 5055에서 제시하고 있는 품질 특성으로 가장 적절하지 않은 것"을 고르는 부정형 문항이다. 5055의 4개 특성 목록(Reliability, Security, Performance Efficiency, Maintainability)을 먼저 확정하고, 보기 중 여기에 없는 것을 찾으면 된다.

  1. ① Maintainability(유지보수성) — 5055의 4개 특성 중 하나. 순환 복잡도, 중복 코드, 과도한 결합도 등 구조적 약점을 정적으로 계수할 수 있다. → 포함
  2. ② Security(보안성) — 5055의 4개 특성 중 하나. CWE에 등재된 취약 코드 패턴을 탐지한다. → 포함
  3. ③ Reliability(신뢰성) — 5055의 4개 특성 중 하나. 자원 누수, null 역참조, 예외 미처리 등을 탐지한다. → 포함
  4. ④ Usability(사용성) — 5055에 없다. 사용성은 ISO/IEC 25010의 8개 특성에는 존재하지만, 사용자가 UI를 통해 시스템과 상호작용하는 과정에서만 평가되는 외부 품질이므로 소스코드 정적 분석으로는 측정할 수 없다. → 미포함 = 정답

보기에 등장하지 않은 나머지 하나인 Performance Efficiency 가 5055의 네 번째 특성이라는 점도 함께 기억해 두면, "보기 중 어느 것이 빠졌는가"를 역으로 확인하는 데 도움이 된다.

보기별 판정​

보기판정근거
① Maintainability오답 보기(5055에 포함됨)4개 특성 중 하나. 복잡도·중복·결합도 등 구조적 약점을 계수
② Security오답 보기(5055에 포함됨)4개 특성 중 하나. CWE 기반 취약 코드 패턴 탐지
③ Reliability오답 보기(5055에 포함됨)4개 특성 중 하나. 자원 누수·예외 미처리 등 장애 유발 패턴 탐지
④ Usability✅ 정답 보기(5055에 없음)ISO/IEC 25010에는 있으나 소스코드만으로 자동 측정 불가하여 5055 대상에서 제외

오답 이유​

  • ①이 포함되는 이유: 유지보수성은 코드의 구조 자체가 곧 측정 대상이다. 순환 복잡도, 모듈 크기, 중복 코드 비율, 팬인/팬아웃, 죽은 코드 같은 지표는 소스코드를 파싱하는 것만으로 산출된다. 5055가 측정하려는 "구조적 품질"의 가장 전형적인 예다.
  • ②가 포함되는 이유: 보안 약점은 CWE라는 잘 정립된 목록이 있고, 대부분이 코드 패턴(검증 없이 입력을 쿼리에 이어 붙이기, 자격증명 하드코딩 등)으로 표현되므로 정적 분석 도구가 탐지하기에 적합하다. 5055가 참조하는 약점이 모두 CWE 항목이라는 점이 이를 뒷받침한다.
  • ③이 포함되는 이유: 신뢰성 측면의 약점(예외 경로에서 자원 미해제, null 검사 누락, 초기화되지 않은 변수 사용, 동시성 위반)도 구문·데이터 흐름 분석으로 검출 가능하다. 5055는 이런 약점의 개수를 신뢰성 측정값으로 삼는다.
  • ④가 포함되지 않는 이유: 사용성은 "사용자가 얼마나 쉽게 배우고, 효율적으로 쓰고, 오류를 덜 내는가"를 뜻한다. 이는 사용자라는 외부 요소와의 상호작용을 관찰해야 알 수 있는 값이라서, 코드를 아무리 정밀하게 분석해도 "이 코드는 사용성이 낮다"는 판정을 내릴 수 있는 약점 패턴이 존재하지 않는다. 같은 이유로 Functional Suitability(요구 명세 필요), Compatibility(실행 환경 필요), Portability(대상 플랫폼 필요) 도 5055에서 빠졌다. 5055는 25010의 8개 특성 중 코드 수준에서 자동 측정 가능한 4개만 골라낸 표준이다.

핵심 정리​

  • ISO/IEC 5055:2021은 CISQ/OMG의 ASCQM을 국제표준화한 것으로, 소스코드의 심각한 약점(weakness)을 탐지·계수해 품질을 측정한다. 각 약점은 CWE에 등재된 항목이다.
  • 5055의 4개 품질 특성 = R·S·P·M: Reliability, Security, Performance Efficiency, Maintainability.
  • ISO/IEC 25010의 8개 특성 중 기능 적합성·호환성·사용성·이식성은 5055에서 제외된다. 모두 코드 바깥의 정보(요구 명세, 실행 환경, 사용자, 대상 플랫폼)가 있어야 평가할 수 있기 때문이다.
  • Usability는 25010에는 있고 5055에는 없다 — 두 표준의 특성 개수(8 vs 4)와 그 차집합을 구분하는 것이 이 문제의 결정타다. 보기에 4개 중 3개만 올리고 25010 쪽 특성 하나를 섞어 넣는 출제 방식이 반복되므로, R·S·P·M 네 단어를 통째로 외워 두는 것이 가장 확실하다.
  • 근거: ISO/IEC 5055:2021 표준 개요(ISO), CISQ Code Quality Standards — 4개 특성이 Security·Reliability·Performance Efficiency·Maintainability이며 이는 ISO/IEC 25010의 8개 특성 중 4개에 해당한다는 서술을 확인했다.
