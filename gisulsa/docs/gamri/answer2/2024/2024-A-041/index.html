041번 · Python 리스트 메소드 추적 (pop / insert / index)

제25회(2024년) 정보시스템감리사 A형 — 소프트웨어 공학

사전 지식​

1. 파이썬 리스트의 기본 성질​

성질설명
순서가 있음(sequence)원소가 들어간 순서대로 저장되며 인덱스로 접근한다
인덱스는 0부터길이 nnn 인 리스트의 유효 인덱스는 0∼n−10 \sim n-10∼n−1. 음수 인덱스는 뒤에서부터 세어 -1이 마지막 원소
가변(mutable)원소를 넣고 빼면 원본 리스트 자체가 바뀐다. 새 리스트가 만들어지는 것이 아니다
중복 허용같은 값이 여러 번 들어갈 수 있다

이 문제의 함정은 세 번째 성질에 있다. pop과 insert는 모두 제자리(in-place) 연산이므로, 한 줄이 실행될 때마다 그 다음 줄이 보는 리스트의 내용과 인덱스가 전부 달라진다. 따라서 마지막 줄만 보고 답을 낼 수 없고 5줄을 순서대로 추적해야 한다.

2. 원소를 꺼내는 메소드​

메소드인자동작반환값대상이 없을 때
lst.pop()없음맨 뒤 원소를 꺼내 제거꺼낸 원소IndexError
lst.pop(i)인덱스인덱스 i 의 원소를 꺼내 제거꺼낸 원소IndexError
lst.remove(x)값그 값을 가진 첫 번째 원소 제거NoneValueError
del lst[i]인덱스인덱스 i 의 원소 제거(식이 아님)IndexError

핵심은 pop()의 기본 인자가 -1(맨 뒤)이라는 점, 그리고 pop은 값을 돌려주는데 remove는 None을 돌려준다는 점이다. 이 문제는 꺼낸 값을 pop, pop2 변수에 담아 나중에 다시 넣으므로, 반환값이 있는 pop을 쓰는 것이 필수적이다.

3. 원소를 넣는 메소드​

메소드동작예시(['a','b','c'] 기준)
lst.append(x)맨 뒤에 하나 추가append('z') → ['a','b','c','z']
lst.insert(i, x)인덱스 i 자리에 x를 넣고, 원래 i 이후 원소를 한 칸씩 뒤로 민다insert(1,'z') → ['a','z','b','c']
lst.extend(it)반복 가능 객체의 원소들을 낱개로 뒤에 이어 붙임extend('z') → ['a','b','c','z']

insert(i, x)를 "인덱스 i 앞에 넣는다"라고 외우든 "삽입 후 x의 인덱스가 i가 된다"라고 외우든 결과는 같다. 후자가 추적할 때 더 편하다 — insert(1, 'c')를 하면 'c'의 인덱스가 1이 된다고 바로 확정할 수 있다.

4. 위치를 찾는 index()​

lst.index(x)는 값 x와 같은 첫 번째 원소의 인덱스를 0-기반으로 돌려준다. 값이 없으면 ValueError가 발생한다. lst.index(x, start, end)처럼 탐색 구간을 줄 수도 있으나 본 문항에서는 쓰이지 않았다.

5. 혼동하기 쉬운 인접 개념​

혼동 지점올바른 이해
pop(1) 을 "1개 꺼내기"로 오해인자는 개수가 아니라 인덱스다. pop(1)은 두 번째 원소를 꺼낸다
pop() 을 맨 앞 원소 제거로 오해기본값은 -1, 즉 맨 뒤다. 큐처럼 앞을 빼려면 pop(0) 또는 collections.deque.popleft()
insert(i, x) 의 인자 순서(인덱스, 값) 순서다. insert('c', 1)처럼 뒤집으면 TypeError
sorted(lst) 와 lst.sort()전자는 새 리스트 반환, 후자는 제자리 정렬 후 None 반환. 본 문항의 pop/insert도 제자리 계열
인덱스와 개수인덱스 3은 네 번째 원소다. 답을 셀 때 1부터 세면 그대로 오답이 된다

상세 풀이​

계산(추적) 유형이다. 5줄을 한 줄씩 실행하며 리스트의 상태를 기록한다.

단계실행 문장반환값실행 후 language인덱스
0language = ['python','java','go','ruby','c']—['python','java','go','ruby','c']0:python 1:java 2:go 3:ruby 4:c
1pop = language.pop()pop = 'c'['python','java','go','ruby']0:python 1:java 2:go 3:ruby
2pop2 = language.pop(1)pop2 = 'java'['python','go','ruby']0:python 1:go 2:ruby
3language.insert(1, pop) → insert(1,'c')None['python','c','go','ruby']0:python 1:c 2:go 3:ruby
4language.insert(2, pop2) → insert(2,'java')None['python','c','java','go','ruby']0:python 1:c 2:java 3:go 4:ruby
5print(language.index('go'))3(변화 없음)'go' 는 4번째 = 인덱스 3

단계별로 짚으면 다음과 같다.

  1. 1단계 — pop()은 인자가 없으므로 맨 뒤의 'c'를 꺼낸다. 리스트 길이는 5 → 4가 된다.
  2. 2단계 — pop(1)은 현재 리스트의 인덱스 1을 꺼낸다. 1단계에서 이미 'c'가 빠졌지만 앞쪽은 그대로이므로 인덱스 1은 여전히 'java'다. 길이는 4 → 3.
  3. 3단계 — insert(1,'c')로 'c'가 인덱스 1 자리에 들어가고 'go', 'ruby'가 한 칸씩 뒤로 밀린다. 이 시점에서 'go'의 인덱스는 1 → 2가 된다.
  4. 4단계 — insert(2,'java')로 'java'가 인덱스 2 자리를 차지하고, 다시 'go', 'ruby'가 한 칸씩 밀린다. 'go'의 인덱스는 2 → 3.
  5. 5단계 — index('go')는 그 3을 그대로 출력한다.

실제 Python 인터프리터로 위 스크립트를 실행해 각 단계의 리스트 상태와 최종 출력 3이 표와 일치함을 확인하였다.

요령: 삽입이 두 번 일어나는 동안 'go'의 인덱스만 추적해도 된다. 2단계 직후 'go'는 인덱스 1 → insert(1,…)로 +1 → insert(2,…)로 +1 → 최종 3. 삽입 지점이 'go'의 앞쪽일 때만 인덱스가 밀린다는 규칙을 쓰면 리스트 전체를 다시 쓰지 않아도 된다.

보기별 판정​

보기판정근거
① 3✅ 정답 보기최종 리스트 ['python','c','java','go','ruby']에서 'go'의 0-기반 인덱스 = 3
② 2오답 보기insert를 한 번만 반영했거나 pop(1)을 맨 뒤 제거로 오인한 값
③ 1오답 보기두 번의 insert를 모두 'go' 뒤쪽 삽입으로 보아 인덱스가 밀리지 않는다고 본 값
④ 0오답 보기index()를 "존재 여부(0/1)"나 리스트의 첫 원소 반환으로 오해한 값

오답 이유​

  • ①이 맞는 이유: pop()(맨 뒤), pop(1)(인덱스 1), insert(1,·), insert(2,·)를 순서대로 적용하면 최종 리스트는 ['python','c','java','go','ruby']이고, 0-기반으로 python(0)·c(1)·java(2)·go(3)·ruby(4)이므로 출력은 3이다.
  • ②가 틀린 이유: 2가 되려면 'go' 앞에 삽입이 한 번만 일어나야 한다. 그러나 insert(1,'c')와 insert(2,'java')는 둘 다 당시 'go'의 인덱스보다 앞이거나 같은 자리에 넣으므로 인덱스가 두 번 밀린다. pop(1)을 "마지막 원소 제거"로 오해해 'ruby'를 빼면 중간 상태가 달라져 2가 나오기도 한다.
  • ③이 틀린 이유: 1은 pop 두 번 직후의 'go' 인덱스로, 두 번의 insert를 반영하지 않은 값이다. insert가 제자리 연산이어서 원본이 바뀐다는 점을 놓치면 이 값이 나온다.
  • ④가 틀린 이유: index()는 존재 여부를 뜻하는 불리언이 아니라 위치를 돌려준다. 0이 되려면 'go'가 맨 앞이어야 하는데, 'python'은 어느 단계에서도 제거되지 않으므로 'go'가 인덱스 0에 올 수 없다.

핵심 정리​

  • pop() = 맨 뒤(기본값 -1), pop(i) = 인덱스 i. 인자는 개수가 아니다. 둘 다 꺼낸 값을 반환한다.
  • insert(i, x) = 삽입 후 x의 인덱스가 i가 되도록 넣고, 뒤쪽 원소를 한 칸씩 민다. remove/sort/insert/append는 모두 None을 반환하는 제자리 연산이다.
  • index(x)는 0-기반 위치를 반환한다. 네 번째 원소의 인덱스는 3이다.
  • pop·insert가 원본 리스트를 매 줄 바꾸므로, 각 줄을 실행한 직후의 리스트를 적어 가며 추적해야 한다 — 관심 원소('go')의 인덱스만 따라가면 "앞쪽 삽입 1회 = +1"로 간단히 3을 얻는다.
