063번 · 뷰 참조 질의의 질의 변경(query modification)

제25회(2024년) 정보시스템감리사 A형 — 데이터베이스

사전 지식​

1. 뷰(view)란 무엇인가​

뷰는 하나 이상의 기본 테이블로부터 유도된 가상 테이블(virtual table) 이다.

성질내용
저장되는 것질의 정의문(SELECT 문)만 카탈로그에 저장
저장되지 않는 것뷰의 데이터 자체(구체화 뷰는 예외)
사용자에게 보이는 모습일반 테이블과 동일
목적논리적 데이터 독립성, 접근 권한 제어, 복잡한 질의의 단순화

핵심은 "뷰에는 데이터가 없다" 는 점이다. 따라서 뷰를 참조하는 질의가 들어오면 DBMS는 어떤 방식으로든 실제 기본 테이블에 대한 질의로 바꿔야 실행할 수 있다.

2. 뷰 처리 방식 두 가지​

방식원리장점단점
질의 변경
(query modification, view merging)		질의문의 뷰 참조를 뷰 정의문으로 치환해 하나의 질의로 합친 뒤 실행중간 결과 저장 불필요, 최적화기가 전체를 한꺼번에 최적화뷰가 복잡하면 치환된 질의가 커짐
뷰 구체화
(view materialization)		뷰 정의를 먼저 실행해 임시 릴레이션을 실제로 만든 뒤 그 위에서 질의뷰를 여러 번 참조할 때 유리저장 공간·갱신 동기화 비용

이 문제는 질의 변경 방식을 묻는다.

3. 질의 변경의 3단계 규칙​

뷰 참조 질의를 기본 테이블 질의로 바꿀 때 지켜야 할 것은 딱 세 가지다.

단계하는 일절대 빠뜨리면 안 되는 것
① FROM 치환뷰 이름을 뷰 정의의 FROM 절로 교체뷰 정의에 들어 있던 모든 테이블
② WHERE 결합뷰 정의의 WHERE 조건과 외부 질의의 WHERE 조건을 AND로 연결조인 조건(S.sid=E.sid)도 뷰 정의 WHERE의 일부이므로 반드시 보존
③ SELECT 대응외부 질의가 참조한 뷰 컬럼명을 뷰 정의의 대응 원본 식으로 교체뷰 컬럼과 원본 컬럼의 위치 대응(1번째↔1번째, 2번째↔2번째 …)

실수의 대부분은 ②에서 나온다. WHERE 절에는 필터 조건과 조인 조건이 섞여 있는데, 필터 조건만 옮기고 조인 조건을 빠뜨리면 질의가 카티션 곱(cartesian product) 이 되어 결과가 완전히 달라진다.

4. 뷰 컬럼명 재정의와 위치 대응​

CREATE VIEW BStudents (name, sid, cid)
AS SELECT S.name, S.sid, E.cid
   FROM Students S, Enrolled E
   WHERE S.sid = E.sid AND E.grade = 'B';

CREATE VIEW 뒤 괄호의 컬럼 목록은 SELECT 절 식들과 순서대로 1:1 대응된다.

뷰 컬럼위치대응 원본 식
name1번째S.name (학생 이름)
sid2번째S.sid
cid3번째E.cid

함정: Enrolled 테이블에도 name 이라는 컬럼이 있다(과목명 DB, OS). 뷰 컬럼 name 이라는 이름이 같다고 해서 E.name 을 가리키는 것이 아니다. 위치 대응에 따라 S.name 이다.

5. 이 문제의 인스턴스​

Students (PK: sid)

sidnameage
53666Jones18
53688Smith18
53650Smith19

Enrolled (PK: cid, sid, name)

cidsidnamegrade
10153666DBB
10153688DBC
10253666OSA

Enrolled의 name 은 학생 이름이 아니라 과목명이라는 점에 주의한다.

6. 혼동하기 쉬운 인접 개념​

개념내용이 문제에서
조인 조건 vs 필터 조건조인 조건은 테이블을 묶고, 필터 조건은 행을 거름S.sid=E.sid(조인) / E.grade='B'(필터) — 둘 다 보존해야 함
카티션 곱조인 조건 없는 FROM A, B조인 조건을 빠뜨리면 3×3=9행에서 필터만 적용됨
뷰 컬럼명 = 원본 컬럼명이름이 같아도 위치 대응이 우선뷰의 name ↔ S.name (≠ E.name)
질의 변경 vs 구체화치환 vs 임시 릴레이션 생성본 문항은 치환

문제​

정답​

③

상세 풀이​

1단계 — 뷰 정의를 조각내기​

(가) CREATE VIEW BStudents (name, sid, cid)
     AS SELECT S.name, S.sid, E.cid          -- 투영
        FROM   Students S, Enrolled E        -- 대상 테이블
        WHERE  S.sid = E.sid                 -- ★ 조인 조건
           AND E.grade = 'B';                -- ★ 필터 조건
조각내용
FROMStudents S, Enrolled E
WHERES.sid=E.sid AND E.grade='B' — 두 조건 모두
컬럼 대응name→S.name, sid→S.sid, cid→E.cid

2단계 — 외부 질의 확인​

(나) SELECT name
     FROM   BStudents
     WHERE  cid = '101';
조각내용
투영뷰 컬럼 name → 치환하면 S.name
FROM뷰 BStudents → 치환하면 Students S, Enrolled E
WHERE뷰 컬럼 cid='101' → 치환하면 E.cid='101'

3단계 — 치환 수행​

① FROM 치환

FROM Students S, Enrolled E

② WHERE 결합 — 뷰 정의의 WHERE 전체 AND 외부 WHERE

WHERE S.sid = E.sid AND E.grade = 'B' AND E.cid = '101'

③ SELECT 대응 — 뷰 컬럼 name 의 원본은 1번째 위치의 S.name

SELECT S.name

최종 변환 결과

SELECT S.name
FROM   Students S, Enrolled E
WHERE  S.sid = E.sid AND E.grade = 'B' AND E.cid = '101';

이는 보기 ③ 과 완전히 일치한다.

4단계 — 실행으로 검증​

SQLite에 위 스키마·인스턴스·뷰를 그대로 만들고 네 보기를 모두 실행했다.

질의실행 결과
뷰 BStudents 전체('Jones', 53666, '101') — 1행
(나) 원본 뷰 질의 SELECT name FROM BStudents WHERE cid='101'Jones
① SELECT S.name ... WHERE E.grade='B' AND E.cid='101'Jones, Smith, Smith (3행) ❌
② SELECT E.name ... WHERE E.grade='B' AND E.cid='101'DB, DB, DB (3행) ❌
③ SELECT S.name ... WHERE S.sid=E.sid AND E.grade='B' AND E.cid='101'Jones ✅
④ SELECT E.name ... WHERE S.sid=E.sid AND E.grade='B' AND E.cid='101'DB ❌

원본 뷰 질의와 결과가 일치하는 것은 ③ 뿐이다.

5단계 — 왜 ①·②가 3행이 되는가​

S.sid=E.sid 가 없으면 FROM Students S, Enrolled E 는 카티션 곱 3×3 = 9행을 만든다. 여기에 E.grade='B' AND E.cid='101' 을 적용하면 Enrolled에서 살아남는 행은 (101, 53666, DB, B) 하나뿐이지만, Students 쪽은 제약이 전혀 없어 3행이 모두 결합된다. 그 결과 9행 중 3행이 통과하고, S.name 을 투영하면 Jones, Smith, Smith 가 나온다. 조인 조건 하나를 빠뜨린 대가로 결과가 1행에서 3행으로 부풀었다.

보기별 판정​

보기판정근거
① SELECT S.name / E.grade='B' AND E.cid='101'오답 보기조인 조건 S.sid=E.sid 누락 → 카티션 곱. 실행 결과 Jones, Smith, Smith 3행으로 원본(1행)과 불일치
② SELECT E.name / E.grade='B' AND E.cid='101'오답 보기조인 조건 누락 + 투영이 E.name(과목명). 실행 결과 DB, DB, DB
③ SELECT S.name / S.sid=E.sid AND E.grade='B' AND E.cid='101'✅ 정답 보기뷰 정의의 FROM·WHERE 전체가 보존되고 외부 조건이 AND로 추가됨. 투영도 위치 대응상 S.name. 실행 결과 Jones 로 원본과 일치
④ SELECT E.name / S.sid=E.sid AND E.grade='B' AND E.cid='101'오답 보기WHERE는 옳으나 투영이 E.name(과목명 DB) 이라 뷰 컬럼 대응과 불일치. 실행 결과 DB

오답 이유​

  • ①이 틀린 이유: 질의 변경은 뷰 정의의 WHERE 절 전체를 가져와야 한다. S.sid=E.sid 는 "필터"가 아니라 "조인"이라는 이유로 성격이 다를 뿐, WHERE 절의 일부라는 점은 같다. 이를 누락하면 두 테이블이 무조건 결합되는 카티션 곱이 되고, 실제로 결과가 1행에서 3행으로 늘어났다. 이 보기에 S.sid=E.sid AND 를 추가하면 곧바로 ③이 된다.

  • ②가 틀린 이유: ①의 조인 조건 누락 문제에 더해 투영 대상까지 틀렸다. E.name 은 Enrolled 테이블의 name, 즉 과목명(DB, OS)이다. 뷰의 name 은 CREATE VIEW BStudents (name, sid, cid) AS SELECT S.name, ... 의 위치 대응에 따라 학생 이름 S.name 이다. 두 군데가 동시에 틀려 결과가 DB, DB, DB 로 나왔다.

  • ③이 맞는 이유: 세 단계 규칙을 모두 지켰다. FROM은 Students S, Enrolled E 로 치환되고, WHERE는 뷰 정의의 S.sid=E.sid AND E.grade='B' 에 외부 조건 E.cid='101' 이 AND로 붙었으며, SELECT는 뷰 컬럼 name 의 원본 식인 S.name 이 되었다. 실행 결과 Jones 한 행으로 원본 뷰 질의와 정확히 일치한다.

  • ④가 틀린 이유: WHERE 절은 ③과 동일하게 올바르지만 투영만 E.name 이다. 컬럼 이름이 name 으로 같다는 이유로 Enrolled의 name 을 골랐다면 함정에 걸린 것이다. 뷰 컬럼과 원본 컬럼의 대응은 이름이 아니라 SELECT 절에서의 위치로 결정된다. SELECT E.name 을 SELECT S.name 으로 고치면 ③과 같아진다.

핵심 정리​

  • 질의 변경(query modification) 은 뷰 참조를 뷰 정의로 치환(view merging) 하는 기법이다. ① FROM 치환, ② WHERE를 AND로 결합, ③ SELECT 컬럼을 원본 식으로 대응 — 이 세 단계를 기계적으로 적용하면 된다.
  • 뷰 정의의 WHERE 절은 조인 조건을 포함해 통째로 보존해야 한다. 조인 조건을 빠뜨리면 카티션 곱이 되어 결과 행이 부풀어 오른다(본 문제에서 1행 → 3행).
  • 뷰 컬럼과 원본 컬럼의 대응은 이름이 아니라 CREATE VIEW (...) 목록에서의 위치로 결정된다. 뷰의 name 은 S.name 이지 동명의 E.name 이 아니다.
  • 이 문제의 결정타: 조인 조건 S.sid=E.sid 보존(①·② 탈락)과 투영 S.name 선택(②·④ 탈락)을 동시에 만족하는 것은 ③ 하나뿐이다.
