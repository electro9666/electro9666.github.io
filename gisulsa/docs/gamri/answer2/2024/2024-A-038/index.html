038번 · 소프트웨어 유지관리 용이성을 향상시키는 개발 활동

제25회(2024년) 정보시스템감리사 A형 — 소프트웨어 공학

사전 지식​

1. 유지보수성(Maintainability)이란​

ISO/IEC 25010 제품 품질 모델에서 유지보수성은 8개 품질 특성 중 하나이며, 다음 5개의 부특성으로 나뉜다.

부특성의미이를 높이는 설계 원칙
Modularity(모듈성)구성 요소를 독립적으로 나눌 수 있는 정도높은 응집도, 낮은 결합도
Reusability(재사용성)다른 시스템에서 다시 쓸 수 있는 정도일반화, 의존성 분리
Analysability(분석성)변경 영향 범위를 파악하고 결함 원인을 찾기 쉬운 정도단순한 제어 흐름, 명확한 명명, 문서화
Modifiability(수정성)결함 주입 없이 고칠 수 있는 정도정보 은닉, 캡슐화, 국소화
Testability(시험성)테스트 기준을 세우고 수행하기 쉬운 정도경로 수가 적은 구조, 부작용 최소화

유지보수 비용은 전체 생명주기 비용의 상당 부분(통상 60~80%)을 차지하므로, 설계·구현 단계에서 유지보수성을 확보하는 것이 소프트웨어 공학의 핵심 과제다.

2. 구조적 프로그래밍(Structured Programming)의 원칙​

유지보수성 관련 문항에서 가장 자주 출제되는 원칙이다.

(1) 세 가지 기본 제어 구조만 사용한다 (Böhm–Jacopini 정리)

구조의미
순차(sequence)문장을 차례대로 실행
선택(selection)if, switch 로 분기
반복(iteration)while, for 로 반복

이 세 가지만으로 계산 가능한 모든 프로그램을 작성할 수 있으므로 goto 같은 임의 분기는 불필요하다는 것이 정리의 요지다.

(2) 단일 진입점·단일 출구점(Single Entry, Single Exit)

모든 모듈(또는 제어 구조 블록)은 들어가는 곳이 하나, 나오는 곳이 하나여야 한다.

구분구조결과
단일 엔트리·단일 엑시트블록의 시작이 한 곳, 끝이 한 곳제어 흐름이 선형적으로 합성 가능. 각 블록을 블랙박스처럼 치환해 추론할 수 있음
복수 엔트리·복수 엑시트블록 중간으로 뛰어들거나(goto label), 여러 지점에서 빠져나감가능한 실행 경로가 조합적으로 증가. 어디서 어디로 흐르는지 추적 불가

3. 복수 엔트리·복수 엑시트가 유지보수성을 해치는 메커니즘​

구체적으로 어떤 부특성이 어떻게 나빠지는지 정리하면 다음과 같다.

부특성악영향
Analysability(분석성)모듈에 도달하는 경로가 여러 개이므로 "여기 도달했을 때 어떤 상태인가" 를 하나로 가정할 수 없다. 결함 추적 시 모든 진입 경로를 전부 확인해야 한다
Modifiability(수정성)한 지점을 고치면 어느 진입 경로에서 왔느냐에 따라 다른 부작용이 생긴다. 회귀 결함 위험 증가
Testability(시험성)순환 복잡도(cyclomatic complexity) 가 커져 경로 커버리지를 달성하는 데 필요한 테스트케이스 수가 폭증한다
Modularity(모듈성)모듈 경계가 무너져 다른 모듈 내부로 직접 뛰어들 수 있게 되면 캡슐화가 깨진다

정량적으로는 맥케이브 순환 복잡도 V(G) = E − N + 2 (E: 간선, N: 노드) 로 측정되며, 진입점·출구점이 늘어날수록 간선이 늘어 V(G)가 커진다. V(G)는 독립 경로의 수이자 기본 경로 테스트에 필요한 최소 테스트케이스 수이므로, 이 값이 커진다는 것은 곧 이해 비용과 테스트 비용이 함께 커진다는 뜻이다.

4. 단계별로 유지보수성을 높이는 활동​

개발 단계유지보수성 향상 활동효과
분석표준·지침 수립 및 준수(코딩 표준, 명명 규칙, 문서 표준), 요구사항 추적성 확보산출물의 일관성 → 이해 가능성(understandability)·분석성 향상
기본(상위) 설계정보 은닉(information hiding), 자료 추상화(data abstraction), 하향식 계층 분해(top-down decomposition), 응집도 향상·결합도 감소변경의 파급 범위를 모듈 내부로 국소화
상세 설계각 루틴의 부작용(side effect) 명시, 예외 처리 방안 정립, 인터페이스 사전/사후 조건 정의변경 시 예상치 못한 영향 예방, 오류 상황의 예측 가능성 확보
구현단일 엔트리·단일 엑시트, 제어 구조 3종 사용, goto 금지, 주석·자기 문서화 코드제어 흐름 단순화 → 복잡도 감소
시험·이행회귀 테스트 자동화, 형상 관리, 인수인계 문서변경 후 검증 비용 절감

5. 혼동하기 쉬운 인접 개념​

개념의미유지보수성과의 관계
정보 은닉모듈 내부의 설계 결정(자료 구조, 알고리즘)을 외부에 감춤내부를 바꿔도 외부가 영향받지 않음 → 향상
자료 추상화자료의 표현을 감추고 연산으로만 접근표현 변경의 파급 차단 → 향상
하향식 계층 분해큰 기능을 단계적으로 작은 모듈로 분해관심사 분리, 계층 간 의존 단순화 → 향상
복수 엔트리·엑시트모듈에 진입·탈출 지점이 여럿경로 폭증, 복잡도 증가 → 저하
(참고) early return현대 언어에서 가드 절로 조기 반환하는 관용구실무에서는 가독성을 위해 허용되기도 하나, 감리 시험에서는 구조적 프로그래밍 원칙(단일 출구)을 기준으로 판단한다

상세 풀이​

"유지관리 용이성을 향상시키는 개발 활동으로 가장 적절하지 않은 것"을 고르는 부정형 문항이다. 보기 네 개 중 셋은 유지보수성을 높이는 활동이고, 하나는 오히려 낮추는 활동이다.

각 보기를 "어떤 단계의 활동인가 + 유지보수성에 어떤 방향으로 작용하는가"로 판정한다.

  1. ① 표준과 지침을 개발하여 실시하는 분석 활동 — 코딩 표준·명명 규칙·문서 표준을 수립하고 준수하면 산출물의 형태가 통일되어 누가 읽어도 같은 방식으로 이해할 수 있다. 분석성과 수정성이 함께 올라간다. → 향상
  2. ② 복수 엔트리, 복수 엑시트 구조를 사용한 구현 활동 — 구조적 프로그래밍의 단일 진입·단일 출구 원칙에 정면으로 위배된다. 제어 흐름 경로가 조합적으로 늘어나 순환 복잡도가 커지고, 이해·추적·테스트·수정이 모두 어려워진다. → 저하 = 정답
  3. ③ 정보은닉, 자료 추상화, 하향식 계층 분배 원리를 관할한 기본 설계 활동 — 세 원칙 모두 응집도를 높이고 결합도를 낮추는 고전적 설계 원칙이다. 변경의 파급이 모듈 내부로 국한된다. → 향상
  4. ④ 각 루틴에 대한 부작용과 예외조치 방안을 정립한 상세 설계 활동 — 부작용을 문서화하면 유지보수자가 변경의 영향 범위를 정확히 알 수 있고, 예외 처리 방안을 미리 정하면 비정상 경로의 동작이 예측 가능해진다. → 향상

유일하게 방향이 반대인 ②가 정답이다.

보기별 판정​

보기판정근거
① 표준·지침 수립 및 실시(분석)오답 보기(적절한 활동)산출물 일관성 확보 → 이해 가능성·분석성 향상
② 복수 엔트리·복수 엑시트 구조 사용(구현)✅ 정답 보기(적절하지 않은 활동)구조적 프로그래밍의 단일 진입·단일 출구 원칙 위배. 경로 폭증 → 순환 복잡도 증가 → 이해·테스트·수정 난이도 상승
③ 정보은닉·자료추상화·하향식 계층 분해(기본 설계)오답 보기(적절한 활동)응집도 향상·결합도 감소 → 변경 파급 국소화
④ 부작용·예외조치 방안 정립(상세 설계)오답 보기(적절한 활동)변경 영향 예측 가능, 비정상 경로 동작 명확화

오답 이유​

  • ①이 적절한 이유: 유지보수는 대개 원 개발자가 아닌 사람이 수행한다. 표준과 지침이 없으면 모듈마다 명명 규칙·주석 양식·오류 처리 방식이 제각각이 되어, 유지보수자가 코드를 읽는 데 드는 시간이 급증한다. 표준의 수립·적용은 ISO/IEC 25010의 Analysability를 직접 끌어올리는 활동이다.
  • ②가 부적절한 이유: 구조적 프로그래밍은 "모든 모듈은 하나의 입구와 하나의 출구를 갖는다" 를 전제로 성립한다. 이 전제가 있어야 각 블록을 하나의 상자로 추상화해 위에서 아래로 읽어 내려갈 수 있다. 복수 엔트리를 허용하면 모듈 중간의 어떤 문장이 실행될 때 앞선 어떤 문장들이 실행된 상태인지 확정할 수 없고, 복수 엑시트를 허용하면 어느 지점에서 자원 해제·후처리가 수행되는지 보장할 수 없다(자원 누수·상태 불일치의 원인). 그 결과 순환 복잡도 V(G)가 증가해 기본 경로 테스트에 필요한 케이스 수도 함께 늘어난다. 올바른 서술로 고치려면 "단일 엔트리, 단일 엑시트 구조를 사용한 구현 활동" 이 되어야 한다.
  • ③이 적절한 이유: 세 원칙이 겨냥하는 바는 모두 같다. 정보 은닉은 "바뀔 가능성이 높은 설계 결정"을 모듈 내부에 감춰 변경이 밖으로 새어 나가지 않게 하고, 자료 추상화는 자료 표현을 연산 뒤에 숨겨 표현 변경의 파급을 막으며, 하향식 계층 분해는 상위 계층이 하위 계층의 세부를 모르게 해 계층 간 의존을 단순화한다. 셋 다 "변경의 국소화"라는 유지보수성의 본질을 직접 겨냥한다.
  • ④가 적절한 이유: 유지보수 중 발생하는 결함의 상당수는 예상치 못한 부작용에서 비롯된다. 어떤 루틴이 전역 상태나 인자를 변경하는지 상세 설계 단계에서 명시해 두면, 유지보수자가 그 루틴을 호출·수정할 때 영향 범위를 정확히 판단할 수 있다. 예외 조치 방안 역시 마찬가지로, 비정상 경로에서의 동작을 설계 시점에 확정해 두어야 나중에 임기응변식 처리가 쌓이는 것을 막는다.

핵심 정리​

  • 구조적 프로그래밍의 2대 원칙: ① 제어 구조는 순차·선택·반복 세 가지만, ② 모든 모듈은 단일 진입점·단일 출구점(Single Entry, Single Exit).
  • 유지보수성(ISO/IEC 25010) 부특성 5종: 모듈성 / 재사용성 / 분석성 / 수정성 / 시험성.
  • 단계별 유지보수성 향상 활동: 분석 = 표준·지침, 기본 설계 = 정보은닉·자료추상화·계층 분해, 상세 설계 = 부작용·예외 처리 명시, 구현 = 단일 엔트리·단일 엑시트.
  • 순환 복잡도 V(G) = E − N + 2 는 독립 경로 수이자 기본 경로 테스트의 최소 케이스 수다. 진입·출구가 늘면 V(G)가 커진다.
  • "복수 엔트리·복수 엑시트"는 구조적 프로그래밍 원칙의 정반대 표현이므로, 유지보수성을 묻는 문항에서 이 문구가 보이면 곧바로 정답 후보다. 이것이 이 문제의 결정타다.
