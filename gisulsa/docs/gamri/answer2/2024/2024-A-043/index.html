043번 · TMMi 레벨 2 「테스트 계획」 프로세스 영역의 목표

제25회(2024년) 정보시스템감리사 A형 — 소프트웨어 공학

사전 지식​

1. TMMi가 무엇인가​

TMMi(Test Maturity Model integration) 는 TMMi Foundation이 발간하는 테스트 프로세스 성숙도 모델이다. CMMI가 개발 조직 전반의 성숙도를 다루는 것과 달리 TMMi는 테스트 활동에 특화되어 있으며, CMMI의 단계적(staged) 표현과 구조·용어를 의도적으로 맞추어 두 모델을 병행 적용할 수 있게 설계되었다.

구조 요소영문설명
성숙도 레벨Maturity Level1~5의 5단계. 상위 레벨은 하위 레벨을 모두 충족해야 달성
프로세스 영역Process Area (PA)각 레벨을 구성하는 활동 묶음. PA 2.1 처럼 번호가 붙는다
특정 목표Specific Goal (SG)해당 PA가 달성해야 할 목표. 본 문항이 묻는 "세부 목표"
특정 실무Specific Practice (SP)SG를 달성하기 위한 구체 활동
일반 목표/실무Generic Goal / Practice모든 PA에 공통 적용되는 제도화 요건

2. TMMi 성숙도 레벨 5단계​

레벨명칭요지
1Initial테스트가 혼돈 상태. 정의된 프로세스가 없고 디버깅과 테스트를 구분하지 못함. 프로세스 영역 없음
2Managed테스트가 프로젝트 단위로 계획·관리됨. 테스트가 개발과 분리된 활동으로 인식됨
3Defined테스트가 조직 표준 프로세스로 정의되고 개발 생명주기 전체에 통합됨. 비기능 테스트·리뷰 도입
4Measured테스트가 측정되고 품질이 정량 평가됨. 정적 분석·동료 검토 제도화
5Optimization결함 예방·품질 통제·테스트 프로세스 지속 최적화

3. 레벨 2(Managed)의 5개 프로세스 영역과 특정 목표​

본 문항의 핵심 표다. PA 2.1과 PA 2.2의 목표를 구분할 수 있어야 한다.

PA명칭특정 목표(SG)
PA 2.1Test Policy and Strategy (테스트 정책 및 전략)SG1 Establish a Test Policy
SG2 Establish a Test Strategy
SG3 Establish Test Performance Indicators
PA 2.2Test Planning (테스트 계획)SG1 Perform a Product Risk Assessment
SG2 Establish a Test Approach
SG3 Establish Test Estimates
SG4 Develop a Test Plan
SG5 Obtain Commitment to the Test Plan
PA 2.3Test Monitoring and Control (테스트 모니터링 및 통제)SG1 Monitor Test Progress against Plan
SG2 Monitor Product Quality against Plan and Expectations
SG3 Manage Corrective Action to Closure
PA 2.4Test Design and Execution (테스트 설계 및 수행)SG1 Perform Test Analysis and Design using Test Design Techniques
SG2 Perform Test Implementation
SG3 Perform Test Execution
SG4 Manage Test Incidents to Closure
PA 2.5Test Environment (테스트 환경)SG1 Develop Test Environment Requirements
SG2 Perform Test Environment Implementation
SG3 Manage and Control Test Environments

근거: TMMi Framework R1.2 / R1.3, Chapter "Level 2: Managed", PA 2.1 및 PA 2.2 Specific Goals (TMMi Foundation 공식 배포본).

4. 왜 "테스트 성능 지표"는 정책·전략 쪽인가​

테스트 성능 지표(Test Performance Indicators) 는 조직이 테스트 개선의 성과를 측정하기 위해 정하는 조직 수준의 KPI다. "테스트 전략이 잘 작동하고 있는가"를 판단하는 잣대이므로, 개별 프로젝트마다 다시 세우는 것이 아니라 테스트 정책·전략을 세울 때 함께 정의된다. 그래서 PA 2.1의 SG3에 놓인다.

반면 테스트 계획(PA 2.2) 은 철저히 프로젝트 단위 활동이다. 이번 프로젝트의 제품 위험을 평가하고(SG1), 그 위험에 맞는 테스트 접근 방식을 정하고(SG2), 필요한 공수·기간을 추정하고(SG3), 이를 테스트 계획서로 묶은 뒤(SG4), 이해관계자의 승인·약속을 확보(SG5)하는 흐름이다. 이 순서 자체가 하나의 이야기로 이어진다는 점을 기억하면 SG1~SG5를 통째로 외우기 쉽다.

5. 혼동하기 쉬운 인접 개념​

혼동구분
Test Policy/Strategy vs Test Plan정책·전략은 조직 수준·장기, 계획은 프로젝트 수준·단기
Test Performance Indicators vs Test Progress Monitoring전자는 PA 2.1(지표 정의), 후자는 PA 2.3(지표로 감시)
제품 위험 평가(PA 2.2 SG1) vs 프로젝트 위험 관리TMMi의 제품 위험 평가는 무엇을 얼마나 테스트할지 정하기 위한 것
TMMi vs TPI NEXT둘 다 테스트 프로세스 개선 모델. TMMi는 단계적 성숙도 레벨, TPI NEXT는 핵심영역별 성숙도 매트릭스
TMMi vs CMMITMMi는 테스트 특화. 레벨 번호와 구조는 CMMI와 정렬되어 있으나 PA 목록은 전혀 다르다

상세 풀이​

"가장 적절하지 않은 것"을 고르는 부정형 문항이다. 네 보기 모두 TMMi 레벨 2에 실재하는 특정 목표이므로, "존재하지 않는 목표"를 찾는 문제가 아니라 소속 프로세스 영역이 다른 목표를 찾는 문제라는 점이 함정이다.

  1. ① Perform a Product Risk Assessment — PA 2.2 Test Planning의 SG1. 테스트 계획의 출발점으로 제품 위험을 식별·분석해 테스트 범위와 우선순위를 정한다. → 테스트 계획의 목표가 맞다.
  2. ② Establish a Test Approach — PA 2.2의 SG2. SG1에서 도출한 위험에 대응하는 테스트 수준·유형·기법·종료 조건을 정한다. → 맞다.
  3. ③ Establish Test Estimates — PA 2.2의 SG3. 정해진 접근 방식을 수행하는 데 드는 공수·일정·자원을 추정한다. → 맞다.
  4. ④ Establish Test Performance Indicators — PA 2.1 Test Policy and Strategy의 SG3. 조직의 테스트 정책·전략이 목표를 달성했는지 측정할 지표를 정의하는 목표로, 같은 레벨 2에 속하지만 테스트 계획 영역의 목표가 아니다. → 부적절 = 정답.

정리하면 PA 2.2의 SG는 SG1~SG5(위험평가 → 접근방식 → 추정 → 계획서 작성 → 승인 확보)이며, ①·②·③이 각각 SG1·SG2·SG3에 정확히 대응한다. 남은 ④만이 다른 PA 소속이다.

보기별 판정​

보기판정근거
① 제품 위험 평가 수행오답 보기(적절한 설명)PA 2.2 Test Planning SG1 Perform a Product Risk Assessment
② 테스트 접근 방식 설정오답 보기(적절한 설명)PA 2.2 Test Planning SG2 Establish a Test Approach
③ 테스트 추정치 설정오답 보기(적절한 설명)PA 2.2 Test Planning SG3 Establish Test Estimates
④ 테스트 성능 지표 설정✅ 정답 보기(적절하지 않은 설명)PA 2.1 Test Policy and Strategy SG3 소속 — 레벨 2이긴 하나 테스트 계획 영역이 아님

오답 이유​

  • ①이 적절한 이유: TMMi는 위험 기반 테스팅(risk-based testing)을 전제로 하므로, 테스트 계획의 첫 목표가 제품 위험 평가다. 무엇이 고장 났을 때 피해가 큰지를 먼저 정해야 테스트 범위와 강도를 합리적으로 배분할 수 있다.
  • ②가 적절한 이유: 접근 방식(test approach)은 SG1의 위험 평가 결과를 실행 가능한 형태 — 테스트 수준, 테스트 유형, 적용 기법, 진입·종료 기준 — 로 번역한 것이다. 계획 수립의 중간 단계로 PA 2.2에 속한다.
  • ③이 적절한 이유: 접근 방식이 정해져야 필요한 공수·기간·인력·환경 비용을 산정할 수 있다. 추정치는 다음 목표인 SG4(테스트 계획서 작성)의 직접 입력물이므로 계획 영역의 본질적 목표다.
  • ④가 부적절한 이유: "테스트 성능 지표 설정"은 개별 프로젝트 계획이 아니라 조직의 테스트 정책·전략 수립 활동의 일부다. TMMi Framework에서 이 목표는 PA 2.1 Test Policy and Strategy의 SG3으로 명시되어 있다. 올바른 서술로 바꾸려면 "테스트 계획의 세부 목표"가 아니라 "테스트 정책 및 전략 프로세스 영역의 세부 목표"라고 해야 한다. 만약 PA 2.2의 나머지 목표를 묻고 싶었다면 SG4 Develop a Test Plan 또는 SG5 Obtain Commitment to the Test Plan 이 들어갔어야 한다.

핵심 정리​

  • TMMi 레벨 2(Managed)의 5개 PA: 2.1 정책·전략 / 2.2 계획 / 2.3 모니터링·통제 / 2.4 설계·수행 / 2.5 환경.
  • PA 2.2 Test Planning의 SG1~SG5: 제품 위험 평가 → 테스트 접근 방식 → 테스트 추정 → 테스트 계획서 작성 → 계획 승인(commitment) 확보. 하나의 흐름으로 외운다.
  • PA 2.1 Test Policy and Strategy의 SG1~SG3: 테스트 정책 수립 → 테스트 전략 수립 → 테스트 성능 지표 수립.
  • "Establish Test Performance Indicators"는 조직 수준 지표이므로 PA 2.1 소속이다 — 레벨 2에 존재하는 목표라는 점에서 헷갈리게 만든 것이 이 문제의 결정타다.
