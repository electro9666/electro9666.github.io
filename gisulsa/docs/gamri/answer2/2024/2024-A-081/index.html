081번 · SSD 가비지 컬렉션 효율을 높이는 OS 기능

제25회(2024년) 정보시스템감리사 A형 — 시스템 구조

사전 지식​

1. NAND 플래시의 근본 제약 — 읽기/쓰기/삭제 단위가 다르다​

SSD의 저장 매체인 NAND 플래시는 자기 디스크(HDD)와 달리 덮어쓰기(overwrite)가 불가능하다. 이유는 셀 구조에 있다. 셀에 전자를 주입(program)하는 것은 페이지 단위로 가능하지만, 전자를 빼내는(erase) 동작은 블록 전체에 고전압을 가해야 하므로 블록 단위로만 가능하다.

동작단위전형적 크기소요 시간(대략)
읽기(read)페이지4 ~ 16 KB수십 µs
쓰기(program)페이지4 ~ 16 KB수백 µs
삭제(erase)블록128 ~ 512 페이지 (수 MB)수 ms

핵심은 "쓰기는 페이지 단위, 삭제는 블록 단위" 이고, 한 번 쓴 페이지는 블록 전체를 지우기 전에는 다시 쓸 수 없다는 점이다.

2. 그래서 FTL과 가비지 컬렉션이 필요하다​

이 제약을 감추기 위해 SSD 컨트롤러 안에는 FTL(Flash Translation Layer) 이라는 소프트웨어 계층이 있다. FTL은 호스트가 보는 논리 주소(LBA) 를 실제 물리 페이지 주소(PPA) 로 매핑하는 표를 관리한다.

호스트가 이미 데이터가 있는 LBA에 새 값을 쓰면 FTL은 다음과 같이 동작한다.

단계동작
1비어 있는 새 페이지에 새 데이터를 쓴다 (out-of-place update)
2매핑 표에서 해당 LBA가 새 페이지를 가리키도록 갱신한다
3이전 페이지를 "무효(invalid)" 로 표시한다 (아직 물리적으로 지우지는 못함)

이렇게 무효 페이지가 쌓이면 쓸 수 있는 빈 페이지가 고갈된다. 이때 FTL이 수행하는 청소 작업이 가비지 컬렉션(Garbage Collection, GC) 이다.

[GC 대상 블록 A]                        [빈 블록 B]
 페이지0: 유효 ──── 복사 ──────────────▶ 페이지0: 유효
 페이지1: 무효  (버림)
 페이지2: 유효 ──── 복사 ──────────────▶ 페이지1: 유효
 페이지3: 무효  (버림)
          ↓
   블록 A 통째로 erase → 빈 블록으로 재사용

GC는 "유효 페이지만 다른 블록으로 옮긴 뒤 원래 블록을 지우는" 작업이므로, 옮겨야 할 유효 페이지가 적을수록 빠르고 효율적이다.

3. 쓰기 증폭(Write Amplification)​

WAF=NAND에 실제로 기록된 양호스트가 요청한 기록량\text{WAF} = \frac{\text{NAND에 실제로 기록된 양}}{\text{호스트가 요청한 기록량}}WAF=호스트가 요청한 기록량NAND에 실제로 기록된 양​

GC가 유효 페이지를 복사하는 만큼 NAND에는 호스트가 요청하지 않은 추가 쓰기가 발생한다. WAF가 커지면 성능이 떨어지고 셀의 P/E(Program/Erase) 사이클을 빠르게 소모해 수명이 줄어든다. GC가 복사할 유효 페이지를 줄이는 것 = WAF를 낮추는 것이다.

4. 파일 삭제의 "정보 단절" 문제와 TRIM​

사용자가 파일을 지우면 운영체제의 파일시스템은 메타데이터(비트맵, 디렉터리 엔트리)만 수정하고 데이터 블록 자체는 건드리지 않는다. 그 결과 다음과 같은 어긋남이 생긴다.

관점해당 LBA의 상태
파일시스템(OS)"빈 공간" — 더 이상 쓸모없는 데이터
SSD의 FTL"유효한 데이터" — 호스트가 언제든 읽을 수 있음

FTL은 그 페이지가 죽었다는 사실을 모르므로, GC 때 이미 쓰레기인 데이터를 성실하게 복사한다. 이 낭비를 없애기 위해 OS가 SSD에게 "이 LBA들은 더 이상 유효하지 않다"고 알려 주는 명령이 필요하다. 그것이 TRIM이다.

인터페이스명령 이름
ATA / SATATRIM (DATA SET MANAGEMENT 명령의 Deallocate 비트)
NVMeDeallocate (Dataset Management 명령)
SCSI / SASUNMAP (또는 WRITE SAME with UNMAP)

TRIM을 받은 FTL은 해당 페이지를 즉시 무효로 표시한다. 그러면 GC가 복사할 유효 페이지 수가 줄어 GC가 빨라지고 WAF가 낮아진다. TRIM은 파일시스템이 발행하는 명령이므로 명백히 운영체제 차원의 기능이다.

5. 혼동하기 쉬운 인접 개념 — "누가 수행하는가"​

이 문제의 함정은 전부 "SSD와 관련은 있지만 주체가 다른" 기능들이다.

기능수행 주체목적GC 효율과의 관계
TRIM운영체제(파일시스템)무효 LBA 통보GC 복사량 직접 감소 ✅
마모 평준화(wear leveling)SSD 컨트롤러(FTL)블록별 P/E 횟수 균등화 → 수명 연장GC와 협력하지만 OS 기능이 아님
미러링(mirroring)RAID 컨트롤러/소프트웨어RAID-1 이중화로 가용성 확보SSD 내부 GC와 무관
캐시 교체 정책CPU 하드웨어 / OS 페이지 관리캐시 적중률 향상플래시 GC와 무관
오버프로비저닝(OP)SSD 제조사(펌웨어)여유 블록 확보GC 효율에 기여하나 OS 기능 아님

정답​

상세 풀이​

"가장 적절한 것"을 고르는 긍정형 문항이다. 지문이 요구하는 조건은 두 가지이며, 둘 다 만족해야 정답이다.

  1. 가비지 컬렉션의 효율을 높이는 기능일 것
  2. 운영체제 차원에서 지원하는 기능일 것

이 두 조건을 각 보기에 대해 교차 검증한다.

보기조건 1 (GC 효율 향상)조건 2 (OS 차원)결과
① TRIM✅ 무효 페이지를 알려 복사량 감소✅ 파일시스템이 발행둘 다 충족
② 미러링❌ 무관❌ RAID 계층탈락
③ 마모 평준화△ 간접 관련❌ SSD 컨트롤러(FTL) 내부 기능탈락
④ 캐시 교체 정책❌ 무관△ OS/HW탈락

③ 마모 평준화가 가장 강력한 함정이다. SSD 수명 관리와 직결되고 GC와도 맞물려 동작하기 때문이다. 그러나 마모 평준화는 "어느 블록에 쓸 것인가"를 FTL이 스스로 결정하는 것으로, 운영체제는 관여하지도 않고 관여할 수도 없다(OS는 물리 블록 주소를 볼 수 없다). 문제가 굳이 "운영체제 차원에서 지원하는" 이라는 한정어를 붙인 것은 바로 이 구분을 묻기 위함이다.

TRIM이 실제로 GC를 어떻게 개선하는가 — 시나리오 비교​

블록 하나가 8페이지이고, 그중 4페이지가 "삭제된 파일"의 데이터라고 하자.

상황블록 상태GC 시 복사할 페이지결과
TRIM 미지원유효 8 (FTL 관점)8페이지 복사WAF 상승, GC 지연
TRIM 지원유효 4 / 무효 44페이지 복사복사량 절반, GC 가속

극단적으로 블록 전체가 TRIM된 경우 복사할 유효 페이지가 0이 되어 GC는 erase만 수행하면 된다. 이것이 TRIM이 "GC 효율을 증대시킨다"고 말하는 정확한 의미다.

보기별 판정​

보기판정근거
① TRIM✅ 정답 보기OS가 무효 LBA를 SSD에 통보하는 명령. GC가 복사할 유효 페이지를 줄여 쓰기 증폭을 낮춘다
② 미러링(mirroring)오답 보기RAID-1의 데이터 이중화 기법. 가용성 확보가 목적이며 플래시 GC와 무관
③ 마모 평준화(wear leveling)오답 보기블록별 P/E 사이클을 균등화하는 SSD 컨트롤러(FTL) 내부 기능. OS 기능이 아님
④ 캐시 교체 정책오답 보기LRU·LFU 등 캐시 희생자 선택 알고리즘. 플래시 GC와 무관

오답 이유​

  • ①이 맞는 이유: NAND는 페이지 단위 쓰기 / 블록 단위 삭제라는 비대칭 때문에 무효 페이지를 회수하는 GC가 필수인데, OS가 파일을 지워도 FTL은 그 사실을 알 수 없다. TRIM(ATA), Deallocate(NVMe), UNMAP(SCSI)은 파일시스템이 "이 LBA는 폐기되었다"고 SSD에 알리는 표준 명령이다. 이를 받은 FTL이 해당 페이지를 즉시 무효 처리하므로 GC가 옮겨야 할 유효 페이지가 줄고, 결과적으로 쓰기 증폭(WAF)이 낮아지며 GC 지연도 감소한다. 지문의 "운영체제 차원에서 지원하는 기능"이라는 한정과 정확히 일치한다.
  • ②가 틀린 이유: 미러링은 동일 데이터를 두 개 이상의 디스크에 복제해 하나가 고장나도 서비스를 유지하는 RAID-1의 가용성 기법이다. SSD 한 대 내부의 플래시 블록 회수 문제와는 층위 자체가 다르다. 오히려 미러링은 같은 쓰기를 두 배로 발생시키므로 GC 부담을 늘리면 늘렸지 줄이지 않는다.
  • ③이 틀린 이유: 마모 평준화는 특정 블록만 반복 사용되어 먼저 마모되는 것을 막기 위해 P/E 사이클 횟수가 적은 블록에 우선 배치하는 기법으로, GC와 함께 FTL이 수행한다. 설명 자체는 옳지만 수행 주체가 SSD 컨트롤러이지 운영체제가 아니다. OS는 논리 주소만 다루므로 물리 블록의 마모도를 알 수도, 제어할 수도 없다. "GC 효율 증대"라는 목적과도 직접 대응하지 않는다(목적은 수명 연장이다).
  • ④가 틀린 이유: 캐시 교체 정책(LRU, LFU, FIFO, Optimal 등)은 캐시가 가득 찼을 때 어떤 블록을 내보낼지 고르는 알고리즘이다. CPU 캐시나 페이지 캐시의 적중률을 다루는 개념으로, NAND 블록의 무효 페이지 회수와는 아무 관련이 없다.

핵심 정리​

  • NAND 플래시: 쓰기는 페이지 단위, 삭제는 블록 단위 → 덮어쓰기 불가 → out-of-place update → 무효 페이지 누적 → 가비지 컬렉션 필요.
  • 쓰기 증폭(WAF) = NAND 실제 기록량 / 호스트 요청량. GC가 복사하는 유효 페이지가 많을수록 WAF가 커지고 성능·수명이 나빠진다.
  • TRIM(ATA) = Deallocate(NVMe) = UNMAP(SCSI). 세 이름은 같은 개념의 인터페이스별 명칭이므로 함께 외운다.
  • 결정타: "누가 수행하는가"로 가른다. TRIM은 운영체제(파일시스템)가 발행하는 명령이고, 마모 평준화·GC·오버프로비저닝은 모두 SSD 컨트롤러(FTL) 내부 기능이다. 문제의 "운영체제 차원에서 지원하는"이라는 한정어가 ③을 배제하는 결정적 근거다.
