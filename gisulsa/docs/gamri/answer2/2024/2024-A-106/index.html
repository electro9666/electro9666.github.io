106번 · 블록암호 운용 모드 GCM(Galois/Counter Mode)

제25회(2024년) 정보시스템감리사 A형 — 보안

사전 지식​

1. 블록암호 운용 모드 비교​

블록암호(AES 등)는 고정 길이 블록 하나만 처리하므로, 임의 길이 메시지를 다루려면 운용 모드(mode of operation) 가 필요하다.

모드제공 서비스병렬 처리비고
ECB기밀성(약함)암·복호화 모두 가능같은 평문 블록 → 같은 암호문 블록. 사용 금지
CBC기밀성암호화 ✗ / 복호화 ○패딩 오라클 공격 주의
CTR기밀성암·복호화 모두 가능블록암호를 스트림암호처럼 사용. 카운터 재사용 금지
CCM기밀성 + 무결성제한적CTR + CBC-MAC 결합 (AEAD)
GCM기밀성 + 무결성·인증암·복호화 모두 가능CTR + GHASH (AEAD). NIST SP 800-38D

2. AEAD와 GCM의 위치​

AEAD(Authenticated Encryption with Associated Data) 는 다음 세 가지를 한 번에 제공하는 암호 방식이다.

  • 기밀성(Confidentiality) — 평문 보호
  • 무결성(Integrity)·인증(Authentication) — 암호문 변조 탐지
  • 연관 데이터(AAD) 인증 — 암호화하지 않지만 변조는 막아야 하는 헤더(IP/포트, 프로토콜 버전, 시퀀스 번호 등)까지 인증 범위에 포함

GCM 은 NIST SP 800-38D 「Recommendation for Block Cipher Modes of Operation: Galois/Counter Mode (GCM) and GMAC」(2007) 로 표준화된 대표 AEAD 모드다. TLS 1.2의 AES_128_GCM 계열, TLS 1.3의 필수 알고리즘, IPsec ESP, SSH, 802.11ac 등에 널리 쓰인다.

3. GCM의 내부 구조​

GCM은 두 갈래로 동작한다.

                    ┌──────────────── 암호화 갈래 (CTR 모드) ───────────────┐
  IV ──► J0 ──► inc32 ──► CB1, CB2, … ──► E_K ──► 키스트림 ──(XOR)──► 암호문 C
   │                                                                    │
   └──► E_K(J0) ───────────────┐                                        ▼
                               │              ┌───── 인증 갈래 (GHASH) ─────┐
   H = E_K(0^128) ─────────────┼────────────► GHASH(H, A, C) ──► S        │
                               └──────────(XOR)──────────────────────► 인증 태그 T
단계내용
① 해시 서브키 생성H=EK(0128)H = E_K(0^{128})H=EK​(0128) — 전부 0인 블록을 암호화한 값
② 초기 카운터 블록IV가 96비트면 J0=IV∥031∥1J_0 = IV \parallel 0^{31} \parallel 1J0​=IV∥031∥1, 아니면 GHASH로 유도
③ 암호화Ci=Pi⊕EK(inc32i(J0))C_i = P_i \oplus E_K(\mathrm{inc32}^i(J_0))Ci​=Pi​⊕EK​(inc32i(J0​)) — CTR 모드
④ 인증S=GHASH(H, A, C)S = \mathrm{GHASH}(H,\ A,\ C)S=GHASH(H, A, C) — AAD와 암호문을 입력으로 누적
⑤ 태그 생성T=MSBt(S⊕EK(J0))T = \mathrm{MSB}_t(S \oplus E_K(J_0))T=MSBt​(S⊕EK​(J0​)) — 보통 t=128t = 128t=128비트

복호화 시에는 태그를 먼저 검증하고, 불일치하면 평문을 절대 반환하지 않는다(FAIL 반환).

4. GHASH — '해시 함수'라는 표현의 정확한 의미​

GHASH\mathrm{GHASH}GHASH 는 유한체 GF(2128)\mathrm{GF}(2^{128})GF(2128) 위의 곱셈을 반복하는 함수다. 입력 블록 X1,…,XmX_1, \dots, X_mX1​,…,Xm​ 에 대해

Y0=0,Yi=(Yi−1⊕Xi)⋅HY_0 = 0,\qquad Y_i = (Y_{i-1} \oplus X_i) \cdot HY0​=0,Yi​=(Yi−1​⊕Xi​)⋅H

를 반복하고 마지막 YmY_mYm​ 이 결과가 된다. 여기서 ⋅\cdot⋅ 는 기약다항식 f(x)=x128+x7+x2+x+1f(x)=x^{128}+x^7+x^2+x+1f(x)=x128+x7+x2+x+1 로 정의된 GF(2128)\mathrm{GF}(2^{128})GF(2128) 곱셈이다.

즉 GHASH는 SHA-256 같은 암호학적 해시 함수가 아니라, 키(HHH)에 의존하는 유니버설 해시(universal hash) 다. 시험 보기에서 "MAC 값 생성을 위해 해시 함수를 사용한다"고 할 때의 '해시 함수'는 GHASH를 가리키는 다소 거친 표현이며, SHA 계열을 쓴다는 뜻이 아니다. (SHA 기반 MAC은 HMAC이고, 이는 GCM과 별개다.)

GHASH가 키에 의존한다는 점은 중요하다. HHH 를 모르면 태그를 위조할 수 없기 때문에 인증이 성립한다. 반대로 같은 키로 같은 IV(nonce)를 재사용하면 HHH 가 노출되어 태그 위조가 가능해진다 — GCM의 가장 유명한 운용상 제약(nonce misuse)이다.

5. 계산으로 확인하기​

GCM 규격의 표준 테스트 벡터(키·IV 모두 0, AES-128)를 파이썬으로 직접 계산해 보면 위 구조가 그대로 확인된다.

계산 결과가 규격의 공식 태그 값과 정확히 일치한다. 즉 GCM은 암호문에 대해 실제로 인증 태그를 만들어 내며, 이 태그가 무결성을 보장한다.

6. 혼동하기 쉬운 인접 개념​

구분기밀성무결성·인증대표
암호화 전용 모드○✗ECB, CBC, CFB, OFB, CTR
MAC 전용✗○CMAC, HMAC, GMAC(GCM에서 평문 없이 AAD만 인증)
AEAD○○GCM, CCM, ChaCha20-Poly1305, OCB

주의: CTR 모드 단독은 무결성을 제공하지 않는다. 스트림 암호 특성상 암호문 비트를 뒤집으면 평문 비트가 그대로 뒤집히므로 오히려 변조에 취약하다. GCM은 여기에 GHASH 인증을 덧붙여 그 약점을 메운 것이다. 이 차이를 섞어 놓으면 "GCM은 기밀성만 제공한다"는 오답 보기가 만들어진다.

상세 풀이​

"가장 적절하지 않은 것"을 고르는 유형이므로, GCM의 정의·구조와 어긋난 서술을 찾는다.

  1. ① "메시지 암호화를 위해 CTR 모드를 이용한다" — GCM의 암호화 갈래는 정확히 CTR 모드다(Ci=Pi⊕EK(inc32i(J0))C_i = P_i \oplus E_K(\mathrm{inc32}^i(J_0))Ci​=Pi​⊕EK​(inc32i(J0​))). 이름의 'Counter'가 바로 이것이다. → 적절.
  2. ② "MAC 값 생성을 위해서는 해시 함수를 사용한다" — 태그 생성에 GHASH를 사용한다. 이름 그대로 해시 계열 함수이며, 정확히는 GF(2128)\mathrm{GF}(2^{128})GF(2128) 기반 유니버설 해시다. 표현이 거칠지만 "해시 함수를 사용한다"는 서술 자체는 틀렸다고 보기 어렵다. → 적절.
  3. ③ "각 블록을 병렬처리 하는 게 가능하므로 실행 속도를 높일 수 있다" — CTR 기반이라 각 블록의 카운터가 독립적이어서 암·복호화 모두 완전 병렬 처리가 가능하고, GHASH도 H,H2,H4…H, H^2, H^4 \dotsH,H2,H4… 를 미리 계산해 여러 블록을 동시에 누적할 수 있다. 여기에 인텔 AES-NI 와 PCLMULQDQ(캐리리스 곱셈) 명령이 하드웨어로 뒷받침하여 TLS에서 AES-GCM이 사실상 표준이 된 이유가 된다. → 적절.
  4. ④ "기밀성은 제공하지만 메시지 무결성은 보장하지 않는다" — GCM은 대표적 AEAD 모드로 기밀성과 무결성·인증을 동시에 제공한다. 위 5절에서 실제 태그 값까지 계산해 확인했다. 정반대 서술이다. → 부적절 = 정답.

오답 이유​

  • ①이 적절한 이유: GCM은 IV로부터 J0J_0J0​ 를 만들고 32비트 카운터를 증가시키며 EKE_KEK​ 로 키스트림을 만든 뒤 평문과 XOR한다. 이는 CTR 모드의 정의 그 자체다. 이름 "Galois/Counter Mode"의 뒷부분이 이를 가리킨다.
  • ②가 적절한 이유: 인증 태그는 암호문·AAD·길이 블록을 GHASH에 통과시킨 값에 EK(J0)E_K(J_0)EK​(J0​) 를 XOR해 만든다. 다만 여기서의 '해시 함수'는 SHA-1/SHA-256 같은 암호학적 해시가 아니라 키 HHH 에 의존하는 유니버설 해시 GHASH다. 보기의 표현이 다소 거칠어 혼동을 줄 수 있으나, ④가 명백한 오류 서술이므로 "가장 적절하지 않은 것"은 ④로 확정된다. 이런 문항에서는 가장 명백히 틀린 보기를 고르는 것이 원칙이다.
  • ③이 적절한 이유: CBC는 이전 블록의 암호문이 다음 블록 입력에 필요해 암호화를 병렬화할 수 없지만, CTR은 카운터만 알면 어느 블록이든 독립적으로 처리할 수 있다. GHASH의 누적 곱셈도 Y=((X1H⊕X2)H⊕X3)H…Y = ((X_1 H \oplus X_2)H \oplus X_3)H \dotsY=((X1​H⊕X2​)H⊕X3​)H… 를 X1H3⊕X2H2⊕X3HX_1H^3 \oplus X_2H^2 \oplus X_3HX1​H3⊕X2​H2⊕X3​H 형태로 전개해 병렬 누산이 가능하다.
  • ④가 부적절한 이유: GCM의 설계 목적 자체가 "CTR의 기밀성 + GHASH의 무결성"이다. 복호화 측은 수신한 태그와 자신이 계산한 태그를 비교해 불일치하면 평문을 반환하지 않고 실패 처리한다(SP 800-38D의 GCM-AD 절차). 올바른 서술로 고치면 "기밀성과 무결성·인증을 동시에 제공하며, 암호화하지 않는 연관 데이터(AAD)에 대해서도 무결성을 보장한다"가 된다. 참고로 기밀성 없이 인증만 쓰는 형태(평문 없이 AAD만 인증)를 따로 GMAC이라 부른다.

핵심 정리​

  • GCM = CTR(암호화) + GHASH(인증) = AEAD. 근거 표준은 NIST SP 800-38D.
  • 구성식 4개를 묶어 기억한다 — H=EK(0128)H = E_K(0^{128})H=EK​(0128), J0=IV∥031∥1J_0 = IV \parallel 0^{31} \parallel 1J0​=IV∥031∥1(96비트 IV), Ci=Pi⊕EK(inc32i(J0))C_i = P_i \oplus E_K(\mathrm{inc32}^i(J_0))Ci​=Pi​⊕EK​(inc32i(J0​)), T=GHASH(H,A,C)⊕EK(J0)T = \mathrm{GHASH}(H,A,C) \oplus E_K(J_0)T=GHASH(H,A,C)⊕EK​(J0​).
  • GHASH는 SHA 계열이 아니라 GF(2128)\mathrm{GF}(2^{128})GF(2128) 기반 유니버설 해시다. GCM에서 같은 키로 IV를 재사용하면 태그 위조가 가능해진다.
  • "GCM은 기밀성만 제공하고 무결성은 보장하지 않는다"는 서술은 AEAD의 정의와 정면으로 배치되며, 이 유형 문항의 전형적인 오답 함정이다.
