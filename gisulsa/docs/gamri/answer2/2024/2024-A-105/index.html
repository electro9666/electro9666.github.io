105번 · C 코드의 포맷 스트링 취약점(CWE-134)

제25회(2024년) 정보시스템감리사 A형 — 보안

사전 지식​

1. C의 가변인자 함수와 포맷 문자열​

printf 계열 함수는 가변인자(variadic) 함수다.

int printf(const char *format, ...);

첫 인자 format 안의 변환 지정자(%d, %s, %x …) 개수와 종류를 보고, 런타임에 "그 뒤에 인자가 몇 개 더 있다"고 추정한다. C 표준은 인자의 실제 개수를 검사하지 않는다. 즉 포맷 문자열이 곧 스택 읽기·쓰기 명령서다.

printf("%d %s\n", 10, "hi");   // 포맷이 "인자 2개"를 지시 → 실제 2개 → 정상
printf("%d %d %d %d\n");        // 포맷이 "인자 4개"를 지시 → 실제 0개 → 스택 쓰레기 출력

여기서 포맷 문자열을 공격자가 제어할 수 있다면, 공격자가 프로그램의 스택 접근을 직접 지시하게 된다.

2. 주요 변환 지정자와 공격적 용도​

지정자정상 용도공격적 용도
%x, %p16진수·포인터 출력스택 메모리 내용을 한 워드씩 덤프 → 카나리 값, 리턴 주소, ASLR 우회용 주소 유출
%s문자열 출력스택에 있는 값을 주소로 간주해 역참조 → 임의 메모리 읽기, 잘못된 주소면 SIGSEGV
%n지금까지 출력한 문자 수를 인자가 가리키는 주소에 기록임의 주소에 임의 값 쓰기 — GOT/리턴 주소 덮어쓰기 → 코드 실행
%N$x (직접 파라미터 접근)N번째 인자 참조원하는 스택 오프셋을 한 번에 지정
%100000c (폭 지정)출력 폭 지정%n과 결합해 기록할 값을 원하는 크기로 조절

%n 하나 때문에 포맷 스트링은 단순 정보 노출을 넘어 원격 코드 실행까지 가능한 취약점이 된다. 그래서 최신 glibc는 _FORTIFY_SOURCE 하에서 쓰기 가능한 메모리의 포맷 문자열에 대한 %n 사용을 막고, GCC는 -Wformat-security 경고를 낸다.

3. CWE-134​

  • 정식 명칭: CWE-134: Use of Externally-Controlled Format String
  • 설명: "The product uses a function that accepts a format string as an argument, but the format string originates from an external source."
  • 취약 예시(CWE 문서): printf(string);, snprintf(buf, 128, argv[1]);
  • 완화: 포맷 문자열 함수에는 사용자가 제어할 수 없는 정적 문자열을 넘기고 인자 개수를 맞출 것, %n을 지원하지 않는 함수 사용을 권장.

한국의 소프트웨어 개발보안 가이드에서는 "포맷 스트링 삽입" 항목으로 다루며, 동일하게 printf("%s", buf) 형태를 요구한다.

4. 안전한 작성법​

/* 취약 */
printf(name);
fprintf(fp, buf);
syslog(LOG_INFO, msg);

/* 안전 — 포맷 문자열은 항상 개발자가 고정한 리터럴 */
printf("%s", name);
fputs(name, stdout);
fprintf(fp, "%s", buf);
syslog(LOG_INFO, "%s", msg);

5. 혼동하기 쉬운 인접 개념​

취약점발생 원인코드상의 신호이 문제 코드에 해당?
포맷 스트링(CWE-134)외부 입력이 포맷 문자열 인자 자리에 직접 전달printf(var);, sprintf(buf, var);✅ printf(name);
스택 버퍼 오버플로(CWE-121)버퍼 경계를 넘는 쓰기gets(), strcpy(), scanf("%s")(길이 무제한)❌ scanf("%99s") 로 길이 제한됨
경쟁 조건 / TOCTOU(CWE-367)검사 시점과 사용 시점의 시간차access() 후 open(), 공유자원 동시 접근❌ 단일 스레드, 파일·공유자원 접근 없음
명령어 주입(CWE-78)외부 입력이 셸 명령 문자열에 삽입system(), popen(), exec*()❌ 해당 호출 없음

③

상세 풀이​

문제의 코드를 줄 단위로 보면 다음과 같다.

#include <stdio.h>

int main() {
    char name[100];                    // (1) 100바이트 스택 버퍼

    printf("Enter your name: ");       // (2) 고정 리터럴 → 안전
    scanf("%99s", name);               // (3) 최대 99자 + '\0' = 100바이트 → 경계 준수
    printf(name);                      // (4) ★ 사용자 입력이 포맷 문자열 자리에 그대로 ★
    ...
    return 0;
}
  • (1)·(3)이 짝을 이룬다. char name[100]에 scanf("%99s", name)은 최대 99문자를 읽고 마지막에 NUL 종료 문자를 붙이므로 정확히 100바이트, 즉 버퍼 경계를 넘지 않는다. 출제자가 %s가 아니라 %99s로 적어 둔 것은 스택 오버플로 오답을 유도하면서 동시에 배제하기 위한 장치다.
  • (2)는 안전하다. 포맷 문자열이 개발자가 고정한 리터럴이고, 변환 지정자가 없다.
  • (4)가 취약점이다. printf(name); 은 name을 포맷 문자열로 해석한다. 사용자가 AAAA%x%x%x%x를 입력하면 스택 내용이 출력되고, %s를 넣으면 임의 주소 역참조가, %n을 넣으면 임의 주소 쓰기가 일어난다.

예를 들어 입력이 다음과 같을 때 실제로 벌어지는 일이다.

입력결과
Alice정상 출력 (Alice) — 변환 지정자가 없어 우연히 안전
%x %x %x %x스택 워드 4개를 16진수로 노출 (정보 유출)
%7$s스택의 7번째 인자 위치 값을 주소로 간주해 역참조 (임의 읽기 / 크래시)
AAAA%7$nAAAA에 해당하는 주소에 출력 문자 수를 기록 (임의 쓰기 → 코드 실행)

따라서 이 코드가 가진 문제점의 정확한 명칭은 포맷 스트링 취약점(CWE-134) 이며, 정답은 ③이다. 수정은 한 줄이면 된다 — printf("%s", name); 또는 fputs(name, stdout);.

보기별 판정​

보기판정근거
① 스택 오버플로우 취약점오답 보기scanf("%99s", name)가 99자로 제한 → char name[100] 경계 내. 경계를 넘는 쓰기가 없음
② 경쟁 조건 취약점오답 보기단일 스레드, 파일·공유자원 접근 없음. TOCTOU의 '검사–사용 시간차'가 존재하지 않음
③ 포맷 스트링 취약점✅ 정답 보기printf(name); — 외부 입력이 포맷 문자열 인자로 직접 전달됨(CWE-134). %x로 읽고 %n으로 쓸 수 있음
④ 명령어 주입 취약점오답 보기system(), popen(), exec*() 등 외부 명령 실행 호출이 코드에 없음

오답 이유​

  • ①이 틀린 이유: 스택 버퍼 오버플로는 버퍼 크기를 초과해 쓰는 것이 전제다. 이 코드는 scanf("%99s", ...)로 읽을 최대 길이를 명시했고, 99자 + NUL = 100바이트로 name[100]에 정확히 들어간다. 만약 scanf("%s", name)나 gets(name)이었다면 ①이 정답이 되었을 것이다. 이 한 글자 차이가 이 문제의 함정이다.
  • ②가 틀린 이유: 경쟁 조건(Race Condition)은 둘 이상의 실행 흐름이 공유 자원에 동시에 접근하거나, access()로 검사한 뒤 open()으로 사용하는 사이에 대상이 바뀌는 TOCTOU 상황에서 발생한다. 이 코드는 스레드도 없고 파일·공유메모리·임시파일 접근도 없다.
  • ③이 맞는 이유: 위 상세 풀이에서 본 대로 printf(name); 한 줄이 CWE-134의 교과서적 사례다. CWE 문서가 제시하는 취약 코드 printf(string); 과 형태가 동일하다. 정보 유출(%x, %s)과 임의 주소 쓰기(%n)가 모두 가능해 심각도가 높다.
  • ④가 틀린 이유: 명령어 주입은 입력이 셸이나 OS 명령 문자열에 연결될 때 성립한다(system("ping " + input) 같은 형태). 이 코드에는 system, popen, exec 계열 호출이 전혀 없으므로 명령이 실행될 경로 자체가 없다.

핵심 정리​

  • printf(변수); 를 보는 순간 포맷 스트링 취약점(CWE-134) 이다. 올바른 형태는 언제나 printf("%s", 변수);.
  • 공격 지정자 3종 — %x/%p 읽기, %s 역참조 읽기, %n 임의 주소 쓰기. %n 때문에 정보 유출을 넘어 코드 실행까지 간다.
  • printf 외에 fprintf, sprintf, snprintf, vprintf, syslog 등 포맷 문자열을 받는 모든 함수가 같은 위험을 갖는다.
  • scanf("%99s", name) 은 char name[100] 의 경계를 정확히 지키므로 스택 오버플로가 아니다 — 이 장치가 ①을 배제하고 ③을 확정하는 결정타다.
