085번 · 데이터 통신의 에러 검출 방식과 압축 기법의 구분

제25회(2024년) 정보시스템감리사 A형 — 시스템 구조

사전 지식​

1. 오류 제어의 기본 원리 — 중복(redundancy)의 추가​

통신 채널에는 잡음이 있어 전송 중 비트가 뒤집힐 수 있다. 수신 측이 원본을 모르는 상태에서 오류를 알아채려면, 송신 측이 데이터로부터 계산한 잉여 정보(중복 비트)를 함께 보내야 한다.

송신: [데이터 D] ── f(D) 계산 ──▶ [데이터 D | 검사비트 f(D)] ──채널──▶
수신: [D' | C'] 수신 → f(D') 재계산 → C' 와 비교
            일치 → 정상으로 간주
            불일치 → 오류 검출

모든 오류 검출 기법의 공통점은 "데이터에 중복을 더한다" 는 것이다. 이 한 문장이 이 문제의 열쇠다.

2. 오류 제어 방식의 분류​

대분류방식대표 기법특징
오류 검출(Error Detection)오류 발견만, 재전송 요청(ARQ)패리티, 블록합(LRC/VRC), 체크섬, CRC중복 비트 적음
전진 오류 정정(FEC)수신 측이 스스로 정정해밍코드, 리드-솔로몬, 컨볼루션, 터보중복 비트 많음, 재전송 불필요
오류 회복재전송 프로토콜Stop-and-Wait ARQ, Go-Back-N, SR ARQ검출 기법과 결합

3. 주요 오류 검출 기법 상세​

(1) 패리티 검사(Parity Check) — VRC​

문자 단위로 1비트를 덧붙여 1의 개수를 짝수(even) 또는 홀수(odd)로 맞춘다. 문자마다 수직 방향으로 검사하므로 VRC(Vertical Redundancy Check) 라고도 한다.

데이터(7비트)1의 개수짝수 패리티 비트전송 비트열
10101014 (짝수)010101010
10100013 (홀수)110100011
  • 검출 능력: 홀수 개(1, 3, 5…)의 오류만 검출. 2비트가 동시에 뒤집히면 1의 개수 짝/홀이 그대로라 놓친다.
  • 정정 능력: 없음(오류 위치를 모름).

(2) 블록합 검사(Block Sum Check) — VRC + LRC​

문자들을 블록으로 묶어 가로(문자별 VRC)와 세로(비트 위치별 LRC) 양방향으로 패리티를 계산한다. LRC(Longitudinal Redundancy Check) 를 추가한 2차원 검사다.

             b1 b2 b3 b4 b5 b6 b7 | VRC(가로)
문자1         1  0  1  0  1  0  1  |  0
문자2         0  1  1  0  0  1  0  |  1
문자3         1  1  0  1  1  0  1  |  1
─────────────────────────────────────────
LRC(세로)     0  0  0  1  0  1  0  |  0  ◀ 블록 검사 문자(BCC)
  • 단일 패리티가 놓치는 짝수 개 오류 상당수를 검출한다.
  • 한 문자 안에서 1비트 오류가 났다면 가로 VRC로 문자를 특정하고 세로 LRC로 비트 위치를 특정해 정정까지 가능하다.
  • 같은 행·같은 열에서 4비트가 사각형 꼴로 뒤집히면 여전히 놓친다.

(3) 순환 중복 검사(CRC, Cyclic Redundancy Check)​

데이터 비트열을 다항식 M(x)M(x)M(x) 로 보고, 약속된 생성 다항식 G(x)G(x)G(x) (차수 rrr)로 모듈로-2 나눗셈을 수행해 나머지를 FCS(Frame Check Sequence)로 붙인다.

전송 프레임=M(x)⋅xr+[M(x)⋅xr mod G(x)]⏟FCS, r비트\text{전송 프레임} = M(x)\cdot x^{r} + \underbrace{\left[ M(x)\cdot x^{r} \bmod G(x) \right]}_{\text{FCS, } r\text{비트}}전송 프레임=M(x)⋅xr+FCS, r비트[M(x)⋅xrmodG(x)]​​

수신 측은 받은 전체를 G(x)G(x)G(x) 로 나누어 나머지가 0이면 정상으로 판단한다.

표준생성 다항식 차수사용처
CRC-1616HDLC, Modbus, USB
CRC-3232이더넷(IEEE 802.3) FCS, ZIP, PNG
CRC-CCITT16X.25, Bluetooth
  • 검출 능력: 모든 홀수 개 오류, 모든 2비트 오류, 생성 다항식 차수 rrr 이하의 모든 버스트 오류를 검출한다. 이더넷·와이파이 등 실제 프로토콜의 표준 방식이다.

4. 허프만 코딩은 무엇인가 — 정반대 방향의 기법​

허프만 코딩(Huffman Coding, 1952) 은 데이비드 허프만이 고안한 무손실 데이터 압축(엔트로피 부호화) 알고리즘이다.

단계동작
1각 심볼의 출현 빈도를 센다
2빈도가 가장 낮은 두 노드를 묶어 부모 노드를 만든다(빈도 = 합)
3노드가 하나 남을 때까지 2를 반복 → 허프만 트리 완성
4루트에서 좌(0)/우(1)로 내려가며 각 심볼의 가변 길이 코드를 부여

예: A(빈도 45), B(13), C(12), D(16), E(9), F(5) → A=0(1비트), B=101, C=100, D=111, E=1101, F=1100

자주 나오는 심볼에 짧은 코드를 주므로 평균 부호 길이가 줄어든다. 고정 3비트로 표현하면 300비트가 필요한 데이터가 허프만 코드로는 약 224비트로 줄어든다.

Lˉ=∑ipi⋅li(섀넌 엔트로피 H≤Lˉ<H+1)\bar{L} = \sum_i p_i \cdot l_i \quad (\text{섀넌 엔트로피 } H \le \bar{L} < H + 1)Lˉ=∑i​pi​⋅li​(섀넌 엔트로피 H≤Lˉ<H+1)

핵심은 허프만 코딩이 중복을 제거해 데이터를 줄이는 기법이라는 점이다. 오류 검출은 중복을 추가하는 것이므로 방향이 정반대다. 게다가 "허프만코딩검사"라는 용어는 존재하지 않는다.

5. 혼동하기 쉬운 인접 개념​

기법분류중복을 어떻게 다루나오류 검출 가능?
패리티 검사오류 검출추가 (1비트)✅
블록합 검사오류 검출추가 (VRC + LRC)✅
CRC오류 검출추가 (rrr비트 FCS)✅ (가장 강력)
체크섬오류 검출추가 (16비트 등)✅ (TCP/UDP/IP 헤더)
해밍코드오류 정정(FEC)추가 (2r≥m+r+12^r \ge m+r+12r≥m+r+1)✅ + 정정까지
허프만 코딩데이터 압축제거❌
LZW, 런-렝스(RLE)데이터 압축제거❌
MD5, SHA-256무결성 검증(암호학적 해시)추가변조 탐지용 (채널 오류용 아님)

시험에서 "해밍코드"는 오류 정정, "패리티·CRC·체크섬"은 오류 검출, "허프만·LZW·RLE"는 압축으로 갈라서 외운다.

② 패리티 검사✅ 1비트 추가오류 검출적절
③ 순환 중복 검사✅ FCS rrr비트 추가오류 검출적절
④ 허프만 코딩 검사❌ 중복을 제거데이터 압축적절하지 않음

④가 답인 두 가지 근거​

근거 1 — 목적이 정반대다. 오류 검출은 채널 잡음에 대비해 의도적으로 잉여를 넣는 행위이고, 허프만 코딩은 저장·전송 비용을 줄이기 위해 잉여를 짜내는 행위다. 정보 이론적으로 허프만 코딩의 목표는 평균 부호 길이를 섀넌 엔트로피 H(X)H(X)H(X) 에 근접시키는 것인데, 이는 곧 중복도(redundancy)를 0에 가깝게 만드는 것이다. 중복이 0인 부호는 어떤 비트가 뒤집혀도 그것이 유효한 다른 부호로 해석될 뿐 오류를 알아챌 수 없다.

근거 2 — 용어 자체가 존재하지 않는다. "블록합검사", "패리티검사", "순환중복검사"는 모두 데이터 통신 교과서와 표준에 등재된 정식 명칭이지만, "허프만코딩검사(Huffman Coding Check)"라는 오류 검출 방식은 존재하지 않는다. 출제자가 압축 기법 이름에 "검사"를 붙여 만든 가짜 용어다.

참고 — 허프만 코딩은 오히려 오류에 취약하다​

가변 길이 부호이기 때문에 비트 하나가 뒤집히면 부호 경계가 어긋나 그 이후 전체가 엉뚱하게 복호(catastrophic error propagation) 되는 특성이 있다. 그래서 실무에서는 허프만 압축 결과에 다시 CRC를 붙여 전송한다(ZIP 파일이 CRC-32를 함께 저장하는 이유). 즉 허프만 코딩과 오류 검출은 대체 관계가 아니라 순차적으로 함께 쓰이는 별개 계층이다.

보기별 판정​

보기판정근거
① 블록합 검사(Block Sum Check)오답 보기(적절한 오류 검출 방식)문자 단위 VRC에 블록 단위 LRC를 더한 2차원 패리티. 단일 패리티가 놓치는 짝수 개 오류까지 상당수 검출
② 패리티 검사(Parity Check)오답 보기(적절한 오류 검출 방식)1비트를 덧붙여 1의 개수를 짝수/홀수로 맞추는 가장 단순한 방식. 홀수 개 오류 검출
③ 순환 중복 검사(CRC)오답 보기(적절한 오류 검출 방식)생성 다항식으로 모듈로-2 나눗셈한 나머지(FCS)를 부착. 이더넷 IEEE 802.3의 CRC-32가 대표 사례
④ 허프만 코딩 검사(Huffman Coding Check)✅ 정답 보기(적절하지 않음)허프만 코딩은 무손실 압축(엔트로피 부호화) 기법으로 중복을 제거한다. 오류 검출 방식이 아니며 해당 용어 자체가 존재하지 않는다

오답 이유​

  • ①이 맞는 이유: 블록합 검사는 각 문자에 수직 패리티(VRC)를 붙이고, 블록 전체에 대해 비트 위치별 수평 패리티(LRC)를 계산한 검사 문자(BCC)를 마지막에 덧붙인다. 2차원으로 교차 검사하므로 단일 패리티가 놓치는 짝수 개 오류를 상당수 잡아내며, 한 문자 내 1비트 오류라면 가로·세로 좌표로 위치를 특정해 정정까지 가능하다. 명백한 오류 검출 방식이다.
  • ②가 맞는 이유: 패리티 검사는 7비트 ASCII에 1비트를 덧붙여 전체 1의 개수를 짝수(또는 홀수)로 맞추는 방식으로, 오류 검출의 가장 기본형이다. 검출 능력은 홀수 개 오류로 제한되지만, 중복 비트를 추가해 수신 측이 대조한다는 오류 검출의 정의를 완전히 충족한다.
  • ③이 맞는 이유: CRC는 데이터를 계수가 0/1인 다항식으로 보고 생성 다항식으로 나눈 나머지를 FCS로 부착하는 방식이다. 생성 다항식 차수 이하의 모든 버스트 오류와 모든 홀수 개 오류를 검출하는 강력한 기법으로, 이더넷(IEEE 802.3)의 프레임 끝 FCS 필드가 CRC-32이고 HDLC·USB·ZIP 등에서도 표준으로 쓰인다. 오류 검출 방식의 대표 주자다.
  • ④가 틀린 이유: 허프만 코딩은 심볼의 출현 확률에 따라 가변 길이 접두 부호를 부여해 평균 부호 길이를 줄이는 무손실 데이터 압축(엔트로피 부호화) 알고리즘이다. 목적이 데이터 크기 축소이므로 오류 검출용 중복 비트를 전혀 추가하지 않고, 오히려 중복도를 이론적 하한인 섀넌 엔트로피에 가깝게 깎아낸다. 게다가 가변 길이 부호 특성상 1비트 오류가 이후 전체 복호를 망가뜨리므로 오류에 취약하기까지 하다. "허프만코딩검사"라는 오류 검출 방식은 존재하지 않는 가공의 용어다. 굳이 대응시킨다면 압축 결과의 무결성은 별도로 붙인 CRC가 보장한다.

핵심 정리​

  • 오류 검출의 정의 = 데이터에 중복(잉여) 비트를 추가해 수신 측이 대조하게 하는 것. 이 기준 하나로 보기를 가른다.
  • 오류 검출: 패리티(VRC), 블록합(VRC+LRC), 체크섬, CRC. 오류 정정(FEC): 해밍코드, 리드-솔로몬, 컨볼루션.
  • 데이터 압축: 허프만 코딩, LZW, 런-렝스(RLE), 산술 부호화. 중복을 제거하므로 오류 검출 기능이 없다.
  • CRC는 생성 다항식으로 모듈로-2 나눗셈한 나머지를 FCS로 붙이며, 이더넷(IEEE 802.3)은 CRC-32를 쓴다.
  • 결정타: 오류 검출은 중복을 "추가"하고 압축은 중복을 "제거"한다. 방향이 정반대인 허프만 코딩이 오류 검출 방식일 수 없으며, "허프만코딩검사"라는 용어 자체가 존재하지 않는다.
