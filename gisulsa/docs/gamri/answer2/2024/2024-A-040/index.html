040번 · 코드 스멜(Code Smell)과 대응 리팩토링 기법의 연결

제25회(2024년) 정보시스템감리사 A형 — 소프트웨어 공학

사전 지식​

1. 코드 스멜이란​

코드 스멜(code smell, 나쁜 냄새) 은 Kent Beck과 Martin Fowler가 제시한 개념으로, "동작에는 문제가 없지만 설계상 개선이 필요함을 시사하는 표면적 징후" 를 말한다. 컴파일 오류나 결함이 아니라 "이 코드는 앞으로 변경하기 어려울 것" 이라는 경고 신호다.

리팩토링은 "냄새를 맡고 → 해당 기법을 적용해 냄새를 없애는" 활동이며, 그래서 감리 시험에서는 "스멜 ↔ 기법" 대응 관계를 자주 묻는다.

2. 주요 코드 스멜과 표준 대응 기법 (본 문항 관련 4종)​

코드 스멜증상근본 원인표준 대응 리팩토링조치 내용
Feature Envy(기능 편애)어떤 메소드가 자기 클래스의 데이터보다 다른 클래스의 데이터를 더 많이 호출·참조메소드가 잘못된 클래스에 놓여 있음Move Method(메소드 이동)메소드를 그 데이터가 있는 클래스로 옮긴다. 일부만 편애하면 Extract Method 후 이동
Shotgun Surgery(산탄총 수술)하나의 변경이 여러 클래스의 여러 곳을 동시에 고치게 만듦하나의 책임이 여러 클래스에 흩어져 있음Move Method / Move Field, 필요시 Inline Class흩어진 기능·데이터를 한 클래스로 모은다
Data Clumps(데이터 뭉치)같은 데이터 항목 묶음(예: 시작일+종료일, 시/도+구/군+상세주소)이 여러 클래스·매개변수 목록에 반복 등장개념적으로 하나인 데이터가 객체로 승격되지 않음Extract Class(클래스 추출), Introduce Parameter Object, Preserve Whole Object그 데이터들을 독립된 클래스로 정의한다
Switch Statements(과도한 switch/if)같은 타입 코드에 대한 분기문이 코드 곳곳에 반복타입별 행위가 다형성으로 표현되지 않음Replace Conditional with Polymorphism (선행: Replace Type Code with Subclasses/State)다형성으로 바꾼다. 같은 시그니처의 메소드를 갖는 여러 클래스를 구현

3. Feature Envy vs Shotgun Surgery — 가장 헷갈리는 한 쌍​

두 스멜의 해결책이 모두 Move Method 계열이라 혼동하기 쉽다. 구분 기준은 "무엇이 잘못 놓여 있는가" 다.

비교 축Feature EnvyShotgun Surgery
관찰 단위메소드 1개변경 요구 1건
증상그 메소드가 남의 데이터만 만진다한 번 고치려면 여러 클래스를 돌아다녀야 한다
방향메소드를 데이터 쪽으로 보낸다흩어진 것들을 한곳으로 모은다
문항 표현"다른 클래스를 지나치게 애용""여러 클래스를 동시에 수정"
대응 조치문(b) 메소드를 그들이 애용하는 데이터가 있는 클래스로 옮긴다(a) 여러 클래스에 흩어진 유사한 기능을 한 곳으로 모은다

문항의 조치문 (a)와 (b)가 각각 "모은다"와 "옮긴다"로 명확히 갈라져 있으므로, 이 표만 있으면 헷갈릴 여지가 없다.

참고로 Shotgun Surgery와 대칭 관계인 스멜로 Divergent Change(발산적 변경) 가 있다. 이는 "한 클래스가 서로 다른 여러 이유로 자꾸 바뀌는" 냄새이며, 해법은 Extract Class 로 클래스를 쪼개는 것이다.

스멜관계해법 방향
Shotgun Surgery변경 1건 → 클래스 N개 수정모은다(Move Method/Field, Inline Class)
Divergent Change클래스 1개 → 변경 사유 N개쪼갠다(Extract Class)

4. Data Clumps와 Extract Class​

Data Clumps 는 "항상 같이 몰려다니는 데이터"다. 판별법은 간단하다. "이 묶음에서 항목 하나를 빼면 나머지가 의미를 잃는가?" 그렇다면 그 묶음은 하나의 개념이며 클래스가 되어야 한다.

// before — 세 항목이 항상 함께 다님
void book(String city, String gu, String detail, Date start, Date end) { ... }

// after — Extract Class / Introduce Parameter Object
void book(Address address, DateRange period) { ... }

효과는 세 가지다. 매개변수 목록이 짧아지고(Long Parameter List 스멜도 동시 해소), 그 데이터에 대한 연산(주소 포맷팅, 기간 길이 계산)을 새 클래스로 옮길 수 있으며, 타입 안전성이 올라간다.

5. 과도한 switch/if와 다형성​

// before — 타입 코드 분기가 여러 곳에 반복
double getSpeed() {
    switch (type) {
        case EUROPEAN: return getBaseSpeed();
        case AFRICAN:  return getBaseSpeed() - getLoadFactor() * numberOfCoconuts;
        case NORWEGIAN_BLUE: return isNailed ? 0 : getBaseSpeed(voltage);
    }
}

// after — Replace Conditional with Polymorphism
abstract class Bird { abstract double getSpeed(); }
class European extends Bird { double getSpeed() { ... } }
class African  extends Bird { double getSpeed() { ... } }
class NorwegianBlue extends Bird { double getSpeed() { ... } }

문항의 조치문 (c) "다형성으로 바꾼다. (같은 메소드를 가진 여러 개의 클래스를 구현한다.)" 가 바로 이 기법의 설명이다.

6. 혼동하기 쉬운 인접 개념​

착각실제
Feature Envy도 "모은다"로 해결한다Feature Envy는 메소드 하나를 옮기는(Move) 문제다. "모으는" 것은 Shotgun Surgery
Data Clumps는 다형성으로 해결한다데이터 묶음 문제이므로 Extract Class. 다형성은 조건 분기 문제의 해법
과도한 switch는 Extract Method로 해결한다Extract Method는 긴 메소드(Long Method) 스멜의 해법. 타입 분기는 다형성
Shotgun Surgery = Divergent Change정반대다. 전자는 변경 1건이 여러 클래스로, 후자는 클래스 1개가 여러 변경 사유로

상세 풀이​

보기 조합형 문항이다. 네 개의 스멜 (가)(라)와 네 개의 조치 (a)(d)를 각각 올바르게 짝지은 다음, 보기 중 두 쌍이 모두 옳은 것을 고른다.

1단계 — 정답 매핑 도출​

스멜문항 표현원인 분석올바른 조치조치 문구
(가) Feature Envy다른 클래스를 지나치게 애용메소드가 잘못된 클래스에 있음Move Method(b) 메소드를 그들이 애용하는 데이터가 있는 클래스로 옮긴다
(나) Shotgun Surgery여러 클래스를 동시에 수정하나의 책임이 여러 클래스에 흩어짐Move Method/Field, Inline Class(a) 여러 클래스에 흩어진 유사한 기능을 한 곳으로 모은다
(다) Data Clumps유사 데이터의 중복데이터 묶음이 객체화되지 않음Extract Class(d) 해당 데이터들을 독립된 클래스로 정의한다
(라) 너무 많은 Switch, if 문장—타입별 행위가 다형성으로 표현되지 않음Replace Conditional with Polymorphism(c) 다형성으로 바꾼다(같은 메소드를 가진 여러 클래스 구현)

정답 매핑은 (가)-(b), (나)-(a), (다)-(d), (라)-(c) 다. 문항이 스멜과 조치를 일부러 어긋난 순서로 배치했다는 점에 주의해야 한다. 표의 같은 행끼리(가-a, 나-b, 다-c, 라-d) 짝지으면 네 쌍 모두 틀린다.

2단계 — 보기 대조​

보기첫 번째 쌍판정두 번째 쌍판정결론
①(가)-(a)✕ (정답은 (b))(다)-(c)✕ (정답은 (d))둘 다 오답
②(가)-(b)○(다)-(d)○둘 다 정답
③(나)-(a)○(라)-(d)✕ (정답은 (c))하나만 정답
④(나)-(b)✕ (정답은 (a))(라)-(c)○하나만 정답

"가장 적절하게 연결한 것만으로 짝지은 것"을 묻고 있으므로, 두 쌍 모두 옳아야 한다. 조건을 만족하는 것은 ② 뿐이다.

3단계 — 결론​

정답은 ②. ③과 ④는 각각 한 쌍만 맞아서 탈락하는 부분 정답형 함정이다.

보기별 판정​

보기판정근거
① (가)-(a), (다)-(c)오답 보기두 쌍 모두 오답. (가)는 (b), (다)는 (d)와 짝지어야 한다
② (가)-(b), (다)-(d)✅ 정답 보기Feature Envy → Move Method(b), Data Clumps → Extract Class(d). 두 쌍 모두 정석 대응
③ (나)-(a), (라)-(d)오답 보기(나)-(a)는 옳지만 (라)는 (c) 여야 한다. 데이터 클래스 추출은 조건 분기와 무관
④ (나)-(b), (라)-(c)오답 보기(라)-(c)는 옳지만 (나)는 (a) 여야 한다. Shotgun Surgery는 "모으는" 조치

오답 이유​

  • ①이 틀린 이유: 두 쌍이 모두 어긋났다.
    • (가)-(a): Feature Envy는 메소드 하나가 엉뚱한 클래스에 놓인 문제다. 그 메소드를 데이터가 있는 클래스로 옮기면(b) 해결된다. "여러 클래스에 흩어진 기능을 모은다(a)"는 서술은 변경이 여러 클래스에 퍼져 있는 Shotgun Surgery 의 해법이다.
    • (다)-(c): Data Clumps는 데이터 문제인데 (c)는 행위(조건 분기) 문제의 해법이다. 다형성으로 바꿔도 반복되는 데이터 묶음은 그대로 남는다.
  • ②가 맞는 이유: 두 쌍 모두 Fowler 카탈로그의 정석 대응이다.
    • (가)-(b): Feature Envy의 판정 기준은 "이 메소드가 어느 클래스의 데이터를 가장 많이 쓰는가"이고, 조치는 가장 많이 쓰는 데이터가 있는 클래스로 메소드를 이동(Move Method) 하는 것이다. "데이터와 그 데이터를 다루는 행위를 한 곳에 둔다"는 객체지향의 기본 원칙을 회복시킨다.
    • (다)-(d): Data Clumps의 조치는 Extract Class 로 그 데이터 묶음을 독립된 클래스로 만드는 것이다. (d)의 "해당 데이터들을 독립된 클래스로 정의한다"가 정확히 이 서술이다.
  • ③이 틀린 이유: (나)-(a)는 옳다. Shotgun Surgery는 하나의 변경이 여러 클래스를 건드리게 만드는 냄새이므로, 흩어진 기능·필드를 한 클래스로 모으는 것이 해법이다. 그러나 (라)-(d)가 틀렸다. 과도한 switch/if는 조건 분기 구조의 문제이고, (d)는 데이터를 클래스로 묶는 조치라 대응하지 않는다. (라)의 올바른 짝은 (c) 다형성 대체다. 문항이 "두 쌍 모두 옳은 것"을 요구하므로 한 쌍이 틀린 ③은 탈락한다.
  • ④가 틀린 이유: (라)-(c)는 옳다. 타입 코드에 따른 분기가 반복되면 Replace Conditional with Polymorphism으로 각 타입을 서브클래스로 만들고 같은 시그니처의 메소드를 오버라이드한다. 그러나 (나)-(b)가 틀렸다. (b)의 "메소드를 애용하는 데이터가 있는 클래스로 옮긴다"는 Feature Envy(가) 의 해법이다. Shotgun Surgery의 초점은 "어느 클래스로 옮길지"가 아니라 "흩어진 것들을 하나로 모아 변경 지점을 단일화"하는 데 있다.

핵심 정리​

  • 4대 대응 관계를 통째로 암기한다.
    • Feature Envy(다른 클래스 애용) → Move Method(데이터가 있는 클래스로 옮긴다)
    • Shotgun Surgery(여러 클래스 동시 수정) → Move Method/Field, Inline Class(한 곳으로 모은다)
    • Data Clumps(유사 데이터 중복) → Extract Class(독립 클래스로 정의한다)
    • 과도한 Switch/if → Replace Conditional with Polymorphism(다형성으로 바꾼다)
  • 대칭 관계도 함께 기억한다. Shotgun Surgery(변경 1 → 클래스 N)는 모으고, Divergent Change(클래스 1 → 변경 사유 N)는 쪼갠다.
  • 조합형 문항은 두 쌍이 모두 옳아야 정답이다. ③·④처럼 한 쌍만 맞는 보기가 반드시 섞여 있으므로, 보기 하나를 확인하고 바로 고르면 안 된다.
  • (가)와 (나)는 둘 다 Move 계열이라 헷갈리지만, (가)는 "옮긴다"(b), (나)는 "모은다"(a) 로 조치문의 동사가 다르다 — 이 동사 차이가 ①과 ④를 걸러내는 결정타다.
