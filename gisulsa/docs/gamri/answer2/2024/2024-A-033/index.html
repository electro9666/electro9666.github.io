033번 · C 배열 포인터와 후위 증가 연산자

제25회(2024년) 정보시스템감리사 A형 — 소프트웨어 공학

사전 지식​

1. 배열 포인터(pointer to array) vs 포인터 배열(array of pointers)​

C에서 * 와 [] 가 함께 나오면 괄호의 유무로 의미가 완전히 달라진다.

선언읽는 법의미p + 1 이 움직이는 거리
int (*p)[4];p 는 포인터 → int[4] 를 가리킴배열 포인터: "int 4개짜리 배열"을 가리키는 포인터 1개16바이트(int 4개 = 한 행)
int *p[4];p 는 배열 → 원소가 int*포인터 배열: int 포인터 4개를 담은 배열(배열이므로 p+1 은 두 번째 포인터)
int *p;단순 int 포인터4바이트(int 1개)

읽는 순서는 "안쪽에서 바깥쪽으로, 오른쪽을 먼저, 그다음 왼쪽" 이다. int (*ptr)[4] 는 괄호 때문에 *ptr 을 먼저 묶으므로 "ptr은 포인터", 그다음 [4] 와 int 를 붙여 "int 4개 배열을 가리킨다"가 된다.

포인터 산술의 핵심 규칙: 포인터 p 에 대해 p + n 은 주소상 n * sizeof(*p) 만큼 이동한다. int (*ptr)[4] 에서 sizeof(*ptr) 은 sizeof(int[4]) = 16바이트이므로, ptr + 1 은 2차원 배열의 다음 "행"을 가리킨다.

2. 배열의 포인터 붕괴(array-to-pointer decay)​

배열 이름은 대부분의 식(sizeof, &의 피연산자 등 예외 제외)에서 첫 원소의 주소로 자동 변환된다.

  • int ary[2][4]; 에서 ary 는 int[2][4] 타입이지만, 식에서는 int (*)[4], 즉 &ary[0] 으로 붕괴한다. 그래서 int (*ptr)[4] = ary; 라는 대입이 타입이 맞아 성립한다.
  • *ptr 은 ary[0], 즉 int[4] 타입인데, 다시 식에서 쓰이면 &ary[0][0](타입 int*) 으로 붕괴한다.
  • 그래서 **ptr 은 *( &ary[0][0] ) = ary[0][0] 이라는 int 값이 된다.

정리하면 역참조 * 를 한 번 할 때마다 "차원이 하나 줄어든다" 고 기억하면 된다.

식타입가리키는 대상
ptrint (*)[4]&ary[0] (0행 전체)
*ptrint[4] → 붕괴 후 int*&ary[0][0]
**ptrintary[0][0] 의 값
*(ptr+1)int[4] → int*&ary[1][0]
*(ptr+1)+3int*&ary[1][3]
*(*(ptr+1)+3)intary[1][3] 의 값

3. 연산자 우선순위 표 (이 문제의 핵심)​

C 연산자 우선순위에서 후위(postfix) 연산자가 단항(unary) 연산자보다 높다. 이 한 줄이 문제 전체를 좌우한다.

순위분류연산자결합 방향
1 (가장 높음)후위(postfix)a++ a-- () 함수 호출 [] . -> 복합 리터럴왼쪽 → 오른쪽
2단항(unary/prefix)++a --a * (역참조) & (주소) +a -a ! ~ (타입) sizeof오른쪽 → 왼쪽
3곱셈류* (곱셈) / %왼쪽 → 오른쪽
4덧셈류+ -왼쪽 → 오른쪽
5시프트<< >>왼쪽 → 오른쪽
6~7관계·동등< <= > >= / == !=왼쪽 → 오른쪽
8~10비트& / ^ / 비트 OR왼쪽 → 오른쪽
11~12논리&& / 논리 OR왼쪽 → 오른쪽
13조건?:오른쪽 → 왼쪽
14대입= += -= ...오른쪽 → 왼쪽
15콤마,왼쪽 → 오른쪽

여기서 반드시 구분해야 할 네 가지 관용 표현이 있다.

식해석증가되는 대상결과 값
*p++*(p++) — 후위 ++ 가 먼저 결합포인터 p증가 이전 위치의 값
*++p*(++p) — 전위 ++ 와 * 는 같은 순위, 오른쪽→왼쪽 결합포인터 p증가 이후 위치의 값
(*p)++괄호로 역참조를 먼저 강제가리키는 값증가 이전의 값
++*p++(*p)가리키는 값증가 이후의 값

4. 후위 증가(i++)의 의미 — 값과 부수효과의 분리​

i++ 는 두 가지 일을 한다.

  1. 식의 값(value): 증가하기 전의 옛 값을 내놓는다.
  2. 부수효과(side effect): i 를 1 증가시킨다.

따라서 b = **ptr++; 이라는 한 줄은

  • b 에는 ptr 이 아직 0행을 가리키고 있을 때의 값이 들어가고,
  • 같은 문장이 끝난 뒤 ptr 은 1행을 가리키게 된다.

"값은 옛 것, 포인터는 새 것"이라는 두 결과가 동시에 일어난다는 점이 이 문제의 함정이다.

5. 혼동하기 쉬운 인접 개념​

착각실제
**ptr++ 는 **ptr 을 증가시킨다++ 는 ptr 에 붙는다. 값이 아니라 포인터가 증가한다
**ptr++ 는 증가한 뒤의 값을 준다후위이므로 증가 전의 값을 준다
ptr + 1 은 4바이트 이동int (*)[4] 이므로 16바이트(한 행) 이동
*(ptr+1)+3 의 +3 은 12바이트 곱하기 3행*(ptr+1) 이 int* 로 붕괴했으므로 +3 은 int 3개 = 12바이트, 즉 같은 행의 4번째 열

문제​

정답​

④

상세 풀이​

0단계 — 메모리 배치​

int ary[][4] = {{10, 20, 30, 40}, {50, 60, 70, 80}};

열 개수 4가 명시되었고 초기화 목록이 2행이므로 ary 는 int[2][4] 다. 메모리는 행 우선(row-major)으로 연속 배치된다. 설명을 위해 ary 의 시작 주소를 1000, sizeof(int) 를 4로 가정한다.

주소10001004100810121016102010241028
원소ary[0][0]ary[0][1]ary[0][2]ary[0][3]ary[1][0]ary[1][1]ary[1][2]ary[1][3]
값1020304050607080

int (*ptr)[4] = ary; → ptr = 1000 (= &ary[0]). 한 번의 ptr + 1 은 sizeof(int[4]) = 16바이트를 이동한다.

1단계 — a = *(*(ptr + 1) + 3);​

안에서 바깥으로 푼다.

단계식계산타입결과
1ptr + 11000 + 1×16int (*)[4]1016 = &ary[1]
2*(ptr + 1)역참조 → ary[1], 식에서 붕괴int*1016 = &ary[1][0]
3*(ptr+1) + 31016 + 3×4int*1028 = &ary[1][3]
4*( ... )1028 번지의 값int80

→ a = 80 (= ary[1][3]). 이 문장에는 ++ 가 없으므로 ptr 은 그대로 1000이다.

2단계 — b = **ptr++;​

이 줄이 문제의 핵심이다.

  1. 결합 순서 결정: 우선순위 표에서 후위 ++(1순위) > 단항 *(2순위)이므로 **ptr++ 는 *( *( ptr++ ) ) 로 묶인다. 증가 대상은 *ptr 이나 **ptr 이 아니라 ptr 자신이다.
  2. 후위 증가의 값: ptr++ 라는 식의 값은 증가 전의 ptr, 즉 1000 (&ary[0]) 이다.
  3. 역참조 2회: *(1000) → ary[0] → 붕괴하면 &ary[0][0] = 1000. 한 번 더 * → 1000번지의 값 = 10.
  4. 부수효과 반영: 이 문장이 끝난 시점에 ptr 은 1000 + 16 = 1016 (&ary[1]) 이 된다.

→ b = 10, 그리고 ptr 은 1행을 가리키도록 이동.

3단계 — c = **ptr;​

이제 ptr = 1016 = &ary[1] 이다.

  • *ptr → ary[1] → 붕괴 → &ary[1][0] = 1016
  • **ptr → 1016번지의 값 = 50

→ c = 50

4단계 — 합산​

a + b + c = 80 + 10 + 50 = 140

printf("%d\n", a+b+c); 는 140을 출력한다. 정답은 ④.

검증​

동일한 메모리 모델(시작 주소 1000, sizeof(int)=4, 행 크기 16바이트)로 세 문장의 주소 계산과 후위 증가의 부수효과를 그대로 재현해 실행한 결과 a=80, b=10, c=50, 합 140이 확인되었다.

ptr init = 1000 (&ary[0])
ptr+1 = 1016 (&ary[1]); *(ptr+1)+3 = 1028 (&ary[1][3]); a = 80
**ptr++ : uses old ptr=1000 (&ary[0]) -> b = 10; ptr now = 1016 (&ary[1])
**ptr   : ptr=1016 (&ary[1]) -> c = 50
a+b+c = 140

보기별 판정​

보기판정근거
① 80오답 보기a 값 하나만 본 경우. b, c를 더하지 않았다
② 100오답 보기b 를 **ptr++ 의 증가 후 값 50으로 착각하고 c 도 다르게 본 경우 등, 후위/전위를 혼동하면 나오는 값
③ 120오답 보기b 를 증가 후 값인 ary[1][0]=50으로 보고 c 도 50으로 계산하면 80+50+50=180, b=10·c=30 식으로 열 단위 이동으로 착각하면 120 등 — 포인터 이동 단위를 int 1개로 오해한 결과
④ 140✅ 정답 보기a=ary[1][3]=80, b=ary[0][0]=10(후위 증가는 옛 값), c=ary[1][0]=50 → 합 140

오답 이유​

  • ①이 틀린 이유: 80은 a 의 값일 뿐이다. 출력하는 것은 a+b+c 이므로 세 값을 모두 구해야 한다. 첫 줄만 계산하고 멈추면 빠지는 함정이다.
  • ②·③이 틀린 이유: 두 값 모두 **ptr++ 의 해석 오류에서 나온다. 대표적인 두 가지 오해는 다음과 같다.
    • (오해 1) 증가가 값에 적용된다고 봄 — **ptr++ 를 (**ptr)++ 로 읽으면 ary[0][0] 이 11이 되고 b 는 10, ptr 은 움직이지 않아 c 도 10이 되어 합이 100이 된다(②). 그러나 후위 ++ 는 바로 왼쪽의 피연산자 ptr 에 결합하므로 (**ptr)++ 가 되려면 괄호를 직접 써야 한다.
    • (오해 2) 포인터가 int 1개 단위로 이동한다고 봄 — ptr 이 int* 라고 착각하면 증가 후 **ptr 이 ary[0][1]=20 등으로 계산되어 합이 120 등으로 어긋난다(③). ptr 의 타입은 int (*)[4] 이므로 한 번의 증가가 행 전체(16바이트) 를 건너뛴다.
  • ④가 맞는 이유: 세 가지 규칙이 모두 지켜진 결과다. (가) int (*ptr)[4] 의 증가 단위는 한 행, (나) **ptr++ 는 우선순위상 *(*(ptr++)) 이므로 증가 대상은 포인터, (다) 후위 증가의 식 값은 증가 이전 값. 그래서 b는 0행의 첫 원소 10을 가져오고, 그 부수효과로 ptr 이 1행으로 넘어가 c가 50이 된다.

핵심 정리​

  • int (*p)[4] 는 배열 포인터로, p + 1 은 int 4개(16바이트) = 한 행만큼 이동한다. int *p[4] (포인터 배열)와 괄호 하나로 갈린다.
  • 2차원 배열 접근의 등가식: ary[i][j] = *(*(ary + i) + j) = *(ary[i] + j). 역참조 한 번마다 차원이 하나 줄어든다.
  • 우선순위: 후위 ++(1순위) > 단항 *(2순위). 따라서 *p++ 는 *(p++) 이고, 값을 증가시키려면 (*p)++ 처럼 괄호를 명시해야 한다.
  • **ptr++ 에서 증가하는 것은 ptr 이고, 식의 값은 증가 "이전" 위치의 값이다 — 이 두 사실(대상 + 시점)을 동시에 지켜야 b=10, c=50이 나오며, 이것이 합 140을 만드는 결정타다.
