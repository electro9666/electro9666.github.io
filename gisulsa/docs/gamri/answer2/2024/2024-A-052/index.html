052번 · 네 가지 관계대수 연산의 결과 카디널리티 계산

제25회(2024년) 정보시스템감리사 A형 — 데이터베이스

사전 지식​

1. 카디널리티와 차수​

용어정의릴레이션에서
카디널리티(cardinality)투플(행)의 개수세로 방향 크기
차수(degree)속성(열)의 개수가로 방향 크기

본 문항은 네 연산 결과의 행 수만 구해 최댓값과 최솟값을 더하는 문제다. 결과의 속성 구성은 답에 영향을 주지 않는다.

2. 이 문항에 등장하는 네 연산의 정의와 카디널리티 계산법​

연산기호정의결과 차수카디널리티 계산 방법
셀렉트(선택)σ조건(R)조건을 만족하는 R의 투플만 남긴다R과 동일조건을 만족하는 행을 센다. 항상 R의 행 수 이하
자연 조인R ⋈N S공통 속성의 값이 같은 투플끼리 결합, 공통 속성은 한 번만 남김deg(R) + deg(S) − 공통속성 수R의 각 투플마다 S에서 매칭되는 투플 수를 세어 합산
세타 조인R ⋈θ Sσθ(R × S) — 곱집합 후 θ 조건으로 거른다. 공통 속성도 양쪽 모두 남김deg(R) + deg(S)곱집합 R×S 쌍(= R행수 × S행수) 중 θ를 만족하는 쌍의 수
나누기(division)R(X,Y) ÷ S(Y)S의 모든 Y 값과 짝을 이루는 R의 X 값들deg(R) − deg(S)X 값마다 "S의 전체 Y 집합을 커버하는가"를 검사

3. 나누기(÷) — 가장 많이 틀리는 연산​

R(X, Y) ÷ S(Y) 의 의미는 자연어로 "S에 있는 모든 Y에 대해 짝이 존재하는 X", 즉 전칭 정량자(∀)에 대응한다.

기본 연산으로 분해하면 다음과 같다.

R ÷ S = ∏X(R) − ∏X( (∏X(R) × S) − R )
단계의미
∏X(R)X 후보 전체
∏X(R) × S있어야 할 (X, Y) 조합 전부
(∏X(R) × S) − R실제로는 빠져 있는 조합(= 결손)
∏X(결손)결손을 가진 X (= 실격자)
후보 − 실격자최종 결과

결과의 카디널리티는 X 값의 개수 이하이며, 조건이 까다로워 대개 매우 작다. 이 문항에서도 나누기 결과가 최솟값이 된다.

4. 자연 조인 vs 세타 조인의 결과 개수 차이​

자연 조인 R ⋈N S세타 조인 R ⋈R.B&lt;S.B S
조건공통 속성 값이 같음(=)지정한 비교 연산(&lt;, &gt;, ≤ 등)
공통 속성 처리중복 제거해 한 번만 출력R.B, S.B 둘 다 출력
카디널리티각 행의 등가 매칭 수 합(R행수 × S행수) 쌍 중 조건 만족 쌍의 수
최대값R행수 × S행수 (모든 값이 같을 때)R행수 × S행수 (조건이 항상 참일 때)

세타 조인의 조건 R.B < S.B 는 "R 쪽 B 값보다 큰 S 쪽 B 값"을 찾는다는 뜻이다. 부등호 방향을 반대로 읽으면 결과가 완전히 달라지므로 어느 쪽이 R.B인지 반드시 확인한다.

5. 원문 라벨 표기에 관한 참고​

PDF에서 텍스트를 추출하면 두 표의 머리글이 S R 처럼 순서가 뒤바뀌어 나오는 경우가 있다. 원본 이미지를 확인하면 왼쪽 6행 표가 R(A, B), 오른쪽 3행 표가 S(B, C) 로 명확히 표기되어 있다.

혹시 라벨을 반대로 읽더라도(즉 3행 표를 R, 6행 표를 S로) 최종 답은 바뀌지 않는다. 아래 표에서 확인할 수 있다.

읽는 방식÷⋈N⋈R.B&lt;S.BσB=10최대 + 최소
원본대로 R=6행(A,B), S=3행(B,C)16526 + 1 = 7
라벨을 뒤집어 R=3행(B,C), S=6행(A,B)06717 + 0 = 7

두 경우 모두 7이므로 정답 ②는 흔들리지 않는다.

연산 1 — R ÷ (∏B(S)) (나누기)​

먼저 제수를 구한다. ∏B(S) = {10, 20, 30} (3개).

R을 A 값별로 묶어 각 A가 가진 B 집합을 본 뒤, {10, 20, 30}을 모두 포함하는지 검사한다.

A해당 A가 가진 B 집합{10,20,30} 전부 포함?판정

3{30}10·20 없음❌ 제외

결과 = { (2) } → 카디널리티 1

연산 2 — R ⋈N S (B에 대한 자연 조인)​

공통 속성은 B다. S의 B 값 10·20·30이 모두 유일하므로 R의 각 투플은 정확히 1개의 S 투플과 매칭된다.

R의 투플매칭되는 S 투플결과 행 수
(1, 10)(10, a)1
(1, 30)(30, c)1
(2, 10)(10, a)1
(2, 30)(30, c)1
(2, 20)(20, b)1
(3, 30)(30, c)1

결과 = {(1,10,a), (1,30,c), (2,10,a), (2,30,c), (2,20,b), (3,30,c)} → 카디널리티 6

S의 B가 유일하므로 이 조인은 손실 없는 1:1 대응이 되어 |R| 그대로 6이 된다. R 쪽 B 값 중 S에 없는 값이 있었다면 그만큼 줄었을 것이다.

연산 3 — R ⋈R.B&lt;S.B S (세타 조인)​

곱집합 6 × 3 = 18 쌍 중 R.B < S.B 를 만족하는 쌍만 남긴다. R의 B 값별로 묶어서 세면 빠르다.

R.B 값해당 R 투플 수S.B > R.B 인 S 투플S 쪽 개수곱
102개 — (1,10), (2,10)(20,b), (30,c)22 × 2 = 4
201개 — (2,20)(30,c)11 × 1 = 1
303개 — (1,30), (2,30), (3,30)없음03 × 0 = 0

합계 = 4 + 1 + 0 = 카디널리티 5

결과 투플: (1,10,20,b) (1,10,30,c) (2,10,20,b) (2,10,30,c) (2,20,30,c)

연산 4 — σB=10(R) (셀렉트)​

R에서 B = 10 인 행은 (1, 10)과 (2, 10) 두 개다. → 카디널리티 2

실행 검증​

Python으로 네 연산을 직접 구현하고, 동일한 데이터를 sqlite3에 넣어 SQL로 교차 확인했다.

R = [(1,10),(1,30),(2,10),(2,30),(2,20),(3,30)]
S = [(10,'a'),(20,'b'),(30,'c')]

PB  = {b for b, c in S}                                    # {10,20,30}
div = {a for a, _ in R if all((a,b) in set(R) for b in PB)}  # -> {2}      : 1
nj  = [(a,b,c) for (a,b) in R for (b2,c) in S if b == b2]    # -> 6 rows   : 6
tj  = [(a,b,b2,c) for (a,b) in R for (b2,c) in S if b < b2]  # -> 5 rows   : 5
sel = [t for t in R if t[1] == 10]                           # -> 2 rows   : 2
실행 결과
R / PI_B(S) = [2]  card = 1
R |x|N S          card = 6
R |x|_{R.B<S.B} S card = 5
sigma_B=10(R)     card = 2
cards = [1, 6, 5, 2]   max + min = 7

sqlite3 교차 확인도 동일한 값(1 / 6 / 5 / 2)을 반환했다.

-- 자연 조인
SELECT COUNT(*) FROM R JOIN S ON R.B = S.B;   -- 6
-- 세타 조인
SELECT COUNT(*) FROM R JOIN S ON R.B < S.B;   -- 5
-- 셀렉트
SELECT COUNT(*) FROM R WHERE B = 10;          -- 2
-- 나누기
SELECT A FROM R GROUP BY A
HAVING COUNT(DISTINCT CASE WHEN B IN (SELECT B FROM S) THEN B END)
     = (SELECT COUNT(DISTINCT B) FROM S);     -- A = 2 한 건

보기별 판정​

보기판정근거
① 6오답 보기최댓값(자연 조인 6)만 적었거나, 최솟값을 0으로 오인하고 6 + 0 으로 계산한 경우
② 7✅ 정답 보기최댓값 6(자연 조인) + 최솟값 1(나누기) = 7
③ 8오답 보기최솟값을 나누기(1)가 아니라 셀렉트(2) 로 잘못 잡아 6 + 2 = 8 로 계산
④ 11오답 보기6 + 5 — 최솟값 대신 두 번째로 큰 값(세타 조인 5) 을 더한 경우

오답 이유​

  • ①(6)이 틀린 이유: 최댓값만 답하거나, 나누기 결과를 공집합(0)으로 잘못 계산하면 6이 나온다. 나누기에서 A=2는 B ∈ {10, 30, 20} 세 값을 모두 가지므로 제수 {10,20,30} 을 완전히 커버한다. 따라서 결과는 공집합이 아니라 {2} 로 카디널리티 1이다. "나누기 결과는 대개 공집합"이라는 막연한 인상으로 검산을 건너뛰면 이 답에 빠진다.
  • ③(8)이 틀린 이유: 최댓값 6은 맞게 구했지만 최솟값을 σB=10(R) 의 2로 잡은 경우다. 네 값 1 · 6 · 5 · 2 중 가장 작은 것은 셀렉트(2)가 아니라 나누기(1) 다. 나누기 계산을 아예 생략하거나 틀리게 한 응시자가 가장 많이 고르는 오답이다. 네 연산 중 하나라도 빠뜨리면 최솟값 판정이 어긋난다는 점을 유의해야 한다.
  • ④(11)이 틀린 이유: 6 + 5 = 11 이므로 "가장 큰 것과 가장 작은 것"을 "가장 큰 두 개"로 잘못 읽었거나, 자연 조인(6)과 세타 조인(5)만 계산하고 나머지 둘을 무시한 경우다. 문제는 최댓값과 최솟값의 합을 묻고 있으므로 네 연산을 모두 계산해야 한다. 또한 세타 조인 5를 6이나 7로 잘못 구해도 이 답 근처로 흘러갈 수 있는데, R.B < S.B 의 부등호 방향을 확인하는 것이 중요하다.
  • 참고로 ②가 맞는 이유를 한 줄로 요약하면 — 네 결과가 1(÷), 6(⋈N), 5(⋈θ), 2(σ) 이므로 max + min = 6 + 1 = 7 이다.

핵심 정리​

  • 나누기 R(X,Y) ÷ S(Y) 는 "S의 모든 Y와 짝을 이루는 X"다. X 값별로 B 집합을 만들어 제수 집합을 포함하는지만 보면 빠르게 계산된다. 이 문항에서는 A=2만 살아남아 1이다.
  • 자연 조인의 카디널리티는 "R의 각 행마다 매칭되는 S 행 수의 합"이다. 조인 대상 쪽 값이 유일하면 |R| 그대로 유지된다(여기서는 6).
  • 세타 조인은 σθ(R × S) 이므로 곱집합 |R|×|S| 를 상한으로 하며, R의 값별로 그룹화해 세면 실수가 줄어든다(여기서는 5).
  • 원문 텍스트에서 표 라벨이 S R 로 뒤집혀 보이더라도, 어느 쪽으로 읽어도 max + min = 7 로 동일하다(원본대로: 6+1, 뒤집어 읽으면: 7+0).
  • 네 연산 중 하나만 빠뜨려도 최솟값 판정이 어긋난다. 가장 놓치기 쉬운 것은 나누기(1)이며, 이를 빼면 최솟값이 셀렉트(2)가 되어 오답 ③(8)로 직행한다.
