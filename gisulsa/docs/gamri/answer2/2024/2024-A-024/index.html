024번 · 연동 기획(rolling wave planning)과 점진적 구체화

제25회(2024년) 정보시스템감리사 A형 — 감리 및 사업관리

사전 지식​

1. 계획의 딜레마 — 왜 '한 번에 전부 계획'이 안 되는가​

프로젝트 초기에는 정보가 가장 적은데, 계획은 그때 가장 많이 필요하다. 이 모순을 불확실성 원뿔(cone of uncertainty) 이라 한다. 착수 시점 추정 오차는 배수 단위(예: −50% ~ +100%)로 크지만, 진행될수록 좁아진다.

시점정보량추정 정밀도(전형적 범위)
개략 산정(ROM, 착수 초기)최소−25% ~ +75%
확정 산정(Definitive, 계획 성숙 후)충분−5% ~ +10%

따라서 합리적 대응은 "정보가 있는 만큼만 상세하게 계획하고, 정보가 생기면 그때 더 상세화"하는 것이다.

2. 점진적 구체화 · 연동 기획 · WBS 분할 수준​

개념정의관계
점진적 구체화(progressive elaboration)정보가 구체화됨에 따라 계획을 지속적으로 상세화·개선해 나가는 원리상위 개념(철학)
연동 기획(rolling wave planning, 연동기획법)가까운 시점의 작업은 상세 수준까지, 먼 미래 작업은 상위 수준으로만 계획하고, 시간이 지나면서 다음 구간을 상세화하는 반복적 기획 기법점진적 구체화의 대표적 구현 기법
연동 기획 패키지(planning package)WBS에서 통제 계정(control account) 아래, 작업 패키지(work package) 위에 놓이는 중간 단위. "할 일은 알지만 아직 상세 활동으로 쪼개지 않은 덩어리"연동 기획의 산출 구조
작업 패키지(work package)WBS 최하위 단위. 일정·원가를 신뢰성 있게 산정·통제할 수 있는 수준상세화가 끝난 결과

연동 기획의 진행 그림은 다음과 같다.

구간초기 계획3개월 후
1~3개월(임박)작업 패키지·활동 수준으로 상세실행 완료
4~6개월계획 패키지 수준상세화됨
7~12개월마일스톤·상위 인도물 수준계획 패키지 수준으로 한 단계 내려옴

PMBOK 6판은 연동 기획을 6.2 활동 정의(Define Activities) 의 기법으로 명시하고, "초기 전략적 계획 시 정보가 부족할 때 작업 패키지를 개략 수준으로만 분할해 두고, 나중에 상세화"한다고 설명한다. 애자일의 백로그 정제(backlog refinement)도 같은 원리다.

3. 오답 보기들의 정확한 정의​

용어정의PMBOK상 위치
요구사항 수집(Collect Requirements)이해관계자의 니즈와 요구를 도출·문서화·관리하는 프로세스. 인터뷰·포커스그룹·설문·프로토타이핑 등을 사용5.2 (범위관리)
대안 분석 / 대체 분석(alternatives analysis)식별된 여러 실행 방안을 비교·평가해 최적안을 선택하는 데이터 분석 기법. 자체 제작 vs 구매, 기술 선택, 자원 투입 방식 등여러 프로세스의 공통 기법(4.5, 6.4, 7.2, 9.2, 11.5 등)

alternatives analysis 는 우리말 번역이 문헌마다 '대안 분석' / '대체 분석'으로 갈리는 같은 개념이다. 본 문항에서 ③과 ④가 동시에 제시된 것 자체가, 둘 중 하나만 정답일 수 없으므로 둘 다 오답임을 알려주는 구조적 단서다.

4. 혼동하기 쉬운 인접 개념​

개념핵심 차이
연동 기획시간축 기준으로 계획의 상세도를 차등화
점진적 구체화상세화를 지향하는 원리 자체
반복적/점증적 생애주기인도물을 여러 번 나눠 만드는 개발 방식(계획 기법이 아님)
예비 산정(ROM)정밀도가 낮은 산정치를 내는 것(계획 구조가 아님)
계획 패키지 vs 작업 패키지계획 패키지는 아직 상세 활동으로 분할되지 않은 중간 단위

정답​

①

상세 풀이​

"단기적으로는 범위의 구체적 측면을 알지만 장기적 세부는 불명확한 경우"라는 문제의 상황 서술은 연동 기획의 적용 조건을 그대로 옮겨 놓은 정의문이다.

  1. ① 연동 기획 — 임박한 작업은 상세하게, 먼 작업은 상위 수준으로만 계획하고 시간 경과에 따라 점진적으로 상세화한다. 문제 상황과 정확히 일치. → 정답.
  2. ② 요구사항 수집 — 이해관계자의 니즈를 도출·문서화하는 프로세스다. 무엇을 만들지를 정하는 활동일 뿐, 계획의 시간적 상세도를 차등화하는 기법이 아니다.
  3. ③ 대안 분석 — 여러 실행 방안을 비교해 최적안을 고르는 기법. "어느 방안이 나은가"를 다루지 "먼 미래를 어떻게 계획할 것인가"를 다루지 않는다.
  4. ④ 대체 분석 — ③과 같은 alternatives analysis의 다른 번역어. ③과 동일한 이유로 오답.

③·④가 동의어로 나란히 배치되어 있다는 점도 결정적 단서다. 객관식 단일정답 문항에서 의미가 같은 두 보기가 동시에 정답일 수는 없으므로, 그 둘은 반드시 오답이다. 남은 ①·② 중 "장기 세부의 불명확성 처리"에 해당하는 것은 ① 하나뿐이다.

오답 이유​

  • ①이 맞는 이유: 연동 기획은 "정보가 확보된 만큼만 계획한다"는 실용적 타협이다. 먼 미래 작업까지 억지로 상세 계획을 세우면, 정보가 바뀔 때마다 대규모 재계획이 필요해 계획 유지 비용만 커지고 계획의 신뢰성도 떨어진다. 대신 계획 패키지 수준으로 남겨 두었다가 실행 시점이 가까워지면 작업 패키지·활동으로 분할한다.
  • ②가 틀린 이유: 요구사항 수집은 "무엇을 만들 것인가"를 정의하는 범위관리 프로세스다. 요구사항을 아무리 잘 수집해도, 12개월 뒤 작업의 일정·원가 세부가 저절로 확정되지는 않는다. 문제가 묻는 것은 요구 파악이 아니라 계획 상세도의 시간적 배분 방법이다.
  • ③이 틀린 이유: 대안 분석은 "A안과 B안 중 무엇을 택할 것인가"에 답하는 기법이다. 선택지들이 이미 식별되어 있어야 작동하므로, 선택지 자체가 불명확한 장기 구간에는 적용할 대상이 없다.
  • ④가 틀린 이유: ③과 같은 alternatives analysis이며, 번역어만 다르다. 같은 개념이 두 보기로 제시된 이상 둘 다 정답일 수 없고, 따라서 둘 다 오답이다.

핵심 정리​

  • 연동 기획(rolling wave planning) = 임박 작업은 상세, 원거리 작업은 개략 → 시간이 지나며 다음 구간을 상세화. PMBOK 6판 6.2 활동 정의의 기법.
  • 점진적 구체화(progressive elaboration) 가 원리, 연동 기획이 그 대표 구현 기법이며, WBS에서는 계획 패키지(planning package) 로 나타난다.
  • 함정 방지: alternatives analysis = 대안 분석 = 대체 분석(같은 개념).
  • "단기는 구체적, 장기는 불명확"이라는 문장이 나오면 곧바로 연동 기획이다. 동의어 보기가 둘 나란히 있으면 그 둘은 반드시 오답이라는 점도 함께 기억해 둘 것.
