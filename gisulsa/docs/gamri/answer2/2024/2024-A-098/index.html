098번 · 애플리케이션과 Well-known 포트 번호의 연결 (복수정답)

제25회(2024년) 정보시스템감리사 A형 — 시스템 구조

사전 지식​

1. 포트 번호 체계​

포트는 16비트(0~65535) 정수로, 하나의 호스트 안에서 어느 프로세스(서비스) 로 데이터를 전달할지 식별한다. IANA는 전 대역을 세 구간으로 나눈다.

구간범위명칭설명
Well-known0 ~ 1023잘 알려진 포트IANA가 표준 서비스에 할당. 유닉스 계열에서는 root 권한이 있어야 바인딩 가능
Registered1024 ~ 49151등록 포트벤더·애플리케이션이 IANA에 등록(예: MySQL 3306, RDP 3389)
Dynamic / Private49152 ~ 65535동적·사설 포트클라이언트 측 임시 포트(ephemeral port)로 사용

통신의 종단은 (IP 주소, 포트 번호) 쌍인 소켓으로 식별되며, TCP 연결은 (출발지 IP, 출발지 포트, 목적지 IP, 목적지 포트) 의 4-튜플로 구별된다.

443은 반드시 이 세 자리 순서로 기억해야 한다. 433은 IANA가 HTTPS에 할당한 포트가 아니며(해당 번호는 nnsp 등 전혀 다른 서비스에 등록되어 있다), 자리 순서만 바꾼 값이라 시험에서 오탈자·함정으로 자주 등장한다.

5. DNS가 TCP 53도 쓰는 이유​

문항이 "TCP 프로토콜 애플리케이션과 …"로 시작하므로 ① DNS-53이 TCP 관점에서도 유효한지 확인이 필요하다.

상황전송계층
일반 질의/응답(512바이트 이하)UDP 53
응답이 512바이트 초과(TC 비트 설정 후 재시도)TCP 53
영역 전송(zone transfer, AXFR/IXFR)TCP 53
DNSSEC 등으로 응답이 커지는 경우TCP 53 또는 EDNS0

즉 포트 번호 53은 UDP·TCP 양쪽 모두에서 DNS에 할당되어 있으므로, TCP 기준으로 봐도 "DNS–53"은 옳은 연결이다.

문제​

정답​

③, ④

상세 풀이​

이 문항은 "가장 적절하지 않은 것"을 하나 고르는 부정형 문항이지만, 틀린 연결이 두 개 존재하여 ③과 ④가 모두 정답으로 인정된 복수정답 문항이다.

보기를 하나씩 검증한다.

  1. ① DNS – 53 — 옳은 연결. DNS는 일반 질의에 UDP 53을 쓰지만, 응답이 512바이트를 초과하거나 영역 전송(AXFR)을 수행할 때는 TCP 53을 사용한다. 포트 번호 53은 UDP·TCP 양쪽에서 DNS에 할당되어 있으므로 문항의 TCP 전제에서도 유효하다.
  2. ② FTP – 21 — 옳은 연결. 21번은 FTP의 제어(control) 연결 포트로, 명령과 응답이 오간다(액티브 모드의 데이터 연결은 20번). 둘 다 TCP다.
  3. ③ POP3 – 25 — 틀린 연결. POP3의 well-known 포트는 TCP 110번이며, 25번은 SMTP의 포트다. 수신 프로토콜과 발신 프로토콜의 포트가 서로 엇갈려 있다. → 정답(출제자 의도상 본래 정답)
  4. ④ HTTPS – 433 — 틀린 연결. HTTPS의 well-known 포트는 443번(RFC 2818)인데 보기에는 433으로 적혀 있다. 443과 433은 전혀 다른 번호이고 433은 HTTPS에 할당된 포트가 아니므로, 표기 오류이든 의도된 함정이든 이 연결 역시 옳지 않다. → 정답(추가 인정)

즉 ③과 ④ 두 개가 모두 "적절하지 않은 연결"에 해당하므로, 하나만 고르도록 한 문항의 전제가 성립하지 않아 복수정답 처리되었다.

보기별 판정​

보기판정근거
① DNS – 53오답 보기(적절한 연결)DNS는 UDP 53 주력, TCP 53도 사용(512B 초과 응답·영역전송 AXFR). 포트 번호 자체가 정확
② FTP – 21오답 보기(적절한 연결)21 = FTP 제어 연결(TCP). 데이터 연결은 액티브 모드에서 20번
③ POP3 – 25✅ 정답 보기(적절하지 않은 연결)POP3는 TCP 110(POP3S 995). 25번은 SMTP — 프로토콜과 포트가 어긋남
④ HTTPS – 433✅ 정답 보기(적절하지 않은 연결)HTTPS는 TCP 443(RFC 2818). 433은 HTTPS에 할당된 포트가 아님

오답 이유​

  • ③이 정답인(틀린) 이유: POP3(Post Office Protocol version 3)는 메일 서버에서 메일을 내려받는 수신 프로토콜이며 IANA가 할당한 well-known 포트는 TCP 110(TLS 적용 시 POP3S 995)이다. 보기에 적힌 25번은 SMTP(Simple Mail Transfer Protocol) 의 포트로, 메일을 발신·릴레이할 때 쓰인다. 즉 "받는 프로토콜에 보내는 포트를 붙여 놓은" 전형적인 교차 오답이다. 올바른 연결은 POP3 – 110 또는 SMTP – 25이다.
  • ④가 정답인(틀린) 이유: HTTPS는 HTTP를 TLS로 감싼 프로토콜로, TCP 443번을 사용한다(RFC 2818 "HTTP Over TLS"). 보기의 433은 443의 두 번째·세 번째 자리를 뒤바꾼 값이며 HTTPS에 할당된 번호가 아니다. 따라서 이 보기도 "애플리케이션과 well-known 포트를 옳게 연결한 것"이 아니다. 출제자가 443을 의도하고 오타를 낸 것으로 보이지만, 보기에 적힌 문자열 그대로 판정하면 틀린 연결이므로 ④ 역시 정답으로 인정되었다. 올바른 연결은 HTTPS – 443이다.
  • ①이 적절한 연결인 이유: DNS의 포트는 53이며, 이는 UDP와 TCP 모두에 대해 IANA에 등록되어 있다. 문항이 "TCP 프로토콜 애플리케이션"이라는 전제를 달았지만, DNS는 응답이 512바이트를 초과하면 TC(truncated) 비트를 세운 뒤 클라이언트가 TCP 53으로 재질의하고, 마스터–슬레이브 간 영역 전송(AXFR/IXFR) 도 TCP 53으로 수행한다. 따라서 이 연결은 옳다.
  • ②가 적절한 연결인 이유: FTP는 명령을 주고받는 제어 연결(TCP 21) 과 실제 파일을 전송하는 데이터 연결을 분리해 사용한다. 데이터 연결은 액티브 모드에서 서버의 20번 포트에서 클라이언트로 열리고, 패시브 모드에서는 서버가 알려 준 임의의 고포트를 클라이언트가 접속한다. 보기의 "FTP–21"은 제어 포트를 정확히 가리키므로 옳은 연결이다.

핵심 정리​

  • Well-known 포트는 0~1023, 등록 포트는 102449151, 동적·사설 포트는 4915265535다.
  • 메일 3종 세트: SMTP 25(발신) / POP3 110(수신·삭제) / IMAP 143(수신·동기화), TLS판은 각각 465 / 995 / 993. 이 문항의 ③은 POP3에 SMTP 포트를 붙인 교차 오답이다.
  • HTTPS = 443(RFC 2818), HTTP = 80. 433은 HTTPS 포트가 아니다 — 자리 바꾼 숫자를 그대로 읽는 습관이 필요하다.
  • DNS = 53(UDP·TCP 둘 다) — "DNS는 UDP만 쓴다"는 서술이 나오면 오답이다. FTP = 21(제어) / 20(데이터).
  • 결정타: 이 문항은 틀린 연결이 ③(POP3–25)과 ④(HTTPS–433) 두 개여서 복수정답 처리되었다. ③은 프로토콜–포트 교차 오류, ④는 443을 433으로 적은 숫자 오류다.
