115번 · 공개키 암호 시스템의 키 개수와 연산 속도

제25회(2024년) 정보시스템감리사 A형 — 보안

사전 지식​

1. 대칭키 vs 공개키 — 근본 비교표​

2. 키 개수 — 왜 공개키가 훨씬 적은가​

대칭키: 두 사람이 통신할 때마다 그 쌍만의 비밀키가 하나씩 필요하다. nnn명 중 2명을 뽑는 조합이므로

대칭키 필요 수=(n2)=n(n−1)2\text{대칭키 필요 수} = \binom{n}{2} = \frac{n(n-1)}{2}대칭키 필요 수=(2n​)=2n(n−1)​

공개키: 각자 자기 키 쌍(공개키 1 + 개인키 1)만 있으면 누구와도 통신할 수 있다. 상대가 늘어나도 내 키는 그대로다.

공개키 필요 수=2n\text{공개키 필요 수} = 2n공개키 필요 수=2n

실제 값을 계산해 보면 차이가 극적이다.

사용자 수 nnn대칭키 n(n−1)2\dfrac{n(n-1)}{2}2n(n−1)​공개키 2n2n2n비율
104520대칭키가 2.3배
1004,950200대칭키가 약 25배
1,000499,5002,000대칭키가 약 250배
10,00049,995,00020,000대칭키가 약 2,500배

위 수치는 python으로 직접 계산해 검증하였다.

nnn이 커질수록 대칭키는 O(n2)O(n^2)O(n2) 로 폭증하고 공개키는 O(n)O(n)O(n) 에 머문다. 즉 공개키 방식이 관리할 키가 훨씬 적다. ③번 보기의 "공개키 방식이 관리할 키가 많다"는 서술은 이 관계를 정반대로 뒤집은 것이다.

(참고: 대칭키의 조합 폭증 문제를 KDC 같은 중앙 키 분배 센터로 완화하는 방법도 있으나, 이 경우 KDC가 SPOF이자 전면 신뢰 지점이 된다.)

3. 연산 속도 — 왜 공개키가 느린가​

방식핵심 연산상대 속도(대략)
AES(대칭키)XOR, S-box 치환, 시프트 등 비트 단위 경량 연산. 하드웨어 명령(AES-NI) 지원기준 (GB/s 급)
RSA(공개키)모듈러 지수승 c=me mod nc = m^e \bmod nc=memodn — 2048~4096비트 정수 거듭제곱대칭키 대비 수백~수천 배 느림
ECC(공개키)타원곡선 스칼라 곱 Q=kPQ = kPQ=kPRSA보다 빠르나 여전히 대칭키보다 훨씬 느림

따라서 실무는 하이브리드 암호 시스템을 쓴다.

역할담당이유
메시지 본문 암호화대칭키(AES 등) + 세션키대용량을 빠르게 처리해야 함
세션키 전달공개키(RSA/ECDH 등)짧은 데이터(세션키)만 처리하면 되고, 키 분배 문제를 해결
부인방지·무결성공개키(전자서명)개인키 보유자만 서명 생성 가능

TLS, PGP, S/MIME 모두 이 구조를 따른다. "공개키는 계산이 빨라 메시지 암호화에 주로 쓴다"는 서술은 하이브리드 구조가 존재하는 이유 자체를 부정하는 말이다.

4. 공개키의 두 가지 사용 방향 — 기밀성과 부인방지​

같은 키 쌍이라도 어느 키로 먼저 처리하느냐에 따라 얻는 성질이 다르다.

목적암호화(서명 생성) 키복호화(서명 검증) 키얻는 성질
기밀성수신자의 공개키수신자의 개인키수신자만 읽을 수 있음
인증·부인방지(전자서명)송신자의 개인키송신자의 공개키송신자만 만들 수 있음

②번 보기는 이 표의 첫 번째 행(기밀성) 을 정확히 서술한 것이다. 방향을 뒤집어 "송신자의 개인키로 암호화해 보내면 기밀성이 보장된다"고 쓰면 오답이 된다(누구나 공개키로 열 수 있으므로 기밀성이 아니라 서명이 된다).

5. ECC의 키 길이 효율 — NIST SP 800-57 기준​

ECC(Elliptic Curve Cryptography) 는 타원곡선 이산대수 문제(ECDLP) 의 어려움에 기반한다. ECDLP를 푸는 최선의 일반 알고리즘이 지수 시간인 데 반해, RSA의 기반인 소인수분해는 준지수 시간 알고리즘(GNFS) 이 존재한다. 그래서 같은 안전성을 얻는 데 ECC가 훨씬 짧은 키로 충분하다.

NIST SP 800-57 Part 1 Rev. 5, Table 2(Comparable security strengths)

보안 강도(bit)대칭키RSA(IFC) 키 길이ECC 키 길이
1123TDEA2048224~255
128AES-1283072256~383
192AES-1927680384~511
256AES-25615360512 이상

즉 ECC 256비트 ≈ RSA 3072비트 ≈ AES-128 수준이다. ④번 보기의 "상대적으로 짧은 키로 대등한 안전성"은 이 표와 정확히 일치한다. 이 특성 덕분에 ECC는 IoT·모바일·스마트카드처럼 연산·대역폭·저장 공간이 제한된 환경에서 선호된다.

6. 혼동하기 쉬운 인접 개념​

함정사실
"공개키는 키가 많아 관리가 어렵다"반대. 대칭키가 O(n2)O(n^2)O(n2), 공개키는 O(n)O(n)O(n). 다만 공개키는 "이 공개키가 진짜 그 사람 것인가" 를 보증할 PKI·인증서·CA 체계가 필요하다는 별도 부담이 있다
"공개키는 키 분배가 필요 없으므로 하이브리드도 불필요"세션키를 공개키로 감싸 보내는 것 자체가 키 캡슐화(KEM) 라는 분배 과정이다
"ECC가 RSA보다 안전하다"같은 보안 강도라면 안전성은 대등하고, ECC는 키가 짧아 효율적인 것이다
"공개키가 대칭키보다 안전하다"안전성은 키 길이·보안 강도로 비교해야 한다. 방식 자체의 우열이 아니다

상세 풀이​

"가장 적절하지 않은 것"을 고르는 부정형 문항이다. ③은 두 가지 주장이 모두 사실과 반대이므로 명백한 오류 문장이다.

  1. ① "공개키와 개인키 키 쌍이 존재하며, 암복호화에 서로 다른 키를 사용하므로 비대칭키 암호 방식이라고도 한다." → 비대칭키 암호의 정의 그 자체다. → 적절.
  2. ② "송신자가 수신자의 공개키로 암호화한 메시지를 전송하면 수신자는 자신의 개인키로 복호화한다." → 기밀성 제공 방향의 정확한 서술이다. 수신자의 개인키를 가진 사람은 수신자뿐이므로 수신자만 열 수 있다. → 적절.
  3. ③ "공개키 암호 방식은 대칭키 암호화 방식에 비해 관리해야 할 키의 개수가 많지만, 계산 속도가 빨라 메시지 암호화에 주로 사용한다." → 키 개수도 속도도 모두 반대다. → 부적절 = 정답.
  4. ④ "ECC는 RSA 등에 비해 상대적으로 짧은 길이의 키를 사용하여 대등한 수준의 안전성을 제공할 수 있다." → NIST SP 800-57 Part 1 Rev. 5 Table 2의 키 길이 대응 관계(ECC 256 ≈ RSA 3072)와 일치한다. → 적절.

오답 이유​

  • ①이 적절한 이유: 공개키 암호의 정의를 그대로 옮긴 문장이다. 암호화 키와 복호화 키가 다르기 때문에 "비대칭(asymmetric)"이라 부르며, 공개키는 공개해도 개인키를 계산해 낼 수 없다는 일방향 수학 문제(소인수분해, 이산대수, 타원곡선 이산대수)가 안전성의 근거다.
  • ②가 적절한 이유: 기밀성을 얻으려면 수신자만 열 수 있어야 하므로 수신자의 공개키로 잠그고 수신자의 개인키로 연다. 방향을 뒤집어 송신자의 개인키로 처리하면 그것은 기밀성이 아니라 전자서명이 되며, 누구나 송신자의 공개키로 열 수 있으므로 기밀성은 전혀 제공되지 않는다.
  • ③이 부적절한 이유: 두 주장이 모두 반대다. ⓐ 키 개수 — nnn명이 상호 통신할 때 대칭키는 n(n−1)/2n(n-1)/2n(n−1)/2 개가 필요하지만 공개키는 각자 키 쌍 하나씩, 총 2n2n2n 개면 충분하다. n=1,000n=1{,}000n=1,000이면 499,500개 대 2,000개로 250배 차이가 난다. ⓑ 속도 — RSA·ECC는 큰 정수 모듈러 지수승이나 타원곡선 스칼라 곱 같은 무거운 연산을 수행하므로 AES 대비 수백~수천 배 느리다. 그래서 실제 시스템은 메시지 본문은 대칭키로, 그 세션키만 공개키로 처리하는 하이브리드 구조를 쓴다. 올바른 서술로 고치면 "공개키 암호 방식은 대칭키 방식에 비해 관리해야 할 키의 개수가 적지만, 계산 속도가 느려 메시지 본문 암호화보다는 세션키 분배와 전자서명에 주로 사용한다"가 된다.
  • ④가 적절한 이유: ECC의 안전성은 타원곡선 이산대수 문제(ECDLP) 에 기반하는데, ECDLP에는 RSA의 소인수분해를 공격하는 GNFS 같은 준지수 시간 알고리즘이 알려져 있지 않다. 그 결과 NIST SP 800-57 Part 1 Rev. 5의 대응표대로 ECC 256비트가 RSA 3072비트와 같은 128비트 보안 강도를 낸다. 키·서명·인증서가 짧아져 IoT, 모바일, 스마트카드처럼 자원이 제한된 환경에 유리하다.

핵심 정리​

  • 키 개수: 대칭키 n(n−1)2\dfrac{n(n-1)}{2}2n(n−1)​ (= O(n2)O(n^2)O(n2)) vs 공개키 2n2n2n (= O(n)O(n)O(n)) — 공개키가 훨씬 적다.
  • 속도: 대칭키 ≫ 공개키. 그래서 본문은 대칭키, 세션키는 공개키로 처리하는 하이브리드 암호 시스템을 쓴다.
  • 방향: 기밀성 = 수신자 공개키로 암호화 / 수신자 개인키로 복호화, 전자서명 = 송신자 개인키로 서명 / 송신자 공개키로 검증.
  • NIST SP 800-57 Part 1 Rev. 5 Table 2: ECC 256 ≈ RSA 3072 ≈ AES-128(128비트 보안 강도).
  • "공개키는 키가 많고 빠르다"는 두 마디가 모두 거꾸로 — 이 문장이 보이면 즉시 오답으로 확정할 수 있다.
