072번 · Apache Spark의 핵심 데이터 추상화 RDD

제25회(2024년) 정보시스템감리사 A형 — 데이터베이스

사전 지식​

1. 빅데이터 스택의 계층 구분​

용어를 고를 때 가장 먼저 해야 할 일은 "저장 계층인가, 연산 계층인가" 를 가르는 것이다.

계층역할대표 구성요소
저장(storage)데이터를 블록으로 나눠 분산 보관HDFS, S3, HBase, Ceph
자원 관리(resource)클러스터 CPU/메모리 할당YARN, Mesos, Kubernetes
연산(processing)분산 계산 모델과 추상화MapReduce, Spark(RDD/DataFrame), Flink
질의/응용(query)SQL·ML·스트리밍 인터페이스Hive, Spark SQL, MLlib

문제 지문은 "관계형 데이터베이스가 데이터 표현을 위한 추상화로 릴레이션을 사용하듯"이라고 명시한다. 즉 파일 시스템(저장 계층)이 아니라 연산 계층의 데이터 추상화를 묻고 있다.

2. HDFS(Hadoop Distributed File System)​

항목내용
정식 명칭Hadoop Distributed File System (Distributed = 분산)
구조NameNode(메타데이터·네임스페이스) + DataNode(실제 블록 저장)
블록기본 128MB(구버전 64MB) 단위로 분할
복제기본 복제 계수 3 — 가용성 확보 수단이지 "Duplicated"라는 이름의 근거는 아님
특성Write-Once-Read-Many, 대용량 순차 읽기에 최적화

Spark은 HDFS에서 데이터를 읽어오지만, HDFS 자체는 Spark의 연산 추상화가 아니다. Spark은 로컬 파일, S3, JDBC 등에서도 똑같이 읽을 수 있다.

3. RDD(Resilient Distributed Dataset)​

RDD = 탄력적 분산 데이터셋. Spark의 근본 추상화이며, 논문 "Resilient Distributed Datasets: A Fault-Tolerant Abstraction for In-Memory Cluster Computing"(NSDI 2012)에서 제안되었다.

약어의미설계 의도
Resilient탄력적(장애 복원력)계보(lineage) 를 기록해 두었다가 노드 장애 시 잃은 파티션만 재계산해 복구
Distributed분산클러스터 여러 노드에 파티션(partition) 단위로 흩어져 존재
Dataset데이터셋타입이 있는 불변(immutable) 레코드 컬렉션

RDD의 5가지 내부 속성

속성설명
파티션 목록병렬 처리의 최소 단위
파티션별 계산 함수각 파티션을 어떻게 만들어내는지
부모 RDD 의존성narrow(1:1) / wide(shuffle) 의존
(선택) 파티셔너key-value RDD의 해시·범위 분할 방식
(선택) 선호 위치데이터 지역성(locality) 힌트

4. 연산자 모델 — 문제 지문과의 대응​

지문의 "하나 이상의 ㉮를 입력으로 받아 출력으로 ㉮를 반환"은 Spark의 변환(transformation) 연산자를 그대로 서술한 것이다.

구분예반환실행 시점
변환(transformation)map, filter, flatMap, join, union, groupByKey새 RDD지연(lazy) — DAG만 쌓임
액션(action)count, collect, reduce, saveAsTextFile값 또는 파일즉시 실행(DAG 스케줄링 유발)

RDD는 불변이므로 map은 원본을 고치지 않고 새 RDD를 만든다. 이 "입력도 RDD, 출력도 RDD"라는 폐쇄성이 관계대수에서 릴레이션을 입력받아 릴레이션을 반환하는 것과 정확히 같은 구조이며, 문제가 릴레이션에 빗댄 이유다.

5. 계보(lineage) 기반 장애 복구​

textFile ──map──▶ RDD1 ──filter──▶ RDD2 ──reduceByKey──▶ RDD3

노드 장애로 RDD2의 파티션 3이 유실되면, Spark은 체크포인트나 복제본이 없어도 계보를 거슬러 올라가 해당 파티션만 재계산한다. 데이터를 복제해 두는 HDFS의 방식과 달리 연산 이력을 복제하는 셈이며, 이것이 이름의 "Resilient"다.

6. Spark 추상화의 진화​

세대추상화특징
Spark 1.xRDD타입 안전, 저수준, 최적화기 없음
Spark 1.3+DataFrame스키마 보유, Catalyst 옵티마이저 적용, 관계형 질의 최적화
Spark 1.6+DatasetDataFrame + 컴파일 타임 타입 안전

DataFrame/Dataset도 내부적으로는 RDD 위에 구축되어 있어, RDD는 여전히 Spark의 근간이다.

7. 혼동하기 쉬운 인접 개념​

용어정확한 풀이무엇인가
HDFSHadoop Distributed File System분산 파일 시스템(저장 계층)
RDDResilient Distributed DatasetSpark의 연산 추상화
DAGDirected Acyclic GraphRDD 간 의존 관계를 나타낸 실행 계획
Lineage계보장애 시 재계산 경로

상세 풀이​

1단계 — 문제 유형​

"㉮에 들어갈 용어로 가장 올바른 것"을 고르는 긍정형 빈칸 채우기 문항이다. 보기가 HDFS 2개·RDD 2개로 짝지어져 있고 약어 풀이만 다르므로, 다음 두 가지를 동시에 판정해야 한다.

  1. 개념이 맞는가 (HDFS냐 RDD냐)
  2. 약어 풀이가 맞는가 (Distributed냐 Duplicated냐)

2단계 — 개념 판정: HDFS인가 RDD인가​

지문을 두 조각으로 나눠 보면 명확하다.

지문요구하는 성질판정
"관계형 DB가 데이터 표현을 위한 추상화로 릴레이션을 사용하듯"저장 포맷이 아니라 논리적 데이터 추상화HDFS는 파일 시스템이므로 부적합
"연산자가 하나 이상의 ㉮를 입력받아 출력으로 ㉮를 반환"연산에 대해 닫혀 있는(closed) 자료형map/filter가 RDD→RDD 이므로 RDD

HDFS는 파일을 읽고 쓰는 대상이지, "HDFS를 입력받아 HDFS를 반환하는 연산자"라는 개념이 없다. → RDD 확정

3단계 — 약어 판정​

보기약어 풀이옳은 풀이판정
①Hadoop Distributed File System✔ 정확한 풀이약어는 맞지만 개념이 틀림
②Hadoop Duplicated File System✘ Distributed가 맞음개념·약어 모두 틀림
③Resilient Distributed Dataset✔ 정확한 풀이개념·약어 모두 정확
④Reproducible Duplicated Dataset✘ Resilient Distributed가 맞음개념은 방향이 맞으나 약어가 틀림

3단계 보충 — ④가 특히 교묘한 이유​

"Reproducible(재현 가능한)"은 계보 기반 재계산의 성질을 어느 정도 설명하는 것처럼 보이는 단어다. 하지만 원 논문과 공식 문서의 정식 명칭은 Resilient이며, "Duplicated(복제된)"는 RDD의 특성이 아니다. RDD는 복제가 아니라 재계산으로 복구한다는 것이 설계의 핵심 차별점이므로 Duplicated는 오히려 정반대 뉘앙스다.

4단계 — 결론​

③ RDD(Resilient Distributed Dataset) 가 정답이다.

보기별 판정​

보기판정근거
① HDFS(Hadoop Distributed File System)오답 보기약어 풀이는 정확하나, HDFS는 저장 계층의 파일 시스템으로 "연산자의 입출력이 되는 데이터 추상화"가 아니다
② HDFS(Hadoop Duplicated File System)오답 보기개념도 틀리고 약어도 틀림. HDFS의 D는 Distributed이며 Duplicated가 아니다
③ RDD(Resilient Distributed Dataset)✅ 정답 보기Spark의 핵심 추상화이자 정확한 약어 풀이. 변환 연산자가 RDD를 입력받아 RDD를 반환한다
④ RDD(Reproducible Duplicated Dataset)오답 보기개념(RDD)은 맞는 방향이나 약어 풀이가 틀림. Resilient Distributed가 정답

오답 이유​

  • ①이 틀린 이유: HDFS는 Hadoop 생태계의 분산 파일 시스템이다. Spark이 데이터를 읽어 오는 원천일 수는 있으나, "연산자가 HDFS를 입력받아 HDFS를 반환한다"는 서술은 성립하지 않는다. 릴레이션에 대응하는 것은 파일 시스템이 아니라 연산에 닫혀 있는 데이터셋 추상화다. 또한 Spark은 HDFS 없이 로컬 파일이나 S3만으로도 동작하므로, HDFS가 Spark의 필수 추상화일 수도 없다.
  • ②가 틀린 이유: ①의 오류에 더해 약어 풀이까지 틀렸다. HDFS의 D는 Distributed(분산) 다. HDFS가 기본 복제 계수 3으로 블록을 복제하는 것은 사실이지만, 그것이 이름의 근거는 아니다. "복제" 개념을 이름에 억지로 끼워 넣은 함정 보기다.
  • ③이 맞는 이유: 지문의 두 조건 — ⓐ 데이터 표현을 위한 추상화, ⓑ 연산자의 입력이자 출력 — 을 모두 만족하는 것은 RDD뿐이며, Resilient Distributed Dataset은 Spark 공식 문서의 정확한 명칭이다.
  • ④가 틀린 이유: RDD라는 개념을 고른 것까지는 맞지만 약어 풀이가 틀렸다. R은 Resilient(탄력적) — 계보를 이용한 재계산 복구를 뜻하고, 두 번째 D는 Distributed(분산) — 파티션이 클러스터에 흩어져 있음을 뜻한다. "Duplicated(복제된)"는 RDD가 택하지 않은 복구 방식이므로 특히 부적절하다. 이 문항처럼 같은 약어를 다르게 풀어 놓은 보기가 나오면 원어를 정확히 외웠는지가 승부처다.

핵심 정리​

  • RDD = Resilient Distributed Dataset — Spark의 핵심 데이터 추상화. 불변이며 파티션 단위로 분산되고, 계보(lineage) 로 장애를 복구한다.
  • HDFS = Hadoop Distributed File System — Hadoop의 저장 계층. Spark의 입력 원천일 뿐 연산 추상화가 아니다. "Duplicated"가 아니라 Distributed.
  • 변환(transformation: map/filter/join)은 RDD → RDD 로 닫혀 있고 지연 평가되며, 액션(action: count/collect)이 호출될 때 비로소 실행된다. 이 폐쇄성이 관계대수의 릴레이션과 대응하는 지점이다.
  • Spark 추상화의 진화: RDD → DataFrame(Catalyst 최적화) → Dataset(타입 안전). 상위 추상화도 내부는 RDD다.
  • 이 문제의 결정타: 지문의 "연산자가 ㉮를 입력받아 ㉮를 반환한다"는 연산 계층 추상화를 가리키므로 파일 시스템인 HDFS는 탈락하고, 남은 두 RDD 보기 중 정확한 약어 풀이인 Resilient Distributed Dataset만 답이 된다.
