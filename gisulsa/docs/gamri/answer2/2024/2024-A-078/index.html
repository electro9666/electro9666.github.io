078번 · 리눅스(POSIX)의 파일 종류 7가지

제25회(2024년) 정보시스템감리사 A형 — 시스템 구조

사전 지식​

1. "모든 것은 파일이다" — 유닉스 철학​

리눅스/유닉스는 일반 데이터뿐 아니라 장치, 프로세스 간 통신 통로, 네트워크 종단점까지 모두 파일 인터페이스(open/read/write/close)로 다룬다. 그래서 "파일의 종류"라는 분류가 단순한 확장자 구분이 아니라 커널이 인식하는 객체 유형을 뜻하게 된다.

2. 파일 종류는 inode의 st_mode에 기록된다​

파일의 메타데이터는 inode에 저장되고, 그중 st_mode 필드의 상위 비트가 파일 타입을 나타낸다.

매크로의미
S_ISREG()일반 파일
S_ISDIR()디렉터리
S_ISLNK()심볼릭 링크
S_ISCHR()문자 장치
S_ISBLK()블록 장치
S_ISFIFO()FIFO(명명 파이프)
S_ISSOCK()소켓

타입 비트가 정의된 값이 이 7가지뿐이므로, 리눅스의 파일 종류는 7종으로 고정되어 있다.

3. 리눅스 파일 7종 — ls -l 첫 문자로 구분​

첫 문자종류설명예
-일반 파일(regular)텍스트·바이너리 등 실제 데이터/etc/passwd, /bin/ls
d디렉터리(directory)파일 이름 ↔ inode 번호 매핑 테이블/home, /etc
l심볼릭 링크(symbolic link)다른 경로를 가리키는 포인터 파일/bin → /usr/bin
c문자 장치(character device)바이트 단위 입출력 장치/dev/tty, /dev/null, /dev/random
b블록 장치(block device)블록 단위 입출력 장치(버퍼 사용)/dev/sda, /dev/loop0
pFIFO / 명명 파이프(named pipe)프로세스 간 단방향 통신 통로mkfifo mypipe 로 생성
s소켓(socket)프로세스 간 양방향 통신 종단점/var/run/docker.sock
$ ls -l
-rw-r--r--  1 root root  1234 ...  passwd      ← 일반 파일
drwxr-xr-x  2 root root  4096 ...  network     ← 디렉터리
lrwxrwxrwx  1 root root     7 ...  bin -> usr/bin   ← 심볼릭 링크
crw-rw-rw-  1 root root  1, 3 ...  null        ← 문자 장치
brw-rw----  1 root disk  8, 0 ...  sda         ← 블록 장치
prw-r--r--  1 user user     0 ...  mypipe      ← FIFO
srw-rw----  1 root root     0 ...  docker.sock ← 소켓

암기 요령: - d l c b p s — "일디심 / 문블 / 파소"

4. FIFO(명명 파이프)를 파일 종류로 보는 이유​

구분익명 파이프FIFO(명명 파이프)
생성pipe() 시스템 콜mkfifo() 또는 mknod
이름없음파일 시스템에 경로가 존재
사용 범위부모-자식 등 혈연 프로세스무관한 프로세스끼리도 가능
ls -l보이지 않음p 로 표시

FIFO는 파일 시스템 네임스페이스에 이름을 가진 inode로 존재하므로 정식 파일 종류다. 데이터는 디스크에 저장되지 않고 커널 버퍼를 거쳐 흐른다.

5. "가상 파일시스템"은 파일 종류가 아니다 — 이 문제의 함정​

리눅스에는 VFS(Virtual File System) 라는 개념과, /proc·/sys·/dev 같은 가상(의사) 파일시스템이 있다. 하지만 이는 파일시스템 계층의 개념이지 파일의 종류가 아니다.

용어층위설명
VFS(가상 파일시스템)커널 추상화 계층ext4·XFS·NFS 등을 하나의 인터페이스로 통합
procfs / sysfs / tmpfs파일시스템 종류디스크가 아닌 커널 메모리 기반
파일 종류(file type)개별 파일의 속성- d l c b p s 7가지

결정적으로, /proc 안의 개체들도 실제로는 7종 중 하나로 표시된다.

$ ls -l /proc/1/
-r--r--r--  1 root root 0 ... cmdline     ← 일반 파일(-)
dr-xr-xr-x  2 root root 0 ... fd          ← 디렉터리(d)
lrwxrwxrwx  1 root root 0 ... exe -> /sbin/init   ← 심볼릭 링크(l)

즉 "가상 파일"이라는 독립된 파일 타입은 존재하지 않는다.

6. 혼동하기 쉬운 인접 개념​

용어파일 종류인가정체
FIFO 파일✅ 예 (p)명명 파이프
소켓 파일✅ 예 (s)유닉스 도메인 소켓
가상 파일❌ 아님정식 타입 없음. 가상 파일시스템과 혼동한 표현
하드 링크❌ 아님같은 inode를 가리키는 또 다른 이름(타입은 원본과 동일)
숨김 파일❌ 아님이름이 . 으로 시작하는 관례일 뿐
특수 파일(special file)상위 묶음장치·FIFO·소켓을 아우르는 총칭
실행 파일❌ 아님일반 파일 + 실행 권한 비트

문제​

정답​

②

상세 풀이​

1단계 — 문제 유형​

"리눅스의 파일 종류로 가장 적절하지 않은 것"을 고르는 부정형 문항이다. 즉 네 보기 중 정식 파일 타입이 아닌 하나를 찾으면 된다.

2단계 — 각 보기를 7종 목록에 대조​

보기ls -l 첫 문자st_mode 매크로7종 목록에 있는가
① FIFO 파일pS_ISFIFO()✅ 있음
② 가상 파일없음대응 매크로 없음❌ 없음
③ 일반 파일-S_ISREG()✅ 있음
④ 디렉토리 파일dS_ISDIR()✅ 있음

3단계 — ②가 왜 없는 종류인가​

  • 리눅스의 파일 종류는 inode st_mode의 타입 비트로 결정되며, 정의된 값은 7가지뿐이다: -(일반), d(디렉터리), l(심볼릭 링크), c(문자 장치), b(블록 장치), p(FIFO), s(소켓).
  • "가상 파일"에 해당하는 비트나 매크로가 존재하지 않는다.
  • /proc, /sys 같은 가상 파일시스템(procfs, sysfs) 은 존재하지만, 그것은 파일시스템의 종류이지 파일의 종류가 아니다. 그 안의 개체들도 조회해 보면 -, d, l 로 표시된다.

4단계 — ①·③·④가 정식 종류인 근거​

보기근거
① FIFO 파일mkfifo 로 생성되는 명명 파이프. 파일 시스템에 경로와 inode를 갖고 ls -l에서 p 로 표시된다. 무관한 프로세스 간 IPC 수단
③ 일반 파일텍스트·바이너리 등 실제 데이터를 담는 가장 기본 유형. - 로 표시
④ 디렉토리 파일리눅스에서 디렉터리도 파일이다. 내용은 "파일 이름 ↔ inode 번호" 쌍의 목록이며 d 로 표시

5단계 — 결론​

정식 파일 종류가 아닌 것은 ② 가상 파일 → 정답 ②

보기별 판정​

보기판정근거
① FIFO 파일오답 보기(적절한 종류)명명 파이프. ls -l 첫 문자 p, S_ISFIFO() 로 판별되는 정식 타입
② 가상 파일✅ 정답 보기(적절하지 않은 종류)st_mode 타입 비트에 대응하는 값이 없다. 가상 파일시스템(procfs/sysfs)과 혼동한 표현
③ 일반 파일오답 보기(적절한 종류)- 로 표시되는 가장 기본 유형. S_ISREG()
④ 디렉토리 파일오답 보기(적절한 종류)d 로 표시. 리눅스에서 디렉터리 역시 파일의 한 종류다. S_ISDIR()

오답 이유​

  • ①이 적절한 종류인 이유: FIFO는 mkfifo pipe1 로 만들면 파일 시스템에 이름과 inode를 갖는 실체가 생기고, ls -l 에서 prw-r--r-- 처럼 p 로 표시된다. 한쪽 프로세스가 쓰고 다른 쪽이 읽는 단방향 통로이며, pipe() 로 만드는 익명 파이프와 달리 혈연 관계가 없는 프로세스끼리도 사용할 수 있다. 장치 파일·소켓과 함께 특수 파일(special file) 로 묶이지만, 특수 파일이라고 해서 파일 종류가 아닌 것은 아니다.
  • ②가 적절하지 않은 이유(= 정답): POSIX/리눅스가 정의하는 파일 타입 비트에는 "가상 파일"이 없다. 존재하는 것은 /proc, /sys, tmpfs 같은 가상 파일시스템이며, 이는 디스크가 아닌 커널 메모리에서 내용이 생성되는 파일시스템 종류를 가리킨다. 그 안의 항목을 ls -l /proc/1 로 확인해 보면 cmdline은 일반 파일(-), fd는 디렉터리(d), exe는 심볼릭 링크(l)로 나타난다. 즉 "가상"은 내용이 어디서 오는가에 대한 성질일 뿐, 파일 타입의 분류 항목이 아니다.
  • ③이 적절한 종류인 이유: 일반 파일(regular file)은 - 로 표시되며 텍스트 파일, 실행 바이너리, 이미지 등 실제 데이터를 담는다. 실행 파일도 별도 종류가 아니라 일반 파일에 실행 권한(x) 비트가 붙은 것이다.
  • ④가 적절한 종류인 이유: 리눅스에서 디렉터리는 특별한 개체가 아니라 파일 이름과 inode 번호의 매핑 목록을 내용으로 갖는 파일이다. ls -l 에서 d 로 표시되며 S_ISDIR() 로 판별한다. "디렉터리는 파일이 아니다"라고 생각하면 걸리는 함정이지만, 유닉스 철학상 디렉터리도 엄연한 파일 종류다.

핵심 정리​

  • 리눅스(POSIX) 파일 종류는 정확히 7가지: - 일반, d 디렉터리, l 심볼릭 링크, c 문자 장치, b 블록 장치, p FIFO(명명 파이프), s 소켓. - d l c b p s 로 외운다.
  • 파일 종류는 inode의 st_mode 타입 비트로 결정되며, ls -l 출력의 첫 문자가 그것을 보여 준다.
  • 디렉터리도 파일이고, FIFO·소켓·장치 파일도 파일이다. 장치·FIFO·소켓을 묶어 특수 파일이라 부르지만 여전히 정식 종류다.
  • "가상 파일시스템"(procfs/sysfs/tmpfs) 은 있어도 "가상 파일"이라는 파일 종류는 없다. /proc 내부 항목도 일반 파일·디렉터리·심볼릭 링크로 표현된다.
  • 이 문제의 결정타: 7종 목록(- d l c b p s)에 "가상"이 없다는 사실 하나로 ②가 확정된다. 계층을 헷갈리게 만든 전형적 함정이므로, 파일시스템의 종류 ≠ 파일의 종류 를 분명히 구분하라.
