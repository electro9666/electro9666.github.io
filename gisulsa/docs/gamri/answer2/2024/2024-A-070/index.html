070번 · NOT IN 부질의에 NULL이 섞였을 때의 결과

제25회(2024년) 정보시스템감리사 A형 — 데이터베이스

사전 지식​

1. SQL의 NULL은 "값"이 아니다​

NULL은 0도 빈 문자열도 아니다. "값이 알려지지 않았거나 적용되지 않음" 을 나타내는 표지(marker) 다. 따라서 NULL이 관여한 비교는 참도 거짓도 아닌 제3의 진리값 UNKNOWN 을 낳는다.

식결과
NULL = NULLUNKNOWN (TRUE 아님!)
NULL <> NULLUNKNOWN
10 = NULLUNKNOWN
10 <> NULLUNKNOWN
NULL IS NULLTRUE ← IS NULL 만이 예외적으로 TRUE/FALSE를 반환
NULL IS NOT NULLFALSE

NULL을 검사하는 유일한 방법은 IS NULL / IS NOT NULL 이다. = NULL 은 절대 참이 되지 않는다.

2. 3값 논리(three-valued logic)의 진리표​

SQL은 TRUE, FALSE, UNKNOWN 세 값을 쓰는 논리 체계 위에서 동작한다.

AND

TRUETRUEFALSEUNKNOWN
FALSEFALSEFALSEFALSE
UNKNOWNUNKNOWNFALSEUNKNOWN

TRUETRUETRUETRUE

핵심 성질 두 가지를 기억한다.

  • AND 에서는 FALSE가 지배한다. 하나라도 FALSE면 전체가 FALSE.
  • AND 에서 UNKNOWN은 지워지지 않는다. TRUE와 만나면 UNKNOWN이 그대로 남는다.

3. WHERE 절의 통과 규칙 — 가장 중요한 한 줄​

WHERE 절은 조건이 TRUE 인 행만 통과시킨다. FALSE 와 UNKNOWN 은 똑같이 버려진다.

이것이 NULL 관련 함정의 근원이다. UNKNOWN 은 "모르겠다"는 뜻이지만 WHERE 절은 이를 거부로 처리한다. 반면 CHECK 제약은 정반대로 FALSE 일 때만 거부하고 UNKNOWN 은 통과시킨다.

절통과시키는 진리값
WHERE / HAVING / ONTRUE만
CHECK 제약TRUE와 UNKNOWN (FALSE만 거부)

4. IN 과 NOT IN 의 전개​

IN 과 NOT IN 은 문법 설탕(syntactic sugar)일 뿐이며, 내부적으로는 다음과 같이 비교의 연쇄로 전개된다.

x  IN  (v1,v2,v3)  ≡  (x=v1)  OR  (x=v2)  OR  (x=v3)x \;\texttt{IN}\; (v_1, v_2, v_3) \;\equiv\; (x = v_1) \;\texttt{OR}\; (x = v_2) \;\texttt{OR}\; (x = v_3)xIN(v1​,v2​,v3​)≡(x=v1​)OR(x=v2​)OR(x=v3​) x  NOT IN  (v1,v2,v3)  ≡  (x≠v1)  AND  (x≠v2)  AND  (x≠v3)x \;\texttt{NOT IN}\; (v_1, v_2, v_3) \;\equiv\; (x \neq v_1) \;\texttt{AND}\; (x \neq v_2) \;\texttt{AND}\; (x \neq v_3)xNOT IN(v1​,v2​,v3​)≡(x=v1​)AND(x=v2​)AND(x=v3​)

여기서 재앙이 시작된다. 목록에 NULL이 하나라도 있으면

연산전개NULL 항의 값전체 결과
IN... OR (x = NULL)UNKNOWN다른 항이 TRUE면 TRUE로 구제됨 (OR은 TRUE가 지배)
NOT IN... AND (x <> NULL)UNKNOWN다른 항이 전부 TRUE여도 UNKNOWN (AND에서 UNKNOWN이 남음)
TRUE⏟x≠v1  AND  TRUE⏟x≠v2  AND  UNKNOWN⏟x≠NULL  =  UNKNOWN\underbrace{\texttt{TRUE}}_{x \neq v_1} \;\texttt{AND}\; \underbrace{\texttt{TRUE}}_{x \neq v_2} \;\texttt{AND}\; \underbrace{\texttt{UNKNOWN}}_{x \neq \texttt{NULL}} \;=\; \texttt{UNKNOWN}x=v1​TRUE​​ANDx=v2​TRUE​​ANDx=NULLUNKNOWN​​=UNKNOWN

즉 NOT IN 의 부질의 결과에 NULL이 단 하나라도 있으면, 어떤 행도 TRUE 를 받을 수 없어 결과가 항상 공집합이 된다. 반면 IN 은 OR로 전개되므로 NULL에 오염되지 않고 정상 작동한다. IN 은 안전하고 NOT IN 은 위험하다는 비대칭이 여기서 나온다.

5. 안전한 대안 세 가지​

대안질의NULL에 안전한 이유
NOT EXISTSWHERE NOT EXISTS (SELECT 1 FROM R2 WHERE R2.age = R1.age)EXISTS 는 행의 존재 여부만 보므로 UNKNOWN을 만들지 않음(0행이면 FALSE, 1행 이상이면 TRUE)
LEFT OUTER JOIN … IS NULLFROM R1 LEFT JOIN R2 ON R1.age=R2.age WHERE R2.age IS NULL조인에 매칭되지 않은 행을 IS NULL 로 식별 — 2값 논리
부질의에서 NULL 제거NOT IN (SELECT age FROM R2 WHERE age IS NOT NULL)오염원 자체를 걷어냄

단, 세 대안이 서로 같은 결과를 주는 것은 아니다. 바깥 테이블에도 NULL이 있으면 NOT EXISTS 와 "NULL 제거한 NOT IN" 의 결과가 갈린다(뒤의 실행 검증 참조).

질의:

SELECT * FROM R1
WHERE R1.age NOT IN (SELECT age FROM R2);

부질의 SELECT age FROM R2 의 결과는 {30,40,NULL}\{30, 40, \textbf{NULL}\}{30,40,NULL} — NULL이 포함되어 있다. 이 시점에서 이미 결과는 공집합으로 결정된다.

2단계 — NOT IN 전개​

R1.age NOT IN (30, 40, NULL)
  ≡  (R1.age <> 30) AND (R1.age <> 40) AND (R1.age <> NULL)
                                              └───────────┘
                                          항상 UNKNOWN (NULL과의 비교)

세 번째 항 R1.age <> NULL 은 R1.age 가 무슨 값이든 언제나 UNKNOWN이다. NULL은 값이 아니므로 같은지 다른지 판정할 수 없기 때문이다.

동일한 스키마와 인스턴스를 SQLite에 만들어 질의를 실행했다.

R1 = [(1, 10), (2, 20), (3, 30), (4, None)]
R2 = [(3, 30), (4, 40), (5, None)]

[Q70 NOT IN]        -> []            ← 0행, 빈 릴레이션

각 행의 술어 진리값도 함께 출력했다.

--- truth value of each row's predicate ---
  id=1 age=10    predicate = UNKNOWN(NULL)
  id=2 age=20    predicate = UNKNOWN(NULL)
  id=3 age=30    predicate = FALSE
  id=4 age=None  predicate = UNKNOWN(NULL)

--- expansion: age<>30 AND age<>40 AND age<>NULL ---
  id=1 age=10    age<>30:T    age<>40:T    age<>NULL:UNK
  id=2 age=20    age<>30:T    age<>40:T    age<>NULL:UNK
  id=3 age=30    age<>30:F    age<>40:T    age<>NULL:UNK
  id=4 age=None  age<>30:UNK  age<>40:UNK  age<>NULL:UNK

3단계에서 손으로 계산한 진리표와 한 칸도 어긋나지 않는다.

IN (SELECT age FROM R2) (참고)[(3,30)]—

읽어 낼 점이 세 가지다.

  1. ② 는 R2의 NULL을 없앤 경우의 답이다. 즉 "부질의에 NULL이 있다"는 사실을 무시하면 ②가 나온다.
  2. ① 은 NOT EXISTS / 외부 조인으로 바꾼 경우의 답이다. 집합론적으로 "R2의 age 집합에 없는 R1 행"을 상식대로 구하면 ①이 나온다 — R1의 NULL(id=4)은 R2의 어느 값과도 매칭되지 않으므로 포함된다.
  3. IN 은 [(3,30)] 만 돌려준다. IN 결과(1행)와 NOT IN 결과(0행)를 합쳐도 R1 전체(4행)가 되지 않는다. 3값 논리에서는 IN 과 NOT IN 이 서로의 여집합이 아니다. 이것이 2값 논리 직관이 깨지는 지점이다.

6단계 — 결론​

부질의 결과에 NULL이 포함된 NOT IN 질의는 어떤 행도 TRUE를 받지 못해 결과가 공집합이다 → ③ 결과 없음(빈 릴레이션)

보기별 판정​

보기판정근거
① (1,10), (2,20), (4,NULL)오답 보기NOT EXISTS 나 LEFT JOIN … IS NULL 로 바꿨을 때의 결과. 원본 NOT IN 은 3값 논리로 UNKNOWN을 만들어 전부 탈락
② (1,10), (2,20)오답 보기부질의에서 NULL을 제거했을 때의 결과. R2의 NULL을 무시한 답이며, R1의 NULL 행(id=4)도 NULL <> 30 이 UNKNOWN이라 통과 못 함
③ 결과 없음(빈 릴레이션)✅ 정답 보기age <> NULL 이 항상 UNKNOWN이고 AND에서 지워지지 않아 어떤 행도 TRUE가 되지 못함. SQLite 실행 결과 0행으로 확인
④ (1,10), (2,20), (3,30), (4,NULL)오답 보기R1 전체를 그대로 반환한 것. NOT IN 조건을 아예 적용하지 않은 것과 같으며, 최소한 id=3은 30 <> 30 이 FALSE라 명백히 탈락

오답 이유​

  • ①이 틀린 이유: "R2의 age 값 집합 {30,40}\{30, 40\}{30,40} 에 없는 R1의 행"이라는 집합론적 직관으로 푼 답이다. NULL은 어느 값과도 같지 않으니 id=4도 포함시켰다. 이 직관 자체는 NOT EXISTS 나 외부 조인의 동작과 정확히 일치하며, 실행 검증에서도 두 질의 모두 [(1,10),(2,20),(4,NULL)] 을 돌려주었다. 그러나 NOT IN 은 집합 포함 여부가 아니라 비교의 AND 연쇄로 평가되므로 결과가 다르다. 이 보기를 답으로 만들려면 질의를 WHERE NOT EXISTS (SELECT 1 FROM R2 WHERE R2.age = R1.age) 로 바꿔야 한다.

  • ②가 틀린 이유: R2의 NULL 행(id=5)을 없는 셈 친 답이다. 부질의 결과를 {30,40}\{30, 40\}{30,40} 로만 보면 id=1, 2가 통과하고 id=3은 탈락하며 id=4는 NULL <> 30 이 UNKNOWN이라 역시 탈락해 정확히 ②가 나온다. 실제로 NOT IN (SELECT age FROM R2 WHERE age IS NOT NULL) 을 실행하면 [(1,10),(2,20)] 이 나온다. 그러나 원본 질의에는 그런 필터가 없다. 부질의는 R2의 모든 행을 돌려주므로 NULL이 포함되고, 그 한 개의 NULL이 전체 결과를 공집합으로 만든다.

  • ③이 맞는 이유: NOT IN 은 <> 의 AND 연쇄로 전개되고, 목록의 NULL 때문에 age <> NULL 항이 모든 행에서 UNKNOWN이 된다. AND 진리표상 TRUE AND UNKNOWN = UNKNOWN, FALSE AND UNKNOWN = FALSE 이므로 결과는 UNKNOWN 아니면 FALSE이고, TRUE는 결코 나오지 않는다. WHERE 절은 TRUE만 통과시키므로 결과는 0행이다. 손 계산과 SQLite 실행이 모두 일치한다.

  • ④가 틀린 이유: R1 전체를 그대로 반환했으므로 NOT IN 조건이 아무 역할도 하지 않은 셈이다. 그러나 id=3은 age = 30 이고 R2에도 30이 있으므로 30 <> 30 이 명백한 FALSE다. 3값 논리를 따지기 이전에, 2값 논리 상식으로도 id=3은 탈락해야 한다. NULL 규칙을 몰라도 배제할 수 있는 보기다.

핵심 정리​

  • NULL이 관여한 모든 비교(=, <>, <, >)는 UNKNOWN이다. NULL = NULL 조차 TRUE가 아니다. NULL을 검사하는 유일한 수단은 IS NULL / IS NOT NULL 이다.
  • WHERE 절은 TRUE인 행만 통과시킨다. FALSE와 UNKNOWN은 똑같이 버려진다. (CHECK 제약은 반대로 FALSE만 거부한다.)
  • IN 은 OR 의 연쇄, NOT IN 은 AND 의 연쇄로 전개된다. OR 에서는 TRUE가 UNKNOWN을 덮어써 구제되지만, AND 에서는 UNKNOWN이 끝까지 남는다. 그래서 IN 은 NULL에 안전하고 NOT IN 은 위험하다.
  • NOT IN 의 부질의 결과에 NULL이 하나라도 있으면 결과는 항상 공집합이다. 실무에서 "분명히 있어야 할 데이터가 안 나온다"는 버그의 단골 원인이다.
  • 안전한 대안: NOT EXISTS, LEFT OUTER JOIN … IS NULL, 또는 부질의에 WHERE 컬럼 IS NOT NULL 추가. 단, 바깥 테이블에도 NULL이 있으면 세 대안의 결과가 서로 다를 수 있으므로 의도를 명확히 하고 골라야 한다.
  • 이 문제의 결정타: 부질의 SELECT age FROM R2 가 NULL을 포함하므로 age <> NULL 항이 모든 행에서 UNKNOWN이 되고, TRUE인 행이 하나도 없어 결과는 빈 릴레이션(③)이다. SQLite 실행 결과도 0행으로 확인되었다.
