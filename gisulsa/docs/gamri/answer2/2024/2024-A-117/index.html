117번 · 하이브리드 암호 시스템의 역할 분담 구조

제25회(2024년) 정보시스템감리사 A형 — 보안

사전 지식​

1. 왜 하이브리드인가 — 두 방식의 장단점 결합​

대칭키와 공개키는 서로의 약점을 정확히 보완한다.

방식강점약점
대칭키(AES 등)연산이 매우 빠름 → 대용량 데이터 암호화에 적합키 분배 문제 — 사전에 안전한 채널로 키를 전달해야 함. nnn명이면 n(n−1)2\dfrac{n(n-1)}{2}2n(n−1)​ 개의 키 필요
공개키(RSA/ECC 등)키 분배 문제 없음(공개키는 공개해도 됨), 전자서명으로 부인방지 가능연산이 매우 느림(모듈러 지수승·타원곡선 스칼라 곱) → 대용량 암호화에 부적합

하이브리드 암호 시스템(Hybrid Cryptosystem) 은 이 둘을 결합해 "빠른 대칭키로 본문을, 느리지만 분배가 쉬운 공개키로 그 대칭키를" 암호화한다.

암호화 대상사용 방식이유
메시지 본문(대용량)대칭키(세션키) — AES, SEED, ARIA 등속도
세션키(짧은 데이터)공개키 — RSA, ECDH 등키 분배 문제 해결

이 역할 분담을 뒤집어 서술하는 것이 이 문제의 함정이다.

2. 동작 흐름 — 송신부터 수신까지​

송신자 A → 수신자 B

단계동작
1A가 의사난수생성기(CSPRNG) 로 일회성 세션키 KsK_sKs​ 생성
2메시지 MMM 을 대칭키 암호로 암호화: C1=EKs(M)C_1 = E_{K_s}(M)C1​=EKs​​(M)
3세션키를 B의 공개키로 암호화(키 캡슐화): C2=EPUB(Ks)C_2 = E_{PU_B}(K_s)C2​=EPUB​​(Ks​)
4(C1,C2)(C_1, C_2)(C1​,C2​) 를 결합해 전송

수신자 B

단계동작
5자신의 개인키로 C2C_2C2​ 복호화 → KsK_sKs​ 복구: Ks=DPRB(C2)K_s = D_{PR_B}(C_2)Ks​=DPRB​​(C2​)
6복구한 KsK_sKs​ 로 C1C_1C1​ 복호화 → 원문 MMM 획득

여기서 3단계(세션키를 공개키로 감싸 전달)를 키 캡슐화 메커니즘(KEM, Key Encapsulation Mechanism) 이라 부른다. 이 자체가 명백한 '키 분배' 과정이다. 하이브리드 구조는 키 분배를 없앤 것이 아니라, 안전 채널 없이 수행할 수 있도록 방식을 바꾼 것이다.

3. 세션키의 요건 — 왜 CSPRNG인가​

세션키는 메시지 1건(또는 1세션)에만 쓰이고 버려지는 일회성 키다.

요건이유
예측 불가능성세션키가 추측되면 공개키 암호를 우회해 본문이 그대로 노출됨
충분한 엔트로피키 공간이 좁으면 전수조사(brute force)에 취약
일회성(freshness)재사용 시 동일 키로 암호화된 여러 암호문이 상관 분석에 노출됨
전방 비밀성(선택)세션키를 DH/ECDHE로 합의하면 장기 개인키가 유출돼도 과거 세션이 보호됨(PFS)

따라서 세션키는 단순 rand()가 아니라 암호학적으로 안전한 의사난수생성기(CSPRNG) 로 생성해야 한다. 취약한 난수 생성기 때문에 뚫린 사례(초기 Netscape SSL의 시각 기반 시드, Debian OpenSSL 엔트로피 결함 등)가 실제로 존재한다. ①번 보기가 이 요건을 서술한다.

4. 대표 구현 사례​

시스템세션키 보호(공개키)본문 암호화(대칭키)비고
PGP / GnuPGRSA, ElGamal, ECDHIDEA, CAST5, 3DES, AES전자메일·파일 암호화의 대표적 하이브리드 구현
S/MIMERSA, ECDHAES인증서(X.509) 기반 메일 보안
TLS / HTTPSRSA 키 전송 또는 (EC)DHE 키 합의AES-GCM, ChaCha20-Poly1305최신 TLS 1.3은 PFS를 위해 (EC)DHE만 허용

PGP는 여기에 전자서명(송신자 개인키) 과 압축까지 결합해, 기밀성·무결성·인증·부인방지를 한 번에 제공한다.

5. 혼동하기 쉬운 인접 개념​

함정 표현사실
"본문을 공개키로 암호화한다"반대다. 본문은 대칭키, 세션키가 공개키로 암호화된다. 공개키로 대용량을 처리하면 느려서 실용성이 없다
"공개키를 쓰므로 키 분배가 불필요하다"세션키를 공개키로 감싸 보내는 것이 곧 키 분배(KEM) 다. 사전 안전 채널이 필요 없을 뿐, 분배 과정 자체는 존재한다
"세션키는 고정 키를 재사용해도 된다"세션키는 일회성이어야 한다. 재사용은 암호 분석의 단서를 준다
"하이브리드 = 두 알고리즘을 동시에 걸어 이중 암호화"이중 암호화가 아니라 대상별 역할 분담이다
"세션키는 송신자의 공개키로 암호화한다"수신자의 공개키로 암호화해야 수신자만 개인키로 풀 수 있다

문제​

정답​

②

상세 풀이​

"가장 적절하지 않은 것"을 고르는 부정형 문항이다. ②와 ③이 서로 모순된다는 점을 먼저 알아채면 답을 빠르게 좁힐 수 있다.

  • ②: "메시지를 암호화할 때는 공개키 암호 시스템을 이용"
  • ③: "메시지 암호화에 사용한 세션키(대칭키)는 수신자의 공개키로 암호화"

③에 따르면 메시지는 세션키(대칭키)로 암호화된 것이다. 그런데 ②는 메시지를 공개키로 암호화한다고 한다. 둘은 양립할 수 없으며, 하이브리드 구조의 정의상 옳은 쪽은 ③이다.

  1. ① "대칭키 암호화 방식에서 사용하는 세션키는 공격자의 추측 공격에 대응하기 위해 의사난수 생성기를 이용하여 생성한다." → 세션키가 예측되면 전체 보안이 무너지므로 암호학적으로 안전한 의사난수생성기(CSPRNG) 로 생성해야 한다. 옳은 서술이다. → 적절.
  2. ② "메시지를 암호화할 때는 공개키 암호 시스템을 이용하므로 별도의 키 분배 과정을 필요로 하지 않는다." → 두 부분이 모두 틀렸다. ⓐ 하이브리드에서 메시지 본문은 대칭키로 암호화하며, 공개키는 세션키 보호용이다. ⓑ 세션키를 공개키로 감싸 전송하는 행위 자체가 키 분배(키 캡슐화) 이므로 "별도의 키 분배 과정이 불필요하다"는 서술도 성립하지 않는다. → 부적절 = 정답.
  3. ③ "메시지 암호화에 사용한 세션키는 수신자의 공개키로 암호화하여 암호문과 결합하여 전송한다." → 하이브리드의 표준 동작을 그대로 서술했다. 수신자만 자신의 개인키로 세션키를 복구할 수 있다. → 적절.
  4. ④ "전자메일 암호화 도구인 PGP에서도 하이브리드 암호 시스템을 이용하여 암호화를 수행한다." → PGP는 세션키를 RSA/ElGamal로, 본문을 IDEA/CAST/AES로 암호화하는 대표적 하이브리드 구현이다. → 적절.

②를 올바른 서술로 고치면: "메시지를 암호화할 때는 대칭키 암호 시스템(세션키) 을 이용하고, 그 세션키를 수신자의 공개키로 암호화하여 함께 전송함으로써 사전 안전 채널 없이 키를 분배한다."

보기별 판정​

보기판정근거
① 세션키를 의사난수 생성기로 생성오답 보기(적절한 설명)세션키 예측 시 전체 보안 붕괴 → CSPRNG로 생성해야 함
② 메시지를 공개키로 암호화하므로 키 분배 불필요✅ 정답 보기(적절하지 않은 설명)본문은 대칭키로 암호화하며, 세션키를 공개키로 감싸는 것 자체가 키 분배(KEM) 다. 두 진술 모두 오류
③ 세션키를 수신자 공개키로 암호화해 암호문과 결합 전송오답 보기(적절한 설명)하이브리드 암호의 표준 동작 구조
④ PGP도 하이브리드 방식 사용오답 보기(적절한 설명)PGP는 세션키를 RSA/ElGamal, 본문을 IDEA/CAST/AES로 암호화

오답 이유​

  • ①이 적절한 이유: 하이브리드 구조에서 본문의 안전성은 오직 세션키에 달려 있다. 공개키 암호를 아무리 강하게 써도 세션키가 예측 가능하면 공격자는 공개키 부분을 건너뛰고 바로 본문을 복호화한다. 그래서 세션키는 시각·PID 같은 예측 가능한 시드가 아니라 운영체제 엔트로피 풀 기반의 CSPRNG로 생성해야 하며, 실제로 난수 생성기 결함으로 뚫린 사고 사례가 반복적으로 있었다.
  • ②가 부적절한 이유: 두 겹으로 틀렸다. ⓐ 역할 뒤집힘 — 하이브리드 방식이 존재하는 이유가 바로 공개키 연산이 느려 대용량 메시지 암호화에 부적합하기 때문이다. 본문을 공개키로 암호화한다면 애초에 하이브리드 구조를 만들 필요가 없다. ⓑ 키 분배 부정 — 세션키를 수신자의 공개키로 암호화해 암호문과 함께 보내는 것은 엄연한 키 분배 과정(키 캡슐화, KEM) 이다. 하이브리드가 없앤 것은 "사전에 안전한 채널을 확보해야 한다는 제약"이지 키 분배 자체가 아니다.
  • ③이 적절한 이유: 하이브리드 암호의 정상 구조 그 자체다. 세션키를 수신자의 공개키로 암호화하므로 대응하는 개인키를 가진 수신자만 이를 복구할 수 있고, 복구한 세션키로 본문 암호문을 푼다. 암호문 C1C_1C1​ 과 캡슐화된 세션키 C2C_2C2​ 를 하나의 메시지로 묶어 전송하는 것도 PGP·S/MIME의 실제 포맷과 일치한다.
  • ④가 적절한 이유: PGP는 하이브리드 암호의 교과서적 사례다. 메시지마다 새 세션키를 만들어 본문을 대칭키 알고리즘(IDEA, CAST5, 3DES, AES 등)으로 암호화하고, 그 세션키를 수신자의 공개키(RSA 또는 ElGamal)로 암호화해 붙인다. 여기에 송신자 개인키 서명과 압축을 더해 기밀성·무결성·인증·부인방지를 함께 제공한다.

핵심 정리​

  • 하이브리드 암호의 한 줄 요약: "본문은 빠른 대칭키(세션키)로, 세션키는 수신자의 공개키로".
  • 세션키는 일회성이며 CSPRNG로 생성해야 한다. 세션키가 예측되면 공개키 계층은 무의미해진다.
  • 세션키를 공개키로 감싸 전송하는 것이 키 캡슐화(KEM) = 키 분배 과정이다. "공개키를 쓰니 키 분배가 필요 없다"는 서술은 틀렸다.
  • 대표 구현: PGP/GnuPG, S/MIME, TLS. TLS 1.3은 전방 비밀성을 위해 (EC)DHE 키 합의만 허용한다.
  • "메시지를 공개키로 암호화한다"는 문장이 나오면 곧바로 오답 — 하이브리드가 존재하는 이유 자체를 부정하는 서술이라는 점이 이 문제의 결정타다.
