087번 · CIDR /27 서브넷의 디폴트 게이트웨이 주소 계산

제25회(2024년) 정보시스템감리사 A형 — 시스템 구조

사전 지식​

1. IPv4 주소와 프리픽스 표기(CIDR)​

IPv4 주소는 32비트이며, 8비트씩 4개의 옥텟으로 끊어 점으로 구분해 적는다. CIDR(Classless Inter-Domain Routing) 표기 a.b.c.d/n 에서 /n 은 앞에서부터 n개의 비트가 네트워크 ID임을 뜻한다.

네트워크 비트=n,호스트 비트=32−n\text{네트워크 비트} = n, \qquad \text{호스트 비트} = 32 - n네트워크 비트=n,호스트 비트=32−n

프리픽스서브넷 마스크호스트 비트블록 크기 232−n2^{32-n}232−n사용 가능 호스트 232−n−22^{32-n}-2232−n−2
/24255.255.255.08256254
/25255.255.255.1287128126
/26255.255.255.19266462
/27255.255.255.22453230
/28255.255.255.24041614
/29255.255.255.248386
/30255.255.255.252242

마지막 옥텟 값은 "앞에서부터 1을 채운" 결과다. /27이면 마지막 옥텟의 상위 3비트가 1이므로

1110 00002=128+64+32=2241110\,0000_2 = 128 + 64 + 32 = 224111000002​=128+64+32=224

2. 네트워크 주소를 구하는 공식​

네트워크 주소=IP 주소  AND  서브넷 마스크\boxed{\text{네트워크 주소} = \text{IP 주소} \;\text{AND}\; \text{서브넷 마스크}}네트워크 주소=IP 주소AND서브넷 마스크​

비트 AND는 "둘 다 1일 때만 1"이므로, 마스크가 1인 자리(네트워크 부분)는 그대로 살리고 마스크가 0인 자리(호스트 부분)는 전부 0으로 만든다. 즉 호스트 비트를 모두 0으로 밀어 버린 것이 네트워크 주소다.

이어서

브로드캐스트 주소=네트워크 주소+(블록 크기−1)\text{브로드캐스트 주소} = \text{네트워크 주소} + (\text{블록 크기} - 1)브로드캐스트 주소=네트워크 주소+(블록 크기−1) 사용 가능 호스트=네트워크 주소+1  ∼  브로드캐스트 주소−1\text{사용 가능 호스트} = \text{네트워크 주소}+1 \;\sim\; \text{브로드캐스트 주소}-1사용 가능 호스트=네트워크 주소+1∼브로드캐스트 주소−1

3. 서브넷 경계는 블록 크기의 배수에서만 생긴다​

/27의 블록 크기는 25=322^5 = 3225=32 이므로, 마지막 옥텟 기준으로 서브넷 경계는 0, 32, 64, 96, 128, 160, 192, 224 에서만 생긴다.

서브넷네트워크사용 가능 호스트 범위브로드캐스트
1.0.1 ~ .30.31
2.32.33 ~ .62.63

4.96.97 ~ .126.127

이 표만 머릿속에 그릴 수 있으면 문제는 즉시 풀린다. 69는 64와 95 사이에 있으므로 세 번째 서브넷이다.

4. 디폴트 게이트웨이란​

호스트가 자기 서브넷 밖으로 나가는 패킷을 넘겨주는 라우터의 인터페이스 주소다. 여기서 두 가지 제약이 따른다.

제약이유
반드시 같은 서브넷 안에 있어야 한다호스트는 게이트웨이와 ARP로 직접 통신해야 하는데, 이는 같은 브로드캐스트 도메인(=같은 서브넷) 안에서만 가능하다. 다른 서브넷의 주소를 게이트웨이로 지정하면 호스트가 그 주소에 도달할 방법이 없다
네트워크 주소·브로드캐스트 주소일 수 없다두 주소는 각각 "서브넷 자체"와 "서브넷 전체"를 가리키는 예약 주소로, 개별 인터페이스에 할당할 수 없다

관례적으로 서브넷의 첫 번째 사용 가능 주소(= 네트워크 주소 + 1) 또는 마지막 사용 가능 주소를 게이트웨이로 쓴다. 문제의 단서 "호스트 아이디 부분은 1로 가정한다"는 전자를 지정한 것이다.

5. 혼동하기 쉬운 인접 개념​

함정사실
"게이트웨이는 무조건 x.x.x.1"❌ /24일 때만 그렇다. 서브넷팅하면 각 서브넷의 네트워크 주소 + 1
"x.x.x.255는 항상 브로드캐스트"❌ /27에서는 .31, .63, .95 … 도 브로드캐스트다. 반대로 /23 등에서는 .255가 일반 호스트 주소일 수 있다
"호스트 ID가 1이면 마지막 옥텟이 1"❌ 호스트 ID는 호스트 비트 영역 안의 값. 네트워크 주소에 더해야 실제 주소가 된다
"IP가 같은 /24 안이면 통신 가능"❌ 마스크가 /27이면 같은 /24 안이라도 서브넷이 다르면 라우터를 거쳐야 한다

상세 풀이​

주어진 값과 구해야 할 값을 먼저 정리한다.

항목값
노드의 IP 주소182.75.187.69
프리픽스/27
조건게이트웨이의 호스트 ID 부분 = 1
구할 것이 노드가 속한 서브넷의 디폴트 게이트웨이 주소

앞의 세 옥텟(182.75.187)은 /27 ≥ /24 이므로 네트워크 부분에 전부 포함되어 변하지 않는다. 따라서 마지막 옥텟만 계산하면 된다.

1단계 — 공식: 서브넷 마스크 구하기​

/27⇒네트워크 비트 27,호스트 비트 32−27=5/27 \Rightarrow \text{네트워크 비트 } 27,\quad \text{호스트 비트 } 32-27 = 5/27⇒네트워크 비트 27,호스트 비트 32−27=5

마지막 옥텟의 마스크는 상위 3비트가 1, 하위 5비트가 0이다.

1 1 1⏟네트워크0 0 0 0 0⏟호스트2=128+64+32=224\underbrace{1\,1\,1}_{\text{네트워크}}\underbrace{0\,0\,0\,0\,0}_{\text{호스트}}{}_{2} = 128+64+32 = 224네트워크111​​호스트00000​​2​=128+64+32=224

∴서브넷 마스크=255.255.255.224\therefore \text{서브넷 마스크} = 255.255.255.224∴서브넷 마스크=255.255.255.224

블록 크기는 25=322^5 = 3225=32 이다.

2단계 — 값 대입: 비트 AND로 네트워크 주소 계산​

마지막 옥텟 69를 2진수로 전개한다.

69=64+4+1=0100 0101269 = 64 + 4 + 1 = 0100\,0101_269=64+4+1=010001012​

이제 마스크와 비트 AND를 수행한다.

                           네트워크 부분  │  호스트 부분(5비트)

0100 01012  AND  1110 00002=0100 00002=640100\,0101_2 \;\text{AND}\; 1110\,0000_2 = 0100\,0000_2 = 64010001012​AND111000002​=010000002​=64

∴네트워크 주소=182.75.187.64/27\therefore \text{네트워크 주소} = \mathbf{182.75.187.64/27}∴네트워크 주소=182.75.187.64/27

3단계 — 계산: 서브넷 범위 확정​

브로드캐스트=64+32−1=95\text{브로드캐스트} = 64 + 32 - 1 = 95브로드캐스트=64+32−1=95

노드 주소 .69는 .65 ~ .94 범위 안에 있으므로 정상적인 호스트 주소이며, 소속 서브넷은 182.75.187.64/27 로 확정된다.

4단계 — 조건 적용: 호스트 ID = 1​

"호스트 아이디 부분을 1로" 한다는 것은 호스트 비트 5개의 값을 000012=100001_2 = 1000012​=1 로 설정한다는 뜻이다.

  네트워크 부분(3비트)   호스트 부분(5비트)
        0 1 0        │      0 0 0 0 1
        ─────────────┴─────────────────
        0100 0001₂  =  64 + 1  =  65

게이트웨이 마지막 옥텟=64⏟네트워크 주소+1⏟호스트 ID=65\text{게이트웨이 마지막 옥텟} = \underbrace{64}_{\text{네트워크 주소}} + \underbrace{1}_{\text{호스트 ID}} = 65게이트웨이 마지막 옥텟=네트워크 주소64​​+호스트 ID1​​=65

5단계 — 결론 (단위: IPv4 점-십진 표기)​

∴디폴트 게이트웨이=182.75.187.65\therefore \text{디폴트 게이트웨이} = \mathbf{182.75.187.65}∴디폴트 게이트웨이=182.75.187.65

검증 — 각 보기가 어느 서브넷에 속하는가​

블록 크기 32의 경계로 나누어 각 보기의 소속을 확인한다.

보기마지막 옥텟마지막 옥텟 2진수AND 224소속 서브넷노드와 같은 서브넷?
① .110000 00010000 0000 = 0182.75.187.0/27❌ 다름
② .550000 01010000 0000 = 0182.75.187.0/27❌ 다름
③ .65650100 00010100 0000 = 64182.75.187.64/27✅ 같음
④ .2552551111 11111110 0000 = 224182.75.187.224/27❌ 다름 (게다가 브로드캐스트)

노드(.69)의 소속은 64 서브넷이므로, 같은 값 64가 나오는 ③만 후보가 되며 그중 호스트 ID가 1인 주소가 정확히 .65다.

보기별 판정​

보기판정근거
① 182.75.187.1오답 보기1  AND  224=01 \;\text{AND}\; 224 = 01AND224=0 → 182.75.187.0/27 소속. 노드(.64 서브넷)와 다른 서브넷이라 ARP가 닿지 않아 게이트웨이가 될 수 없다. "/24 습관"으로 고르기 쉬운 최대 함정
② 182.75.187.5오답 보기5  AND  224=05 \;\text{AND}\; 224 = 05AND224=0 → 역시 182.75.187.0/27 소속. 노드와 다른 서브넷
③ 182.75.187.65✅ 정답 보기65  AND  224=6465 \;\text{AND}\; 224 = 6465AND224=64 → 노드와 동일한 182.75.187.64/27 소속이며, 호스트 ID가 000012=100001_2 = 1000012​=1 인 첫 사용 가능 주소
④ 182.75.187.255오답 보기255  AND  224=224255 \;\text{AND}\; 224 = 224255AND224=224 → 182.75.187.224/27 소속이고, 그 서브넷의 브로드캐스트 주소(224+32−1=255) 이므로 인터페이스에 할당 자체가 불가능

오답 이유​

  • ①이 틀린 이유: 마지막 옥텟 1을 마스크 224와 AND하면 0000 0001 AND 1110 0000 = 0000 0000 = 0 이므로 이 주소는 182.75.187.0/27(범위 .0 ~ .31)에 속한다. 노드가 속한 182.75.187.64/27과는 별개의 서브넷이다. 디폴트 게이트웨이는 호스트가 ARP로 MAC 주소를 알아내 직접 프레임을 보내야 하는 대상이므로 반드시 같은 브로드캐스트 도메인 안에 있어야 하는데, 다른 서브넷이면 그 자체로 라우팅이 필요해 모순이 된다. "게이트웨이는 x.x.x.1"이라는 /24 시절 습관이 만드는 가장 흔한 오답이다.
  • ②가 틀린 이유: 5 역시 0000 0101 AND 1110 0000 = 0000 0000 = 0 으로 .0 ~ .31 범위인 첫 번째 서브넷 소속이다. ①과 동일한 이유로 배제된다. "호스트 아이디 부분은 1로 가정한다"를 "마지막 옥텟이 작은 값"으로 잘못 읽으면 걸리는 보기다.
  • ③이 맞는 이유: /27의 블록 크기가 32이므로 서브넷 경계는 0, 32, 64, 96 … 이고, 노드 주소 .69는 64 ≤ 69 ≤ 95 이므로 182.75.187.64/27 에 속한다. 이 서브넷의 사용 가능 호스트는 .65 ~ .94이며, 호스트 비트 5개를 00001200001_2000012​ 로 둔 주소는 0100 0000 + 0000 0001 = 0100 0001 = 65 다. 같은 서브넷 안에 있고 예약 주소도 아니므로 게이트웨이 요건을 모두 충족한다.
  • ④가 틀린 이유: 두 가지 이유로 동시에 불가능하다. 첫째, 255  AND  224=224255 \;\text{AND}\; 224 = 224255AND224=224 이므로 이 주소는 182.75.187.224/27(범위 .224 ~ .255)에 속해 노드와 서브넷이 다르다. 둘째, 224 + 32 − 1 = 255 이므로 그 서브넷의 브로드캐스트 주소여서 어떤 인터페이스에도 할당할 수 없다. "마지막 옥텟 255 = 브로드캐스트"라는 인상만으로 고르면 서브넷팅 상황에서는 .31, .63, .95 등도 브로드캐스트라는 점을 놓치게 된다.

핵심 정리​

  • 네트워크 주소 = IP AND 서브넷 마스크. 호스트 비트를 전부 0으로 미는 연산이다.
  • /27 → 마스크 255.255.255.224, 호스트 비트 5개, 블록 크기 32, 사용 가능 호스트 30개. 경계는 0, 32, 64, 96, 128, 160, 192, 224.
  • 이 문제의 계산: 69=0100 0101269 = 0100\,0101_269=010001012​, 224=1110 00002224 = 1110\,0000_2224=111000002​, AND → 0100 00002=640100\,0000_2 = 64010000002​=64 → 서브넷 182.75.187.64/27 (.64 ~ .95) → 호스트 ID 1 → 64 + 1 = 65.
  • 디폴트 게이트웨이의 두 요건: ① 호스트와 같은 서브넷 안에 있어야 하고, ② 네트워크·브로드캐스트 주소가 아니어야 한다.
  • 결정타: "게이트웨이는 x.x.x.1"이라는 /24 습관을 버려야 한다. 서브넷팅된 망에서는 각 서브넷의 네트워크 주소에 1을 더한 값이 게이트웨이이며, 마지막 옥텟이 255가 아니어도 브로드캐스트일 수 있다(/27에서는 .31, .63, .95 …).
