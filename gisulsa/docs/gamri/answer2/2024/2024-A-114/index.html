114번 · SSO(Single Sign On)의 구조와 한계

제25회(2024년) 정보시스템감리사 A형 — 보안

사전 지식​

1. SSO의 정의와 구조​

SSO(Single Sign On) 는 사용자가 한 번의 인증(single authentication) 으로 연계된 여러 시스템을 추가 로그인 없이 이용할 수 있게 하는 통합 인증 방식이다.

핵심은 인증 기능의 중앙 집중화다.

구분SSO 도입 전(분산 인증)SSO 도입 후(중앙 인증)
인증 정보(계정·비밀번호) 저장 위치각 시스템마다 개별 보관중앙 인증 서버(SSO 서버/IdP)에 집중
사용자 경험시스템 수만큼 로그인1회 로그인 후 자유 이동
계정 관리시스템별로 생성·변경·삭제 반복한 곳에서 생성·변경·퇴사 시 즉시 차단
비밀번호 정책시스템마다 제각각일관 적용
장애 영향한 시스템 장애는 그 시스템만 영향인증 서버 장애 시 전체 이용 불가(SPOF)
침해 영향한 시스템 침해는 그 시스템만 노출인증 서버 침해 시 전체 노출

즉 SSO는 편의성·관리성과 집중 위험(SPOF)을 맞바꾼 구조다. 이 트레이드오프가 이 문항의 출제 의도다.

2. 동작 흐름 — 중앙 인증 서버와 토큰​

단계내용
1사용자가 서비스 A에 접근 → 미인증 상태이므로 SSO 서버(IdP)로 리다이렉트
2SSO 서버에서 1회 인증(ID/PW, 인증서, MFA 등)
3SSO 서버가 인증 토큰/티켓 발급(SAML Assertion, OIDC ID Token, Kerberos TGT 등)
4사용자는 토큰을 제시하고 서비스 A 이용
5이후 서비스 B·C 접근 시에도 기존 세션·토큰으로 재인증 없이 통과

여기서 "인증(Authentication)"과 "인가(Authorization)"는 구분해야 한다. SSO가 보장하는 것은 "이 사람이 누구인지 확인됐다"는 인증의 재사용이다. 실제로 어느 자원을 쓸 수 있는지는 각 시스템의 권한 정책(RBAC 등) 이 별도로 결정한다.

3. 대표 구현 — Kerberos와 Windows Active Directory​

Kerberos는 MIT에서 개발된 대칭키 기반 네트워크 인증 프로토콜로, 현재 RFC 4120(The Kerberos Network Authentication Service (V5)) 에 규정되어 있다. Windows Active Directory 도메인 인증의 기본 프로토콜이며, 가장 널리 쓰이는 SSO 구현체다.

구성요소역할
KDC(Key Distribution Center)인증 중심. AS + TGS로 구성
AS(Authentication Server)최초 인증을 수행하고 TGT(Ticket Granting Ticket) 발급
TGS(Ticket Granting Server)TGT를 검증하고 개별 서비스 티켓(Service Ticket) 발급
Principal / Realm인증 주체 식별자 / 관리 영역

RFC 4120이 정의하는 3단계 교환

교환메시지내용
AS ExchangeKRB_AS_REQ / KRB_AS_REP사용자 최초 인증 → TGT 획득(하루 1회 수준)
TGS ExchangeKRB_TGS_REQ / KRB_TGS_REPTGT 제시 → 접근하려는 서비스별 티켓 획득
AP ExchangeKRB_AP_REQ / KRB_AP_REP서비스 티켓 제시 → 해당 서버 이용

TGT를 한 번 받아 두면 이후 서비스마다 비밀번호를 다시 입력할 필요가 없다는 점이 바로 SSO의 실현 원리다. 또한 Kerberos는 타임스탬프로 재전송(replay) 공격을 막으므로 KDC와 클라이언트의 시각 동기화(기본 허용 오차 5분) 가 필수이며, 이 역시 KDC 의존성 = SPOF 를 보여 주는 대목이다.

4. SSO의 위험과 보완 기법​

위험설명보완
단일 장애점(SPOF)인증 서버가 죽으면 연계 시스템 전부 로그인 불가인증 서버 이중화·클러스터링, 지역 분산, 백업 KDC
침해 시 전면 확산인증 서버·마스터 계정 탈취 시 모든 시스템 동시 노출관리자 계정 MFA, 인증 서버 망 분리, 특권 접근 관리(PAM)
세션·토큰 탈취토큰 하나로 전체 접근 가능토큰 유효시간 단축, 재사용 탐지, 디바이스 바인딩
과도한 접근 범위"한 번 들어오면 다 된다"는 구조중요 자원 접근 시 단계별 재인증(step-up authentication), 최소권한 원칙, 제로트러스트(ZTNA)

특히 step-up 인증(중요 정보 접근 시 재인증·추가 인증요소 요구)은 SSO의 편의성을 유지하면서 위험을 줄이는 표준적 보완 기법이며, ③번 보기가 바로 이것을 서술한다.

5. 혼동하기 쉬운 인접 개념​

개념정의SSO와의 차이
SSO1회 인증으로 다수 시스템 이용인증의 중앙 집중·재사용
통합 계정 관리(IM/IAM)계정의 생성·변경·삭제 수명주기 관리인증 재사용이 아니라 계정 프로비저닝이 목적
EAM(Extranet Access Management)SSO + 접근 통제(인가) 통합인가 정책까지 포함
Federation(SAML/OIDC)서로 다른 조직·도메인 간 인증 정보 신뢰SSO를 조직 경계 너머로 확장한 형태
Password Vault 방식 SSO대행 프로그램이 각 시스템 비밀번호를 저장·자동 입력진정한 통합 인증이 아닌 대행(delegation) 방식. 이 경우에도 볼트 자체가 SPOF

상세 풀이​

"가장 적절하지 않은 것"을 고르는 부정형 문항이다. SSO의 정의와 대표적 단점을 제대로 알고 있는지가 관건이다.

  1. ① "SSO 서버로부터 인증에 성공하면 SSO 서버가 관리하는 다른 시스템에 대한 접근권한을 모두 얻을 수 있다." → SSO의 기본 동작을 서술한 문장이다. 1회 인증으로 SSO 연계 영역 내 시스템들을 추가 로그인 없이 이용할 수 있다. 엄밀히 말해 각 시스템의 세부 권한은 별도 인가 정책이 정하지만, 보기 수준에서 SSO의 개념을 옳게 설명한 것으로 본다. → 적절.
  2. ② "대표적인 인증 방법으로는 커버로스(Kerberos)를 이용한 윈도우 액티브 디렉터리가 있다." → Windows Active Directory 도메인 인증은 Kerberos(RFC 4120) 기반이며, TGT를 한 번 받아 서비스 티켓으로 각 자원에 접근하는 구조가 곧 SSO다. 가장 널리 인용되는 SSO 사례다. → 적절.
  3. ③ "보안을 강화하기 위해 중요 정보에 접근할 때는 지속적인 재인증을 요구하기도 한다." → SSO의 광범위한 접근 범위와 세션 탈취 위험을 보완하는 step-up 인증(단계별 재인증) 을 설명한 것으로, 실제로 널리 적용되는 강화 기법이다. → 적절.
  4. ④ "각 시스템마다 인증 정보를 저장하므로 단일 장애점(SPOF) 문제가 존재하지 않는다." → 두 부분 모두 틀렸다. 첫째, SSO는 정의상 인증 정보를 중앙 인증 서버에 집중시킨다. "각 시스템마다 인증 정보를 저장"하는 것은 SSO 도입 이전의 분산 인증 방식이다. 둘째, SSO는 인증이 한 곳에 집중되기 때문에 SPOF가 오히려 대표적 단점이다. → 부적절 = 정답.

④의 전제(각 시스템 개별 저장)와 결론(SPOF 없음)은 서로 논리적으로 연결되어 있지만, 그 전제 자체가 SSO가 아니다. 즉 보기가 설명하는 것은 SSO가 아니라 SSO가 극복하려 한 이전 방식이다.

오답 이유​

  • ①이 적절한 이유: SSO의 존재 이유 그 자체다. 사용자는 SSO 서버에서 한 번 인증한 뒤 발급받은 토큰·티켓으로 연계된 업무 시스템(메일, 그룹웨어, ERP 등)을 추가 로그인 없이 이용한다. 다만 실제 환경에서는 "인증됐다"와 "그 자원을 쓸 권한이 있다"가 별개이므로, 각 시스템이 RBAC 등으로 인가를 따로 판단한다는 점은 알아 둘 만하다.
  • ②가 적절한 이유: Kerberos는 RFC 4120에 규정된 대칭키 기반 인증 프로토콜로, AS Exchange(TGT 발급) → TGS Exchange(서비스 티켓 발급) → AP Exchange(서비스 이용) 3단계로 동작한다. 사용자가 TGT를 한 번 받으면 이후 각 서비스마다 비밀번호를 다시 입력할 필요가 없어 SSO가 성립한다. Windows Active Directory가 이 구조를 채택한 가장 대표적인 구현이다.
  • ③이 적절한 이유: SSO는 토큰 하나로 다수 시스템에 접근하므로 세션 탈취의 파급이 크다. 그래서 인사·재무 등 민감 자원에 접근할 때는 기존 세션이 있어도 비밀번호를 다시 묻거나 OTP·생체 인증 같은 추가 요소를 요구하는 step-up 인증을 적용한다. 편의성을 전부 포기하지 않으면서 위험 구간만 방어하는 실무 기법이다.
  • ④가 부적절한 이유: 두 겹으로 틀렸다. ⓐ 전제 오류 — SSO는 인증 정보를 각 시스템에 흩어 두는 방식이 아니라 중앙 인증 서버에 집중시키는 방식이다. "각 시스템마다 인증 정보를 저장"하는 것은 SSO 이전의 분산 인증이다. ⓑ 결론 오류 — 바로 그 집중 때문에 인증 서버가 정지하면 연계된 모든 시스템을 이용할 수 없고, 침해되면 모든 시스템이 한꺼번에 노출된다. 이것이 SSO의 교과서적 단점인 단일 장애점(SPOF) 이다. 올바른 서술로 고치면 "인증 정보를 중앙 서버에 집중 저장하므로 단일 장애점 문제가 존재하며, 이를 완화하기 위해 인증 서버를 이중화한다"가 된다.

핵심 정리​

  • SSO = 인증의 중앙 집중과 재사용. 편의성·계정 관리 효율을 얻는 대신 SPOF와 침해 시 전면 확산 위험을 진다.
  • SSO의 대표 단점은 단일 장애점(SPOF) 이며, 대응은 인증 서버 이중화·클러스터링이다. "SSO에는 SPOF가 없다"는 서술은 항상 오답.
  • Kerberos(RFC 4120) = KDC(AS+TGS) 기반 대칭키 인증. AS Exchange → TGT, TGS Exchange → 서비스 티켓, AP Exchange → 서비스 이용. Windows Active Directory가 대표 구현.
  • ④는 "각 시스템마다 인증 정보를 저장"이라는 전제부터 SSO의 정의와 정반대 — 정의를 부정하는 보기가 곧 답이라는 것이 이 문제의 결정타다.
