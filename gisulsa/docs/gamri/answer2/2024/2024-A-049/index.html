049번 · Java 변수 섀도잉과 익명 클래스의 this

제25회(2024년) 정보시스템감리사 A형 — 소프트웨어 공학

사전 지식​

1. Java의 변수 종류와 유효 범위​

종류선언 위치생존 기간this.로 접근
인스턴스 변수(필드)클래스 본문객체와 함께가능
정적 변수클래스 본문 + static클래스 로딩 ~ 종료클래스명으로 접근
지역 변수메소드·블록 내부블록을 벗어나면 소멸불가능
매개변수메소드 시그니처메소드 실행 동안불가능

이 문제에는 a라는 이름의 변수가 네 개 등장하며, 그중 둘은 필드, 둘은 지역 변수다.

#선언종류소속
1public final int a = 10;인스턴스 필드바깥 클래스 Test
2int a = 20; (runIt() 안)지역 변수메소드 runIt()
3public final int a = 30;인스턴스 필드익명 클래스
4int a = 40; (run() 안)지역 변수메소드 run()

2. 섀도잉(shadowing)​

안쪽 범위에 같은 이름의 변수가 선언되면 바깥쪽 변수를 가린다. 단순 식별자 a로 접근하면 가장 안쪽에서 보이는 선언이 선택된다.

위치단순 식별자 a 가 가리키는 것
Test의 다른 메소드필드 a = 10
runIt() 본문지역 변수 a = 20 (필드 10을 가림)
run() 본문지역 변수 a = 40 (익명 필드 30, 바깥 필드 10을 모두 가림)

3. this가 가리키는 대상 — 이 문제의 핵심​

코드 위치this비고
일반 인스턴스 메소드그 클래스의 인스턴스
익명 클래스·내부 클래스의 메소드그 익명/내부 클래스의 인스턴스바깥 인스턴스가 아니다
익명 클래스 안에서 바깥 인스턴스Test.this (한정된 this, qualified this)바깥클래스명.this 형식
람다식 내부바깥(감싸는) 클래스의 인스턴스익명 클래스와 정반대. 람다는 자신의 this를 만들지 않는다

즉 run() 안의 this는 Runnable을 구현한 익명 클래스 인스턴스이며, 바깥 Test 객체가 아니다.

4. this.a가 선택하는 범위​

this.a처럼 필드 접근 식을 쓰면 선택 규칙이 달라진다.

접근 형태탐색 대상
a (단순 식별자)지역 변수 → 매개변수 → 필드 → 바깥 클래스 필드 순으로 탐색
this.athis가 가리키는 객체의 필드만. 지역 변수는 아예 후보가 아니다
Test.this.a바깥 Test 인스턴스의 필드만
super.a상위 타입의 필드 (여기서는 Object라 a 없음)

이 규칙 덕분에 this.a는 지역 변수 40과 20을 후보에서 배제하고, 익명 클래스 필드 30을 고른다.

5. 익명 클래스(anonymous class) 문법​

Runnable b = new Runnable() {   // Runnable을 구현하는 이름 없는 클래스를 즉석 정의
    public final int a = 30;    // 익명 클래스 자신의 필드 선언 — 가능하다
    public void run() { ... }   // 인터페이스 메소드 구현
};

익명 클래스는 인터페이스나 상위 클래스를 그 자리에서 구현·상속하면서 자체 필드와 메소드를 가질 수 있는 완전한 클래스다. 컴파일하면 Test$1.class 같은 별도 클래스 파일이 생성된다. 이 점이 람다식(Runnable b = () -> {...})과 결정적으로 다르다 — 람다는 자체 필드도, 자체 this도 갖지 않는다.

6. 혼동하기 쉬운 인접 개념​

혼동구분
this.a vs a전자는 필드만, 후자는 지역 변수 우선
익명 클래스의 this vs 람다의 this익명 클래스 = 자기 자신 / 람다 = 바깥 인스턴스
final 필드 vs final 지역 변수final은 재할당 금지일 뿐 범위 규칙과 무관. 이 문제에서 final은 함정 장식이다
정적 중첩 클래스 vs 내부 클래스전자는 바깥 인스턴스 참조를 갖지 않아 Test.this 사용 불가
섀도잉 vs 오버라이딩필드는 섀도잉(참조 타입 기준 정적 결정), 메소드는 오버라이딩(실제 객체 기준 동적 결정)

문제​

정답​

③

상세 풀이​

코드 추적 유형이며, 판단해야 할 것은 단 하나 — System.out.println(this.a) 의 this가 무엇이고 this.a가 어느 변수인가이다.

1단계 — 실행 흐름​

순서실행
1main에서 new Test() → Test 인스턴스 생성, 필드 a = 10 초기화
2c.runIt() 호출 → 지역 변수 a = 20 선언
3new Runnable(){...} → 익명 클래스 인스턴스 생성, 그 필드 a = 30 초기화
4b.run() 호출 → 지역 변수 a = 40 선언
5System.out.println(this.a) 평가

2단계 — this 확정​

run()은 익명 클래스의 인스턴스 메소드다. 따라서 그 안의 this는 3단계에서 만든 익명 클래스 인스턴스를 가리킨다. 바깥의 Test 인스턴스 c를 가리키려면 Test.this라고 써야 한다.

3단계 — this.a 확정​

this.a는 필드 접근이므로 익명 클래스 인스턴스가 가진 필드 중 이름이 a인 것을 찾는다. 익명 클래스에는 public final int a = 30; 이 선언되어 있으므로 값은 30이다.

후보값this.a의 후보인가
Test의 필드 a10✗ — Test.this.a 로 써야 접근 가능
runIt()의 지역 변수 a20✗ — 지역 변수는 필드 접근식의 대상이 아님
익명 클래스의 필드 a30✅ — this가 가리키는 객체의 필드
run()의 지역 변수 a40✗ — 지역 변수. this. 를 붙인 순간 배제됨

따라서 출력은 30, 정답은 ③이다.

4단계 — 실제 실행으로 검증​

문제의 코드를 그대로 컴파일(OpenJDK 1.8)해 실행한 결과 출력은 30이었다. 확인을 위해 같은 메소드에서 세 가지 형태를 함께 출력해 보면 다음과 같다.

표현식출력
a (단순 식별자)40 — 지역 변수
this.a30 — 익명 클래스 필드
Test.this.a10 — 바깥 클래스 필드

이 세 줄이 곧 이 문제가 노리는 세 갈래 함정에 대한 답이다. (runIt()의 지역 변수 20은 어떤 표현식으로도 run() 안에서 이름 a로 참조할 수 없다.)

보기별 판정​

보기판정근거
① 10오답 보기바깥 클래스 Test의 필드. 접근하려면 Test.this.a 가 필요하다
② 20오답 보기runIt()의 지역 변수. 필드가 아니므로 this.로 접근 불가, run() 안에서 이름으로도 보이지 않는다
③ 30✅ 정답 보기익명 클래스의 필드. run() 안의 this는 익명 클래스 인스턴스이므로 this.a == 30
④ 40오답 보기run()의 지역 변수. 단순 식별자 a였다면 40이지만, this.a는 지역 변수를 배제한다

오답 이유​

  • ①이 틀린 이유: 익명 클래스 내부의 this는 자신을 감싸는 Test 인스턴스가 아니라 익명 클래스 자신의 인스턴스다. 바깥 인스턴스의 필드를 읽으려면 한정된 형식 Test.this.a를 명시해야 한다. 실제로 그렇게 고쳐 실행하면 10이 출력된다.
  • ②가 틀린 이유: runIt()의 int a = 20은 지역 변수이므로 어떤 객체에도 속하지 않아 this.로 접근할 수 없다. 나아가 익명 클래스 안에서 이름 a는 익명 클래스 필드(30)와 run()의 지역 변수(40)에 의해 가려지므로, 20은 애초에 도달 불가능하다.
  • ③이 맞는 이유: run()이 익명 클래스의 인스턴스 메소드이므로 this = 익명 인스턴스이고, this.a = 익명 클래스에 선언된 public final int a = 30 이다. 실제 컴파일·실행 결과도 30이다.
  • ④가 틀린 이유: 40은 this.를 빼고 단순히 a라고 썼을 때의 값이다. 출제자는 가장 가까운 선언이 정답일 것이라는 직관을 노려 지역 변수 40을 배치했다. 그러나 this.를 붙이는 순간 지역 변수는 후보에서 완전히 제외되므로 40은 선택될 수 없다.

핵심 정리​

  • 익명 클래스·내부 클래스 안의 this는 그 익명/내부 인스턴스를 가리킨다. 바깥 인스턴스는 바깥클래스명.this 로 접근한다. 람다식은 정반대로 바깥 인스턴스의 this 를 그대로 쓴다.
  • this.x는 필드만 탐색한다. 지역 변수는 this.로 접근할 수 없으므로 섀도잉 후보에서 빠진다. 단순 식별자 x는 지역 변수를 우선한다.
  • 익명 클래스는 자체 필드를 가질 수 있는 완전한 클래스이며, 컴파일 시 Test$1.class 로 생성된다.
  • 같은 이름의 변수 네 개(10·20·30·40)가 깔려 있어도 "run()의 this = 익명 인스턴스" + "this.a = 필드만" 두 규칙이면 30으로 확정된다 — 이것이 결정타다.
