아래 답안은 정보관리기술사 4교시 실전 답안 수준으로 구성하였습니다. 핵심은 Supernetting과 Subnetting의 방향성 차이를 설명하고, VLSM은 반드시 필요 호스트 수가 큰 순서대로 할당하는 것입니다.

네트워크 슈퍼네팅(Supernetting), 서브네팅(Subnetting) 및 VLSM 설계

Ⅰ. 개요​

IP 네트워크는 주소 공간의 효율적 사용과 라우팅 테이블 축약을 위해 네트워크 대역을 분할하거나 통합한다.

  • 서브네팅(Subnetting) 은 하나의 큰 네트워크를 여러 개의 작은 네트워크로 분할하는 기법이다.
  • 슈퍼네팅(Supernetting) 은 여러 개의 연속된 네트워크를 하나의 큰 네트워크로 통합하는 기법이다.
  • VLSM(Variable Length Subnet Mask) 은 각 서브넷의 호스트 수에 따라 서로 다른 서브넷 마스크를 적용하여 주소 낭비를 최소화한다.
주소 분할                         주소 통합
/22 ──Subnetting──► /23, /24, /25     /24 + /24 ──Supernetting──► /23

가. 슈퍼네팅과 서브네팅의 개념

1. 서브네팅(Subnetting)​

서브네팅은 호스트 비트 일부를 네트워크 비트로 전환하여 하나의 네트워크를 여러 개의 논리적 하위 네트워크로 분할하는 기법이다.

목적​

  • IP 주소의 효율적 할당
  • 부서·업무별 네트워크 분리
  • 브로드캐스트 도메인 축소
  • 보안 정책과 장애 범위 분리
  • 네트워크 관리성 향상

예시​

192.168.0.0/24
       │
       ├─ 192.168.0.0/25
       └─ 192.168.0.128/25

프리픽스 길이가 /24 → /25로 증가하므로 네트워크 수는 증가하고, 각 네트워크의 호스트 수는 감소한다.

2. 슈퍼네팅(Supernetting)​

슈퍼네팅은 연속된 여러 네트워크의 공통 상위 비트를 기준으로 하나의 더 큰 네트워크 주소로 집약하는 기법이다. 라우트 집약(Route Aggregation) 또는 CIDR 집약이라고도 한다.

목적​

  • 라우팅 테이블 항목 축소
  • 라우팅 업데이트 트래픽 감소
  • 경로 탐색 효율 향상
  • 네트워크 확장성 확보

예시​

192.168.0.0/24 ┐
192.168.1.0/24 ├──► 192.168.0.0/22
192.168.2.0/24 │
192.168.3.0/24 ┘

프리픽스 길이가 /24 → /22로 감소하므로 여러 네트워크가 하나의 상위 경로로 통합된다.

3. 슈퍼네팅과 서브네팅 비교​

구분서브네팅슈퍼네팅
목적네트워크 분할네트워크 통합
프리픽스증가감소
네트워크 수증가감소
호스트 수서브넷별 감소통합 대역 증가
주요 활용부서별 망 분리라우팅 경로 집약
핵심 효과주소 효율·보안·관리성라우팅 효율·확장성

나. 192.168.0.0/22 대역의 VLSM 분할

1. 요구사항 분석​

대상 네트워크는 192.168.0.0/22이며 전체 주소 범위는 다음과 같다.

  • 전체 주소: 192.168.0.0 ~ 192.168.3.255
  • 전체 주소 수: 2^(32-22) = 1,024개
  • 사용 가능한 호스트 수: 1,022개

각 부서의 요구 호스트 수를 충족하도록 네트워크 주소와 브로드캐스트 주소를 포함한 최소 블록을 산정한다.

부서필요 호스트필요 주소 수최소 블록PrefixSubnet Mask사용 가능 호스트
개발팀500502 이상512/23255.255.254.0510
영업팀250252 이상256/24255.255.255.0254
인사팀125127 이상128/25255.255.255.128126
보안팀125127 이상128/25255.255.255.128126

필요한 총 주소 수는 다음과 같다.

512 + 256 + 128 + 128 = 1,024개

따라서 /22 대역 전체를 낭비 없이 정확하게 사용할 수 있다.

2. VLSM 할당 원칙​

VLSM은 주소 중첩과 단편화를 방지하기 위해 호스트 수가 가장 많은 부서부터 내림차순으로 할당한다.

192.168.0.0/22
        │
        ├─ 개발팀  /23 : 512개
        ├─ 영업팀  /24 : 256개
        ├─ 인사팀  /25 : 128개
        └─ 보안팀  /25 : 128개

3. 부서별 VLSM 할당 결과​

① 개발팀: 500명​

500명의 호스트를 수용하려면 510개의 사용 가능한 주소를 제공하는 /23이 필요하다.

항목값
Network Address192.168.0.0/23
Subnet Mask255.255.254.0
전체 주소 범위192.168.0.0 ~ 192.168.1.255
할당 가능 Host IP192.168.0.1 ~ 192.168.1.254
Broadcast Address192.168.1.255
사용 가능 Host 수510개

② 영업팀: 250명​

250명의 호스트를 수용하려면 254개의 사용 가능한 주소를 제공하는 /24가 필요하다.

항목값
Network Address192.168.2.0/24
Subnet Mask255.255.255.0
전체 주소 범위192.168.2.0 ~ 192.168.2.255
할당 가능 Host IP192.168.2.1 ~ 192.168.2.254
Broadcast Address192.168.2.255
사용 가능 Host 수254개

③ 인사팀: 125명​

125명의 호스트를 수용하려면 126개의 사용 가능한 주소를 제공하는 /25가 필요하다.

항목값
Network Address192.168.3.0/25
Subnet Mask255.255.255.128
전체 주소 범위192.168.3.0 ~ 192.168.3.127
할당 가능 Host IP192.168.3.1 ~ 192.168.3.126
Broadcast Address192.168.3.127
사용 가능 Host 수126개

④ 보안팀: 125명​

나머지 /25 대역을 보안팀에 할당한다.

항목값
Network Address192.168.3.128/25
Subnet Mask255.255.255.128
전체 주소 범위192.168.3.128 ~ 192.168.3.255
할당 가능 Host IP192.168.3.129 ~ 192.168.3.254
Broadcast Address192.168.3.255
사용 가능 Host 수126개

Ⅲ. VLSM 설계 시 고려사항

고려사항주요 내용
대규모 서브넷 우선가장 많은 호스트를 요구하는 서브넷부터 할당
Network 경계 준수/23, /24, /25별 블록 시작주소 정렬
예약 주소 제외Network·Broadcast 주소는 호스트에 할당 불가
확장성 고려향후 사용자·장비 증가분을 포함한 여유 대역 필요
보안 분리VLAN, ACL, 방화벽 정책과 서브넷을 연계
라우팅 효율상위 라우터에서는 /22로 경로 집약 가능

본 문제의 주소 공간은 요구량과 정확히 일치하므로 추가 호스트 증가, 게이트웨이·서버·프린터·네트워크 장비의 IP까지 고려하면 여유 주소가 부족할 수 있다. 실무에서는 향후 증가율을 반영하여 더 큰 주소 대역을 확보하거나 사용자 단말 수를 재산정해야 한다.

Ⅳ. 결론

서브네팅은 하나의 네트워크를 여러 하위 네트워크로 분할하여 주소 효율성, 보안성 및 관리성을 향상시키고, 슈퍼네팅은 연속된 네트워크를 하나의 경로로 집약하여 라우팅 테이블과 라우팅 트래픽을 감소시킨다.

주어진 192.168.0.0/22 대역은 VLSM을 적용하여 개발팀 /23, 영업팀 /24, 인사팀과 보안팀 각각 /25로 분할할 수 있다. 이 설계는 전체 1,024개 주소를 정확히 사용하지만 예비 주소가 없으므로, 실제 구축 시에는 향후 확장성과 네트워크 장비용 주소까지 함께 고려해야 한다.
