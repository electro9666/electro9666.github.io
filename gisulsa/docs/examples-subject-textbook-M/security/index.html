1. 암호화 기술​

1.1 대칭키 암호화​

대칭키 암호화(Symmetric Key Encryption)는 암호화와 복호화에 동일한 키를 사용하는 방식이다. 송신자와 수신자가 사전에 동일한 비밀 키를 공유해야 하며, 대표적인 알고리즘으로는 DES(56비트), 3DES, AES(128/192/256비트), SEED, ARIA 등이 있다. AES는 현재 가장 널리 사용되는 대칭키 알고리즘으로, 미국 NIST에서 표준으로 채택하였다.

블록 암호화 모드는 대칭키 암호화에서 중요한 개념이다. ECB(Electronic CodeBook) 모드는 각 블록을 독립적으로 암호화하여 구현이 단순하지만 패턴이 노출될 수 있는 취약점이 있다. CBC(Cipher Block Chaining) 모드는 이전 암호문 블록을 다음 블록의 입력에 XOR하여 패턴 노출 문제를 해결한다. CFB(Cipher FeedBack)와 OFB(Output FeedBack) 모드는 블록 암호를 스트림 암호처럼 활용할 수 있게 한다.

대칭키 암호화의 가장 큰 단점은 키 배분(Key Distribution) 문제이다. n명의 사용자가 서로 통신하려면 n(n-1)/2개의 키가 필요하며, 안전한 채널을 통한 키 공유가 선행되어야 한다. 이를 보완하기 위해 비대칭키 암호화 방식과 혼합하여 사용하는 하이브리드 암호화 방식이 일반적으로 채택된다.

1.2 비대칭키 암호화 (공개키)​

비대칭키 암호화(Asymmetric Key Encryption)는 공개키(Public Key)와 개인키(Private Key)라는 수학적으로 연관된 키 쌍을 사용한다. 공개키로 암호화한 데이터는 대응하는 개인키로만 복호화할 수 있으며, 반대로 개인키로 서명한 데이터는 공개키로 검증할 수 있다. 대표적인 알고리즘으로는 RSA, ElGamal, ECC(Elliptic Curve Cryptography) 등이 있다.

RSA는 두 소수의 곱으로 이루어진 큰 수의 인수분해가 어렵다는 수학적 원리에 기반한다. ElGamal은 이산로그 문제의 어려움을 기반으로 하며, 암호화와 전자서명 모두에 활용된다. ECC(타원곡선 암호)는 타원곡선 이산로그 문제를 기반으로 RSA보다 짧은 키 길이로 동등한 보안 수준을 제공하여, 모바일 환경 등 자원이 제한된 환경에서 선호된다.

전자봉투(Digital Envelope)는 비대칭키와 대칭키를 혼합한 방식이다. 생성 절차는 다음과 같다: 먼저 임시 대칭키(세션키)를 생성하여 메시지를 암호화하고, 수신자의 공개키로 세션키를 암호화한 뒤 암호화된 메시지와 함께 전송한다. 수신자는 자신의 개인키로 세션키를 복호화한 후, 세션키로 메시지를 복호화한다. 이 방식은 대칭키의 속도와 비대칭키의 키 배분 편의성을 동시에 취한다.

1.3 해시 함수​

해시 함수(Hash Function)는 임의 길이의 입력 데이터를 고정 길이의 출력값(해시값, 다이제스트)으로 변환하는 단방향 함수이다. 주요 특성은 역상 저항성(원본 복원 불가), 제2역상 저항성(같은 해시값을 가진 다른 입력 탐색 불가), 충돌 저항성(같은 해시값을 가진 두 입력 탐색 불가)의 세 가지다. 대표적인 알고리즘으로는 MD5(128비트, 현재 취약), SHA-1(160비트, 현재 취약), SHA-256/SHA-3(256비트 이상, 현재 표준) 등이 있다.

해시 함수의 취약점으로는 레인보우 테이블(Rainbow Table) 공격이 있다. 이는 사전에 계산된 해시값 목록을 이용해 역방향으로 원본 데이터를 찾아내는 공격이다. 이에 대한 대응 방법으로 솔트(Salt)가 사용된다. 솔트는 해시 함수 적용 전 원본 데이터에 임의의 값을 추가하여 동일한 입력도 매번 다른 해시값을 생성하도록 한다. 키 스트레칭(Key Stretching)은 해시 함수를 수천 회 반복 적용하여 무차별 대입 공격을 어렵게 만드는 기법이다.

HMAC(Hash-based Message Authentication Code)은 해시 함수와 비밀 키를 결합한 메시지 인증 코드다. 메시지의 무결성과 발신자 인증을 동시에 제공하며, HMAC-SHA256 등의 형태로 TLS, IPSec 등의 프로토콜에서 널리 사용된다. HMAC은 단순 해시와 달리 키를 알아야만 인증값을 생성하거나 검증할 수 있어 인증 기능을 추가로 제공한다.

1.4 양자 암호 및 포스트 양자 암호​

양자암호통신(Quantum Cryptography)은 양자역학의 원리를 이용한 암호 통신 방식이다. 핵심은 QKD(Quantum Key Distribution, 양자 키 분배)로, 광자(Photon)의 양자 상태를 이용해 도청이 물리적으로 불가능한 암호키를 분배한다. 도청 시도 시 양자 상태가 변하여 도청 사실이 자동으로 탐지되는 원리(하이젠베르크 불확정성 원리)를 활용한다. 주요 프로토콜로는 BB84, E91 등이 있으며, 취약점으로는 장거리 전송 시 신호 손실, 중계 장비의 보안 문제 등이 있다.

포스트 양자 암호(Post-Quantum Cryptography, PQC)는 양자 컴퓨터의 공격에도 안전한 고전적 암호 알고리즘이다. 양자 컴퓨터는 Shor 알고리즘으로 기존 RSA, ECC 등 공개키 암호를 빠르게 해독할 수 있어, 이를 대체할 새로운 알고리즘이 필요하다. NIST는 격자 기반(Lattice-based), 해시 기반(Hash-based), 코드 기반(Code-based), 다변수 다항식(Multivariate) 등의 PQC 알고리즘을 표준화하고 있다.

동형암호(Homomorphic Encryption)는 암호화된 상태에서 연산을 수행할 수 있는 특수한 암호 방식이다. 데이터를 복호화하지 않고도 암호문에 대해 덧셈, 곱셈 등의 연산을 수행하면, 그 결과를 복호화했을 때 평문에서 동일한 연산을 수행한 결과와 동일하다. 클라우드 환경에서 데이터의 기밀성을 유지하면서 분석·처리가 가능하여 의료 데이터, 금융 데이터 처리 등에 활용이 기대된다. 부분 동형암호(PHE), 완전 동형암호(FHE) 등의 유형이 있으며, 연산 성능 개선이 지속적인 연구 과제다.

2. 인증 및 접근제어​

2.1 전자서명 및 공개키 기반구조(PKI)​

전자서명(Digital Signature)은 메시지의 무결성 및 발신자 인증, 부인 방지를 제공하는 암호 기법이다. 서명자는 메시지의 해시값을 자신의 개인키로 암호화하여 서명을 생성하고, 수신자는 서명자의 공개키로 서명을 복호화하여 검증한다. 전자서명은 기밀성을 제공하지 않으므로 필요 시 추가적인 암호화가 병행된다. 2020년 전자서명법 개정으로 공인인증서와 사설인증서의 법적 효력이 동등해졌으며, 이에 따라 카카오, 네이버, 패스(PASS) 등 다양한 사설 인증 서비스가 확산되었다.

PKI(Public Key Infrastructure)는 공개키 암호화를 위한 인프라 체계로, 인증기관(CA), 등록기관(RA), 인증서 저장소 등으로 구성된다. CA는 사용자의 공개키와 신원 정보를 결합한 디지털 인증서를 발급하며, X.509 표준 형식을 따른다. 블록체인 기반 인증은 탈중앙화된 방식으로 인증서를 관리하여 단일 CA에 대한 의존성을 제거하고 위변조를 방지한다.

DID(Decentralized Identity, 분산 ID)는 중앙화된 인증기관 없이 개인이 자신의 신원을 스스로 관리하는 자기주권형 신원 체계이다. 블록체인 기반으로 구현되며, W3C 표준을 따른다. 신원증명의 발전 단계는 중앙화 신원 → 연합 신원 → 자기주권 신원 순으로 진화했다. 모바일 신분증은 DID 기술을 활용한 대표적 응용 사례로, 스마트폰에 신분증을 디지털로 저장하여 사용한다.

2.2 FIDO 및 다중인증​

FIDO(Fast Identity Online)는 비밀번호 없는 강력한 인증을 위한 개방형 표준이다. FIDO 1.0은 UAF(Universal Authentication Framework)와 U2F(Universal 2nd Factor)로 구성된다. UAF는 생체인식 등 기기 내 인증기를 활용하여 비밀번호를 완전히 대체하며, U2F는 기존 비밀번호 인증에 보안 키(USB 토큰 등)를 2차 인증으로 추가하는 방식이다.

FIDO 2.0은 FIDO1.0을 발전시켜 웹 환경까지 확장한 표준으로, WebAuthn(W3C 표준)과 CTAP(Client to Authenticator Protocol)로 구성된다. WebAuthn은 브라우저와 웹 서버 간의 인증 프로토콜이고, CTAP은 외부 인증기(스마트폰, 보안 키 등)와 클라이언트 기기 간의 통신 프로토콜이다. 인증 정보는 서버에 저장되지 않고 기기에 저장되어 대규모 데이터 유출 위험을 줄인다.

다중인증(MFA, Multi-Factor Authentication)은 두 가지 이상의 인증 요소를 결합한 방식이다. 사용자 인증 요소는 지식 기반(알고 있는 것: 비밀번호, PIN), 소유 기반(가지고 있는 것: OTP 토큰, 스마트카드), 특성 기반(신체적 특성: 지문, 홍채, 얼굴)의 세 가지 유형과 행동 기반(하는 것: 서명 패턴)을 포함한 네 가지 유형으로 분류된다. 비대면 거래 증가와 함께 MFA의 중요성이 더욱 강조되고 있다.

2.3 접근제어 모델​

접근제어(Access Control)는 인가된 사용자만이 특정 자원에 접근할 수 있도록 제한하는 보안 메커니즘이다. 주요 정책으로는 강제적 접근제어(MAC), 임의적 접근제어(DAC), 역할 기반 접근제어(RBAC)가 있다. MAC(Mandatory Access Control)은 보안 레이블을 기반으로 시스템이 강제적으로 접근을 통제하며, 군사 보안 등 고보안 환경에서 활용된다. DAC(Discretionary Access Control)는 자원 소유자가 접근 권한을 스스로 설정하는 방식으로, 일반 운영체제의 파일 권한 시스템이 이에 해당한다.

RBAC(Role-Based Access Control)는 사용자의 역할(Role)에 따라 접근 권한을 부여하는 방식으로, 대규모 조직에서의 권한 관리에 효율적이다. 사용자는 하나 이상의 역할을 가지며, 역할에 사전 정의된 권한이 부여된다. 대표적인 보안 모델로는 기밀성 보장을 위한 벨-라파듈라(BLP) 모델(읽기 상향 금지, 쓰기 하향 금지), 무결성 보장을 위한 비바(BIBA) 모델(읽기 하향 금지, 쓰기 상향 금지), 상업 환경을 위한 클락-윌슨(Clark-Wilson) 모델이 있다.

NAC(Network Access Control)는 네트워크에 접속하려는 기기의 보안 상태를 검사하고 정책 기반으로 접근을 통제하는 기술이다. 운영체제 패치 적용 여부, 백신 설치 및 업데이트 상태 등을 확인하여 비준수 기기는 격리 영역으로 이동시키거나 치료 후 접근을 허용한다. 내부 네트워크 보안 강화와 내부자 위협 대응에 효과적이다.

3. 네트워크 보안​

3.1 방화벽 및 네트워크 보안 장비​

방화벽(Firewall)은 내부 네트워크와 외부 네트워크 사이에서 트래픽을 필터링하는 네트워크 보안 장비이다. 패킷 필터링, 상태 기반 검사(Stateful Inspection), 애플리케이션 게이트웨이(프록시) 등의 방식으로 동작한다. 업무용 망을 인터넷 망에서 분리(망 분리)하는 경우 보안성은 높아지지만, 성능 저하와 비용 증가가 수반된다. 망 분리 구축 방안으로는 물리적 망 분리, 논리적 망 분리(가상화), 클라우드 기반 분리 등이 있다.

IDS(Intrusion Detection System, 침입탐지시스템)는 네트워크나 시스템에서 침입 시도를 탐지하여 관리자에게 경보를 발생시키는 시스템이다. 오용 탐지(Misuse Detection, 시그니처 기반)와 이상 탐지(Anomaly Detection, 행위 기반) 두 가지 방식을 사용한다. IPS(Intrusion Prevention System, 침입방지시스템)는 IDS의 탐지 기능에 차단 기능을 추가한 능동적 보안 장비로, 인라인(In-line) 방식으로 네트워크에 배치된다. IDS는 탐지 후 경보 발송, IPS는 탐지 즉시 차단 조치를 취한다는 점이 주요 차이점이다.

SIEM(Security Information and Event Management)은 여러 보안 장비와 시스템에서 수집한 로그와 이벤트를 통합 분석하여 위협을 탐지하고 대응하는 플랫폼이다. SOAR(Security Orchestration, Automation and Response)는 SIEM에서 진화한 개념으로, 보안 프로세스의 자동화와 오케스트레이션을 추가하여 반복적인 보안 운영 작업을 자동화하고 대응 시간을 단축한다. SIEM이 탐지와 분석에 초점을 둔다면, SOAR는 자동화된 대응까지 포함하는 더 넓은 개념이다.

3.2 VPN 및 통신 보안​

VPN(Virtual Private Network)은 공용 네트워크를 통해 사설 네트워크와 같은 수준의 보안을 제공하는 기술이다. 터널링(Tunneling), 암호화, 인증, 접근제어의 네 가지 핵심 기술 요소로 구성된다. IPSec VPN은 네트워크 계층(L3)에서 동작하며 IP 패킷 전체를 암호화하고, SSL VPN은 전송 계층(L4)에서 동작하여 별도의 클라이언트 소프트웨어 없이 웹 브라우저만으로 접속이 가능하다. 제로 트러스트 아키텍처의 확산으로 전통적인 VPN 방식에 대한 보안 재검토가 이루어지고 있다.

TLS(Transport Layer Security)는 인터넷 통신의 기밀성과 무결성을 보장하는 표준 프로토콜이다. TLS 1.2는 핸드셰이크 과정에서 취약한 알고리즘 협상, BEAST, POODLE 등 다양한 공격에 취약점이 발견되었다. TLS 1.3은 이러한 취약점을 개선하여 안전하지 않은 암호화 스위트를 제거하고, 1-RTT(Round-Trip Time) 핸드셰이크로 성능을 향상시켰으며, 0-RTT 세션 재개를 지원한다. TLS 1.3은 현재 권고 표준이다.

HTTPS는 HTTP에 TLS를 결합한 프로토콜로, 웹 통신의 기밀성과 무결성을 보장한다. HTTP는 평문 전송으로 도청, 변조, 위장 공격에 취약하지만, HTTPS는 암호화를 통해 이를 방어한다. FTP와 FTPS, SFTP의 차이도 중요한 개념이다. FTPS는 FTP에 TLS/SSL을 적용한 것이고, SFTP는 SSH 프로토콜을 기반으로 하는 완전히 다른 프로토콜로 SSH의 보안 채널을 통해 파일을 전송한다.

3.3 망 분리 및 보안 아키텍처​

망 분리는 업무망과 인터넷망을 물리적 또는 논리적으로 분리하여 내부 정보의 유출과 외부 공격을 차단하는 보안 방식이다. 물리적 망 분리는 완전히 독립된 두 개의 네트워크를 운영하는 방식으로 보안성이 가장 높지만 비용과 불편이 크다. 논리적 망 분리는 가상화 기술을 활용하여 단일 PC에서 두 환경을 분리 운영하는 방식으로 비용 절감 효과가 있다.

국가 망 보안체계(N2SF, National Network Security Framework)는 2025년 국가정보원이 공공기관을 대상으로 발표한 보안 가이드라인으로, 기존 물리적 망 분리 중심의 보안에서 데이터 중심의 보안으로 전환하는 방향을 제시한다. 업무 중요도와 데이터 민감도를 기반으로 보안 구역을 분류하고, 각 구역에 맞는 보안 조치를 적용하는 위험 기반 접근 방식을 채택한다. 클라우드, 재택근무 등 변화된 업무 환경에 유연하게 대응할 수 있는 보안 체계를 목표로 한다.

4. 악성코드 및 공격 기법​

4.1 APT 및 지능형 공격​

APT(Advanced Persistent Threat, 지능형 지속공격)는 특정 대상을 목표로 오랜 기간에 걸쳐 지속적으로 수행되는 고도화된 사이버 공격이다. 사이버 킬 체인(Cyber Kill Chain)은 Lockheed Martin이 제시한 APT 공격 단계 모델로, 정찰(Reconnaissance) → 무기화(Weaponization) → 전달(Delivery) → 취약점 공격(Exploitation) → 설치(Installation) → C&C(Command & Control) → 목적달성(Actions on Objectives)의 7단계로 구성된다. 각 단계에서 공격을 탐지하고 차단하는 방어 전략을 수립하는 데 활용된다.

스턱스넷(Stuxnet)은 2010년 발견된 최초의 실질적 사이버 무기로, 이란 핵 시설의 산업제어시스템(ICS/SCADA)을 공격한 악성코드다. USB를 통해 에어갭(Air-gap) 네트워크에 침투하여 원심분리기를 오작동시키면서도 정상 운영처럼 위장하였다. 국가 배후 사이버전(Cyber Warfare)의 대표적 사례로, 이후 산업제어시스템 보안 분야에 큰 관심을 불러일으켰다.

공격 표면(Attack Surface)은 공격자가 시스템에 침투하거나 데이터를 추출할 수 있는 모든 잠재적 접점의 합계이다. 공격 벡터(Attack Vector)는 실제 공격이 이루어지는 경로나 수단을 의미한다. IT 인프라 확장, 클라우드 도입, IoT 기기 증가 등으로 공격 표면이 지속적으로 넓어지고 있다. 측면 이동(Lateral Movement)은 공격자가 초기 침투 후 내부 네트워크에서 권한을 확대하며 이동하는 기법으로, Pass-the-Hash, Pass-the-Ticket 등의 기법이 사용된다.

4.2 랜섬웨어 및 악성코드​

랜섬웨어(Ransomware)는 피해자의 파일을 암호화하거나 시스템 접근을 차단한 후 복구 대가로 금전(주로 암호화폐)을 요구하는 악성코드이다. 주요 감염 경로는 이메일 첨부파일, 악성 웹사이트, 취약한 RDP, 소프트웨어 취약점 등이다. 암호화 동작 원리는 AES 등 대칭키로 파일을 암호화하고, 해당 대칭키를 공격자의 공개키로 암호화하여 복호화 키를 공격자만 보유하도록 한다.

RaaS(Ransomware as a Service)는 랜섬웨어를 서비스 형태로 제공하는 비즈니스 모델이다. 랜섬웨어 개발자가 악성코드와 관리 인프라를 제공하고, 공격자(Affiliate)가 이를 활용하여 공격을 수행하며 수익을 분배하는 구조다. 기술적 지식 없이도 랜섬웨어 공격이 가능해져 위협 행위자의 진입 장벽이 낮아졌다. 예방을 위해서는 정기적인 오프라인 백업, 최소 권한 원칙 적용, 보안 패치 적시 적용, 이메일 필터링 강화가 중요하다.

크라임웨어(Crimeware)는 경제적 이익을 목적으로 하는 모든 유형의 악성 소프트웨어를 포괄하는 용어로, 키로거, 스파이웨어, 뱅킹 트로이목마, 봇넷 등이 포함된다. CDR(Content Disarm and Reconstruction)은 문서 파일에 포함된 악성코드를 제거하는 기술로, 파일을 분해(Disarm)하여 안전한 요소만 재조합(Reconstruction)하는 방식으로 알려지지 않은(Unknown) 악성코드에도 대응 가능하다.

4.3 DDoS 및 웹 공격​

DDoS(Distributed Denial of Service)는 다수의 좀비 PC(봇넷)를 이용해 특정 시스템이나 서비스에 대량의 트래픽을 전송하여 서비스를 마비시키는 공격이다. 대응 방법으로는 스크러빙 센터(Scrubbing Center)와 CDN(Content Delivery Network)이 대표적이다. 스크러빙 센터는 대규모 공격 트래픽을 별도 센터로 우회하여 정상 트래픽만 통과시키며, CDN은 분산된 엣지 서버를 통해 트래픽을 분산 처리한다.

인젝션(Injection) 공격은 OWASP Top 10의 대표적 취약점으로, SQL Injection, LDAP Injection, OS Command Injection 등이 있다. 공격자가 입력 데이터에 악성 코드나 명령어를 삽입하여 서버에서 의도하지 않은 동작을 실행시킨다. 대응 방안으로는 입력값 검증, 파라미터화된 쿼리(Prepared Statement) 사용, 최소 권한 적용이 있다. 포맷 스트링 공격(Format String Attack)은 printf 등의 함수에서 포맷 문자열을 직접 입력받을 때 메모리를 읽거나 쓸 수 있는 취약점이다.

스피어 피싱(Spear Phishing)은 특정 개인이나 조직을 목표로 맞춤형 정보를 활용한 피싱 공격이다. 일반 피싱이 불특정 다수를 대상으로 하는 반면, 스피어 피싱은 사전 조사를 통해 신뢰할 수 있는 발신자로 위장한다. 사회공학(Social Engineering)은 기술적 취약점 대신 인간 심리를 이용하여 기밀 정보를 획득하거나 특정 행동을 유도하는 기법의 총칭이다.

5. 디지털 포렌식​

5.1 디지털 포렌식 개념 및 원칙​

디지털 포렌식(Digital Forensics)은 범죄 수사나 민사 분쟁에서 디지털 기기에 저장된 전자적 증거를 수집, 보존, 분석하여 법정에서 증거로 활용할 수 있도록 하는 과학적 절차와 기술의 총칭이다. 디지털 포렌식의 5대 원칙은 정당성의 원칙(적법한 절차), 재현성의 원칙(동일한 조건에서 동일한 결과), 신속성의 원칙(증거 수집의 신속한 처리), 연계 보관성의 원칙(Chain of Custody: 증거의 이동 경로 추적), 무결성의 원칙(증거 데이터의 변조 방지)으로 구성된다.

디지털 포렌식 조사 모델은 일반적으로 증거 식별 → 증거 수집 → 증거 보존 → 증거 분석 → 결과 보고의 단계로 진행된다. 증거 수집 기술로는 라이브 포렌식(휘발성 데이터 수집), 이미징(디스크 복제), 해시를 통한 무결성 검증 등이 있다. 증거 분석 기술로는 파일 시스템 분석, 레지스트리 분석, 네트워크 패킷 분석, 메모리 분석 등이 있다.

디지털 포렌식의 분야는 컴퓨터 포렌식(PC/서버), 모바일 포렌식(스마트폰/태블릿), 네트워크 포렌식, 클라우드 포렌식, 데이터베이스 포렌식 등으로 분류된다. 클라우드 포렌식은 가상화 환경, 데이터 분산 저장, 다중 관할권 등의 특성으로 인해 전통적인 포렌식과 다른 접근이 필요하다. 아티팩트(Artifact)는 운영체제나 애플리케이션이 정상 동작 중에 생성하는 파일, 레지스트리 항목, 로그 등 포렌식 조사의 단서가 되는 흔적이다.

5.2 안티포렌식​

안티포렌식(Anti-Forensics)은 디지털 증거의 발견, 수집, 분석을 방해하거나 무력화하려는 기술과 행위의 총칭이다. 주요 기법으로는 데이터 삭제 및 파기(Wiping), 파일 시스템 은닉, 스테가노그래피(Steganography, 데이터 숨기기), 메타데이터 위조, 암호화, 타임스탬프 조작 등이 있다. 안티포렌식에 대응하기 위해서는 증거 수집 시 원본 보존, 로그 시스템 강화, 컴플라이언스(Compliance) 시스템을 통한 행위 감사가 필요하다.

6. 개인정보보호 및 비식별화​

6.1 개인정보 비식별화 기술​

개인정보 비식별화는 특정 개인을 식별할 수 없도록 개인정보를 처리하는 기술이다. 주요 비식별 기법으로는 가명처리(Pseudonymization, 식별자를 다른 값으로 대체), 총계처리(Aggregation, 통계값으로 대체), 데이터 삭제(식별자 제거), 데이터 범주화(구체적 값을 범위값으로 대체), 데이터 마스킹(일부 정보를 '*'등으로 대체) 등이 있다. k-익명성(k-anonymity)은 동일한 속성값을 가진 레코드가 최소 k개 이상 존재하도록 하여 개인 식별을 방지하는 모델이다.

가명정보와 익명정보는 데이터 3법(개인정보 보호법, 정보통신망법, 신용정보법) 개정으로 도입된 개념이다. 가명정보는 추가 정보와 결합하면 개인 식별이 가능한 정보로, 연구, 통계, 공익적 목적으로 동의 없이 처리 가능하다. 익명정보는 어떠한 방법으로도 개인을 식별할 수 없는 정보로, 개인정보 보호법의 적용을 받지 않는다. 가명정보의 결합은 전문기관을 통해서만 가능하며, 반출 시 추가적인 비식별 조치가 필요하다.

PPDM(Privacy Preserving Data Mining)은 개인 프라이버시를 보호하면서 데이터 마이닝을 수행하는 기법이다. 데이터 교란(Perturbation), 데이터 암호화, 분산 처리 등의 기법을 활용한다. 차분 프라이버시(Differential Privacy)는 데이터셋에 개인이 포함되는지 여부에 관계없이 쿼리 결과가 거의 동일하도록 통계적 노이즈를 추가하는 방식으로, 강력한 프라이버시 보장을 수학적으로 증명할 수 있다.

6.2 개인정보 보호 강화기술(PET)​

PET(Privacy Enhancing Technology, 개인정보 보호 강화기술)는 개인정보 처리의 최소화와 프라이버시 보호를 기술적으로 구현하는 기술의 집합이다. 주요 PET 기술로는 동형암호(암호화 상태에서 연산 가능), 차분 프라이버시(통계적 프라이버시 보장), 합성 데이터(실제 데이터 분포를 모방한 가상 데이터 생성), 연합학습(Federated Learning), 다자간 계산(MPC) 등이 있다.

연합학습(Federated Learning)은 데이터를 중앙 서버로 전송하지 않고 각 기기에서 로컬로 모델을 학습시킨 후 파라미터만 공유하는 분산 AI 학습 방식이다. 개인 데이터가 기기 밖으로 나오지 않아 프라이버시를 보호할 수 있다. 보안 위협으로는 그래디언트 역공격(Gradient Inversion Attack), 모델 포이즈닝(Model Poisoning) 등이 있으며, 차분 프라이버시나 동형암호를 결합하여 보안성을 강화할 수 있다.

PbD(Privacy by Design)는 시스템을 설계 단계부터 프라이버시를 내재화하는 개념이다. Ann Cavoukian이 창안한 7대 원칙은 예방적 조치, 기본값으로의 프라이버시, 설계에 내재화, 완전한 기능성, 생애주기 전반의 보안, 가시성과 투명성, 사용자 프라이버시 존중을 포함한다. 8대 전략(Minimize, Hide, Separate, Aggregate, Inform, Control, Enforce, Demonstrate)은 구체적 구현 방향을 제시한다.

6.3 개인정보보호법 및 제도​

개인정보보호법은 개인정보의 수집, 이용, 제공, 관리에 관한 기본 법률이다. 2023년 개정된 개인정보보호법은 개인정보 전송요구권(마이데이터), AI 활용을 위한 자동화 의사결정 대응권, 국외 이전 요건 강화 등을 포함한다. 마이데이터(My Data)는 정보 주체가 자신의 개인정보를 제3자에게 전송할 것을 요구할 수 있는 권리로, 금융, 의료, 공공 분야에서 데이터 이동권을 보장한다.

개인정보 안심구역은 기업이 안전한 환경에서 데이터를 분석할 수 있도록 물리적으로 격리된 공간을 제공하는 제도로, 데이터 반출은 허용하지 않고 분석 결과만 반출을 허용한다. 데이터 안심구역은 이보다 더 광범위한 개념으로 클라우드 기반의 가상 분석 환경을 포함한다. APEC CBPR(Cross-Border Privacy Rules)은 아태지역 국가 간 개인정보의 안전한 국경 간 이전을 위한 인증 체계이다.

7. 보안관리체계​

7.1 ISMS 및 ISMS-P​

ISMS(Information Security Management System, 정보보호 관리체계)는 조직의 정보보호 활동을 체계적으로 관리하기 위한 종합적인 관리 프레임워크이다. 국내 ISMS 인증은 정보통신망법 제47조에 근거하며, 일정 규모 이상의 정보통신서비스 제공자는 의무적으로 인증을 받아야 한다. 의무 대상 기준은 매출액 100억 원 이상의 정보통신서비스 제공자, ISP, 연간 매출액 또는 세입이 1,500억 원 이상이며 일일 평균 이용자 수 100만 명 이상인 기업 등이 해당한다.

ISMS-P(ISMS-Privacy)는 ISMS에 개인정보보호 관리체계(PIMS)를 통합한 인증 제도이다. ISMS가 정보보호 관리과정(16개 항목)과 정보보호 대책(64개 항목)으로 구성된다면, ISMS-P는 여기에 개인정보처리 단계별 요구사항(22개 항목)이 추가된 총 102개 항목의 인증 기준을 적용한다. ISMS와 ISMS-P의 차이는 개인정보 처리 관련 항목의 포함 여부이며, 개인정보를 대규모로 처리하는 기업은 ISMS-P 인증이 권고된다.

ISMS 관리과정은 PDCA(Plan-Do-Check-Act) 사이클을 기반으로 한다. 정보보호 정책 수립 → 범위 설정 → 위험 관리 → 구현 → 사후 관리의 순환 과정으로 운영된다. 정보보호 거버넌스의 6대 원리는 책임, 전략적 정렬, 가치 제공, 위험 관리, 성과 관리, 자원 관리로 구성된다(ISO/IEC 27014 기반). CISO(Chief Information Security Officer)는 기업의 정보보안 전략과 정책을 총괄하는 임원급 책임자이다.

7.2 정보보호 정책 및 컴플라이언스​

정보보호 정책(Information Security Policy)은 조직의 정보보호 목표, 원칙, 책임을 규정한 최상위 문서이다. 정보보호 정책의 계층 구조는 정책(Policy) → 표준(Standard) → 지침(Guideline) → 절차(Procedure) 순으로 구성된다. 개인정보의 안전성 확보조치 기준은 개인정보처리자가 반드시 적용해야 할 기술적·관리적 보호조치를 규정한 고시로, 내부관리계획 수립, 접근권한 관리, 암호화, 접속기록 보관 등을 포함한다.

IT 컴플라이언스(Compliance)는 기업이 법령, 규제, 계약 등 외부 요구사항을 준수하는 활동이다. 주요 요구사항으로는 개인정보보호법, ISMS 인증, ISO 27001, GDPR 등이 있다. DevSecOps는 개발(Dev), 보안(Sec), 운영(Ops)을 통합하여 CI/CD 파이프라인의 모든 단계에서 보안을 내재화하는 방법론이다. SBOM(Software Bill of Materials)은 소프트웨어 구성 요소와 의존성을 목록화한 문서로, 오픈소스 취약점 관리와 공급망 보안에 활용된다.

공급망 보안(Supply Chain Security)은 소프트웨어 및 하드웨어의 개발, 유통, 운영 전 과정에서 보안 위협을 관리하는 활동이다. SolarWinds 해킹 사건 등 공급망 공격의 증가로 중요성이 부각되었다. SBOM을 활용하여 사용 중인 소프트웨어의 취약한 구성 요소를 추적하고, 제로 트러스트 기반 공급망 보안 아키텍처를 적용하는 것이 권고된다.

8. 제로 트러스트​

8.1 제로 트러스트 개념 및 원칙​

제로 트러스트(Zero Trust)는 "아무것도 신뢰하지 말고 항상 검증하라(Never Trust, Always Verify)"는 보안 원칙에 기반한 보안 모델이다. 전통적인 경계 기반 보안(Perimeter Security)이 내부 네트워크는 신뢰할 수 있다는 가정 하에 외부 위협만을 차단하는 데 집중했다면, 제로 트러스트는 내부 사용자, 기기, 네트워크도 기본적으로 신뢰하지 않고 모든 접근 요청을 검증한다. 원격 근무 확산, 클라우드 도입, 내부자 위협 증가 등 변화된 환경에 적합한 보안 패러다임이다.

제로 트러스트의 핵심 원칙은 최소 권한 원칙(Least Privilege), 명시적 검증(Verify Explicitly), 침해 가정(Assume Breach)의 세 가지다. 적용 분야는 사용자 및 기기 인증, 네트워크 마이크로 세그멘테이션, 애플리케이션 및 워크로드 보호, 데이터 중심 보안으로 구분된다. 기존 Trust Security 모델과의 비교에서 가장 큰 차이는 내부 네트워크에 대한 신뢰 여부와 동적인 접근 정책 적용에 있다.

CISA(미국 사이버보안 인프라보안국)의 제로 트러스트 성숙도 모델 2.0은 전통적(Traditional) → 고급(Advanced) → 최적화(Optimal)의 3단계로 성숙도를 정의한다. 5개 축(ID, 기기, 네트워크/환경, 애플리케이션 워크로드, 데이터)에 대해 각 성숙도 수준의 요구사항을 제시한다. 도입 시 고려사항으로는 기존 인프라와의 통합, 사용자 경험 저하 최소화, 단계적 전환 계획 수립 등이 있다.

8.2 제로 트러스트 아키텍처​

제로 트러스트 아키텍처(ZTA)는 제로 트러스트 원칙을 구현하기 위한 시스템 설계 방식이다. 핵심 구성 요소는 정책 엔진(Policy Engine), 정책 관리자(Policy Administrator), 정책 시행 지점(PEP, Policy Enforcement Point)으로 구성된 제어 평면과 실제 데이터 흐름을 처리하는 데이터 평면으로 나뉜다. SDP(Software Defined Perimeter)는 제로 트러스트 원칙을 구현하는 대표적 기술로, 인증된 사용자와 기기에만 동적으로 네트워크 연결을 허용한다.

9. 클라우드 보안​

9.1 클라우드 보안 위협 및 대응​

클라우드 컴퓨팅 환경에서의 보안 위협은 기존 온프레미스 환경과 다른 고유한 특성을 가진다. 주요 보안 위협으로는 데이터 유출, 계정 탈취, 불안전한 API, 공유 기술 취약점, 불충분한 인증/권한 관리, 멀웨어 주입, 내부자 위협 등이 있다. 클라우드 프라이버시 이슈로는 데이터의 물리적 위치 불명확성, 다중 테넌트 환경에서의 데이터 격리 문제, 클라우드 제공업체의 데이터 접근 가능성 등이 있다.

클라우드 보안을 위한 정보보호 정책의 관리적 측면으로는 보안 정책 수립, 보안 책임 분담(공동 책임 모델), 보안 교육, 감사 등이 있으며, 기술적 측면으로는 암호화, 접근제어, 네트워크 보안, 취약점 관리, 보안 모니터링 등이 있다. ISO/IEC 27017은 클라우드 서비스 정보보호를 위한 국제 표준으로, CSP(Cloud Service Provider)와 CSC(Cloud Service Customer) 각각의 보안 통제 지침을 제공한다.

공공기관 클라우드 보안 인증제도(CSAP, Cloud Security Assurance Program)는 공공기관에 서비스를 제공하는 클라우드 사업자가 반드시 획득해야 하는 인증으로, 하(SaaS 표준 등급), 중(IaaS), 상(국가·공공 중요 정보 처리) 세 가지 등급으로 구분된다. SECaaS(Security as a Service)는 클라우드 방식으로 보안 서비스를 제공하는 모델로, 방화벽, IDS/IPS, SIEM, 취약점 스캐닝 등을 구독 형태로 이용할 수 있다.

9.2 클라우드 보안 도입 시 고려사항​

클라우드 서비스 도입 시 IT 담당자는 다음과 같은 보안 요소를 고려해야 한다. 데이터 암호화(저장 중, 전송 중, 처리 중), 강력한 IAM(Identity and Access Management) 체계 구축, 네트워크 보안(가상 방화벽, 보안 그룹, VPN), 지속적인 보안 모니터링과 로그 관리, 데이터 위치 및 주권 문제 검토, 사고 대응 계획 수립 등이 핵심 고려사항이다.

블록체인 시스템 도입 시 보안 고려사항으로는 스마트 컨트랙트(Smart Contract)의 코드 취약점, 합의 알고리즘 취약점, 개인키 관리 취약점, 51% 공격, 프런트 러닝 등이 있다. 스마트 컨트랙트 감사(Audit)는 배포 전 코드의 보안 취약점을 발견하고 수정하는 과정으로, 정적 분석, 동적 분석, 형식적 검증(Formal Verification) 등의 방법을 사용한다.

10. AI 및 신기술 보안​

10.1 AI·머신러닝 보안​

머신러닝 시스템에 대한 적대적 공격(Adversarial Attack)은 AI 학습 과정 및 추론 단계를 공격 대상으로 한다. 주요 공격 유형 4가지는 다음과 같다. 데이터 포이즈닝(Data Poisoning): 학습 데이터에 악의적 샘플을 삽입하여 모델의 성능이나 동작을 변조한다. 적대적 예제(Adversarial Example): 인간이 인식하기 어려운 미세한 노이즈를 입력에 추가하여 모델을 오분류하게 만든다. 모델 추출(Model Extraction): 쿼리를 통해 모델의 내부 구조나 파라미터를 역공학으로 추출한다. 멤버십 추론(Membership Inference): 특정 데이터가 모델의 학습에 사용되었는지 여부를 판단하여 프라이버시를 침해한다.

생성형 AI(Generative AI) 활용 시 보안 위협으로는 프롬프트 인젝션(Prompt Injection), 할루시네이션(Hallucination)으로 인한 잘못된 정보 생성, 민감 정보 노출, 모델 역전 공격(Model Inversion Attack) 등이 있다. 프롬프트 인젝션은 악의적으로 조작된 입력을 통해 AI 모델의 시스템 지침을 무력화하거나 의도하지 않은 동작을 유발하는 공격이다. MCP(Model Context Protocol)를 활용한 AI 서비스에서는 외부 도구와의 연동 과정에서 추가적인 보안 취약점이 발생할 수 있다.

OWASP LLM Top 10(2025)은 LLM 애플리케이션의 주요 보안 위협을 정의한다. 프롬프트 인젝션, 안전하지 않은 출력 처리, 학습 데이터 오염, 모델 서비스 거부, 공급망 취약점, 민감 정보 노출, 안전하지 않은 플러그인 설계, 과도한 에이전시(Excessive Agency), 과잉 의존(Overreliance), 모델 절도(Model Theft)가 포함된다. 기업은 AI 시스템 설계 시 OWASP LLM 가이드라인을 참조하여 보안 통제를 수립해야 한다.

10.2 IoT 및 신기술 보안​

IoT(Internet of Things) 보안은 초연결 환경에서 다양한 기기 간의 신뢰성 확보가 핵심이다. IoT 네트워크 보안 프로토콜로는 CoAP(Constrained Application Protocol, HTTP의 경량 대체), MQTT(Message Queuing Telemetry Transport, 발행-구독 방식의 경량 메시지 프로토콜), LwM2M(Lightweight M2M, 기기 관리 프로토콜)이 대표적이다. 보안 이슈로는 기기의 제한된 자원으로 인한 암호화 적용의 어려움, 기기 인증, 펌웨어 업데이트 보안 등이 있다.

TPM(Trusted Platform Module)은 보안 기능을 제공하는 하드웨어 칩으로, 암호화 키 생성 및 저장, 플랫폼 무결성 측정, 보안 부팅 등의 기능을 제공한다. TTPs(Tactics, Techniques and Procedures)는 MITRE ATT&CK 프레임워크의 핵심 개념으로, 공격자의 행동 방식을 전술(목적), 기법(수단), 절차(세부 방법)로 분류하여 위협 인텔리전스 및 방어 전략 수립에 활용한다.

딥페이크(Deepfake)는 AI 기술을 이용해 인물의 얼굴이나 음성을 실제처럼 조작하는 기술이다. 사기, 허위 정보 확산, 명예훼손 등에 악용될 수 있으며, 탐지 기술로는 GAN 기반 탐지, 생체 신호 분석(눈 깜빡임 패턴, 맥박 등), 블록체인 기반 콘텐츠 인증 등이 연구되고 있다. AI 개인정보보호 자율점검표는 AI 시스템의 개인정보보호 원칙 준수를 위한 점검 기준을 제시한다.
