컴퓨터구조/운영체제

CPU 스케줄링​

CPU 스케줄링은 여러 프로세스가 CPU 자원을 효율적으로 공유하도록 실행 순서를 결정하는 운영체제의 핵심 기능입니다. SJF(Shortest Job First)는 실행 시간이 짧은 프로세스를 먼저 처리하여 평균 대기 시간을 최소화하지만, 긴 프로세스는 무한히 대기하는 기아(Starvation) 현상이 발생할 수 있습니다. HRN(Highest Response-ratio Next)은 응답 비율 = (대기 시간 + 서비스 시간) / 서비스 시간을 계산하여 오래 기다린 프로세스에 우선권을 부여함으로써 기아 현상을 해소합니다.

MLQ(Multi Level Queue)는 프로세스를 여러 큐로 분류하여 각 큐마다 다른 스케줄링 알고리즘을 적용하는 방식입니다. MLFQ(Multi Level Feedback Queue)는 MLQ를 개선하여 프로세스가 실행 이력에 따라 큐 간 이동이 가능하도록 합니다. 실시간 스케줄링에서는 우선순위 역전(Priority Inversion) 문제가 발생할 수 있으며, 이를 해결하기 위해 우선순위 상속(Priority Inheritance)과 우선순위 천장(Priority Ceiling) 기법이 사용됩니다.

  • 137회 3교시 - CPU 스케줄링과 디스크 스케줄링, SJF, SRT, SSTF, SLTF
  • 126회 4교시 - 우선순위 역전(Priority Inversion) 및 해결 기법

프로세스와 스레드​

프로세스(Process)는 실행 중인 프로그램의 인스턴스로, 독립된 메모리 공간(코드, 데이터, 힙, 스택 영역)을 가집니다. 운영체제는 프로세스마다 PCB(Process Control Block)를 유지하며 상태(생성, 준비, 실행, 대기, 종료)를 관리합니다. 프로세스 간 컨텍스트 스위칭(Context Switching)은 오버헤드가 크며, 메모리 공간이 분리되어 있어 직접 통신이 불가능합니다.

스레드(Thread)는 프로세스 내부의 실행 흐름 단위로, 같은 프로세스 내 스레드들은 코드·데이터·힙 영역을 공유하고 각자의 스택만 독립적으로 유지합니다. 멀티스레드(Multi-thread)는 자원 공유로 메모리 효율이 높고 컨텍스트 스위칭 비용이 낮지만, 동기화 문제(Race Condition)에 주의해야 합니다. 스핀 락(Spin Lock)은 임계 구역 진입 전 CPU를 점유하며 대기하는 동기화 기법으로, 대기 시간이 짧을 때 유리합니다.

관련 기출문제​

  • 116회 3교시 - 스레드, 멀티스레드 개념 및 프로세스와의 차이점
  • 110회 2교시 - 스핀 락(Read/Write Spin Lock)의 개념과 활용
  • 138회 2교시 - 메모리의 코드, 데이터, 힙, 스택 영역

교착상태와 은행가 알고리즘​

교착상태(Deadlock)는 두 개 이상의 프로세스가 서로 상대방이 보유한 자원을 기다리며 무한 대기에 빠지는 상태입니다. 교착상태 발생의 4가지 필요충분조건은 상호 배제(Mutual Exclusion), 점유 대기(Hold and Wait), 비선점(Non-preemption), 순환 대기(Circular Wait)이며, 이 중 하나라도 방지하면 교착상태를 예방할 수 있습니다.

은행가 알고리즘(Banker's Algorithm)은 다익스트라(Dijkstra)가 제안한 교착상태 회피 알고리즘입니다. 시스템이 안전 상태(Safe State)를 유지할 수 있는 경우에만 자원을 할당하며, 자원 할당 전에 모든 프로세스가 최대 요구량을 충족할 수 있는 안전 순서(Safe Sequence)가 존재하는지 검사합니다. 주요 자료구조로는 할당 행렬(Allocation), 최대 요구 행렬(Max), 가용 자원 벡터(Available)가 사용됩니다.

관련 기출문제​

  • 124회 3교시 - 교착상태와 은행가 알고리즘의 개념 및 자료구조
  • 138회 1교시 - 은행가 알고리즘(Banker's Algorithm)

메모리 관리 (페이징/세그멘테이션)​

페이징(Paging)은 물리 메모리를 고정 크기의 프레임(Frame)으로, 논리 메모리를 같은 크기의 페이지(Page)로 분할하여 관리하는 기법입니다. 페이지 테이블(Page Table)을 통해 논리 주소를 물리 주소로 변환하며, 외부 단편화(External Fragmentation)가 발생하지 않습니다. 그러나 페이지 크기에 의한 내부 단편화(Internal Fragmentation)와 페이지 테이블 관리 오버헤드가 단점입니다.

세그멘테이션(Segmentation)은 프로그램을 코드, 데이터, 스택 등 논리적 의미 단위인 세그먼트(Segment)로 분할하는 기법입니다. 세그먼트 테이블에 기준(Base)과 한계(Limit)를 저장하여 주소를 변환하며, 내부 단편화가 없지만 외부 단편화가 발생합니다. 페이지드 세그멘테이션(Paged Segmentation)은 두 기법을 결합하여 장점을 취하는 방식입니다.

관련 기출문제​

  • 132회 3교시 - 페이징 기법과 세그멘테이션 기법 비교
  • 138회 2교시 - 메모리 4가지 주요 영역의 역할과 특징

페이지 교체 알고리즘​

페이지 교체 알고리즘은 물리 메모리가 부족할 때 어떤 페이지를 디스크로 내보낼지 결정하는 정책입니다. 스래싱(Thrashing)은 프로세스가 페이지 교체에 대부분의 시간을 소비하여 CPU 이용률이 급격히 저하되는 현상으로, 워킹 셋(Working Set) 모델이나 PFF(Page Fault Frequency) 기법으로 완화할 수 있습니다.

주요 교체 알고리즘으로는 FIFO(First In First Out), OPT(Optimal, 최적), LRU(Least Recently Used), LFU(Least Frequently Used), NUR(Not Used Recently), Clock 알고리즘이 있습니다. OPT는 이론적으로 최소 페이지 부재를 보장하지만 미래 참조를 알 수 없어 실제 구현이 불가능합니다. LRU는 최근에 가장 오래 사용되지 않은 페이지를 교체하는 방식으로 OPT에 근접한 성능을 보이며, 스택이나 카운터로 구현합니다.

관련 기출문제​

  • 117회 4교시 - 페이지 교체 알고리즘 종류 및 동작 과정
  • 126회 1교시 - 스래싱(Thrashing)
  • 110회 4교시 - 프로세스 스래싱의 발생 원인과 예방책

파이프라인​

파이프라인(Pipeline)은 CPU 명령어 처리를 여러 단계(Stage)로 분할하여 각 단계를 병렬로 처리함으로써 처리량(Throughput)을 향상시키는 기법입니다. 일반적으로 인출(IF), 해독(ID), 실행(EX), 메모리 접근(MEM), 쓰기(WB)의 5단계로 구성됩니다. n개 명령어를 m단계 파이프라인으로 처리할 때 수행 시간은 (m + n - 1) × k(단계당 처리 시간)이며, 비파이프라인 방식의 m × n × k와 비교하여 큰 성능 향상을 보입니다.

파이프라인 해저드(Hazard)는 구조적 해저드(Structural Hazard), 데이터 해저드(Data Hazard), 제어 해저드(Control Hazard)의 세 가지로 분류됩니다. 데이터 해저드는 데이터 포워딩(Data Forwarding)으로, 제어 해저드는 분기 예측(Branch Prediction)과 지연 분기(Delayed Branch)로 완화합니다. 슈퍼스칼라(Superscalar) 구조는 파이프라인을 복수로 구성하여 명령어 수준 병렬성(ILP)을 극대화합니다.

관련 기출문제​

  • 113회 4교시 - 파이프라인 방식과 비파이프라인 방식 CPU 처리시간 비교

캐시 메모리​

캐시 메모리(Cache Memory)는 CPU와 주기억장치(RAM) 사이에 위치한 고속 소용량 메모리로, 자주 사용되는 데이터를 임시 저장하여 메모리 접근 지연(Latency)을 줄입니다. 지역성(Locality)의 원리 — 시간적 지역성(Temporal Locality)과 공간적 지역성(Spatial Locality) — 에 의해 높은 적중률(Hit Rate)을 달성합니다. 캐시는 L1, L2, L3 계층으로 구성되며 상위 계층일수록 속도가 빠르고 용량이 작습니다.

캐시 쓰기 정책(Write Policy)으로는 쓰기 연동(Write-Through)과 쓰기 지연(Write-Back)이 있습니다. Write-Through는 캐시와 주기억장치에 동시에 쓰므로 일관성이 높지만 쓰기 오버헤드가 큽니다. Write-Back은 캐시에만 쓰고 교체 시 주기억장치에 반영하여 쓰기 성능이 높지만, 멀티프로세서 환경에서 캐시 일관성(Cache Coherence) 문제가 발생할 수 있습니다. MESI 프로토콜 등을 통해 캐시 일관성을 유지합니다.

IPC (프로세스 간 통신)​

IPC(Inter-Process Communication)는 독립된 프로세스 간에 데이터를 교환하고 동기화하기 위한 메커니즘입니다. 프로세스는 독립적인 메모리 공간을 가지므로 운영체제가 제공하는 IPC 메커니즘을 통해서만 통신할 수 있습니다. IPC는 협력 프로세스 간 데이터 공유, 작업 분산, 이벤트 통지 등의 목적으로 사용됩니다.

주요 IPC 기법으로는 파이프(Pipe), 메시지 큐(Message Queue), 공유 메모리(Shared Memory), 소켓(Socket), 세마포어(Semaphore), 시그널(Signal)이 있습니다. 공유 메모리는 가장 빠른 IPC 방식이지만 동기화 문제가 발생하며, 세마포어나 뮤텍스로 임계 구역을 보호해야 합니다. 메시지 큐는 비동기 통신에 적합하며, 소켓은 네트워크를 통한 원격 프로세스 통신까지 지원합니다.

  • 138회 4교시 - IPC의 개념, 주요기법, 동기화 기법

인터럽트​

인터럽트(Interrupt)는 CPU가 현재 실행 중인 프로그램을 일시 중단하고 발생한 이벤트를 처리하도록 하는 메커니즘입니다. 하드웨어 인터럽트(Hardware Interrupt)는 입출력 장치, 타이머, 전원 이상 등 외부 장치에서 발생하며, 소프트웨어 인터럽트(Software Interrupt)는 프로그램 내 예외(Exception)나 시스템 콜(System Call)로 발생합니다.

인터럽트 처리 순서는 인터럽트 요청 → 현재 상태 저장(PSW, PC) → 인터럽트 벡터 테이블 조회 → ISR(Interrupt Service Routine) 실행 → 복귀 순서로 진행됩니다. 인터럽트 우선순위는 전원 이상 > 기계 착오 > 외부 > 입출력 > 명령어 착오 > 소프트웨어 인터럽트 순으로 일반적으로 설정됩니다. 멀티프로세서 환경에서는 인터럽트 처리 시 공유 자원 동기화 문제에 주의해야 합니다.

관련 기출문제​

  • 113회 2교시 - 멀티프로세스 환경에서 인터럽트 처리 우선순위

파일 시스템​

파일 시스템(File System)은 보조기억장치에 데이터를 구조적으로 저장·관리하는 운영체제의 구성 요소입니다. FAT(File Allocation Table), NTFS(NT File System), ext4 등 다양한 파일 시스템이 존재하며, 각각 성능, 안정성, 지원 기능에서 차이가 있습니다. 파일 할당 방식으로는 연속 할당(Contiguous Allocation), 연결 할당(Linked Allocation), 색인 할당(Indexed Allocation)이 있습니다.

UNIX 파일 시스템은 i-node(Index Node) 구조를 사용하며, 부팅 과정은 BIOS → 부트로더(GRUB) → 커널 적재 → init 프로세스 실행 → 런레벨별 서비스 시작 순서로 진행됩니다. 저널링(Journaling) 파일 시스템은 변경 사항을 트랜잭션으로 기록하여 시스템 비정상 종료 시에도 데이터 무결성을 보장합니다. 디스크 스케줄링 알고리즘(FCFS, SSTF, SCAN, C-SCAN, SLTF)은 디스크 헤드 이동을 최소화하여 I/O 성능을 향상시킵니다.
