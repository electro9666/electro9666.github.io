빅데이터 개념(3V/5V)​

개요​

**빅데이터(Big Data)**는 기존의 데이터 관리 도구로는 처리하기 어려운 대규모 데이터를 의미하며, 초기에는 3V(Volume·Velocity·Variety)로 정의되었습니다. **Volume(규모)**은 페타바이트 이상의 방대한 데이터 양을, **Velocity(속도)**는 실시간에 가까운 데이터 생성·처리 속도를, **Variety(다양성)**은 정형·반정형·비정형의 다양한 데이터 형태를 의미합니다. 이후 **Veracity(정확성)**와 Value(가치) 가 추가되어 5V 모델로 확장되었으며, 신뢰할 수 있는 데이터에서 비즈니스 가치를 창출하는 것이 핵심 목표입니다.

빅데이터 분석의 수행 절차는 일반적으로 비즈니스 이해 → 데이터 수집·탐색 → 데이터 준비 → 모델링 → 평가 → 배포 단계로 구성됩니다. 대표적인 방법론으로는 CRISP-DM(Cross Industry Standard Process for Data Mining)이 있으며, 산업 전반에 걸쳐 데이터 마이닝 프로젝트를 수행하는 표준 프로세스로 활용됩니다. 분석 주제는 하향식(비즈니스 전략 기반)과 상향식(데이터 탐색 기반) 방식으로 도출할 수 있습니다.

빅데이터 플랫폼 인프라는 분산 저장·처리 기술(Hadoop·Spark), 스트리밍 처리 기술(Kafka·Flink), 클라우드 기반 확장성을 결합한 아키텍처로 구성됩니다. 플랫폼 설계 시에는 데이터 수집(인제스천) 구조, 저장 구조(원본/가공 구분), 입출력 인터페이스(배치/스트리밍/API) 세 가지 측면의 설계가 필요합니다. 빅데이터 분석 도구 선택의 원칙으로는 처리 데이터 규모, 실시간 요건, 기술 성숙도, 운영 비용 등을 종합적으로 고려합니다.

데이터 마이닝(연관규칙/분류/군집)​

개요​

**데이터 마이닝(Data Mining)**은 대용량 데이터에서 유용한 패턴·규칙·지식을 자동으로 추출하는 과정입니다. 통계와의 차이점은 데이터 마이닝이 대규모 비정형 데이터를 다루고 탐색적·귀납적 접근을 취하는 반면, 통계는 모집단에서 표본을 추출하여 연역적 가설 검증에 집중한다는 점입니다. 주요 기법은 연관규칙 분석, 분류(Classification), 군집 분석(Clustering), 회귀 분석, 이상치 탐지 등으로 구분됩니다.

연관규칙 분석은 데이터 항목들 사이의 공존 관계를 발견하는 기법으로, '기저귀 → 맥주'와 같은 장바구니 분석이 대표적 사례입니다. 연관 정도를 측정하는 3가지 기준은 지지도(Support), 신뢰도(Confidence), **향상도(Lift)**입니다. 지지도는 전체 거래 중 두 항목이 함께 구매된 비율, 신뢰도는 선행 항목 구매 시 후행 항목도 구매되는 조건부 확률, 향상도는 두 항목의 독립 가정 대비 실제 함께 구매되는 비율입니다.

분류 모델의 성능 평가에는 혼동행렬(Confusion Matrix)이 활용됩니다. 혼동행렬에서 TP(True Positive), TN(True Negative), FP(False Positive), FN(False Negative)을 기반으로 정확도(Accuracy), 정밀도(Precision), 재현율(Recall), F1-Score를 산출합니다. 군집 분석으로는 K-Means(거리 기반 중심점 이동), DBSCAN(밀도 기반 노이즈 처리), SOM(Self-Organizing Map, 신경망 기반 비지도 학습) 등이 있으며, 의사결정나무의 분기 기준으로는 지니 지수(Gini Index)와 엔트로피 지수(Entropy Index)가 활용됩니다.

텍스트 마이닝​

개요​

**텍스트 마이닝(Text Mining)**은 비정형 텍스트 데이터에서 의미 있는 정보와 패턴을 추출하는 기술입니다. 기본 분석 절차는 텍스트 수집 → 전처리(토큰화·불용어 제거·형태소 분석) → 특징 추출(TF-IDF·Word Embedding) → 분석(분류·군집·감성 분석) → 해석 및 시각화 순으로 진행됩니다. 형태소 분석을 통해 문서별 단어 빈도를 식별하고, TF-IDF(Term Frequency-Inverse Document Frequency)를 계산하여 각 문서에서 중요한 단어를 수치화합니다.

**오피니언 마이닝(Opinion Mining)**은 소셜 미디어·리뷰·뉴스 등에서 개인이나 집단의 감성·의견·태도를 분석하는 기법입니다. 감성 분석(Sentiment Analysis)이라고도 하며, 긍정·부정·중립을 분류하거나 감정 강도를 수치화합니다. 수행 절차는 데이터 수집 → 전처리 → 감성 사전 구축 또는 기계학습 모델 적용 → 감성 점수 산출 → 인사이트 도출 순이며, 텍스트 마이닝의 하위 분야이자 확장으로 볼 수 있습니다.

**사회연결망 분석(SNA, Social Network Analysis)**은 개인이나 조직 간의 관계를 그래프 이론 기반으로 분석하는 기법입니다. 분석 표현 방법으로는 소시오그램(Sociogram), 인접 행렬(Adjacency Matrix), 연결 목록(Edge List)이 있으며, 중심성 분석(연결중심성·매개중심성·인접중심성), 클러스터링, 커뮤니티 탐지 등의 분석 기법이 활용됩니다. 음성 데이터 마이닝은 텍스트 마이닝의 확장으로, STT(Speech-to-Text) 변환 후 콜센터·의료 기록 분석 등에 활용됩니다.

데이터 시각화​

개요​

**데이터 시각화(Data Visualization)**는 데이터를 그래프·차트·지도·인포그래픽 등의 시각적 형태로 변환하여 인사이트를 직관적으로 전달하는 기법입니다. 시각화의 원리는 게슈탈트 법칙(근접성·유사성·연속성)과 사전주의적 처리(Pre-attentive Processing) 이론에 기반하며, 절차는 목표 정의 → 데이터 준비 → 시각 인코딩 선택 → 디자인·구현 → 평가 단계로 진행됩니다.

시각화 유형은 데이터 특성에 따라 분류됩니다. 비교 시각화(막대 차트·라디오 차트), 분포 시각화(히스토그램·박스플롯), 관계 시각화(산점도·버블 차트), 시계열 시각화(라인 차트), 공간 시각화(지도 기반 히트맵·코로플레스 맵), 텍스트 시각화(워드 클라우드·트리맵) 등으로 구분됩니다. 빅데이터 시각화 도구로는 Tableau, Power BI, D3.js, Apache Superset, Kibana 등이 대표적입니다.

효과적인 데이터 시각화를 위한 효율화 방안으로는 데이터 잉크 비율(Data-Ink Ratio) 최대화, 차트 정크(Chart Junk) 제거, 색상 사용의 일관성 유지, 인터랙티브 드릴다운 기능 제공 등이 있습니다. 또한 대용량 데이터의 경우 집계·샘플링·계층적 데이터 구조를 활용한 렌더링 최적화가 필요하며, 다양한 기기와 화면 크기에 대응하는 반응형 시각화 설계도 중요합니다.

데이터 품질관리​

개요​

**데이터 품질관리(Data Quality Management)**는 데이터가 목적에 부합하는 수준의 정확성·완전성·일관성·유효성·적시성을 유지하도록 관리하는 체계입니다. 데이터 품질관리 프레임워크는 품질 정책 수립, 품질 기준 정의, 품질 진단·개선, 성과 모니터링의 순환 구조로 구성됩니다. 데이터 품질관리 총괄 책임자는 품질 정책 수립, 조직 내 데이터 품질 문화 정착, 부서 간 품질 이슈 조정 역할을 담당합니다.

정보 생명주기(ILC, Information Life Cycle) 단계별 품질 관리는 생성 → 저장 → 활용 → 공유·이동 → 폐기 각 단계에서 발생 가능한 품질 저하 요인을 사전에 제어하는 방식입니다. 데이터 품질 진단 절차는 진단 계획 수립 → 데이터 프로파일링 → 오류 원인 분석 → 개선 계획 수립 → 개선 실행 → 결과 검증 순으로 진행됩니다. 데이터 프로파일링(Data Profiling)은 컬럼별 유효값 비율, null 비율, 분포, 중복 등 데이터 값의 특성을 정량적으로 분석하는 활동입니다.

AI 학습용 데이터 품질관리는 일반 데이터 품질관리와 구별되는 특성이 있습니다. AI 학습 데이터는 정확한 **레이블링(Labeling)**과 **어노테이션(Annotation)**이 모델 성능에 직접적으로 영향을 미치므로, 가이드라인 기반의 라벨러 교육, 교차 검증, 이상치 제거 프로세스가 필수적입니다. 한국지능정보사회진흥원의 AI 학습용 데이터 품질관리 가이드라인 v2.0은 품질 모델, 단계별 수행 방안, 측정 지표를 체계적으로 제시합니다.

데이터 거버넌스​

개요​

**데이터 거버넌스(Data Governance)**는 조직 내 데이터 자산의 가용성·무결성·보안·활용성을 보장하기 위한 의사결정 구조, 정책, 절차의 총체입니다. 주요 기능으로는 데이터 표준 관리, 메타데이터 관리, 데이터 보안 관리, 데이터 품질 관리, 마스터 데이터 관리(MDM), 데이터 생명주기 관리 등이 있습니다. 코로나19 이후 데이터 주권 이슈가 부각되면서, 조직 내부뿐 아니라 공급망 전체의 데이터 거버넌스 전략이 중요해졌습니다.

**마스터 데이터(Master Data)**는 조직 내 여러 시스템에서 공통으로 사용되는 핵심 참조 데이터(고객·제품·직원·공급업체 정보 등)를 말합니다. **마스터 데이터 관리(MDM)**는 이 데이터를 단일하고 신뢰할 수 있는 형태로 통합·유지하는 프로세스로, 구성 요소로는 데이터 통합 레이어, 데이터 품질 엔진, 비즈니스 규칙 관리, 마스터 데이터 허브가 있습니다. MDM 구축 시에는 조직 변화관리, 데이터 소유권 정의, 기존 레거시 시스템과의 통합 전략이 핵심 고려 사항입니다.

DataOps는 DevOps의 원칙을 데이터 파이프라인에 적용하여 데이터의 수집·가공·배포 과정을 자동화하고 협업을 강화하는 방법론입니다. DevOps와의 차이점은 DevOps가 소프트웨어 개발·배포 자동화에 집중하는 반면, DataOps는 데이터 품질·신뢰성 확보와 빠른 데이터 전달에 초점을 맞춥니다. **데이터 관측가능성(Data Observability)**은 파이프라인 내 데이터의 상태를 실시간으로 모니터링하여 이상 징후를 사전에 탐지하는 개념으로, DataOps의 핵심 요소입니다.

  • 129회 3교시 - 데이터 거버넌스 개념, 마스터 데이터 관리(MDM)
  • 130회 1교시 - 데이터 거버넌스

  • 138회 1교시 - 데이터 관측가능성(Data Observability)

람다/카파 아키텍처​

개요​

**람다 아키텍처(Lambda Architecture)**는 대규모 데이터를 배치 처리(Batch Layer)와 실시간 처리(Speed Layer)로 이원화하고, 서빙 레이어(Serving Layer)에서 두 결과를 통합하는 빅데이터 처리 아키텍처입니다. 배치 레이어는 전체 데이터에 대한 정확한 뷰(Batch View)를 생성하고, 스피드 레이어는 배치 처리 지연을 보완하기 위해 최근 데이터를 실시간으로 처리합니다. 정확성과 실시간성을 동시에 달성할 수 있지만, 배치·실시간 두 시스템을 병행 운영해야 하는 복잡성이 단점입니다.

**카파 아키텍처(Kappa Architecture)**는 람다 아키텍처의 복잡성을 해결하기 위해 스트리밍 처리 단일 경로로 통합한 아키텍처입니다. 모든 데이터를 Kafka와 같은 스트리밍 플랫폼을 통해 처리하며, 재처리(Reprocessing)가 필요한 경우에도 동일한 스트리밍 파이프라인을 재활용합니다. 시스템의 단순성·유지보수 용이성이 장점이지만, 매우 복잡한 배치 연산에는 적합하지 않을 수 있습니다.

두 아키텍처의 선택 기준은 데이터 처리 요건에 따라 달라집니다. 과거 전체 이력에 대한 복잡한 배치 분석이 필수적인 경우 람다가 유리하며, 단순하고 실시간성이 중요한 경우 카파가 더 적합합니다. 최근에는 Apache Flink·Spark Structured Streaming의 발전으로 스트리밍으로도 배치 수준의 정확성 달성이 가능해지면서 카파 아키텍처의 채택이 늘어나는 추세입니다.

관련 기출문제​

데이터 레이크​

개요​

**데이터 레이크(Data Lake)**는 정형·반정형·비정형 데이터를 원본 형태 그대로 중앙 저장소에 보관하여, 필요에 따라 다양한 분석 목적으로 활용하는 데이터 저장 아키텍처입니다. 데이터 웨어하우스(DW)가 사전에 정의된 스키마로 정형화된 데이터를 저장하는 Schema-on-Write 방식인 반면, 데이터 레이크는 적재 시점에 스키마를 정의하지 않는 Schema-on-Read 방식을 채택합니다. 이를 통해 탐색적 분석과 다양한 워크로드를 유연하게 지원합니다.

**로지컬 데이터웨어하우스(LDW, Logical Data Warehouse)**는 전통적 데이터 웨어하우스와 Hadoop 기반 빅데이터 플랫폼을 추상화·통합한 정보 분석 아키텍처입니다. LDW는 데이터를 물리적으로 이동시키지 않고 논리적 레이어를 통해 다양한 소스에서 통합된 뷰를 제공하며, 구성 요소로는 데이터 가상화 레이어, 메타데이터 관리, 통합 쿼리 엔진이 있습니다. 데이터 레이크 환경에서 체계적인 메타데이터 관리가 부족하면 데이터 늪(Data Swamp)으로 전락할 위험이 있습니다.

**데이터 늪(Data Swamp)**은 데이터 레이크가 메타데이터·데이터 카탈로그·품질 관리가 부재하여 데이터를 찾거나 신뢰할 수 없는 상태로 방치되는 현상을 말합니다. 예방을 위해서는 데이터 카탈로그 구축, 데이터 리니지(Lineage) 추적, 접근 권한 관리, 데이터 품질 모니터링 등의 데이터 거버넌스 체계 병행이 필수적입니다.

  • 137회 1교시 - 데이터 늪(Data Swamp)

프로세스 마이닝​

개요​

**프로세스 마이닝(Process Mining)**은 정보시스템의 이벤트 로그(Event Log)를 분석하여 실제 업무 프로세스를 발견·적합성 검사·개선하는 기법입니다. 기존의 프로세스 관리가 주관적 인터뷰나 문서 기반이었다면, 프로세스 마이닝은 실제 시스템 데이터에서 객관적인 프로세스 모델을 자동으로 도출합니다. 주요 기술 요소로는 이벤트 로그 수집, 프로세스 발견(Process Discovery), 적합성 검사(Conformance Checking), 개선 분석(Enhancement)이 있습니다.

프로세스 마이닝의 연구 분야는 세 가지로 구분됩니다. 프로세스 발견은 이벤트 로그에서 프로세스 모델(페트리 넷, BPMN)을 자동 생성하는 것이며, 적합성 검사는 발견된 모델과 사전에 정의된 표준 모델 간의 차이를 측정합니다. 개선 분석은 병목 구간 탐지, 처리 시간 분석, 자원 활용도 측정을 통해 프로세스 최적화 방향을 도출합니다. ERP·BPM 시스템과의 연계를 통해 제조·금융·의료 분야에서 활발히 적용되고 있습니다.

프로세스 마이닝의 필요성은 디지털 전환 가속화로 더욱 부각됩니다. 복잡한 멀티시스템 환경에서 프로세스 흐름을 가시화하고 컴플라이언스 준수 여부를 실시간으로 확인할 수 있습니다. 빅데이터 감리 실무에서도 지능정보기술 감리 가이드라인(2023)에 따라 빅데이터 정보화사업의 분석·설계 단계에서 프로세스 마이닝 적용 타당성이 점검 항목으로 포함됩니다.

LOD​

개요​

**LOD(Linked Open Data)**는 웹 상의 데이터를 URI로 식별하고, RDF(Resource Description Framework) 트리플(Subject-Predicate-Object) 형태로 표현하여 서로 다른 데이터셋을 상호 연결하는 기술입니다. Tim Berners-Lee의 시맨틱 웹 비전을 구현하는 핵심 기술로, 개방형 표준(URI·HTTP·RDF·SPARQL·OWL)을 활용합니다. 공공기관·도서관·위키피디아·DBpedia 등 다양한 도메인에서 LOD를 공개하여 글로벌 지식 그래프를 형성하고 있습니다.

LOD의 핵심 기술 요소는 네 가지입니다. URI는 자원을 고유하게 식별하며, RDF는 트리플 구조로 데이터 간의 의미 있는 관계를 표현합니다. SPARQL은 RDF 데이터를 질의하는 표준 쿼리 언어이며, **온톨로지(OWL/SKOS)**는 도메인 지식의 개념과 관계를 형식적으로 정의합니다. 오픈데이터 플랫폼에서 LOD를 구현하면 부서 간·기관 간 데이터 연계가 표준화된 방식으로 가능해집니다.

LOD와 관련된 데이터 등급(5성급 모델)은 팀 버너스리가 제안한 오픈 데이터 품질 척도입니다. 1성급은 어떤 형식이든 웹에 공개된 데이터, 2성급은 구조화된 기계 가독 데이터(예: Excel), 3성급은 비독점 개방 형식(예: CSV), 4성급은 URI를 사용한 자원 식별, 5성급은 다른 LOD와 연결된 데이터입니다. 오픈데이터 생태계에서 5성급 달성은 데이터의 재활용 가치를 극대화하는 목표입니다.

데이터 사이언스​

개요​

**데이터 사이언스(Data Science)**는 통계학·컴퓨터 공학·수학·도메인 전문 지식을 융합하여 데이터에서 의미 있는 인사이트를 도출하는 학문 분야입니다. 데이터 사이언티스트에게 요구되는 역량은 Hard Skill(통계·머신러닝·프로그래밍·데이터 엔지니어링)과 Soft Skill(비즈니스 이해·커뮤니케이션·문제 정의 능력·협업)로 구분됩니다. 분석 유형은 기술 분석(Descriptive)·진단 분석(Diagnostic)·예측 분석(Predictive)·처방 분석(Prescriptive)의 4단계 성숙도 모델로 이해할 수 있습니다.

데이터 사이언스에서 **상관관계(Correlation)**와 **인과관계(Causation)**의 구분은 매우 중요합니다. 상관관계는 두 변수 간의 통계적 연관성을 나타내지만, 인과관계는 한 변수가 다른 변수를 직접 유발하는 관계를 의미합니다. 상관관계만으로 정책 결정을 내릴 경우 잘못된 결론에 도달할 수 있으며, 인과관계 파악을 위해서는 통제 실험(A/B 테스팅), 이중차분법(Difference-in-Differences), 도구변수법 등 인과추론 방법론이 필요합니다.

앙상블 모형은 여러 개의 약한 학습기(Weak Learner)를 결합하여 강한 예측 모델을 만드는 방법론입니다. **배깅(Bagging)**은 Bootstrap Aggregating의 약자로, 데이터를 복원 추출하여 다수의 독립적 모델을 학습하고 투표·평균으로 결합합니다(랜덤 포레스트가 대표 예). **부스팅(Boosting)**은 이전 모델이 잘못 예측한 샘플에 가중치를 높여 순차적으로 모델을 개선하는 방식으로, XGBoost·LightGBM이 대표적입니다. A/B 테스팅은 두 버전의 특정 요소를 비교 실험하여 더 나은 결과를 도출하는 데이터 기반 의사결정 방법론입니다.
