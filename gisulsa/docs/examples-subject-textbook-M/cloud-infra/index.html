클라우드 서비스 모델(IaaS/PaaS/SaaS)​

개요​

클라우드 컴퓨팅 서비스 모델은 제공되는 자원의 추상화 수준에 따라 세 가지로 구분됩니다. **IaaS(Infrastructure as a Service)**는 서버·스토리지·네트워크 등 인프라를 가상화하여 제공하며, 사용자가 OS 이상의 계층을 직접 관리합니다. **PaaS(Platform as a Service)**는 애플리케이션 개발·실행 환경(런타임·미들웨어·데이터베이스)을 제공하여 개발자가 인프라 관리 부담 없이 코드 작성에 집중할 수 있습니다. **SaaS(Software as a Service)**는 완성된 애플리케이션을 웹을 통해 제공하며, 사용자는 소프트웨어 이용만 담당합니다.

배치 모델(Deployment Model)은 퍼블릭 클라우드, 프라이빗 클라우드, 하이브리드 클라우드, 커뮤니티 클라우드 네 가지로 구분됩니다. 퍼블릭은 공개된 인터넷을 통해 불특정 다수에게 제공하는 방식으로 비용 효율이 높고, 프라이빗은 단일 조직 전용으로 보안성이 높습니다. 하이브리드는 두 방식을 결합한 형태로, 민감 데이터는 프라이빗에, 부하 분산이 필요한 서비스는 퍼블릭에 배치하는 클라우드 버스팅(Cloud Bursting) 전략을 활용합니다.

공공기관에서 클라우드를 전환할 때에는 전환 대상 선정 기준, 클라우드 아웃소싱 요구사항, 서비스 수준 협약(SLA) 체계 수립이 핵심 과제입니다. 공공부문 SaaS 이용 가이드라인(2024)에 따라 클라우드 서비스 위험 관리 원칙, 보안대책 수립, 보안성 검토, SLA 협약 절차가 체계화되어 있습니다. 서비스 전환 후에도 단계별 감리를 통한 품질 검증이 의무화됩니다.

가상화(하이퍼바이저/VM/컨테이너)​

개요​

**가상화(Virtualization)**는 물리적 하드웨어 자원을 추상화하여 여러 개의 논리적 자원으로 분할하거나 통합하는 기술입니다. **하이퍼바이저(Hypervisor)**는 물리 서버 위에서 여러 가상 머신(VM)을 생성·관리하는 소프트웨어 계층으로, 하드웨어에 직접 설치되는 Type 1(베어메탈, VMware ESXi·Hyper-V)과 호스트 OS 위에 설치되는 Type 2(VMware Workstation·VirtualBox)로 구분됩니다. 가상 머신은 완전한 OS를 포함하여 강한 격리성을 제공하지만 오버헤드가 크다는 단점이 있습니다.

**컨테이너(Container)**는 호스트 OS의 커널을 공유하면서 프로세스 격리 수준의 가상화를 제공하는 경량화 기술입니다. VM 대비 기동 속도가 빠르고, 이미지 크기가 작으며, 자원 오버헤드가 낮습니다. 반면 커널 공유로 인해 VM보다 격리 수준이 낮고 호스트 OS 의존성이 있습니다. **VDI(Virtual Desktop Infrastructure)**는 데스크톱 환경을 서버에서 가상화하여 중앙 관리하는 방식으로, 계층별 구성 요소로는 하이퍼바이저·연결 브로커·프로토콜 게이트웨이·엔드포인트 클라이언트가 있습니다.

네트워크 가상화 기술로는 VLAN(논리적 네트워크 분리), VPN(암호화된 사설 터널), NFV(네트워크 기능을 소프트웨어로 가상화)가 있습니다. 스토리지 연결 방식으로는 DAS(Direct Attached Storage, 서버에 직접 연결), NAS(Network Attached Storage, 파일 기반 공유), SAN(Storage Area Network, 블록 기반 고성능 공유)으로 구분됩니다. **코드형 인프라스트럭처(IaC, Infrastructure as Code)**는 인프라 구성을 코드로 정의하여 버전 관리·자동화·반복 배포를 가능하게 하는 DevOps 핵심 실천 방법입니다.

도커/쿠버네티스​

개요​

**도커(Docker)**는 애플리케이션과 그 실행 환경을 이미지로 패키징하여 어디서나 일관되게 실행할 수 있도록 하는 컨테이너 플랫폼입니다. Dockerfile로 이미지를 정의하고, Docker Hub를 통해 이미지를 공유하며, docker-compose를 통해 다중 컨테이너 애플리케이션을 정의·실행합니다. **도커 스웜(Docker Swarm)**은 도커의 기본 내장 컨테이너 오케스트레이션 도구로, 여러 도커 호스트를 클러스터로 묶어 컨테이너를 분산 배포·관리합니다.

**쿠버네티스(Kubernetes, K8s)**는 컨테이너화된 애플리케이션의 배포·확장·자동화를 관리하는 오픈소스 오케스트레이션 플랫폼입니다. 주요 컴포넌트는 Control Plane(API Server·etcd·Scheduler·Controller Manager)과 Worker Node(kubelet·kube-proxy·컨테이너 런타임)으로 구성됩니다. 핵심 오브젝트로는 Pod(최소 배포 단위), Deployment(선언적 배포 관리), Service(네트워크 엔드포인트 추상화), ConfigMap/Secret(설정 관리)이 있습니다.

**HPA(Horizontal Pod Autoscaler)**는 CPU·메모리 사용률 또는 커스텀 메트릭 기반으로 Pod 수를 자동으로 조절하는 쿠버네티스 기능입니다. HPA는 Scale-Out(Pod 수 증가) 방식으로 부하를 분산하며, VPA(Vertical Pod Autoscaler)는 Pod의 자원 요청량(CPU·메모리)을 자동 조정합니다. 클라우드 네이티브 환경으로의 전환 프로젝트에서 TA(Technical Architect)와 AA(Application Architect)의 협업은 인프라 설계와 애플리케이션 아키텍처 정합성 확보를 위해 필수적입니다.

오토스케일링​

개요​

**오토스케일링(Auto Scaling)**은 서비스 부하의 변화에 따라 컴퓨팅 자원을 자동으로 증감하여 성능과 비용 효율성을 동시에 달성하는 클라우드 기능입니다. **Scale-Up(수직 확장)**은 기존 인스턴스의 CPU·메모리 등 사양을 높이는 방식으로, 단일 노드 성능 향상이 필요할 때 적합하지만 하드웨어 한계와 재기동 다운타임이 발생합니다. **Scale-Out(수평 확장)**은 동일 사양 인스턴스를 추가하는 방식으로, 로드밸런서와 결합하여 이론상 무한한 확장이 가능하고 고가용성 아키텍처 구현에 유리합니다.

오토스케일링 트리거 방식은 두 가지로 구분됩니다. 스케줄 기반 Auto Scale은 사전에 정의된 일정(예: 매주 월요일 오전 9시)에 따라 자원을 증감하며, 트래픽 패턴이 예측 가능한 서비스에 적합합니다. 부하 기반 Auto Scale은 CPU 사용률·네트워크 트래픽·사용자 정의 메트릭 등 실시간 지표가 임계값을 초과하거나 하회할 때 자원을 조정하며, 예측 불가능한 트래픽 스파이크 대응에 효과적입니다.

쿠버네티스 환경에서의 오토스케일링은 HPA(Pod 수 조절), VPA(Pod 자원 조절), CA(Cluster Autoscaler, 노드 수 조절)의 세 계층이 상호 보완적으로 작동합니다. 다중 지역 동시 가동(Multi-Region Active-Active) 재해복구 시스템에서는 각 리전에 독립적인 오토스케일링 정책을 적용하면서도 글로벌 트래픽 분산 전략과 연계가 필요합니다.

HCI​

개요​

**HCI(Hyper Converged Infrastructure, 하이퍼 컨버지드 인프라)**는 서버·스토리지·네트워킹·가상화 소프트웨어를 단일 어플라이언스 또는 소프트웨어 정의 플랫폼으로 통합한 인프라 아키텍처입니다. 기존의 스리-티어(3-Tier, 별도 서버·스토리지·네트워크 장비 구성) 방식 대비 배포 단순화, 확장 용이성(노드 추가만으로 확장), 운영 복잡성 감소, TCO 절감이 주요 장점입니다. 소프트웨어 정의 스토리지(SDS)가 핵심 구성 요소로, Nutanix·VMware vSAN·Microsoft S2D가 대표적 제품입니다.

HCI의 유형은 크게 어플라이언스형과 소프트웨어 정의형으로 구분됩니다. 어플라이언스형은 하드웨어와 소프트웨어가 사전 통합된 형태로 빠른 구축과 지원의 용이성이 장점이며, 소프트웨어 정의형은 기존 범용 하드웨어 위에 HCI 소프트웨어 스택을 구성하는 방식으로 하드웨어 유연성이 높습니다. 클라우드 기반 HCI는 퍼블릭 클라우드의 확장성과 프라이빗 HCI의 제어권을 결합한 하이브리드 형태로 진화하고 있습니다.

HCI 도입 시 고려사항으로는 워크로드 특성 분석(I/O 집약형 vs. 컴퓨팅 집약형), 마이그레이션 계획, 기존 인프라와의 통합 전략, 벤더 종속(Vendor Lock-in) 위험 관리 등이 있습니다. VDI(가상 데스크톱)·ERP·데이터베이스 통합 환경에서 HCI의 활용 효과가 높으며, AI/ML 워크로드를 위한 GPU 지원 HCI 노드 구성도 확대되고 있습니다.

관련 기출문제​

클라우드 보안 인증(CSAP)​

개요​

**CSAP(Cloud Security Assurance Program, 클라우드 서비스 보안인증)**는 공공기관이 안전하게 민간 클라우드 서비스를 이용할 수 있도록 한국인터넷진흥원(KISA)이 보안 요구사항 충족 여부를 인증하는 제도입니다. 클라우드 컴퓨팅 발전 및 이용자 보호에 관한 법률에 근거하며, IaaS·SaaS·DaaS 서비스 유형에 따라 인증 기준이 차별화됩니다. 인증 등급은 상(국가정보원 보안적합성 검증 병행)·중·하로 구분되어 데이터 민감도에 따른 차등 적용이 가능합니다.

CSAP 인증 절차는 신청 및 서류 검토 → 보안 컨설팅(선택) → 인증 심사(문서 심사·현장 심사) → 인증 위원회 심의 → 인증서 발급 → 사후 관리 단계로 진행됩니다. 평가 기준은 관리적·물리적·기술적 보호조치를 포괄하며, 주요 항목으로는 접근 통제, 암호화, 가용성 보장, 침해사고 대응, 데이터 보호 등이 있습니다. 공공기관은 행정·공공기관 클라우드 서비스 이용 기준에 따라 CSAP 인증 서비스를 우선 활용해야 합니다.

클라우드 보안과 관련하여 ISO/IEC 27017(클라우드 서비스 정보보호 통제)은 ISO/IEC 27001의 클라우드 특화 확장 표준으로, CSP(Cloud Service Provider)와 클라우드 고객 양측의 보안 책임 분담(Shared Responsibility Model)을 명확히 규정합니다. 금융 클라우드 SLA 가이드는 서비스 연속성, 데이터 이동성, 감사 권한, 준거법·관할권 등 금융 규제 특수성을 반영한 추가 요구사항을 제시합니다.

멀티클라우드​

개요​

**멀티클라우드(Multi-Cloud)**는 두 개 이상의 클라우드 서비스 제공자(AWS·Azure·GCP 등)의 서비스를 동시에 활용하는 전략입니다. 벤더 종속(Vendor Lock-in) 위험 분산, 서비스별 최적 CSP 선택(Best-of-Breed), 규제 요구사항 충족, 지역별 가용성 확보가 주요 도입 목적입니다. 멀티클라우드 환경에서는 클라우드 간 일관된 보안 정책 적용, 비용 가시성 확보, 데이터 거버넌스 통합이 핵심 도전 과제입니다.

멀티클라우드의 시스템 요구사항으로는 통합 오케스트레이션 레이어(쿠버네티스 기반 멀티클러스터 관리), 통합 모니터링·관찰가능성 플랫폼, IAM(Identity and Access Management) 연합, 네트워크 인터커넥트(VPC Peering·전용선) 등이 있습니다. 주요 기술로는 서비스 메시(Istio·Linkerd), 클라우드 관리 플랫폼(CMP), 컨테이너 기반 추상화 레이어(Anthos·Azure Arc)가 활용됩니다.

**클라우드 관리 플랫폼(CMP, Cloud Management Platform)**은 멀티클라우드 환경에서 자원 프로비저닝·비용 관리·성능 모니터링·정책 적용을 통합적으로 수행하는 플랫폼입니다. 필수 기능으로는 셀프서비스 프로비저닝, 비용 최적화(FinOps), 정책 기반 거버넌스, 자동화 워크플로가 있으며, 선정 기준으로는 지원 클라우드 범위, 통합 용이성, 확장성, 보안 기능이 고려됩니다.

관련 기출문제​

  • 131회 3교시 - 클라우드 관리 플랫폼의 정의, 필수 기능, 선정 기준
  • 138회 3교시 - 멀티클라우드 개념·필요성, 시스템 요구사항, 주요 기술

서버리스​

개요​

**서버리스 컴퓨팅(Serverless Computing)**은 개발자가 서버 인프라 관리 없이 함수(Function) 단위의 코드를 작성하고 이벤트 트리거에 의해 실행되는 클라우드 실행 모델입니다. **FaaS(Function as a Service)**가 서버리스의 대표 형태로, AWS Lambda·Azure Functions·Google Cloud Functions가 대표적 서비스입니다. 실행 시에만 과금되는 종량제 모델로 비용 효율이 높고, 자동 확장·고가용성이 플랫폼에서 기본 제공됩니다.

**BaaS(Backend as a Service)**는 모바일·웹 애플리케이션 개발에 필요한 백엔드 기능(인증·데이터베이스·푸시 알림·파일 저장)을 API 형태로 제공하는 서비스입니다. FaaS가 커스텀 비즈니스 로직 실행에 집중하는 반면, BaaS는 공통 백엔드 기능의 즉시 활용을 지원합니다. 두 서비스를 결합한 서버리스 아키텍처는 이벤트 드리븐(Event-Driven) 마이크로서비스 구현에 적합하며, 콜드 스타트(Cold Start) 지연, 실행 시간 제한, 상태 관리의 어려움이 단점으로 꼽힙니다.

서버리스 컴퓨팅의 활용 패턴으로는 API 게이트웨이 백엔드, 실시간 스트림 처리, 예약 작업(Cron Job), 파일 업로드 처리, IoT 디바이스 이벤트 처리 등이 있습니다. 서버리스와 컨테이너(Knative 등)를 결합한 하이브리드 접근법도 부상하고 있으며, 엣지 서버리스(Cloudflare Workers 등)는 네트워크 엣지에서 함수를 실행하여 지연시간을 최소화하는 방향으로 발전하고 있습니다.

관련 기출문제​

  • 121회 1교시 - BaaS와 FaaS
  • 136회 1교시 - 서버리스 컴퓨팅(Serverless Computing)

엣지 컴퓨팅​

개요​

**엣지 컴퓨팅(Edge Computing)**은 데이터 생성 지점(IoT 디바이스·기지국·게이트웨이)에 가까운 위치에서 데이터를 처리하여 클라우드 전송 전에 실시간 연산을 수행하는 분산 컴퓨팅 패러다임입니다. 중앙 클라우드 대비 초저지연(Ultra-Low Latency), 대역폭 절감, 오프라인 동작 가능성, 데이터 프라이버시 보호 등의 이점을 제공합니다. 자율주행 자동차·스마트 팩토리·실시간 의료 모니터링·AR/VR 등 지연 시간에 민감한 응용 분야에 핵심 인프라입니다.

**모바일 엣지 컴퓨팅(MEC, Mobile Edge Computing)**은 이동통신망(5G)의 기지국 근방에 컴퓨팅 자원을 배치하여 모바일 서비스에 클라우드 수준의 컴퓨팅을 제공하는 기술입니다. 제품 분류 관점의 기반 기술로는 프로세서(ARM·FPGA·GPU 기반 AI 가속기), 메모리(고대역폭 LPDDR), 플랫폼(컨테이너 기반 엣지 런타임), 네트워크(5G·Wi-Fi 6·TSN)가 있습니다.

엣지 컴퓨팅의 공급망 관점 기술 범위는 스마트 팩토리(PLC 데이터 실시간 분석·예지보전), 자율주행 자동차(V2X 통신·실시간 장애물 인식), 실시간 관리시스템(도시 인프라 모니터링), 리모트 시스템(원격지 인프라 무인 관리)에 걸쳐 있습니다. 엣지와 클라우드를 연속적 스펙트럼으로 관리하는 클라우드-엣지 연속체(Cloud-Edge Continuum) 아키텍처가 차세대 인프라 설계 방향으로 부상하고 있습니다.

데이터센터​

개요​

**데이터센터(Data Center)**는 서버·스토리지·네트워크 장비를 집중 수용하고, 전원·냉각·보안·통신 인프라를 갖춘 시설입니다. 가용성 등급은 TIA-942 기준 Tier I~Tier IV로 구분되며, Tier IV는 연간 다운타임 26.3분 이하의 최고 수준 이중화 구성을 의미합니다. AI 서비스 확산에 따른 GPU 클러스터 도입으로 전력 밀도 급증, 냉각 혁신(액침냉각·후면 도어 열교환기), 저지연 네트워크(InfiniBand·100GbE RoCE)가 주요 설계 과제로 부상하고 있습니다.

대규모 AI 서비스를 위한 데이터센터 구축에는 저지연 기술(RDMA 기반 고속 인터커넥트, 네트워크 토폴로지 최적화)과 스케일링 확보 기술(수평 확장 가능 스토리지, 분산 파일시스템 GPFS·Lustre)이 필수입니다. **DCI(Data Center Interconnect)**는 지리적으로 분산된 데이터센터 간을 고대역폭·저지연 광네트워크로 연결하는 기술로, 재해복구(DR) 및 분산 AI 학습 클러스터 구성에 활용됩니다.

망 분리는 업무망과 인터넷망을 물리적 또는 논리적으로 분리하여 외부 위협으로부터 내부 시스템을 보호하는 보안 아키텍처입니다. 물리적 망 분리, 가상화 기반 논리적 망 분리, 망 연계 솔루션(단방향 전송 게이트웨이) 등의 구축 방안을 보안·성능·비용 세 가지 관점에서 비교하여 적용 방안을 선택합니다. 국가 망 보안체계(N2SF)는 2025년 국가정보원이 발표한 공공기관 망 보안 가이드라인으로, 기존 망 분리 정책을 기반으로 보안 수준별 차등 적용 기준을 제시합니다.

RAID​

개요​

**RAID(Redundant Array of Independent Disks)**는 여러 개의 디스크를 논리적으로 묶어 성능 향상, 용량 확대, 데이터 안정성(중복성)을 달성하는 기술입니다. **RAID 0(스트라이핑)**은 데이터를 여러 디스크에 분산 저장하여 읽기·쓰기 성능을 극대화하지만, 단일 디스크 장애 시 전체 데이터 손실 위험이 있어 중복성이 없습니다. **RAID 1(미러링)**은 두 디스크에 동일 데이터를 복제하여 높은 내고장성을 제공하지만 유효 용량이 50%로 감소합니다.

RAID 5는 스트라이핑에 분산 패리티를 추가하여 단일 디스크 장애 시 복구가 가능하며, 최소 3개 디스크가 필요합니다. 유효 용량은 (N-1)/N 수준으로 RAID 1보다 용량 효율이 높아 가장 널리 사용됩니다. RAID 6은 이중 패리티를 사용하여 동시에 2개 디스크 장애까지 허용하며, 최소 4개 디스크가 필요합니다. 대용량 디스크 환경에서 RAID 5의 리빌드 시간 동안 발생하는 추가 장애 위험에 대응하기 위해 RAID 6 채택이 증가하고 있습니다.

실무에서는 RAID 레벨을 혼합한 **중첩 RAID(Nested RAID)**를 활용하기도 합니다. RAID 10(1+0)은 미러링과 스트라이핑을 결합하여 성능과 안정성을 동시에 달성하지만 비용이 높으며, 데이터베이스 서버의 고성능 I/O 환경에 적합합니다. SSD 기반 올플래시 스토리지 도입과 SDS(Software Defined Storage) 발전으로 소프트웨어 계층에서 RAID와 유사한 데이터 보호 기능을 구현하는 방향으로 발전하고 있습니다.

관련 기출문제​

  • 120회 1교시 - RAID 0, 1, 5, 6

SDN/SDDC​

개요​

**SDN(Software-Defined Networking)**은 네트워크의 제어 평면(Control Plane)과 데이터 평면(Data Plane)을 분리하여, 소프트웨어 컨트롤러가 네트워크 전체를 중앙에서 프로그래밍 방식으로 제어하는 기술입니다. 제어 평면은 네트워크 토폴로지 파악·경로 결정을 담당하고, 데이터 평면의 스위치/라우터는 컨트롤러의 지시에 따라 패킷을 전달합니다. OpenFlow 프로토콜은 SDN 컨트롤러와 포워딩 장비 간 통신을 표준화한 남향(Southbound) 인터페이스 프로토콜입니다.

SDN의 주요 특징으로는 중앙화된 네트워크 가시성, 동적 트래픽 제어, 자동화·프로그래머빌리티, 하드웨어 독립성이 있습니다. 기존 네트워크 대비 변경 관리 속도가 향상되고, API를 통한 네트워크 자동화가 가능하여 DevOps·클라우드 환경과의 통합에 유리합니다. 단점으로는 SDN 컨트롤러의 단일 장애점(SPOF) 위험과 새로운 기술 스택에 대한 운영 인력 역량 요구가 있습니다.

**SDDC(Software-Defined Data Center)**는 서버·스토리지·네트워크 등 데이터센터의 모든 인프라 계층을 소프트웨어로 추상화·가상화·자동화하는 개념입니다. 구성 요소로는 SDN(네트워크 가상화), SDS(스토리지 가상화), SDC(컴퓨팅 가상화), 클라우드 관리 플랫폼이 있습니다. SDDC는 HCI와 밀접하게 연관되며, 인프라 전체를 코드(IaC)로 정의·관리하는 자동화 데이터센터 구현의 기반 기술입니다.
