06. 소프트웨어아키텍처

1. 아키텍처 기초​

1.1 아키텍처 개념​

1.1.1 기본 개념​

  • Software Architecture
  • Architecture Description
  • Stakeholder / Concern
  • 설계원칙(Separation of Concerns, Modularity, Loose Coupling, High Cohesion)

1.1.2 뷰와 모델​

  • 4+1 View Model
  • 아키텍처 모델 유형: 소프트웨어 아키텍처(Architecture)의 모델 유형
  • 기능의 분할과 배치: 기능의 분할과 배치 관점에서 데이터 중심형 모델, 클라이언트-서버 모델, 계층 모델 및 MVC(Model View Controller) 모델
  • ISO/IEC/IEEE 42010

1.2 아키텍트 역할​

1.2.1 아키텍트​

  • TA/AA: TA(Technical Architect)와 AA(Application Architect)의 역할 비교
  • Software Architect
  • ADR (Architecture Decision Record)

2. 아키텍처 스타일​

2.1 스타일 개요​

2.1.1 스타일과 패턴​

  • 아키텍처 스타일: 대표적인 아키텍처 스타일 3가지
  • 스타일과 디자인패턴 비교: 아키텍처 스타일과 디자인 패턴의 차이점

2.2 계층형 구조​

2.2.1 Layer 기반​

  • Layered Architecture: 계층 모델
  • N-tier Architecture
  • MVC: MVC(Model View Control) 패턴, MVC(Model View Controller) 모델
  • MVP
  • MVVM

2.3 데이터 중심 및 흐름 구조​

2.3.1 데이터 중심​

  • Repository(데이터 중심형): 데이터 중심형 모델
  • Pipe & Filter
  • Blackboard

2.4 이벤트 기반 구조​

2.4.1 Event Architecture​

  • EDA: EDA(Event Driven Architecture)의 토폴로지 구성요소
  • Mediator Topology: 중재자 토폴로지(MediatorTopology)
  • Broker Topology: 브로커 토폴로지(Broker Topology)
  • Pub/Sub
  • Event Streaming

2.5 웹 아키텍처​

2.5.1 웹 구조​

  • SPA: SPA(Single Page Web Application)
  • Service Worker: 서비스 워커(Service Worker)
  • Reverse Proxy: 리버스 프록시(Reverse Proxy), 무중단 배포를 위한 리버스 프록시와 로드밸런싱, 리버스 프록시(Reverse Proxy)의 개념, 동작원리, 설정방법
  • Load Balancing: 무중단 배포를 위한 리버스 프록시와 로드밸런싱
  • Web Syndication: 웹 신디케이션(Web Syndication)

3. 서비스 지향 아키텍처와 MSA​

3.1 서비스 아키텍처​

3.1.1 SOA와 MSA​

  • SOA
  • MSA: 마이크로서비스 아키텍처(MicroService Architecture), 모놀리스(Monolith)와 마이크로서비스(Microservice) 아키텍처의 개념 비교, MSA 개념 및 특징과 구현시 지켜야 할 원칙
  • Monolithic Architecture: 모놀리스(Monolith), 모놀리스 아키텍처(Monolith Architecture)와 MSA 비교

3.1.2 서비스 설계​

  • DDD (Domain Driven Design)
  • Bounded Context
  • Service Decomposition
  • Database per Service

3.2 서비스 통신​

3.2.1 API​

  • REST: REST API(REpresentational State Transfer Application Programming Interface), 2가지 구조(SOAP, REST)별 특징 비교
  • SOAP: SOAP의 4가지 구성요소, SOAP 및 REST 구성요소
  • Open API: 개방형 API(Open Application Programming Interface), 오픈 플랫폼의 주요기술인 Open API, 개방형 API(Open API)
  • OAS: OAS(OpenAPI Specification)
  • API Gateway: API Gateway의 역할과 필요성, 주요기능
  • Service Mesh: MSA 구현을 위한 서비스 매쉬(Service Mesh)
  • 스크래핑과 API: 스크래핑(Scraping)과 API(Application Programming Interface) 기술
  • gRPC

3.2.2 분산 데이터 패턴​

  • CQRS
  • Event Sourcing
  • Saga Pattern
  • Circuit Breaker

4. 미들웨어 및 시스템 통합​

4.1 통합 패턴​

4.1.1 Enterprise Integration​

  • EIP: EIP(Enterprise Intergration Patterns)
  • ESB
  • ETL/CDC

4.2 메시지 지향 미들웨어​

4.2.1 MOM​

  • Message Queuing: 메시지큐잉에 대한 개념과 필요성, 종류, 기능
  • Kafka
  • RabbitMQ

5. 분산 시스템 아키텍처​

5.1 분산 구조​

5.1.1 분산 모델​

  • Client-Server: 클라이언트-서버 모델
  • P2P: 하이브리드 P2P(Hybrid P2P) 방식과 퓨어 P2P(Pure P2P) 방식 비교
  • Broker
  • Master-Slave

5.1.2 분산 데이터 관리​

  • Replication: 여러 서버에 데이터를 복제하는 경우의 복제 유형
  • Partitioning
  • Distributed Transaction

6. 품질속성(Quality Attribute)​

6.1 성능​

6.1.1 Performance​

  • 성능지표: 정보시스템의 성능 요구사항 작성 시 고려해야 하는 주요 성능지표
  • 웹 성능 최적화: 웹 성능저하 요인, 프론트-엔드 관점에서의 웹 최적화 방안 6가지
  • Throughput / Response Time
  • Scalability

6.2 가용성​

6.2.1 Availability​

  • HA: HA(High Availability) 구현 방법
  • Fault Tolerance: FTS(Fault Tolerant System) 구현 방법
  • Multi-Region Active-Active: 다중지역 동시 가동방식(Multi - Region Active - Active) 재해복구시스템
  • Failover
  • Redundancy

6.3 기타 품질속성​

6.3.1 기타​

  • Modifiability
  • Security
  • Interoperability
  • Observability

7. 아키텍처 설계 및 평가​

7.1 아키텍처 설계​

7.1.1 설계 기법​

  • ADD (Attribute Driven Design)
  • Utility Tree
  • Quality Attribute Scenario

7.2 아키텍처 평가​

7.2.1 평가 방법​

  • 아키텍처 분석: 소프트웨어 아키텍처 정방향 분석과 역방향 분석
  • ATAM: ATAM(Architecutre Trade-off Analysis Method)
  • CBAM: CBAM(Cost Benefit Analysis Method)
  • SAAM
  • ARID

7.2.2 Trade-off 분석​

  • Sensitivity Point
  • Trade-off Point
  • Risk / Non-Risk
