02. 소프트웨어 아키텍처 (Software Architecture)

1. 아키텍처 기초​

1.1 아키텍처 개념​

1.1.1 기본 개념​

  • Software Architecture: 시스템의 구조와 구성요소·관계를 정의한 최상위 설계
  • Architecture Description: 아키텍처를 문서·모델로 기술한 산출물
  • Architecture View: 특정 관심사 관점에서 표현한 아키텍처의 한 측면
  • Viewpoint: 뷰를 작성하는 규칙·관점을 정의한 틀
  • Stakeholder: 시스템에 이해관계를 가진 관련자
  • Concern: 이해관계자가 중요하게 여기는 관심사
  • Architecture Driver: 아키텍처 결정을 좌우하는 핵심 요인(요구·제약)

1.1.2 설계원칙​

  • Separation of Concerns: 관심사를 분리해 복잡도를 낮추는 원칙
  • Modularity: 시스템을 독립적 모듈로 나누는 모듈화
  • Encapsulation: 내부 구현을 감추고 인터페이스로 접근하는 캡슐화
  • Abstraction: 핵심만 드러내고 세부를 숨기는 추상화
  • Loose Coupling: 구성요소 간 의존을 낮추는 느슨한 결합
  • High Cohesion: 관련 기능을 한데 모으는 높은 응집도
  • Information Hiding: 변경 가능성이 큰 정보를 숨기는 정보 은닉

1.1.3 품질속성 개념​

  • Quality Attribute: 성능·보안 등 시스템이 갖춰야 할 품질 특성
  • Utility Tree: 품질속성을 우선순위로 구조화한 트리
  • Quality Scenario: 품질속성을 자극-반응 형태로 구체화한 시나리오

1.2 아키텍트 역할​

1.2.1 아키텍트​

  • Software Architect: 시스템 구조와 기술 결정을 책임지는 아키텍트
  • Solution Architect: 특정 솔루션의 기술 설계를 담당하는 아키텍트
  • Enterprise Architect: 조직 전체의 IT 아키텍처를 총괄하는 아키텍트

1.2.2 아키텍처 산출물​

  • SAD: 아키텍처 설계를 종합 기술한 소프트웨어 아키텍처 문서
  • ADR (Architecture Decision Record): 주요 아키텍처 결정과 근거를 기록한 문서
  • Architecture Blueprint: 아키텍처 전체 구조를 나타낸 청사진

2. 아키텍처 스타일​

2.1 계층형 구조​

2.1.1 Layer 기반​

  • Layered Architecture: 기능을 계층으로 분리한 계층형 아키텍처
  • N-tier Architecture: 물리·논리적으로 다층으로 분리한 구조
  • MVC: 모델-뷰-컨트롤러로 역할을 분리한 패턴
  • MVP: 모델-뷰-프리젠터로 분리한 UI 패턴
  • MVVM: 모델-뷰-뷰모델로 데이터 바인딩을 활용한 패턴

2.2 데이터 흐름 구조​

2.2.1 Pipe 기반​

  • Pipe & Filter: 필터를 파이프로 연결해 데이터를 처리하는 구조
  • Batch Sequential: 단계별로 일괄 처리해 순차 전달하는 구조
  • Data Flow Architecture: 데이터 흐름을 중심으로 구성한 아키텍처

2.3 이벤트 기반 구조​

2.3.1 Event Architecture​

  • Event Driven Architecture (EDA): 이벤트 발생·소비로 동작하는 아키텍처
  • Pub/Sub: 발행자와 구독자를 분리한 메시징 방식
  • Event Broker: 이벤트를 중계·전달하는 중개자
  • Event Streaming: 이벤트를 실시간 스트림으로 처리하는 방식

2.4 서비스 기반 구조​

2.4.1 Service Architecture​

  • SOA: 재사용 가능한 서비스 단위로 구성한 서비스 지향 아키텍처
  • MSA: 작고 독립적인 서비스로 구성한 마이크로서비스 아키텍처
  • REST: HTTP 자원 기반의 표준화된 통신 방식
  • gRPC: 프로토콜 버퍼 기반의 고성능 원격 호출 방식

2.5 객체 및 컴포넌트 기반​

2.5.1 Component​

  • Component-Based Architecture: 재사용 컴포넌트를 조립한 아키텍처
  • Object-Oriented Architecture: 객체와 협력을 기반으로 구성한 아키텍처
  • Plug-in Architecture: 확장을 플러그인으로 추가하는 구조
  • Microkernel: 최소 핵심과 확장 모듈로 구성한 구조

2.6 분산 구조​

2.6.1 Distributed​

  • Broker: 분산 컴포넌트 간 요청을 중계하는 구조
  • Peer-to-Peer: 노드들이 대등하게 통신하는 P2P 구조
  • Client-Server: 요청-응답으로 나뉜 클라이언트-서버 구조
  • Master-Slave: 주 노드가 작업을 분배·통제하는 구조
  • Space-Based Architecture: 공유 공간 기반으로 확장성을 확보하는 구조

3. 마이크로서비스 아키텍처(MSA)​

3.1 서비스 설계​

3.1.1 서비스 분리​

  • Bounded Context: 도메인 모델의 경계를 명확히 구분한 영역
  • Domain Driven Design (DDD): 도메인 중심으로 설계하는 방법론
  • Service Decomposition: 시스템을 서비스 단위로 분해하는 활동
  • Database per Service: 서비스마다 독립 DB를 두는 원칙

3.2 서비스 통신​

3.2.1 API​

  • REST API: HTTP 자원 기반의 표준 API 방식
  • API Gateway: 클라이언트 요청을 중앙에서 라우팅·관리하는 게이트웨이
  • Service Mesh: 서비스 간 통신을 인프라 계층에서 제어하는 메시
  • Sidecar: 애플리케이션 옆에 배치해 공통 기능을 담당하는 패턴
  • Envoy: 서비스 메시에 널리 쓰이는 프록시 서버

3.2.2 비동기 통신​

  • Message Queue: 메시지를 큐로 비동기 전달하는 방식
  • Kafka: 대용량 이벤트 스트리밍 플랫폼
  • RabbitMQ: 메시지 브로커 기반의 큐 시스템
  • Event Bus: 이벤트를 여러 구독자에 전달하는 통로

3.3 데이터 관리​

3.3.1 분산 데이터​

  • CQRS: 명령과 조회 모델을 분리하는 패턴
  • Event Sourcing: 상태 대신 이벤트 이력으로 상태를 관리하는 방식
  • Saga Pattern: 분산 트랜잭션을 보상 처리로 관리하는 패턴
  • Distributed Transaction: 여러 서비스에 걸친 분산 트랜잭션
  • Outbox Pattern: DB와 메시지 발행의 일관성을 보장하는 패턴

3.4 운영​

3.4.1 운영기술​

  • Service Discovery: 서비스 위치를 동적으로 찾는 메커니즘
  • Circuit Breaker: 장애 전파를 차단하는 회로 차단기 패턴
  • Bulkhead: 자원을 격리해 장애 확산을 막는 패턴
  • Retry: 실패한 요청을 재시도하는 기법
  • Failover: 장애 시 예비 시스템으로 전환하는 기법
  • Health Check: 서비스 상태를 주기적으로 점검하는 기능
  • Blue-Green Deployment: 두 환경을 전환해 무중단 배포하는 방식
  • Canary Deployment: 일부에만 먼저 배포해 위험을 줄이는 방식

4. 클라우드 네이티브 아키텍처​

4.1 컨테이너​

4.1.1 Container​

  • Docker: 애플리케이션을 컨테이너로 패키징·실행하는 플랫폼
  • OCI: 컨테이너 이미지·런타임의 개방형 표준
  • Image: 실행에 필요한 요소를 담은 컨테이너 이미지
  • Registry: 컨테이너 이미지를 저장·배포하는 저장소

4.2 오케스트레이션​

4.2.1 Kubernetes​

  • Pod: 컨테이너를 묶은 쿠버네티스 최소 배포 단위
  • ReplicaSet: 파드 복제본 수를 유지하는 컨트롤러
  • Deployment: 파드 배포·업데이트를 선언적으로 관리하는 객체
  • Service: 파드 집합에 대한 안정적 접근을 제공하는 추상화
  • Namespace: 클러스터 자원을 논리적으로 분리하는 단위
  • Ingress: 외부 트래픽을 서비스로 라우팅하는 진입점

4.3 Serverless​

4.3.1 Serverless​

  • FaaS: 함수 단위로 실행하는 서버리스 컴퓨팅
  • BaaS: 백엔드 기능을 서비스로 제공하는 방식
  • Function: 이벤트에 반응해 실행되는 서버리스 함수

4.4 Infrastructure​

4.4.1 IaC​

  • Terraform: 코드로 인프라를 프로비저닝하는 IaC 도구
  • Ansible: 구성 관리·자동화를 수행하는 도구
  • Helm: 쿠버네티스 애플리케이션을 패키징·배포하는 도구
  • ArgoCD: GitOps 기반의 쿠버네티스 배포 도구

5. 품질속성(Quality Attribute)​

5.1 성능​

5.1.1 Performance​

  • Throughput: 단위 시간당 처리량
  • Response Time: 요청에 대한 전체 응답 시간
  • Latency: 요청과 응답 사이의 지연 시간
  • Scalability: 부하 증가에 대응하는 확장성

5.2 가용성​

5.2.1 Availability​

  • HA: 장애에도 서비스를 지속하는 고가용성
  • Fault Tolerance: 결함이 있어도 정상 동작하는 내결함성
  • Redundancy: 예비 자원을 두는 이중화
  • Disaster Recovery: 재해 시 시스템을 복구하는 체계

5.3 변경용이성​

5.3.1 Maintainability​

  • Modifiability: 변경을 쉽게 수용하는 수정 용이성
  • Extensibility: 기능을 쉽게 추가하는 확장 용이성
  • Portability: 다른 환경으로 이식하는 이식성
  • Reusability: 구성요소를 재활용하는 재사용성

5.4 보안​

5.4.1 Security​

  • Authentication: 사용자 신원을 확인하는 인증
  • Authorization: 접근 권한을 부여하는 인가
  • Confidentiality: 정보 노출을 막는 기밀성
  • Integrity: 정보 위·변조를 막는 무결성
  • Non-repudiation: 행위를 부인하지 못하게 하는 부인방지

5.5 기타 품질속성​

5.5.1 기타​

  • Reliability: 오류 없이 동작하는 신뢰성
  • Testability: 테스트하기 쉬운 정도인 시험 용이성
  • Interoperability: 다른 시스템과 연동하는 상호운용성
  • Usability: 사용하기 편한 정도인 사용성
  • Observability: 내부 상태를 관측할 수 있는 관측성

6. 아키텍처 설계​

6.1 설계기법​

6.1.1 설계​

  • Attribute Driven Design (ADD): 품질속성을 기반으로 설계하는 기법
  • Domain Driven Design (DDD): 도메인 중심으로 설계하는 방법론
  • Tactical Design: 엔티티·애그리거트 등 구현 수준의 전술적 설계
  • Strategic Design: 경계·컨텍스트를 다루는 전략적 설계

6.2 설계원칙​

6.2.1 SOLID 기반​

  • SOLID: 객체지향 설계의 5가지 핵심 원칙
  • DRY: 중복을 제거하는 원칙
  • KISS: 단순하게 유지하는 원칙
  • YAGNI: 필요할 때까지 만들지 않는 원칙

6.3 설계패턴​

6.3.1 Enterprise Pattern​

  • Repository: 데이터 접근을 추상화하는 패턴
  • Unit of Work: 트랜잭션 단위로 변경을 묶어 관리하는 패턴
  • Dependency Injection: 의존성을 외부에서 주입하는 패턴
  • CQRS: 명령과 조회 모델을 분리하는 패턴
  • Event Sourcing: 이벤트 이력으로 상태를 관리하는 방식

7. 아키텍처 평가​

7.1 평가방법​

7.1.1 정성평가​

  • ATAM: 품질속성 기반의 아키텍처 트레이드오프 평가법
  • SAAM: 시나리오 기반의 아키텍처 분석법
  • CBAM: 비용·편익을 고려한 아키텍처 평가법
  • ARID: 초기 설계를 능동적 검토로 평가하는 방법

7.2 Trade-off 분석​

7.2.1 의사결정​

  • Utility Tree: 품질속성을 우선순위로 구조화한 트리
  • Risk Analysis: 아키텍처 위험을 식별·분석하는 활동
  • Sensitivity Point: 품질에 크게 영향을 주는 민감 지점
  • Trade-off Point: 여러 품질이 상충하는 절충 지점

8. 아키텍처 거버넌스​

8.1 관리​

8.1.1 Governance​

  • Architecture Governance: 아키텍처 결정·준수를 통제하는 거버넌스
  • Architecture Review Board: 아키텍처를 심의하는 검토 위원회
  • Architecture Compliance: 아키텍처 표준 준수 여부를 관리하는 활동

8.2 표준​

8.2.1 표준​

  • ISO/IEC/IEEE 42010: 아키텍처 기술에 관한 국제 표준
  • TOGAF: 엔터프라이즈 아키텍처 개발 프레임워크
  • Zachman: 관점·측면으로 구조화한 EA 분류 체계

9. 운영 아키텍처​

9.1 관측성​

9.1.1 Observability​

  • Logging: 이벤트 기록을 남기는 로깅
  • Monitoring: 시스템 상태를 감시하는 모니터링
  • Metrics: 정량적 상태를 나타내는 지표
  • Tracing: 요청 흐름을 추적하는 트레이싱
  • OpenTelemetry: 관측 데이터 수집의 개방형 표준

9.2 운영​

9.2.1 운영​

  • SRE: 소프트웨어 공학으로 운영을 개선하는 사이트 신뢰성 공학
  • SLI: 서비스 수준을 나타내는 지표
  • SLO: 목표로 삼는 서비스 수준 목표
  • SLA: 고객과 합의한 서비스 수준 협약
  • Chaos Engineering: 의도적 장애 주입으로 복원력을 검증하는 기법

10. 최신 아키텍처​

10.1 AI 아키텍처​

10.1.1 AI​

  • AI Agent: 자율적으로 목표를 수행하는 AI 에이전트
  • LLM Architecture: 대규모 언어모델 기반 시스템 구조
  • RAG: 검색으로 보강해 답변 품질을 높이는 방식
  • MCP: AI와 도구·데이터를 연결하는 개방형 컨텍스트 프로토콜
  • A2A: 에이전트 간 상호작용·협업 방식

10.2 데이터 중심​

10.2.1 Data​

  • Data Mesh: 도메인 단위로 데이터를 분산 소유·관리하는 방식
  • Data Fabric: 데이터를 통합·연결하는 지능형 데이터 계층
  • Lakehouse: 데이터 레이크와 웨어하우스를 결합한 구조

10.3 미래 아키텍처​

10.3.1 Emerging​

  • Edge Computing: 데이터 발생 지점 근처에서 처리하는 엣지 컴퓨팅
  • Digital Twin: 실물을 디지털로 복제해 시뮬레이션하는 기술
  • Green Architecture: 에너지 효율을 고려한 친환경 아키텍처
  • Quantum Architecture: 양자 컴퓨팅 기반의 미래 아키텍처
