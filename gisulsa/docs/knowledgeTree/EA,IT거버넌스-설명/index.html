10. EA / IT거버넌스

1. EA 개요​

1.1 EA 기본​

1.1.1 Enterprise Architecture​

  • Enterprise Architecture (EA): 기업 전체의 IT·업무 구조를 통합 설계하는 체계
  • Enterprise Engineering: 기업을 체계적으로 설계·개선하는 공학
  • Enterprise Transformation: 기업 전반을 혁신·전환하는 활동
  • Business Architecture: 업무 구조와 프로세스를 정의한 아키텍처
  • Enterprise Integration: 기업 시스템을 통합하는 활동

1.2 EA 목적​

1.2.1 EA 가치​

  • Alignment: 비즈니스와 IT를 정렬하는 가치
  • Standardization: 기술·프로세스를 표준화하는 가치
  • Integration: 시스템·데이터를 통합하는 가치
  • Optimization: 자원·프로세스를 최적화하는 가치
  • Agility: 변화에 민첩하게 대응하는 가치

1.3 EA 구성​

1.3.1 EA Domain​

  • Business Architecture: 업무·프로세스 관점의 아키텍처
  • Data Architecture: 데이터 구조·흐름 관점의 아키텍처
  • Application Architecture: 애플리케이션 구성 관점의 아키텍처
  • Technology Architecture: 기술 인프라 관점의 아키텍처

2. EA 프레임워크​

2.1 TOGAF​

2.1.1 TOGAF​

  • ADM: 아키텍처를 개발하는 반복적 방법론
  • Architecture Content Framework: 산출물 구조를 정의한 프레임워크
  • Enterprise Continuum: 아키텍처 자산을 분류하는 연속체
  • Architecture Repository: 아키텍처 자산을 저장하는 저장소

2.2 Zachman​

2.2.1 Zachman Framework​

  • What: 데이터 관점의 질문 축
  • How: 기능·프로세스 관점의 질문 축
  • Where: 위치·네트워크 관점의 질문 축
  • Who: 사람·조직 관점의 질문 축
  • When: 시간·일정 관점의 질문 축
  • Why: 동기·목표 관점의 질문 축

2.3 FEAF​

2.3.1 Government EA​

  • FEAF: 미국 연방정부의 EA 프레임워크
  • BRM: 업무를 분류하는 비즈니스 참조모델
  • DRM: 데이터를 분류하는 데이터 참조모델
  • SRM: 서비스 컴포넌트를 분류하는 참조모델
  • PRM: 성과를 측정하는 성과 참조모델
  • TRM: 기술을 분류하는 기술 참조모델

2.4 국내 EA​

2.4.1 Korean EA​

  • 범정부 EA: 정부 전체 차원의 EA 체계
  • EA 메타모델: EA 구성요소를 정의한 메타모델
  • EA 참조모델: EA 구축의 표준 참조모델
  • EA 성숙도: EA 역량의 성숙도 수준

3. EA 개발​

3.1 EA 계획​

3.1.1 Architecture Planning​

  • EA Vision: EA가 지향하는 목표·비전
  • Architecture Principle: 아키텍처 결정의 기본 원칙
  • Architecture Roadmap: 아키텍처 이행 계획을 담은 로드맵
  • Migration Plan: 현재에서 목표로 이행하는 계획

3.2 EA 모델링​

3.2.1 Architecture Modeling​

  • As-Is: 현재 상태를 나타낸 모델
  • To-Be: 목표 상태를 나타낸 모델
  • Gap Analysis: 현재와 목표의 차이를 분석하는 활동
  • Transition Architecture: 이행 과정의 중간 아키텍처

3.3 EA 산출물​

3.3.1 Deliverables​

  • Architecture Repository: 아키텍처 자산을 저장하는 저장소
  • Architecture Catalog: 아키텍처 요소를 정리한 목록
  • Matrix: 요소 간 관계를 표현한 매트릭스
  • Diagram: 아키텍처를 도식화한 다이어그램

4. EA 거버넌스​

4.1 Architecture Governance​

4.1.1 Governance​

  • Architecture Board: 아키텍처를 심의하는 위원회
  • Architecture Review: 아키텍처를 검토하는 활동
  • Compliance Review: 표준 준수 여부를 검토하는 활동
  • Architecture Contract: 아키텍처 준수를 약정하는 계약

4.2 EA 관리​

4.2.1 Management​

  • Architecture Change Management: 아키텍처 변경을 관리하는 활동
  • Configuration Management: 구성을 통제하는 관리
  • Repository Management: 저장소를 관리하는 활동

4.3 EA 성숙도​

4.3.1 Maturity​

  • EA Maturity Model: EA 역량을 평가하는 성숙도 모델
  • Capability Assessment: 역량을 진단하는 활동
  • Continuous Improvement: 지속적으로 개선하는 활동

5. IT 거버넌스​

5.1 Governance​

5.1.1 IT Governance​

  • Governance: IT 의사결정·통제 체계
  • Management: 실행을 담당하는 관리
  • Decision Rights: 의사결정 권한의 배분
  • Accountability: 결과에 대한 책무성

5.2 COBIT​

5.2.1 COBIT​

  • EDM: 평가·지시·감시의 거버넌스 영역
  • APO: 조정·계획·조직화 관리 영역
  • BAI: 구축·확보·구현 관리 영역
  • DSS: 제공·서비스·지원 관리 영역
  • MEA: 감시·평가·측정 관리 영역

5.3 IT 투자관리​

5.3.1 Investment​

  • IT Portfolio: IT 투자 자산을 관리하는 포트폴리오
  • IT Investment: IT 투자 의사결정 활동
  • Benefits Realization: 투자 편익을 실현하는 활동
  • Value Management: IT 가치를 관리하는 활동

6. EA 운영​

6.1 EA Repository​

6.1.1 Repository​

  • Metadata: 아키텍처 자산을 설명하는 데이터
  • Architecture Asset: 재사용 가능한 아키텍처 자산
  • Reuse: 자산을 재활용하는 활동
  • Version Control: 자산 버전을 관리하는 활동

6.2 표준화​

6.2.1 Standardization​

  • Technical Standard: 기술 표준
  • Reference Model: 표준 참조모델
  • Standard Technology: 표준으로 채택된 기술
  • Technology Lifecycle: 기술의 도입부터 폐기까지의 생명주기

6.3 프로젝트 연계​

6.3.1 Project Governance​

  • Architecture Review: 아키텍처를 검토하는 활동
  • Solution Architecture: 개별 솔루션의 아키텍처
  • Project Compliance: 프로젝트의 표준 준수
  • Design Authority: 설계 표준을 통제하는 권한 조직

7. 디지털 전환​

7.1 Digital Transformation​

7.1.1 DX​

  • Digital Transformation: 디지털 기술로 업무를 혁신하는 전환
  • Business Transformation: 사업 모델·구조를 혁신하는 전환
  • Operating Model: 조직이 가치를 창출·전달하는 운영 모델
  • Customer Experience: 고객이 겪는 경험

7.2 플랫폼​

7.2.1 Platform​

  • Digital Platform: 디지털 서비스를 제공하는 플랫폼
  • Platform Business: 플랫폼 기반의 사업 모델
  • API Economy: API로 가치를 교환하는 경제
  • Open Platform: 외부에 개방된 플랫폼

7.3 데이터 중심​

7.3.1 Data Driven​

  • Data Governance: 데이터 관리를 통제하는 거버넌스
  • AI Governance: AI 개발·운영을 통제하는 거버넌스
  • Data Platform: 데이터를 통합·활용하는 플랫폼
  • Digital Twin: 실물을 디지털로 복제해 시뮬레이션하는 기술

8. 아키텍처 관리​

8.1 Application Portfolio​

8.1.1 APM​

  • Application Portfolio Management: 애플리케이션 자산을 관리하는 활동
  • Rationalization: 중복을 정리해 합리화하는 활동
  • Legacy Modernization: 노후 시스템을 현대화하는 활동
  • Technical Debt: 누적된 기술적 부채

8.2 Technology Portfolio​

8.2.1 TPM​

  • Technology Portfolio: 기술 자산을 관리하는 포트폴리오
  • Technology Radar: 기술 동향을 평가·분류하는 도구
  • Lifecycle Management: 기술 생명주기를 관리하는 활동
  • Technology Refresh: 노후 기술을 갱신하는 활동

8.3 Business Capability​

8.3.1 Capability​

  • Capability Map: 업무 역량을 시각화한 지도
  • Value Stream: 가치를 만드는 활동 흐름
  • Business Process: 업무를 수행하는 프로세스
  • Operating Model: 가치 창출·전달의 운영 모델

9. EA 평가​

9.1 Architecture Assessment​

9.1.1 Assessment​

  • Architecture Compliance: 아키텍처 표준 준수 여부
  • Architecture KPI: 아키텍처 성과 지표
  • Architecture Quality: 아키텍처의 품질 수준
  • Architecture Risk: 아키텍처와 관련된 위험

9.2 EA 성과​

9.2.1 Performance​

  • ROI: 투자 대비 수익률
  • Business Value: 창출된 비즈니스 가치
  • IT Value: IT가 제공하는 가치
  • Strategic Alignment: 전략과 IT의 정렬 정도

10. 최신 EA​

10.1 Agile EA​

10.1.1 Modern EA​

  • Agile Enterprise Architecture: 애자일 방식의 EA
  • Lean Architecture: 낭비를 줄인 린 아키텍처
  • Continuous Architecture: 지속적으로 진화하는 아키텍처
  • Architecture as Code: 아키텍처를 코드로 관리하는 방식

10.2 AI 기반 EA​

10.2.1 AI EA​

  • AI Governance: AI 개발·운영을 통제하는 거버넌스
  • AI Enterprise Architecture: AI를 접목한 엔터프라이즈 아키텍처
  • Autonomous Enterprise: 자율적으로 운영되는 기업
  • Digital Enterprise: 디지털 기반으로 운영되는 기업
