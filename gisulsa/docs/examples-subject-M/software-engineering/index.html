소프트웨어공학

정보관리기술사 기출문제 중 소프트웨어공학 관련 문제를 정리한 페이지입니다.

110회​

3교시​

  • 최근 미국에서 자율자동차의 사고로 인하여 인명 피해가 발생하였다. 이로 인해 자율 시스템에 포함된 소프트웨어의 기능 안전 문제가 크게 대두되고 있는데 모든 산업에 적용가능한 기능 안전기준을 제시한 IEC61508 시리즈와 전체 프레임워크를 도식화 하여 설명하시오.

IEC 61508은 전기·전자·프로그래머블 전자 시스템의 기능 안전을 다루는 국제 표준으로, 자동차·의료·항공 등 다양한 산업별 파생 표준의 기반이 된다. 안전 무결성 수준(SIL 1~4)을 정의하고, 위험 분석부터 설계·검증·운영까지 전 생명주기에 걸친 프로세스를 규정한다. 자율주행 소프트웨어의 사고 예방을 위해 SIL 등급 산정 및 안전기능 요구사항 도출 절차가 핵심이다.

111회​

1교시​

  • MVC(Model View Control) 패턴

MVC 패턴은 소프트웨어를 Model(데이터·비즈니스 로직), View(UI 표현), Controller(입력 처리·흐름 제어) 세 레이어로 분리하는 아키텍처 패턴이다. 관심사 분리를 통해 유지보수성과 테스트 용이성을 높이며, 웹 프레임워크(Spring MVC, Django 등)에서 광범위하게 적용된다. 각 컴포넌트 간 의존성을 최소화하여 독립적인 변경과 재사용이 가능하다.

2교시​

  • 데브옵스(DevOps)와 애자일(Agile) 방법론을 비교하여 설명하시오.

애자일은 짧은 이터레이션을 통해 요구사항 변화에 유연하게 대응하는 소프트웨어 개발 방법론으로, 개발팀의 협업과 빠른 피드백을 강조한다. 데브옵스는 개발(Dev)과 운영(Ops) 간 사일로를 제거하고, CI/CD 파이프라인과 자동화를 통해 빠르고 안정적인 배포를 실현하는 문화·관행·도구의 집합이다. 애자일이 개발 프로세스 자체에 초점을 맞춘다면, 데브옵스는 개발부터 운영까지 전체 가치 흐름의 가속화를 목표로 한다.

3교시​

  • 국내 중소기업은 소프트웨어공학 프로세스에 의한 소프트웨어 개발 품질관리를 수행하기에 인력과 비용이 부족하여, 소프트웨어 개발 품질관리를 수행하기 위한 방안으로 소프트웨어 Visualization이 부각하고 있다. 소프트웨어 Visualization을 개발 프로세스 및 소스코드 관점에서 설명하시오.

소프트웨어 Visualization은 복잡한 개발 프로세스나 소스코드 구조를 시각적으로 표현하여, 개발자와 관리자가 품질 문제를 빠르게 파악할 수 있도록 돕는 기법이다. 개발 프로세스 관점에서는 번다운 차트·칸반 보드 등을 통해 진행상황을 가시화하고, 소스코드 관점에서는 의존성 그래프·코드 복잡도 맵을 통해 품질 취약점을 식별한다. 인력·비용이 제한된 중소기업에서도 자동화 도구 기반 시각화를 활용하면 효율적인 품질관리가 가능하다.

4교시​

  • 아키텍쳐 모델 중 기능의 분할과 배치 관점에서 데이터 중심형 모델, 클라이언트-서버 모델, 계층 모델 및 MVC(Model View Controller) 모델을 각각 설명하시오.

소프트웨어 아키텍처 모델은 시스템의 기능을 어떻게 분할하고 배치할지를 결정하는 설계 청사진이다. 데이터 중심형은 공유 저장소를 중심으로 컴포넌트가 상호작용하며, 클라이언트-서버는 서비스 요청자와 제공자로 역할을 분리한다. 계층 모델은 기능을 수직으로 계층화하여 상위 계층이 하위 계층 서비스를 사용하고, MVC는 데이터·표현·제어를 분리하여 유연성을 높인다.

113회​

1교시​

  • 재공학(Re-enginerring), 역공학(Reverse Engineering)

재공학은 기존 소프트웨어를 이해하고 더 나은 형태로 재구성하는 활동으로, 레거시 시스템의 유지보수성 향상과 기술 부채 해소를 목적으로 한다. 역공학은 완성된 소프트웨어를 분석하여 설계 명세나 소스코드를 추출·복원하는 과정으로, 재공학의 선행 단계로 수행된다. 둘 다 소프트웨어 3R(Reverse Engineering, Re-Engineering, Reuse)의 핵심 요소이다.

  • 품질보증(QA : Quality Assurance), 품질통제(QC : Quality Control)

품질보증(QA)은 소프트웨어 개발 프로세스 전반에 걸쳐 품질 기준이 준수되는지를 확인하는 예방 중심의 활동이다. 품질통제(QC)는 산출물을 검사·테스트하여 결함을 발견하고 수정하는 사후 적발 중심의 활동이다. QA가 프로세스를 관리한다면, QC는 제품을 직접 검증하는 차이점이 있다.

2교시​

  • 소프트웨어 기능안전(Functional Safety)에 대한 사항이다. 다음 질문에 답하시오.
    • 가. 소프트웨어 안전과 소프트웨어 보안의 차이점
    • 나. IEC 61508에서 정의한 안전기능 요구사항 도출과정
    • 다. IEC 61508과 의료기기, 항공기, 자동차 분야의 기능안전 표준들 간 비교

소프트웨어 안전(Safety)은 시스템 오작동으로 인한 인명·환경 피해를 방지하는 것에 초점을 맞추며, 소프트웨어 보안(Security)은 외부 공격·비인가 접근으로부터 시스템을 보호하는 것을 목표로 한다. IEC 61508은 위험원 분석을 통해 SIL 등급을 결정하고 안전기능 요구사항을 도출하는 표준 프레임워크를 제공한다. 의료기기(IEC 62304), 자동차(ISO 26262), 항공(DO-178C) 등 산업별 파생 표준은 IEC 61508의 원칙을 해당 도메인에 특화하여 적용한다.

3교시​

  • 소프트웨어 품질의 테스트 방법인 화이트박스 및 블랙박스 테스트의 4가지 검증기준(coverage)을 예를 들어 설명하고, 테스트 자동화 도구의 유형에 대하여 설명하시오.

화이트박스 테스트는 내부 코드 구조를 기반으로 구문(Statement), 분기(Branch), 조건(Condition), 경로(Path) 커버리지 등 4가지 기준으로 검증한다. 블랙박스 테스트는 입출력 명세만을 기반으로 동등분할, 경계값 분석, 원인-결과 그래프 등의 기법을 사용한다. 테스트 자동화 도구는 단위 테스트(JUnit), 통합 테스트, UI 테스트(Selenium), 성능 테스트(JMeter) 등의 유형으로 구분된다.

4교시​

  • 소프트웨어 성능테스트에 대하여 설명하시오.
    • 가. 리틀의 법칙(Little's Law)을 통한 성능테스트의 목적에 대하여 설명하시오.
    • 나. 성능테스트의 종류 및 구성요소에 대하여 설명하시오.

리틀의 법칙(L = λW)은 시스템 내 평균 항목 수(L)가 평균 도착률(λ)과 평균 체류시간(W)의 곱과 같음을 나타내며, 처리량·응답시간·동시사용자 간의 관계를 수학적으로 분석하는 데 활용된다. 성능테스트 종류에는 부하(Load), 스트레스(Stress), 스파이크(Spike), 내구성(Endurance) 테스트 등이 있으며, 각각 정상·한계·급격한 증가·장시간 조건에서 성능을 측정한다. 구성요소로는 가상 사용자 생성기, 부하 주입기, 모니터링 도구, 분석 리포터가 포함된다.

  • JAVA 언어의 Abstract Class(추상 클래스)와 Interface(인터페이스)에 대하여 다음 질문에 답하시오.
    • 가. 다음 조건일 때 클래스 다이어그램을 작성하시오.
    • 나. 위의 가.조건에서 Animal, Curtain, Dog, Blind 클래스를 JAVA 언어로 선언 부분을 작성하시오.

추상 클래스(Abstract Class)는 일부 구현을 포함할 수 있으며 단일 상속만 가능하고, 인터페이스(Interface)는 메서드 시그니처만 정의하며 다중 구현이 가능하다. Java에서 추상 클래스는 공통 속성·메서드를 공유하는 계층 구조에 적합하고, 인터페이스는 서로 다른 계층의 클래스에 공통 행위를 부여할 때 사용한다. 클래스 다이어그램에서 추상 클래스는 이탤릭체, 인터페이스는 인터페이스 스테레오타입으로 표기한다.

116회​

1교시​

  • 마이크로서비스 아키텍처(MicroService Architecture)

마이크로서비스 아키텍처(MSA)는 단일 애플리케이션을 독립적으로 배포 가능한 소규모 서비스들의 집합으로 구성하는 아키텍처 스타일이다. 각 서비스는 자체 데이터 저장소를 가지고 API(주로 REST 또는 메시지 브로커)로 통신하며, 서비스별로 독립적인 확장·배포·기술 선택이 가능하다. 모놀리식 대비 높은 유연성을 제공하지만, 분산 시스템 복잡성과 서비스 간 통신 오버헤드가 단점으로 꼽힌다.

2교시​

  • 소프트웨어 비용 산정 방법 중 상향식 비용 산정 방법, 하향식 비용 산정 방법에 대하여 설명하시오.

상향식(Bottom-Up) 비용 산정은 개별 작업 단위(WBS)를 먼저 산정한 후 합산하는 방식으로, 정확도가 높지만 시간이 많이 소요된다. 하향식(Top-Down) 비용 산정은 전체 프로젝트 규모를 먼저 추정하고 세부 항목으로 분배하는 방식으로, 초기 단계 신속 추정에 적합하나 세부 불확실성이 크다. 실제 프로젝트에서는 두 방법을 병행하여 상호 검증하는 방식이 권장된다.

4교시​

  • 소프트웨어 성능테스트에 대하여 설명하시오.
    • 가. 리틀의 법칙(Little's Law)을 통한 성능테스트의 목적에 대하여 설명하시오.
    • 나. 성능테스트의 종류 및 구성요소에 대하여 설명하시오.

리틀의 법칙은 시스템의 처리량, 응답시간, 동시 접속자 수 간의 정량적 관계를 제공하여 목표 SLA 달성 가능 여부를 수학적으로 분석할 수 있게 한다. 성능테스트는 이 법칙을 기반으로 부하 조건을 설계하고, 시스템이 요구 성능 기준을 충족하는지 측정·검증한다. 부하·스트레스·스파이크·내구성 테스트로 유형을 구분하며, 각각 다른 시나리오에서 성능 특성을 파악한다.

  • 소프트웨어 안전성 분석 개념 및 안전성 분석 기법을 설명하시오.

소프트웨어 안전성 분석은 시스템 오류나 소프트웨어 결함으로 인해 발생할 수 있는 위험을 식별·평가·제어하는 체계적 활동이다. 대표적인 기법으로 결함 나무 분석(FTA), 고장 유형 영향 분석(FMEA), 위험 및 운전성 연구(HAZOP)가 있으며, 각 기법은 귀납적 또는 연역적 접근으로 위험원을 분석한다. 안전성 분석 결과는 설계 단계에서 안전 요구사항으로 반영되어야 한다.

118회​

1교시​

  • CMMi의 단계적 표현(StagedRepresentation)과 연속적 표현(Continuous Representation)

CMMI(Capability Maturity Model Integration)는 소프트웨어 프로세스 성숙도를 평가하는 프레임워크로, 두 가지 표현 방식을 제공한다. 단계적 표현은 조직 전체의 성숙도를 15 단계로 측정하며, 연속적 표현은 개별 프로세스 영역(PA)별 능력 수준(05)을 독립적으로 평가한다. 단계적 표현은 조직 전반의 개선 로드맵에, 연속적 표현은 특정 프로세스 영역의 집중 개선에 적합하다.

2교시​

  • 소프트웨어 설계에 있어서 중심이 되는 원리인 추상화, 정보은닉, 단계적분해, 모듈화에 대하여 설명하시오.

  • 소프트웨어(이하 SW) 운영단계 대가산정에 대하여 다음을 설명하시오.
    • 가. 응용 SW 요율제 유지관리비 산정방식과 SW 운영 투입공수 산정방식
    • 나. 고정비/변동비 산정방식
  • 정보시스템의 성능 요구사항 작성 시 고려해야 하는 주요 성능지표 및 내용에 대하여 설명하시오.

4교시​

  • 소프트웨어 진흥법(시행 2023.10.19)은 소프트웨어 산업의 발전을 위해 시행되어야 할 다양한 활동의 법적 근거를 마련하고 있다. 이와 관련하여 다음을 설명하시오.
    • 가. 제5조(기본계획의 수립 등)의 2항에 따른 기본계획 내 포함되어야 할 사항
    • 나. 제30조(소프트웨어안전 확보)의 2항에 따른 소프트웨어안전 확보를 위한 지침 내 포함되어야 할 사항
  • 소프트웨어 개발에 필요한 규모 산정 방식 종류와 특징을 비교 설명하고, 공공 소프트웨어 사업 규모 산정 방식의 현실적 개선 방안에 대하여 설명하시오.

133회​

1교시​

  • REST API(REpresentational State Transfer Application Programming Interface)에 대하여 설명하시오.
  • 소프트웨어 테스트 유형 중 뮤테이션 테스트(Mutation Test)에 대하여 설명하시오.
  • 소프트웨어 유지보수 향상 및 비용절감을 위한 3R을 설명하시오.

3교시​

  • 소프트웨어 요구공학(Requirement Engineering)에 대하여 설명하시오.
    • 가. 요구공학 정의 및 필요성
    • 나. 요구공학 절차
    • 다. 요구사항 명세서

4교시​

  • 정보시스템 개발과 운영 단계에서 수행되는 소프트웨어 테스트의 종류를 쓰고, 이 중 신뢰성 테스트와 이식성 테스트의 세부 활동에 대하여 각각 설명하시오.

134회​

1교시​

  • 형상관리의 개념과 형상관리 기준선(Baseline)
  • 객체 간의 데이터 보호를 위한 정보은닉(Information Hiding)

3교시​

  • 실행 중인 애플리케이션에 대한 배포 전략 및 테스트 전략에 대하여 설명하시오.
  • 소프트웨어 테스트에 대하여 설명하시오.
    • 가. 소프트웨어 테스트 원리
    • 나. 블랙박스 테스트와 화이트박스 테스트
    • 다. 명세기반, 구조기반, 경험기반 테스트 기법
  • SBOM(Software Bill of Materials)에 대하여 설명하시오.
    • 가. 오픈소스 소프트웨어 취약점
    • 나. SBOM 기반 오픈소스 소프트웨어 관리 방안

135회​

1교시​

  • 요구사항 추적표(Requirement Traceability Matrix)
  • 소프트웨어 기술 부채의 유형과 관리 방법

2교시​

  • CI/CD(Continuous Integration/Continuous Delivery or Continuous Deployment) 파이프라인에서 DevSecOps 적용방안에 대하여 설명하시오.

4교시​

  • 인공지능 소프트웨어 품질 보증을 위한 테스트 기법에 대하여 다음을 설명하시오.
    • 가. 메타모픽 테스트(Metamorphic Test)
    • 나. 뉴런 커버리지 테스트(Neuron Coverage Test)
    • 다. 안전 반경 최대화 테스트

136회​

1교시​

  • 프록시(Proxy) 디자인 패턴
  • DevOps 장점과 단점

2교시​

  • 소프트웨어 개발방법론 중 하나인 제품계열(Product Line) 방법론에 대하여 다음을 설명하시오.
    • 가. 개념과 특징
    • 나. 활용 기술과 고려사항

3교시​

  • 소프트웨어 품질보증과 관련하여 다음을 설명하시오.
    • 가. 소프트웨어 품질의 의미
    • 나. 소프트웨어 품질보증의 목적과 기능
    • 다. 인스펙션(Inspection)과 인스펙션 프로세스(Inspection Process)

4교시​

  • 소프트웨어 품질 속성 중 보안 품질에 대하여 다음을 설명하시오.
    • 가. 소프트웨어 보안 품질의 정의와 중요성
    • 나. 보안 품질 확보를 위한 자동화 기술과 도구
    • 다. 소프트웨어 라이프사이클 관점에서 보안 자동화 구현방안
    • 라. 기대 효과와 시사점

137회​

1교시​

  • 소프트웨어 역공학과 재공학을 설명하시오.
  • A/B 테스팅을 설명하시오.

2교시​

  • 소프트웨어 테스트 중 동적 테스트에 대하여 설명하시오.
    • 가. 동적 테스트의 명세 기반 테스트와 구조 기반 테스트 비교
    • 나. 아래의 [프로그램 명세]로 명세 기반 테스트 기법의 동등 분할과 분류 트리 기법의 테스트 케이스 작성

4교시​

  • UML(Unified Modeling Language)에서 사용하는 행위 다이어그램(Behavior Diagram)인 활동 다이어그램(Activity Diagram), 상태 다이어그램(State Diagram), 그리고 유스케이스 다이어그램(Use-Case Diagram)에 대하여 각각 설명하시오.
  • 소프트웨어 사업 대가산정에 대하여 다음을 설명하시오.
    • 가. 소프트웨어 대가산정 가이드 목적
    • 나. 인공지능(AI) 서비스 도입 사업유형과 사업비 산정 절차

138회​

1교시​

  • 소프트웨어 개발 프로젝트에서 선도개발을 위한 개발방법론 테일러링(Tailoring)

2교시​

  • ISP(Information Strategy Planning)의 정의 및 목적, ISP 수행방법론 체계와 절차, ISP와 ISMP 비교에 대하여 설명하시오.
  • 소프트웨어 유지보수를 위한 재공학(Re-engineering)과 역공학(Reverse-engineering)에 대하여 다음 내용을 설명하시오.
    • 가. 재공학 개념 및 목적
    • 나. 재공학 절차
    • 다. 역공학 개념 및 활용 방안
