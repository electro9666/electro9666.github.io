컴퓨터구조/운영체제

정보관리기술사 기출문제 중 컴퓨터구조/운영체제 관련 문제를 정리한 페이지입니다.

110회​

2교시​

  • 5.동기화 기법인 스핀 락(Read/Write Spin Lock)의 개념을 기술하고 스핀 락을 활용하는 방법을 사례를 들어 설명하시오.

스핀 락(Spin Lock)은 임계 구역에 진입하려는 스레드가 락이 해제될 때까지 계속 반복 확인(busy-waiting)하며 대기하는 동기화 기법입니다. 컨텍스트 스위칭 오버헤드가 없어 대기 시간이 매우 짧은 상황에서 효율적이지만, 대기 시간이 길어지면 CPU 자원을 낭비합니다. Read/Write Spin Lock은 다수의 읽기 동시 허용, 쓰기는 단독 접근을 보장하여 읽기 빈도가 높은 공유 자원 보호에 적합합니다.

4교시​

  • 5.프로세스 스레싱(Thrashing)의 발생 원인과 예방책을 설명하시오.

스래싱은 다중 프로그래밍 정도가 과도해져 프로세스가 실제 연산보다 페이지 교체에 더 많은 시간을 소비하는 현상입니다. 각 프로세스에 충분한 페이지 프레임이 할당되지 않아 빈번한 페이지 부재(Page Fault)가 연속적으로 발생하는 것이 원인입니다. 작업 집합(Working Set) 모델, 페이지 부재 빈도(PFF) 기법, 다중 프로그래밍 정도 조절 등으로 예방할 수 있습니다.

113회​

2교시​

  • 4.멀티프로세스 환경에서 프로그램 실행 시 컴퓨터 내외부에서 발생할 수 있는 인터럽트(Interrupt)의 처리 우선순위에 대하여 설명하시오.

인터럽트는 CPU가 현재 수행 중인 작업을 일시 중단하고 인터럽트 서비스 루틴(ISR)을 실행하도록 하는 신호입니다. 처리 우선순위는 일반적으로 전원 이상 > 기계 착오 > 외부 인터럽트 > 입출력 인터럽트 > 프로그램 인터럽트 > SVC 순으로 높습니다. 멀티프로세스 환경에서는 인터럽트 마스킹(Masking)과 우선순위 인코더를 통해 충돌 없이 처리 순서를 결정합니다.

113회​

4교시​

  • 4.CPU의 명령어 처리에 있어서 파이프라인(pipeline) 방식과 비파이프라인 방식에 대하여 각각의 CPU 처리시간을 비교하여 설명하시오. (단, 파이프라인의 단계 수를 m, 각 파이프라인 단계에서의 처리시간을 k, 실행할 명령어들의 수를 n이라고 한다.)

비파이프라인 방식은 하나의 명령어가 모든 단계(인출, 해독, 실행, 저장)를 완료한 후 다음 명령어를 처리하며 총 처리시간은 n × m × k입니다. 파이프라인 방식은 여러 명령어를 단계별로 중첩하여 동시에 처리하므로 총 처리시간은 (m + n - 1) × k로 획기적으로 단축됩니다. 파이프라인은 스테이지 수가 많을수록, 명령어 수가 많을수록 비파이프라인 대비 효율이 높아집니다.

116회​

3교시​

  • 4.스레드(Thread)와 멀티스레드(Multi-thread)의 개념, 스레드(Thread)와 프로세스(Process)의 차이점을 비교하여 설명하시오.

스레드는 프로세스 내에서 실행되는 가장 작은 실행 단위로, 프로세스의 코드·데이터·힙 영역을 공유하며 독립적인 스택과 레지스터를 가집니다. 멀티스레드는 하나의 프로세스에서 여러 스레드가 동시에 실행되는 방식으로 응답성 향상과 자원 공유가 장점입니다. 프로세스는 독립된 메모리 공간을 가지나 스레드는 메모리를 공유하므로 통신은 빠르지만 동기화 문제를 주의해야 합니다.

117회​

1교시​

  • 12.UNIX 운영체제 부팅과정

UNIX 부팅 과정은 전원 인가 후 BIOS/UEFI의 POST(Power-On Self Test)를 시작으로 부트로더(GRUB)가 커널을 메모리에 로드합니다. 커널 초기화 후 init(또는 systemd) 프로세스가 실행되어 시스템 서비스와 데몬을 순차적으로 기동합니다. 최종적으로 로그인 프롬프트가 표시되어 사용자가 시스템에 접근할 수 있게 됩니다.

2교시​

  • 4.IPC(Inter Process Communication) 방식의 주요기법 3가지에 대하여 설명하시오.

IPC는 독립된 프로세스들이 데이터를 교환하고 협력하기 위한 메커니즘입니다. 대표적인 기법으로 파이프(Pipe), 메시지 큐(Message Queue), 공유 메모리(Shared Memory)가 있습니다. 파이프는 단방향 스트림, 메시지 큐는 구조화된 메시지 단위 통신, 공유 메모리는 가장 빠른 통신 방법이지만 동기화가 필수적입니다.

119회​

3교시​

  • 6.CPU 스케줄링 알고리즘에 대하여 설명하시오.
    • 가.SJF(Shortest Job First)와 HRN(Highest Response-ratio Next)

SJF는 CPU 버스트 시간이 가장 짧은 프로세스를 먼저 실행하는 비선점 스케줄링으로 평균 대기 시간을 최소화합니다. 그러나 실행 시간이 긴 프로세스는 무한 대기(기아 현상)가 발생할 수 있습니다. HRN은 SJF의 기아 현상을 보완하기 위해 응답 비율(대기 시간 + 서비스 시간) / 서비스 시간을 기준으로 우선순위를 결정하는 방법입니다.

  • 나.MLQ(Multi Level Queue) 와 MLFQ(Multi Level Feedback Queue)

MLQ는 프로세스를 여러 우선순위 큐로 분류하여 고정된 큐에서 스케줄링하는 방식으로 큐 간 이동이 불가능합니다. MLFQ는 MLQ를 개선하여 프로세스가 CPU 사용 패턴에 따라 큐 사이를 이동할 수 있어 적응형 스케줄링이 가능합니다. MLFQ는 CPU 집약적 프로세스는 하위 큐로, 대화형 프로세스는 상위 큐에 유지하여 반응성과 처리율을 모두 향상시킵니다.

124회​

3교시​

  • 4.교착 상태(Dead Lock)의 개념과 교착상태를 회피하기 위한 은행가 알고리즘(Banker's Algorithm)의 개념 및 자료구조를 설명하시오.

교착 상태는 두 개 이상의 프로세스가 서로 상대방의 자원을 기다리며 무한 대기 상태에 빠지는 현상입니다. 발생 조건은 상호 배제, 점유와 대기, 비선점, 순환 대기의 4가지가 모두 충족될 때입니다. 은행가 알고리즘은 자원 할당 전 안전 상태 여부를 시뮬레이션하여 교착 상태를 사전에 회피하는 기법입니다.

126회​

1교시​

  • 10.스래싱

스래싱(Thrashing)은 물리 메모리 부족으로 인해 페이지 교체가 빈번하게 발생하여 시스템 성능이 급격히 저하되는 현상입니다. 다중 프로그래밍 정도가 임계점을 초과하면 CPU 이용률이 오히려 감소하는 역설적 상황이 나타납니다. 작업 집합(Working Set) 기법으로 각 프로세스에 필요한 최소 프레임을 보장하거나 PFF 제어로 예방합니다.

4교시​

  • 2.Real Time Scheduling이 갖는 문제 중 우선순위 역전(Priority Inversion)이 있다. Task1, Task2, Task3 순으로 우선순위가 낮다고 할 때 우선순위 역전을 사례기반으로 설명하고, 우선순위 역전을 해결하기 위한 2가지 기법에 대하여 설명하시오.

우선순위 역전은 낮은 우선순위 태스크(Task3)가 공유 자원을 점유한 상태에서 높은 우선순위 태스크(Task1)가 그 자원을 기다리는 동안 중간 우선순위 태스크(Task2)가 실행되는 현상입니다. 이로 인해 실질적으로 Task2가 Task1보다 먼저 실행되는 우선순위 역전이 발생합니다. 해결 기법으로는 우선순위 상속(Priority Inheritance)과 우선순위 상한(Priority Ceiling Protocol) 기법이 있습니다.

3교시​

  • 5.운영체제 메모리 관리 기법 중 페이징 기법과 세그멘테이션 기법의 개념을 설명하고, 두 기법에 대하여 비교 설명하시오.

페이징은 물리 메모리와 논리 메모리를 동일한 크기의 블록(페이지/프레임)으로 분할하여 외부 단편화를 제거하는 기법입니다. 세그멘테이션은 프로그램을 논리적 의미 단위(코드, 데이터, 스택 등)로 분할하여 관리하며 내부 단편화가 없지만 외부 단편화가 발생합니다. 두 기법을 결합한 세그먼트-페이지 기법을 사용하면 양쪽의 장점을 취할 수 있습니다.

137회​

2교시​

  • 1.캐시 메모리(Cache Memory)에 대하여 다음을 설명하시오.
    • 가.캐시 쓰기 정책(Write Policy)

캐시 쓰기 정책은 캐시에 데이터를 쓸 때 주기억장치와의 일관성을 유지하는 방법을 정의합니다. Write-Through는 캐시와 주기억장치에 동시에 쓰는 방식으로 일관성이 높지만 쓰기 속도가 느립니다. Write-Back은 캐시에만 쓰고 해당 블록이 교체될 때 주기억장치에 반영하여 성능이 높지만 불일치 위험이 있습니다.

  • 나.캐시 일관성(Cache Coherence) 문제의 원인과 해결 방법

멀티프로세서 환경에서 각 프로세서가 독립된 캐시를 가지면 동일 메모리 블록의 복사본이 서로 달라지는 캐시 일관성 문제가 발생합니다. 원인은 한 프로세서가 공유 데이터를 수정했을 때 다른 프로세서의 캐시가 갱신되지 않는 것입니다. MESI 프로토콜(Modified, Exclusive, Shared, Invalid)이나 스누핑(Snooping) 기법으로 캐시 일관성을 유지합니다.

3교시​

  • 1.운영체제 스케줄링 기법에 대한 각 내용을 설명하시오.
    • 가.CPU 스케줄링과 디스크 스케줄링의 개념

CPU 스케줄링은 준비 큐의 여러 프로세스 중 CPU를 할당할 프로세스를 결정하는 정책으로 시스템 처리율과 응답 시간에 영향을 줍니다. 디스크 스케줄링은 디스크 입출력 요청의 처리 순서를 결정하여 디스크 헤드의 이동 거리(탐색 시간)를 최소화하는 정책입니다. 두 스케줄링 모두 공평성, 효율성, 반응성의 세 가지 목표를 균형 있게 달성해야 합니다.

  • 나.SJF(Shortest Job First)와 SRT(Shortest Remaining Time)

SJF는 CPU 버스트 시간이 가장 짧은 프로세스를 먼저 실행하는 비선점 방식으로 평균 대기 시간을 최소화합니다. SRT(Shortest Remaining Time)는 SJF의 선점형 버전으로, 새로운 프로세스 도착 시 남은 실행 시간이 더 짧으면 즉시 선점합니다. SRT는 대화형 환경에서 응답성이 높지만 컨텍스트 스위칭 오버헤드와 기아 현상이 발생할 수 있습니다.

  • 다.SSTF(Shortest Seek Time First)와 SLTF(Shortest Latency Time First)

SSTF는 현재 헤드 위치에서 가장 가까운 트랙의 요청을 먼저 처리하는 디스크 스케줄링 알고리즘으로 평균 탐색 시간을 줄입니다. SLTF는 회전 지연 시간을 최소화하기 위해 현재 헤드 위치에서 회전 방향으로 가장 가까운 섹터를 먼저 서비스합니다. SSTF는 기아 현상이 발생할 수 있고, SLTF는 구현이 복잡하지만 회전 속도가 느린 디스크에서 효과적입니다.

138회​

2교시​

  • 6.프로그램 실행 시 운영체제는 메모리를 4가지 주요 영역으로 나누어 할당 및 관리한다. 각 영역의 역할과 특징 그리고 영역 간 동작 메커니즘에 대하여 다음 내용을 설명하시오.
    • 가.코드(Code)

코드 영역(텍스트 영역)은 실행할 프로그램의 기계어 명령어가 저장되는 공간입니다. 읽기 전용(Read-Only)으로 설정되어 프로그램 실행 중 코드가 변경되지 않도록 보호합니다. 여러 프로세스가 동일 프로그램을 실행할 경우 코드 영역을 공유하여 메모리를 절약할 수 있습니다.

  • 나.데이터(Data)

데이터 영역은 프로그램 실행 전에 초기화된 전역 변수와 정적 변수가 저장되는 공간입니다. BSS 영역(초기화되지 않은 전역/정적 변수)과 data 영역(초기화된 전역/정적 변수)으로 세분화됩니다. 프로그램 시작 시 할당되고 종료 시 해제되는 정적 할당 구조를 가집니다.

  • 다.힙(Heap)

힙 영역은 프로그램 실행 중 동적으로 할당·해제되는 메모리 공간으로 malloc, new 등의 함수로 관리합니다. 메모리 주소가 낮은 곳에서 높은 쪽으로 증가하며, 개발자가 명시적으로 해제하지 않으면 메모리 누수(Memory Leak)가 발생합니다. 힙 영역이 스택 영역과 충돌할 때까지 확장될 수 있어 크기가 동적으로 변합니다.

  • 라.스택(Stack)

스택 영역은 함수 호출 시 지역 변수, 매개변수, 리턴 주소 등이 저장되는 LIFO 구조의 메모리 공간입니다. 함수 호출 시 스택 프레임이 생성되어 스택에 쌓이고, 함수 반환 시 해당 프레임이 자동으로 제거됩니다. 크기가 고정되어 있어 재귀 호출이 과도하면 스택 오버플로(Stack Overflow)가 발생합니다.

4교시​

  • 2.프로세스 간 통신을 위해 사용되는 IPC(Inter Process Communication)에 대하여 다음을 설명하시오.
    • 가.IPC의 개념과 목적

IPC는 운영체제에서 독립적으로 실행 중인 프로세스들이 데이터를 교환하고 협력하기 위한 메커니즘과 기술의 총칭입니다. 프로세스는 기본적으로 독립된 메모리 공간을 가지므로 직접 데이터 공유가 불가능하여 IPC가 필요합니다. IPC의 주요 목적은 정보 공유, 연산 속도 향상, 모듈화, 편리성 제공입니다.

  • 나.IPC 주요기법 3가지

파이프(Pipe)는 부모-자식 프로세스 간 단방향 통신에 사용되며 간단하지만 동일 호스트 내에서만 사용 가능합니다. 메시지 큐(Message Queue)는 커널이 관리하는 메시지 저장소를 통해 구조화된 데이터를 비동기적으로 전달합니다. 공유 메모리(Shared Memory)는 동일한 물리 메모리 영역을 여러 프로세스가 공유하여 가장 빠른 IPC를 제공하지만 세마포어 등의 동기화가 필요합니다.

  • 다.공유 자원의 충돌이나 일관성 문제를 해결하기 위한 동기화 기법

공유 자원에 대한 동시 접근은 경쟁 조건(Race Condition)을 유발하여 데이터 불일치 문제가 생깁니다. 뮤텍스(Mutex)는 상호 배제를 보장하는 잠금 메커니즘으로 한 번에 하나의 스레드만 임계 구역에 진입할 수 있습니다. 세마포어(Semaphore)는 카운터 기반으로 복수의 자원 관리가 가능하며, 모니터(Monitor)는 고수준 동기화 추상화를 제공합니다.
