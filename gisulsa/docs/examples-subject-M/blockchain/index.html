블록체인

정보관리기술사 기출문제 중 블록체인 관련 문제를 정리한 페이지입니다.

110회​

4교시​

  • 6.가상화폐의 핵심기술로 사용되는 블록체인의 개념과 작동 원리를 설명하고, 블록체인의 오픈플랫폼(Open Platform)인 이더리움(Ethereum)의 개념과 특징을 가상화폐와 비교하여 설명하시오.

블록체인은 거래 데이터를 블록 단위로 연결하고 분산 네트워크의 모든 참여자가 동일한 원장을 공유하는 탈중앙화 데이터 저장 기술입니다. 이더리움은 비트코인과 달리 스마트 컨트랙트를 통해 프로그래밍 가능한 블록체인 플랫폼으로 DApp 개발을 지원합니다. 비트코인은 통화 기능에 특화된 반면, 이더리움은 다양한 탈중앙화 애플리케이션을 위한 범용 플랫폼입니다.

111회​

1교시​

  • 5.블록체인(Block Chain) 구성요소 중 마이닝(Mining)

마이닝(채굴)은 블록체인 네트워크에서 새로운 거래를 검증하고 블록을 생성하는 작업입니다. 작업 증명(PoW) 방식에서는 복잡한 수학적 해시 퍼즐을 가장 먼저 해결한 노드가 블록 생성 권한과 보상(코인)을 받습니다. 마이닝은 블록체인의 무결성 유지와 이중 지불 방지에 핵심적인 역할을 하지만 막대한 에너지 소비 문제가 있습니다.

113회​

4교시​

  • 2.블록체인(Block Chain)기술을 정의하고, 블록체인의 생성주체(Public, Private)별 운영 방식의 특징을 정보, 생성, 합의 주체, 규칙 변경, 거래 속도, 거래확정 주체의 관점에서 비교하여 설명하시오.

퍼블릭 블록체인은 누구나 참여 가능한 완전 개방형으로 높은 탈중앙성과 보안성을 가지지만 거래 속도가 느립니다. 프라이빗 블록체인은 허가된 참여자만 접근 가능하여 거래 속도가 빠르고 프라이버시를 보장하지만 탈중앙성이 낮습니다. 합의 주체 측면에서 퍼블릭은 불특정 다수, 프라이빗은 지정된 기관이 담당하여 신뢰 모델이 근본적으로 다릅니다.

116회​

3교시​

  • 3.블록체인(Block Chain) 플랫폼의 보안위협과 대응 방안에 대하여 설명하시오.

블록체인의 주요 보안 위협으로는 51% 공격(해시 파워 과반 장악), 스마트 컨트랙트 취약점, 개인 키 탈취, Sybil 공격 등이 있습니다. 51% 공격은 막대한 연산 비용으로 현실적으로 어렵지만 소규모 블록체인에서는 여전히 위협이 됩니다. 대응 방안으로 스마트 컨트랙트 감사(Audit), 다중 서명(Multi-sig), 하드웨어 지갑, 탈중앙 합의 강화 등이 활용됩니다.

117회​

1교시​

  • 2.하이퍼레저(Hyperledger)

하이퍼레저는 리눅스 재단이 주도하는 기업용 블록체인 기술 개발을 위한 오픈소스 협업 프로젝트입니다. 허가형(Permissioned) 블록체인으로 참여 노드가 식별되며, 채굴 없이 PBFT 계열의 합의 알고리즘을 사용하여 높은 처리 성능을 제공합니다. 하이퍼레저 패브릭(Fabric)이 가장 많이 사용되며 금융, 공급망, 의료 분야에서 기업 블록체인 표준으로 자리잡고 있습니다.

2교시​

  • 5.블록체인(Block Chain)의 Smart Contract는 다양한 기능을 제공하지만 불안한 소스코드로 인해 해킹 및 보안사고의 원인이 되고 있다. Smart Contract Audit에 대하여 설명하시오.

스마트 컨트랙트 감사(Audit)는 배포 전 코드를 전문가가 검토하여 논리적 결함, 재진입 공격(Reentrancy), 정수 오버플로 등 취약점을 식별하는 과정입니다. 블록체인에 배포된 스마트 컨트랙트는 불변성 때문에 취약점 발견 후 수정이 어려워 사전 감사가 필수적입니다. 정적 분석 도구(Mythril, Slither)와 전문 감사 기관을 통한 이중 검증이 권장됩니다.

2교시​

  • 6.분산원장기술에 대하여 설명하고, 퍼블릭(Public) 블록체인과 프라이빗(Private) 블록체인을 비교하시오.

분산원장기술(DLT)은 중앙 기관 없이 네트워크 참여자들이 동일한 데이터 원장을 공유·관리하는 기술로 블록체인이 대표적입니다. 퍼블릭 블록체인은 개방성과 탈중앙화가 특징이며 높은 투명성과 검열 저항성을 제공하지만 처리 속도가 느립니다. 프라이빗 블록체인은 허가된 참여자만 접근하므로 빠른 처리와 높은 프라이버시를 제공하지만 중앙화 리스크가 있습니다.

3교시​

  • 1.비트코인은 이더리움의 계좌잔고모델(Account Balance Model)과 달리 UTXO(Unspent Transaction Output) 기반으로 거래의 유효성을 검사하고 코인의 존재여부를 확인한다.
    • 가.UTXO의 개념을 설명하시오.

UTXO(미사용 거래 출력)는 비트코인 거래 시 이전 거래의 출력 중 아직 사용되지 않은 부분을 의미합니다. 비트코인 잔액은 실제로 존재하지 않고 UTXO의 집합으로 표현되며, 각 거래는 기존 UTXO를 입력으로 소비하고 새로운 UTXO를 출력으로 생성합니다. 이중 지불 방지를 위해 각 UTXO는 단 한 번만 사용 가능하며 전체 네트워크가 유효성을 검증합니다.

  • 나.비트코인 주소A에서 주소B로 3.6BTC(BiTCoin)를 송금하고자 할 때 가장 적은 네트워크 수수료(Transaction Fee)로 거래하는 방법을 아래 조건을 고려하여 설명하시오.

수수료는 거래 크기(바이트)에 비례하므로 입력 UTXO 수를 최소화하면 수수료를 절감할 수 있습니다. 3.6BTC를 충족하는 가장 적은 수의 UTXO를 선택하되, 큰 단위 UTXO를 우선 사용하면 입력 개수가 줄어들고 거래 크기가 작아집니다. 잔돈(Change) UTXO가 생성되면 출력이 늘어나 수수료가 증가하므로 잔돈이 최소화되는 UTXO 조합을 선택하는 것이 최적입니다.

3교시​

  • 4.블록체인의 핵심기술 중 하나인 P2P 통신 중 하이브리드 P2P(Hybrid P2P) 방식과 퓨어 P2P(Pure P2P) 방식을 비교하여 설명하시오.

퓨어 P2P는 중앙 서버 없이 모든 노드가 동등하게 연결되어 완전한 탈중앙성을 실현하지만 노드 탐색 효율이 낮습니다. 하이브리드 P2P는 중앙 인덱스 서버로 노드를 검색하고 실제 데이터 전송은 P2P 방식으로 수행하여 탐색 효율과 확장성을 향상시킵니다. 비트코인은 퓨어 P2P에 가깝고, 초기 냅스터(Napster)는 하이브리드 P2P 방식을 사용하였습니다.

118회​

4교시​

  • 4.스마트 계약(Smart Contract)은 계약 조건을 블록체인에 기록하고 조건이 충족 시 자동으로 계약이 실행되게 하는 프로그램이며, 금융 거래 등 다양한 계약에 활용될 수 있다. 스마트 계약과 관련된 다음을 설명하시오.
    • 가.솔리디티(Solidity)

솔리디티(Solidity)는 이더리움 스마트 컨트랙트 개발을 위해 설계된 정적 타입 프로그래밍 언어입니다. JavaScript, Python, C++의 영향을 받았으며 EVM(이더리움 가상 머신)에서 실행 가능한 바이트코드로 컴파일됩니다. 재진입 공격, 정수 오버플로 등 취약점을 방지하기 위한 신중한 코딩이 요구되며 OpenZeppelin 같은 보안 라이브러리 활용이 권장됩니다.

  • 나.이더리움 가상머신(EVM: Ethereum Virtual Machine)

EVM은 이더리움 네트워크에서 스마트 컨트랙트를 실행하는 격리된 가상 환경으로, 모든 이더리움 노드에서 동일하게 동작합니다. 튜링 완전(Turing-complete) 환경을 제공하여 복잡한 로직을 처리할 수 있으며, 가스(Gas) 메커니즘으로 무한 루프를 방지합니다. EVM의 결정론적 실행 보장으로 모든 노드가 동일한 상태를 유지하는 블록체인 합의가 가능합니다.

  • 다.디앱(DApp, Decentralized Application)

DApp은 블록체인 기반의 스마트 컨트랙트를 백엔드로 사용하는 탈중앙화 애플리케이션으로 중앙 서버에 의존하지 않습니다. 사용자는 지갑(MetaMask 등)을 통해 DApp과 상호작용하며 모든 거래 기록이 블록체인에 투명하게 저장됩니다. DeFi(탈중앙화 금융), NFT 마켓플레이스, 분산 거버넌스 등이 대표적인 DApp 활용 사례입니다.

119회​

1교시​

  • 11.머클트리(Merkle Tree)

머클 트리는 각 데이터 블록의 해시값을 리프 노드로 하여 부모 노드가 두 자식 해시의 결합 해시가 되는 이진 트리 구조입니다. 루트 해시(머클 루트) 하나로 트리 내 모든 데이터의 무결성을 검증할 수 있어 블록체인에서 거래 검증에 필수적으로 사용됩니다. SPV(단순 지불 검증) 노드는 전체 블록 없이 머클 경로만으로 특정 거래의 포함 여부를 효율적으로 확인합니다.

  • 4.DID(Decentralized Identity)

DID는 중앙화된 신원 제공자 없이 블록체인 기반으로 개인이 스스로 신원을 관리·통제하는 탈중앙 신원 체계입니다. W3C DID 표준에 따라 DID 식별자, DID 문서, 검증 가능한 자격증명(VC)으로 구성됩니다. 개인정보의 선택적 공개와 자기 주권 신원(SSI, Self-Sovereign Identity)을 실현하여 프라이버시를 강화합니다.

2교시​

  • 6.기업에 블록체인기술을 도입하기 위한 보안 고려사항을 설명하시오.

기업 블록체인 도입 시 스마트 컨트랙트 코드 취약점, 개인 키 관리, 합의 알고리즘의 보안성을 우선 검토해야 합니다. 프라이빗 블록체인은 허가된 참여자 인증 체계와 데이터 암호화가 필수적이며 네트워크 레이어 보안도 강화해야 합니다. 정기적인 스마트 컨트랙트 감사, 다중 서명, 하드웨어 보안 모듈(HSM) 활용이 기업 블록체인 보안의 핵심 대책입니다.

3교시​

  • 1.4차 산업의 핵심기술로 부상하고 있는 Digital Twin 기술을 활용하여 스마트 시티를 구현하려고 한다.

디지털 트윈 기반 스마트 시티는 실제 도시의 물리적 자산과 인프라를 가상 공간에 동일하게 복제하여 실시간으로 시뮬레이션하고 최적화하는 개념입니다. IoT 센서로 수집한 실시간 데이터를 디지털 트윈에 반영하여 교통, 에너지, 안전 등 도시 서비스를 최적화합니다. 블록체인은 디지털 트윈 데이터의 신뢰성과 무결성을 보장하는 데 활용될 수 있습니다.

120회​

4교시​

  • 6.블록체인 플랫폼 구축과정에서 성능 및 보안 측면의 고려사항을 설명하시오.

성능 측면에서 TPS(초당 거래 처리량), 블록 생성 시간, 네트워크 지연을 최소화하기 위한 합의 알고리즘 선택과 샤딩(Sharding) 기법 적용을 고려해야 합니다. 보안 측면에서 합의 공격(51% 공격), 스마트 컨트랙트 취약점, 개인 키 탈취, Sybil 공격에 대한 방어 메커니즘을 설계해야 합니다. 성능과 보안은 상충 관계에 있어 비즈니스 요구사항에 맞는 적절한 균형점을 찾는 것이 중요합니다.

122회​

2교시​

  • 2.블록체인 합의 알고리즘(Consensus Algorithm)에 대하여 다음을 설명하시오.
    • 가.합의 알고리즘의 목적

블록체인 합의 알고리즘은 중앙 권위 없이 분산된 참여자들이 동일한 원장 상태에 동의하도록 하는 메커니즘입니다. 비잔틴 장애(악의적 노드 포함) 환경에서도 네트워크 전체가 올바른 데이터 상태를 유지하고 이중 지불을 방지하는 것이 주요 목적입니다. 탈중앙화, 보안성, 확장성(성능)의 세 가지를 동시에 달성하기 어려운 블록체인 트릴레마 극복이 합의 설계의 핵심 과제입니다.

  • 나.합의 알고리즘의 원리

합의 알고리즘은 새로운 블록을 제안할 권한을 공정하게 배분하고, 제안된 블록의 유효성을 다수 노드가 검증하여 승인하는 원리로 작동합니다. 모든 정직한 노드가 동일한 블록을 최종 블록으로 수락하는 합의(Finality)가 달성되면 해당 거래는 불변으로 간주됩니다. 네트워크 분할(Partition) 상황에서 일관성(Consistency)과 가용성(Availability) 중 무엇을 우선할지 CAP 이론을 기반으로 설계됩니다.

  • 다.합의 알고리즘의 종류 및 특징

PoW(작업 증명)는 해시 퍼즐 풀기 경쟁으로 보안성이 높지만 에너지 소비가 막대합니다. PoS(지분 증명)는 코인 보유량 비례로 검증 권한을 부여하여 에너지 효율적이며 이더리움 2.0이 채택하였습니다. PBFT(실용적 비잔틴 장애 허용)는 기업형 블록체인에서 빠른 합의와 즉각적인 완결성을 제공하지만 참여 노드 수가 제한됩니다.

3교시​

  • 3.분산 ID(Decentralized Identity)와 관련하여 다음을 설명하시오.
    • 가.개념 및 등장배경

분산 ID(DID)는 중앙화된 신원 제공자 없이 개인이 자신의 디지털 신원을 완전히 소유하고 통제하는 개념입니다. 기존 중앙화 신원 체계(소셜 로그인 등)의 개인정보 독점, 침해 위험, 서비스 종료 시 신원 소멸 문제를 해결하기 위해 등장하였습니다. 블록체인과 W3C DID 표준을 기반으로 하며 자기 주권 신원(SSI) 개념의 기술적 구현체입니다.

  • 나.신원증명 발전 단계

신원증명은 중앙화 신원(사일로형) → 연합 신원(소셜 로그인) → 사용자 중심 신원 → 자기 주권 신원(SSI/DID)의 4단계로 발전하였습니다. 초기에는 서비스별로 분리된 계정 관리였다가 점차 사용자 통제권이 강화되는 방향으로 진화하였습니다. DID는 최종 단계로서 신원 데이터의 완전한 소유권을 개인에게 돌려주는 패러다임 전환을 의미합니다.

  • 다.특징 및 기본 구조도

DID의 핵심 특징은 개인정보 최소 공개(선택적 공개), 검증 가능성, 탈중앙성, 이식성입니다. 기본 구조는 DID 주체(Subject), DID 식별자, DID 문서(공개키·서비스 엔드포인트 포함), 검증 가능한 자격증명(VC), DID 레지스트리(블록체인)로 구성됩니다. 발행자(Issuer)-소유자(Holder)-검증자(Verifier)의 신뢰 삼각형이 DID 에코시스템의 기본 모델입니다.

  • 라.활용 분야

DID는 금융권 비대면 실명확인(KYC), 공공기관 디지털 신분증, 의료 기록 관리, 학력·자격증 검증 등 다양한 분야에 활용됩니다. 메타버스 환경에서 디지털 아바타의 신원 증명과 NFT 소유권 연계에도 DID가 적용됩니다. 데이터 3법 개정과 마이데이터 제도 시행으로 DID 기반 개인 데이터 관리 플랫폼의 수요가 급증하고 있습니다.

4교시​

  • 5.퍼블릭(Public) 블록체인과 프라이빗(Private) 블록체인의 차이점을 비교하여 설명하시오.

퍼블릭 블록체인은 누구나 참여·열람 가능하며 완전한 탈중앙화와 높은 보안성을 제공하지만 처리 속도가 느리고 에너지 소비가 큽니다. 프라이빗 블록체인은 허가된 조직·개인만 참여할 수 있어 빠른 처리 속도와 높은 프라이버시를 제공하지만 탈중앙성이 낮습니다. 기업 환경에서는 성능과 프라이버시가 중요하여 프라이빗 또는 컨소시엄 블록체인을 주로 선택합니다.

2교시​

  • 5.퍼블릭 블록체인(Public Blockchain), 프라이빗 블록체인(Private Block Chain), 하이브리드 블록체인(Hybrid Blockchain)을 비교 설명하시오.

퍼블릭은 완전 개방형, 프라이빗은 허가형 폐쇄형, 하이브리드는 두 방식을 결합한 형태입니다. 하이브리드 블록체인은 민감 데이터는 프라이빗 체인에서 처리하고 검증 결과만 퍼블릭 체인에 앵커링하여 프라이버시와 투명성을 동시에 확보합니다. 금융기관의 규제 준수 요구와 투명성 확보를 동시에 만족시키는 하이브리드 구조가 기업 블록체인의 현실적인 대안으로 주목받고 있습니다.

3교시​

  • 2.데이터저장 측면에서 파일, 데이터베이스, 블록체인을 비교하시오.

파일 시스템은 단순 데이터 저장에 적합하지만 구조화된 쿼리와 동시성 제어가 어렵습니다. 데이터베이스는 구조화된 데이터를 효율적으로 저장·조회하고 ACID 트랜잭션을 지원하지만 중앙화 구조로 단일 장애점이 존재합니다. 블록체인은 분산 저장으로 탈중앙성과 불변성을 보장하지만 저장 비용이 높고 수정·삭제가 불가능하여 일반 데이터 저장에는 적합하지 않습니다.
