데이터베이스

정보관리기술사 기출문제 중 데이터베이스 관련 문제를 정리한 페이지입니다.

110회​

4교시​

  • 4.SQL에서 정의하는 JOIN의 유형을 기술하고, JOIN 성능을 높이기 위한 기법을 사례를 들어 설명하시오.

SQL JOIN은 INNER JOIN, LEFT/RIGHT OUTER JOIN, FULL OUTER JOIN, CROSS JOIN 등 여러 유형으로 구성됩니다. 성능 향상을 위해 인덱스를 활용한 Nested Loop Join, 정렬 기반의 Sort-Merge Join, 해시 기반의 Hash Join 기법을 상황에 따라 선택합니다. 대용량 데이터 처리 시 조인 순서 최적화와 인덱스 설계가 핵심입니다.

111회​

1교시​

  • 8.다중 버전 동시성 제어(MVCC : Multi Version Concurrency Control)

MVCC는 데이터의 여러 버전을 동시에 유지하여 읽기와 쓰기 간의 충돌을 최소화하는 동시성 제어 기법입니다. 읽기 작업은 이전 버전의 스냅샷을 참조하므로 잠금 없이 수행되어 처리량을 높입니다. PostgreSQL, MySQL InnoDB 등 주요 DBMS에서 채택하고 있습니다.

2교시​

  • 1.RDBMS의 Dirty Read와 Phantom Read를 설명하시오.

Dirty Read는 아직 커밋되지 않은 다른 트랜잭션의 변경 데이터를 읽는 현상으로, 롤백 시 잘못된 데이터를 참조하게 됩니다. Phantom Read는 같은 쿼리를 두 번 실행했을 때 중간에 다른 트랜잭션이 행을 삽입하여 결과가 달라지는 현상입니다. 격리 수준을 높여 이러한 이상 현상을 방지할 수 있습니다.

4교시​

  • 3.공간 인덱스 구조에서 MBR(Minimym Bounding Region)을 설명하고, R트리, R+트리, R*트리를 비교하시오.

MBR(최소 경계 사각형)은 공간 객체를 포함하는 최소 크기의 직사각형으로, 공간 인덱스의 기본 단위입니다. R트리는 MBR이 겹칠 수 있으며, R+트리는 겹침을 허용하지 않아 검색 효율이 높습니다. R*트리는 R트리를 개선하여 겹침과 면적을 최소화하는 재삽입 전략을 적용합니다.

113회​

1교시​

  • 2.데이터베이스 카디널리티(Database Cardinality)

카디널리티는 릴레이션에서 튜플(행)의 수 또는 속성이 가질 수 있는 고유값의 수를 의미합니다. 인덱스 선택 시 카디널리티가 높은 컬럼(고유값 많음)일수록 인덱스 효율이 높습니다. ER 모델에서는 엔티티 간의 관계 수(1:1, 1:N, M:N)를 나타내기도 합니다.

  • 6.그래프 데이터베이스(Graph Database)

그래프 데이터베이스는 노드(Node)와 엣지(Edge)로 데이터와 관계를 표현하는 NoSQL 데이터베이스입니다. 소셜 네트워크, 추천 시스템, 지식 그래프처럼 복잡한 연결 관계를 효율적으로 탐색할 수 있습니다. Neo4j가 대표적인 구현체이며 Cypher 쿼리 언어를 사용합니다.

3교시​

  • 1.NoSQL 특징, 데이터 모델링 패턴 및 데이터 모델링 절차에 대하여 설명하시오.

NoSQL은 스키마 유연성, 수평 확장성, 고가용성을 특징으로 하며 Key-Value, Document, Column Family, Graph 등의 모델로 분류됩니다. 모델링 패턴으로는 임베딩(Embedding), 참조(Reference), 버킷(Bucket) 패턴 등이 있습니다. 절차는 도메인 분석 → 쿼리 패턴 정의 → 데이터 모델 설계 → 최적화 순으로 진행됩니다.

  • 3.데이터웨어하우스에서 다차원 온라인분석처리(MOLAP)의 설계방법과 고려사항을 설명하고, 다음의 요구사항에 맞는 다차원 데이터 큐브를 설계하시오.

MOLAP은 데이터를 다차원 큐브 구조로 사전 집계하여 저장함으로써 빠른 분석 쿼리를 지원합니다. 설계 시 차원(Dimension)과 측도(Measure)를 명확히 정의하고, 스파스 데이터 처리 방안을 고려해야 합니다. 큐브 설계는 사실 테이블과 차원 테이블로 구성되는 스타 스키마 또는 스노우플레이크 스키마를 기반으로 합니다.

4교시​

  • 3.병렬 데이터베이스와 분산 데이터베이스를 비교하여 설명하시오.

병렬 데이터베이스는 단일 시스템 내에서 여러 프로세서가 동시에 쿼리를 처리하여 성능을 높이는 방식입니다. 분산 데이터베이스는 네트워크로 연결된 여러 독립 노드에 데이터를 분산 저장하고 관리합니다. 병렬 DB는 처리 속도 향상에, 분산 DB는 가용성과 지리적 분산에 초점을 둡니다.

115회​

1교시​

  • 2.SQL(Structured Query Language)

SQL은 관계형 데이터베이스에서 데이터를 정의, 조작, 제어하기 위한 표준 질의 언어입니다. DDL(데이터 정의), DML(데이터 조작), DCL(데이터 제어), TCL(트랜잭션 제어)로 구분됩니다. ANSI/ISO 표준을 기반으로 하며 대부분의 RDBMS에서 지원합니다.

  • 13.힐버트(Hilbert) R-tree

힐버트 R-tree는 힐버트 곡선을 이용하여 공간 객체에 선형 순서를 부여하고, 이를 기반으로 R-tree를 구성하는 공간 인덱스입니다. 힐버트 곡선의 공간 지역성 보존 특성 덕분에 인접한 객체가 같은 노드에 묶일 가능성이 높아 검색 효율이 향상됩니다. 기존 R-tree 대비 노드 활용도와 쿼리 성능이 개선됩니다.

117회​

1교시​

  • 9.NoSQL

NoSQL은 'Not Only SQL'의 약자로, 관계형 모델을 벗어나 유연한 스키마와 수평 확장을 지원하는 데이터베이스 유형입니다. Key-Value Store, Document Store, Column Family Store, Graph DB 등 다양한 모델이 존재합니다. 빅데이터와 실시간 웹 애플리케이션 환경에서 주로 활용됩니다.

  • 10.인메모리 데이터베이스(In-memory Database)

인메모리 데이터베이스는 데이터를 디스크가 아닌 주메모리(RAM)에 저장하여 디스크 I/O를 제거함으로써 극단적으로 빠른 응답 속도를 제공합니다. 캐싱, 세션 관리, 실시간 분석 등 지연 시간에 민감한 워크로드에 적합합니다. Redis, SAP HANA, VoltDB가 대표적인 구현체입니다.

2교시​

  • 3.동적 SQL 개념, 장점, 단점에 대하여 설명하시오.

동적 SQL은 실행 시점에 SQL 문자열을 생성하고 실행하는 방식으로, 쿼리 구조가 런타임에 결정됩니다. 장점은 유연한 쿼리 생성과 다양한 조건 처리가 가능하다는 것이며, 단점은 SQL 인젝션 위험과 실행 계획 재사용 불가로 인한 성능 저하입니다. 정적 SQL은 사전 컴파일로 안전하고 빠르지만 유연성이 떨어집니다.

4교시​

  • 3.병렬 데이터베이스와 분산 데이터베이스를 비교하여 설명하시오.

병렬 데이터베이스는 단일 시스템 내에서 여러 프로세서가 동시에 쿼리를 처리하여 성능을 높이는 방식입니다. 분산 데이터베이스는 네트워크로 연결된 여러 독립 노드에 데이터를 분산 저장하고 관리합니다. 병렬 DB는 처리 속도 향상에, 분산 DB는 가용성과 지리적 분산에 초점을 둡니다.

118회​

1교시​

  • 1.정규화(Normalization)의 의미와 효과

정규화는 데이터베이스 설계에서 데이터 중복을 제거하고 이상 현상을 방지하기 위해 릴레이션을 분해하는 과정입니다. 1NF부터 BCNF까지 단계적으로 적용하며 삽입, 삭제, 갱신 이상을 해소합니다. 데이터 일관성과 무결성이 향상되지만 과도한 정규화는 조인 증가로 성능 저하를 유발할 수 있습니다.

3교시​

  • 1.데이터 웨어하우스에 적용되는 온라인 분석처리(OLAP, On-Line Analytical Processing)를 온라인 트랜잭션처리(OLTP, On-Line Transaction Processing)와 비교하여 설명하고, 분석정보 데이터베이스(데이터 웨어하우스)와 운영정보 데이터베이스(운영 데이터베이스)가 분리 운영되어야 하는 이유에 대하여 설명하시오.

OLTP는 일상적인 업무 트랜잭션을 빠르게 처리하는 반면, OLAP는 대용량 데이터를 다차원으로 분석하는 데 최적화되어 있습니다. 두 시스템이 동일한 DB를 공유하면 분석 쿼리의 대용량 스캔이 운영 트랜잭션 성능에 영향을 미칩니다. 따라서 운영 DB와 데이터 웨어하우스를 분리하여 각각의 목적에 맞게 최적화하는 것이 필수적입니다.

119회​

1교시​

  • 8.데이터베이스 샤드(database shard)

데이터베이스 샤드는 대용량 데이터를 여러 데이터베이스 서버에 수평으로 분할하여 저장하는 기법입니다. 각 샤드는 전체 데이터의 일부를 독립적으로 저장하고 처리하여 단일 서버의 한계를 극복합니다. 샤딩 키 선정이 중요하며, 범위(Range), 해시(Hash), 디렉토리(Directory) 방식으로 분할합니다.

  • 13.데이터베이스의 Isolation Level

트랜잭션 격리 수준은 동시 실행되는 트랜잭션 간의 데이터 가시성을 제어하는 설정입니다. Read Uncommitted, Read Committed, Repeatable Read, Serializable의 4단계로 구성됩니다. 격리 수준이 높을수록 데이터 일관성이 보장되지만 동시성이 낮아져 성능이 저하됩니다.

121회​

2교시​

  • 2.DBMS 병행수행(Concurrency)제어가 되지 않는 경우 발생할 수 있는 3가지 문제와 그 해결방법에 대하여 예시를 들어 각각 설명하시오.

병행 수행 제어가 없으면 갱신 분실(Lost Update), 미완료 의존성(Dirty Read), 부정확한 분석(Inconsistent Analysis)의 세 가지 문제가 발생합니다. 갱신 분실은 두 트랜잭션이 같은 데이터를 동시에 수정할 때 한 쪽의 변경이 사라지는 현상입니다. 이를 해결하기 위해 잠금(Locking), 타임스탬프(Timestamp), MVCC 등의 기법을 사용합니다.

4교시​

  • 6.B기업은 공급자(Suppliers)와 상품(Products) 데이터베이스를 다음 조건과 같이 설계중이다. 다음에 대하여 작성하시오.
    • 가. 바커(Barker) 표기법으로 표현된 ERD
    • 나. 도메인과 테이블을 생성하는 DDL
    • 다. 'P02' 상품을 공급하는 서울소재 공급자의 SNAME을 조회하는 SQL

바커(Barker) 표기법은 Oracle에서 주로 사용하는 ERD 표기법으로 실선/점선으로 필수/선택 관계를 표현합니다. 공급자와 상품은 다대다(M:N) 관계이므로 공급(Supply) 교차 엔티티를 통해 분해합니다. DDL로 테이블을 생성하고 JOIN 기반 SELECT문으로 원하는 데이터를 조회합니다.

122회​

1교시​

  • 13.스타 스키마(Star Schema)

스타 스키마는 데이터 웨어하우스에서 중앙의 사실 테이블(Fact Table)과 이를 둘러싼 차원 테이블(Dimension Table)로 구성되는 스키마 구조입니다. 별(Star) 모양의 구조로 쿼리가 단순하고 조인 횟수가 적어 분석 성능이 우수합니다. 비정규화된 차원 테이블을 사용하므로 저장 공간이 더 필요하지만 쿼리 속도가 빠릅니다.

4교시​

  • 5.아래 조건으로 학생과 수강신청서 간의 관계에 대하여 다음을 작성하시오.
    • 가. ERD(Entity Relationship Diagram)
    • 나. 관계형 데이터 모델(Relational Data Model)

ERD는 엔티티(Entity), 속성(Attribute), 관계(Relationship)를 시각적으로 표현한 데이터 모델링 도구입니다. 학생과 수강신청서는 1:N 관계로, 한 학생이 여러 수강신청을 할 수 있습니다. 관계형 데이터 모델로 변환 시 외래 키(FK)를 통해 두 테이블 간의 관계를 표현합니다.

123회​

1교시​

  • 11.Column Family 데이터베이스

Column Family 데이터베이스는 행(Row)과 열 패밀리(Column Family)를 기반으로 데이터를 저장하는 NoSQL 유형입니다. 관련 열들을 묶어 Column Family로 관리하며, 행마다 다른 열을 가질 수 있는 유연한 스키마를 지원합니다. Apache Cassandra, HBase가 대표적이며 대규모 분산 환경에서 쓰기 성능이 뛰어납니다.

124회​

1교시​

  • 8.데이터베이스 제5정규형

제5정규형(5NF)은 조인 종속성(Join Dependency)을 제거하여 릴레이션을 더 이상 무손실 분해할 수 없는 상태를 의미합니다. 릴레이션이 세 개 이상의 테이블로 분해될 때 발생하는 조인 종속을 제거하는 단계입니다. 제4정규형(4NF) 이후 적용되며 실무에서는 적용 빈도가 낮습니다.

트랜잭션 격리 수준은 동시 트랜잭션 간 데이터 가시성을 조절하는 4단계 설정입니다. Read Uncommitted는 커밋 전 데이터까지 읽고, Read Committed는 커밋된 데이터만 읽으며, Repeatable Read는 반복 읽기를 보장하고, Serializable은 완전한 직렬화를 보장합니다. 격리 수준이 높을수록 일관성은 높아지지만 동시성과 성능은 저하됩니다.

3교시​

  • 5.다차원 색인구조(Multidimensional Index Structure)의 개념, 유형, 활용 사례에 대하여 설명하시오.

다차원 색인구조는 2차원 이상의 데이터를 효율적으로 검색하기 위한 인덱스 구조로 공간 데이터 처리에 필수적입니다. R-tree, KD-tree, Quad-tree, Grid File 등의 유형이 있으며 각각 다른 분할 전략을 사용합니다. GIS 지도 검색, 이미지 유사도 검색, 위치 기반 서비스에서 활용됩니다.

4교시​

  • 1.확장성 해싱(Extendible Hashing)기법에 대하여 다음을 설명하시오.
    • 가. 개념 및 구성요소
    • 나. 충돌회피 기법

확장성 해싱은 데이터 증가에 따라 동적으로 버킷 수를 늘릴 수 있는 동적 해싱 기법으로, 디렉토리와 버킷으로 구성됩니다. 디렉토리는 해시 비트 접두사를 기반으로 버킷 포인터를 관리하며, 버킷 오버플로우 시 디렉토리 크기를 두 배로 늘리는 분할(Split) 연산을 수행합니다. 충돌 회피는 버킷 분할 및 디렉토리 확장을 통해 처리하며 전체 재해싱 없이 점진적 확장이 가능합니다.

  • 2.릴레이션 무결성 제약의 유형과 사례를 제시하고, 구현 방법에 대하여 설명하시오.

릴레이션 무결성 제약은 데이터베이스의 데이터 정확성과 일관성을 보장하기 위한 규칙입니다. 도메인 무결성, 개체 무결성(NULL 불허 PK), 참조 무결성(FK), 사용자 정의 무결성으로 분류됩니다. SQL의 PRIMARY KEY, FOREIGN KEY, CHECK, NOT NULL, UNIQUE 제약 조건으로 구현합니다.

135회​

1교시​

  • 4.제4정규형

제4정규형(4NF)은 BCNF를 만족하면서 다치 종속(Multi-valued Dependency)을 제거한 정규형입니다. 하나의 릴레이션에 독립적인 다치 종속이 둘 이상 존재할 때 이상 현상이 발생하며, 이를 별도의 릴레이션으로 분해하여 해결합니다. 3NF와 BCNF 이후 적용되는 고급 정규화 단계입니다.

2교시​

  • 5.데이터베이스 인덱스(Index)를 설명하고, 클러스터드 인덱스(Clustered Index)와 논클러스터드 인덱스(Non-Clustered Index)를 비교하여 설명하시오.

인덱스는 데이터 검색 속도를 높이기 위해 특정 컬럼 값과 레코드 위치를 매핑한 자료 구조입니다. 클러스터드 인덱스는 데이터가 인덱스 순서로 물리적으로 정렬 저장되며 테이블당 하나만 생성 가능합니다. 논클러스터드 인덱스는 데이터와 별도로 인덱스 구조만 유지하며 여러 개 생성이 가능합니다.

136회​

2교시​

  • 6.TEXT2SQL에 대하여 다음 각 항목을 설명하시오.
    • 가. TEXT2SQL의 개념
    • 나. TEXT2SQL 활용 사례 2가지

TEXT2SQL은 자연어 질문을 자동으로 SQL 쿼리로 변환하는 기술로, 대규모 언어 모델(LLM)을 활용합니다. 비전문가도 데이터베이스에서 원하는 정보를 자연어로 조회할 수 있게 하여 데이터 접근성을 높입니다. 활용 사례로는 BI 도구에서의 자연어 보고서 생성, 고객 서비스 챗봇의 데이터 조회 등이 있습니다.

3교시​

  • 4.데이터베이스 트랜잭션 격리 수준(Transaction Isolation Level)과 관련하여 아래 사항을 설명하시오.
    • 가. 데이터베이스 트랜잭션 격리 수준 4가지
    • 나. 데이터베이스 트랜잭션 격리 수준에 따라 발생할 수 있는 이상 현상

트랜잭션 격리 수준은 Read Uncommitted, Read Committed, Repeatable Read, Serializable의 4단계로 구성됩니다. 격리 수준이 낮을수록 Dirty Read, Non-Repeatable Read, Phantom Read 등의 이상 현상이 발생할 수 있습니다. 적절한 격리 수준 선택은 데이터 일관성과 시스템 성능 사이의 균형을 결정합니다.

4교시​

  • 2.벡터 데이터베이스(Vector Database)의 효율적 검색을 위한 HNSW(Hierarchical Navigable Small World)와 IVF(Inverted File Index)의 동작원리를 설명하시오.

벡터 데이터베이스는 임베딩 벡터를 저장하고 유사도 기반 검색을 지원하는 데이터베이스로 AI/ML 응용에 활용됩니다. HNSW는 계층적 그래프 구조로 근사 최근접 이웃(ANN) 검색을 수행하며 높은 정확도와 빠른 검색 속도를 제공합니다. IVF는 벡터 공간을 클러스터로 분할하고 역색인을 이용해 후보 클러스터만 검색하여 효율을 높입니다.

137회​

1교시​

  • 9.정보모델링의 참조 무결성

참조 무결성은 외래 키(FK)가 참조하는 부모 테이블의 기본 키(PK)가 반드시 존재해야 한다는 데이터 무결성 규칙입니다. 자식 테이블에 존재하지 않는 부모 키를 참조하거나, 자식이 참조 중인 부모 레코드를 삭제하는 것을 방지합니다. CASCADE, SET NULL, RESTRICT 등의 옵션으로 참조 무결성 위반 시 처리 방식을 지정합니다.

2교시​

  • 1.최근 상용 DBMS를 오픈소스 DBMS로 전환하는 수요가 늘고 있다. 다음 내용을 설명하시오.
    • 가. 오픈소스 DBMS 전환 배경
    • 나. 오픈소스 DBMS 전환 시 검토해야 할 제약사항
    • 다. 오픈소스 DBMS 전환 시 단계별 마이그레이션 절차
    • 라. 신뢰성 확보를 위한 고가용성(HA) 아키텍처 구성 방안

오픈소스 DBMS 전환은 라이선스 비용 절감, 벤더 종속성 탈피, 클라우드 친화성 확보를 위해 증가하고 있습니다. 전환 시 SQL 방언 차이, 저장 프로시저 호환성, 성능 특성 차이 등의 제약사항을 면밀히 검토해야 합니다. 마이그레이션은 현황 분석 → 대상 선정 → 변환 및 검증 → 파일럿 → 전환의 단계로 진행하며, HA 구성은 Master-Slave 복제 또는 Patroni 같은 클러스터 솔루션을 활용합니다.

3교시​

  • 3.분산 데이터베이스 시스템 구축을 위한 데이터베이스 분할에 대하여 다음 내용을 설명하시오.
    • 가. 데이터베이스 분할 단위
    • 나. 수평분할과 수직분할

분산 데이터베이스의 분할 단위는 테이블을 행 단위로 나누는 수평 분할과 열 단위로 나누는 수직 분할로 구분됩니다. 수평 분할은 특정 조건(범위, 해시 등)에 따라 레코드를 여러 노드에 분산하여 부하를 균등하게 합니다. 수직 분할은 자주 접근하는 컬럼과 그렇지 않은 컬럼을 분리하여 I/O 효율을 높입니다.

138회​

1교시​

  • 8.데이터 관측가능성(Data Observability)

데이터 관측가능성은 데이터 파이프라인과 데이터 시스템의 상태를 지속적으로 모니터링하고 이상을 감지하는 역량을 의미합니다. 신선도(Freshness), 분포(Distribution), 볼륨(Volume), 스키마(Schema), 계보(Lineage)의 5가지 핵심 요소로 구성됩니다. 데이터 품질 문제를 사전에 감지하고 신뢰할 수 있는 데이터 환경을 구축하는 데 활용됩니다.
