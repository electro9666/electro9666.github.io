컴퓨터구조 및 운영체제 개념 상세설명 (비유로 쉽게 이해하기)

정보관리기술사 기출 키워드 기반 각 개념을 일상생활의 비유를 통해 쉽게 설명합니다.

1. CPU​

1.1 컴퓨터 구조 모델​

폰 노이만 구조(Von Neumann Architecture)​

비유: 한 줄로 된 좁은 복도 식당

주방(CPU)과 창고(메모리)가 하나의 좁은 복도(버스)로 연결되어 있다. 재료(데이터)와 레시피(명령어)가 같은 창고에 보관되고, 같은 복도를 통해 운반된다. 한 번에 하나만 옮길 수 있어 복도가 병목이 된다. 이것이 "폰 노이만 병목(Von Neumann Bottleneck)"이다. 현대 대부분의 컴퓨터가 이 구조를 기반으로 한다.

하버드 구조(Harvard Architecture)​

비유: 복도가 두 개인 식당

레시피 전용 복도(명령어 버스)와 재료 전용 복도(데이터 버스)가 따로 있다. 동시에 레시피를 읽으면서 재료를 운반할 수 있어 속도가 빠르다. DSP(디지털 신호 처리기)나 마이크로컨트롤러에서 주로 사용한다.

1.2 명령어 집합 구조​

RISC(Reduced Instruction Set Computer)​

비유: 기본 도구만 있는 공구 세트

드라이버, 망치, 펜치 같은 기본 도구만 있다. 각 도구는 단순하고 사용법이 동일하다. 복잡한 작업은 기본 도구를 조합해서 한다. 명령어가 단순하고 길이가 고정되어 파이프라인 처리에 유리하다. ARM 프로세서가 대표적이다.

CISC(Complex Instruction Set Computer)​

비유: 만능 멀티툴 공구 세트

가위, 칼, 드라이버, 캔따개, 톱이 한 몸에 붙어 있는 스위스 아미 나이프다. 하나의 도구(명령어)로 복잡한 작업을 한 번에 할 수 있지만, 도구마다 크기와 사용법이 다르다. 명령어 길이가 가변적이고 종류가 많다. x86 프로세서가 대표적이다.

1.3 명령어 실행​

명령어 사이클(Instruction Cycle)​

비유: 세탁기의 작동 단계

세탁기가 "급수 - 세탁 - 헹굼 - 탈수"를 반복하듯, CPU는 "인출(Fetch) - 해독(Decode) - 실행(Execute) - 저장(Store)"을 끊임없이 반복한다. 하나의 명령어를 처리하는 전체 과정이 하나의 사이클이다.

파이프라인(Pipeline)​

비유: 자동차 조립 라인

한 명이 자동차를 처음부터 끝까지 만드는 대신, 컨베이어 벨트 위에서 "차체 조립 - 엔진 장착 - 도색 - 검수" 각 단계를 다른 작업자가 동시에 수행한다. 첫 번째 차가 엔진 장착 단계에 있을 때, 두 번째 차는 이미 차체 조립 중이다. 각 단계가 겹쳐 실행되어 전체 처리량이 크게 증가한다.

해저드(Hazard)​

비유: 조립 라인의 정체 원인

조립 라인이 원활하게 흘러가지 못하는 상황이다.

  • 구조적 해저드(Structural Hazard): 도색 부스가 하나뿐인데 두 대가 동시에 도색하려는 상황. 하드웨어 자원이 부족해서 발생한다.
  • 데이터 해저드(Data Hazard): 2번 작업자가 1번 작업자의 결과물이 있어야 진행할 수 있는데 아직 안 나온 상황. 이전 명령어의 결과를 다음 명령어가 필요로 할 때 발생한다.
  • 제어 해저드(Control Hazard): 조립 라인에서 다음에 어떤 차를 올려야 할지 모르는 상황. 분기 명령어(if/else)로 인해 다음 실행할 명령어가 불확실할 때 발생한다.

분기 예측(Branch Prediction)​

비유: 내비게이션의 경로 예측

교차로에 도착하기 전에 "아마 좌회전할 것"이라고 미리 예측하고 준비하는 것이다. 예측이 맞으면 시간을 절약하고, 틀리면(분기 예측 실패) 되돌아가야 해서 손해가 생긴다. 현대 CPU는 90% 이상의 적중률을 보인다.

1.4 고성능 CPU 기법​

슈퍼스칼라(Superscalar)​

비유: 다차선 고속도로

1차선(단일 파이프라인)이 아니라 2~4차선(다중 파이프라인)으로 동시에 여러 명령어를 실행한다. 한 사이클에 여러 명령어를 동시 인출, 해독, 실행할 수 있다.

OoO(Out-of-Order Execution, 비순차 실행)​

비유: 식당에서 빨리 되는 메뉴 먼저 나오기

주문 순서대로 나오지 않고, 조리가 빨리 끝나는 음식부터 먼저 나온다. CPU도 앞선 명령어가 대기 중이면 뒤의 독립적인 명령어를 먼저 실행한다. 단, 최종 결과는 원래 순서대로 정리(커밋)한다.

1.5 CPU 보안 취약점​

스펙터(Spectre)​

비유: 미리 읽어둔 비밀 편지의 흔적

분기 예측을 악용한다. CPU가 "아마 이 경로로 갈 것"이라고 예측하고 미리 데이터를 읽어두는데, 예측이 틀려 결과를 폐기해도 캐시에 흔적이 남는다. 공격자는 이 흔적(타이밍 차이)을 분석해 비밀 데이터를 유추한다. 거의 모든 현대 CPU가 영향을 받는다.

멜트다운(Meltdown)​

비유: 임시로 열린 금고 문 틈새로 엿보기

비순차 실행을 악용한다. CPU가 권한 검사를 하기 전에 미리 데이터를 읽어두는 순간을 노린다. 일반 프로그램이 커널(운영체제) 메모리를 엿볼 수 있는 심각한 취약점이다. 주로 Intel CPU에서 발견되었다.

1.6 GPU 및 특수 프로세서​

GPGPU(General-Purpose computing on GPU)​

비유: 단순 노동에 아르바이트생 수백 명 투입

GPU는 수천 개의 작은 코어를 가지고 있다. 원래 그래픽(화면의 수백만 픽셀을 동시 계산) 전용이었지만, 단순 반복 계산이 많은 범용 작업(과학 연산, AI 학습)에도 활용하는 것이 GPGPU다. CUDA, OpenCL이 대표적 프레임워크다.

GPU vs TPU​

  • GPU(Graphics Processing Unit): 수천 명의 아르바이트생. 단순 반복 작업을 대규모 병렬로 처리한다. 그래픽, AI 학습 등 범용적이다.
  • TPU(Tensor Processing Unit): 행렬 곱셈 전문 계산기. 구글이 만든 AI 연산 전용 칩으로, 텐서(다차원 배열) 연산에 최적화되어 AI 학습과 추론 속도가 GPU보다 빠르다.

뉴로모픽 칩(Neuromorphic Chip)​

비유: 인간 뇌를 모방한 반도체

기존 CPU가 "계산기"라면, 뉴로모픽 칩은 "인공 두뇌"다. 뉴런과 시냅스의 동작 방식을 하드웨어로 구현하여 극도로 낮은 전력으로 패턴 인식 등을 처리한다. Intel의 Loihi가 대표적이다.

NPU(Neural Processing Unit)​

비유: 스마트폰 속 AI 전담 비서

스마트폰이나 PC에 내장된 AI 전용 프로세서다. 사진 보정, 음성 인식, 번역 같은 AI 작업을 CPU나 GPU 대신 전담하여 빠르고 전력 소모가 적다.

FPGA(Field Programmable Gate Array)​

비유: 레고로 만드는 맞춤형 회로

완성된 칩을 사는 것이 아니라, 레고 블록(로직 블록)을 원하는 대로 조합해서 회로를 만든다. 설계를 바꾸고 싶으면 다시 조립하면 된다. ASIC보다 유연하지만 성능과 전력 효율은 떨어진다.

ASIC(Application Specific Integrated Circuit)​

비유: 공장에서 찍어낸 전용 부품

특정 용도에 맞게 설계된 맞춤형 반도체다. 비트코인 채굴용 ASIC처럼 한 가지 작업만 하지만 그 작업에서는 최고 성능과 최고 전력 효율을 보인다. 한번 만들면 변경이 불가능하고 초기 설계 비용이 높다.

1.7 메모리 인터커넥트​

CXL(Compute Express Link)​

비유: CPU와 메모리를 잇는 초고속 전용 고속도로

기존에는 CPU마다 자기 전용 메모리만 쓸 수 있었다. CXL은 여러 CPU와 가속기가 하나의 메모리 풀을 공유할 수 있게 해주는 초고속 인터커넥트 표준이다. 데이터센터에서 메모리를 유연하게 확장하고 공유할 수 있다.

HBM(High Bandwidth Memory)​

비유: 메모리를 층층이 쌓은 고층 아파트

일반 메모리(DDR)가 단층 주택이라면, HBM은 메모리 칩을 수직으로 쌓아 올린 고층 아파트다. 좁은 면적에서 엄청난 대역폭(데이터 이동 속도)을 제공한다. GPU와 AI 가속기에 주로 사용된다.

1.8 인터럽트​

인터럽트(Interrupt)​

비유: 업무 중 울리는 전화벨

보고서를 작성하다가(현재 작업) 전화벨이 울리면(인터럽트 발생) 하던 일을 잠시 멈추고(상태 저장), 전화를 받고(인터럽트 처리), 다시 보고서로 돌아온다(상태 복원). CPU가 현재 작업을 중단하고 긴급한 요청을 먼저 처리하는 메커니즘이다.

  • 하드웨어 인터럽트: 외부 장치(키보드, 마우스, 네트워크 카드)가 CPU에 신호를 보내는 것. 초인종 소리.
  • 소프트웨어 인터럽트: 프로그램이 OS에 서비스를 요청(시스템 콜)하는 것. 내선 전화.
  • 인터럽트 벡터 테이블: 전화번호부. 어떤 인터럽트가 발생하면 어떤 처리 루틴을 실행할지 주소가 적혀 있다.

1.9 우선순위 역전 문제​

우선순위 역전(Priority Inversion)​

비유: 사장님이 인턴의 열쇠를 기다리는 상황

높은 우선순위 작업(사장)이 낮은 우선순위 작업(인턴)이 가진 자원(열쇠)을 기다리는데, 중간 우선순위 작업(대리)이 인턴의 작업을 밀어내 사장이 더 오래 기다리게 되는 현상이다. 화성 탐사선 패스파인더(1997)에서 실제로 발생하여 유명해졌다.

우선순위 상속(Priority Inheritance)​

비유: 인턴에게 임시로 사장 권한 부여

열쇠를 가진 인턴의 우선순위를 일시적으로 사장 수준으로 올려서, 대리에게 밀리지 않고 빨리 작업을 끝내도록 한다. 열쇠를 반납하면 원래 우선순위로 돌아간다.

우선순위 천장(Priority Ceiling)​

비유: 자원에 "최소 직급" 표시를 붙이기

열쇠(자원)에 미리 "이 열쇠를 사용하려면 최소 부장급"이라는 표시를 붙여둔다. 열쇠를 획득한 사람은 자동으로 부장급 우선순위를 얻어 역전이 원천 차단된다.

2. 메모리​

2.1 메모리 레이아웃​

Code/Data/Heap/Stack 영역​

비유: 사무실의 구역 배치

프로그램이 메모리에 올라가면 4개 구역으로 나뉜다.

  • Code(Text) 영역: 업무 매뉴얼 보관함. 실행할 명령어(프로그램 코드)가 저장된다. 읽기 전용이다.
  • Data 영역: 고정 비품 창고. 전역 변수, 정적 변수처럼 프로그램 시작부터 끝까지 유지되는 데이터가 저장된다.
  • Heap 영역: 자유 창고. 프로그래머가 필요할 때 공간을 빌리고(malloc/new) 다 쓰면 반납(free/delete)한다. 아래에서 위로 자란다.
  • Stack 영역: 서류 쟁반(LIFO). 함수 호출 시 지역 변수, 매개변수, 복귀 주소가 쌓인다. 함수가 끝나면 자동으로 정리된다. 위에서 아래로 자란다.

2.2 바이트 순서​

빅엔디언(Big-Endian)​

비유: 왼쪽부터 읽는 책

숫자 0x12345678을 메모리에 저장할 때 큰 자릿수(12)부터 먼저 저장한다. 사람이 읽는 순서와 같아 네트워크 프로토콜에서 주로 사용한다(네트워크 바이트 오더).

리틀엔디언(Little-Endian)​

비유: 뒤에서부터 읽는 책

숫자 0x12345678을 저장할 때 작은 자릿수(78)부터 먼저 저장한다. 연산 시 하위 바이트부터 처리하기 편하다. Intel x86 CPU가 리틀엔디언을 사용한다.

2.3 메모리 계층 구조​

메모리 계층(Memory Hierarchy)​

비유: 책상 - 책장 - 창고 - 외부 물류센터

  • 레지스터: 손에 들고 있는 종이. 가장 빠르지만 극소량.
  • 캐시(L1/L2/L3): 책상 위 서류함. 빠르고 자주 쓰는 것을 가까이 둔다.
  • 주기억장치(RAM): 사무실 책장. 용량은 크지만 책상보다 꺼내는 데 시간이 걸린다.
  • 보조기억장치(SSD/HDD): 외부 창고. 대용량이지만 가져오는 데 오래 걸린다.

위로 갈수록 빠르고 비싸고 용량이 작다. 아래로 갈수록 느리고 싸고 용량이 크다. 이 계층 구조가 속도와 비용의 균형을 맞춘다.

2.4 캐시(Cache)​

캐시 메모리​

비유: 자주 쓰는 양념을 조리대 위에 올려두는 것

냉장고(메인 메모리)까지 갈 필요 없이, 자주 쓰는 소금, 후추(데이터)를 조리대(캐시) 위에 올려두면 요리 속도가 빨라진다. 지역성(Locality) 원리에 기반한다.

  • 시간적 지역성: 방금 쓴 소금을 곧 또 쓸 가능성이 높다.
  • 공간적 지역성: 소금 옆에 있는 후추도 곧 쓸 가능성이 높다.

Write-Through(즉시 기록)​

비유: 메모를 하면 원본 파일에도 즉시 반영

캐시에 쓸 때마다 메인 메모리에도 동시에 쓴다. 데이터 일관성이 보장되지만 쓰기 속도가 느리다.

Write-Back(나중 기록)​

비유: 메모를 모아뒀다가 퇴근 전에 한꺼번에 파일에 반영

캐시에만 먼저 쓰고, 캐시 블록이 교체될 때 메인 메모리에 반영한다. 쓰기 속도가 빠르지만 캐시와 메모리 간 데이터 불일치가 발생할 수 있다.

캐시 일관성(Cache Coherence)​

비유: 여러 사무실의 사본이 모두 같은 내용이어야 하는 문제

멀티코어 CPU에서 각 코어가 자기만의 캐시를 갖고 있을 때, 한 코어가 데이터를 수정하면 다른 코어의 캐시에 있는 같은 데이터도 갱신되어야 한다. 그렇지 않으면 서로 다른 값을 보게 된다.

MESI 프로토콜​

비유: 사본 문서의 상태 관리 스티커

각 캐시 블록에 4가지 상태 스티커를 붙여 관리한다.

  • M(Modified): "나만 수정함". 이 캐시만 최신이고 메모리는 오래된 값.
  • E(Exclusive): "나만 갖고 있음(수정 안 함)". 이 캐시에만 복사본이 있고 메모리와 동일.
  • S(Shared): "여러 명이 같은 사본 보유". 읽기만 가능.
  • I(Invalid): "이 사본은 쓸모없음". 다른 코어가 수정해서 무효화됨.

캐시 매핑(Cache Mapping)​

비유: 도서관 책 배치 방식

  • 직접 매핑(Direct Mapped): 지정석. 각 메모리 블록이 캐시의 특정 위치에만 들어갈 수 있다. 단순하지만 충돌이 잦다.
  • 완전 연관 매핑(Fully Associative): 자유석. 어떤 메모리 블록이든 캐시의 아무 위치에 들어갈 수 있다. 충돌이 적지만 검색 비용이 크다.
  • 집합 연관 매핑(Set Associative): 구역 자유석. 캐시를 여러 세트로 나누고, 메모리 블록은 지정된 세트 안에서 자유롭게 배치된다. 직접 매핑과 완전 연관의 절충안이다.

2.5 메모리 인터리빙​

인터리빙(Interleaving)​

비유: 계산대를 여러 개 운영하는 마트

하나의 메모리 모듈에 연속 접근하면 대기 시간이 생긴다. 메모리를 여러 뱅크(계산대)로 나누고, 번갈아 접근하면 대기 시간 없이 연속으로 데이터를 가져올 수 있다. 한 뱅크가 응답하는 동안 다른 뱅크에 요청을 보낸다.

2.6 가상 메모리 - 페이징​

페이징(Paging)​

비유: 책을 같은 크기의 페이지로 나누어 보관

물리 메모리를 같은 크기의 프레임(빈 서랍)으로, 프로그램을 같은 크기의 페이지(문서 묶음)로 나눈다. 페이지가 반드시 연속된 서랍에 들어갈 필요 없이 빈 서랍 아무 데나 넣는다. 페이지 테이블이 "이 페이지는 몇 번 서랍에 있다"는 매핑 정보를 관리한다. 외부 단편화가 없지만, 마지막 페이지에 빈 공간(내부 단편화)이 생길 수 있다.

2.7 가상 메모리 - 세그멘테이션​

세그멘테이션(Segmentation)​

비유: 용도별로 다른 크기의 방을 배정

프로그램을 논리적 단위(코드 세그먼트, 데이터 세그먼트, 스택 세그먼트)로 나누고, 각 단위에 맞는 크기의 공간을 배정한다. 논리적으로 자연스럽지만, 다양한 크기의 방을 배치하다 보면 빈 공간(외부 단편화)이 생긴다.

2.8 페이지 교체 알고리즘​

FIFO(First In First Out)​

비유: 가장 오래된 우유부터 버리기

냉장고(메모리)가 가득 차면 가장 먼저 넣은 우유(페이지)를 버린다. 구현이 단순하지만, 오래되었어도 자주 쓰는 우유를 버릴 수 있다. Belady의 모순(프레임 수를 늘려도 페이지 폴트가 증가)이 발생할 수 있다.

LRU(Least Recently Used)​

비유: 가장 오랫동안 안 꺼낸 옷 기부하기

옷장이 가득 차면 가장 최근에 안 입은 옷을 기부한다. "최근에 쓰지 않은 것은 앞으로도 쓰지 않을 것"이라는 가정이다. FIFO보다 효율적이지만, 최근 사용 시점을 추적하는 오버헤드가 있다.

LFU(Least Frequently Used)​

비유: 가장 적게 입은 옷 기부하기

사용 빈도가 가장 낮은 옷을 기부한다. 자주 쓰이는 데이터를 잘 유지하지만, 과거에 많이 쓰이고 지금은 안 쓰이는 데이터가 계속 남아있을 수 있다.

Optimal(최적 교체)​

비유: 미래를 보는 눈으로 판단

"앞으로 가장 오랫동안 안 쓸 페이지"를 교체한다. 이론적으로 최적이지만, 미래를 예측할 수 없으므로 실제 구현이 불가능하다. 다른 알고리즘의 성능을 비교하는 기준(상한선)으로 사용된다.

Clock(시계) 알고리즘​

비유: 원형 회전판에서 기회를 한 번 더 주기

페이지를 시계처럼 원형으로 배치하고, 시계 바늘이 돌면서 "참조 비트"를 확인한다. 참조 비트가 1이면 0으로 바꾸고 넘어가고(기회를 한 번 줌), 0이면 교체한다. LRU의 근사치를 저비용으로 구현한 것이다.

2.9 스레싱과 워킹셋​

스레싱(Thrashing)​

비유: 서류를 쉴 새 없이 꺼내다 넣다 반복

책상이 너무 작아서(물리 메모리 부족) 서류를 꺼내면(페이지 로드) 다른 서류를 창고에 넣어야 하고, 곧 또 필요해서 다시 꺼내는 악순환이 반복된다. CPU 사용률은 떨어지고, 대부분의 시간을 페이지 교체에 허비한다.

워킹셋(Working Set)​

비유: 지금 작업에 필요한 서류 묶음

특정 시간 동안 프로세스가 자주 참조하는 페이지 집합이다. 이 워킹셋만큼의 프레임을 확보해 주면 스레싱을 방지할 수 있다. "지금 요리에 필요한 재료만 조리대에 올려두기."

PFF(Page Fault Frequency)​

비유: 서류 못 찾는 빈도로 책상 크기 조절

페이지 폴트 빈도를 모니터링한다. 너무 자주 발생하면 프레임을 더 주고, 너무 적으면 프레임을 회수한다. 워킹셋보다 단순한 방식으로 메모리 할당량을 조절한다.

2.10 동적 메모리 관리​

동적 메모리 할당(Dynamic Memory Allocation)​

비유: 호텔 객실 배정

손님(프로그램)이 원하는 크기의 방(메모리)을 예약(malloc)하고, 체크아웃(free)할 때 반납한다.

  • First Fit: 빈 방 목록에서 처음 맞는 방 배정. 빠르지만 앞쪽에 작은 빈 방이 많아진다.
  • Best Fit: 딱 맞는 크기의 방 배정. 공간 낭비가 적지만 아주 작은 자투리 공간이 많아진다.
  • Worst Fit: 가장 큰 빈 방에 배정. 남은 공간이 크므로 다른 손님도 쓸 수 있다.

메모리 누수(Memory Leak)​

비유: 체크아웃 안 하고 떠난 손님

방을 쓰고 나갔는데 프런트에 반납을 안 해서, 빈 방인데도 사용 불가 상태가 된다. 프로그래머가 할당한 메모리를 해제하지 않으면 사용 가능한 메모리가 점점 줄어들어 결국 시스템이 느려지거나 멈춘다.

GC(Garbage Collection, 가비지 컬렉션)​

비유: 호텔 자동 청소 시스템

손님이 체크아웃을 깜빡해도, 호텔 시스템이 자동으로 빈 방을 감지하고 청소(메모리 회수)한다. Java, Python, Go 등의 언어에서 프로그래머가 수동으로 메모리를 해제하지 않아도 자동으로 회수한다.

  • Mark-and-Sweep: 사용 중인 방에 표시(Mark)하고, 표시 없는 방을 청소(Sweep).
  • Generational GC: 최근 투숙 손님은 곧 떠날 확률이 높으므로 자주 점검하고, 장기 투숙 손님은 가끔 점검한다.

2.11 단편화​

단편화(Fragmentation)​

비유: 주차장의 빈 자리 문제

  • 내부 단편화(Internal Fragmentation): 대형 주차 구역에 경차를 세워서 공간이 남는 것. 할당된 공간이 요청보다 커서 내부에 낭비가 생긴다.
  • 외부 단편화(External Fragmentation): 주차장 곳곳에 빈 칸이 있지만 연속되지 않아 대형 버스를 세울 수 없는 것. 총 빈 공간은 충분하지만 연속된 공간이 부족하다.
  • 압축(Compaction): 차들을 한쪽으로 몰아서 빈 공간을 합치는 것. 비용이 크다.

Segmentation Fault​

비유: 출입 금지 구역에 들어가기

프로그램이 허용되지 않은 메모리 영역에 접근하려 할 때 운영체제가 강제로 프로그램을 종료시키는 것이다. 해제된 메모리 접근, 배열 범위 초과, NULL 포인터 역참조 등이 원인이다. "직원 전용 구역에 일반인이 들어가면 경비원이 내쫓는 것"과 같다.

3. 프로세스와 스레드​

3.1 프로세스 vs 스레드​

프로세스(Process)​

비유: 독립된 공장

각 공장(프로세스)은 자기만의 건물(메모리 공간), 설비(자원), 직원(스레드)을 갖는다. 다른 공장과 완전히 분리되어 있어, 한 공장이 폭발해도 다른 공장에 영향이 없다. 운영체제가 자원을 할당하는 기본 단위다.

스레드(Thread)​

비유: 한 공장 안의 작업 라인

같은 공장(프로세스) 안에서 여러 작업 라인(스레드)이 건물과 설비(코드, 데이터, 힙)를 공유하면서 각자 작업을 진행한다. 각 라인마다 자기만의 작업 메모(스택, 레지스터)를 갖는다. CPU 스케줄링의 기본 단위다.

멀티스레드(Multi-thread)​

비유: 한 주방에서 여러 요리사가 동시에 요리

한 주방(프로세스)에서 여러 요리사(스레드)가 식재료(데이터)를 공유하며 동시에 다른 요리를 만든다. 효율적이지만 같은 재료에 손이 겹치지 않도록(동기화) 주의해야 한다.

3.2 컨텍스트 스위칭​

컨텍스트 스위칭(Context Switching)​

비유: 여러 과목 시험 볼 때 머릿속 전환

수학 시험을 보다가 영어 시험으로 넘어갈 때, 수학 관련 내용을 저장하고 영어 관련 내용을 불러오는 과정이다. CPU가 하나의 프로세스에서 다른 프로세스로 전환할 때, 현재 상태(레지스터, 프로그램 카운터)를 PCB(Process Control Block)에 저장하고 다음 프로세스의 상태를 복원한다. 이 과정에서 오버헤드가 발생한다.

3.3 CPU 스케줄링​

FCFS(First Come First Served)​

비유: 은행 번호표 순서

먼저 온 손님부터 처리한다. 공평하지만, 앞에 시간이 오래 걸리는 손님이 있으면 뒤의 간단한 업무도 오래 기다려야 한다(호위 효과, Convoy Effect).

SJF(Shortest Job First)​

비유: 간단한 업무부터 먼저 처리

처리 시간이 짧은 작업을 먼저 실행한다. 평균 대기 시간이 최소지만, 긴 작업이 계속 뒤로 밀리는 기아(Starvation) 현상이 발생할 수 있다. 비선점형이다.

SRT(Shortest Remaining Time)​

비유: 남은 시간이 더 짧은 손님에게 양보

SJF의 선점형 버전이다. 새로운 작업이 도착했을 때, 현재 실행 중인 작업의 남은 시간보다 새 작업의 총 시간이 짧으면 교체한다.

HRN(Highest Response Ratio Next)​

비유: 오래 기다린 사람에게 가산점

대기 시간을 고려하여 응답 비율이 가장 높은 작업을 선택한다. 응답 비율 = (대기시간 + 서비스시간) / 서비스시간. SJF의 기아 문제를 완화한다.

RR(Round Robin)​

비유: 돌아가면서 한 입씩

각 프로세스에 동일한 시간(타임 슬라이스, 예: 10ms)을 주고 돌아가면서 실행한다. 피자를 한 조각씩 돌아가며 먹는 것과 같다. 공평하지만, 타임 슬라이스가 너무 짧으면 컨텍스트 스위칭 오버헤드가 크고, 너무 길면 FCFS와 같아진다.

MLQ(Multi-Level Queue)​

비유: VIP/일반/학생 창구가 따로 있는 은행

프로세스를 우선순위에 따라 여러 큐로 나눈다. 시스템 프로세스는 VIP 창구, 대화형 프로세스는 일반 창구, 배치 작업은 학생 창구. 각 큐마다 다른 스케줄링 알고리즘을 적용한다. 큐 간 이동이 불가능하다.

MLFQ(Multi-Level Feedback Queue)​

비유: 실적에 따라 승강하는 리그 시스템

MLQ와 비슷하지만 프로세스가 큐 사이를 이동할 수 있다. 처음에는 최상위 큐에서 짧은 타임 슬라이스를 받고, 시간 내에 못 끝내면 하위 큐로 강등된다. CPU를 적게 쓰는 대화형 프로세스에 유리하고, CPU를 많이 쓰는 프로세스는 자연스럽게 하위 큐로 이동한다.

3.4 동기화​

경쟁 조건(Race Condition)​

비유: 두 사람이 동시에 같은 통장에서 출금

잔액이 100만 원인데 두 사람이 동시에 50만 원을 출금하면, 둘 다 "잔액 100만 원"을 읽고 각자 50만 원을 빼서 50만 원을 저장한다. 결과적으로 100만 원이 빠져야 하는데 50만 원만 빠진다. 여러 프로세스가 공유 자원에 동시 접근할 때 실행 순서에 따라 결과가 달라지는 현상이다.

TOCTOU(Time of Check to Time of Use)​

비유: 가격표 확인 후 계산대에서 가격이 바뀐 상황

물건 가격을 확인(Check)하고 계산대로 갔는데(Use), 그 사이에 가격이 바뀌어 있는 상황이다. 권한을 확인하는 시점과 실제 사용하는 시점 사이에 상태가 변경되는 보안 취약점이다.

임계영역(Critical Section)​

비유: 1인용 화장실

한 번에 한 사람만 사용할 수 있는 공간이다. 공유 자원에 접근하는 코드 영역으로, 동시에 여러 프로세스가 진입하면 안 된다. 상호배제(Mutual Exclusion), 진행(Progress), 한정 대기(Bounded Waiting) 조건을 만족해야 한다.

세마포어(Semaphore)​

비유: 주차장 잔여석 표시기

주차장에 "남은 자리: 3"이라는 카운터가 있다. 차가 들어가면 -1, 나오면 +1. 카운터가 0이면 대기한다. 이진 세마포어(0 또는 1)는 뮤텍스처럼 동작하고, 카운팅 세마포어는 N개의 동시 접근을 허용한다.

모니터(Monitor)​

비유: 은행 창구 시스템

고객은 번호표를 받고 대기하며, 창구 직원(모니터)이 한 명씩 호출한다. 모니터는 상호배제를 자동으로 보장하는 고수준 동기화 구조로, 세마포어보다 사용하기 쉽다. Java의 synchronized 키워드가 대표적이다.

뮤텍스(Mutex)​

비유: 열쇠가 하나뿐인 화장실

열쇠(락)를 가진 사람만 들어갈 수 있고, 나올 때 열쇠를 반납한다. 세마포어와 달리 소유권 개념이 있어, 열쇠를 획득한 스레드만 해제할 수 있다.

스핀락(Spinlock)​

비유: 화장실 앞에서 문을 계속 두드리며 기다리기

잠겨 있으면 그 자리에서 계속 확인한다("사용 중인가? 사용 중인가?"). 대기 시간이 짧을 때 유리하지만, 길면 CPU를 낭비(바쁜 대기, Busy Waiting)한다. 커널 내부에서 짧은 임계영역 보호에 사용된다.

3.5 교착상태(Deadlock)​

교착상태​

비유: 좁은 골목에서 두 차가 마주 보고 막힌 상황

두 차(프로세스)가 각자 골목(자원)을 점유하고 상대방이 비켜주기를 기다리는데, 아무도 양보하지 않아 영원히 멈추는 상황이다.

교착상태 4가지 조건 (모두 동시에 만족해야 발생)​

  • 상호배제(Mutual Exclusion): 한 번에 한 차만 골목을 지날 수 있다.
  • 점유와 대기(Hold and Wait): 자기 골목을 점유한 채 상대 골목을 기다린다.
  • 비선점(No Preemption): 상대 차를 강제로 치울 수 없다.
  • 순환 대기(Circular Wait): A가 B를 기다리고, B가 A를 기다리는 원형 대기.

은행가 알고리즘(Banker's Algorithm)​

비유: 은행이 대출 전에 안전성 검사

은행(OS)이 고객(프로세스)에게 돈(자원)을 빌려줄 때, "이 돈을 빌려줘도 다른 모든 고객의 대출금을 회수할 수 있는가?"를 미리 계산한다. 안전 상태(Safe State)가 보장될 때만 자원을 할당한다.

교착상태 처리 전략​

  • 예방(Prevention): 4가지 조건 중 하나를 원천 차단. 골목을 넓혀 양방향 통행 가능하게 하기. 자원 낭비가 클 수 있다.
  • 회피(Avoidance): 은행가 알고리즘처럼 안전한 경우에만 자원 할당. 미리 교통 상황을 보고 우회.
  • 탐지(Detection): 교착상태가 발생하면 감지. 자원 할당 그래프에서 순환을 탐색. 정기적으로 교통 상황 모니터링.
  • 회복(Recovery): 교착상태를 탐지한 후 해결. 한 프로세스를 강제 종료하거나 자원을 빼앗는다. 교통경찰이 한 차를 후진시키기.

3.6 IPC(Inter-Process Communication)​

IPC 개요​

비유: 독립된 공장 사이의 소통 방법

각 공장(프로세스)은 담이 쳐져 있어 직접 왕래가 불가능하다. 다양한 방법으로 소통한다.

파이프(Pipe)​

비유: 두 공장을 연결하는 수도관

한 방향으로만 물(데이터)이 흐르는 관이다. 양방향 통신이 필요하면 관 2개가 필요하다. 부모-자식 프로세스 간 통신에 주로 사용한다. 이름 없는 파이프(Anonymous Pipe)는 혈연관계 프로세스끼리만, 이름 있는 파이프(Named Pipe/FIFO)는 무관한 프로세스끼리도 사용 가능하다.

메시지 큐(Message Queue)​

비유: 우체통

보내는 공장이 편지(메시지)를 우체통(큐)에 넣으면, 받는 공장이 꺼내 읽는다. 비동기 통신이 가능하고, 여러 프로세스가 하나의 큐를 공유할 수 있다.

공유 메모리(Shared Memory)​

비유: 두 공장 사이의 공용 게시판

담 위에 공용 게시판(공유 메모리 영역)을 설치하고 양쪽 공장 모두 읽고 쓸 수 있다. 가장 빠른 IPC 방식이지만, 동기화를 직접 처리해야 한다.

소켓(Socket)​

비유: 전화 통화

같은 건물이든 다른 나라든 전화(네트워크)로 소통할 수 있다. 같은 컴퓨터 내부는 물론 네트워크를 통한 원격 프로세스 간 통신이 가능하다. 양방향 통신이다.

시그널(Signal)​

비유: 공장에 울리는 비상벨

간단한 알림(인터럽트 신호)을 보낸다. "작업 중단해!(SIGKILL)", "일시정지!(SIGSTOP)" 같은 짧은 메시지만 전달 가능하고, 대량의 데이터 전달에는 부적합하다.

4. 파일 시스템과 스토리지​

4.1 Unix 파일시스템​

Unix 파일시스템​

비유: 나무 구조의 서류 보관 시스템

최상위 서랍(/)에서 시작하여 가지(디렉터리)를 따라 내려가면 잎(파일)에 도달하는 트리 구조다. "모든 것이 파일이다"라는 철학으로, 일반 파일뿐 아니라 디바이스, 소켓도 파일로 취급한다.

4.2 파일시스템 종류​

inode​

비유: 도서관 카드 목록(카탈로그)

책(파일)의 제목, 저자, 위치 정보를 적은 카드다. 파일의 메타데이터(소유자, 권한, 크기, 생성일, 데이터 블록 위치)를 저장한다. 파일 이름은 inode에 없고, 디렉터리 엔트리에 "파일명 - inode 번호" 매핑으로 존재한다.

FAT(File Allocation Table)​

비유: 보물찾기 지도의 연결 고리

"1번 상자에서 다음 단서는 5번 상자, 5번 상자에서 다음 단서는 12번 상자..."처럼 각 블록이 다음 블록을 가리키는 연결 리스트 구조의 테이블이다. 구조가 단순하여 USB, SD 카드에 널리 쓰인다.

NTFS(New Technology File System)​

비유: 첨단 보안 도서관

Windows의 기본 파일시스템이다. MFT(Master File Table)로 파일 정보를 관리하며, 저널링(변경 기록을 먼저 남김), 파일 권한(ACL), 암호화(EFS), 압축, 대용량 파일 지원 등 고급 기능을 제공한다.

ext4(Fourth Extended File System)​

비유: Linux의 국민 파일시스템

Linux의 기본 파일시스템이다. inode 기반이며 저널링을 지원한다. Extent(연속된 블록 묶음) 방식으로 대용량 파일 처리 효율이 좋고, 최대 1EB(엑사바이트) 파일시스템, 16TB 파일을 지원한다.

4.3 파일 슬랙​

파일 슬랙(File Slack)​

비유: 택배 상자 안의 빈 공간

작은 물건을 보내는데 큰 상자를 사용하면 안에 빈 공간이 남는다. 파일이 디스크 블록(클러스터)을 다 채우지 못해 남는 여백이다. 디지털 포렌식에서 중요한데, 이전에 삭제된 파일의 잔여 데이터가 슬랙 공간에 남아있을 수 있다.

  • RAM 슬랙: 마지막 섹터에서 파일이 끝나고 남은 부분. OS가 RAM 내용으로 채운다.
  • 드라이브 슬랙: 마지막 섹터 이후 클러스터 끝까지 남은 부분. 이전 파일의 흔적이 남아있다.

4.4 RAID​

RAID(Redundant Array of Independent Disks)​

비유: 여러 금고를 조합하는 전략

금고(디스크) 하나에 모든 보석(데이터)을 넣으면 금고가 망가지면 끝이다. 여러 금고를 조합하여 성능과 안전성을 높인다.

  • RAID 0(스트라이핑): 보석을 여러 금고에 나누어 보관. 접근이 빠르지만 금고 하나만 망가져도 전체 데이터 손실. 속도만 필요할 때.
  • RAID 1(미러링): 같은 보석을 두 금고에 복제 보관. 하나가 망가져도 안전하지만 저장 공간이 절반. 안전이 최우선일 때.
  • RAID 5(분산 패리티): 보석을 나누어 저장하고, 복구용 암호(패리티)도 분산 저장. 디스크 1개 고장까지 복구 가능. 읽기 성능과 안전성의 균형. 최소 3개 디스크.
  • RAID 6(이중 패리티): 패리티를 2개 저장. 디스크 2개 동시 고장까지 복구 가능. 최소 4개 디스크.
  • RAID 10(1+0): RAID 1로 미러링한 쌍을 RAID 0으로 스트라이핑. 속도와 안전성 모두 확보하지만 비용이 높다. 최소 4개 디스크.
  • RAID 50(5+0): RAID 5 그룹을 RAID 0으로 스트라이핑. 대용량 고성능 환경.
  • RAID 60(6+0): RAID 6 그룹을 RAID 0으로 스트라이핑. 최고 수준의 안전성과 성능.

4.5 스토리지 아키텍처​

DAS(Direct Attached Storage)​

비유: 책상 서랍

컴퓨터에 직접 연결된 저장장치다. 외장 하드디스크처럼 케이블로 직접 연결한다. 간단하고 빠르지만 다른 컴퓨터와 공유가 어렵다.

NAS(Network Attached Storage)​

비유: 사무실 공용 파일 서버

네트워크에 연결된 전용 저장장치다. 사무실의 모든 컴퓨터가 네트워크를 통해 파일을 공유한다. 파일 단위로 접근하며, 설치와 관리가 쉽다.

SAN(Storage Area Network)​

비유: 전용 고속도로로 연결된 대형 물류 창고

서버와 스토리지를 전용 네트워크(Fibre Channel 등)로 연결한 고성능 스토리지 네트워크다. 블록 단위로 접근하며, 대기업의 대용량 데이터 처리에 사용한다. NAS보다 빠르고 확장성이 좋지만 비용이 높다.

4.6 스토리지 유형​

블록 스토리지(Block Storage)​

비유: 빈 주차장 구획

데이터를 고정 크기 블록으로 나누어 저장한다. 파일시스템이나 데이터베이스가 위에 올라간다. SAN에서 주로 사용하며, 빠른 I/O가 필요한 환경에 적합하다.

파일 스토리지(File Storage)​

비유: 정리된 서류 캐비넷

디렉터리/파일 계층 구조로 데이터를 저장한다. NAS가 대표적이며, 사람이 이해하기 쉬운 구조다.

오브젝트 스토리지(Object Storage)​

비유: 거대한 창고에 라벨을 붙인 상자 보관

각 데이터(객체)에 고유 ID와 메타데이터(라벨)를 붙여 평평한 구조로 저장한다. 디렉터리 계층이 없다. AWS S3가 대표적이며, 대용량 비정형 데이터(사진, 동영상, 백업) 저장에 최적이다.

4.7 스토리지 가상화​

스토리지 가상화(Storage Virtualization)​

비유: 여러 창고를 하나의 초대형 창고처럼 보이게 하기

물리적으로 분산된 여러 스토리지를 소프트웨어로 묶어 하나의 거대한 저장 공간처럼 사용한다. 관리가 편하고, 용량 확장이 유연하며, 특정 스토리지 장비에 종속되지 않는다.

4.8 디스크 스케줄링​

FCFS(First Come First Served)​

비유: 요청 순서대로 방문하는 택배 기사

도착한 순서대로 처리한다. 공평하지만 디스크 헤드가 왔다 갔다 하여 비효율적일 수 있다.

SSTF(Shortest Seek Time First)​

비유: 가장 가까운 집부터 배달

현재 위치에서 가장 가까운 요청을 먼저 처리한다. 이동 거리가 줄지만, 멀리 있는 요청이 계속 뒤로 밀리는 기아가 발생할 수 있다.

SCAN(엘리베이터 알고리즘)​

비유: 엘리베이터

한 방향(위)으로 끝까지 간 다음 반대 방향(아래)으로 끝까지 간다. 경로 상의 모든 요청을 처리한다. 공평하고 효율적이다.

C-SCAN(Circular SCAN)​

비유: 순환 버스

한 방향으로만 서비스하고 끝에 도달하면 처음으로 되돌아간다(돌아가는 동안 서비스 안 함). SCAN보다 대기 시간이 균일하다.

LOOK​

비유: 요청이 있는 곳까지만 가는 엘리베이터

SCAN처럼 동작하되 끝까지 가지 않고, 해당 방향에 더 이상 요청이 없으면 방향을 바꾼다. 불필요한 이동을 줄인다. C-LOOK도 같은 원리로 C-SCAN을 최적화한 것이다.

5. 운영체제(OS)​

5.1 UNIX 부팅 과정​

UNIX 부팅(Booting)​

비유: 아침에 사무실 여는 과정

  1. 전원 ON: 건물 전기를 켠다.
  2. POST(Power-On Self Test): 설비 점검. 메모리, 키보드 등 하드웨어가 정상인지 확인.
  3. 부트로더 실행: 경비원(BIOS/UEFI)이 사무실 열쇠(부트로더)를 찾아 건네준다.
  4. 커널 로드: 사무실 매니저(커널)가 출근하여 업무를 시작한다. 메모리에 커널을 올린다.
  5. init 프로세스: 매니저가 각 부서(시스템 서비스)를 하나씩 깨운다. PID 1인 첫 번째 프로세스가 시작된다.
  6. 런레벨/서비스 시작: 각 부서가 업무를 개시한다. 네트워크, 로그인 서비스 등이 시작된다.

5.2 BIOS와 UEFI​

BIOS(Basic Input/Output System)​

비유: 오래된 건물의 아날로그 관리인

컴퓨터 전원을 켜면 가장 먼저 실행되는 펌웨어다. 하드웨어를 초기화하고 부팅 장치를 찾아 OS를 로드한다. 16비트, MBR(Master Boot Record) 방식으로 2TB 이하 디스크만 부팅 가능. 텍스트 기반의 설정 화면.

UEFI(Unified Extensible Firmware Interface)​

비유: 최신 건물의 스마트 관리 시스템

BIOS의 현대적 대체제다. 64비트, GPT(GUID Partition Table) 방식으로 2TB 이상의 대용량 디스크 부팅을 지원한다. 그래픽 설정 화면, 빠른 부팅(Fast Boot), 보안 부팅(Secure Boot: 서명된 OS만 부팅 허용) 등 고급 기능을 제공한다.

5.3 가상화​

가상화 프로그램(Virtualization)​

비유: 한 건물에 여러 사무실을 독립적으로 운영

하나의 물리 서버(건물) 위에 여러 가상 머신(사무실)을 만들어 각각 독립된 OS와 앱을 실행한다.

  • 하이퍼바이저(Hypervisor): 건물 관리 시스템. 물리 자원을 가상 머신에 배분한다.
    • Type 1(베어메탈): 하드웨어 위에 직접 설치. 성능이 좋다. VMware ESXi, Hyper-V.
    • Type 2(호스트형): OS 위에 설치하는 소프트웨어. 설치가 쉽지만 성능 오버헤드. VirtualBox, VMware Workstation.
  • 전가상화(Full Virtualization): 게스트 OS를 수정 없이 실행. 호환성이 좋지만 오버헤드.
  • 반가상화(Para-virtualization): 게스트 OS를 수정하여 하이퍼바이저와 직접 통신. 성능이 좋지만 OS 수정 필요. Xen.
  • 컨테이너 가상화: OS 커널을 공유하고 앱 환경만 격리. VM보다 가볍고 빠르다. Docker.

6. 형식 언어(Formal Language)​

6.1 유한 오토마타​

유한 오토마타(Finite Automata)​

비유: 자동문의 센서 시스템

자동문은 "닫힘"과 "열림" 두 가지 상태를 갖는다. 사람이 다가오면(입력) "닫힘"에서 "열림"으로 전이하고, 사람이 없으면 다시 "닫힘"으로 돌아간다. 유한한 수의 상태와 전이 규칙으로 입력 문자열을 인식하는 기계(수학적 모델)다.

DFA(Deterministic Finite Automaton)​

비유: 길이 하나뿐인 미로

각 갈림길(상태)에서 화살표(입력)를 따라가면 갈 곳이 딱 하나다. 같은 상태에서 같은 입력이면 항상 같은 다음 상태로 간다. 결정적이라 구현이 단순하고 빠르다.

NFA(Non-deterministic Finite Automaton)​

비유: 갈림길이 여러 개인 미로

한 갈림길에서 같은 화살표를 따라갈 수 있는 길이 여러 개다. 가능한 모든 경로를 동시에 탐색한다고 상상한다. 입력 없이 이동하는 엡실론 전이도 가능하다. DFA보다 표현이 간결하지만, 실행은 DFA로 변환(부분집합 구성법)해야 한다. DFA와 NFA의 인식 능력은 동일하다.

6.2 정규식​

정규식(Regular Expression)​

비유: 전화번호 패턴 검색

"010-XXXX-XXXX" 형식의 전화번호를 찾고 싶을 때, "010-숫자4개-숫자4개"라는 패턴을 정의하는 것이 정규식이다. 문자열에서 특정 패턴을 검색, 매칭, 치환하는 표현식이다. 유한 오토마타와 동치인 표현 능력을 가진다.

  • 기본 연산: 합집합(a 또는 b), 연결(ab), 반복(a*)
  • 활용: 텍스트 검색, 입력 유효성 검사, 로그 분석, 컴파일러의 어휘 분석(Lexer)

6.3 촘스키 위계(Chomsky Hierarchy)​

촘스키 위계​

비유: 언어의 난이도 등급 시스템

언어(문법)를 4단계로 분류한 체계다. 위로 갈수록 표현력이 강하지만 인식이 어렵다.

Type 3 - 정규 문법(Regular Grammar)​

비유: 간단한 암호 규칙

"A 다음에 B, B 다음에 C"처럼 가장 단순한 패턴이다. 유한 오토마타가 인식하고, 정규식으로 표현 가능하다. 프로그래밍 언어의 토큰(키워드, 숫자, 식별자) 인식에 사용한다.

Type 2 - 문맥자유 문법(Context-Free Grammar, CFL)​

비유: 올바른 괄호 짝 맞추기

"여는 괄호가 있으면 반드시 닫는 괄호가 있어야 한다"처럼 중첩 구조를 표현할 수 있다. 정규 문법으로는 괄호 짝을 검사할 수 없지만, 문맥자유 문법은 가능하다. 프로그래밍 언어의 문법(구문 분석)이 대표적이다. PDA(푸시다운 오토마타)가 인식한다.

Type 1 - 문맥의존 문법(Context-Sensitive Grammar, CSL)​

비유: 주변 상황에 따라 의미가 달라지는 말

"배"가 과일인지 신체 부위인지 교통수단인지 문맥에 따라 달라지듯, 주변 기호에 따라 규칙 적용이 달라진다. 선형 한정 오토마타(Linear Bounded Automaton)가 인식한다.

Type 0 - 무제한 문법(Unrestricted Grammar)​

비유: 아무 규칙이나 적용 가능한 자유 작문

어떤 제약도 없는 가장 강력한 문법이다. 튜링 머신이 인식하며, 결정 불가능한 문제도 포함한다.

6.4 PDA(Pushdown Automaton)​

푸시다운 오토마타(PDA)​

비유: 접시를 쌓고 빼는 스택이 달린 자동문

유한 오토마타에 스택(접시 쌓기)을 추가한 것이다. 접시를 쌓고(push) 빼면서(pop) 짝을 맞출 수 있어, 괄호 짝 맞추기, 회문 검사 등 중첩 구조를 처리할 수 있다. 문맥자유 문법(Type 2)을 인식하는 기계다. 컴파일러의 구문 분석기(Parser)의 이론적 기반이다.

6.5 튜링 머신(Turing Machine)​

튜링 머신​

비유: 무한히 긴 종이 테이프와 연필을 가진 사람

무한히 긴 테이프(메모리)에 기호를 읽고, 쓰고, 좌우로 이동하며, 유한한 규칙표(상태 전이)에 따라 작동하는 가상의 기계다. 앨런 튜링이 1936년에 제안했다.

  • 계산 가능성: 튜링 머신으로 풀 수 있는 문제가 "계산 가능"한 문제다. 현대 모든 컴퓨터는 튜링 머신과 같은 계산 능력을 가진다(처치-튜링 논제).
  • 정지 문제(Halting Problem): "이 프로그램이 언젠가 멈출까, 영원히 돌까?"를 판별하는 것은 일반적으로 불가능하다(결정 불가능). 튜링이 증명한 유명한 한계.
  • 튜링 완전(Turing Complete): 튜링 머신을 시뮬레이션할 수 있는 시스템을 튜링 완전하다고 한다. 현대 프로그래밍 언어는 모두 튜링 완전하다.
