클라우드/인프라 개념 상세설명 (비유로 쉽게 이해하기)

정보관리기술사 110~138회 기출 키워드 기반 각 개념을 일상생활의 비유를 통해 쉽게 설명합니다.

1. 클라우드 컴퓨팅 개요​

1.1 클라우드 정의 및 특성​

클라우드 컴퓨팅(Cloud Computing)​

비유: 수도/전기 같은 유틸리티 서비스

집에서 물을 쓸 때 정수 시설을 직접 만들지 않고, 수도꼭지만 틀면 깨끗한 물이 나온다. 클라우드 컴퓨팅도 마찬가지로 서버, 스토리지, 네트워크 같은 IT 자원을 직접 구축하지 않고, 인터넷을 통해 필요한 만큼 빌려 쓰는 방식이다. 수도 요금처럼 쓴 만큼만 비용을 낸다.

클라우드 5대 특성​

비유: 뷔페 레스토랑의 5가지 원칙

뷔페 레스토랑이 잘 운영되려면 다섯 가지 원칙이 필요하다.

  • On-demand Self-service(주문형 셀프서비스): 직원을 부르지 않고 원하는 음식을 직접 가져온다. 관리자에게 요청하지 않고도 사용자가 스스로 자원을 할당받는 것이다.
  • Broad Network Access(광범위한 네트워크 접근): 어떤 테이블에 앉든 모든 음식 코너에 접근할 수 있다. 노트북, 스마트폰, 태블릿 등 어떤 기기에서든 네트워크를 통해 접속 가능하다.
  • Resource Pooling(자원 풀링): 주방에서 음식을 대량으로 만들어 모든 손님이 나눠 먹는다. 물리 자원을 공유 풀로 묶어 여러 사용자에게 동적으로 배분한다.
  • Rapid Elasticity(빠른 탄력성): 손님이 몰리면 테이블을 추가하고, 빠지면 치운다. 필요에 따라 자원을 빠르게 늘리거나 줄일 수 있다.
  • Measured Service(측정 가능한 서비스): 각 손님이 먹은 양을 계량해서 요금을 매긴다. 자원 사용량을 모니터링하고, 사용한 만큼 과금한다.

1.2 클라우드 서비스 모델​

IaaS(Infrastructure as a Service)​

비유: 빈 땅만 빌리는 것

건설회사에서 빈 땅(서버, 스토리지, 네트워크)만 빌려주고, 건물 설계와 시공은 임차인이 알아서 한다. OS 설치부터 애플리케이션 배포까지 모두 사용자 몫이다. 자유도는 높지만 관리해야 할 것이 많다.

PaaS(Platform as a Service)​

비유: 공유 주방(셰어드 키친) 임대

주방 시설(개발 환경, 미들웨어, 런타임)이 갖춰진 공간을 빌린다. 요리사(개발자)는 식재료(코드)만 가져와서 요리(서비스)를 만들면 된다. 가스레인지 설치나 환풍기 관리는 신경 쓸 필요 없다.

SaaS(Software as a Service)​

비유: 배달 음식 주문

요리를 직접 하지 않고 완성된 음식을 배달시켜 먹는 것이다. 이메일, 그룹웨어, ERP 같은 완성된 소프트웨어를 구독료를 내고 바로 사용한다. 가장 편하지만, 커스터마이징의 자유도는 낮다.

BaaS(Backend as a Service)​

비유: 반조리 밀키트

밀키트에는 손질된 재료와 소스가 들어 있어서, 볶기만 하면 요리가 완성된다. BaaS는 인증, 데이터베이스, 알림, 파일 저장 같은 백엔드 기능을 통째로 제공해서, 개발자는 프론트엔드(볶는 것)에만 집중하면 된다.

FaaS(Function as a Service)​

비유: 동전 노래방

노래방 기계를 사지 않고, 동전을 넣으면 한 곡만 부를 수 있다. FaaS는 함수 단위로 코드를 올려두면, 이벤트가 발생할 때만 실행되고 끝나면 자원이 반환된다. 실행 시간만큼만 과금되므로 매우 경제적이다.

DaaS(Desktop as a Service)​

비유: PC방에서 내 컴퓨터 접속하기

어떤 PC방에 가든 로그인만 하면 내 바탕화면, 내 파일, 내 프로그램이 그대로 나타난다. DaaS는 데스크톱 환경을 클라우드에서 제공하므로, 어떤 단말기에서든 동일한 업무 환경을 사용할 수 있다.

SECaaS(Security as a Service)​

비유: 경비 업체 구독 서비스

집에 CCTV와 경보 시스템을 직접 구축하는 대신, 월정액을 내고 경비 업체에 보안을 맡기는 것이다. SECaaS는 방화벽, 침입 탐지, 백신, 접근 제어 같은 보안 기능을 클라우드 서비스로 제공한다.

1.3 클라우드 배치 모델​

퍼블릭 클라우드(Public Cloud)​

비유: 대중교통(시내버스)

누구나 요금을 내면 탈 수 있다. 불특정 다수가 함께 쓰는 공용 인프라이며, 초기 비용이 낮고 확장이 쉽다. 대신 노선(정책)을 내가 정할 수 없다.

프라이빗 클라우드(Private Cloud)​

비유: 자가용

나만 타는 차다. 특정 기관이나 기업이 전용으로 구축하여 사용하는 클라우드로, 보안과 커스터마이징에 유리하지만 구축과 유지 비용이 높다.

하이브리드 클라우드(Hybrid Cloud)​

비유: 자가용 + 대중교통 병행

평소에는 자가용(프라이빗)을 쓰고, 출퇴근 시간에 막히면 지하철(퍼블릭)로 갈아탄다. 민감한 데이터는 프라이빗에서 처리하고, 일반 업무는 퍼블릭에서 처리하는 혼합 방식이다.

커뮤니티 클라우드(Community Cloud)​

비유: 아파트 단지 카셰어링

같은 단지 주민(동일 업종, 동일 규제를 받는 기관)들만 공유하는 차량이다. 공통의 요구사항과 보안 정책을 가진 조직들이 함께 구축하고 공유하는 클라우드다.

멀티클라우드(MultiCloud)​

비유: 여러 통신사 유심을 쓰는 것

하나의 통신사에 의존하면 장애 시 먹통이 된다. 여러 통신사 유심을 쓰면 한 곳이 안 되도 다른 곳으로 전환할 수 있다. 멀티클라우드는 AWS, Azure, GCP 등 여러 CSP를 동시에 사용하여 벤더 종속을 피하고, 장애 대응력을 높이는 전략이다.

1.4 국내 클라우드 플랫폼​

파스-타(PaaS-TA)​

비유: 국산 공유 주방 프랜차이즈

외국 프랜차이즈(AWS, Azure)에 의존하지 않고, 국내 기술로 만든 공유 주방이다. 파스-타는 한국지능정보사회진흥원이 개발한 오픈소스 기반 국산 PaaS 플랫폼으로, 공공기관이 클라우드 환경에서 애플리케이션을 개발하고 운영할 수 있도록 지원한다.

2. 가상화​

2.1 가상화 개요​

가상화(Virtualization)​

비유: 하나의 건물을 여러 세대로 나누기

한 건물(물리 서버)을 벽으로 나눠 여러 세대(가상 환경)를 만드는 것이다. 각 세대는 독립적인 생활 공간이지만, 건물의 기초와 배관은 공유한다. 하나의 물리 하드웨어 위에 여러 독립적인 컴퓨팅 환경을 만들어 효율적으로 자원을 활용하는 기술이다.

2.2 하이퍼바이저​

하이퍼바이저(Hypervisor)​

비유: 아파트 관리 사무소

건물(물리 서버)의 전기, 수도, 주차장을 각 세대(VM)에 공정하게 배분하는 관리 사무소다. 하이퍼바이저는 물리 하드웨어와 가상머신 사이에 위치하여 CPU, 메모리, 스토리지를 각 VM에 분배하고 격리해준다.

Type 1 Hypervisor (Bare-metal)​

비유: 건물 기초에 내장된 관리 시스템

건물을 지을 때부터 관리 시스템이 기초(하드웨어) 위에 직접 설치되어 있다. 별도의 운영체제 없이 하드웨어 바로 위에서 동작하므로 성능이 우수하다. VMware ESXi, Xen, KVM, Hyper-V가 대표적이다. 데이터센터 환경에서 주로 사용한다.

Type 2 Hypervisor (Hosted)​

비유: 기존 집 위에 설치한 파티션

이미 입주한 집(호스트 OS) 안에 파티션을 설치해 방을 나누는 것이다. 기존 운영체제 위에 소프트웨어로 설치하므로 편리하지만, 호스트 OS를 거치기 때문에 Type 1보다 성능 오버헤드가 있다. VirtualBox, VMware Workstation이 대표적이다. 개발/테스트 환경에서 주로 사용한다.

2.3 가상머신 vs 컨테이너​

가상머신(VM)​

비유: 독채 주택

각 집마다 자체 기초, 배관, 지붕(게스트 OS)이 있어서 완전히 독립적이지만 무겁다. VM은 하이퍼바이저 위에 각각 완전한 OS를 포함하므로 격리성은 뛰어나지만, 리소스를 많이 차지하고 부팅 시간이 길다.

컨테이너(Container)​

비유: 셰어하우스의 개인 방

건물의 기초와 주방, 화장실(호스트 OS 커널)은 공유하지만, 각자의 방(컨테이너)은 독립적이다. 컨테이너는 OS 커널을 공유하면서 애플리케이션과 그 의존성만 패키징하므로, VM보다 훨씬 가볍고 시작이 빠르다. 수 초 만에 실행 가능하다.

VM vs 컨테이너: VM은 독채 주택(무겁지만 완전 격리), 컨테이너는 셰어하우스 개인 방(가볍지만 커널 공유)이다. 보안이 중요하면 VM, 빠른 배포와 효율이 중요하면 컨테이너를 선택한다.

2.4 컨테이너 기술​

Docker​

비유: 표준 규격 택배 상자

택배를 보낼 때 물건 크기에 맞는 표준 상자에 넣으면 어떤 택배사든 동일하게 운반할 수 있다. Docker는 애플리케이션과 실행 환경을 표준 이미지(상자)로 패키징하여, 어떤 서버(택배 트럭)에서든 동일하게 실행할 수 있게 한다.

Docker Swarm​

비유: 택배 물류센터의 기본 관리 시스템

택배 상자(Docker 컨테이너)가 수십 개로 늘어나면 어디로 보낼지 관리가 필요하다. Docker Swarm은 Docker 자체에 내장된 오케스트레이션 도구로, 여러 서버에 걸쳐 컨테이너를 배포하고 관리한다. 설정이 간단하지만, 대규모 환경에서는 기능이 제한적이다.

containerd​

비유: 택배 상자를 실제로 트럭에 싣고 내리는 작업자

Docker라는 브랜드(상위 도구)가 있고, 그 안에서 실제 컨테이너를 생성하고 실행하는 핵심 엔진이 containerd다. 경량 컨테이너 런타임으로, Kubernetes에서 Docker 없이도 containerd만으로 컨테이너를 운영할 수 있다.

2.5 컨테이너 오케스트레이션​

Kubernetes​

비유: 대형 물류 허브의 자동화 관제 시스템

수천 개의 택배 상자(컨테이너)가 매일 들어오고 나가는 거대한 물류 허브에서, 어떤 트럭에 어떤 상자를 실을지, 고장 난 트럭을 대체할지, 물량이 늘면 트럭을 추가할지를 자동으로 관제한다. Kubernetes는 컨테이너의 배포, 스케일링, 장애 복구를 자동 관리하는 오케스트레이션 플랫폼이다.

Kubernetes 컴포넌트​

비유: 물류 허브의 조직도

  • API Server: 물류 허브의 접수 창구. 모든 요청이 여기를 통해 들어온다.
  • etcd: 물류 허브의 중앙 장부. 모든 상태 정보(어떤 트럭에 뭐가 실려 있는지)가 기록된다.
  • Scheduler: 배차 담당자. 새 화물(Pod)이 들어오면 여유 있는 트럭(노드)에 배정한다.
  • Controller Manager: 품질 관리자. "트럭은 항상 5대 가동" 같은 규칙이 지켜지는지 감시하고, 이상이 생기면 조치한다.
  • Kubelet: 각 트럭의 운전기사. 자기 트럭(노드)에서 컨테이너가 정상 실행되도록 관리한다.

HPA(Horizontal Pod Autoscaler)​

비유: 콜센터 자동 인력 배치

전화가 많이 오면 상담원(Pod)을 추가 투입하고, 한가해지면 줄인다. HPA는 CPU나 메모리 사용률 같은 지표를 모니터링하여, Pod 수를 자동으로 늘리거나 줄이는 Kubernetes의 자동 확장 기능이다.

Pod​

비유: 트럭 한 대에 실린 화물 묶음

트럭에 함께 실려야 하는 관련 화물을 하나로 묶은 단위다. Pod는 Kubernetes에서 배포할 수 있는 가장 작은 단위로, 하나 이상의 컨테이너가 네트워크와 스토리지를 공유하며 함께 실행된다.

Service​

비유: 물류 허브의 고정 전화번호

트럭(Pod)은 교체될 수 있지만, 고객이 전화하는 번호(Service)는 변하지 않는다. Service는 Pod 집합에 대한 고정 접점(IP, DNS)을 제공하여, Pod가 교체되어도 클라이언트가 동일한 주소로 접근할 수 있게 한다.

Helm​

비유: 가구 조립 설명서 패키지(IKEA 패키지)

이케아에서 책상을 사면 나사, 판, 설명서가 한 세트로 온다. Helm은 Kubernetes 애플리케이션 배포에 필요한 여러 리소스(Deployment, Service, ConfigMap 등)를 하나의 차트(Chart)로 패키징하여, 한 번의 명령으로 설치/업그레이드/삭제할 수 있게 한다.

2.6 네트워크 가상화​

VLAN(Virtual LAN)​

비유: 사무실 층별 칸막이

같은 건물(물리 네트워크)인데 칸막이(논리 분리)로 부서별 공간을 나누는 것이다. 물리적으로 같은 스위치에 연결되어 있어도, VLAN으로 논리적으로 분리하면 서로 다른 네트워크처럼 동작한다. 최대 4,096개까지 만들 수 있다.

VPN(Virtual Private Network)​

비유: 비밀 지하 통로

두 건물 사이에 외부에서 보이지 않는 비밀 지하 통로를 만드는 것이다. 공용 인터넷(공개 도로)을 통과하지만, 암호화된 터널을 만들어 마치 전용 회선처럼 안전하게 데이터를 주고받는다. 재택근무자가 회사 내부망에 접속할 때 사용한다.

VXLAN(Virtual eXtensible LAN)​

비유: 전국 단위 칸막이 시스템

VLAN이 한 건물(4,096개)의 칸막이라면, VXLAN은 전국 수천만 개 건물에 칸막이를 칠 수 있는 시스템이다. VLAN의 4,096개 제한을 극복하여 약 1,600만 개의 가상 네트워크를 만들 수 있다. 대규모 클라우드 환경에서 수많은 테넌트(입주자)를 격리하는 데 필수적이다.

2.7 스토리지 가상화​

스토리지 가상화​

비유: 여러 창고를 하나의 거대한 창고처럼 쓰기

서울, 부산, 대전에 창고가 하나씩 있는데, 관리 시스템이 이 세 창고를 하나의 거대한 창고처럼 보여준다. 물건을 넣으면 시스템이 알아서 적절한 창고에 배치한다. 스토리지 가상화는 여러 물리 스토리지를 하나의 논리적 풀로 묶어 관리하는 기술이다.

  • 블록 레벨 가상화: 창고 선반 한 칸 단위로 관리. 가장 빠르고 정밀하다. 데이터베이스에 적합하다.
  • 파일 레벨 가상화: 폴더/파일 단위로 관리. 여러 NAS를 하나로 통합한다.
  • 오브젝트 레벨 가상화: 택배 상자(객체) 단위로 관리. 사진, 동영상 같은 비정형 데이터에 적합하다.

2.8 데스크톱 가상화​

VDI(Virtual Desktop Infrastructure)​

비유: 극장 영사실에서 각 스크린에 영상 보내기

영사실(서버)에서 영화를 재생하고, 각 상영관(사용자 단말기)에 화면만 전송한다. 상영관에는 스크린만 있으면 된다. VDI는 서버에서 데스크톱 환경을 실행하고, 사용자는 씬 클라이언트(단말기)에서 화면만 받아 보는 구조다. 데이터가 서버에 있으므로 보안이 강화된다.

DaaS(Desktop as a Service)​

비유: 넷플릭스처럼 구독하는 데스크톱

영사 장비(VDI 인프라)를 직접 사지 않고, 넷플릭스처럼 월정액을 내고 클라우드에서 데스크톱을 스트리밍 받는 것이다. VDI가 직접 구축형이라면, DaaS는 이를 클라우드 서비스로 제공하는 형태다. 회사 장비 없이 어디서든 동일한 업무 환경을 사용할 수 있다.

3. 서버리스 및 자동화​

3.1 서버리스 컴퓨팅​

서버리스 컴퓨팅(Serverless Computing)​

비유: 택시 타기

자가용(서버)을 사지 않고, 필요할 때만 택시를 부른다. 목적지에 도착하면 택시는 다른 손님을 태우러 간다. 서버리스는 서버를 직접 관리하지 않고, 코드를 올려두면 요청이 있을 때만 실행 환경이 만들어지고, 끝나면 자원이 자동 반환된다. "서버가 없다"가 아니라 "서버를 신경 쓰지 않아도 된다"는 뜻이다.

3.2 자동 확장​

Auto Scale​

비유: 놀이공원 매표소 창구

평일에는 매표 창구 2개만 열지만, 주말에 사람이 몰리면 5개로 늘린다. 다시 한가해지면 줄인다. Auto Scale은 트래픽이나 부하에 따라 서버 자원을 자동으로 늘리거나 줄이는 기능이다.

Scale Up(수직 확장)​

비유: 매표 직원을 더 빠른 사람으로 교체

창구 수는 그대로 두고, 더 빠르게 일하는 직원(더 높은 사양의 서버)으로 교체하는 것이다. 서버의 CPU, 메모리, 디스크를 업그레이드하여 성능을 높인다. 한계가 있고, 교체 시 다운타임이 발생할 수 있다.

Scale Out(수평 확장)​

비유: 매표 창구 자체를 추가

직원 한 명의 속도를 올리는 대신, 창구(서버)를 더 설치하는 것이다. 동일한 사양의 서버를 여러 대 추가하여 부하를 분산한다. 이론적으로 무한 확장이 가능하고, 클라우드 환경에서 선호되는 방식이다.

3.3 코드형 인프라​

IaC(Infrastructure as Code)​

비유: 요리 레시피 문서화

매번 감으로 요리하면 맛이 들쭉날쭉하다. 레시피를 정확히 문서화해 두면 누가 해도 같은 맛을 낸다. IaC는 서버, 네트워크, 스토리지 같은 인프라 구성을 코드로 작성하여, 반복 가능하고 일관된 환경을 자동으로 프로비저닝하는 방식이다. 코드이므로 Git으로 버전 관리도 가능하다.

Terraform​

비유: 만능 레시피 번역기

한식, 양식, 중식(AWS, Azure, GCP) 어떤 주방에서든 작동하는 범용 레시피 형식이다. HashiCorp이 만든 오픈소스 IaC 도구로, 클라우드 벤더에 독립적인 선언형 언어(HCL)로 인프라를 정의한다. 멀티클라우드 환경에서 특히 유용하다.

Ansible​

비유: 집 정리 체크리스트

"거실 청소 - 설거지 - 빨래" 순서대로 체크리스트를 만들어 놓으면, 누가 와도 같은 절차로 집을 정리한다. Ansible은 YAML 기반 플레이북으로 서버 설정, 소프트웨어 설치, 배포 작업을 자동화하는 도구다. 별도 에이전트 설치가 필요 없는 것이 특징이다.

4. 데이터센터 및 인프라​

4.1 데이터센터 진화​

SDDC(Software-defined Data Center)​

비유: 스마트 홈

예전에는 조명, 에어컨, 보안을 각각 수동으로 관리했지만, 스마트 홈에서는 앱 하나로 모든 것을 제어한다. SDDC는 서버(컴퓨팅), 스토리지, 네트워크를 모두 소프트웨어로 추상화하고 자동화하는 데이터센터 모델이다. 물리 장비를 직접 만지지 않고 소프트웨어로 제어한다.

HCI(Hyper Converged Infrastructure)​

비유: 올인원 프린터(복합기)

프린터, 스캐너, 복사기, 팩스가 각각 따로 있으면 공간도 많이 차지하고 관리가 복잡하다. 올인원 복합기처럼 서버, 스토리지, 네트워킹을 하나의 어플라이언스로 통합한 것이 HCI다. 레고 블록처럼 노드를 추가하면 자원이 비례해서 늘어나므로 확장이 쉽다.

4.2 데이터센터 운영​

그린 데이터센터​

비유: 에코 하우스

태양광 패널, 빗물 재활용, 단열재를 갖춘 친환경 주택처럼, 그린 데이터센터는 신재생 에너지를 사용하고, 냉각 효율을 극대화하며, 탄소 배출을 최소화하는 데이터센터다. 기후변화 대응과 ESG 경영의 핵심 요소이다.

AI 데이터센터(대규모 AI 서비스 데이터센터)​

비유: F1 레이싱 전용 서킷

일반 도로(범용 DC)와 달리, F1 서킷(AI DC)은 초고속 주행을 위해 노면, 커브, 안전 시설이 특화되어 있다. AI 데이터센터는 GPU 클러스터, 초고속 인터커넥트, 대용량 냉각 시스템 등 AI 학습과 추론에 최적화된 인프라를 갖춘다.

PUE(Power Usage Effectiveness)​

비유: 연비(km/L)

자동차가 기름 1L로 몇 km를 가느냐가 연비이듯, PUE는 데이터센터가 전력을 얼마나 효율적으로 쓰느냐를 나타내는 지표다. PUE = 총 전력 / IT 장비 전력이며, 1.0에 가까울수록 효율적이다. 이상적인 값은 1.0(모든 전력이 IT 장비에만 사용)이지만, 냉각 등에 전력이 필요하므로 현실적으로는 1.2~1.5 수준을 목표로 한다.

DCI(Data Center Interconnect)​

비유: 도시 간 고속도로

각 도시(데이터센터)를 연결하는 고속도로(전용 네트워크)다. DCI는 지리적으로 분산된 데이터센터 간을 초고속 광 네트워크로 연결하여, 데이터 복제, 재해복구, 부하 분산을 가능하게 하는 기술이다. AI 데이터센터에서는 GPU 클러스터 간 저지연 통신이 필수적이다.

5. 클라우드 도입 및 전환​

5.1 클라우드 전환​

클라우드 전환 선정기준​

비유: 이사할 짐 선별 기준

이사를 갈 때 모든 짐을 한꺼번에 옮기지 않고, "버릴 것 / 먼저 옮길 것 / 나중에 옮길 것"을 분류한다. 클라우드 전환 선정기준은 기존 온프레미스 시스템 중 어떤 것을 먼저 클라우드로 옮길지, 비용-효과-위험을 기준으로 우선순위를 정하는 프레임워크다.

클라우드 전환 감리​

비유: 건축 감리관

건물을 지을 때 감리관이 설계대로 시공되는지 단계별로 확인하듯, 클라우드 전환 감리는 전환 사업이 계획대로 진행되는지 요구분석, 설계, 이행, 안정화 각 단계를 점검하고 검증하는 활동이다.

5.2 클라우드 아키텍처 설계​

존(Zone) 구성​

비유: 아파트 단지의 동별 용도 구분

아파트 단지에서 101동은 주거, 102동은 상가, 103동은 커뮤니티센터로 용도를 나누듯, 클라우드 존 구성은 인프라를 용도별(웹, WAS, DB, 관리 등) 존으로 나누어 설계하는 것이다. 존 간 접근 제어를 통해 보안을 강화한다.

CMP(Cloud Management Platform)​

비유: 아파트 통합 관리 앱

전기 요금, 수도 요금, 주차, 민원을 하나의 앱에서 관리하는 것처럼, CMP는 여러 클라우드 환경의 자원 프로비저닝, 모니터링, 비용 관리, 거버넌스를 한 곳에서 통합 관리하는 플랫폼이다. 멀티클라우드 환경에서 특히 중요하다.

5.3 공공/금융 클라우드​

공공부문 클라우드 서비스​

비유: 정부 관용차 대신 공유차 이용 정책

각 부처마다 관용차(자체 서버)를 보유하는 대신, 정부 인증된 공유차 서비스(클라우드)를 이용하도록 하는 정책이다. 공공기관의 클라우드 서비스 활용 절차, 기본 설계 방법, 보안 요건을 규정한다.

SaaS 가이드라인(공공부문 SaaS 이용 가이드라인)​

비유: 관용차 공유 서비스 이용 규칙

공유차를 이용할 때도 "업무용만 사용", "개인정보 두고 내리기", "사고 시 보고 절차" 같은 규칙이 필요하다. SaaS 가이드라인은 공공기관이 SaaS를 도입할 때 따라야 할 위험 관리 원칙, 보안 기준, 데이터 주권 확보 방안을 제시한다.

금융 클라우드 SLA​

비유: 금고 보관 서비스 계약서

귀중품을 금고에 맡길 때 "24시간 경비", "도난 시 보상", "접근 기록 보관" 등을 계약서에 명시한다. 금융 클라우드 SLA는 금융기관이 클라우드를 사용할 때 가용성, 보안 수준, 장애 복구 시간, 데이터 보호 수준을 서비스 수준 협약(SLA)으로 명확히 규정한 것이다.

5.4 클라우드 보안 및 거버넌스​

CSAP(Cloud Security Assurance Program)​

비유: 식품 안전 인증 마크(HACCP)

식당이 HACCP 인증을 받아야 공공기관 급식을 납품할 수 있듯, 클라우드 서비스 업체가 CSAP 인증을 받아야 공공기관에 서비스를 제공할 수 있다. 한국인터넷진흥원(KISA)이 물리적 보안, 데이터 보호, 침해사고 대응 등을 평가하여 인증을 부여한다.

클라우드 보안 고려사항​

비유: 셰어하우스 입주 시 체크리스트

셰어하우스(클라우드)에 입주할 때 "현관 비밀번호 관리", "개인 물건 잠금장치", "화재 대피로 확인" 등을 체크하듯, 클라우드 보안 고려사항은 데이터 암호화, 접근 제어, 네트워크 분리, 감사 로그, 재해 복구 등 클라우드 도입 시 반드시 점검해야 할 보안 항목이다.

아웃소싱 리스크 관리(클라우드 아웃소싱 리스크)​

비유: 위탁 급식 업체 리스크 관리

학교 급식을 위탁 업체에 맡기면 편하지만, 업체가 부실하면 식중독 사고가 난다. 클라우드 아웃소싱 리스크 관리는 CSP에게 인프라를 맡길 때 발생할 수 있는 위험(벤더 종속, 데이터 유출, 서비스 중단, 법적 준거 등)을 식별하고, 대응 전략을 수립하는 것이다.

6. 엣지 컴퓨팅​

6.1 엣지 컴퓨팅 개요​

엣지 컴퓨팅(Edge Computing)​

비유: 지역 응급실 vs 대학병원

모든 환자가 서울 대학병원(중앙 클라우드)에 가면 대기 시간이 너무 길다. 동네 응급실(엣지)에서 1차 처리를 하고, 중증 환자만 대학병원으로 이송한다. 엣지 컴퓨팅은 데이터가 발생하는 현장(공장, 차량, 기지국) 가까이에서 1차 처리를 수행하여 지연 시간을 줄이고, 필요한 데이터만 클라우드로 전송하는 분산 컴퓨팅 모델이다.

6.2 모바일 엣지 컴퓨팅​

MEC(Mobile Edge Computing)​

비유: 편의점(동네 미니 물류센터)

대형 마트(클라우드)까지 가지 않고, 동네 편의점(5G 기지국 근처 서버)에서 바로 물건을 받는 것이다. MEC는 이동통신 기지국 근처에 컴퓨팅 자원을 배치하여, 스마트폰이나 차량에서 발생한 데이터를 수 밀리초 이내로 처리한다. AR/VR, 자율주행, 실시간 게임 같은 초저지연 서비스의 핵심 인프라다.

6.3 분산 클라우드 / Fog Computing​

Fog Computing​

비유: 지역 물류 허브

중앙 물류센터(클라우드)와 각 가정(엣지 디바이스) 사이에 지역 물류 허브를 두는 것이다. Fog Computing은 클라우드와 엣지 디바이스 사이의 중간 계층에서 데이터를 수집, 처리, 저장한다. 엣지보다는 더 많은 자원을 갖추고, 클라우드보다는 사용자에게 가까운 위치에서 동작한다.

분산 클라우드(Distributed Cloud)​

비유: 전국에 분점을 둔 프랜차이즈

본사(중앙 클라우드)가 운영하지만, 전국 각지에 분점(분산 노드)이 있어서 고객은 가장 가까운 분점에서 서비스를 받는다. 분산 클라우드는 퍼블릭 클라우드 서비스를 여러 지리적 위치에 분산 배치하되, 중앙에서 일관되게 관리하는 모델이다. 일관된 정책과 거버넌스를 유지하면서도 저지연 서비스를 제공한다.

Cloudlet​

비유: 무인 택배 보관함(스마트 로커)

대형 물류센터(클라우드)까지 가지 않고, 아파트 입구의 무인 보관함에서 택배를 수령하는 것이다. Cloudlet은 사용자 근처에 설치된 소규모 클라우드 인프라로, 지연 시간이 극히 짧아야 하는 모바일 애플리케이션을 지원한다. MEC와 유사하지만, 학술 연구에서 시작된 개념으로 Wi-Fi 기반 환경에서 주로 논의된다.
