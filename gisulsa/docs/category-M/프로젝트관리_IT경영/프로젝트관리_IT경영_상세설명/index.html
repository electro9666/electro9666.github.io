프로젝트관리/IT경영 개념 상세설명 (비유로 쉽게 이해하기)

정보관리기술사 110~138회 기출 키워드 기반 각 개념을 일상생활의 비유를 통해 쉽게 설명합니다.

1. 프로젝트관리 기초​

1.1 IT 프로젝트 관리 개요​

IT 프로젝트 관리​

비유: 결혼식 준비

결혼식은 정해진 날짜(일정)와 예산(비용) 안에서 최고의 행사(품질)를 만들어야 하는 한시적 이벤트다. IT 프로젝트 관리도 마찬가지로, 정해진 범위/일정/비용 안에서 목표를 달성하기 위해 착수부터 종료까지 체계적으로 관리하는 것이다.

프로그램 관리(Program Management)​

비유: 축제 전체 운영

축제에는 공연, 먹거리 부스, 체험관 등 여러 행사(프로젝트)가 동시에 진행된다. 프로그램 관리는 이렇게 서로 관련된 여러 프로젝트를 묶어서 개별적으로 관리할 때보다 더 큰 시너지를 얻기 위해 통합 관리하는 것이다.

포트폴리오 관리(Portfolio Management)​

비유: 투자 포트폴리오 운용

주식, 채권, 부동산에 자산을 배분하듯, 기업이 보유한 여러 프로젝트와 프로그램을 전략 목표에 맞게 선별하고 우선순위를 정해 자원을 배분하는 것이다. "어디에 투자하면 가장 높은 가치를 얻을까?"를 결정한다.

1.2 프로젝트 관리 표준​

PMBOK(Project Management Body of Knowledge)​

비유: 요리 백과사전

어떤 요리든 "재료 준비, 조리, 플레이팅"의 기본 원리가 있듯, PMBOK은 프로젝트 관리의 지식 체계를 10개 지식영역(범위, 일정, 비용, 품질, 자원, 의사소통, 위험, 조달, 이해관계자, 통합)과 5개 프로세스 그룹(착수, 계획, 실행, 감시통제, 종료)으로 정리한 백과사전이다.

ISO 21500​

비유: 국제 표준 레시피북

PMBOK이 미국식 요리책이라면, ISO 21500은 전 세계 어디서든 통용되는 국제 표준 레시피북이다. 프로젝트 관리의 개념과 프로세스를 국제 표준으로 정의하여 국가와 산업을 넘어 공통 언어를 제공한다.

PRINCE2(Projects IN Controlled Environments)​

비유: 영국식 정원 관리 매뉴얼

영국 정원은 구획마다 역할이 명확하고 단계별로 꼼꼼하게 관리한다. PRINCE2도 프로젝트를 여러 단계(Stage)로 나누고, 각 단계 끝에서 경영진이 "계속 진행할지 중단할지"를 판단하는 관문(Stage Gate)을 둔다. 비즈니스 정당성을 지속적으로 검증하는 것이 특징이다.

1.3 제약 이론​

TOC(Theory of Constraints)​

비유: 가장 좁은 도로가 전체 교통량을 결정한다

10차선 고속도로도 중간에 2차선 병목 구간이 있으면 전체 통행량은 2차선 수준으로 떨어진다. TOC는 시스템의 성과가 가장 약한 고리(병목)에 의해 결정된다는 이론이다. 병목을 찾아 개선하면 전체 시스템 성과가 향상된다. 5단계: 제약 식별 - 제약 활용 - 제약에 종속 - 제약 향상 - 반복.

2. 범위 및 일정 관리​

2.1 작업 분류 체계​

WBS(Work Breakdown Structure)​

비유: 큰 피자를 조각으로 나누기

피자 한 판을 한 입에 먹을 수 없으니 조각으로 나눈다. WBS는 프로젝트 전체 범위를 관리 가능한 작은 작업 단위(Work Package)로 계층적으로 분해한 것이다. "이사하기"를 "짐 포장 - 운반 - 정리"로 나누고, "짐 포장"을 다시 "옷 포장, 그릇 포장, 가전 포장"으로 세분화하는 것과 같다.

PBS / OBS / RBS​

비유: 같은 이사를 다른 관점으로 보기

  • PBS(Product Breakdown Structure): 이사에서 "무엇을 옮기나?" - 산출물(제품) 중심 분해
  • OBS(Organization Breakdown Structure): "누가 담당하나?" - 조직/인력 중심 분해
  • RBS(Resource Breakdown Structure): "어떤 자원이 필요한가?" - 트럭, 인력, 포장재 등 자원 중심 분해

2.2 일정 관리 기법​

CPM(Critical Path Method)​

비유: 가장 오래 걸리는 출근 경로 찾기

집에서 회사까지 "샤워 - 옷 입기 - 아침 식사 - 운전"의 여러 경로가 있다. CPM은 모든 경로 중 가장 오래 걸리는 경로(주공정, Critical Path)를 찾는다. 이 경로가 지연되면 전체 프로젝트가 지연되므로, 집중 관리 대상이 된다.

주공정(Critical Path)​

비유: 도미노의 가장 긴 줄

도미노를 여러 갈래로 배치했을 때, 가장 긴 줄이 모두 넘어져야 마지막 도미노가 쓰러진다. 주공정은 프로젝트에서 여유 시간(Float)이 0인 활동들의 연결이며, 이 경로의 길이가 곧 프로젝트 최소 소요 기간이다.

CCPM(Critical Chain Project Management)​

비유: 안전 여유를 모아서 한 곳에 두기

각 방에 소화기를 하나씩 두는 대신, 복도에 대형 소화기를 비치하는 것과 같다. CCPM은 각 활동에 숨겨진 안전 여유(버퍼)를 제거하고, 프로젝트 끝에 프로젝트 버퍼를 모아두어 전체적으로 더 효율적으로 관리한다. TOC를 프로젝트 일정에 적용한 기법이다.

PERT(Program Evaluation and Review Technique)​

비유: 낙관/비관/평균으로 소요 시간 추정

"출근 시간이 20분(낙관), 40분(비관), 보통 30분(최빈)"이라면 기대값을 산출한다. PERT는 3점 추정(낙관치, 비관치, 최빈치)을 사용하여 불확실한 활동의 소요 기간을 확률적으로 계산한다. 기대값 = (낙관 + 4 x 최빈 + 비관) / 6.

네트워크 다이어그램​

비유: 지하철 노선도

지하철 노선도가 역(활동)과 노선(의존관계)을 보여주듯, 네트워크 다이어그램은 프로젝트 활동 간의 선후관계를 시각적으로 표현한다. AOA(Activity on Arrow)는 화살표 위에, AON(Activity on Node)은 노드 안에 활동을 표시한다.

일정 단축(Schedule Compression)​

비유: 마감일을 당기는 비상 수단

보고서 마감일이 갑자기 앞당겨졌을 때 쓰는 전략이다. 범위를 줄이지 않으면서 일정만 단축하는 두 가지 방법이 있다.

Crashing​

비유: 야근 수당 주고 인력 투입

추가 비용을 투입하여 일정을 단축한다. 이사할 때 친구를 더 불러 도와달라고 밥을 사주는 것과 같다. 비용 대비 일정 단축 효과가 가장 큰 활동부터 적용한다.

Fast Tracking​

비유: 순서를 무시하고 동시에 진행

원래 "설계 끝나면 시공"인데, 설계가 80% 되었을 때 시공을 시작하는 것이다. 비용 추가 없이 일정을 단축하지만, 재작업 위험이 커진다.

3. 가치 및 성과 관리​

3.1 EVM(Earned Value Management)​

EVM(Earned Value Management)​

비유: 다이어트 진행률 관리

"3개월에 15kg 감량" 계획에서 2개월째 확인: 계획상 10kg 빠져야 했는데(PV), 실제 7kg 빠졌고(EV), 헬스장비에 돈은 12만 원 썼다(AC). 계획 대비 실적을 비용과 일정 관점에서 객관적으로 측정하는 기법이다.

PV(Planned Value, 계획 가치)​

비유: 오늘까지 빠져야 할 계획 체중

특정 시점까지 완료하기로 계획한 작업의 예산 가치. "2개월까지 10kg 빠지는 게 목표"에서 10kg에 해당한다.

EV(Earned Value, 획득 가치)​

비유: 실제로 빠진 체중

실제로 완료한 작업의 예산 가치. "2개월째 실제로 7kg 빠졌다"에서 7kg에 해당한다.

AC(Actual Cost, 실제 비용)​

비유: 실제로 쓴 다이어트 비용

작업을 수행하는 데 실제 투입된 비용. 헬스장 등록비, 식단 비용 등 실제 지출액이다.

SPI / CPI / SV / CV​

비유: 성적표의 각 항목

  • SV(Schedule Variance, 일정차이) = EV - PV: 계획보다 빠른지 느린지. 음수면 지연.
  • CV(Cost Variance, 비용차이) = EV - AC: 예산 내인지 초과인지. 음수면 초과 지출.
  • SPI(Schedule Performance Index) = EV / PV: 일정 효율. 1보다 크면 앞서감.
  • CPI(Cost Performance Index) = EV / AC: 비용 효율. 1보다 크면 예산 절약.

EVM vs Burn Down Chart​

비유: 건강검진표 vs 체중계 그래프

EVM은 혈압, 혈당, 체지방 등 여러 지표를 종합적으로 분석하는 건강검진표다. 반면 번다운 차트는 "남은 체중"만 간단하게 보여주는 체중계 그래프다. EVM은 비용/일정을 정밀 분석하고, 번다운 차트는 남은 작업량을 직관적으로 보여준다. 애자일에서는 번다운 차트를, 전통적 PM에서는 EVM을 주로 사용한다.

4. 위험 관리​

4.1 위험 관리 개요​

프로젝트 위험관리​

비유: 여행 전 만반의 준비

해외여행 전에 "여권 분실 대비 복사본 준비, 아플 때를 대비해 상비약 챙기기, 환율 변동 대비 카드 준비" 등을 하는 것이다. 프로젝트 위험관리는 불확실한 사건을 미리 식별하고, 발생 확률과 영향을 분석하여, 대응 전략을 수립하고 모니터링하는 체계적 프로세스다.

ISO 31000​

비유: 위험 관리의 국제 교과서

모든 종류의 조직과 위험에 적용 가능한 범용 위험 관리 프레임워크다. "위험 관리 원칙 - 프레임워크 - 프로세스"의 3계층 구조를 갖는다. 특정 산업이 아닌 보편적 위험 관리의 국제 표준이다.

4.2 정량적 위험 분석​

정량적 위험분석​

비유: 감으로 느끼는 것이 아니라 숫자로 계산하기

"위험할 것 같다"(정성적)가 아니라 "이 위험이 발생하면 3천만 원 손실, 발생확률 30%"(정량적)처럼 숫자로 표현한다. 4가지 대표 기법이 있다.

민감도 분석​

비유: 요리에서 소금 양을 바꿔보기

소금을 조금 더 넣으면 맛이 어떻게 변하는지 확인하듯, 하나의 변수를 바꿔가며 결과에 미치는 영향을 분석한다. 토네이도 다이어그램으로 어떤 변수가 가장 큰 영향을 주는지 시각화한다.

기대값 분석(EMV)​

비유: 복권의 기대수익 계산

"1등 당첨금 10억 x 확률 0.001% = 기대값 1만 원"처럼, 각 위험 시나리오의 (영향 x 확률)을 계산해 합산한다. 의사결정에 객관적 근거를 제공한다.

의사결정나무(Decision Tree)​

비유: 선택의 갈림길 지도

RPG 게임에서 선택지마다 다른 결과가 나오는 것처럼, 각 의사결정 지점에서 선택지와 그에 따른 확률/결과를 나무 형태로 그린다. 각 가지의 기대값을 비교하여 최선의 선택을 한다.

몬테카를로 시뮬레이션​

비유: 주사위를 만 번 던져보기

"이 프로젝트가 6개월 안에 끝날 확률은?"에 답하기 위해, 컴퓨터로 수천~수만 번 시뮬레이션을 돌린다. 각 활동의 소요 기간을 확률 분포로 입력하면, 전체 프로젝트 완료 시점의 확률 분포를 얻는다. S-커브 형태의 결과를 통해 "80% 확률로 7개월 내 완료" 같은 답을 제공한다.

4.3 위험 대응 전략​

회피(Avoid)​

비유: 비 오는 날 소풍 취소

위험 자체를 제거한다. 프로젝트 계획을 변경하여 위험이 발생할 수 없도록 만든다. 예: 검증되지 않은 기술 대신 안정적인 기술을 선택.

전가(Transfer)​

비유: 보험 가입

화재 위험을 보험회사에 전가하듯, 위험의 결과를 제3자에게 이전한다. 아웃소싱, 보증, 계약 조건 등이 해당한다. 위험이 사라지는 것이 아니라 책임 주체가 바뀐다.

완화(Mitigate)​

비유: 안전벨트 착용

사고를 완전히 막을 수는 없지만, 안전벨트로 피해를 줄인다. 위험의 발생 확률이나 영향을 줄이는 사전 조치다. 예: 핵심 인력 백업 확보, 프로토타입 선행 개발.

수용(Accept)​

비유: 우산 없이 소나기를 맞기로 결정

위험이 발생해도 감수하기로 한다. 능동적 수용은 비상 예비비(Contingency Reserve)를 확보하고, 수동적 수용은 발생 시 대처한다. 영향이 작거나 대응 비용이 더 클 때 선택한다.

5. 인적 자원 및 의사소통​

5.1 팀 발달 모델​

터크만 사다리 모델(Tuckman Ladder Model)​

비유: 새 학기 반 친구들의 변화 과정

새 학기가 시작되면 서먹한 시기를 거쳐 점점 팀워크가 만들어진다. 터크만은 팀이 성숙해가는 5단계를 정의했다.

Forming(형성기)​

비유: 첫 날 어색한 자기소개

팀원들이 처음 만나 서로를 탐색한다. 역할과 책임이 불명확하고, 리더에게 의존한다.

Storming(격동기)​

비유: 반장 선거 때 의견 충돌

서로의 성격과 의견 차이가 드러나면서 갈등이 발생한다. 이 시기를 잘 넘기면 팀이 강해진다.

Norming(규범기)​

비유: 반 규칙이 만들어지고 자리 잡기

갈등을 극복하고 팀의 규칙과 역할이 정해진다. 서로를 이해하고 협력 방식이 확립된다.

Performing(성과기)​

비유: 호흡이 척척 맞는 학예회 준비

팀이 자율적으로 높은 성과를 낸다. 리더의 지시 없이도 문제를 해결하고, 시너지가 극대화된다.

Adjourning(해산기)​

비유: 졸업식

프로젝트가 완료되어 팀이 해산된다. 성과를 정리하고, 교훈을 기록한다.

5.2 갈등 관리​

갈등관리​

비유: 가족 회의에서 의견 충돌 해결

가족끼리 여행지를 정할 때 의견이 다르면 다양한 해결법을 쓴다. 프로젝트에서도 팀원 간 갈등은 불가피하며, PM은 적절한 해결 전략을 선택해야 한다.

PM 갈등 해결 전략​

비유: 부모의 중재 방식

  • 협력/문제해결(Collaborate): 함께 가장 좋은 답을 찾는다 - "둘 다 원하는 것을 만족시킬 방법을 찾자"
  • 타협(Compromise): 서로 양보한다 - "번갈아 가자"
  • 철회/회피(Withdraw): 일단 피한다 - "나중에 다시 얘기하자"
  • 강제(Force): 권한으로 밀어붙인다 - "내가 정한다"
  • 완화(Smooth): 공통점을 강조한다 - "우리 생각이 비슷하잖아"

5.3 의사소통 관리​

커뮤니케이션 통로​

비유: 단체 카톡방 인원 수 vs 대화량

5명 카톡방에서 모든 사람이 1:1로 대화할 수 있는 통로 수는 10개다. 통로 수 공식은 n(n-1)/2. 팀원이 10명이면 45개, 20명이면 190개로 기하급수적으로 늘어난다. 인원이 많아질수록 의사소통 복잡도가 급증하므로, 체계적 의사소통 계획이 필요하다.

6. 정보화 전략 및 컨설팅​

6.1 ISP / ISMP​

ISP(Information Strategy Planning)​

비유: 도시 마스터플랜

도시를 건설하기 전에 주거지, 상업지, 공업지를 어디에 배치할지 종합 계획을 세우듯, ISP는 기업의 경영 전략에 맞추어 정보 시스템을 어떻게 구축할지 장기 계획을 수립하는 것이다. "3~5년 후 우리 IT는 어떤 모습이어야 하는가?"에 답한다.

ISMP(Information Strategy Master Plan)​

비유: 건축 설계도

ISP가 마스터플랜이라면, ISMP는 개별 건축물의 설계도다. 특정 정보화 사업을 추진하기 위한 구체적 방법론, 범위, 일정, 예산을 담는다. RFP 작성의 근거가 된다.

ISP/ISMP 비교​

비유: 도시계획 vs 건축설계

ISP는 "전사 차원의 중장기 IT 전략"이고, ISMP는 "개별 사업의 실행 계획"이다. ISP가 넓고 깊은 바다라면, ISMP는 특정 항구의 상세 설계도다.

EA/ITA(Enterprise Architecture / 정보기술아키텍처)​

비유: 기업의 IT 지도

구글 맵처럼 기업의 업무, 데이터, 응용 시스템, 기술 인프라를 한눈에 보여주는 설계도다. 중복 투자를 방지하고, 전체 시스템 간 정합성을 확보한다. 업무(BA), 데이터(DA), 응용(AA), 기술(TA) 아키텍처로 구성된다.

6.2 BPR/PI​

BPR(Business Process Reengineering)​

비유: 집을 허물고 새로 짓기

낡은 집을 리모델링하는 수준이 아니라, 완전히 허물고 새로 설계하여 짓는 것이다. BPR은 기존 업무 프로세스를 근본적으로 재설계하여 비용, 품질, 서비스, 속도를 획기적으로 개선하는 것이다.

PI(Process Innovation)​

비유: 집 리모델링

기존 구조는 유지하면서 주방을 넓히거나 욕실을 현대화하는 것처럼, PI는 기존 프로세스를 점진적으로 혁신한다. BPR보다 위험이 낮고 실행이 용이하다.

6.3 디지털 전환​

DX(Digital Transformation)​

비유: 종이 도서관에서 디지털 도서관으로

카드 목록함으로 책을 찾던 도서관이 검색 시스템, 전자책, AI 추천으로 바뀌는 것이다. DX는 디지털 기술을 활용하여 비즈니스 모델, 프로세스, 조직 문화를 근본적으로 변화시키는 것이다.

AX(AI Transformation)​

비유: 자동 운전 모드 전환

DX가 차를 수동에서 자동 변속기로 바꾼 것이라면, AX는 자율주행으로 한 단계 더 나아간 것이다. AI 기술을 조직 전반에 내재화하여, 의사결정과 업무를 AI가 지원하거나 자동화한다.

디지털 플랫폼 정부​

비유: 정부를 하나의 앱스토어로

각 부처가 개별 앱을 만드는 대신, 공통 플랫폼 위에서 데이터와 서비스를 연결하는 것이다. 국민은 하나의 창구에서 여러 정부 서비스를 이용하고, 민간도 공공 데이터를 활용해 혁신 서비스를 만든다.

7. 감리 및 PMO​

7.1 정보시스템 감리​

정보시스템 감리​

비유: 건축물의 제3자 안전 검사

건물을 지을 때 시공사가 아닌 제3자 검사관이 구조 안전, 소방 시설 등을 점검하듯, 정보시스템 감리는 독립된 감리법인이 정보시스템 구축 과정의 적정성을 객관적으로 점검하는 것이다. 발주자와 사업자 사이에서 공정한 시각을 제공한다.

감리 기준(행안부 고시)​

비유: 안전 검사 체크리스트

건축 안전 검사에 법적 기준이 있듯, 정보시스템 감리도 행안부 고시에 따라 감리 시점, 영역, 점검항목 등이 규정되어 있다.

감리 수행 가이드​

비유: 검사관의 업무 매뉴얼

감리원이 실제 감리를 수행할 때 참고하는 구체적 절차, 검사기준서, 산출물 양식 등을 담은 실무 지침이다.

7.2 PMO​

PMO(Project Management Office)​

비유: 학교 교무실

각 교실(프로젝트)에서 수업이 진행되지만, 교무실(PMO)에서 전체 시간표를 조율하고, 교육 품질을 관리하며, 공통 자원을 배분한다. PMO는 프로젝트 관리 표준을 수립하고, 여러 프로젝트를 조율하며, PM을 지원하는 상설 조직이다.

정보시스템 감리 vs PMO​

비유: 외부 감사 vs 내부 관리팀

감리는 외부 회계 감사처럼 독립적 제3자가 사후 점검하는 것이고, PMO는 내부 재무팀처럼 프로젝트 진행 중 지속적으로 관리/지원하는 것이다. 감리는 문제를 "지적"하고, PMO는 문제를 "예방하고 해결"한다.

상주감리/PMO 연관관계​

비유: 상근 관리인과 관리사무소의 협업

아파트 상근 관리인(상주감리)이 매일 현장을 점검하고, 관리사무소(PMO)가 전체 단지를 관리하며 서로 협력하는 관계다.

7.3 운영/유지보수 감리​

시스템 운영/유지보수 감리​

비유: 입주 후 건물 관리 감사

건물이 완공된 후에도 엘리베이터 점검, 소방 설비 관리가 제대로 되는지 정기적으로 감사하듯, 정보시스템이 운영 단계에서도 안정적으로 관리되는지 점검하는 것이다.

클라우드 전환 사업 감리​

비유: 이사(온프레미스에서 클라우드로) 과정 검사

자가 주택에서 임대 아파트로 이사할 때, 짐이 안전하게 옮겨졌는지, 새 집 시설이 계약대로인지 확인하듯, 클라우드 전환 시 데이터 이전, 보안, 서비스 수준 등을 감리하는 것이다.

8. IT 투자 및 성과 평가​

8.1 IT 투자 평가​

IT-ROI 투자 성과평가 모델​

비유: 가게 수익률 계산

치킨집에 5천만 원 투자해서 연 매출 1억이면 수익률을 계산하듯, IT 투자에 대한 수익률을 정량적으로 측정하는 모델이다. 유형 효과(비용 절감)와 무형 효과(고객 만족도 향상)를 모두 고려한다.

예비타당성조사 제도​

비유: 집 사기 전 시세 조사

비싼 집을 사기 전에 "이 가격이 적정한가? 투자 가치가 있는가?"를 조사하듯, 대규모 정보화 사업에 국민 세금을 투입하기 전에 기술적/경제적 타당성을 사전 검증하는 제도다.

8.2 BSC 및 전략맵​

BSC(Balanced Score Card)​

비유: 학생의 종합 생활기록부

성적(재무)만 보지 않고, 친구 관계(고객), 학습 습관(내부 프로세스), 자기개발(학습과 성장)까지 균형 있게 평가하는 것이다.

BSC 4가지 관점​

비유: 건강검진의 4대 영역

  • 재무 관점: 혈압/혈당 같은 핵심 수치 - "주주에게 어떤 재무 성과를 보여줄 것인가?"
  • 고객 관점: 환자 만족도 - "고객에게 어떤 가치를 제공할 것인가?"
  • 내부 프로세스 관점: 병원 운영 효율 - "어떤 업무 프로세스를 탁월하게 수행할 것인가?"
  • 학습과 성장 관점: 의료진 교육/연구 - "미래를 위해 어떻게 역량을 키울 것인가?"

BSC 전략맵​

비유: 인과관계 지도

"직원 교육(학습) - 업무 자동화(프로세스) - 고객 만족(고객) - 매출 증가(재무)"처럼 4개 관점의 목표들이 어떻게 연결되는지를 인과관계 화살표로 보여주는 지도다.

SEM(Strategic Enterprise Management)​

비유: 경영 내비게이션

운전 중 내비게이션이 현재 위치, 목적지, 최적 경로를 알려주듯, SEM은 기업의 현재 성과를 실시간으로 측정하고 전략 목표까지의 경로를 안내한다. BSC를 포함하여 가치기반경영(VBM), 활동기준경영(ABM) 등을 통합한 전략적 경영 체계다.

8.3 정보시스템 운영 성과평가​

정보시스템 운영 성과평가​

비유: 학기말 성적 평가

학기 동안 수업(시스템 운영)이 제대로 이루어졌는지, 출석률, 과제 완성도, 시험 성적 등 다양한 지표로 종합 평가하듯, 정보시스템이 운영 목표를 얼마나 달성했는지 정량적/정성적으로 측정한다.

9. 비용 산정 및 규모 산정​

9.1 SW 비용 산정​

소프트웨어 비용 산정​

비유: 집 짓는 데 얼마나 들까?

집을 짓기 전 "인건비, 자재비, 기간"을 추정하듯, SW 개발에 필요한 노력(인/월), 비용, 기간을 사전에 추정하는 것이다. 정확한 산정은 현실적 계획 수립의 기반이다.

상향식 산정(Bottom-Up)​

비유: 장바구니에 하나씩 담아 합산

각 작업 단위(WBS의 Work Package)별로 비용을 추정하고 합산한다. 정확하지만 시간과 노력이 많이 든다.

하향식 산정(Top-Down)​

비유: 총 예산에서 나눠 배분

"전체 예산 5억 중 설계 30%, 개발 50%, 테스트 20%"처럼 경험과 유사 프로젝트를 기반으로 전체에서 나누어 산정한다. 빠르지만 정확도가 떨어질 수 있다.

9.2 SW 규모 산정​

기능점수(Function Point)​

비유: 집의 평수 계산

집의 크기를 "몇 평"으로 나타내듯, 소프트웨어의 크기를 사용자가 요구하는 기능의 수와 복잡도로 측정한다. 입력(External Input), 출력(External Output), 조회(External Inquiry), 내부파일(ILF), 외부파일(EIF)의 5가지 기능 유형을 세고 복잡도 가중치를 적용한다.

COCOMO II Post-Architecture Model​

비유: 건축 설계 확정 후 정밀 견적

건축 설계가 나온 후에 자재와 인력을 정밀하게 산출하듯, 소프트웨어 아키텍처가 확정된 이후 17개 비용 동인(Cost Driver)과 5개 규모 인자(Scale Factor)를 반영하여 정밀하게 비용을 산정한다.

LOC(Lines of Code)​

비유: 원고지 매수로 글 분량 측정

글의 분량을 원고지 매수로 세듯, 소프트웨어의 규모를 코드 줄 수로 측정한다. 단순하지만 프로그래밍 언어나 코딩 스타일에 따라 편차가 크다.

9.3 SW 운영/AI 대가산정​

SW 운영단계 대가산정​

비유: 아파트 월 관리비 산정

아파트를 분양받은 후에도 매달 관리비가 든다. SW도 개발 후 운영/유지보수에 비용이 발생하며, 이를 체계적으로 산정하는 기준이다. 기능점수 기반, 투입공수 기반, 고정대가 기반 방식 등이 있다.

SW 대가산정(AI 서비스)​

비유: 맞춤 요리사 고용비

일반 식당 운영비와 미슐랭 셰프 고용비가 다르듯, AI 서비스는 데이터 수집/가공, 모델 학습, 추론 인프라 등 기존 SW와 다른 특수 비용 요소를 반영하여 산정한다.

9.4 HW 규모 산정​

HW 규모산정​

비유: 식당 주방 크기와 장비 결정

손님 수(사용자 수)와 메뉴 종류(업무 유형)에 따라 주방 크기, 오븐 수, 냉장고 용량을 결정하듯, 서버 CPU, 메모리, 디스크 용량을 업무량 기반으로 산정한다. 참조 방식, 산정식 방식, 시뮬레이션 방식의 3가지 방법이 있다.

9.5 품질 비용​

소프트웨어 품질비용​

비유: 자동차 안전 관련 비용의 4가지

  • 예방비용: 안전벨트, 에어백 설치비 - 결함을 미리 막는 비용 (교육, 리뷰, 프로세스 개선)
  • 평가비용: 출고 전 검사비 - 결함을 발견하기 위한 비용 (테스트, 감사, 코드 검토)
  • 내부실패비용: 공장에서 발견된 불량 폐기비 - 출시 전 결함 수정 비용 (재작업, 재테스트)
  • 외부실패비용: 리콜비 - 출시 후 고객이 발견한 결함 처리 비용 (패치, 배상, 평판 손실)

예방/평가비용을 늘리면 실패비용이 줄어들어 총 품질비용이 감소한다.

10. IT 거버넌스 및 IT 서비스 관리​

10.1 IT 거버넌스​

IT 거버넌스​

비유: 기업의 IT 헌법

국가 헌법이 권력 구조와 국민의 권리를 정하듯, IT 거버넌스는 "IT 의사결정 권한은 누가 갖는가? IT 자원은 어떻게 배분하는가? 성과는 어떻게 측정하는가?"를 정의하는 최상위 관리 체계다.

CMMI(Capability Maturity Model Integration)​

비유: 요리 실력 등급제

"초보 - 레시피 따라하기 - 자기 레시피 만들기 - 맛을 숫자로 관리 - 미슐랭 셰프"처럼 조직의 프로세스 성숙도를 5단계로 평가한다.

  • Level 1 (Initial, 초기): 감으로 요리. 결과 예측 불가.
  • Level 2 (Managed, 관리): 레시피를 따라 함. 반복 가능.
  • Level 3 (Defined, 정의): 표준 레시피가 조직에 정착.
  • Level 4 (Quantitatively Managed, 정량 관리): 맛, 온도, 시간을 수치로 관리.
  • Level 5 (Optimizing, 최적화): 지속적으로 레시피를 혁신.

COBIT(Control Objectives for Information and Related Technology)​

비유: IT 운전 면허 시험 기준

운전면허 시험에 "안전 운전, 교통법규, 차량 관리" 항목이 있듯, COBIT은 IT 거버넌스와 관리를 위한 프레임워크로 "계획/조직, 도입/구축, 운영/지원, 모니터링/평가"의 통제 목표를 제시한다.

10.2 IT 서비스 관리​

ITSM(IT Service Management)​

비유: 호텔 서비스 운영 체계

호텔이 "체크인-룸서비스-불만처리-체크아웃"을 체계적으로 관리하듯, ITSM은 IT를 "기술"이 아닌 "서비스" 관점에서 체계적으로 관리하는 것이다. 고객(사용자)에게 가치 있는 IT 서비스를 효율적으로 전달하는 데 초점을 둔다.

ISO/IEC 20000​

비유: 호텔 서비스 국제 인증

ISO 9001이 품질경영 인증이듯, ISO 20000은 IT 서비스 관리의 국제 표준 인증이다. ITSM을 수행하고 있음을 공식적으로 인정받는 것이다.

ITIL(IT Infrastructure Library)​

비유: 호텔 서비스 운영 모범사례 교과서

유명 호텔 체인의 운영 노하우를 정리한 교과서처럼, ITIL은 IT 서비스 관리의 모범사례(Best Practice)를 체계적으로 정리한 라이브러리다. 서비스 전략, 설계, 전환, 운영, 지속적 개선의 생애주기를 다룬다.

10.3 SLA/SLM​

SLM(Service Level Management) 프레임워크​

비유: 학교 급식 품질 관리 체계

급식의 맛, 영양, 위생 기준을 정하고(SLA), 조리실 내부 기준(OLA)을 세우고, 식재료 납품 기준(UC)을 관리하는 전체 프레임워크다.

SLA(Service Level Agreement)​

비유: 배달 앱의 배달 보증

"30분 내 배달, 지연 시 할인 쿠폰 제공"처럼 서비스 제공자와 고객 사이에 서비스 수준(가용성, 응답시간, 장애복구시간 등)을 명문화한 합의서다.

OLA(Operational Level Agreement)​

비유: 주방과 배달기사 간 내부 약속

SLA가 고객과의 약속이라면, OLA는 서비스를 제공하기 위해 내부 부서 간에 맺는 약속이다. "주방은 15분 내 조리 완료, 배달팀은 15분 내 배달" 같은 내부 합의다.

Penalty / Incentive​

비유: 지각비와 개근상

SLA를 못 지키면 벌금(Penalty), 초과 달성하면 보상(Incentive)이다. 서비스 수준을 유지하기 위한 동기부여 장치다.

10.4 클라우드/SaaS 거버넌스​

SaaS 이용 가이드라인​

비유: 월세 아파트 입주 가이드

월세 아파트에 입주할 때 "계약 조건, 시설 사용법, 퇴거 절차"를 안내받듯, SaaS를 도입할 때 보안, 데이터 관리, 서비스 수준, 계약 조건 등을 점검하기 위한 가이드라인이다.

클라우드 아웃소싱 리스크 관리​

비유: 남의 창고에 물건 맡기기

자기 집 창고 대신 외부 창고(클라우드)에 물건(데이터)을 맡길 때 "도난, 화재, 창고 업체 폐업" 등의 위험을 관리해야 한다. 데이터 유출, 벤더 종속, 서비스 중단 등의 리스크를 식별하고 대응하는 것이다.

10.5 IT 컴플라이언스​

IT 컴플라이언스​

비유: 교통법규 준수

운전할 때 교통법규(속도 제한, 신호 준수)를 지켜야 하듯, 기업의 IT 활동이 관련 법규, 규정, 표준을 준수하도록 관리하는 것이다. 개인정보보호법, 전자금융거래법 등 각종 법적 의무를 IT 시스템에 반영한다.

11. 경영전략 및 분석​

11.1 가치사슬 및 산업 분석​

가치사슬(Value Chain)​

비유: 빵집의 가치 만들기 과정

밀가루 구매(물류) - 반죽/제빵(생산) - 포장(출고) - 매장 판매(마케팅) - 고객 응대(서비스)의 각 단계가 가치를 더한다. 마이클 포터의 가치사슬은 기업 활동을 주 활동과 지원 활동으로 분해하여 어디서 경쟁 우위를 만들 수 있는지 분석한다.

ERP(Enterprise Resource Planning)​

비유: 가정 살림의 가계부 통합 관리

수입, 지출, 저축, 보험을 하나의 가계부 앱으로 통합 관리하듯, 기업의 재무/인사/생산/물류를 하나의 시스템으로 통합하여 실시간 관리한다.

SCM(Supply Chain Management)​

비유: 편의점 물류 배송 시스템

공장에서 물건을 만들어 물류창고를 거쳐 편의점에 진열되기까지의 전 과정을 최적화한다. 수요예측으로 적정 재고를 유지하고, 안전재고로 품절을 방지한다.

MES(Manufacturing Execution System)​

비유: 공장 현장의 실시간 모니터링

공장 라인에서 "지금 몇 개 만들었고, 불량은 몇 개인지"를 실시간 화면으로 보여주는 시스템이다. ERP(계획)와 현장(실행) 사이를 연결한다.

CRM(Customer Relationship Management)​

비유: 단골 고객 관리 장부

단골 고객의 취향, 구매 이력, 불만 사항을 기록하고 맞춤 서비스를 제공하듯, CRM은 고객과의 관계를 체계적으로 관리하여 고객 만족과 충성도를 높인다.

11.2 경영환경 분석​

SWOT 분석​

비유: 자기소개서 작성

자기소개서에 "강점, 약점, 기회, 위협"을 쓰듯, 기업의 내부 강점(Strengths)/약점(Weaknesses)과 외부 기회(Opportunities)/위협(Threats)을 분석하여 전략을 도출한다.

3C 분석​

비유: 삼각관계 분석

"나(자사, Company), 경쟁자(Competitor), 상대방(고객, Customer)"의 세 가지 관점에서 시장을 분석한다. 고객이 무엇을 원하고, 경쟁자는 무엇을 하고, 우리는 무엇이 다른지 파악한다.

PEST 분석​

비유: 날씨 예보 보기

여행 전에 "정치 상황(P, 비자), 경제 상황(E, 환율), 사회 문화(S, 현지 풍습), 기술 트렌드(T, 통신)"를 확인하듯, 기업을 둘러싼 거시 환경을 분석한다.

5 Forces(5세력 모델)​

비유: 동네 치킨집이 직면하는 5가지 압력

  • 기존 경쟁자: 옆집 치킨집
  • 신규 진입자: 새로 오픈하는 치킨집
  • 대체재: 피자, 족발
  • 공급자 교섭력: 닭 도매상의 가격 결정력
  • 구매자 교섭력: 가격에 민감한 고객

마이클 포터가 정의한 산업 내 경쟁 강도를 결정하는 5가지 힘이다.

11.3 4차 산업혁명​

4차 산업혁명​

비유: 모든 것이 연결되고 지능화되는 시대

1차(증기기관), 2차(전기/대량생산), 3차(컴퓨터/인터넷)에 이어, 4차는 AI/IoT/빅데이터/로봇이 융합되어 "사이버-물리 시스템"이 구현되는 혁명이다. 냉장고가 우유가 떨어지면 자동 주문하고, 공장이 스스로 불량을 감지하여 조치하는 세상이다.

11.4 린/성장 전략​

린 스타트업(Lean Startup)​

비유: 최소 비용으로 포장마차 시작

큰 식당을 차리기 전에 포장마차로 시작해서, 손님 반응을 보고 메뉴를 바꾸고, 잘 되면 확장한다. Build(만들기) - Measure(측정) - Learn(학습) 반복 루프가 핵심이다.

그로스 해킹(Growth Hacking)​

비유: 입소문 폭발시키기

광고비 대신 창의적 방법으로 고객을 모은다. "친구 초대하면 5천 원 적립" 같은 바이럴 전략이 대표적이다. 데이터 분석을 기반으로 저비용 고효율 성장을 추구한다. AARRR 퍼널(획득-활성화-유지-수익-추천)을 활용한다.

TAM-SAM-SOM 프레임워크​

비유: 바다에서 내가 잡을 수 있는 물고기

  • TAM(Total Addressable Market): 바다 전체의 물고기 - 전체 시장 규모
  • SAM(Serviceable Available Market): 내 어선이 갈 수 있는 해역의 물고기 - 접근 가능한 시장
  • SOM(Serviceable Obtainable Market): 실제로 잡을 수 있는 물고기 - 실현 가능한 목표 시장

투자자에게 사업 규모를 설명할 때 사용하는 시장 크기 분석 프레임워크다.

11.5 SCM 및 ECM​

ECM(Enterprise Content Management)​

비유: 회사의 디지털 서류 캐비닛

종이 서류를 캐비닛에 분류/보관/폐기하듯, 기업의 모든 디지털 콘텐츠(문서, 이미지, 이메일 등)를 생성부터 폐기까지 체계적으로 관리하는 시스템이다.

11.6 ESG 및 디지털 혁신​

ESG 경영​

비유: 착한 기업 성적표

학교에서 성적뿐 아니라 봉사활동, 인성도 평가하듯, 기업을 환경(Environmental: 탄소배출), 사회(Social: 인권/다양성), 지배구조(Governance: 투명경영) 관점에서 평가한다. 투자자들이 재무제표와 함께 ESG 성적을 본다.

CoE(Center of Excellence)​

비유: 올림픽 대표팀 훈련센터

각 부서의 최고 전문가를 모아 특정 분야(AI, 클라우드 등)의 역량을 집중적으로 키우고, 그 노하우를 전사에 전파하는 전문 조직이다.

11.7 프로세스 마이닝 및 데이터 전략​

프로세스 마이닝​

비유: 환자의 동선을 CCTV로 분석

병원에서 환자가 "접수-진료-검사-수납" 과정에서 실제로 어떻게 움직이는지 CCTV로 분석하면, "검사실 앞에서 30분 대기" 같은 병목이 보인다. 프로세스 마이닝은 IT 시스템의 로그 데이터를 분석하여 실제 업무 프로세스의 흐름, 병목, 편차를 시각화하고 개선점을 발견하는 기법이다.

12. 발주 및 계약 관리​

12.1 RFP 및 제안서​

RFP(Request for Proposal)​

비유: 결혼식장에 보내는 견적 요청서

"몇 명, 어떤 음식, 어떤 분위기, 예산 범위"를 적어 여러 웨딩홀에 보내는 것이다. RFP는 발주기관이 사업 목적, 범위, 요구사항, 평가기준을 명시하여 업체에 제안서를 요청하는 공식 문서다.

SRS 중심 공공사업 관리​

비유: 건축 계약서에 설계도를 첨부하기

구두 약속이 아닌 상세 설계도(SRS: 소프트웨어 요구사항 명세서)를 기반으로 사업을 관리하면 분쟁을 줄일 수 있다.

12.2 발주 제도​

SW사업 분할 발주​

비유: 인테리어 공사를 전문 업체별로 분리 발주

한 업체에 전체를 맡기지 않고, HW는 HW 전문 업체, SW는 SW 전문 업체에 따로 발주한다. 전문성을 높이고 대기업 종속을 방지한다.

단계별 발주제도​

비유: 분할 납품

전체를 한 번에 발주하지 않고, "분석/설계 단계"를 먼저 발주하고 결과를 보고 "개발/구축 단계"를 발주한다. 요구사항이 불명확한 사업에서 위험을 줄인다.

협상에 의한 계약체결​

비유: 부동산 매매 협상

공개입찰(최저가 낙찰)이 아니라, 기술력과 가격을 종합 평가한 후 1순위 업체와 협상하여 계약한다. 기술력이 중요한 IT 사업에 적합하다.

제안서 평가​

비유: 오디션 심사

참가자(업체)의 노래(기술 제안), 춤(사업 관리), 외모(가격)를 종합적으로 심사하듯, 기술 평가와 가격 평가를 합산하여 최적 업체를 선정한다.

13. 사용성 및 UX​

13.1 사용성 평가​

사용성 평가(Usability Evaluation)​

비유: 신제품 시식회

새 메뉴를 출시하기 전에 고객에게 맛보게 하고 반응을 보듯, 소프트웨어를 실제 사용자에게 사용하게 하여 "쉽게 쓸 수 있는가, 효율적인가, 만족스러운가"를 평가한다.

휴리스틱 평가(Heuristic Evaluation)​

비유: 맛집 평론가의 전문 평가

일반 손님이 아니라 전문 평론가(UX 전문가)가 "메뉴판이 읽기 쉬운가(가시성), 주문 취소가 가능한가(사용자 제어)" 등 10가지 원칙(닐슨의 10가지 휴리스틱)에 따라 전문적으로 평가하는 방법이다.

User Testing / Cognitive Walkthrough​

비유: 실제 손님 관찰 vs 동선 시뮬레이션

  • User Testing: 실제 고객이 식당에서 주문하는 모습을 관찰하여 문제를 발견
  • Cognitive Walkthrough: 전문가가 고객 입장에서 "입장-메뉴 선택-주문-결제"를 단계별로 시뮬레이션하며 인지적 어려움을 점검

13.2 디자인 싱킹​

Design Thinking​

비유: 의사의 진료 과정

환자(사용자) 이야기를 듣고(공감), 병명을 찾고(정의), 치료법을 구상하고(아이디어), 시험 투약하고(프로토타입), 경과를 관찰(테스트)하는 것처럼, 사용자 중심으로 문제를 해결하는 혁신 방법론이다.

공감(Empathize)​

비유: 환자의 입장에서 느끼기

의사가 진찰하기 전에 환자의 고통을 이해하려고 이야기를 경청하듯, 관찰, 인터뷰, 체험을 통해 사용자의 진짜 문제와 감정을 깊이 이해하는 단계다.

Define(정의)​

비유: 병명 진단

여러 증상(공감 단계의 발견)을 종합하여 핵심 문제를 명확하게 정의한다. "이 사용자의 진짜 문제는 무엇인가?"

Ideate(아이디어)​

비유: 치료법 브레인스토밍

가능한 모든 치료법(해결책)을 제한 없이 발산적으로 떠올린다. 브레인스토밍, 마인드맵 등을 활용한다.

Prototype(프로토타입)​

비유: 시험 투약 / 시제품

최소한의 비용으로 아이디어를 구체화한 시제품을 만든다. 종이 프로토타입, 와이어프레임, 목업 등이 해당한다.

Test(테스트)​

비유: 경과 관찰

프로토타입을 사용자에게 보여주고 피드백을 받아 개선한다. 필요하면 공감 단계로 돌아가 반복한다.

13.3 정부 UX/UI 가이드라인​

전자정부 웹사이트 UI/UX​

비유: 관공서 안내 표지판 표준

모든 관공서의 안내 표지판 디자인을 통일하면 어디서든 길을 찾기 쉬운 것처럼, 전자정부 웹사이트의 UI/UX 설계 기준을 표준화하여 국민 누구나 쉽게 이용하도록 한다.

디지털 정부서비스 UI/UX​

비유: 모바일 시대에 맞춘 관공서 앱 디자인 가이드

PC 중심에서 모바일/태블릿까지 확장된 정부 서비스의 UI/UX 가이드라인이다. 접근성, 사용성, 일관성을 중시한다.

13.4 인터페이스 기술​

멀티모달 인터페이스​

비유: 오감을 사용하는 소통

사람이 말(음성), 손짓(제스처), 표정(시각), 글씨(텍스트)로 소통하듯, 여러 입출력 방식(음성, 터치, 시선, 제스처 등)을 동시에 활용하는 인터페이스다. AI 스피커에 말로 명령하면서 화면으로 결과를 보는 것이 대표적이다.

반응형 웹 디자인(RWD, Responsive Web Design)​

비유: 물이 그릇 모양에 맞게 변하듯

같은 물이 컵에 넣으면 컵 모양, 그릇에 넣으면 그릇 모양이 되듯, 하나의 웹페이지가 PC/태블릿/모바일 화면 크기에 따라 자동으로 레이아웃을 조정하는 기술이다. 미디어 쿼리(Media Query)를 활용한다.

13.5 기술 수용 및 UX 어두운 면​

기술수용모델(TAM, Technology Acceptance Model)​

비유: 새 앱을 깔까 말까 결정하는 과정

새 앱을 설치할 때 "유용한가?(인지된 유용성)", "사용하기 쉬운가?(인지된 용이성)"를 따져본다. TAM은 사용자가 새 기술을 수용하는 데 영향을 미치는 요인을 설명하는 이론이다. 유용성과 용이성이 높을수록 사용 의도가 증가한다.

다크패턴(Dark Pattern)​

비유: 미끼 상술

"무료 체험"을 누르면 자동 결제가 되거나, 해지 버튼을 일부러 숨기는 것처럼, 사용자를 기만하여 의도하지 않은 행동을 유도하는 UI/UX 설계 패턴이다. 규제 대상이 되고 있으며, 윤리적 UX 설계의 반면교사다.
