네트워크 통신 개념 상세설명 (비유로 쉽게 이해하기)

정보관리기술사 110~138회 기출 키워드 기반 각 개념을 일상생활의 비유를 통해 쉽게 설명합니다.

1. 통신 및 네트워크 기초​

1.1 정보이론​

샤논의 제1정리(소스 코딩 정리)​

비유: 짐을 가장 효율적으로 싸는 방법

여행 가방에 짐을 넣을 때, 옷을 압축팩으로 줄이면 더 많이 넣을 수 있다. 샤논의 제1정리는 "데이터를 손실 없이 압축할 수 있는 한계"를 수학적으로 증명한 것이다. 정보의 엔트로피(불확실성)가 높을수록 더 많은 비트가 필요하고, 엔트로피 이하로는 절대 줄일 수 없다. ZIP 압축이나 허프만 코딩 같은 무손실 압축의 이론적 근거다.

샤논의 제2정리(채널 용량 정리)​

비유: 수도관의 최대 수송 능력

수도관의 굵기와 수압에 따라 한 번에 보낼 수 있는 물의 양(채널 용량)이 정해져 있다. 샤논의 제2정리는 잡음이 있는 통신 채널에서도 오류 없이 전송할 수 있는 최대 데이터 전송률(채널 용량, C)이 존재함을 증명했다. 핵심 공식은 C = B log2(1 + S/N)으로, 대역폭(B)과 신호 대 잡음비(S/N)가 클수록 더 많은 데이터를 보낼 수 있다.

1.2 교환방식​

회선교환(Circuit Switching)​

비유: 전용 고속도로 예약

서울에서 부산까지 전용 도로를 통째로 예약하고, 통화가 끝날 때까지 독점 사용하는 것이다. 안정적이고 지연이 일정하지만, 통화하지 않는 시간에도 도로를 비워둬야 하므로 비효율적이다. 전통적인 전화망(PSTN)이 이 방식이다.

패킷교환(Packet Switching)​

비유: 택배 배송

큰 짐을 여러 상자(패킷)로 나눠 각각 독립적으로 배송하고, 도착지에서 다시 조립한다. 상자마다 다른 경로로 갈 수도 있고, 도로를 다른 택배와 함께 공유한다. 인터넷이 바로 이 방식이다. 효율적이지만 도착 순서가 바뀔 수 있다.

  • 데이터그램 방식: 각 택배 상자가 독립적으로 최적 경로를 찾아 이동. 순서 보장 안 됨.
  • 가상회선 방식: 배송 전에 경로를 미리 정해놓고, 모든 상자가 같은 경로로 이동. 순서 보장.

메시지교환(Message Switching)​

비유: 우체국 중계 시스템

편지를 보내면 각 우체국에서 전체 편지를 받아 저장한 뒤, 다음 우체국으로 전달하는 축적-전달(Store-and-Forward) 방식이다. 실시간성은 떨어지지만, 회선을 독점하지 않아 효율적이다. 이메일이 이 방식과 유사하다.

1.3 OSI 7 Layer​

OSI 7계층 모델​

비유: 국제 우편물이 전달되는 7단계 과정

한국에서 미국으로 선물을 보낸다고 상상해보자. 각 단계마다 담당자가 있다.

  • 7계층 - 응용(Application): 선물을 고르는 사람. 사용자가 직접 접하는 서비스(웹브라우저, 이메일).
  • 6계층 - 표현(Presentation): 선물을 포장하고 라벨을 붙이는 사람. 데이터의 형식 변환, 암호화, 압축을 담당.
  • 5계층 - 세션(Session): 발송자와 수신자 사이의 대화 채널을 열고 닫는 관리자. 통신 세션의 시작, 유지, 종료를 관리.
  • 4계층 - 전송(Transport): 택배 회사. 선물이 분실 없이, 순서대로 도착하도록 보장(TCP) 또는 빠르게 보냄(UDP).
  • 3계층 - 네트워크(Network): 배송 경로를 정하는 물류센터. IP 주소를 기반으로 최적 경로를 찾아 라우팅.
  • 2계층 - 데이터링크(Data Link): 각 구간의 배달부. 인접 노드 간 프레임 전송, 오류 검출, MAC 주소 사용.
  • 1계층 - 물리(Physical): 도로와 트럭. 실제 비트를 전기 신호, 광 신호로 변환하여 전송하는 물리적 매체.

TCP/IP 4계층​

비유: OSI 7층 건물을 4층으로 리모델링

OSI 모델의 복잡한 7층 건물을 실용적인 4층 건물로 합친 것이 TCP/IP 모델이다.

  • 네트워크 접속 계층: OSI의 물리 + 데이터링크. 실제 케이블과 이더넷.
  • 인터넷 계층: OSI의 네트워크. IP 프로토콜로 주소 지정과 라우팅.
  • 전송 계층: OSI의 전송. TCP/UDP로 데이터 전달 신뢰성 관리.
  • 응용 계층: OSI의 세션 + 표현 + 응용. HTTP, FTP, DNS 등 사용자 서비스.

2. 네트워크 프로토콜​

2.1 프로토콜 설계​

프로토콜(Protocol)​

비유: 외교 의전 규칙

각국 정상이 만날 때 악수 순서, 인사 방법, 통역 규칙이 정해져 있듯이, 프로토콜은 컴퓨터 간 통신할 때 지켜야 할 약속이다. 프로토콜의 3요소는 구문(Syntax, 데이터 형식), 의미(Semantics, 제어 정보의 의미), 타이밍(Timing, 통신 속도와 순서)이다.

2.2 오류 제어​

CRC(Cyclic Redundancy Check)​

비유: 택배 상자의 검수 바코드

택배를 보낼 때 상자에 바코드를 붙이고, 도착지에서 바코드를 스캔해 내용물이 손상되었는지 확인하는 것이다. CRC는 데이터에 다항식 연산으로 검사값을 붙여 전송하고, 수신 측에서 같은 연산으로 오류를 탐지한다. 오류 검출 능력이 매우 뛰어나 이더넷, USB 등에서 널리 사용된다.

패리티 비트(Parity Bit)​

비유: 짝수 맞추기 게임

친구들과 손가락 개수를 세는 게임에서 "항상 짝수로 맞추자"라고 약속한다. 데이터 비트의 1 개수가 짝수(짝수 패리티) 또는 홀수(홀수 패리티)가 되도록 1비트를 추가한다. 단순하지만 2비트 이상 오류는 검출하지 못하는 한계가 있다.

해밍 코드(Hamming Code)​

비유: 오답 위치까지 찾아주는 채점 시스템

시험에서 오답이 있으면 "몇 번이 틀렸다"까지 알려주는 채점 시스템이다. 패리티 비트를 여러 위치에 삽입하여 1비트 오류의 위치를 정확히 찾아 자동 수정(FEC)할 수 있다. 2비트 오류는 검출만 가능하다.

ARQ(Automatic Repeat reQuest)​

비유: 편지 수신 확인과 재발송

편지를 보내고 "잘 받았다"는 답장(ACK)을 기다린다. 답장이 안 오면 다시 보낸다.

  • Stop-and-Wait ARQ: 편지 한 통 보내고 답장 올 때까지 기다린 후 다음 편지를 보냄. 확실하지만 느리다.
  • Go-Back-N ARQ: 여러 편지를 연속으로 보내다가 3번 편지에 오류가 발생하면, 3번부터 끝까지 전부 다시 보냄. 빠르지만 낭비가 있다.
  • Selective Repeat ARQ: 오류가 난 3번 편지만 골라서 다시 보냄. 효율적이지만 수신 측에서 정렬 버퍼가 필요하다.
  • Adaptive ARQ: 통신 상태에 따라 위 방식을 자동으로 전환함. 도로 상황에 따라 배송 전략을 바꾸는 스마트 물류.

2.3 흐름/혼잡 제어​

슬라이딩 윈도우(Sliding Window)​

비유: 컨베이어 벨트의 작업 창

공장 컨베이어 벨트에서 작업자가 한 번에 볼 수 있는 구간(윈도우)이 정해져 있다. 작업이 끝난 물건이 빠져나가면 창이 앞으로 밀려나(슬라이드) 새로운 물건이 들어온다. 송신 측이 확인 응답 없이 보낼 수 있는 패킷 수를 윈도우 크기로 제한하여 수신 측이 처리할 수 있는 만큼만 데이터를 보낸다.

TCP 혼잡제어(Congestion Control)​

비유: 도로 교통 흐름 관리

출퇴근 시간에 모든 차가 동시에 도로에 나오면 정체가 발생한다. TCP는 네트워크 혼잡을 감지하고 전송 속도를 조절한다.

  • Slow Start: 새로 개통한 도로에 차를 한 대씩 보내보고, 문제없으면 2대, 4대, 8대로 기하급수적으로 늘린다.
  • Congestion Avoidance: 임계값(ssthresh)에 도달하면 한 대씩 조심스럽게 늘린다. 정체가 시작되기 전에 속도를 줄이는 것.
  • Fast Retransmit: 같은 차가 3번 연속 "앞차 안 왔다"고 신고(중복 ACK 3회)하면, 타이머를 기다리지 않고 즉시 재전송한다.
  • Fast Recovery: 사고 후 도로를 완전 통제하지 않고, 절반 수준으로 빠르게 복구하여 흐름을 유지한다. 윈도우를 절반으로 줄이고 바로 Congestion Avoidance로 진입.

2.4 전송 계층​

TCP(Transmission Control Protocol)​

비유: 등기우편

보낸 사람이 받는 사람의 수신 확인을 받고, 분실 시 재발송하는 등기우편이다. 신뢰성 있는 데이터 전송을 보장한다.

  • 3-way Handshake (연결 설정): 전화 걸기와 같다. "여보세요(SYN)" - "네, 들립니다(SYN+ACK)" - "잘 들리네요, 시작합시다(ACK)". 세 번의 교환으로 양방향 연결을 확인한다.
  • 4-way Handshake (연결 종료): 전화 끊기와 같다. "이만 끊을게요(FIN)" - "네 알겠습니다(ACK)" - "저도 끊을게요(FIN)" - "네 안녕히(ACK)". 양쪽 모두 전송이 끝났음을 확인한다.

UDP(User Datagram Protocol)​

비유: 일반 우편(엽서)

엽서를 보내면 도착 확인도 없고, 분실되어도 알 수 없다. 대신 빠르고 간단하다. 실시간 스트리밍, 게임, DNS 조회처럼 속도가 중요하고 약간의 손실이 허용되는 곳에 사용된다.

SCTP(Stream Control Transmission Protocol)​

비유: 복수 차선 등기우편

하나의 연결에서 여러 개의 독립적인 스트림을 동시에 전송할 수 있다. 한 차선에서 사고가 나도 다른 차선은 영향 없이 달린다(HOL Blocking 해결). TCP의 신뢰성과 UDP의 메시지 경계를 결합했다. 멀티호밍(여러 IP 동시 사용)도 지원한다.

QUIC​

비유: VIP 전용 고속 배송 서비스

기존 등기우편(TCP)이 접수-확인-배송에 여러 단계가 필요했다면, QUIC는 접수와 동시에 배송이 시작되는 초고속 서비스다. UDP 위에 구축되어 연결 설정이 0~1 RTT로 매우 빠르고, TLS 1.3 암호화가 기본 내장되어 있다. HTTP/3의 기반 프로토콜이다.

2.5 응용 계층​

HTTP/HTTPS​

비유: 식당 주문 시스템

  • HTTP: 손님(클라이언트)이 "메뉴 주세요"(요청)하면 웨이터(서버)가 "여기요"(응답)하는 주문 방식. 주문은 일회성이며, 이전 주문을 기억하지 않는다(Stateless).
  • HTTPS: 주문서를 암호화된 봉투에 넣어 전달하는 방식. SSL/TLS로 통신을 암호화하여 도청을 방지한다.

HTTP/2​

비유: 멀티 레인 드라이브 스루

HTTP/1.1이 한 줄 서기(한 번에 하나의 요청-응답)였다면, HTTP/2는 여러 레인에서 동시에 주문하고 받는 방식이다. 멀티플렉싱(하나의 연결에서 여러 요청 동시 처리), 헤더 압축, 서버 푸시를 지원한다.

HTTP/3​

비유: 드론 배송

기존 도로(TCP) 대신 하늘길(QUIC/UDP)을 이용한 배송이다. 도로 정체(TCP HOL Blocking)에 영향을 받지 않고, 목적지까지 독립적으로 빠르게 도달한다.

FTP/FTPS/SFTP​

비유: 파일 배달 서비스의 진화

  • FTP: 일반 트럭 배송. 파일을 빠르게 전송하지만 보안이 없다. 제어 연결(21번)과 데이터 연결(20번) 두 개의 채널을 사용.
  • FTPS: 방탄 트럭 배송. FTP에 SSL/TLS 암호화를 추가한 것.
  • SFTP: 비밀 터널을 통한 배송. SSH 프로토콜 위에서 동작하며, 하나의 암호화 채널로 파일을 전송한다.

SMTP/IMAP/POP3​

비유: 우체국 시스템

  • SMTP: 편지를 보내는 우체통. 이메일 발신 전용 프로토콜. 발신자 우체국에서 수신자 우체국까지 편지를 전달한다.
  • POP3: 우체국에 가서 편지를 가져오면 우체국에서 편지가 사라지는 방식. 이메일을 로컬에 다운로드하고 서버에서 삭제.
  • IMAP: 우체국에 편지를 두고 언제든 열람하는 방식. 서버에 이메일이 남아있어 여러 기기에서 동기화 가능.

DNS(Domain Name System)​

비유: 전화번호부

"홍길동"이라는 이름으로 전화번호를 찾듯, "www.example.com"이라는 도메인 이름으로 IP 주소(192.168.1.1)를 찾아주는 시스템이다. 계층적 구조(루트 - TLD - SLD)로 이루어져 있으며, 캐싱으로 반복 조회를 빠르게 한다.

DHCP(Dynamic Host Configuration Protocol)​

비유: 호텔 자동 객실 배정

호텔에 체크인하면 프론트에서 자동으로 빈 방을 배정해주듯, DHCP 서버는 네트워크에 접속하는 기기에 IP 주소, 서브넷 마스크, 게이트웨이, DNS 서버 정보를 자동 할당해준다. 임대(Lease) 방식이라 체크아웃(임대 만료) 후 다른 기기에 재배정된다.

2.6 IoT 프로토콜​

MQTT(Message Queuing Telemetry Transport)​

비유: 구독형 게시판

카페 게시판에 글(메시지)을 올리면(Publish), 해당 게시판을 구독(Subscribe)한 사람만 알림을 받는다. 브로커(게시판 관리자)가 중개한다. 매우 가벼워서 센서, 스마트홈 기기처럼 자원이 제한된 IoT 장치에 적합하다.

CoAP(Constrained Application Protocol)​

비유: 저전력 미니 웹서버

HTTP가 대형 음식점의 풀코스 주문이라면, CoAP는 간이 매점의 간단 주문이다. HTTP와 유사한 REST 구조(GET, PUT, POST, DELETE)를 사용하지만, UDP 기반으로 훨씬 가볍다. 배터리로 동작하는 소형 IoT 센서에 적합.

XMPP(Extensible Messaging and Presence Protocol)​

비유: 실시간 채팅 프레임워크

카카오톡처럼 실시간 메시지를 주고받을 수 있는 개방형 프로토콜이다. XML 기반으로 확장성이 뛰어나며, 접속 상태(온라인/오프라인) 확인이 가능하다. IoT에서 기기 간 실시간 통신에 활용된다.

LwM2M(Lightweight M2M)​

비유: IoT 기기 원격 관리 리모컨

TV 리모컨으로 채널 변경, 볼륨 조절, 설정 변경을 하듯, LwM2M은 IoT 기기를 원격으로 등록, 모니터링, 펌웨어 업데이트할 수 있는 경량 관리 프로토콜이다. OMA에서 표준화했으며 CoAP 기반으로 동작한다.

AMQP(Advanced Message Queuing Protocol)​

비유: 기업용 대형 우체국

일반 우체국(MQTT)이 간단한 편지를 다룬다면, AMQP는 계약서, 세금계산서처럼 절대 분실되면 안 되는 문서를 다루는 대형 우체국이다. 메시지 큐잉, 라우팅, 트랜잭션을 지원하며, 금융 시스템 등 신뢰성이 중요한 엔터프라이즈 메시징에 사용된다.

MODBUS​

비유: 공장 기계들의 공용 언어

공장의 다양한 기계(PLC, 센서, 모터)가 서로 대화하기 위한 공용 언어다. 1979년에 만들어진 산업용 시리얼 통신 프로토콜로, 단순한 요청-응답 구조로 레지스터 값을 읽고 쓴다. 마스터-슬레이브 방식으로 동작한다.

2.7 소켓/실시간 통신​

TCP Socket​

비유: 전화 통화

전화를 걸어 연결이 되면 끊을 때까지 양방향으로 자유롭게 대화할 수 있다. TCP 소켓도 연결을 맺으면 서버와 클라이언트가 지속적으로 데이터를 주고받는 양방향 통신 채널이다.

WebSocket​

비유: 인터컴(양방향 스피커)

일반 HTTP가 "초인종 누르고 문 열기를 반복"하는 것이라면, WebSocket은 인터컴을 설치해 언제든 양쪽에서 말할 수 있는 것이다. 최초 HTTP 핸드셰이크 후 연결을 업그레이드하여 전이중(Full-Duplex) 통신을 유지한다. 채팅, 실시간 알림, 주식 시세 등에 사용된다.

WebRTC(Web Real-Time Communication)​

비유: 직접 만나서 대화

전화(서버 중계)가 아니라, 두 사람이 직접 만나서(P2P) 대화하는 것이다. 브라우저 간 별도 서버 없이 직접 영상, 음성, 데이터를 주고받는다. 화상회의, 파일 공유에 사용되며, STUN/TURN 서버는 상대방 위치(주소)를 알려주는 안내자 역할만 한다.

Non-blocking I/O​

비유: 카페 진동벨

주문 후 카운터 앞에서 기다리는 것이 Blocking I/O라면, 진동벨을 받고 자리에서 다른 일을 하다가 벨이 울리면 가져오는 것이 Non-blocking I/O다. 입출력 작업이 완료될 때까지 기다리지 않고 다른 작업을 처리할 수 있어 동시 접속이 많은 서버에 필수적이다. Node.js의 이벤트 루프가 대표적이다.

3. 라우팅 및 IP​

3.1 라우팅 알고리즘​

거리벡터(Distance Vector) 알고리즘​

비유: 이웃에게 길 물어보기

낯선 마을에서 목적지까지의 경로를 이웃 주민에게만 물어본다. 각 주민은 자기가 아는 거리와 방향만 알려준다. 라우터가 인접 라우터로부터 받은 거리 정보(홉 수)를 기반으로 최단 경로를 계산한다. 단순하지만, 정보가 느리게 퍼지는 "느린 수렴" 문제가 있다. RIP가 대표적이다.

링크상태(Link State) 알고리즘​

비유: 전체 지도를 보고 네비게이션이 경로 계산

네비게이션이 전체 도로 지도를 가지고 있고, 실시간 교통 정보를 수집하여 최적 경로를 직접 계산한다. 각 라우터가 자신의 링크 상태를 모든 라우터에게 알리고(Flooding), 전체 네트워크 토폴로지를 기반으로 다익스트라 알고리즘으로 최단 경로를 계산한다. OSPF가 대표적이다.

경로벡터(Path Vector) 알고리즘​

비유: 국제 여행 경로 안내

"한국 - 일본 - 미국 순서로 가세요"처럼 목적지까지 거쳐가는 나라(AS) 목록 전체를 알려준다. 경로 루프를 쉽게 탐지할 수 있고, 정책 기반 라우팅이 가능하다. BGP가 이 방식을 사용한다.

3.2 라우팅 프로토콜​

IGP/EGP​

비유: 시내버스와 시외버스

  • IGP(Interior Gateway Protocol): 한 도시(AS) 안에서 운행하는 시내버스. 내부 네트워크의 라우팅을 담당. (RIP, OSPF, EIGRP, IS-IS)
  • EGP(Exterior Gateway Protocol): 도시와 도시를 연결하는 시외버스. 서로 다른 AS 간의 라우팅을 담당. (BGP)

RIP(Routing Information Protocol)​

비유: 몇 정거장 남았는지만 세는 버스 안내

"목적지까지 3정거장(홉)"처럼 거리만 따진다. 최대 15홉까지만 지원하고, 30초마다 전체 라우팅 테이블을 교환한다. 소규모 네트워크에 적합하지만 수렴이 느리다.

OSPF(Open Shortest Path First)​

비유: 도시 전체 지도로 최단 경로 찾기

모든 라우터가 도시 전체 교통 지도를 공유하고, 다익스트라 알고리즘으로 최단 경로를 계산한다. 네트워크를 영역(Area)으로 나눠 효율적으로 관리하며, 대규모 기업 네트워크의 표준이다. 변경이 생긴 정보만 즉시 전파(LSA)한다.

BGP(Border Gateway Protocol)​

비유: 국가 간 항공 노선 협정

각 나라(AS)가 "우리나라를 거치면 이 나라에 갈 수 있어요"라고 서로 협상하며 경로를 정하는 것이다. 인터넷의 백본을 구성하는 유일한 EGP로, 정책 기반으로 경로를 선택한다. 경로 속성(AS-PATH, LOCAL_PREF 등)을 고려하여 최적 경로를 결정한다.

EIGRP(Enhanced Interior Gateway Routing Protocol)​

비유: 시스코 전용 고급 내비게이션

거리벡터와 링크상태를 결합한 하이브리드 방식(DUAL 알고리즘)이다. 변경된 정보만 전파하고, 대체 경로(Feasible Successor)를 미리 계산해두어 장애 시 즉시 전환한다. 원래 시스코 전용이었으나 현재는 개방 표준이 되었다.

IS-IS(Intermediate System to Intermediate System)​

비유: OSPF의 형제

OSPF와 마찬가지로 링크상태 알고리즘을 사용하지만, OSI 프로토콜 체계에서 탄생했다. 대규모 ISP 네트워크에서 주로 사용되며, 확장성이 뛰어나다. OSPF가 IP 위에서 동작하는 반면, IS-IS는 데이터링크 계층에서 직접 동작한다.

3.3 IP 주소​

IPv4​

비유: 10자리 전화번호

32비트로 약 43억 개의 주소를 제공한다. 192.168.0.1처럼 점으로 구분된 4개의 숫자(각 0~255)로 표현한다. 세계 인구보다 적어 주소 고갈 문제가 발생했다.

IPv6​

비유: 국제 전화번호 체계 확장

128비트로 사실상 무한한 주소(약 3.4 x 10^38개)를 제공한다. 2001:0db8:85a3::8a2e:0370:7334처럼 16진수와 콜론으로 표현한다. 자동 설정(SLAAC), 보안(IPSec 내장), 효율적인 라우팅을 지원한다.

서브네팅(Subnetting)​

비유: 큰 땅을 여러 구획으로 나누기

100평 땅을 25평씩 4구획으로 나누듯, 하나의 네트워크를 여러 개의 작은 서브넷으로 분할한다. 서브넷 마스크로 네트워크 부분과 호스트 부분을 구분하며, 보안과 관리 효율을 높인다.

수퍼네팅(Supernetting)​

비유: 여러 작은 땅을 합쳐 큰 단지로

서브네팅의 반대 개념이다. 여러 개의 작은 네트워크를 하나의 큰 네트워크로 합쳐 라우팅 테이블 크기를 줄인다.

CIDR(Classless Inter-Domain Routing)​

비유: 주소 체계의 유연한 구역 설정

기존 A/B/C 클래스가 "정해진 크기의 아파트만 짓는" 방식이라면, CIDR은 필요한 크기만큼 자유롭게 토지를 분할하는 것이다. 192.168.1.0/24처럼 프리픽스 길이로 네트워크 크기를 유연하게 표현한다.

NAT(Network Address Translation)​

비유: 회사 대표 전화번호와 내선번호

회사 밖에서는 대표번호(공인 IP)로 전화하고, 교환원(NAT)이 내선번호(사설 IP)로 연결해준다. 사설 IP를 공인 IP로 변환하여 IPv4 주소 부족 문제를 완화하고, 내부 네트워크를 숨겨 보안도 높인다.

PAT(Port Address Translation)​

비유: 내선번호까지 활용하는 대표 전화

NAT가 대표번호 하나에 한 명만 통화할 수 있었다면, PAT는 포트 번호를 활용해 하나의 공인 IP로 여러 내부 기기가 동시에 외부와 통신할 수 있게 한다. 대부분의 가정용 공유기가 이 방식을 사용한다.

3.4 데이터 표현/프록시​

ASN.1(Abstract Syntax Notation One)​

비유: 국제 표준 서류 양식

각 나라마다 서류 양식이 다르면 혼란스럽다. ASN.1은 데이터 구조를 정의하는 국제 표준 표기법으로, 어떤 시스템이든 동일하게 해석할 수 있는 데이터 형식을 정의한다. SNMP, X.509 인증서 등에서 사용된다.

리버스 프록시(Reverse Proxy)​

비유: 건물 안내 데스크

방문객(클라이언트)이 건물에 들어오면 안내 데스크(리버스 프록시)에서 적절한 사무실(서버)로 안내해준다. 외부에서는 안내 데스크만 보이고 뒤의 사무실 구조는 알 수 없다. 로드밸런싱, 캐싱, SSL 종료, 보안 필터링 역할을 수행한다.

프레임릴레이(Frame Relay)​

비유: 고속도로 톨게이트 간소화

기존 X.25가 모든 교차로에서 일일이 검문(오류 제어)했다면, 프레임릴레이는 출발지와 도착지의 톨게이트만 통과하면 되는 고속도로다. 오류 제어를 단순화하여 속도를 높인 WAN 기술이다. 현재는 MPLS에 대체되었다.

4. 이동 통신​

4.1 5G​

5G 특화망​

비유: 기업 전용 고속도로

일반 고속도로(공용 5G)와 별도로, 특정 기업이나 기관이 전용으로 사용하는 고속도로를 깔아주는 것이다. 공장, 병원, 항만 등에서 자체적으로 5G 네트워크를 구축하여 보안, 성능, 커버리지를 맞춤 제어한다.

네트워크 슬라이싱(Network Slicing)​

비유: 하나의 도로를 용도별 전용차로로 분할

같은 도로를 버스 전용차로, 자전거 전용차로, 일반차로로 나누듯, 하나의 물리적 5G 네트워크를 여러 개의 가상 네트워크(슬라이스)로 분할한다. 자율주행용(초저지연), 영상 스트리밍용(고대역폭), IoT용(대규모 연결)을 각각 독립적으로 운영할 수 있다.

4.2 6G​

6G AI-Native Network​

비유: AI 비서가 운영하는 미래 도시 교통

사람이 신호등을 제어하는 것이 5G라면, AI가 모든 교통 흐름을 자동으로 최적화하는 것이 6G AI-Native Network다. 네트워크 설계, 운영, 최적화의 모든 단계에 AI가 내장되어 자율적으로 관리한다. 2030년대 상용화를 목표로 한다.

AI-RAN(AI-Radio Access Network)​

비유: AI가 관제하는 공항 관제탑

기존에는 사람이 비행기 이착륙(무선 접속)을 관리했다면, AI-RAN은 AI가 실시간으로 무선 자원 할당, 간섭 관리, 빔포밍을 자동 최적화하는 무선 접속 네트워크다.

SATIN(Satellite-Terrestrial Integrated Network)​

비유: 하늘과 땅을 연결하는 통합 교통망

고속도로(지상 네트워크)와 항공 노선(위성 통신)을 하나의 통합 교통 시스템으로 운영하는 것이다. 위성과 지상 네트워크를 유기적으로 결합하여 오지, 해양, 재난 상황에서도 끊김 없는 통신을 제공한다.

4.3 무선 접속​

NOMA(Non-Orthogonal Multiple Access)​

비유: 같은 라디오 주파수에서 여러 명이 대화

기존 OMA가 한 사람씩 차례로 마이크를 사용하는 것이라면, NOMA는 여러 명이 동시에 같은 마이크를 사용하되, 목소리 크기(전력)를 다르게 하여 수신 측에서 분리(SIC)하는 방식이다. 더 많은 사용자를 동시에 수용할 수 있다.

OFDMA(Orthogonal Frequency Division Multiple Access)​

비유: 수영장의 레인 나누기

수영장을 여러 레인으로 나누어 각 수영 선수가 자기 레인에서 동시에 수영하는 것이다. 넓은 주파수 대역을 여러 개의 좁은 부반송파로 나누고, 각 사용자에게 필요한 만큼의 부반송파를 할당한다. LTE, Wi-Fi 6에서 사용된다.

SDR(Software Defined Radio)​

비유: 만능 라디오 수신기

AM, FM, 단파 라디오를 각각 사야 했던 것을 소프트웨어 업데이트만으로 모든 주파수를 수신할 수 있는 만능 라디오로 만드는 기술이다. 하드웨어 변경 없이 소프트웨어로 무선 통신 방식을 변경할 수 있다.

MIMO/Massive MIMO​

비유: 다차선 터널과 초대형 터널

  • MIMO(Multiple Input Multiple Output): 1차선 터널 대신 4차선 터널을 뚫어 동시에 더 많은 차를 보내는 것. 송수신 안테나를 여러 개 사용하여 전송 용량을 늘린다.
  • Massive MIMO: 4차선이 아니라 64256차선 초대형 터널을 만드는 것. 기지국에 수십수백 개의 안테나를 설치하여 동시에 많은 사용자를 서비스하고, 빔포밍으로 특정 방향에 집중 전송한다. 5G의 핵심 기술이다.

4.4 차량 통신​

C-V2X(Cellular Vehicle-to-Everything)​

비유: 셀룰러 망을 이용한 차량 대화

자동차가 5G/LTE 네트워크를 통해 다른 차(V2V), 인프라(V2I), 보행자(V2P), 네트워크(V2N)와 소통하는 기술이다. 교차로에서 신호등이 "곧 빨간불이니 감속하세요"라고 차에게 직접 알려주는 것과 같다.

DSRC(Dedicated Short Range Communication)​

비유: 하이패스 단거리 통신

고속도로 톨게이트에서 하이패스 단말기와 수신기가 짧은 거리에서 빠르게 통신하는 것처럼, DSRC는 차량 간 단거리(약 300m) 직접 통신 기술이다. 5.9GHz 대역을 사용하며, C-V2X와 경쟁 관계에 있다.

4.5 Wi-Fi​

802.11 표준​

비유: Wi-Fi의 세대별 규격서

스마트폰이 갤럭시 S1, S2, S3으로 세대가 올라가듯, 802.11도 a, b, g, n, ac, ax, be로 발전해왔다. 각 세대마다 속도, 주파수, 기술이 개선된다.

802.11bn (Wi-Fi 8)​

비유: 차세대 초고속 Wi-Fi

Wi-Fi 7의 다음 세대로, 더 넓은 대역폭과 더 높은 효율을 목표로 개발 중인 차세대 표준이다. 협력적 MIMO, 다중 AP 조율 등 첨단 기술이 포함될 예정이다.

Wi-Fi 6/7​

비유: 혼잡한 카페에서도 빠른 무선 인터넷

  • Wi-Fi 6 (802.11ax): 혼잡한 카페에서 모든 손님이 동시에 빠른 인터넷을 쓸 수 있도록 OFDMA, MU-MIMO, BSS Coloring 등으로 효율을 극대화한 세대.
  • Wi-Fi 7 (802.11be): Wi-Fi 6를 더 진화시켜 320MHz 채널 폭, 4096-QAM, 멀티링크 운영(MLO)으로 최대 46Gbps 속도를 목표로 한다.

WPA3(Wi-Fi Protected Access 3)​

비유: 3세대 Wi-Fi 보안 자물쇠

WPA2가 기존 잠금장치라면, WPA3는 비밀번호가 약해도 뚫리지 않는 강화 자물쇠다. SAE(Simultaneous Authentication of Equals) 핸드셰이크로 오프라인 사전 공격을 방어하고, 공공 Wi-Fi에서도 개별 암호화(OWE)를 제공한다.

5. IoT 및 센서 네트워크​

5.1 IoT​

IoB(Internet of Behaviors)​

비유: 사람의 행동 패턴을 수집하는 IoT

IoT가 사물의 데이터를 수집한다면, IoB는 사람의 행동 데이터를 수집하고 분석하여 행동 변화를 유도한다. 건강보험사가 운동 데이터를 기반으로 보험료를 할인해주거나, 운전 습관에 따라 자동차 보험료를 책정하는 것이 예시다.

CPS(Cyber-Physical System)​

비유: 디지털 트윈이 현실을 제어

가상 세계(Cyber)와 현실 세계(Physical)가 센서와 액추에이터로 긴밀하게 연결된 시스템이다. 공장의 디지털 트윈이 실시간으로 설비 상태를 모니터링하고, 이상이 감지되면 자동으로 설비를 제어하는 것과 같다. 스마트 팩토리, 자율주행의 핵심 개념이다.

5.2 IoT 식별​

OID(Object Identifier)​

비유: 국제 표준 물품 번호 체계

모든 물건에 고유한 번호(1.2.840.113549...)를 붙여 전 세계 어디서든 식별할 수 있게 한 체계다. ITU-T와 ISO가 관리하며, IoT 기기, 인증서, SNMP MIB 등에서 객체를 고유하게 식별한다.

EPC(Electronic Product Code)​

비유: RFID 태그에 새긴 디지털 바코드

마트의 바코드가 상품 종류만 알려준다면, EPC는 RFID 태그에 저장되어 개별 상품 하나하나를 고유하게 식별한다. "이 콜라는 2024년 3월 15일 부산 공장에서 생산된 12345번 제품"까지 추적 가능하다.

5.3 WSN(Wireless Sensor Network)​

애드혹 네트워크(Ad-hoc Network)​

비유: 인프라 없이 사람들이 직접 릴레이하는 통신

산속에서 기지국이 없을 때, 등산객들이 서로 소리쳐 메시지를 릴레이하는 것이다. 고정 인프라(AP, 기지국) 없이 기기들이 자율적으로 네트워크를 구성하고 라우팅한다. 재난 현장, 군사 작전에서 활용된다.

Itinerary Routing​

비유: 순회 버스 노선

센서 데이터를 수집할 때, 각 센서가 중앙으로 개별 보고하는 대신 이동 에이전트가 정해진 순서대로 센서를 돌아다니며 데이터를 모아 한꺼번에 전달한다. 우유 배달부가 집집마다 돌며 빈 병을 수거하는 것과 같다.

LEACH/PEGASIS​

비유: 센서 네트워크의 에너지 절약 전략

  • LEACH: 반장을 돌아가며 하는 학급. 센서 노드들이 클러스터를 형성하고, 클러스터 헤드(반장)를 교대로 맡아 데이터를 모아 기지국에 전달한다. 특정 노드만 에너지를 많이 쓰는 것을 방지한다.
  • PEGASIS: 릴레이 줄넘기. 센서들이 체인(사슬)을 형성하여 인접 노드끼리만 데이터를 전달하고, 리더 노드만 기지국과 통신한다. LEACH보다 에너지 효율이 높다.

5.4 저전력 광역 통신​

LPWA(Low Power Wide Area)​

비유: 소포는 못 보내지만 편지는 아주 멀리 보내는 우체국

대용량 데이터 전송은 못하지만, 작은 데이터를 매우 먼 거리(수 km~수십 km)까지 아주 적은 전력으로 보낼 수 있는 통신 방식이다. 배터리 하나로 수년간 동작하는 IoT 센서에 이상적이다.

LoRa(Long Range)​

비유: 저전력 장거리 무전기

비면허 대역(900MHz 등)에서 CSS 변조로 수 km까지 도달하는 저전력 무선 기술이다. LoRaWAN이라는 네트워크 프로토콜과 함께 사용되며, 스마트 미터링, 농업 센서 등에 활용된다.

SigFox​

비유: 하루에 엽서 몇 장만 보내는 초절전 우체국

하루에 최대 140건, 한 번에 12바이트만 보낼 수 있지만, 가입형 서비스로 별도 기지국 구축 없이 글로벌 커버리지를 제공한다. 초저전력, 초저비용이 핵심이다.

NB-IoT(Narrowband IoT)​

비유: 기존 통신사 기지국을 활용하는 IoT 전용 회선

새로운 기지국을 세우지 않고, 기존 LTE 기지국의 좁은 대역(200kHz)을 IoT 전용으로 할당한다. 통신사 인프라를 활용하므로 커버리지와 신뢰성이 높고, 건물 내부(지하 등) 침투력이 우수하다.

5.5 IoT 보안/응용​

스마트팩토리(Smart Factory)​

비유: AI가 운영하는 무인 공장

사람이 일일이 기계를 조작하는 대신, IoT 센서가 설비 상태를 실시간 수집하고, AI가 분석하여 자동으로 생산을 최적화하는 공장이다. CPS, 디지털 트윈, 빅데이터, 로봇이 결합되어 불량률 감소, 에너지 절약, 다품종 소량 생산을 실현한다.

6. SDN/NFV​

6.1 SDN(Software Defined Networking)​

SDN 개요​

비유: 교통 관제 센터에서 모든 신호등을 중앙 제어

기존에는 각 교차로(라우터/스위치)가 자체적으로 신호(라우팅)를 결정했다. SDN은 중앙 관제 센터(컨트롤러)가 모든 교차로의 신호를 통합 제어한다. 네트워크의 두뇌(제어 평면)와 몸(데이터 평면)을 분리하여 소프트웨어로 네트워크를 프로그래밍한다.

제어 평면(Control Plane)​

비유: 교통 관제 센터의 관제사

교차로의 신호등 타이밍을 결정하는 관제사다. SDN에서 제어 평면은 네트워크 전체의 경로를 결정하고, 정책을 수립하는 두뇌 역할을 한다. 데이터 평면(실제 차량이 달리는 도로)과 분리되어 동작한다.

OpenFlow​

비유: 관제 센터와 신호등 사이의 통신 규약

중앙 관제 센터(SDN 컨트롤러)가 각 교차로의 신호등(스위치)에게 "이 차는 좌회전시켜, 저 차는 직진시켜"라고 지시하는 표준 통신 프로토콜이다. 플로우 테이블에 규칙을 설정하여 패킷 처리 방법을 지정한다.

6.2 NFV(Network Functions Virtualization)​

NFV​

비유: 전용 기계를 범용 컴퓨터로 대체

세탁기, 건조기, 식기세척기를 각각 사는 대신, 만능 로봇 하나가 소프트웨어에 따라 세탁도, 건조도, 식기 세척도 하는 것이다. 방화벽, 로드밸런서, WAN 가속기 같은 전용 하드웨어 장비를 범용 서버에서 소프트웨어(가상 네트워크 기능, VNF)로 구현한다. CAPEX/OPEX를 절감하고 유연한 확장이 가능하다.

6.3 VLAN/VPN/VXLAN​

VLAN(Virtual LAN)​

비유: 같은 건물의 부서별 출입 구역

물리적으로 같은 건물(스위치)에 있지만, 인사부, 개발부, 영업부를 논리적으로 분리하여 서로의 구역에 못 들어가게 하는 것이다. 브로드캐스트 도메인을 분리하여 보안과 성능을 향상시킨다.

VPN(Virtual Private Network)​

비유: 공용 도로 위의 투명 터널

모든 차가 다니는 공용 고속도로(인터넷) 위에 투명한 전용 터널을 만들어, 터널 안의 차량(데이터)은 외부에서 볼 수 없게 하는 것이다. 암호화와 터널링으로 공용 네트워크에서 사설 네트워크처럼 안전하게 통신한다.

VXLAN(Virtual Extensible LAN)​

비유: VLAN의 대규모 확장판

VLAN이 최대 4,096개 구역만 만들 수 있는 작은 건물이라면, VXLAN은 약 1,600만 개 구역을 만들 수 있는 초대형 빌딩이다. L2 네트워크를 L3 위에 오버레이(터널링)하여 데이터센터의 대규모 가상화 환경을 지원한다.

6.4 IBN(Intent-Based Networking)​

IBN​

비유: 음성 명령으로 움직이는 스마트홈

"거실 불 켜줘"라고 말하면(의도 입력), 스마트홈 시스템이 알아서 어떤 스위치를 제어할지 결정하고 실행하는 것처럼, IBN은 관리자가 "영업부는 외부 접근 차단"이라는 비즈니스 의도만 입력하면, 시스템이 자동으로 네트워크 정책을 생성, 적용, 검증한다. SDN의 진화된 형태다.

7. QoS(Quality of Service)​

7.1 QoS 모델​

DiffServ(Differentiated Services)​

비유: 비행기 클래스 분류

비행기에 퍼스트, 비즈니스, 이코노미 클래스가 있듯, 패킷에 등급(DSCP)을 표시하여 등급별로 차등 서비스를 제공한다. 각 라우터가 독립적으로 등급에 따라 처리하므로 확장성이 뛰어나다.

IntServ(Integrated Services)​

비유: VIP 전용 도로 예약

VIP 차량이 이동할 경로의 모든 교차로에 미리 "이 시간에 이 차를 우선 통과시켜"라고 예약(RSVP)해두는 것이다. 종단 간 QoS를 보장하지만, 모든 라우터가 예약 상태를 유지해야 하므로 확장성이 떨어진다.

MPLS(Multi-Protocol Label Switching)​

비유: 화물 컨테이너의 색깔 태그

항구에 도착한 컨테이너에 "빨간 태그는 A 창고, 파란 태그는 B 창고"처럼 라벨을 붙이면, 중간 경유지에서 주소를 일일이 확인하지 않고 태그만 보고 빠르게 분류한다. IP 주소 대신 짧은 라벨로 고속 포워딩하며, VPN, 트래픽 엔지니어링에 활용된다.

7.2 큐잉(Queuing)​

WFQ(Weighted Fair Queuing)​

비유: 놀이공원 패스트패스 (가중치형)

일반 줄과 패스트패스 줄이 있되, 각 줄에 가중치를 부여하여 패스트패스 손님이 일반 손님보다 2배 빠르게 탑승하되, 일반 손님도 무한정 기다리지는 않게 한다. 각 흐름에 공정한 대역폭을 보장하되 가중치로 우선순위를 조절한다.

FIFO(First In First Out)​

비유: 줄 선 순서대로 서비스

식당에서 먼저 온 손님부터 차례로 서비스하는 것이다. 가장 단순한 큐잉 방식으로, 우선순위 구분 없이 도착 순서대로 패킷을 처리한다. 구현이 간단하지만, 긴급한 패킷도 기다려야 하는 단점이 있다.

Priority Queuing(우선순위 큐잉)​

비유: 응급실 환자 분류(트리아지)

응급실에서 경증 환자보다 중증 환자를 먼저 치료하는 것처럼, 패킷을 우선순위별(높음/중간/보통/낮음) 큐에 분류하고, 높은 우선순위 큐를 항상 먼저 처리한다. 단, 낮은 우선순위 패킷은 무한정 대기(기아 현상)할 수 있다.

8. 망 정책​

8.1 망중립성(Network Neutrality)​

망중립성​

비유: 고속도로에서 모든 차를 평등하게 대우

고속도로 관리 회사(ISP)가 특정 택배 회사의 트럭만 빠르게 달리게 하고, 다른 회사 트럭은 느리게 만드는 것은 불공정하다. 망중립성은 인터넷 서비스 제공자가 모든 트래픽을 동등하게 취급해야 한다는 원칙이다. 특정 콘텐츠나 서비스를 차별하거나 차단해서는 안 된다.

8.2 제로 레이팅(Zero Rating)​

제로 레이팅​

비유: 특정 놀이기구만 무료인 놀이공원

놀이공원(통신사)이 특정 놀이기구(특정 앱이나 서비스)는 무료로 탈 수 있게 해주는 것이다. 예를 들어 유튜브는 데이터 무제한이지만 넷플릭스는 데이터가 차감되는 식이다. 소비자에게 유리해 보이지만, 무료가 아닌 서비스가 불이익을 받아 망중립성 위반 소지가 있다.

9. 근거리 무선​

9.1 NFC/HCE​

NFC(Near Field Communication)​

비유: 손가락 터치로 정보 교환

두 사람이 손가락을 맞대면 정보가 전달되는 마법 같은 기술이다. 약 10cm 이내의 초근거리에서 13.56MHz 주파수로 데이터를 교환한다. 교통카드, 모바일 결제(삼성페이, 애플페이), 출입증이 대표적이다.

HCE(Host Card Emulation)​

비유: 실물 카드 없이 스마트폰이 카드 역할

기존에는 NFC 결제를 위해 USIM 안의 보안 칩(SE)이 필요했다. HCE는 보안 칩 없이 스마트폰의 소프트웨어가 직접 카드를 흉내(에뮬레이션)내는 기술이다. 통신사에 종속되지 않고 앱만으로 NFC 결제가 가능해진다.

9.2 TOR(The Onion Router)​

TOR​

비유: 여러 겹의 봉투로 감싼 비밀 편지

편지를 보낼 때 3겹의 봉투로 감싸고, 각 중계 우체국에서 한 겹씩 벗겨 다음 목적지만 확인한다. 최종 수신자는 발신자를 알 수 없고, 중간 우체국도 전체 경로를 알 수 없다. 양파(Onion)처럼 겹겹이 암호화하여 익명성을 보장하는 네트워크다. 프라이버시 보호에 유용하지만, 불법 용도로 악용되기도 한다.

9.3 FSO(Free Space Optics)​

FSO​

비유: 레이저 손전등으로 모스 부호 보내기

두 건물 사이에 레이저 빛으로 데이터를 전송하는 기술이다. 광케이블을 깔 필요 없이 자유 공간(대기)을 통해 광 신호를 보내므로 빠르게 설치할 수 있다. 대역폭이 넓고 주파수 허가가 불필요하지만, 안개, 비, 눈 등 기상 조건에 영향을 받는다.

10. 엣지/클라우드​

10.1 모바일 엣지 컴퓨팅(MEC)​

MEC(Multi-access Edge Computing)​

비유: 동네 편의점 vs 대형 마트

필요한 물건을 사려고 멀리 있는 대형 마트(클라우드 데이터센터)까지 가는 대신, 가까운 동네 편의점(엣지 서버)에서 바로 구매하는 것이다. 기지국 근처에 소형 서버를 두어 데이터를 가까운 곳에서 처리함으로써 초저지연을 실현한다. 자율주행, AR/VR, 실시간 게임에 필수적이다.

10.2 DCI(Data Center Interconnect)​

DCI​

비유: 대형 마트 지점 간 물류 네트워크

서울, 부산, 대전에 있는 대형 마트 물류 창고(데이터센터)를 고속 전용 도로로 연결하여 재고를 실시간 이동시키는 것이다. 데이터센터 간 대용량 고속 연결을 위한 기술로, WDM 광전송, DWDM 등을 활용한다. 재해 복구, 부하 분산, 데이터 동기화에 필수적이다.

10.3 멀티클라우드(Multi-Cloud)​

멀티클라우드​

비유: 여러 은행에 나누어 예금하기

한 은행에만 돈을 넣으면 그 은행이 파산할 때 위험하다. 여러 은행(AWS, Azure, GCP)에 나누어 예금(워크로드)을 분산하면 리스크를 줄이고, 각 은행의 장점(금리, 서비스)을 활용할 수 있다. 벤더 종속(Lock-in)을 방지하고, 장애 시 다른 클라우드로 전환할 수 있지만, 관리 복잡성이 증가한다.

10.4 해저케이블(Submarine Cable)​

해저케이블​

비유: 대륙을 연결하는 해저 고속도로

대륙과 대륙 사이 바닷속에 광케이블을 깔아 국제 인터넷 트래픽의 약 99%를 전송하는 물리적 인프라다. 위성 통신보다 대용량, 저지연이며, 구글, 메타 같은 빅테크 기업들이 자체 해저케이블을 건설하고 있다. 해저케이블 손상은 국가 간 인터넷 장애를 유발할 수 있어 전략적 자산으로 취급된다.
