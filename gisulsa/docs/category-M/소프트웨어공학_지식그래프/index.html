소프트웨어공학 지식 그래프

CSV의 키워드를 기점으로 분류 → 중분류 → 소분류 → 키워드 → 형제/유사 개념까지 확장한 학습용 지식 트리. CSV에 등장하는 기출 키워드는 굵게, 그 외는 표준 SW공학 개념으로 보강함.

0. 전체 분류 개관​

1. 개발방법론​

트리​

  • 개발방법론
    • 전통 방법론
      • 폭포수(Waterfall)
      • 구조적 방법론
      • 정보공학(IE)
      • V-모델
      • 나선형(Spiral)
      • 프로토타이핑
      • CBD(컴포넌트 기반 개발)
    • 애자일 계열
      • 스크럼(Scrum) — 팀구성, 백로그, 스프린트, 데일리스탠드업, 회고
      • 칸반(Kanban) — WIP 제한, 시각화 보드
      • XP(Extreme Programming) — 페어, TDD, CI, 단순설계
      • 린 스타트업(Lean Startup) — Build-Measure-Learn, MVP
      • 크리스탈, FDD, DSDM
      • 형제 개념: SAFe, LeSS, Disciplined Agile (스케일드 애자일)
    • DevOps 계열
      • DevOps — CALMS(Culture/Automation/Lean/Measurement/Sharing)
      • DevSecOps — 보안 시프트레프트
      • DataOps — 데이터 파이프라인 자동화
      • 형제: MLOps, AIOps, GitOps, FinOps, PlatformOps
    • CI/CD
      • CI/CD 파이프라인
      • 배포 전략 — Blue-Green, Canary, Rolling, Shadow, Feature Toggle
      • 테스트 전략 — 단위→통합→E2E (테스트 피라미드)
    • 제품 라인 / 재사용
      • 제품계열(Product Line, SPL) — 코어 자산 + 변동성 관리
      • 컴포넌트 마켓플레이스, 도메인 공학
    • 신흥 개발 방식
      • 로우코드(Low Code)
      • 노코드(No Code)
      • PaaS 기반 개발
      • 바이브코딩, AI 페어 프로그래밍 (Copilot, Cursor)
    • 관리 프레임워크
      • ALM(Application Lifecycle Management)
      • 테일러링(Tailoring) — 프로젝트 특성 기반 방법론 조정
      • EVM, Burn Down Chart, Burn Up, CFD

핵심 관계 그래프​

2. 테스트/품질​

트리​

  • 테스트/품질
    • 테스트 기법
      • 명세 기반(블랙박스)
        • 동등분할, 경계값 분석, 결정테이블, 분류트리
        • 상태전이, 페어와이즈, 시나리오
      • 구조 기반(화이트박스)
        • 구문/분기/조건/조건-결정/MC-DC 커버리지
        • 데이터 흐름, 경로 테스트
      • 경험 기반
        • 탐색적 테스트, 오류추정, 체크리스트
    • 테스트 레벨
      • 단위(Unit) → 통합(Integration) → 시스템 → 인수
      • 통합 방식: 점진적/비점진적, 하향식/상향식, 빅뱅, 드라이버/스텁
    • 테스트 유형
      • 회귀(Regression), 몽키(Monkey), 뮤테이션(Mutation), 카오스(Chaos), A/B 테스팅
      • 성능 테스트 — 부하/스트레스/내구/스파이크, 리틀의 법칙
      • 신뢰성, 이식성, 사용성, 보안성, 호환성
      • 임베디드 SW 테스트
      • AI 테스트 — 메타모픽, 뉴런 커버리지, 안전반경
    • 커버리지
      • 테스트 커버리지 vs 코드 커버리지
      • 명령문, 분기, 조건, MC-DC, 경로
    • 자동화
      • 테스트 자동화 — Selenium, JUnit, Pytest, Cypress, Playwright
      • 소프트웨어 Visualization — 코드/프로세스 시각화
      • 보안 품질 자동화 — SAST, DAST, IAST, SCA, SBOM 연계
    • 품질 관리
      • 품질비용(COQ) — 예방/평가/내부실패/외부실패
      • QA vs QC — 프로세스 vs 산출물
      • 인스펙션 vs 워크스루 vs 동료검토(Peer Review)
      • AI 소프트웨어 품질보증
    • 품질 모델 / 인증
      • CMMI(단계적/연속적) — 5단계: 초기/관리/정의/정량/최적화
      • SPICE(ISO/IEC 15504), SP 인증, GS 인증
      • 형제: ISO/IEC 25010(SQuaRE), ISO 9126, ISO/IEC 12207

품질 모델 그래프​

3. 아키텍처/설계​

트리​

  • 아키텍처/설계
    • 아키텍처 스타일
      • 데이터 중심형, 저장소 패턴
      • 클라이언트-서버, 3-Tier, N-Tier
      • 계층(Layered), 파이프-필터, 블랙보드
      • 이벤트 기반(EDA) — 중재자(Mediator) / 브로커(Broker) 토폴로지
      • 모놀리스(Monolith)
      • SOA, MSA(마이크로서비스)
      • 서버리스(Serverless), FaaS
      • P2P, 마스터-슬레이브
    • 마이크로서비스 생태계
      • MSA 특징 — 독립 배포, 분산, 다중 언어/저장소
      • 서비스 메쉬(Service Mesh) — Istio, Linkerd, Consul
      • API Gateway — 라우팅, 인증, 레이트리밋, 응답 합성
      • 사이드카, Saga, CQRS, Event Sourcing, Outbox
      • 분산 추적 — OpenTelemetry, Jaeger
    • API 설계
      • REST API / RESTful — HATEOAS, Richardson 성숙도
      • SOAP — WSDL, UDDI
      • OAS(OpenAPI Specification) — Swagger
      • 개방형 API(Open API)
      • 형제: GraphQL, gRPC, WebSocket, Webhook
    • 디자인 패턴(GoF 23)
      • 생성: 싱글톤, 팩토리, 추상팩토리, 빌더, 프로토타입
      • 구조: 어댑터, 프록시, 데코레이터, 파사드, 브리지, 컴포지트, 플라이웨이트
      • 행위: 옵저버, 전략, 커맨드, 상태, 책임연쇄, 템플릿메소드, 이터레이터, 메디에이터, 메멘토, 비지터, 인터프리터
    • 표현 계층 패턴
      • MVC, MVP, MVVM, Flux/Redux
    • 아키텍처 평가
      • ATAM(Architecture Tradeoff Analysis Method) — 정방향/역방향 분석
      • CBAM(Cost Benefit Analysis Method)
      • SAAM, ARID
      • 형제: Wellness check, Fitness function

아키텍처 진화 그래프​

4. 요구공학​

트리​

  • 요구공학(Requirement Engineering)
    • 요구사항 유형
      • 기능 요구사항
      • 비기능 요구사항 — 성능, 가용성, 보안, 신뢰성, 사용성, 이식성
      • 인터페이스 요구사항
      • 도메인 요구사항, 제약 요구사항
    • RE 프로세스
      • 도출(Elicitation) → 분석(Analysis) → 명세(Specification) → 검증(Validation) → 관리(Management)
    • 도출 기법
      • 인터뷰, 설문, 워크숍, 브레인스토밍, JAD
      • 관찰(Observation), 문서 분석
      • 프로토타이핑, 시나리오, 유즈케이스
      • 형제: Story Mapping, Event Storming, Impact Mapping
    • 명세 산출물
      • SRS(Software Requirement Specification) — IEEE 830
      • 요구사항명세서 기술항목
      • 정형 명세 — Z, VDM, B
      • 시각적 명세 — UML, BPMN
    • 추적성/관리
      • RTM(Requirement Traceability Matrix) — 전방향/후방향
      • 요구사항 변경 관리, 베이스라인
    • 품질 속성 (요구사항)
      • 명확성, 완전성, 일관성, 검증가능성, 추적가능성, 우선순위, 실현가능성

프로세스 그래프​

5. 유지보수/리팩토링​

트리​

  • 유지보수/리팩토링
    • 유지보수 유형 (ISO/IEC 14764)
      • 수정(Corrective), 적응(Adaptive), 완전화(Perfective), 예방(Preventive)
    • SW 변화 원리
      • Lehman의 법칙 — 8가지 (지속변경, 복잡도 증가, 자기조절 등)
    • 3R
      • 재공학(Re-engineering) — 기존 시스템 개선/현대화
      • 역공학(Reverse Engineering) — 코드 → 설계
      • 재사용(Re-use)
    • 리팩토링
      • 정의 — 외부 행위 보존하며 내부 구조 개선
      • 기법 — Extract Method, Rename, Move, Pull Up/Push Down, Replace Conditional with Polymorphism, Introduce Parameter Object
      • 코드 스멜(Code Smell) — Long Method, Large Class, Duplicate Code, Long Parameter List, Feature Envy, Shotgun Surgery, Divergent Change
      • 도구 — IDE 리팩토링, SonarQube
    • 리팩토링 vs 디자인패턴
      • 공통점: 코드 품질 향상
      • 차이: 패턴은 설계 청사진, 리팩토링은 변환 절차
    • 기술 부채(Technical Debt)
      • 의도적 vs 비의도적
      • 신중한 vs 무모한 (Martin Fowler 4분면)
      • 부채 관리 — 식별, 측정(SQALE), 상환 전략
    • 형제 개념: 레거시 모더나이제이션, 스트랭글러 패턴(Strangler Fig)

진화 그래프​

6. 설계원칙/객체지향​

트리​

  • 설계원칙/객체지향
    • OO 핵심 개념
      • 추상화(Abstraction)
      • 캡슐화(Encapsulation)
      • 정보은닉(Information Hiding)
      • 상속(Inheritance), 다형성(Polymorphism)
    • SOLID 5대 원칙
      • SRP — 단일 책임
      • OCP — 개방-폐쇄
      • LSP — 리스코프 치환
      • ISP — 인터페이스 분리
      • DIP — 의존성 역전
    • DI(의존성 주입)
      • 생성자 주입, 세터 주입, 인터페이스 주입
      • IoC 컨테이너 — Spring, Guice
      • 형제: Service Locator, Factory
    • 모듈 설계
      • 응집도(Cohesion) — 우연적 < 논리적 < 시간적 < 절차적 < 통신적 < 순차적 < 기능적
      • 결합도(Coupling) — 내용 > 공통 > 외부 > 제어 > 스탬프 > 자료
      • Fan-In / Fan-Out
    • 설계 원리
      • 단계적 분해, 모듈화
      • 형제: DRY, KISS, YAGNI, GRASP(9개 원칙)
    • 신뢰성 모델
      • SRGM(Software Reliability Growth Model)
      • 형제: Goel-Okumoto, Musa, Jelinski-Moranda
    • 프로그래밍 패러다임
      • 절차지향 vs 객체지향
      • 함수형, 선언형, 논리형
      • 형제: 리액티브 프로그래밍, AOP

원칙 관계 그래프​

7. UML/모델링​

트리​

  • UML/모델링
    • UML 다이어그램 (UML 2.x, 14종)
      • 구조 다이어그램
        • 클래스(Class), 객체, 컴포넌트, 배치, 패키지, 복합구조, 프로파일
      • 행위 다이어그램
        • 유즈케이스(Use Case), 시퀀스(Sequence), 활동(Activity), 상태(State), 통신, 타이밍, 상호작용 개요
    • 클래스 관계
      • 일반화(상속), 실체화(인터페이스 구현), 연관, 집합, 합성, 의존
      • 추상 클래스 vs 인터페이스
    • 데이터 모델링
      • ERD — 개체, 속성, 관계, 카디널리티
      • CRUD 매트릭스 — 데이터 vs 프로세스 매핑
      • 정규화(1NF~BCNF)
    • 횡단 관심사 모델링
      • AOP(Aspect Oriented Programming) — 관심사 분리, Pointcut, Advice, Aspect
      • 형제: Mixin, Decorator, Interceptor
    • 형제 모델링 표기법
      • BPMN(비즈니스 프로세스), SysML(시스템), ArchiMate(엔터프라이즈), C4 모델

UML 분류 그래프​

8. 형상관리/배포​

트리​

  • 형상관리/배포
    • 형상관리 (SCM)
      • 형상관리 개념
      • 기준선(Baseline) — 기능, 할당, 제품 기준선
      • 활동 — 식별, 통제, 감사, 기록
      • 도구 — Git, SVN, Mercurial
      • 형제: Trunk-based, GitFlow, GitHub Flow
    • 빌드/패키징
      • SBOM(Software Bill of Material) — SPDX, CycloneDX
      • 오픈소스 관리 — 라이선스(GPL, MIT, Apache), 취약점 스캔
      • 형제: SAST, SCA, Sigstore, in-toto
    • 배포 전략
      • 무중단 배포
        • 리버스 프록시, 로드밸런싱
        • Blue-Green, Canary, Rolling, Shadow
      • 카나리 + 점진 트래픽
      • 롤백 전략
    • CI/CD
      • CI/CD 파이프라인 — 빌드, 테스트, 패키지, 배포
      • DevSecOps — 보안 게이트, 시프트레프트
      • 도구 — Jenkins, GitHub Actions, GitLab CI, ArgoCD, FluxCD

배포 파이프라인 그래프​

9. SW안전​

트리​

  • SW안전(Safety)
    • 안전 vs 보안
      • SW Safety vs Security
      • Safety — 사용자/환경에 미치는 위해 방지
      • Security — 외부 위협으로부터 자산 보호
    • 표준
      • IEC 61508 — 일반 기능안전, SIL 1~4
      • 형제: ISO 26262(자동차, ASIL), DO-178C(항공), IEC 62304(의료), EN 50128(철도)
    • 안전성 분석 기법
      • FTA(Fault Tree Analysis) — 톱다운 결함 트리
      • FMEA(Failure Mode and Effects Analysis) — 보텀업 고장 영향 분석
      • HAZOP(HAZard and OPerability) — 위험 및 운전성
      • STPA(System-Theoretic Process Analysis) — 시스템 이론 기반
      • 형제: ETA(Event Tree), Bowtie 분석, FMECA
    • Secure SDLC
      • 요구→설계→구현→테스트→배포→운영 단계별 보안 활동
      • 프레임워크: MS SDL, OpenSAMM, BSIMM, NIST SSDF
    • SW 안전성 진단
      • 소프트웨어 진흥법 근거
      • 안전진단 가이드 — 기능동작 정확성
    • 형제 개념: Resilience Engineering, 카오스 엔지니어링(테스트와 연결)

안전 분석 그래프​

10. SW비용산정​

트리​

  • SW비용산정
    • 산정 접근법
      • 하향식(Top-down) — 전문가 판단, 델파이, 가격대비추정
      • 상향식(Bottom-up) — WBS 기반, LOC 합산
      • 유추 추정(Analogous), 매개변수 추정(Parametric)
    • 규모 산정 모델
      • LOC(Lines Of Code) — 낙관/기대/비관 (3점 추정)
      • 기능점수(Function Point) — IFPUG, NESMA, COSMIC
        • 데이터 기능 — ILF, EIF
        • 트랜잭션 기능 — EI, EO, EQ
      • 객체점수(Object Point)
      • 유즈케이스 점수(UCP)
      • 스토리포인트(Agile)
    • 노력/비용 산정 모델
      • COCOMO — Basic, Intermediate, Detailed
      • COCOMO II — Application Composition / Early Design / Post-Architecture
      • Putnam Model(SLIM) — Rayleigh 곡선
      • Function Point → 비용 환산
    • 운영 단계 대가
      • SW 운영단계 대가산정
      • 응용SW 요율제, 투입공수 산정
      • 형제: SLA 기반, T&M 계약
    • AI 서비스 대가산정
      • AI 도입 사업유형 분류
      • AI 사업비 산정 가이드 — 데이터 구축, 모델 개발, 운영
    • 한국 공공 가이드: SW사업 대가산정 가이드(KOSA), GS인증 가산점
